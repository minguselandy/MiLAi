## LC-015 Minimal Context

- ContextCapsule 固定为 `ACTIVE GOAL`、`ACTIVE STATE`、`OPEN ISSUES`、`CONSTRAINTS`、
  `RETRIEVED EVIDENCE`、`TRACE POINTERS` 六分区；
- Goal、constraints、Gate 后 ECS 与全部 live OpenIssue 是 protected items；issue 保留 ID、
  target、status、两侧 branch 和 discharge rule；
- 构建器按 `FULL → COMPACT → MINIMAL` 降级；最小保护表示仍超预算则返回
  `CONTEXT_BUDGET_INFEASIBLE`；
- pointer recovery 重验 ID、hash、permission、retention、revocation、Blob physical state 和
  Capsule TTL/status；TX-05 同步使旧 pointer/capsule fail closed。

## LC-016 Traceable Chat 与 UI

- Chat 只消费带持久化 QueryPlan 的 RetrievalTrace 和通过 Canonical Gate 的 Capsule；
- ChatTurn append-only 保存 ClaimVersion/Evidence/OpenIssue/Trace/Capsule 引用和 query
  fingerprint，不保存 query 明文；数据库 procedure 再次验证全部引用为本 tenant 且 live；
- action-sensitive 请求强制 `CANONICAL_REQUIRED`。`CONFIRM_ACTION` 字符串本身不再足以放行：
  必须引用 5 分钟内、可读、未撤销、source/ref/subject/content 匹配的
  `USER_CONFIRMATION` Evidence；该 Evidence 进入 ChatTurn/answer lineage；
- permission snapshot `readable != true` 时 Evidence GET 不返回正文；
- 本地 UI 支持 Chat、correct→Proposal、review、live confirmation Evidence、trace、revoke、
  Episode capture 和 Settlement；UI 不提供模型直接写 canonical 的路径。

## LC-017 Episode / Settlement

- `0011_episode_settlement` 新增 tenant-scoped `episode`、`episode_settlement`、
  `episode_transition`，全部 forced RLS；capture identity 不可变，settlement/transition
  append-only；
- Episode capture 只接受存在的 Evidence/ChatTurn/ContextCapsule 引用，校验唯一性和上限，
  与 operational event/outbox/idempotency 原子提交；
- Settlement 只能由 Steward procedure 执行，要求 `SETTLE`、expected revision CAS，最多保留
  3 个 pending residual Proposal，并校验 live OpenIssue；
- Settlement 关闭 Episode、使关联 ContextCapsule/Pointer 过期并留下 transition/outbox，
  但不创建 ClaimVersion、不自动审核 residual Proposal；
- API/Steward 均无 Episode 表 direct DML；跨 tenant SELECT 返回零行；
- Episode 三表进入 exhaustive backup inventory，真实 backup/restore 后 ID、状态和 Settlement
  记录逐表对账。
