## 实现范围

- `0007` 建立全局 outbox sequence、每 projection 独立 delivery/lease/retry/dead-letter 和
  contiguous watermark；`fts`、`vector`、`purge` 不能跨 gap 推进；
- FTS 使用 PostgreSQL `tsvector`/GIN，向量使用 pgvector `vector(16)`/HNSW；deterministic
  embedding 仅用于可重复测试；
- `QueryPlanner` 用版本化确定性规则生成 typed `QueryPlan`，包含 intent、散列 entity、时间、
  Scope、authority、confirmation 要求、complexity、consistency、budget 和 routes；不存 query
  明文；
- `0012_query_plan_trace` 将完整 QueryPlan 与每条 RetrievalTrace 原子持久化，procedure 校验
  plan 的 route/consistency/authority/scope 与实际执行参数一致；历史 trace 回填 legacy plan；
- L0 依据 Claim ID 或完整 identity 直接读取 canonical Head；L1 对 metadata/time/scope 预过滤，
  融合并去重 FTS/vector；L2 显式 `ROUTE_DISABLED`；
- 所有 candidate 都以 ClaimVersion ID 进入统一 Gate；在一致快照中检查 tenant、permission、
  retention、revocation、Head/version、GroundingBlock、Scope、time、live OpenIssue、authority
  和 lineage；
- `READ_YOUR_WRITES` 在 projection 落后或 snapshot advance 时回退 canonical；
  `CANONICAL_REQUIRED`/DB outage 明确 abstain；
- 正式接口已覆盖 `POST /v1/memory/query`、`GET /v1/retrieval-traces/{id}`、
  `GET /v1/system/watermarks`、`GET /v1/system/degraded-routes`；旧 `/retrieval/query` 保留兼容；
- E1 创建、E2 冲突、E3 合法解决、resolution Evidence revoke 四阶段均经 L0 Gate 生成 trace，
  reject reason 分别可回放为 accepted、`OPEN_ISSUE`、accepted、`GROUNDING_BLOCKED`。

## 失败与降级证据

- vector outage 时 FTS 继续并显式标记 degraded；
- dead-letter 阻断 watermark，显式 retry 后才推进；
- stale version、revoke 后 stale projection、wrong scope/tenant/authority/time 均 fail closed；
- projection lag 记录 `PROJECTION_LAG` canonical fallback；
- Canonical Gate/DB 故障返回空结果和 `CANONICAL_UNAVAILABLE`，不让 projection 自判；
- RetrievalTrace 不含 query token且 append-only；API 无 direct UPDATE；
- action-sensitive Chat 的 trace 将 `require_user_confirmation=true` 持久化，并由 Chat/DB
  procedure 校验 live confirmation Evidence。
