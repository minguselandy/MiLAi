# MiLAi v0.2 小型原型执行合同

日期：2026-09-05。本文补充 [v0.2 主方案](<C:/Users/Mingx/Documents/ChatGPT/New project 2/MiLAi_方案研究规划_v0.2_通用Agent记忆流程_20260905.md>) 的观测与比较约定。它不新增产品状态机，不要求改变现有记忆表示。以下实验尚未运行；工程可行性、真实使用收益和创新性分别验证，创新性保持 **RQ pending**。

**本轮收敛目标：在同一任务边界，观察 Agent 是否利用来源改善当前判断、是否正确保存有延续价值的变化，以及这些变化在后续任务中是否仍有用。**

**最高实验方法学原则：Agent 的使用策略保持开放；每项比较事先声明观测边界、干预差异和评价规则；将可观察事实、分层诊断与因果结论分开报告。**它约束实验和结论，不要求 Agent 逐层执行，也不要求每个运行都能确定根因。

## 1. 三种主张分别成立

| 主张 | 最小实验 | 能支持的结论 | 不能替代的结论 |
|---|---|---|---|
| 条件能力 | 明确要求检查当前记忆与来源 | 能力被调用后是否改善判断 | 正常工作中是否会及时调用 |
| 集成净收益 | 正常任务中，由实际宿主在一个既有位置提供通用机会 | 当前接入策略是否改善任务结果，额外成本多少 | 无宿主保障时，模型也一定会主动调用 |
| 持久变化的后续价值 | 保持其他条件相同，比较保存前后记忆所支持的后续任务 | 已产生的记忆变化是否帮助后续使用 | 写回选择策略已在所有任务上有效 |

附件所称“此前已经证明纯 MCP 自然首次调用不可靠”，本轮没有对应运行记录可核验，不写成新实验已经确认的事实。首版只需注明接入由谁负责：实际 Host 提供机会、使用已有 hook，或模型自行决定且属于 best effort。

## 2. 固定一个可观察位置，保留行为自由

接入时先选择宿主确实支持的位置，优先考虑跨会话恢复后的第一次上下文装配。拿不到真实 hook 时，使用离线 checkpoint，并明确称为模拟接入。

对同一任务的配对比较，控制任务版本、初始记忆、来源条件、工具、模型配置、机会位置与资源上限；被研究的干预因素除外。不同案例可以有不同任务版本，不能要求整个任务集使用同一个起点。Agent 可以直接继续、重读已呈现材料、检索、改写查询、调整当前产物，或选择是否保存。

**控制条件与观察结果分开。**同预算是相同可用上限，不要求实际调用、token 或耗时相等。查询变化后取得不同材料、影响后续行为，是策略作用的可能路径，不能为了“其他条件相同”强行消除。额外提示和 reviewer 的调用与输入均计入成本；若有意增加工具、上下文容量或预算，应声明为额外因素或组合方案，不能单独归因于查询策略。

首轮选一个接入位置便于调试；以后可以预先比较不同位置，或固定一套动态调度规则。单因素对照只变一个声明因素；多因素设计分别描述因素和交互；组合方案允许评价总效果。未声明的混合位置与配置应标为偏离，不能事后拼成某个单因素解释。

历史来源版本与当前披露资格分别记录。受控回放可以使用相同来源快照及预定权限变化时间线；真实接入仍以每次访问时有效的资格为准。出现撤销或外部变化时，如实记录条件差异，不以实验“冻结”为由继续披露。

工具调用、被下游使用的产物判断和提交最终回答均可成为可观察决策。预先定义“首次相关判断”的外部边界，例如向用户交付、进入下游使用，或被接受为任务完成结果；单纯写入未交付草稿不自动计为错误行动。是否计分取决于预定使用边界，不能由方法事后加上 draft 标签规避。工具提议与实际执行分报；不读取模型私有推理。评测标签不能成为运行时触发提示。

“给了机会”“模型发起回查”“关键材料实际进入输入”“判断正确”分别计数。调用率高本身不代表系统好。

## 3. 最薄的观测记录

复用宿主已有日志，组织为三类记录视图；它们可以共用一个 JSONL 文件或由现有 trace 导出，无需新增三套存储或要求模型填写 schema。

| 记录视图 | 最小内容 | 记录责任 |
|---|---|---|
| Observation：观察依据 | 运行 ID、观测规则、任务/记忆版本、来源与当前资格、模型/工具/预算；各次实际输入引用及呈现片段/截断，机会是否送达 | 宿主、工具与输入装配层；不可观测项注明缺失 |
| Intervention：比较差异 | 配对/分组依据、被改变的因素、控制条件、预定评价与分析；实际配置相对约定的偏离 | 实验框架在运行前声明，运行后核对实际配置 |
| Outcome：行为与结果 | 外显查询与返回、当前行动/产物、记忆差异及提交结果、后续装配与行为、未决状态、调用/token/耗时；独立评价与诊断依据 | 宿主与存储记录事实；评测器运行后附加评价，不向 Agent 提供标签 |

必须保留几项区分：

- **变化不等于纠正。**修改前没有外显判断，就把 `decision_changed` 记为未知，不能推测模型原本会怎样回答。纠正率来自可核验的前态或配对对照。
- **当前变化与持久变化是两个维度。**不能用 `CONTEXT_ONLY / PERSISTED_UPDATE / NO_CHANGE` 三选一替代原始记录；它们只适合作为派生展示标签。
- **没尝试、提交失败、版本冲突、成功保存、确认无持久变化、提交结果未知分别记录。**超时不意味着一定没写入；未确认时先核对提交状态，不盲目重试。无变化回执只绑定被检查版本，不能为更新版本背书。写入调用成功返回或内容摘要相等，均不单独证明语义正确。
- **摘要值用于定位版本，实际差异用于评价内容。**Markdown 段落、JSON 路径、整份新摘要都可以；保留策略允许时，留下可恢复旧版本及内容差异。
- **只记外显 Hint 和查询。**不要求模型披露或补写隐藏思维链。未输出的内部思考标为不可观察；模型自述停止理由与工具实际超时分别记录。

一份持久修改回执可只包含：运行 ID、目标引用、表示类型、旧/新版本、差异引用、依据引用、适用范围（确有需要时）、提交结果。新增或删除允许前值或后值为空；一次修改涉及多份记忆时可以列多个目标，不增加固定语义操作表。目标不是持久记忆时，不伪造记忆写入回执；当前输出变化已有独立记录。

日志支持审计和输入回放，不承诺随机模型重跑会得到相同结果。来源原文、查询和日志仍遵守当前访问与保留政策；无法合法保留完整内容时记录这一回放限制，不能为了“完整留痕”无限复制。

### 3.1 查询与后续使用的可观察范围

记录实际发出的查询及顺序，必要时关联产生下一查询的外显工具反馈。只有实际系统记录了查询间关系，才填写父查询或来源关系；允许多个父查询、新起点和未知，不强制把发散搜索表示成一棵树，也不由时间先后补造依赖。

“后续会话使用了修改”分开描述为：修改后的版本被取回、相关内容实际进入输入、后续判断是否正确。进入输入或被引用仍不单独证明内容对结果有贡献；保存的作用由 Prototype-2 的配对重访评价。

### 3.2 分层定位问题，按证据决定是否归因

下表提供排查方向，不是自动根因分类器，也不是要求每一步都发生的状态机。

| 可观察现象 | 优先核查 | 不能直接推断 |
|---|---|---|
| 按预定接入规则应提供机会，但没有送达 | Host 接入、调度或观测记录 | 所有未提供机会都属于故障 |
| 有机会，未调用来源工具 | 现有输入是否足够、是否直接对照、选择策略 | 没调用工具就是漏检 |
| 发起回查，关键材料未获得 | 来源资格/可得性、查询、索引、工具故障 | 未找到就是来源不存在，或一定是检索算法错误 |
| 工具返回关键内容，实际输入没有该内容 | 输入装配、过滤、截断 | 文档 ID 命中等于材料可见 |
| 关键内容已呈现，外显判断仍错 | 来源冲突、适用性、解释与任务执行 | 仅凭可见性就认定唯一原因是模型推理 |
| 当前判断正确，未保存修改 | 是否有延续价值、是否已有等效记忆、保存选择 | 一次性正确回答必须写回 |
| 发起保存，未确认提交 | 存储回执、冲突、权限、超时后的实际状态 | 被正确拒绝的过期写入是存储错误，或超时等于没写入 |
| 已提交，内容错误或破坏其他内容 | 更新语义、依据、适用范围、实际差异 | 提交成功证明记忆修好 |
| 有正确持久版本，下次没有装配相关内容 | 新任务是否需要、当前资格、恢复与选择机制 | 每个新任务都必须读取该版本 |
| 下次装配了相关内容，仍发生同一错误 | 内容是否充分、适用条件、复用和行动环节 | 实际读取已经证明有效使用 |
| 资格规则禁止暴露所需来源 | 权限执行与任务在当前范围内是否可完成 | 合规拒绝属于 retrieval miss，或可以从总体任务结果中删除 |

每项诊断保留观察依据、待排查层、可能的其他因素与确定程度；允许多因、未知和不适用。未执行某个可选步骤先评价其合理性，不默认失败。主诊断可以为空，无需为了填满记录而声称已经确定根因。

日志一般足以确认显式错误码、实际输入或版本结果；对“哪一机制导致收益或失败”的结论，还须结合对应干预、配对比较或针对性复验。总体任务失败仍计入总体结果；分层诊断只帮助解释，不能用于事后排除不利运行。

## 4. 先检查资格，再暴露内容

来源工具在向 Agent 返回内容之前执行当前披露资格检查。受限来源的标题、摘要、检索片段和派生记忆也属于可能暴露的信息，不能先展示再贴“不可用”标签。

离线原型可以使用封闭的允许来源集合，声明 `governance emulated by sealed allowed-source set`。允许集在方法运行前按主体、任务与权限规则产生，包含合法无关材料，不能按 gold 答案筛选。初始记忆视图也在披露范围内。只有通过受控工具入口实际限制可读集合，才能验证这一限定条件；仅在提示词写“不要读其他文件”不构成权限隔离。

这种原型不证明生产中的权限撤销、并发更新或删除传播正确。真实接入继续遵守 v0.2 的现有权限和版本边界；没有真实事件日志的参考原型不虚构 Basis。

## 5. 小型实验按三个问题推进

### Prototype-0：先看被调用后的能力

先选两个任务域，例如一个软件/工具任务和一个研究简报任务。每域包含四类起点：正确记忆、错误或过时记忆、摘要遗漏重要细节、当前需要展开但不必持久保存。8 个案例可以启动调试，8–12 个案例属于流程 pilot，不能据此宣称统计显著或广泛泛化。

普通回查提示可统一为：“使用现有来源检查当前记忆是否仍适合当前任务，然后继续完成任务；必要时修订，有延续价值时再保存。”它不指出哪个案例有错、不透露遗漏位置，也不提供标准答案。

先比较两项：

| 配置 | 行为约定 | 解释 |
|---|---|---|
| A0 | 宿主已有正常流程，保留原有搜索、阅读和保存能力 | 产品基础对照 |
| A1 | 相同能力与总预算，增加统一回查要求 | 条件回查整套策略相对原流程的效果 |

A1 对 A0 的差异包含回查要求及其后续行为，不单独证明某种查询算法有效。两组都在同一预设边界续接任务，A0 仍可自行搜索。

**A2 暂不默认添加。**若 A1 已能自由改写查询，“A1 + 自由改写”没有清楚的新干预。需要比较时，明确唯一变化，例如增加一条跨概念查询生成指令；保留相同工具、反馈机会及总预算，并报告它是提示策略比较。若限制 A1 的原有能力以隔离机制，这一组只能作为受限诊断对照，不能替代完整 A0。

先检查是否完成任务、关键判断是否正确、其他正确内容是否受损、成本是否可接受。来源未找到是查询策略诊断的一个入口；已有检索过贵、返回噪声过多或新任务迁移差，也可以构成入口。不把“普通回查必须先成功”或“只有检索失败才研究 Hint”设成普遍前置条件；先说明具体要改善什么，再做有界比较。

### Prototype-1：再看实际宿主是否用得合适

选择一个实际可观测接入点，比较正常宿主与加入通用机会的宿主。机会内容对有错和无错案例保持一致，不能由离线 gold 决定何时提供。

总任务结果和成本以所有分配运行作分母；再诊断机会是否送达、实际回查比例、需要时是否取得材料、无需额外回查时的负担，以及首次相关判断。

运行前依据当时输入可得信息确定“需要回查”的标签，或使用明示的有限构造案例；有争议就单列。不能看到某组查了以后有收益才反向标为“需要”，也不能把所有未发生修改的检索都称为不必要。

### Prototype-2：最后识别保存本身的价值

在运行前选定具有后续任务的案例。Session N 的两种行为结果可以描述性比较，但直接比较“自行选择保存”和“自行选择不保存”会混入案例难度、证据质量及策略选择差异。

对确实产生记忆变化的同一运行，使用同一个后续任务建立配对重访：

- 分支 U 使用 Session N 之前的持久记忆版本。
- 分支 V 使用 Session N 成功提交的持久记忆版本。

两分支移除 Session N 的临时上下文，固定相同外部环境、任务产物、其他持久载体、模型配置、来源权限、工具和预算。差异只在被比较的记忆版本；需要允许原文再检索时，两侧都允许，并记录实际查询。

这能检验所产生记忆更新对后续流程的作用，包括是否减少重新检索的成本。如果两侧都再次查到同样来源，准确率可能接近而成本不同，不能据此认定保存毫无作用。另设禁止重新检索的诊断可以检查单独保存了什么，但不能代替正常流程收益。

上述配对结果只适用于产生该更新的子集。要评价**选择性保存策略整体**，还须按预先选定的全部后续任务报告成功、没保存、保存失败、错误复发与负面迁移；不能只留下成功修订案例。Pilot 中发现的有用案例可用于调试，但确认性比较应使用独立留出案例。

## 6. 少量指标，明确分母

| 指标 | 首轮定义 | 必须同时报告 |
|---|---|---|
| 关键来源恢复 | 在起点确实缺少已标注关键材料、且存在合格来源的运行中，材料实际被呈现的比例 | 材料是否本来已可见；来源无权限/不可得单列；文档 ID 命中不足以计成功 |
| 当前判断正确/纠正 | 首次相关外显判断的正确率；纠正率仅用于起点已有可核验错误判断的子集 | 无判断、失败、超时、拒绝推进；最终任务进展 |
| 非必要回查开销 | 在运行前标注为已有足够依据的案例中，额外回查比例与成本 | 合理确认性读取可争议；不凭“无修改”判定浪费 |
| 连带内容损坏 | 相对起点，原本正确且仍适用的已标注内容被丢失或误改 | 全部分配运行的损坏率，以及实际修改运行中的条件损坏率；未写入则后者不适用 |
| 跨会话复用 | 后续任务的首次相关判断、完成情况、同一错误复发及负面迁移 | 更新版本配对结果与全部后续任务结果分别报告 |
| 总成本 | 回查、上下文阅读、重写、保存、复核及失败重试的实际调用、token、耗时 | 当前会话与后续会话成本；固定索引/初始化成本另列；未知用量不填零 |

连带损坏是关键防退化指标，当前任务成功与可接受成本同样必须成立。零写入、零行动可以得到很低的损坏率，却不代表方案有用。

首轮逐案例展示配对结果和原始计数，不用少量模板或重复 seed 拼成“大样本”。软件只用 JSON、写作只用 Markdown 时，领域与表示会混在一起；若要单独主张表示泛化，至少对部分相同语义任务做两种表示的配对测试，并注明长度/信息差异。

## 7. 首轮交付与继续条件

最小交付是：一个实际可运行的入口、两个领域的少量案例、独立评测依据、可审查输入/来源/差异/行为记录，以及一份包含失败和成本的结果表。代码测试或固定脚本回放只能证明执行管线，不能冒充真实模型能力结果。

| 观察 | 下一步 |
|---|---|
| 普通回查改善判断，成本可接受 | 先做真实接入与后续任务验证 |
| 查询未取得关键材料 | 有界比较另一条查询策略，检查路线和证据变化 |
| 关键材料已呈现但判断仍错 | 优先检查解释、适用判断或执行环节 |
| 当前正确，但跨会话复发 | 检查选择性保存、提交、下一次上下文装配与重新检索 |
| 修复一处却破坏其他正确记忆 | 缩小修改范围或增加针对性校验，并重新比较净效果 |
| Hint 与普通查询相近且更贵 | 收缩当前 Hint 实现；不扩展成所有 Hint 无效 |
| 正常任务相关错误少 | 降低默认额外开销，压力实验单独报告 |

外显路线标签与找到来源的先后关系是诊断证据；主效果来自事先定义的配对比较，不能事后只挑“看起来有跳跃”的成功运行归因。两组实际路线重叠时，仍可比较所分配策略的总效果，只是对路线差异的解释能力有限。随机条件允许时随机化运行顺序；大规模机制比较与正式统计留待小型闭环有可解释结果之后。

当前判断：v0.2 的方向适合准备小型可行性原型。这是设计审阅结论，实际宿主、效果和生产可靠性仍须由对应运行证明。
