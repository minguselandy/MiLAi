## 3. 新目录：8 个工具

下表为本地候选合同；公网仍未切换。工具参数应由类型模型生成 Schema，不维护另一套手写校验规则。

| 工具 | 默认/核心参数 | 覆盖与限制 |
| --- | --- | --- |
| `milai_memory_search` | `query`；可选 `note_query`、`note_limit`、`previous_context_id` | 并发查合法 Note 与治理来源；不查 Working State，不承诺穷尽原始 Evidence |
| `milai_memory_read` | `target.kind`、`target.id` | 精确读取 NOTE / EVIDENCE / CLAIM；只接受该类型支持的版本、分页和时间字段 |
| `milai_memory_list` | 默认 NOTE；可选 `selection`、`limit=5`、`cursor` | NOTE 支持字面 query/tags；EVIDENCE 支持 source_type/subject_id 精确过滤；两类分页不混用 |
| `milai_memory_save` | `content`、`operation_id`；可选 `options` | 默认 ADD_NOTE；UPDATE_NOTE 需要 ID 和当前版本；CAPTURE_EVIDENCE 需要来源合同及 CAPTURE |
| `milai_memory_delete` | `target`、`operation_id` | NOTE 逻辑删除；EVIDENCE 撤销；不支持 Claim 删除或全命名空间清理 |
| `milai_memory_status` | `target.kind` 及对应标识 | NOTE_WRITE 查持久回执；EVIDENCE_DELETION 查删除阶段；不伪造通用异步任务 API |
| `milai_working_state_get` | `scope`，默认 TASK | 读取已有作用域检查点；SESSION 不等于跨 session 历史 |
| `milai_working_state_update` | `operation_id`、`expected_version`、`payload` 等 | 保存任务检查点，继续已有版本保护和可信绑定，不充当普通 Note |

保留两个 Working State 工具，因为检查点有作用域、过期和恢复生命周期，不能与普通长期笔记混为一谈。
读、写、破坏性动作继续分工具，保证 MCP 风险提示准确，不做一个混合所有动作的万能工具。

高级功能仍在 `ordinary-memory-v1` / 既有角色目录中：Proposal、Review、治理诊断及管理员能力按原边界开放。
新目录不静默改变旧 `milai_memory_get` 的 Canonical 语义，因此使用新名称 `milai_memory_read`。
旧目录兼容不意味着精简目录接受旧名称；即使缓存客户端持有全部 scope，未注册旧工具也必须拒绝调用。

### 3.1 最常用的调用

保存普通记忆，不必填写 Evidence 来源字段，也不经过审批：

```json
{
  "content": "用户希望先恢复简短任务状态，需要细节时再回查来源。",
  "operation_id": "note-save-example-001"
}
```

以上为 `milai_memory_save` 的示例参数，不是要执行的真实写入。返回的 Note 引用应直接可调用：

```json
{
  "read_tool": "milai_memory_read",
  "read_arguments": {
    "target": {
      "kind": "NOTE",
      "id": "00000000-0000-4000-8000-000000000099",
      "version": 1
    }
  }
}
```

修改同一 Note，仍然使用 `milai_memory_save`：

```json
{
  "content": "更新后的完整笔记正文。",
  "operation_id": "note-edit-example-001",
  "options": {
    "action": "UPDATE_NOTE",
    "memory_id": "00000000-0000-4000-8000-000000000099",
    "expected_version": 1
  }
}
```

明确需要记录来源观察时，才选择同一工具的 Evidence 分支：

```json
{
  "content": "Synthetic observation: runtime.port is 6432.",
  "operation_id": "evidence-save-example-001",
  "options": {
    "action": "CAPTURE_EVIDENCE",
    "source_type": "AGENT_TURN",
    "source_ref": "manual://synthetic-example/turn-1",
    "subject_id": "synthetic-subject",
    "observed_at": "2026-09-08T00:00:00Z",
    "confirmation": "CAPTURE"
  }
}
```

所有示例只含合成内容；真实调用必须使用真实来源与当前任务授权。统一入口不能替调用者编造历史时间、
用户原话或授权。普通 Note 不需要为简化调用而假装成 Evidence。

## 4. 不可改变的语义与权限

### 4.1 对象、版本和删除

- Note：精确保存 Host 提交正文；当前正文可追加新版本；省略更新元数据保留原值，空数组才表示清空。
- Evidence：来源观察、非正式真理；不可原地改写；修正需要显式记录新观察，不能把 UPDATE_NOTE 套到 Evidence。
- Claim：依旧由受治理的正式流程产生；搜索、复制、保存和统一读取都不能自动批准 Claim。
- Note 删除：当前明确意图 + 当前版本 + DELETE；所有版本不可读取，历史仍留存，物理删除不支持。
- Evidence 撤销：当前明确意图 + reason_code + REVOKE；权限/派生披露门槛立即生效，物理清理和备份另报状态。
- Note→Evidence：本 Goal **不实现自动转换或提升**。将来若需要，必须明确 Note ID/版本/摘要及来源关系、
  撤销传播和重复计证边界；手工复制正文不能冒充已经存在的系统级依赖关系。

### 4.2 共用工具不能共用一把权限钥匙

| 统一入口中的动作 | 仍需检查的原 scope |
| --- | --- |
| Note 保存、修改 | `milai.note.write` |
| Note 读取、浏览、写入回执 | `milai.note.read` |
| Note 删除 | `milai.note.delete` |
| Evidence 采集 | `milai.evidence.capture` |
| Evidence 精确读取、浏览 | `milai.evidence.read` |
| Evidence 撤销 | `milai.evidence.revoke` |
| Claim 读取、治理检索、Evidence 删除状态 | `milai.memory.read`，保留当前能力合同 |
| Working State 读/写 | 对应 `milai.state.read` / `milai.state.write` |

目录可因持有任一合法分支的 scope 而显示统一工具；**执行时按选中的分支再次鉴权**。
搜索两个分支独立检查，无权限分支为 NOT_AUTHORIZED，不能伪装为空历史。
主体、项目、角色及私有绑定继续来自可信 OAuth/Host 上下文，模型不能通过参数自报或扩大。
已有 Runtime operation-ID 命名空间继续使用，换工具别名不应使同一次合法提交重复落库。

### 4.3 错误与返回内容

- 公共原则放入 initialize instructions，工具描述只写自身用途与关键限制；完整分支 Schema 不出现 `unknown`。
- 版本冲突：`retryable=false`、READ_AND_REBASE，下一入口为统一读取，不自动增大版本覆盖。
- 未知提交：保留原 operation_id；Note 指向统一状态查询。缺少回执或当前 head 不等于某次在途提交失败。
- 没有独立的 Evidence 采集状态 API，必须如实说明；不得把 Evidence 删除状态查询冒充采集回执查询。
- 搜索结果、保存回执、错误恢复提示使用精简目录中的可调用名称；保留对象类型、权限、版本和删除阶段。
- 仅适配服务器生成的引用/提示结构；不递归改写用户正文、Claim payload 或 Host 声明的 source_refs。
- `suggested_next_step` 为可选数据，不授予权限；不向普通保存结果附带自动建 Proposal/APPROVE 的流程要求。

## 5. 跨 session 检索是独立验收项

必须验证下面这条链，而不是仅证明“保存后同一进程 GET 成功”：

```text
会话 A 明确保存 Note → 结束客户端进程
  → 会话 B 仅获得新问题和同一合法身份
  → memory_search 发现历史 → 按返回引用 memory_read → 核对续做所需约束
```

会话 B 不预置 memory_id、旧 cursor、完整历史或答案；通过查询结果获得引用是合法的正常路径。
任务检查点和长期 Note 各自核验，不能把固定 TASK 绑定复用当成所有跨 session 检索的证明。

首轮不改 Note 字面匹配算法、不增大默认返回量、不增加语义 Reader。具体安排：

1. 通用历史问题用 `memory_search`；必要时将当前问题保留在 query，另给一个短字面 note_query。
2. 命中后优先读精确引用；长正文固定 Note 版本后按 offset 续读，来源引用按 source_offset 单独分页。
3. Note 继续查找用 `memory_list(selection={kind: NOTE, query: 原字面词}, cursor: 原游标)`；
   治理检索使用其 context_id 继续；两种游标不互换，不将旧会话 cursor 当身份或永久快照。
4. 未命中只说明这次有界查询结果；有明确线索时允许一次有针对性的补查或一小页浏览，不默认列 50 条。
5. 来源无权、不可用、超时和真正空结果分开报告。相对日期按问题时间与用户时区解释，存储时间不冒充事件时间。
6. 换用户、撤销来源、删除 Note 后，旧引用和历史版本仍必须受当前可见性门槛约束。

若精简后仍漏检，先定位：目录/选路、词面查询、权限、来源资格、片段呈现或行动消费。
只有定位到具体检索能力缺口，再提出独立算法增量；工具改名不等于语义召回优化完成。

## 8. 成本与调用体验评价

默认新增付费模型请求 = 0；本地 vLLM 请求 = 0。C0–C4 以真实 MCP 协议和工程测试验证，不启动自动总结、
embedding 外部付费服务、独立 Reviewer 或每轮维护。已有本地模型进程存在不代表本 Goal 可使用其预算。

分别记录，不混成一个总分：

- 工具数：22 → 8；同时记录实际 scope 下的可见工具数，不能靠取消用户所需权限制造“精简”。
- 目录开销：相同序列化方式下 tools/list 与 initialize instructions 的 UTF-8 字节数；
  如使用特定 tokenizer，注明名称和版本，不能用字节比例冒充实际模型 token 节省。
- 交互开销：普通保存所需参数数、协议调用数、参数纠错次数、失败及拒绝次数、正文返回量。
- 执行开销：端到端耗时与服务侧耗时分别记录；新目录不新增后端模型调用或隐式重试。
- 检索可用性：可调用引用比例、正确对象类型、来源状态和首个相关续做动作；不以调用次数越少越好。

本地测试已检查精简目录序列化体积小于旧目录，但**精确字节、token 与真实调用净成本尚待记录**。
产品路径不强制每次保存后再 GET；验收中的额外读取属于测试取证，必须与产品成本分账。

真实模型选工具能力如需验证，应在 C4 后单独批准一个小型本地 vLLM pilot：固定相同任务和资料，
比较旧/新目录的普通保存、编辑、来源采集、跨 session 读取、删除和错误恢复六类场景。
先预检模型实际支持的 tool schema 和上下文容量，再约定总请求/token/时长上限；所有失败、未调用、
超限均进入分母，不无限重试。不在本 Goal 自动授予该 pilot 额度，也不将模型 pilot 与 PG 验收混淆。

## 9. 交付物、终态与停止条件

应交付：ADR、生成的精简目录合同/快照、适配代码、协议与真实 PG 测试、普通/高级目录使用说明、
同一候选版本的包及摘要、目标入口切换和回退记录。不存在的产物记为待做，不能只列文件名宣布已交付。

终态分开：

- `LOCAL_READY_FOR_RELEASE`：C0–C4 完成，尚未证明公网或目标宿主可用。
- `COMPLETED_COMPACT_MCP_USABLE`：C5 获准并完成，目标连接上合成对象的保存—冷发现—精确读取—维护闭环通过；
  单独注明是否有真实模型选工具验证，不能从协议成功推导长期收益。
- `BLOCKED_NEEDS_AUTHORIZATION`：当前下一必要动作需要发布、真实身份交互或业务写入授权；停在安全边界并列出所需决定。
- `KEEP_EXISTING_CATALOG`：新入口出现安全/兼容回归，或实际使用更难；保留当前公网目录与所有数据，不强行切换。

任一越权、来源撤销后正文泄漏、幂等重复提交、静默覆盖、伪造持久化成功为硬失败。
工具数更少、测试总数增加或 UI 更好看均不能抵消这些失败。
没有获得 C5 授权时交付本地候选即可，不把“公网未改”当作需要绕过的障碍。

回退只选择既有目录或恢复先前固定版本服务；不删表、不迁移记忆、不改 OAuth subject、project、scope。
回到高级目录会恢复其更多工具展示，仍受原有权限控制；需刷新客户端目录，不假设旧缓存自动消失。
