当前核验到的[官方目录说明](https://github.com/icedreamc/STALE/tree/main/STALE)明确提供

公开仓库[LICENSE](https://github.com/icedreamc/STALE/blob/main/LICENSE)标 MIT，

因此 STALE 的进入条件是：固定数据可定位并核验、来源使用条件清楚、可运行输入与语义评分路径就绪。

## 3. 前瞻准入合同：先冻结过程，再得出 accepted IDs

### 3.1 两次封存，解决资格审查与禁止补题的冲突

**Seal A：在资格正文审查与任何答案生成前封存抽样过程。**
允许先做发布/目录/元数据 inventory；不先看具体答案挑“最适合 State”的候选。

必须包含：

- Goal/合同版本、官方 repo commit、dataset revision、所需文件 hash、代码/数据许可状态；
- 候选 ID universe、配置/子集/变体、cluster 与来源 lineage 的构造规则；
- 旧 exposure/protected manifest 的版本、受控去重方法、审查允许读取的字段和责任角色；
- discovery/confirmation 分区、排序 seed、序列化/hash 规则及并列规则；
- eligibility predicate、全部拒绝码、未确定项处理和 pool-level 就绪门；
- 每 cluster 的 probe/题目选择方法、分层配额、accepted 目标和最低可运行批次；
- 最大筛查数、资格审查劳动/工具成本、超时、池耗尽、提前停止与继续规则；
- A0 profile、完整来源/输入资源合同、评分模板和执行分配建议。

**Seal B：在首个实验生成前封存该运行的接纳清单与逐题评价合同。**
按 Seal A 筛查，得到最多目标数量的 accepted clusters；不要求必须凑满。
记录每个拒绝、未确定、未筛查位置及接纳证据；同时完成 source/evaluator preflight。
后续小波次只用 Seal B 的固定前缀；不是一边看 A0 成败一边重新解释资格。
若要增加 accepted 目标、换数据/seed/资格规则或重新开放 UNKNOWN，建立新的 prospective revision，
保留旧分母；不能原地改 manifest 或承接旧候选的“未使用余额”。

### 3.2 资格判断只使用答案运行前可知的非效果信息

| 可用于 eligibility | 不可用于 eligibility |
| --- | --- |
| 模态、文件完整性、格式、工具要求、来源可用性 | “看起来容易错”“像 v0.5 的对象绑定错误” |
| 固定资源上限、输入构造能力、许可与分区权限 | A0 是否正确、某提示能否救回、预期收益 |
| 既往调参暴露、同源近重复、可核验的 cluster lineage | gold 的具体值、正确选项、旧/新状态的具体答案 |
| 已冻结的官方能力/题型元数据与 probe 完整性 | 根据答案语义重新分层、筛掉不支持假设的题 |
| 有无可用 evaluator/参考字段，契约可否执行 | 看了输出才决定换评分器或判题尺度 |

资格端只接收评价“可执行/缺失”的状态，不接收 gold 文本来选择题目。
数据解析器可机械读取长度/hash/字段；去重审查必要时看合法来源/问题，但不因 semantic difficulty 排除。
标准语义题的评分若需要人工，须事先具备该路径；不能以“难评分”选择性留下更简单的题。
没有统一 evaluator 属于 pool/stratum-level NOT_READY，不循环筛到偶然可字符串判定的个例。

建议拒绝/挂起码：PROTECTED_PARTITION、EXPOSED_TASK、NEAR_DUPLICATE_SOURCE、
EXPOSURE_UNRESOLVED、CLUSTER_UNRESOLVED、LICENSE_UNRESOLVED、SOURCE_UNAVAILABLE、
CORRUPT_DATA、MODALITY_UNSUPPORTED、RESOURCE_INFEASIBLE、REQUIRED_PROBE_MISSING。
未知暴露可按预定规则隔离并继续，但不自动视为合格；“与冻结的 MiLAi 暴露索引未发现重叠”
是有限保证，不要求证明全世界/预训练绝未见过。共享无关 filler 不是自动判为同一任务的依据。
发现池资格审查打开过的样本均留暴露记录，不能转入确认集，即使没有发生成请求。
既往排除以 Seal A 封存的暴露快照为准；本轮按合同进行的隔离资格/评价审查记 REVIEW_OPENED，
不把这种必要审查误算成“候选刚被审查所以立即失去 discovery 资格”。若其内容被用于修改提示/方法，
则记 TUNING_EXPOSED，不再作为该修改后方法的独立确认；在线 Host 始终不能读取审查或评分材料。

### 3.3 Cluster-first 划分与确定性排序

| 测试床 | 最小分组单位 | 必须关联的变体 |
| --- | --- | --- |
| STALE | 底层 scenario / conflict pair | SR/PR/IPA、历史长度版本、同源改写 |
| HorizonBench | user / timeline | 同用户全部题、同源跨生成器变体 |
| FactConsolidation | 独立源历史/事实宇宙 lineage | 多 QA、重叠长度切片或事实变体 |
| 后续行动/新鲜任务 | memory chain / task group / trajectory-seed | 同一前置经历派生的全部任务 |

按 cluster 先分区，再在 discovery 内顺序接纳。建议确定算法：

```text
hash_input = UTF8(JSON_COMPACT_ARRAY([
  goal_id, contract_version, benchmark_revision,
  purpose, canonical_cluster_id, seed
]))
digest = SHA256(hash_input)

purpose="split": 按 (digest, cluster_id) 排序；
前 floor(2*N/3) 个 cluster 属于 discovery，其余属于 confirmation。

purpose="admission": 仅在 discovery 中重新排序，作为资格筛查顺序。
purpose="probe": 同一 cluster/预注册题型内按同样规则排序题目。
```

JSON 紧凑格式、UTF-8 编码与 canonical ID 规则必须固定并纳入复算测试，不能使用进程随机 hash。
本次已在独立 Seal A 落实 seed `v0212-20260909-r1`、真实 universe/hash；
254 个 metadata 关联 cluster 先排除89个旧保护/暴露组，再将165个允许组分为110 discovery/55 confirmation。
按 Type I/II、evolved/static 等公开元数据分层时，先固定 quota/轮取顺序；空层如实不足，
不能转移配额。cluster 数很少或来源关联不明时，不承诺存在有意义的独立确认集。

confirmation 只可暴露分区所需中性 ID/元数据；正文、gold、来源派生控制信息保持封存，
不预先做逐题语义评分或用其调试解析/提示。机制与确认合同冻结并获准后，才对该分区走同样准入。
后续发现跨分区同源/泄漏时隔离受影响 cluster，公开修订与损失，不挑一个替代样本悄悄补齐。

### 3.4 顺序接纳与分母

```text
for cluster in frozen_discovery_order:
    if screened_limit / review_budget / wall_clock reached: stop
    check frozen eligibility without any model answer
    if reject_or_unresolved:
        record reasons and evidence; continue
    accept cluster and its preselected probes
    if accepted_target reached: stop
seal accepted manifest and evaluation contracts
run only explicitly authorized prefixes
```

ACCEPT 前不合格沿队列继续，是已注册抽样的一部分，不是替换运行失败。
**ACCEPT 后的超时、格式错误、实际来源未取回、组装遗漏、答错和提交失败留在接纳分母中；
即便后来发现漏过的资格问题，也记录 ADMISSION_ERROR，不反向删除或补入新题。**
不能用 retry、变更 seed、换模型、改 top-k 或跳过高成本已接纳题保持“全过”。

同时报告 cluster 与 query 两级：pool、protected/reserved、screened、accepted、rejected、
unresolved、not_screened、attempted、valid、scored、correct/incorrect/disputed/not_run。
筛查不消耗实验回答额度，但会产生元数据/人工或授权审查成本，必须单列，不能写成总成本为零。

## 4. 样本目标与 lane 选择：小批次，不运行新混合总分

以下只是 discovery 的覆盖上限；confirmation 不计入，也不保证池内有足够合格 cluster：

| 池 | accepted 目标上限 | 每 cluster 查询 | 首个小波次 | 筛查 cluster 上限建议 |
| --- | ---: | --- | --- | ---: |
| STALE | 12 scenarios，Type I/II 各至多 6 | 3 个官方 probe | 2 scenarios，各类型 1 个；共 6 probes | 60 |
| HorizonBench discovery | 12 user clusters | 预选 evolved/static 各 1 题 | 2 users，共至多 4 题 | 60 |
| FactConsolidation sanity | 2 独立源 clusters | hash 选 2 题 | 至多 2 sources / 4 题 | 冻结 discovery 候选全集，不扩入其他 MAB 组件 |

最小可运行批次：STALE 为上述 2 个场景，Horizon 为 2 个用户，FactConsolidation 可为 1 个源/2 题。
单源 sanity 只能查接线与该历史的使用，不能支撑跨 cluster 结论；不为了满足两源目标拆分同源变体。
Horizon 的 evolved/static 是预注册题型覆盖，不根据具体偏好/gold 挑题；缺配对者按既定规则记录。
STALE 三 probe 分别从相同不可变历史冷建 query scope，SR 的回答/自发保存不得帮助 PR/IPA。
同样，Horizon 同用户多题及 FactConsolidation 共享源的多 QA 不共享此前答案或可写工作状态。
可复用不可变来源/索引，但每 query 的请求、生成、写入和冷/热条件独立记账。

在 Seal B 和任何效果结果之前，按以下就绪条件选首个 lane，并记录原因：

1. STALE 固定数据、来源、许可、评分和 A0 路径全部就绪：优先 Lane A / STALE。
2. 否则，Horizon discovery 的数据、无 Judge 评分和来源访问就绪：可作为 Lane A 起点，
   但不打开其 confirmation user clusters。
3. 若前两池不就绪，FactConsolidation 合格则只做 Lane B sanity；不把其通过算 State 机制确认。
4. 都不就绪则交付具体 pool-level 阻断，停止；不自动生成新数据、解封 LME 或新增付费 Judge。

这是可用性/成本驱动的预注册路由，不是看哪套 benchmark 分数有利就选哪套。
一旦该 run 产生模型结果，不在同一分母内替换主池。进入另一 lane 须使用其独立清单、预算和结果表。
首批全部正确而无 use failure，可有限 KEEP_BASELINE；若有 presented-but-wrong，
按已封存前缀再开一个同大小小波次确认；无新增独立同类失败即停，不为用完目标数继续。
达到 §8 候选门时先报告，不自动运行 S1/S2 或开启所有剩余 lane。

## 5. 输入与 Product 边界：可用来源不等于已呈现证据

### 5.1 A0 配置与非语义摄取

复用 V02-11 已验证的源文件、分页读取、身份隔离与账本思路；按 artifact hash 验证适用性，
不宣称换数据后所有检查自然通过。Lab 只增加薄 adapter/runner，不改 Product Runtime、
检索算法、8 工具、权限、业务 State schema，不移植 CUPMem 或其他 Memory Store 作为 MiLAi 架构。

默认候选 profile 为 **A0_MCP_BOUNDED_SOURCE_DIAGNOSTIC**：一个本地 Host，
正常 compact MCP 工具＋冻结的合法源文件读取，最多 3 次生成完成首次回答。
固定模型/tokenizer、system/tool 提示、普通检索策略、分块/排序/返回上限和输入装配。
原始历史完整可访问，不使用 gold 抽取关键句、State projection、额外语义 Reader 或自动总结。
常规有界检索不等于由 Control State 隐藏合法材料；检索未取回支持是可测失败，不是准入淘汰理由。

完整历史直接输入若超出限制，不能截断后冒称 full-history；选择工具检索 profile 必须在生成前固定。
这与官方整段输入/增量写入协议可能不同，结果明确标 NONSTANDARD_LOCAL_DIAGNOSTIC。
如果只用源文件而没有使用 MiLAi 记忆对象，要如实记录，不把普通文件能力当 MiLAi 的独立净收益。

原始历史→Note/Evidence/源文件只允许机械去评价字段、分块与封装；保留正文、时间、角色、
修订顺序、关系和可精确定位的版本。MCP search 不等于全量 Raw Evidence/Working State 搜索。
不能自动批准 Claim 或增加提示，把检索缺口修成“State 有效”。

### 5.2 两级来源就绪，避免循环门禁

生成前检查 SOURCE_READY：原件/分块完整、合法路径覆盖、序列化/图片合同和预算可执行。
它不要求模型已经回答，也不以 gold 命中为门；固定替身只证明机械接线。
首个获准的正常回答请求记录实际 payload，据此判 PRESENTATION_VERIFIED / ASSEMBLY_LOSS / UNKNOWN，
不额外调用模型做兼容探针。实际呈现不等于模型理解；理解失败只能依据公开输出判定。
不兼容、不确定和运行失败留在准入/执行各自分母，不能混成已呈现后使用错误。

### 5.3 隔离、授权与三类写入

沿用现有持久 operation_id、幂等/CAS 与服务端可信 scope；重放不得改 ID 或绕过确认。
Lab 账本分类分别为 HARNESS_INGEST、SYNTHETIC_BACKEND_PREFLIGHT、AGENT_MEMORY_MUTATION，
不是新 Product operation 枚举。准备、工程测试写入与 Host 自发保存成本不能混账。
源底座不可被 Host 改写；每个 probe/query 的写回位于隔离域，不流入其他题或 confirmation。
题目/历史内的工具指令和 URL 只是数据；不得实际登录、下单、改远端项目或调用真实业务 API。
teardown 只处理明确获准、本次拥有的合成 scope/进程；记录逻辑隔离与物理保留，
不默认全库清理、删除旧数据、重启共享 vLLM 或变更公网。没有清理权限不影响保留隔离审计快照。

## 6. 生成前冻结评分，Judge 不随 benchmark 默认启动

Seal B 每道题的离线 evaluation_contract 必须有官方 answer/reference 版本、evidence 定位状态、
评分模式/解析器版本、完整正确性、拒答、争议、责任角色及成本；缺官方证据标 NOT_PROVIDED，
衍生定位不得伪装成官方 gold。不可用时停止该 pool/stratum，不先运行一批再补评分方法。

| 池 | 答案评分 | 必须单列的限制 |
| --- | --- | --- |
| STALE | 固定语义 rubric，人工裁决；其他模型审查须另行授权和计量 | 官方自动 Judge 未启用；SR/PR/IPA 不可用关键词通过代替语义判断；IPA 仍是回答 probe，不是真实工具执行 |
| HorizonBench | 固定官方 letter parser＋correct_letter 比较 | 另报格式歧义与旧选项选择率；离线图仅用于归因，不注入 Host |
| FactConsolidation | 固定 substring_exact_match | 包含正确值又并列旧值可能仍命中；另记矛盾/无依据采用，未具备语义裁决时标 UNKNOWN，不能称完整关系理解通过 |

正确性与最早可证实失败层分开：官方规则得分不覆盖 local semantic dispute，后者也不能悄悄改官方标签。
CORRECT / INCORRECT / DISPUTED / UNSCORED 分别保留；无首次输出的传输失败不冒充语义错误。
拒答或已交付格式错误按冻结规则评价，不作为无效样本删掉；只报告已裁定 C/(C+I) 时同时报告评分覆盖。
若评分协议需事后修订，原合同、原结果和修订后结果并列，标 post-hoc，不能只重评对候选有利的题。

本地 Judge、subagent 审查、人工劳动都不是免费在线能力。用户已明确授权 subagent 替代人工，
本次资格及来源审查标 MODEL_ASSISTED_ADJUDICATION，成本与 benchmark Provider 分开，
不声称独立人类 gold。实际 benchmark 生成10次，benchmark Judge及语料生成调用为0；
没有执行官方一键脚本或继承其外部 API/自动重试配置。

## 7. 增量开发顺序与成本上限建议

### 7.1 交付顺序

| 阶段 | 交付 | 进入下一步的条件 |
| --- | --- | --- |
| P0：Pool readiness，零实验生成 | 固定数据/许可/模态/评分路径，历史暴露索引，至少一个可评估 lane | 不以 README 规模代替真实 inventory；没有就绪池则停止 |
| P1：Prospective admission，零实验生成 | Seal A、确定排序/分区、筛查账本、Seal B 与逐题合同 | 足够支撑最小批次的合格 clusters；未满目标允许按预定最小批次执行 |
| P2：最小 A0 首波 | 正常来源→实际 payload→首次答案→评分/归因/成本 | 运行有效；错误留在分母，不新建 State 机制 |
| P3：有界复现或停止 | 固定前缀的额外一小波、分层结果与决定 | 仅在获准预算内并有可复核 use failure 时继续；无新增独立复现即停 |
| P4：条件性机制/确认规划 | 最小自由 State 对照和未打开确认合同 | §8 有证据才提出；本轮不实施 |

不先同时建设三套完整后端。P0 的 pool-level 调查到足以确认可用/阻断即可，
不为寻找十二个合格题无限做人工审查或下载全量历史。

### 7.2 先授权一个首波，不自动分配所有 lane

**本次只选 Horizon 首波，并按 §4 的已裁定 presented-but-wrong 条件另立一波复现分配。**
两波上限各12次/80,000 raw，实际各5次/34,454与34,871 raw；下表保留互斥起点合同，未相加执行：

| 可选首波 | 接纳 cluster | queries | Host 生成上限 | raw token 上限 |
| --- | ---: | ---: | ---: | ---: |
| STALE | 2 scenarios | 6 probes | 18 | 120,000 |
| Horizon discovery | 2 users | 4 MCQs | 12 | 80,000 |
| FactConsolidation sanity | 至多 2 sources | 至多 4 QA | 12 | 80,000 |

每 query 至多 3 次 Host 生成、6 次有界工具调用（含普通记忆 mutation）、20,000 raw；

禁止隐式重试、自动换模型、未计量 embedding/rerank/summary/Judge。
单实验在途上限只控制模型消费，不限制 Product 正常并发读取。

最大 discovery 目标也只是覆盖上限：STALE 12×3＝36 probes、Horizon 12×2＝24 MCQs，

## 8. 失败证据与研究决策

按 pool/profile/cluster/probe 分表保留以下链路：

```text
admission → availability → acquired → presented → use/applicability → answer
```

不能取得来源则定位 acquisition；取得未呈现则定位装配；只有必要支持实际呈现、
答案经冻结规则判错，才讨论 relation/applicability/control-use。日志缺失标 UNKNOWN，不猜内部注意力。
旧项被选中、格式合格、提到了对象或来源，都不能单独证明正确/错误的完整使用链。

**Mechanism candidate gate**：至少 3 个独立底层 clusters，跨至少 2 个预注册任务族/主题域，
重复出现有支持的关系/适用性错误；同场景 SR/PR/IPA 不凑 cluster 或异质任务数。
这最多允许提出 S1/S2 小 pilot；不需要为了达门人为拆分 FactConsolidation 历史。

**Core research signal**：还需未打开确认集重复、强简单对照成立，并有 STALE 之外的异质证据。
公布 relation/applicability failures 在 support-presented-and-wrong 中的 n/N、完整 failure taxonomy、
准入损失与停止规则；专门冲突 benchmark 的比例不能解释成普通工作流发生率。
没有行为观察是未测，不是无效；没有合格 signal 就保持 A0，不建设 binding Schema。

如需第二阶段，只提出同样合法材料/预算下 A0-review、S1 自由记录、S2 自由关系上下文的公平比较，
保留 A0 单轮成本参考、自然关系保留率、候选污染和负迁移；指令领域无关，不暗含发现集答案。
只有自由表达的帮助先被验证、残余问题仍指向表示，才考虑最小结构或动态持久化的后续合同。
内部信号之后还需直接近邻强对照；本 Goal 不自动启用这些方法或将 QA 改善等同于真实行动收益。
