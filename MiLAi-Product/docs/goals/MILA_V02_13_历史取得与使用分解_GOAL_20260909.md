### 3.1 成本拆解必须避免重计

按每次请求及整个 query 输出账本：

| 输入/输出组成 | 观测 |
| --- | --- |
| 固定 system/协议 | 首次出现、后续重复发送的 token/字节 |
| 记忆工具与 source 工具定义 | 每类 schema/描述及重复发送；与业务任务工具 schema 分开 |
| 初始历史视图 | 实际页、大小及重复出现，不用全文体积代替实际输入 |
| 后续来源/工具结果 | acquired、presented、尚未发送分别计数 |
| Host 历史输出与消息包装 | 可见控制 JSON、重复历史、角色模板和格式包装 |
| 本次生成 | 实测输出及输出预约；未知 usage 不填零 |

“内容类别 × 首次/重复”的交叉表保证同一 token 不被既计 history 又计 repeated context。
分块单独 tokenization 与完整输入可能不相加；以完整实际 payload 的计数为准，
分项归因须公开方法及边界残差。计费缓存、网络压缩、客户端复用不能从 raw-token 分母中直接扣除。

### 3.2 对未发第三次请求做机械预约复算

从已保存消息和工具结果恢复当时本应发送的完整第三次 payload，包括最后的交付提示与 schema。
逐项核验“为什么停”，并计算：

`headroom = 20,000 - 已结清 raw - tokenize(完整下一请求) - 1,024`

未发送的输入/输出不是实际消费。若重建材料缺失，标 REPLAY_INCOMPLETE，不生成一个想象的下一步补齐。
这一步能证明预算可否预约，不能证明第三次本来会答对。

### 3.3 允许提出的最小 Host 候选

先检查是否存在重复序列化、无效冗余包装、重复公共说明或未有界返回等机械问题。
在不删除合法历史、必要工具约束、来源标识、授权边界的前提下，最多冻结一个 compact 输入候选并重算成本。
仅把工具放到 system、改 SDK 缓存位置或开启网络压缩，不代表服务端少计输入。
不能不再发送工具定义却假定无状态模型仍知道它们；不能通过删真实证据/工具能力提高表面成功率。

任何改变模型可见文本、工具目录或交付调度的候选都另标 **H0_COMPACT / HOST_DELIVERY_CANDIDATE**，
保留原 A0，不回填原预算停止。零生成回放只给 MECHANICAL_HEADROOM_ESTIMATE，
行为正确性须后续独立有界比较，不能直接宣布成本优化不影响质量。
本 Goal 不预授权任意 Host/检索优化；先交付原因、候选和验证范围，不顺带修改 Product。

## 4. 三条件诊断合同

### 4.1 共同起点与不同取得方式

对每个已接纳任务，冻结同一完整合法历史 H、问题 Q、普通初始视图 V、来源版本、
业务工具定义、模型/采样、回答合同与证据输入预算。三条件均从独立、等价作用域开始，
不共享别组回答、查询产物、自发写回或 Oracle 选择信息。

| 条件 | 历史取得方式 | 主要回答的问题 |
| --- | --- | --- |
| A0_AUTONOMOUS | 正常 Host 自主决定是否查、查哪里、查什么 | 当前有界自主工作流怎样取得和使用历史 |
| R1_FIXED_RETRIEVAL | 预注册、非 gold 的机械取得；随后同模型一次回答 | 不依赖模型选择检索调用时，强简单路径能否取得有用材料 |
| O_EVIDENCE_ORACLE | 离线 evaluator 选原始支持片段；随后同模型一次回答 | 在已核实充分支持下，答案/参数是否仍错误 |

共同的是历史、能力边界和任务；**实际呈现证据并不相同**，这正是实验变量。
A0 有选择/取证生成，R1/O 没有这些生成；这不是等推理机会的机制试验。
保持相同 Reader 模型、业务输出 schema 和来源格式，记录全部提示、工具定义与上下文长度差异。
R1/O 的单次 Reader 是明确实验条件，不是隐藏在 A0 内的第二个 Reader；A0 不追加修复调用。

### 4.2 来源承载必须明确，不能继续把空库当历史检索

每个 run 出具 `source_binding_manifest`：H 存在哪里、哪些接口覆盖它、Product 是否已摄取，
只做中性的来源入口说明，不给 gold 路径或题目专属检索建议。

- 若历史只放普通源文件，标 SOURCE_FILES_ONLY；A0/R1 必须拥有相同合法原件访问范围。
  空 Product 的 MISS 只描述该分支，不能算完整历史不存在或 MiLAi 检索效果。
- 若要验 Product memory_search/read，须在生成前以公开接口机械导入完整许可范围的 Note，
  核对数量/版本、可读性及 query-blind 测试；不得自动 approve Claim 或做语义总结。
  标 PRODUCT_NOTES_WITH_SOURCE_BACKSTOP，并为所有条件提供同等来源与授权起点。
- 两种承载不能在结果中混成同一 profile；第一轮优先复用普通源文件做低成本分解。
  这不证明 Product retrieval 净收益；Product-backed 后续测试要有非空、同内容的强简单对照。

所有 source ingest、工程 preflight、自主 memory mutation 分账；原件不可变，写回按任务/arm 隔离。
元数据配置必须诚实区分已有 Note、工作检查点与原始历史，不用一次全局“memory MISS”覆盖所有范围。

### 4.3 R1：一个预先固定的非 gold 强简单候选

默认规划为 **R1_RAW_LEXICAL**：Lab 的机械原文检索，非新的 Product Memory Store。
P1 在打开实验结果前固定一个版本，不同时尝试多套政策后挑最有利的一套。

1. H 若可完整装入共同证据预算，直接读完整 H；否则按普通 session/turn 顺序和固定 token 大小分块。
   建议上限 1,024 tokens/块、重叠 128；保留原始 byte/span/version 对照，不按答案分块。
2. query 只来自当前 Q、Q 内明示的字面实体/标识符，以及任务本来提供的工具名称/参数名。
   若使用工具定义，按同一规则处理所有合法候选，不借 target answer 选工具；词法规则/stoplist 锁 hash。
3. 使用冻结的纯词面 BM25 配置，建议 k1=1.2、b=0.75；不做 LLM 改写、embedding、语义 rerank 或 synonym 扩充。
   取 top-k，建议 k=4；并列按中性来源 ID/offset，重叠去重，保留完整所选片段与引用。
4. 从同一读取接口取原文，按预定顺序装配；证据预算建议 ≤4,096 tokens，且完整 Reader 输入 ≤8,192。
   超限只按事先规则停止加入低序片段并标记遗漏，不根据 gold 优先保留，也不半截裁掉否定或时间条件。
5. 无命中仍记录空返回，不看答案改 query、扩大 k、增加轮次或改用另一模型“救活”。

这些参数是待冻结的实验默认值，不是已经实现/证明最优的检索配置。
只要 R1 与 A0 实际使用的 backend/排序不同，A0−R1 比较包含检索政策差异，
**不能单独归因为 tool selection**。必要时将 A0 已产生的 query 在相同 backend 上做零生成检索回放，
或将冻结 R1 query 送入 A0 的同一合法入口，比较证据覆盖；这不新增答案，也不改变原轨迹。
旧“前 16 个字面命中”结果不得改名为 BM25；Lab 原文排名不得宣称 Product 已升级。

### 4.4 O：支持充分性诊断，不泄漏标准答案

Oracle 在任何该批模型输出产生前由离线评价侧准备；允许用 gold/reference/grounding 标签定位，
但模型只见 H 中真实原文、普通时间/角色和中性引用，不见 gold 参数 JSON、答案摘要、
“这就是正确来源”标签、解释图或人工控制 State。

片段应保留使对象、时间、否定、条件、旧新冲突与必要关系可解释的上下文；
不能只抽出一个正确值，掩盖完整任务仍有歧义。历史中本来存在的真实工具调用可保留为历史数据。
预先记录充分性、替代证据组合与可裁定范围；同样受 Reader 输入预算限制。
若支持无法在预算内完整提供、参考冲突或定位未核实，记 ORACLE_INVALID / ORACLE_INSUFFICIENT /
ORACLE_BUDGET_INFEASIBLE，不将该 O 的错误归为 use failure，也不因此更换已接纳任务。

O 不是数学上界；可能受原文装配、评分和模型波动影响。
若 R1 与 O 的**完整模型可见 payload**（含任务、来源、提示、工具、格式和模型参数）在生成前逐字节相同，
可预注册共用一次响应并标 IDENTICAL_INPUT_ALIAS；没有第二个独立观测，不声称估计了 R1−O 效应。
不得看 R1 答对后才决定省略 O。其余情况各组独立运行，不挑最优答案。

## 5. 从结果组合到瓶颈：必须附证据链

下表中的“错”指已交付、可裁定的语义/参数错误；预算停止、无效 Oracle、评分争议另列。

| 观测组合 | 还需确认 | 可支持的最小方向 |
| --- | --- | --- |
| A0 错，R1 对 | A0 支持不足、R1 支持充分；检查来源覆盖与 backend 是否一致 | acquisition policy 候选；只有控制检索差异后，才进一步指向激活/query 选择 |
| A0/R1 错，O 对 | A0/R1 未呈现充分支持，O 充分且任务/模型条件合法 | 当前检索/表示/排名或证据预算的缺口；不证明所有简单检索均无效 |
| A0/R1/O 都错 | O 的支持、任务合同、输入与评分均有效 | evidence use、推理、参数转换或任务适配问题；不是自动启用 State 的许可 |
| A0 与 R1 都已有充分支持却表现不同 | 比较材料组织、额外上下文、提示/生成机会和波动 | use/presentation 或不可归因差异，不能仍叫纯 activation |
| A0 对而 R1/O 错，或其他非单调组合 | 审查 Oracle/检索组装与评分；保留全部结果 | NON_MONOTONIC，不能把基线正确改判成“巧合”后删掉 |
| 任一组预算停止或无答案 | 请求/输入/工具结果哪些实际发送，预约是否完整 | HOST_BUDGET / EXECUTION，不计作读懂证据后答错 |

少量 O 正确只说明这些任务在该证据条件下可答，不追溯否定 v0.5 的受控失败，也不证明其必为过拟合。
只有跨独立任务重复的、Oracle 有效且 support presented 的关系/适用性/下一步错误，
才值得**另行提出** State/attention 假设；普通推理错、工具 schema 不懂或评分争议不够。

不将两三个任务推成“主要瓶颈已统计确认”。首批用于定位流程与候选层，
后续是否扩大由新合同/预算决定；不为追求某种失败类型修改 R1 或 O。

## 6. 测试床：Mem2ActBench 优先，Horizon 只作旧轨迹回放

### 6.1 Mem2ActBench 的价值与发布边界

[官方论文](https://aclanthology.org/2026.acl-long.370/)报告 400 个工具任务、2,029 个历史 sessions，
人工验证中 91.3% 为强 memory-dependent。该比例是论文的验证结果，不保证本次每个候选都必须检索。
它适合检验历史约束是否进入工具参数，但本轮仍需核对固定发布制品、工具条件与本地可评分性。

[官方仓库](https://github.com/Cantaloupe-M/Mem2ActBench)同时含数据构建流水线和发布目录，
不能把运行构建脚本当成下载现成题池；不重跑事实提取、模型生成、embedding 或“记忆锚定验证”生成新题。
顶层说明与[数据目录说明](https://github.com/Cantaloupe-M/Mem2ActBench/blob/main/Mem2ActBench/README.md)
存在文件名/难度分级口径差别，P1 必须以锁定制品的实际格式为准，不凭 README 选错文件或标签。

官方说明允许离线按 source_conversation_ids/session_id 映射到对应**完整长 Session**作为历史。
可据此建立三组共同 H；不得仅拿 source_fact_id 的答案句当 A0/R1 的全部历史，
也不把 evaluator 的来源指针额外作为在线 query hint。原始 Source/Tool/User 轮次顺序与日期保留。

### 6.2 必须分开工具选择、参数填写与实际执行

QA 含 tool_call、grounding_info、target_tool_schema 等字段；不能整体传给 Host。

- 若正常输入只提供 target_tool_schema，工具名已知，标 **KNOWN_TOOL_PARAMETER_GROUNDING**，
  只能主张参数 grounding，不能计为从候选工具中正确选择。
- 只有存在独立于标准答案的合法候选工具目录时，才标 **TOOL_SELECTION_AND_PARAMETER_GROUNDING**；
  三组看到同一完整目录，不根据 gold 筛工具或把正确工具排到特殊位置。
- 工具名/参数 JSON 比对是 **ACTION_INTENT_ONLY**；除非后续在受控模拟环境中真正 step 并验证结果，
  否则不称 action executed、任务完成或外部服务调用成功。

首版将业务动作提交给离线记录器，不发送给真实预订、支付、邮件或企业系统。
MCP/source 读取是实验实际工具调用；benchmark 业务动作是待评分产物，两类调用分账。
“首次相关行动”首版定义为首次业务调用意图，不把记忆搜索计成业务成功动作。
有多步任务时，第一步正确和完整调用计划正确分别评价，不以一条正确工具名代替整题。

### 6.3 新抽样，不消耗封存 Horizon

沿用 V02-12 的 frozen-pool sequential acceptance 方法，但建立独立 Goal/数据/来源 manifest：

1. 先锁定 Mem2ActBench repo/data/license、合法 history mapping、工具/评分模式与候选 universe。
   原始 memory chain/session/来源对话 lineage 为 cluster，不把同链 10 个 QA 当独立任务。
2. 与既往 BFCL、ToolACE、OASST 及本地 memory 实验的暴露/保护记录核对；同源组传播排除。
   共用公开工具定义本身不是同一任务；未知血缘隔离，不冒充全新或预训练未见过。
3. 在正文/答案审查前冻结 eligibility、hash 顺序、cluster 分区、筛查上限与 probe 规则。
   新池按 cluster 预留至少约 1/3 为确认；不使用已封存的 Horizon 55 clusters 替补。
4. 建议接纳上限 **4 个独立 clusters，每组 1 个预选任务**；筛查上限建议 30 clusters。
   最小三臂首波为前 2 个合格 clusters，不按预期 A0/R1/O 胜负挑题。
5. 首次生成前封存 accepted IDs、三组输入/检索配置、Oracle 包与逐题评分。
   ACCEPT 前不合格可沿冻结队列继续；ACCEPT 后失败/Oracle 不适用均保留，不补题。

允许用官方 L1/L2/L3 等元数据描述覆盖，但实际分级先核对；不按具体答案复杂度筛“容易救”的案例。
如果 Mem2ActBench 发布、映射、授权范围或评分不就绪，完成 P0/接线限制报告后停止，
不自动换成已封存 Horizon、EvoMem 或新生成任务。

### 6.4 EvoMemBench 后置

[EvoMemBench 官方仓库](https://github.com/DSAIL-Memory/EvoMemBench)区分 in/cross episode 与 knowledge/execution，
CrossEp-Tool 报告 800 个样例，适合作为后续执行与效率确认。
它复用 BFCL 等底层数据，不能仅因 benchmark 名不同就视为新独立样本。
本轮不接环境、模型服务或默认外部 API，不把其已有质量/效率结果转述为 MiLAi 已达到指标。

## 7. 评分、过程观测与公平成本

### 7.1 生成前冻结 evaluation_contract

每题记录参考版本、官方字段可见范围、业务工具候选集、完整参数判定、原文证据/Oracle 充分性、
默认值/缺省参数、时间单位和等价形式、拒答、格式错误、多工具顺序与争议处理。
纯确定性评分只对确实可封闭判断的调用/参数使用；日期/同义表达的规范化事先固定，
不在看到模型输出后放宽匹配。数据构建时的软锚定检查不自动等于正式评价器。

缺官方 evaluator 时报告 **NONSTANDARD_LOCAL_ACTION_GROUNDING_DIAGNOSTIC**，
不报官方 Mem2ActBench accuracy/leaderboard。人工或另行授权的模型辅助归因须独立标注、记成本，
不能把本地 Judge/代理审查当作零成本默认；当前新增 Judge/代理评价分配为 0。
无法裁定记 DISPUTED/UNSCORED，不自动增加模型复核或把样本移出接纳分母。

### 7.2 最少过程记录

| 环节 | 必须记录 |
| --- | --- |
| Availability | 完整 H/hash、实际存储分支、允许路径、Product 非空/空状态 |
| Activation | 是否请求来源、首次相关来源动作、原始 query；无调用不自动算错 |
| Acquired | 实际返回的来源版本/span、召回范围、MISS/截断/游标 |
| Presented | 真正发送的 payload/hash、支持片段覆盖；工具结果未发送须独立标明 |
| Use / action intent | 参数与支持的关系、首次业务工具意图及完整计划判定 |
| Execution / budget | 所有发送/停发、预约/usage、工具等待、格式错误与终止原因 |

重复读写、空库探索、重复 query、source-page 展开等只作过程成本，不按调用数量给奖励。
报告每组的 accepted/attempted/answered/scored/正确与 UNKNOWN、预算停止；
成对比较只有两侧有效时才进入对应条件分母，同时公开不能配对的全部任务。
任务 cluster 为独立单位，三臂和同一输入别名不增加样本数。

### 7.3 比较不是免费增加推理机会

A0 的取证决策、所有重发输入、工具结果和自主写入均计入完整成本；R1 的建索引/检索/原文读取也计入。
O 的离线定位/语义审查成本单列，不能视为可部署的免费在线能力。
货币、raw tokens、缓存、CPU/磁盘、网络、查询/整题延迟与审查劳动分别报告。
模型、Reader 上限和任务权限固定，不等于三个工作流总成本相等；不以 A0 多两次机会解释成无成本优势。

## 8. 开发与实验顺序

| 阶段 | 交付 | 不做什么 |
| --- | --- | --- |
| P0 零生成回放 | 8 个已执行 Horizon 任务的输入成本拆账、2 个停发请求重建与候选 headroom | 不重答、不改旧结果、不提高 20k |
| P1 薄接线与准入 | Mem2Act 制品/cluster/评分冻结；同源三臂、R1/Oracle 隔离与 source-fit | 不跑数据生成流水线、不新增 Product Memory Store |
| P2 最小三臂 | 前 2 个独立任务，A0/R1/O 首次结果与完整链路 | 不在组内追加提示、检索或答案修复 |
| P3 有界重复/停止 | 仅有有效对比线索时，在另行明确分配下运行剩余固定前缀至多 2 个任务 | 不凭首个结果持续扩大，不消耗 Horizon confirmation |
| P4 最小后续工作 | Host 调度、来源/排名、普通 use 或任务合同中的一个局部候选 | 不自动重开 State、S1/S2 或结构绑定 |

确定性机械缺陷可由最小复现支持一个 Lab Host 修复提案，不需伪造更多语义失败。
但改变模型可见提示/检索/交付策略必须成为新版本/条件；三臂运行中不边改边测。
只有充分支持下的同类 use 错误跨独立任务重复、常规任务/评分问题排除后，
才单独讨论 State/attention；这不是本 Goal 的默认下游交付。
