# MiLAi v0.2 通用 Agent 记忆：可用性优先的增量开发与实验 Goal

## 1. 目标与执行口径

在现有 MiLAi 与 Codex Host 上交付一个可使用、可观察的记忆闭环：Agent 为当前任务读取记忆，按需要回查来源和调整理解；有后续价值时保存可追踪的修改；新会话能恢复并继续任务。

用户只需正常提出任务、补充信息或要求继续工作。task binding、版本、回执与实验字段由 Host、适配层和 Lab 管理。Agent 可以直接继续、只修正当前回答、查询或重读来源，也可以不保存；不要求每轮经过统一检查、Hint、重建和写回。

本 Goal 是 [v0.2 主方案](../MiLAi_方案研究规划_v0.2_通用Agent记忆流程_20260905.md) 与 [小型原型执行合同](../MiLAi_v0.2_小型原型执行合同_20260905.md) 的开发执行规划。G0–G4现已完成，终态为 `COMPLETED_KEEP_BASELINE`：保留完整A0，A1/H1未显示预定净收益。专用锁、隔离实例、46次分配（含失败与偏离）、逐阶段结果和成本见 [Lab 执行记录](../../../MiLAi-Lab/studies/active/MILA_V02_MEMORY_FLOW.md)；普通启动与续做见 [现有runbook](../runbooks/http-mcp.md#ordinary-task-continuation)。既有工程与实验仅作为起点，不计作本 Goal 的新验收结果。

执行采用以下顺序：

```text
固定可运行起点
  → 两个案例跑通真实 Host 使用与保存
  → 少量配对任务检查回查收益和损坏
  → 正常恢复任务与保存前后重访
  → 新任务家族验证并交付可用配置
```

每一步都先交付能运行的最小功能，再做能决定下一步的实验。局部失败进入当前阶段的修复循环；负面策略结果用于保留基线或缩小适用范围，不自动冻结其他可用性工作。

## 3. 最小实现与仓库分工

### 3.1 首轮实现选择

默认使用现有 Codex Host、`milai codex` 恢复入口、公开 MCP 读取与 Working State GET/UPDATE。首轮单任务串行，使用隔离实验实例与显式稳定 task ref。模型采用 G0 核验可用的既有 Host 配置；在比较开始前记录实际模型标识、推理配置与版本。

| 需要的能力 | 复用位置 | 允许的最小增量 |
|---|---|---|
| 恢复时装配记忆 | Product `integrations/mcp/src/milai_mcp/launcher.py` | 复用原有 bootstrap；必要时补可观察的输入引用和运行回执 |
| 按需查询 | 公开 `milai_memory_resolve` 与 Host 已有合法来源读取工具 | Lab 保存外显查询、返回内容及截断信息；不新增隐藏 Reader |
| 选择性保存 | 公开 `milai_working_state_get/update` | 记录旧/新内容、真实版本和结果；调用方无需手工维护协议字段 |
| Event 驱动的显式修订 | 已有 `milai-hook ReconcileState` | 只在确实处理 Event window 时使用；不伪装成通用历史修复协议 |
| 试验执行与评价 | Lab `tools`、`studies/active`、`tests` | 一个薄入口、一份配置、一组案例、一份结果表 |

优先直接使用公开 State 更新接口做历史回查后的保存。当前 State payload 是一般 JSON；文本笔记可置于 JSON 文本字段并附独立的来源引用，首轮不新建 Markdown 后端。若比较结构化表示，使用等价内容的另一种 payload，记录信息量和长度差异。

现有 StateDelta 只支持指定顶层字段的 `REPLACE/CLEAR`，并要求引用冻结窗口内的 Event。自由文本与纯历史来源修改不强行转换成这套 Delta。当前没有完整 `HISTORY_ONLY/HYBRID` 调解模式；实验可记录“只读取旧来源且未消费新 Event”，不虚构 Basis、epoch 或 freshness 保证。

### 3.2 查询与写回的真实语义

- 同查询消费 D1 页面时，保留原查询并传入对应 `previous_context_id`；更换查询时开启新的 resolve，不携带旧查询的 continuation ID。
- 已呈现的原文可以直接使用，不以工具调用次数判定是否回查。
- 保存使用真实 expected version、operation ID 与公开 CAS。旧版本内容与实际差异留在允许保存的实验记录中；不回退共享 State head。
- 未尝试保存、明确无变化、冲突、失败、成功和结果未知分别记录。超时后先确认状态；相同操作的安全重试沿用已有合同，不盲目创建新写入。
- Runtime 校验引用资格与版本，不证明自然语言内容成立。字段替换后仍要评价原本正确内容是否被丢失或误改。
- 当前任务结束不意味着必须保存。是否有后续用途、是否已经存在等价记忆，都属于选择性保存的评价内容。

### 3.3 Product 与 Lab 的边界

Product 只承担实际接入、保存、读取及必要的产品缺陷修复；案例、标签、对照、评分、实验专用提示和结果分析归 Lab。Product 代码不能依赖 Lab，`src/milai_lab` 不导入 Product 私有模块或 `milai_client`；通过已锁定的公开接口访问产品。

本 Goal 优先使用 `PRODUCT_BLACK_BOX` 记录真实产品路径。只读公开 testkit 用于 `PRODUCT_TESTKIT` 诊断。改用自建参考算法或模拟 Host 时另标 `RESEARCH_PROTOTYPE` / `SIMULATION`，不继承产品效果结论。实验 arm 类型也不自动提供统计或因果证明。

不预设新增数据库对象、持久 Basis、图存储、Dense、路径训练、常驻 reviewer、统一 item 化或新 MCP 工具。若一个具体失败确实需要这些变化，先记录最小问题及方案范围，再按既有架构与 ADR 规则处理；不为填写架构清单而开发。

## 4. 增量里程碑

| 阶段 | 首要交付 | 随功能完成的实验 | 进入下一步的依据 |
|---|---|---|---|
| G0 执行起点 | 有效产品锁、隔离环境、明确的 A0 与预算 | 现有入口的最小连通和来源资格检查 | 身份、输入与边界可确认 |
| G1 两例闭环 | 真实 Host 可以使用、按需保存并恢复记忆 | 有后续价值的修订例 + 正确记忆控制例 | 核心路径能运行，失败能定位 |
| G2 条件回查 pilot | 一次可重复的 A0/A1 配对执行入口 | 两领域、四类起点，建议 8–12 例 | 有逐例收益、损坏和成本结果 |
| G3 正常使用与后续重访 | 普通恢复任务可用，保存结果能供下一会话使用 | Host 接入对照 + 旧/新记忆版本配对 | 能区分当前收益、保存收益和未解决问题 |
| G4 新家族与交付 | 可用配置、示例、结果报告和明确适用范围 | 未参与开发的新任务家族 | 选择保留候选、保留基线或明确部分完成 |

数字是起步工作量建议，不是显著性门槛或必须凑齐的配额。先跑最小样本，再依据当前证据确定下批任务；调整样本计划发生在下一批运行前，并记录开发使用历史。G3 的首对重访可在 G1 出现真实保存后尽早开展，无需等待 G2 全部结束。

### G0：确定一个真实可运行的起点

工作内容：

1. 核对 Product 源码、manifest、实际运行 artifact 和 Host 配置。为本研究创建独立 lock，保留 Lab 默认锁及旧实验锁。
2. 选择隔离实例与合法来源集合，检查现有 MCP、TASK GET、版本写入和恢复入口；仅在本阶段确有需要时做最小写入 smoke。
3. 导出完整 A0：包括现有 bootstrap 的重新核验要求、MCP 说明、工具目录、模型参数、可用来源和资源限制。
4. 确定一个观察位置：跨会话恢复后的首次上下文装配。没有真实入口时可以先用离线 checkpoint，但标为模拟接入。
5. 在首次模型运行前将每会话时间、工具调用、可执行的 token 限制及整批运行预算写入配置。沿用可用 Host 的现有默认值并核对它们确实生效；未知用量不填零。

最小验收：专用 Product pin 通过；工具与来源范围可核验；正常 Host 能启动；A0、预算和案例输入可定位。身份校验失败时修复配置或选用正确 artifact，不重跑语义实验寻找“好结果”。

本阶段不需要补全历史文档、重跑全部旧实验或清理整个工作区。公开环境密钥不进入配置、日志或命令行；实验运行记录只保存安全引用。

### G1：先跑通两个可用案例

默认选择一个软件任务与一个研究简报任务。先验证用户真实可感知的行为：继续工作、正确交付、保存必要变化，以及下一次恢复。

案例一具有可核验的旧记忆错误或遗漏，并预先安排后续任务。真实 Agent 在统一的条件回查请求下读取来源、继续任务；如果决定保存，使用现有公开接口产生真实新版本，再启动新会话观察恢复。案例二使用正确且足够的记忆，检查是否能正常推进，以及额外读取或修改是否合理。

这些案例可以是明确标识的构造案例，来源含合法干扰材料。初始记忆在方法运行前准备；不能在运行后人工补写“正确 State”、强制代写答案或把脚本填充字段计为 Agent 能力。

开发只补影响这两个案例运行的最小接入、记录或错误反馈。优先验证现有工具能否完成任务，不先增加自动 checkpoint detector。

验收分别记录：

- 工程：实际 Host、读取、提交及新会话恢复是否贯通；必要记录是否存在。
- 语义：当前判断、保存内容、控制例处理与后续动作是否正确。
- 未保存时：是合理选择、工具不可用、失败，还是选择策略待改进；不能用“未调用”直接替代诊断。

工程通过而语义失败时，保留运行入口并在本阶段定位问题；需要时使用相同公开工具做显式调用诊断，结果标为条件能力。测试替身只用于调试，不能完成真实模型验收。

### G2：小样本检验条件回查的增量

复用 G1 入口，按 [原型合同 Prototype-0](../MiLAi_v0.2_小型原型执行合同_20260905.md#5-小型实验按三个问题推进) 比较：

| Arm | 定义 | 主张范围 |
|---|---|---|
| A0 | 当前完整 Host 与记忆流程，保留原有搜索、阅读、保存能力和既有核验提示 | 实际产品基础对照 |
| A1 | 相同任务起点、来源、工具、模型与总预算，增加一次统一条件回查要求 | 该回查提示及其后续行为的总效果 |

起步提示采用：“使用现有来源检查当前记忆是否仍适合当前任务，然后继续完成任务；必要时修订，有延续价值时再保存。”它不包含错误位置、gold 或参考答案。保存 A0/A1 的确切差异；A0 已经包含的能力不得删掉。若实际只增加了提示强调，就按提示策略报告，不宣称新增了检索机制。

案例覆盖：正确记忆、错误或过时记忆、遗漏重要细节、当前需要展开但不必保存。软件与研究简报优先各覆盖这些起点，先分小批执行，再扩到建议的 8–12 例。纠错、现实变化和任务需要展开细节分别标注。

每对运行使用隔离的初始 State 与相同的来源条件，防止 A1 读到 A0 的产物或更新。运行顺序在可行时随机化；同一对中途不修改代码、提示、标签或预算。模型自发发起的不同查询及实际消耗属于结果。

首轮不默认增加 A2、额外 reviewer 或多因素矩阵。只有具体瓶颈使另一个策略值得比较时才加入；如果 A1 已能自由改写查询，不能把“再允许自由改写”当成新干预。

交付逐案例结果表和失败摘要，分别回答：回查是否改善首次相关判断，是否破坏正确内容，无需回查时有什么成本。小样本不要求显著性；无增益时保留 A0，也可以继续验证其正常可用性和已产生记忆的后续价值。

### G3：正常恢复任务与保存价值

本阶段保留两项不同实验，分别配置和报告。

**G3a：实际 Host 中是否用得合适。**

建议从 3–4 条短任务链开始，包含至少一种非编码工作。用户输入为正常的任务继续请求，不显式指出需要检查哪份记忆。两侧使用相同的现有 Host 预读位置；一侧保留 A0，另一侧加入一次可替换的通用回查机会。

候选机会可以表达：“继续当前任务时，可按需要核对记忆与来源；已有依据足够可直接继续，有后续用途时再保存变化。”具体文本与装配位置在运行前固定。若与 A0 没有可辨认的差异，不制造额外实验 arm，只记录 A0 可用性。

Host 保证机会送达，Agent 决定具体使用方式。此实验不续跑 HC4，也不循环强化全局工具说明。条件回查 G2 与正常接入 G3a 分开报告；“Host 提供机会后有收益”不解释为无 Host 保障时模型会自然调用。

先用有代表性的可回放任务形成配对结果，再在正常使用中观察。无法保持同起点的真实任务只报告使用观察，不能混入配对分母。

**G3b：保存本身是否有价值。**

在 Session N 运行前指定哪些案例存在后续任务。出现真实保存后，尽早建立同一后续任务的 U/V 配对：U 使用保存前内容，V 使用实际成功保存后的内容。

两分支都清除 Session N 临时对话、工具缓存及其他残留上下文，保持相同任务产物、其他持久载体、来源资格、模型、工具和预算。两侧均可重新搜索原始来源；记录因此发生的成本，不强制只能依赖摘要回答。

通过公开接口在两个隔离分支中初始化对应内容快照，记录分支真实 State ID/version 与来源版本的对应关系。不能回退共享数据库的 head、伪造旧版本号或直接修改产品表。隔离绑定标识仅作为运行元数据，不向模型泄露 arm 或标签。

更新前后版本的配对结果只适用于实际产生更新的子集。另按全部预定后续任务报告：保存、未保存、保存失败、错误复发、负面迁移和完成情况，以评价选择性保存策略。

验收需要至少实际观察到可评价的保存与重访路径；没有合格更新时记为“持久变化价值尚不可评价”，继续检查选择与保存环节。准确率相同但后续成本下降可以是有效结果；只取回新版本或引用它不构成净收益证明。

### G4：新家族验证与可用性交付

冻结已选配置后，在未参与策略开发的任务家族上做小规模验证，建议 4–8 例，例如从软件/研究简报扩展到项目规划或内容写作。不为新家族临时添加专用触发器或答案模板；必要适配应记录成本并限制泛化结论。

若要主张表示泛化，对部分相同语义任务配对比较文本笔记与结构化 payload；软件只用 JSON、写作只用文本的结果不能单独证明表示泛化。

完成交付：现有 Host 的明确启动方式、两领域使用示例、可选择或撤回的候选配置、逐阶段结果及未解决问题。默认行为只采用有证据支持的最小变化；候选没有增益时交付原有可用基线和研究结论。

## 5. 每一阶段都采用的修复循环

```text
记录实际失败及输入/版本
  → 找到最早可确认的失败位置，允许多因和未知
  → 提出一个最小、可复现的修复
  → 定向验证原失败与相关控制例
  → 用新配置身份运行后续比较
```

| 观察 | 优先处理 | 后续最小验证 |
|---|---|---|
| 应提供的恢复机会没送达 | Host 装配或运行记录 | 原入口顺序与真实输入 |
| 有机会但没调用工具 | 检查已有信息是否足够，再评价选择 | 正确记忆与确需来源的对照 |
| 来源没取得 | 资格、来源可得性、查询或索引 | 一种有针对性的查询变化及控制例 |
| 候选有关键内容但 Host 看不到 | 过滤、截断、预算或呈现 | 实际输入中的关键片段与旧内容损失 |
| 内容已呈现但判断仍错 | 适用条件、冲突解释与任务执行 | 同证据诊断；不立即增加更多搜索 |
| 当前正确但值得保存的变化未延续 | 保存选择、提交、下次装配 | 同一条任务链及 U/V 重访 |
| 修改导致旧内容损坏 | 更新范围和实际差异 | 原失败 + 正确内容控制例 |
| 空结果被当成成功或失败状态丢失 | 既有工具契约与日志 | 精确结果码和使用边界 |

一次修复只改变一个可解释的因素；组合修复明确列出差异。每次修复后保留旧运行，不能覆盖失败记录。局部失败不要求创建新的 Goal、完整审计矩阵或重复环境；后续比较至少使用一个独立新例检验修复能否迁移。

同一路线连续出现无增益、旧内容损失或更高成本，且没有新的诊断证据时，停止扩大该路线并保留基线。新证据可以支持下一次小改动；不通过加 seed、放大 Top-k、按题目写规则或挑选成功运行维持正面结果。

普通工程修复不以两个人工评审或统计显著为前提。安全、权限、版本和事务语义变化仍按既有 ADR、迁移和真实 PostgreSQL 测试规则处理。实验构造失败留在 Lab；真实生产任务失败才进入 [Production Failure Ledger](../reports/MILA_PRODUCTION_FAILURE_LEDGER.md)，不伪造 production failure ID。

## 6. 最少记录与指标

复用现有 Host/MCP 日志，补成以下三个视图即可；允许存于同一 JSONL，不要求模型填写统一 schema。

| 视图 | 必须能回答的问题 |
|---|---|
| Observation | 哪个任务、记忆和源码版本；当时允许读什么；机会是否送达；各次输入实际呈现什么、哪些内容截断；模型、工具与预算是什么 |
| Intervention | A0/A1 或 U/V 怎样配对；唯一或组合差异是什么；预定判断与分析规则是什么；实际执行是否偏离 |
| Outcome | 外显查询、返回、首次相关判断、最终进展；改前改后及提交结果；后续装配和行为；调用、token、耗时与未知项 |

查询间关系只记录系统实际观测到的依赖，不由时间先后补造推理树。不记录私有思维链；无法观测到实际输入时如实注明，不把工具返回全文当成已进入模型上下文。

| 指标 | 分母与判定 |
|---|---|
| 首次相关判断与任务进展 | 全部分配运行；预先明确向用户交付、执行工具或被下游接受的边界；失败、超时、无行动保留 |
| 关键来源恢复 | 起点缺少关键材料且存在合格来源的运行；以关键内容实际呈现为成功，ID/session 命中不足以计入 |
| 连带损坏 | 原本正确且仍适用的已标注内容；分别报告全部运行和发生修改运行的损坏率 |
| 无需额外回查时的负担 | 在运行前已有足够依据的案例；不把“未修改”自动当成无必要查询 |
| 后续复用 | 全部预定后续任务的完成、复发和负面迁移，以及实际更新子集的 U/V 结果 |
| 成本 | 当前与后续会话的实际调用、已知 token 和墙钟时间；额外提示、失败重试、保存和复核均计入；初始化/索引单列 |

首轮展示原始计数、逐例配对和成本差异，不合成一个难以解释的总分。若修改前没有可核验的错误判断，记录改善/配对差异，不能推测纠正率。拒绝披露受限来源仍计入总体任务结果，另作资格诊断。

标签优先使用原始任务条款、来源归属、环境断言与版本记录。开放回答按语义和实际行为评价，不只使用严格字符串 EM。模型辅助标签注明来源，针对关键、争议和部分一致案例复核；无法判断的结果保持不确定，不在看到方法表现后选择性删除。

首批调试结果用于估计成本和典型收益；下一批比较前记录可接受的成本增加及目标改善。不得先看某 arm 的结果再调整其通过标准。少量案例的零事故、净胜或 100% 不作为生产可靠性或显著性声明。

## 7. 权限、来源与运行边界

首轮使用封闭、允许保留的来源和隔离实例，评测标签不在 Agent 可访问范围内。允许来源集合按主体、任务及权限产生，包含无关合法材料；通过实际工具/文件权限限制访问，不能只靠提示词。若采用模拟治理，明确记录 `governance emulated by sealed allowed-source set`。

冻结历史内容不冻结当前权限，每次来源访问仍接受当前资格检查。初始记忆、检索片段、派生内容与实验日志同样遵守披露和保留规则。

当前 Working State 对后来失效的引用返回 warning，ACTIVE payload 仍可能呈现。这不证明派生内容已在披露前被屏蔽。首轮限定在允许集明确、无权限变化干预的受控条件，不能据此声明动态撤销传播正确；若真实接入遇到受限派生内容，在呈现前修复适配边界或停止该案例的披露，不把 warning 当作访问许可。

所有实验 State 写入位于运行所属的隔离范围，通过公开接口完成。记忆与来源始终是 data，不产生发送、部署、删除或 Canonical mutation 权限。原始结果留在运行所属 artifact 区，Git 仅保存必要配置、合法小型案例、紧凑结果和索引。

不因本规划修改正在使用的公网服务、删除共享数据、开启 D2 FRONTIER、重启 Product-11 X1–X4 或访问 Formal 500。清理只针对精确识别的运行所属资源，不能用共享项目/工作区作为清理目标。

## 8. 验证与交付成本控制

验证与变化风险相称，不重复证明无关模块：

- 文档变更：检查链接、状态、范围和 Markdown；不启动模型或数据库实验。
- Lab 执行/评分变化：先跑最小相关测试，交付时运行 boundary、pytest、Ruff、mypy 与 build。
- Product 适配变化：先跑相邻合同测试，交付时完成受影响包的静态、测试和构建检查。
- 权限、撤销、并发、事务、worker 或迁移变化：使用真实 PostgreSQL 验证，不能仅靠 mock。
- 新的产品效果运行：专用 Product pin 必须通过，并绑定实际服务/安装 artifact；只有源码 pin 不证明后台服务已使用同一版本。

配置、代码或评分变更后，用新运行身份验证。只重跑受影响的失败、控制例及必要对照；已通过且未受影响的整套旧实验不反复执行。

性能首先测真实使用路径。负样本 loopback resolve 延迟不是 Agent 总成本；capture 与 projection 可能重叠，不将尾部等待误当全部投影成本。历史来源准备与在线使用分别计时；可以复用同一受控来源快照，但不同 arm 的 State、任务产物和模型上下文必须隔离。

## 10. 完成与停止判定

本 Goal 的工程目标是交付可用流程并明确增量价值，而非保证任何预定策略一定获胜。

| 终态 | 判定条件 |
|---|---|
| `COMPLETED_USABLE_CANDIDATE` | 真实 Host 使用、保存、恢复与必要失败处理可用；完成小型配对、新家族和成本评价；候选的已观察收益及风险支持其限定用途；适用检查通过 |
| `COMPLETED_KEEP_BASELINE` | 基线使用与恢复可用；完成足以判断候选取舍的计划内观察和比较；候选无增益、更贵或有损坏，保留基线并报告范围；未证明的研究主张保持未知 |
| `PARTIAL` | 已交付部分路径，但真实 Host、必要写回、重访或评价仍未完成；逐项列明缺口，不能以时间耗尽替代完成 |
| `BLOCKED_EXTERNAL` | 已穷尽本阶段安全替代路径，仍缺少不可替代的凭据、来源、环境或用户选择；只暂停依赖它的工作，报告具体恢复条件 |

以上是文档中的交付标签，不自动操作 Goal 系统或改写历史实验状态。局部候选无增益可以停止该候选；不会把未完成的必要工程交付改成“已完成”。研究机制价值、自然调用能力、产品可用性和 Schema 冻结分别报告。
