## 4. D1：保存、恢复与分层装配的详细设计

### 4.1 建议的内部接口

以下是设计接口名，不是已存在的 API，也不是新增 MCP 工具：

```text
read_candidate(config, workspace) -> CandidateRead
plan_save(candidate, current_state, binding) -> SavePlan
confirm_detail(plan, public_files_or_memory) -> DetailObservation
commit_state(plan, expected_version, operation_id) -> OperationObservation
observe_head(binding) -> HeadObservation
restore_layers(binding, layer_mapping) -> RestoredMemory
assemble_bootstrap(restored, mode, input_limits) -> BootstrapAssembly
```

候选读取、计划和装配优先写成不发模型请求的纯逻辑；只有公开接口调用层产生存储副作用。返回记录分开表达选择、操作、当前 head、资格和比较机会，不把它们压成一个布尔值。

### 4.2 最小记录合同

| 记录 | 最小内容 | 注意 |
|---|---|---|
| CandidateRead | 入口、格式、原始字节摘要、JSON 值摘要（适用时）、候选 L1/L2 定位、来源映射是否确认 | 结构合法不等于语义足够 |
| SavePlan | expected version、自有位置变更、原有非自有字段保护、operation ID、候选版本摘要 | 无权重写他人字段；不根据文本中的 UUID 猜支持关系 |
| OperationObservation | 是否尝试、结果、操作 ID、关联版本、公开证据、观察时间 | 结果可 UNKNOWN；HTTP 超时不是确定失败 |
| HeadObservation | 当前版本、内容摘要、观察时间、当前资格/warning | head 可以在本操作之后被合法推进 |
| BootstrapAssembly | 模式、实际装配的 L1/L2 片段、控制元数据、来源版本映射、超限/降级状态 | 必须随后在实际 transport 路径核对 |

建议保存结果使用独立字段：`selection_reason`、`operation_outcome`、`head_observation`、`layer_mapping_status`、`comparison_opportunity`。具体枚举沿既有合同；新增内部枚举只为机械观测，不增加业务状态机。

### 4.3 保存顺序与故障语义

正常顺序为：读当前 H → 确定候选与自有变更 → 确认 L2 的持久版本可定位 → CAS 提交 L1 → 确认操作关联 → GET 观察当前 head → 记录是否形成 H*。

| 情况 | 必须返回/记录 | 禁止行为 |
|---|---|---|
| 无候选或无延续必要 | 未尝试保存及原因；正常任务结果独立记录 | 为提高保存率补摘要 |
| 自然已保存，适配器 no-op | 自然回执、恢复证据；没有适配器新增贡献 | 重新写一版制造“写回成功” |
| L2 持久确认失败 | 详细产物不可确认，L1 不提交指向它的新引用 | 先声明完成再补文件 |
| L2 成功，L1 明确未提交 | 新 L2 暂未被引用，保留可核验旧 State | 自动清除可能仍有价值的产物 |
| L1 提交未知 | operation UNKNOWN；独立记录当前 head | 把超时当失败盲写；把内容相等当成功 |
| 已确认 V8，GET 为 V9 | 操作成功，head 已推进；检查 H* 是否可安全固定 | 把 V9 不等于 V8 当作 V8 失败 |
| CAS 冲突 | 冲突、读取版本及当前版本 | 自动覆盖、自动语义合并 |
| 无实质变化 | no-op 或版本变化据实记录 | 宣称记忆内容改善 |

H* 必须是已确认、当前允许且具有合法 L1/L2 的共同起点。记录历史操作成功不自动保证某个当前 head 适合作为 H*；若出现并发写入，先核对可固定起点，不自动回滚或强用旧版本。[S1 §3.3、D1、§9.2–§9.3]

### 4.4 L2 版本、失效与撤销

固定路径不等于固定版本。首版优先复用现有不可变产物路径、文件版本或已公开的版本定位机制；内容摘要辅助验证，但不自动赋予文件持久性或访问权限。

若 L1 引用 L2-v1，而存在 L2-v2，需要分别记录“v1 是否仍可读”和“是否存在后续版本”。旧版本可读不等于失效引用，也不等于适用于当前任务。可用已有元数据完成的检查不读取全部 L2；必须读取正文才能核验时，将读取与耗时计入实际成本，不能视为免费预处理。

权限失效时不得先返回正文再加 warning。检查保护范围内的 State 派生内容、文件副本和工具返回路径；不能只测试 Evidence GET。跨层派生撤销的实际 Product 语义尚需 D0/真实测试核验，缺口不由适配器自行降低权限来解决。[S1 §3.3、D3]

### 4.5 装配与超限

A 使用相同 L1＋事先约定的当前任务 L2；B 只使用 L1＋必要控制元数据。两者其余 Host 提示、工具 schema、源能力与预算保持一致。不得把“B 更应该查来源”的额外指导塞入 B；比较变量应由装配配置实现。

保留完整持久 State，不等于把所有字段装配到模型。自然保存的 State 若无可靠层次映射，记录布局不支持/无比较机会，不通过字段名猜测 L1。

超限时明确拒绝本次装配或进入预先注册的正常来源降级路径；保留原内容，不截断尾部、不自动抽摘要、不悄悄将 A 改成 B。降级成功可作为任务可用性结果，但不是原 A/B 处理已按设计完成。

**D1 出口**：纯逻辑及公开调用边界测试通过；文本/JSON/no-op/旧字段保护/冲突/UNKNOWN/旧引用/超限均有明确结果；不以 mock 通过替代 D3。[S1 D1]

## 5. D2：可信请求边界、预算与时间控制

### 5.1 先验证现有 Host，而不是先写替代品

以不计费的回放/模拟 transport 检查现有 Host：能否在最终序列化前后观测全部模型输入，能否拦截每次发送，能否关闭重试、fallback 与额外摘要，能否读取 usage 并控制输出上界，能否隔离 provider 会话状态。还要核对 MCP/工具内部可能产生的模型请求；只拦截主循环不构成完整证明。

若这些能力已具备，`v02_e2e_host.py` 只做薄接入。只有出现有证据的缺口，才做单进程轻宿主；完整保留相同 13 个公开工具及允许文件能力。检查工具名、schema、目录范围、运行身份和实际行为，不能只比较数量。[S1 D2]

本计划不指定 Provider、当前价格或 SDK 参数；资料没有提供这些事实。D2 必须针对实际选择核对官方合同与锁定版本，不能把未验证的 tokenizer 估计视为硬上界。

### 5.2 请求流水线

```text
构成完整请求
→ 保存无认证信息的实际 payload 及内容映射
→ 计算可信输入/输出/费用上界
→ 同时检查会话和批次剩余额度、deadline、在途状态
→ 持久记录预约及 request ID
→ 发送一次
→ 记录 Provider 关联标识与响应
→ 用真实 usage 结算，或保留 UNKNOWN 预约并停止后续发送
```

预约必须早于网络发送落盘。首版复用既有总账/本地追加记录，不新建预算服务。重启后先重放未决预约；无法证明未发送的请求按可能已计费处理。只有明确未发送或已取得可信结算证据才释放相应预留。

同任务最多一个在途请求。建议本轮实验顺序执行，减少共享账本与隔离复杂度；这不是限制未来产品并发。共享批次存在未决费用时，默认停止该批次后续计费发送，直至按合同确认。

### 5.3 预算不变量

对 token 和金额分别维护，而不是用 token 代替金额：

```text
settled_session + unresolved_reserved_session + new_request_upper <= session_cap
settled_batch   + unresolved_reserved_batch   + new_request_upper <= batch_cap
in_flight_for_session <= 1
```

候选 token 指标为各真实请求的累计 raw input＋output。输入包含系统/开发者提示、用户任务、全部工具定义、已带回的历史和工具结果；每次重复输入都计入。cached 是 input 的子集，不再重复相加。Provider 若有单列计费项，另行按合同记录，不假定都已包含在 output 中。[S1 §6、§9.6]

发送前价格上界不得依赖尚未确认的缓存命中。适用时使用更保守的非缓存费用，真实结算再记 cached/uncached；输入/输出上下界的来源必须可审阅。超过已声明上界说明控制合同失效，保留事实并阻断，不能修改历史预约“修成通过”。

“23 会话”不是“23 次请求”。一次会话可有多个受控模型请求；总量仍受会话、批次、时限和金额约束。分配、请求和费用使用不同标识，避免把启动失败或重试隐藏在同一会话名下。

### 5.4 30 秒口径与尾部保存

30 秒是 S1 的候选目标，尚未获接受，不是当前系统性能结论。计时从就绪服务上开始任务绑定/恢复前开始，到最终交付及该会话必要保存/确认完成；共同 G 后处理留在 G 内。服务初始化、来源导入和变体准备另记研究成本。[S1 §6、§9.6]

建议用单调时钟测时长，用可追踪时间戳记录事件。发起下一次模型/工具调用前检查剩余时间；不得为“刚好完成”无限延长。最终产物正确但确认超时，需要同时报告任务结果、保存结果和时限未满足，而不是合并成单一失败或删除超时。

本地停止不能证明远端未计费；保存响应丢失不能证明未提交。清理与事后核对不得将原会话追认成按时成功。

### 5.5 观测不变量

至少区分 `SOURCE_ACQUIRED`、`CONTENT_ASSEMBLED`、`REQUEST_SUBMITTED` 以及发送结果未知。真正的请求记录用于证明内容进入发送路径；只有 SDK 上游计划、GET 成功或内容摘要，均不足以证明最终呈现。

建议每个片段记录来源/版本、层次、消息位置、实际正文或其受控存储定位，以及可定位范围。离线评价可以用封存的必要证据标注核验；不能把这些标注交给运行 Agent。模型是否“理解”不从内部过程猜测，以首次实质行动和最终产物判定。

保存请求正文时剥离认证 headers，不把密钥写日志。正文和工具返回仍按敏感资料受控保存，不能因用于审计就变成公开资料。没有可访问的实际正文而只有 hash 时，相关语义呈现判断可为未判定。

**D2 出口**：可审阅的完整请求与所有发送路径、输出限制、预算上界、未决费用规则、deadline 和 Provider 合同证据。模拟测试只证明执行器，不证明 Provider 合同本身。[S1 D2]

## 6. D3：真实 Product 的最小工程闭环

### 6.1 先建立一条正常纵切

使用本轮独占的本地 Runtime/PG/MCP 和原有服务管理器；模型 transport 关闭。通过公开接口导入工程 fixture、保存 L2 与 L1、确认操作及 head，结束客户端和 Host，清空临时 home，再用新的客户端和同一合法任务绑定读取。

这测试真实持久化与客户端冷恢复。不能把模拟 Agent 输出叫成真实 Agent 行为；也不要求首轮扩建故障集群或生产灾备验证。

正常纵切通过后再加入格式、冲突、撤销、故障注入、隔离和预算边界。针对持久化/CAS/权限的结论必须在真实 PG 上验证；纯转换器可以用单元测试。[S1 D3]

### 6.2 分叉隔离：在 D3 证明，不拖到付费 D4

建议用已有公开作用域和独立文件工作区建立 A/B 分支；每臂只取得本臂合法绑定和凭证。允许公开导入必要来源并重绑定 State 引用，不直接复制数据库行，也不新建数据库克隆系统。

分支快照至少包括：G 的普通产物、原始允许来源、已确认 H*、L2 版本、来源资格、工具能力、可发现目录及初始检索语义。A/B 分支启动后可正常写入，但写入互不可见。

公开重绑定需记录原标识→新标识映射，并验证：作者/归属、原始发生时间、有效时间条件、版本关系和资格未改变。导入时间可以不同，但不能被悄悄当成新的业务发生时间。纯标识变化不能让“最近来源”排序产生未声明差异。

不要在不透明正文中全局替换看似 UUID 的字符串。需要调整的引用应由明确公开协议定位；无法可靠定位的引用记缺口，不丢弃引用来凑同源。

建议的泄漏验证是：向 A 写入独有 canary，确认 B 的所有合法搜索、引用读取、普通文件、工具输出和启动请求都不能看到；反向再测一次。只保证默认 State GET 不串臂是不够的。

公开 API 若无法保持必要的来源时序、资格或隔离，D3 记录阻断，受影响的 A/B 不具备公平条件。可以继续其他非模型测试，但不能用 SQL 修补后声称公开链已通过。

### 6.3 资格与普通文件不能形成旁路

对需要保护的材料，撤销测试应覆盖受控来源、其受控派生 L1/L2、文件副本和后续上下文装配。受控正文不能通过普通文件接口绕过资格限制。独立合法来源仍按各自权限处理，不能把“撤销一条 Memory”误当作删除所有独立资料。

模型进程应看不到另一个分支的文件、密钥和评测目录。日志里的受控正文也不能挂载为模型可搜索材料。已经进入旧会话的内容不能靠新 GET 撤销“抹除”；本轮资格验证重点是撤销后新请求/冷会话的披露边界。

## 7. D4：最多一个真实开发链

D1–D3 通过、D2 的 Provider/金额合同可执行且明确获得最多 3 会话额度后才运行。当前仍为未授权。[S1 D4、§6]

### 7.1 执行步骤

先做无需模型的 preflight：源码/配置 pin、来源清单、公开能力、隔离、账本与预算合同。随后正式分配 G；一旦进入已分配的启动尝试，启动失败也不回收为“未用名额”。

G 只执行正常前序任务，按既定通用约定自然形成产物。记录自然 State H、候选 M、适配器操作及是否形成 H*。G 的实际必要保存/确认与费用均在共同 G 闭环内。没有 L1 或合法 L2、不确定提交或没有分层机会，就保留结果，不追加 G 或补写摘要。

H* 确认后，使用 D3 已验证的公开方式分叉。在两臂均完成静态资格检查后，按预先固定的顺序分别分配 A/B，启动新进程执行同一续做任务。不能继承 G 的 provider conversation/thread 或临时上下文；服务方计费缓存与会话内容继承分别记录，不把 cached token 自动当作跨会话信息泄漏。

每臂记录完整请求、模型可见工具返回、首次相关实质判断、最终产物、自然写回、usage 与清理。基础设施或预算失败不自动重跑。普通工具的业务性恢复行为是否允许，须已在共同 Host 策略中明确，不得在实验失败后临时放开。

### 7.2 成功与失败的归属

G 成功不代表产生了分层机会；A/B 任务成功不代表新保存有因果收益；保存成功也不代表语义正确。分别记录：已分配会话、已确认保存链、合法 H*、有比较机会、实际配对完成、可评价配对。

D4 无机会时，不开展 D5。D4 暴露一般问题后可以修非模型工程，但当前合同不允许自动追加真实链；修改后的 D4 模型验证需要新的明确额度，不能把“最多 3 会话”解释为“每次改代码都再来 3 次”。

**D4 出口**：实际开发链按合同完成、必要行为正确且成本满足冻结条件，才具备进入 D5 的前提；这仍不是留出泛化结论。

## 8. D5：不扩大预算的留出与变体安排

### 8.1 预注册矩阵

保留 S1 的两个留出家族、每家族两条独立链，共四条。下面只描述覆盖位置，不提供留出题、答案或难点提示；可见的矩阵不是已经封存的任务集。

| 链位 | 家族 | 预期信息条件 | 会话 | 结构扰动覆盖 |
|---|---|---|---|---|
| R1 | 研究简报 | L1 足够 | G、A、B、B_rep、B_struct | 正文前移 |
| R2 | 研究简报 | 需要 L2/L3 | G、A、B、B_rep、B_struct | 正文后移 |
| W1 | 内容写作 | L1 足够 | G、A、B、B_rep、B_struct | 非保留键换序 |
| W2 | 内容写作 | 需要 L2/L3 | G、A、B、B_rep、B_struct | 删除无语义可选包装 |

具体扰动→链位映射是建议，可在运行前按格式适用性调整后一次冻结；不得看到结果再重新分配。A/B 顺序建议在每个家族内各安排一次 A→B 与 B→A，并记录时点、缓存和服务条件；小样本下不声称已完全消除顺序效应。

四链×五会话=20，加 D4 三会话，总候选最大 23 会话。按每会话 20k 计算为 460,000 token 候选上界，不是批准量，也不是实际花费。变体准备与公开持久化无需新增模型，但仍记录调用、耗时及研究成本。[S1 D5、§6]

### 8.2 补充：预期条件与实际条件必须分开

S1 一面要求 L1 由 G 自然形成，一面要求每家族一条 L1 已足够、另一条需展开。二者不能靠设计意图自动保证：G 可能把原计划放在 L2 的关键条件也写入 L1，或漏掉原以为必有的内容。

建议在任何 A/B 发送前，依据预注册必要条件，由不向运行 Agent 暴露判断的评价侧检查 H*，记录 `intended_information_stratum` 与 `observed_information_stratum`。实际条件可为 L1_SUFFICIENT、EXPANSION_REQUIRED 或 UNDETERMINED。

“需要展开”的判断必须检查完整初始信息，而不是仅看 L1：续做题本身、固定 Host 文本、工具描述或默认文件预览中已有事实，就不能算只能从 L2/L3 得到。

不为满足分组删改 L1、不选择表现较好的 G、不临时换续做题、不自动追加样本。若实际分组未实现，保留可成立的配对结论，并明确预定覆盖未满足；不能授予完整的计划范围泛化结论。

### 8.3 变体层与变换器

建议首版把表示变体固定作用于 L1，使 B 启动时确实接触被扰动层；L2/L3 保持不变。这是实施选择，须在 D5 冻结前登记。选择 L2 也可以，但未实际读取时，只能证明持久化/恢复或可用性，不能声称模型处理了该变体。

对自然 Markdown，可使用可逆的段落/小节编码分布到多个 JSON 字段，保持原文块、顺序、来源、时间与不确定性；从 JSON 反向重建能辅助证明无丢失。它只证明该类信息组织转换，不等于模型理解了任意复杂 JSON。禁止借转换重述结论、压缩细节或补答案。

仅把全文放到 `{"text":"..."}` 测的是包装兼容；应与字段组织变化分开报告。JSON 结构换序需要母本本来具有可换序的非保留键；不能先把 Markdown 改成 JSON 再换序，却声称只测位置。某扰动不适用则记未判定，不临时发明另一题。

每个变体独立从 G 的 H* 分叉，不从执行过原 B 的状态继续。链路必须为：母本 → 等价变换 → 公开保存 → 新进程恢复 → 实际请求 → 续做。变换记录同时比较持久内容与实际输入，区分适配器消除差异、模型确实面对差异和未暴露差异。[S1 §9.4]

### 8.4 留出失败处理

留出未运行不记失败；明确任务失败、控制失效、不可评价分别记录。安全/预算/隔离失败停止受影响运行，不能为完成矩阵继续发送；单个任务失败但安全控制仍有效时，后续是否继续按预注册执行规则处理，不临时扩样。

观察留出后修改实现，已暴露材料转为开发材料；不能把修复后的同题结果包装成独立留出成功。报告每链结果，不将 12 个 B 类续做会话当成 12 条独立任务链；实际仍是四条独立链、两个家族。[S1 D5、§5]

## 9. 评价、归因与成本报告

### 9.1 先固定可观察的结果

| 维度 | 主要证据 | 分母/限制 |
|---|---|---|
| 保存归因 | 自然或适配器操作回执、关联版本、独立 head 观察 | 已尝试操作；自然已存在但无回执不算本次保存链 |
| 冷恢复 | 新进程身份、合法绑定、恢复版本与实际启动请求 | 实际恢复会话 |
| 分层执行 | B 无 L2 初始正文；按需读仍可到合法 L2/L3 | 处理臂按设计实施的会话 |
| 首次相关判断 | 预定义的工具动作、下游使用或最终交付位置 | 有可靠判据且已到达该边界的任务 |
| 必要证据呈现 | 指定来源/版本/片段在相关动作前进入实际请求 | 实际需要展开的任务；L1 足够时不强求检索 |
| 最终任务 | 封存必要条件与来源/环境核验 | 可评价任务；不自动推广到开放式整体质量 |
| 表示/结构 | 变体前后持久内容、实际输入、配对任务结果 | 适用且可观测的配对；不当成独立任务 |
| 成本 | 每请求 usage、预约、工具时长、保存/恢复与共享开销 | 包含失败；未知不填零 |

对于某次表现变差，可定位到产生候选、提交、恢复、发现、取得、装配、任务行为、资格、成本等环节。没有观察到模型内部解释时，不把“解释错误”写成已知事实；可以记录“证据已呈现，首次行为仍不满足条件”。

### 9.2 分母必须显式输出

汇总至少列出计划量、获授权量、已分配量、实际启动量、已确认保存链、有合法 H* 的链、有 A/B 机会链、完成配对、可评价配对、表示/结构适用配对、未判定与失败。未启动的预留槽位不冒充已花费会话；已经分配的启动失败不能回收为零成本或无限重试机会。[S1 §9.2、§9.7]

观察到 H′ 与 H 无实质变化不意味着任务失败；B 不检索也不必然错误；A 全部答对不否定 B 可用；B 省 token 但超时或失去关键正确性不能称总体更优。

### 9.3 三本口径，不重复计费

**后续装配比较**：每链分别列 A/B 的质量、raw/cached/uncached/output、金额和时延。对相同指标 x 可报告 `Δx = x_B - x_A`；负成本差值表示 B 在该指标较低，不能跨币种、token、秒直接相加。

**正常单链成本**：反事实方案分别为 `G+A` 与 `G+B`。G 虽在配对实验中共享，但每种实际使用方案均需承担相应前序工作。额外产生/维护 L1 的成本不能仅靠共享 G 被识别；不可分离时保留未知或可解释的上下界，不声称免费。

**研究总账**：实际发生的 G 只计一次，再加 A、B、表示/结构变体、失败、初始化、来源导入、公开重绑定、清理和其他实际费用。开发劳动、开发对话和非模型设施支出分别列，不把 0 实验模型调用写成整个项目免费。[S1 §5–§6、§9.6]

建议补充输入拆账：固定 Host/工具定义、当前任务、初始 L1、A 初始 L2、后续历史、检索返回、最终/维护输出。它帮助判断节省来自哪里，但不改变 Provider 原始 usage；难以精确分摊的部分明确标估算。

### 9.4 结果状态不互相覆盖

保留 S1 的状态名称。汇总先给各维度结果，再形成受限总评，不使用一个布尔值覆盖所有信息。

| 情况 | 应使用的结果 |
|---|---|
| 真实工程闭环通过 | `ENGINEERING_E2E_PASS` |
| D0–D3 完成，模型未运行 | `ENGINEERING_COMPLETE_E2E_UNVERIFIED` |
| 模型实验因授权/控制/预算条件不足未启动 | `E2E_NOT_RUN`，说明原因 |
| 已观察到必要任务条件失败 | 相应维度不支持，整体按 S1 为 `E2E_NOT_SUPPORTED` |
| 判据或关键观测不足 | 条目 `NOT_EVALUABLE`，相关结论 `E2E_INCONCLUSIVE` |
| 所有必需范围与验收均满足 | `E2E_GENERALIZATION_SUPPORTED_IN_TESTED_SCOPE`，附 `HOST_MANAGED` 与实际范围 |
| 新保存内容的因果增量 | 本轮固定 `NOT_TESTED` |
| 自主触发/自动语义维护 | 本轮未验证，不借用 HOST_MANAGED 结果 |

若既有明确失败又有未判定项，二者均报告，不能用 UNKNOWN 抹去明确失败，也不能把未判定项补成失败计数。若对照无效，停止 A/B 因果解释，但保留可成立的单臂工程与任务观察。
