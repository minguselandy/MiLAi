### 2.1 首版只围绕现有普通工具工作

### 2.2 任务绑定必须可解释

现有 `_working_state_binding` 允许服务器配置 scope_ref，也存在按私人 project 派生默认 TASK 的路径。
该事实不能直接解释成同一账号下不同仓库、不同任务自动独立。

首版固定“一个已明确选择的工作流”，使用普通用户可以复现的稳定绑定方式：

- G/R 使用同一工作流；重启、换客户端不应因随机 session/client ID 丢失记忆。
- 执行前核对公网入口与受支持 Host 实际如何选择工作流，不能让实验员每次修改服务配置来伪造产品体验。
- 不支持多任务选择时，明确展示单工作流限制；遇到不同任务不得静默覆盖或混用，可提示用户选择/确认。
- 若需要新增可信任务选择能力，先复用现有 scope_ref；身份、授权或作用域语义变化按 ADR 和真实 PG 测试处理。
  模型自报 tenant/project/principal、旧记忆中的授权文字不能成为绑定依据。

## 3. “模拟 Codex 真实调用”分成三层证明

### 3.1 主路径：原生 Codex + 本地模型 + 真实 MCP

```text
普通用户任务
  → 原生 Codex（固定版本；文件/执行测试能力；当前 MiLAi 配置）
  ↔ 本地 vLLM（只替代付费推理；完整请求纳入预算）
  → Codex MCP 客户端 → HTTP tools/list / tools/call
  → MiLAi MCP → MiLAi Runtime → PostgreSQL / 原件存储
  → 原始工具结果回到 Codex → 后续实际模型输入 → 代码/测试/最终产物
```

这是首选：**模拟付费模型环境，不模拟 MCP 的执行结果。** G、R 都由原生 Codex 进程工作，
工具调用 ID、参数、返回、错误与后续输入可关联。模型服务地址固定 loopback，不能静默回退付费 Provider。

先以当前 vLLM 原生 Responses 能力核对 Codex 合同，包括工具定义、call_id、工具结果回送、
流结束/usage 和请求预算。若需要协议适配，只做有明确边界、可测试的最薄适配，不改模型决策或 MCP 结果。
若不能在小额兼容预算内成立，就记录 `CLIENT_MODEL_COMPATIBILITY_NOT_PASSED`；不借机建设多 Provider 平台。

### 3.2 可选诊断路径：模拟 Host + 真实 MCP

主路径遇到客户端/Provider 兼容问题时，可复用 Lab 轻 Host 验证工具使用，但必须另列
`SIMULATED_CODEX_HOST_REAL_HTTP_MCP`，不能授予原生 Codex 通过。

相对旧 JSON-action 模式，优先从真实 catalog 转换为 Provider 支持的工具描述，模型返回调用后，
通过 MCP SDK 执行真实 `tools/call`，以相同 call_id 将完整合法结果返回模型。保留原始名称、参数约束、
annotations、isError、来源、版本及截断信息。若仍采用 JSON-action，显式记录该差异。

本轮插件使用臂关闭旧模拟器的隐式 State 预取、来源回查和答案补充；不能把 Host 偷读的内容算成 Agent 调用。
需要开发确定性生命周期接入时，作为独立 `HOST_MANAGED` 配置交付并标记触发者，而不是伪造自主行为。

### 3.3 零模型工程控制

脚本、mock Provider 和固定工具序列可验证协议、预算、错误回送、并发和持久化，结果只记工程通过。
三层证据不得相互替代。最低观测链为：

`模型请求/客户端事件 → tool call ID → MCP 实际调用 → Runtime 操作结果 → 工具返回 → 下一次实际模型输入`。

多条独立工具调用允许并发，结果按 ID 正确回送；依赖型调用保留因果顺序。
同一模型任务的发送预算限制不成为 Memory 服务的全局串行锁。

## 4. 开发与实验执行队列

按 U0→U1→U2→U3→U5 推进；U4 复用现有工程证据，并只补受本轮改动影响的容量/接入缺口。
普通安全修复按最小失败先推进，不为每项工作新建审批流程。模型额度、生产变更和作用域扩张仍须有相应授权。

| 阶段 | 核心交付 | 进入条件 | 出口与停止规则 |
|---|---|---|---|
| U0 固定真实入口与观测/预算 | 客户端/模型/MCP 运行身份、兼容性合同、发送前限制 | 文档执行授权；生成请求另有明确额度 | 未授权不发送；协议不兼容先定位，不能自动换付费模型 |
| U1 工具使用与机械闭环 | 真实 HTTP 工具发现/调用、保存/冷 GET、错误/隔离回归 | U0 无模型控制通过 | 能从公开合同完成使用；脚本通过不计语义通过 |
| U2 最小 G/R 产品链 | 正常开发、模型发起保存、新进程模型发起恢复与续做 | 相关安全/保存门通过；最多两会话额度 | 任务正确且 MCP 链路可归因；失败先分类，不自动重跑 G |
| U3 连续纠正与无需写入 | 复用同一 G/R 的两个后续会话 R2/R3 | U2 通过；下一阶段额度 | 更新有效、冷恢复不复发、无关内容保留、无必要写入可正确不作为 |
| U4 交互容量与实际入口 | 两用户隔离、正常交互混合负载、公网客户端接入证据 | 只用专用身份/数据；生产操作单独授权 | 容量与部署版本声明明确；旧批量导入失败不被新低负载覆盖 |
| U5 可复现交付 | 产品配置/说明、逐链结果、成本与终态、剩余问题 | 必需验收有回执 | 按第9节判终态，不以 tests passed 或模拟结果替代 |

### U0：先证明不是另一套“看起来像 Codex”的脚本

1. 固定 Codex 二进制版本/摘要、Product wheel/lock、Runtime 与 MCP 配置身份；区分工作树与安装版本。
2. 选择现有私人部署等价的独占本地 HTTP MCP/真实 PG。可以使用明确标注的合成认证夹具做本地工程；
   最终接入使用已完成 OAuth 的专用真实测试连接，不能把合成 JWT 测试叫真人登录。
3. 捕获实际协商协议、server instructions、授权 catalog/JSON Schema。旧握手与新 SDK 模式分别验证，不硬编码错误生命周期。
4. 原生 Codex 保留正常文件读写、搜索和运行受限测试的能力；不能以旧模拟器“只写一段答案”的 finish 充当 Coding 交付。
5. 固定专用客户端配置/会话目录与容器挂载。评价材料、旧 rollouts、其他 Agent 的记忆、真实用户配置及 Runtime 密钥不可见。
6. 复用现有预算和请求记录；原生路径缺少逐请求上界时，先补仅 loopback 的有界观测/转发点。
   该点不改提示、工具结果、检索和授权，不成为另一套 Agent。
7. 先用 mock/固定协议样本验证完整工具往返和预算；最多两次本地生成请求作兼容探针，另计额度，不记任务效果。

交付一份可执行配置和一个复现入口。不能直接把现有 `milai codex` 私有全控制启动器作为公网私人插件的等价物；
需要 Host-managed 接入时，产品侧适配同一受支持 MCP 入口，保持相同权限和显式行为说明。

### U1：先修用户会碰到的工具问题

- 正常调用不要求用户手填 operation/state/evidence ID；Agent/可信客户端依据公开返回与合同构造参数。
- `tools/list` 与直接调用权限一致；未知工具、缺参数、错误 ID、越权参数返回可解释结果，不能悄悄代填业务答案。
- 实际保存并退出客户端，新客户端核对内容与关联版本；保存回执与额外 GET 的当前 head 分账。
- 覆盖同版本 CAS 竞争、重复 operation、相同 ID 不同 payload、响应未知、引用不合格、索引未就绪与普通 ABSENT。
- 明确区分 HTTP 错误、MCP `isError`、业务拒绝与工具正常返回；工具错误送回模型后仍能继续独立的低风险工作。
- 核对同用户工作流连续性、两用户隔离、正文/来源保真、超限不静默丢字段；已有对应 pin 的直接测试可复用。

优先改现有工具说明、参数示例、必要错误反馈或最薄 Host 接入。只有可复现的公开能力缺失才改 Runtime。
不为模型误解新增隐藏 Reviewer，不把历史叙事自动标注成当前 Runtime 已证实事实。

### U2：一条正常 Coding 任务的 G/R

使用独立小型开发工作区，例如标准库实现的文件校验/批处理 CLI，具备能执行的测试。
具体任务、正常来源与验收条件在分配前冻结；开发材料不冒称盲测，也不复用 D5 留出做调参。

**G：正常完成一个有后续工作的开发里程碑。** 用户提供真实任务范围、约束和合法材料；
Codex 阅读、实现、运行测试，并按已启用的项目工作记忆约定选择值得保存的内容。
记忆优先保留约束、决定理由、失败路径和下一步，而不是复制整份代码；不要求固定业务 schema 或 L1/L2 格式。
保存参数和正文由当时实际工作形成，不看 R 的评价答案，不由评测助手在结束后另写“更好记忆”。

**R：新进程正常续做。** 保留 G 的正常代码、普通笔记、完整合法来源和已保存 Memory；
客户端不继承旧对话。用户只提出新的开发要求，不重贴旧约束、不指定标准答案片段或 MCP 调用序列。
Codex 通过真实 MCP 取得合法记忆，必要时查原始来源，执行后续修改与测试。

必要条件包括：首个依赖历史的实质动作遵守既有约束；最终产物实际存在且测试满足合同；
记忆相关判断有及时可见依据；未将 UNKNOWN 说成已记住；全部请求及失败进入成本账本。

已完成任务而没有保存机会记 `NO_MEMORY_OPPORTUNITY`，不能凭任务成功授予保存链通过。
Agent 不调用 Memory 而从正常文件完成任务，记“任务通过/插件激活未证明”，不删除文件制造记忆必要性。
操作者指定工具名的诊断可另做，但只能证明显式调用能力，不能覆盖正常续做的激活失败。

### U3：用已有链验证“能纠正、不会越用越错”

- **R2：用户给出一项真实的新要求或纠正。** 在同一工作流中读取旧状态，按当前授权完成代码/资料更新，
  保存有延续价值的新内容。新来源有版本/出处，未受影响的正确约束仍保留。
- **R3：再启动一个新进程。** 用户正常要求按当前决定继续或核对下一步；检查新约束被恢复、旧错误不复发。
  该轮若无材料变化，不应仅为“用了记忆”制造一次写入；合理不保存/no-op 单独记录。

两会话复用已有 G/R，不新建更容易成功的 G。更换 Host、记忆策略或提示后按新条件记账，旧失败保留。
这是一条连续使用验收，不是自动维护策略的自然端到端收益比较，也不保证长期稳定性。

### U4：验收实际插件入口与限定交互容量

**实际接入不是重新验收 OAuth。** 优先让 U2/U3 在已授权的专用公网测试连接上完成；
若开发修复只能先在隔离候选上执行，则最终安装同一已验证构建后补一条公网 G/R。
同版本、同入口、同配置的已有合格链直接复用，不为不同报告重复生成 G。

- 使用专用测试身份和非敏感任务数据；身份由现有认证获得，不复制真实用户的整个客户端目录或生产令牌。
- 正常产品入口不得要求操作者读取 Runtime 密钥、手工预填 State、修改用户私人项目或后台修正记忆。
- 公网只做有限正常工具使用；故障注入、并发竞争和压力测试均在独占本地实例进行。
- 公网部署更新、测试数据写入须有明确执行授权；没有测试连接时记接入证据待补，不重做认证体系。
- 同一部署的两用户隔离测试可复用相同 pin 的已验证证据；影响作用域的修复必须重新跑真实 PG 回归。

容量验收先保留现有 700 次读取和旧混合负载结果，再检查本轮是否改变路径、安装包或配置。
需要补测时，使用一个小而明确的**交互型**工作负载，不先做百万级容量研究：

| 配置项 | 首轮建议，执行前冻结 |
|---|---|
| 实例与数据 | 1 个本地 MCP/Runtime、真实 PG，2 个私人用户，1000 条 State；正文 512/2048/8192 字节 |
| 负载 | 先纯读，再相同读取加写入；总计20次 State GET/s、1次 State UPDATE/s、1次 Evidence capture/s；各30秒 |
| 资源 | 优先沿用已有已测配置；明确 CPU、线程/连接池及存储位置；读最多6在途、写最多2在途、无隐式重试 |
| 初始目标 | loopback MCP State GET P95≤50ms，必要持久化确认 P95≤150ms；容量内无意外丢失、串用户或未解释拒绝 |
| 其他路径 | resolve/search 单列真实返回体、P95/P99及完整成本；没有冻结过的 SLO 不补造已达标数字 |
| 公网测量 | 客户端网络/TLS与服务时间分开，不把loopback目标直接当公网总延迟保证 |

这些是待接受的限定容量目标，不是已经达到的服务承诺；完整请求分母、排队时间、拒绝、超时和 UNKNOWN 保留。
独立搜索和读写可并发，但不能对存在依赖的工具调用强制并行。
已有等价结果可复用；配置改变即另列条件，不反复全矩阵压测。

旧“10次导入/s，48/50完成、保存P95约260ms”的门仍为未通过。新低写入交互范围即使通过，
也只支持该范围的候选使用，不能宣称旧门已修复或支持大批量导入。先关联 fsync 的文件角色、
线程等待及请求，再做单项修正；不关闭可靠同步、不盲目扩队列、不依据孤立磁盘测试迁移生产存储。

### U5：把实验中能用的路径交给用户

交付至少包括：一个固定版本的产品接入示例、一组普通任务/续做操作说明、一条可复现的 G/R 命令入口、
保存与恢复状态说明、适用容量和已知限制。说明必须与实际授权 catalog 相同，不能继续引导用户调用被关闭的治理工具。

若为确定性恢复增加 Host 接入，配置/实现归属 Product，Lab 只负责评价与运行编排；
仅有 Lab 私有脚本才能恢复，不能通过产品交付。没有新增产品代码需求时，只补说明与直接验收，不造框架。

## 5. 冷启动、真实调用与可归因观测合同

### 5.1 冷启动保留什么、隔离什么

| 保留 | 不得继承或注入 |
|---|---|
| 同一合法用户和工作流绑定、正常产品配置及客户端必要认证状态 | 旧 Codex thread、`exec resume/fork`、临时对话、自动导出的历史摘要 |
| G实际代码、普通笔记、测试和完整合法来源 | 评价答案、失败分析表、标准 Evidence ID 列表、研究变体标签 |
| 通过公开 MCP 保存的真实记忆及可核验操作结果 | 从服务端/数据库后台拼出的答案、评测助手事后改写的 State |
| 新任务正常提供的新材料 | 其他用户的 State、缓存、rollout、配置和凭据 |

使用独立进程和干净会话目录，认证凭据与对话记录分开管理。记录 G 退出及 R 的新 PID/thread 身份、
初始文件 manifest、来源版本和最初实际输入。模型服务可能有共享前缀缓存，其命中若不可观测记 unknown；
不能把新进程称为“全部缓存清空”，也不能让旧会话内容通过服务端 continuation 被复用。

不删正常文件来制造记忆优势。记忆是否改善无记忆方案的效果不在本 Goal 中通过这种链推断。

### 5.2 每个关键调用最少关联这些信息

1. 客户端/会话身份、触发者（模型、Host生命周期、固定脚本）、工具名与调用 ID。
2. 实际发送参数的受限记录或摘要、MCP结果及 `isError`、Runtime request/operation 与版本身份。
3. 模型实际收到的工具结果、相关来源/span、输入摘要与时间；区分 acquired、presented 和 truncation。
4. 第一次相关实质动作的工具参数/文件差异/明确交付，以及最终测试/产物。
5. 模型请求预算预约、实际usage、工具与等待时间、未知结果、失败和清理。

`tools/list`、Host预取或 MCP HTTP 200 均不能单独证明模型实际调用并使用了 Memory。
不得只保存最终回答中的“已记住”；不得将初始 prompt 导出当作后续所有请求的证据。
工具结果被客户端截断时，记录实际呈现范围；不在截断后仍声称关键来源已完整呈现。

受限原始记录放在 Lab Git 外产物目录。普通报告不含认证头、cookie、refresh token、Runtime 密钥或私人正文；
不索取、展开或公开模型私有思维链。只评价可观察动作和交付，不猜测模型“已经理解”。

### 5.3 失败分类决定下一步

| 观察 | 分类 | 允许的下一步 |
|---|---|---|
| Codex不能正确发送/接收本地模型工具消息 | CLIENT_MODEL_COMPATIBILITY | 修协议/配置最小缺陷；模拟Host结果另列，不自动付费兜底 |
| 看不到工具、参数不清、结果不能回到模型 | TOOL_USABILITY_OR_TRANSPORT | 修catalog、说明、参数/错误映射或传输；不改任务答案 |
| 用户正常续做但Agent未调用Memory | ACTIVATION_NOT_ESTABLISHED | 核对受支持工作流；显式调用只作诊断；必要Host接入另标HOST_MANAGED |
| 记忆/来源没被实际呈现 | RECOVERY_OR_DISCLOSURE | 查绑定、来源资格、装配/截断，不先增大检索范围 |
| 必要来源已在动作前呈现，仍作出错误判断 | HOST_INTERPRETATION_OR_ACTION | 离线对照已有输入与动作；修一般说明缺陷或保留模型能力限制，不追加Reader |
| 回执缺失、CAS冲突或源失效 | MECHANICAL_OUTCOME_OR_SCOPE | 保持明确失败/UNKNOWN，安全继续无关工作；禁止盲覆盖 |
| 来源与任务正确但没有记忆机会 | NO_MEMORY_OPPORTUNITY | 保留任务结果和成本，不制造保存机会或自动重跑 |
| 触及预算/时限，输出不完整 | BUDGET_OR_DELIVERY | 停止后续发送并结算；不把截断运行解释成完整语义比较 |

不因单例失败停止整个工程开发；能离线修复的一般原因继续处理。重新运行模型仍占同一累计额度，
不得通过新 execution_id、换目录、换 seed 或改名隐藏重试。涉及新权限或额外费用时先取得相应授权。

## 6. 成本与执行授权：先两会话，再决定是否扩大

**当前授权仍为0。** 用户明确执行本 Goal 后，按下表建议值登记获准批次；没有授权记录或传输预算控制，
runner 默认拒绝生成请求。本地模型不等于免费资源，不继承旧 SIM/N5 的历史额度。

| 阶段 | 建议最多会话/请求 | 建议累计raw token上界 | 放行条件 |
|---|---:|---:|---|
| 兼容探针 | 2次实际生成请求，不计产品任务会话 | 16,000 | 零模型协议与预算测试先通过；两次计入总账 |
| U2 首条G/R | 2会话，各最多8请求 | 128,000 | 对应机械门通过；优先只申请到此阶段 |
| U3 R2/R3 | 2会话，各最多8请求 | 128,000 | U2通过且该批额度获准；不重做G |
| U4 必要公网补充G/R | 最多2会话，各最多8请求 | 128,000 | 仅在U2/U3不能复用为实际入口证据时申请 |
| 全部上限 | 最多6任务会话＋2探针，合计≤50生成请求 | **400,000** | 不是一次性自动执行额度；阶段退出条件持续有效 |

默认单任务会话raw上限64,000；单请求输入上限16,000、输出上限8,192，实际发送上限还要受剩余预约约束。
兼容探针每次总上界8,000。会话deadline建议180秒、单模型请求90秒、单MCP调用20秒；
运行前验证这些参数在当前客户端/Provider上真实生效。不能为适配token上限静默丢弃合法关键来源。

发送控制要求：

- 原生 Codex 和模拟 Host 都必须经过获准的本地 Provider 路径；不加载付费模型认证、不自动回退、不使用隐式重试。
- 发送前用同一服务/模板的可信token计数或已验证保守上界，预约完整输入（含工具Schema、历史工具结果等）及输出。
  上下文窗口、20k提醒、字符数估算和单次工具截断不是累计费用硬上限。
- usage含失败已发送请求；cached input 是 input 子集，不能重复相加。未知usage保留预约并阻止新发送。
- 超时/杀本地进程不等于服务端未生成；核对在途请求终态，不盲目释放预算或开始下一批。
- 兼容探针、显式诊断、tokenize、模型重放分别记账；默认新增总结、Judge、语义Reader、付费embedding请求均为0。
- 同一任务最多一个在途生成请求；MCP独立工具、不同用户读写的并发仍按服务容量控制。

成本分别报告：G与正常记忆形成、保存、每次冷恢复、来源读取、生成、工具、索引、失败、准备及清理。
金额、raw/cached/output tokens、墙钟、本地CPU/GPU和存储分账；未观测值保留unknown，不填0。
共享G的实际实验成本计一次，讨论产品链时不得把G免费化。质量未通过时不能仅凭token下降宣布降本。

当前400k是可审阅的规划上限，不是目标消耗量；首个G/R无可修复进展时，停止模型扩样，保留工程工作。

## 9. 完成条件、部分交付与停止规则

### 9.1 本Goal完成条件

只有以下条件同时成立，才能标记 **COMPLETED_LIMITED_PLUGIN_USABILITY**：

1. 原生Codex＋本地模型路径成立；真实调用、工具返回与后续输入有证据，不能仅有模拟Host。
2. G/R及R2/R3在普通受支持工作流中完成，M06–M09取得适用行为证据；没有操作者事后补写State或注入答案。
3. M01–M14各项必要证据齐备；工程复用注明原pin/配置/适用性，未覆盖项不能补填PASS。
4. 产品安装/配置入口可复现，实际已可用OAuth入口有对应版本的普通记忆操作证据；不再要求重做登录开发。
5. 声明的交互容量与错误反馈可用；预算、失败、未知结果和清理已核对，没有未结算的模型在途请求。
6. 报告明确只有一条开发链及限定客户端/容量证据，不声称增量效果、广泛泛化、自动维护或批量导入门通过。

若因可靠性需要产品化HOST_MANAGED恢复，应如实交付并标注触发者；
**仅Host代读、模型没有实际MCP使用证据时，不能授予普通直连插件的完整通过。**
不具备生命周期接入的任意第三方客户端仍只承诺已测工具及显式操作，不承诺自动保存/恢复。

### 9.2 部分结果不能升级成完成

| 结果 | 可交付结论 | 仍缺什么 |
|---|---|---|
| HTTP/PG及mock工具序列通过 | 工具与持久化工程候选可用 | 真实模型选择、调用与正确续做 |
| 模拟Host完成链 | 本地模拟条件下真实MCP闭环成立 | 原生Codex客户端及其实际装配/行为 |
| G/R通过，R2/R3未完成 | 单次保存—冷恢复可用 | 连续纠正、后续复发/负迁移检查 |
| HOST_MANAGED可用、直连激活未成立 | 该受支持Host路径可用 | 普通插件使用仍需显式说明，不能宣称自主激活 |
| 本地候选通过，实际安装/公网操作未核对 | 本地版本可用 | 产品交付版本和实际入口证据 |
| 交互范围通过，旧批量导入门失败 | 限定低写入候选可用 | 批量摄取容量；不得扩大公开容量承诺 |

某条链失败只否定该条件下的完成，不把所有已有工程成果推倒重来。
已有关键来源及时呈现而行为仍错时，不继续扩检索；仅换格式/提示后需要新结果，不能改写旧SIM12。
预算耗尽或兼容探针失败后停止新增生成请求，报告PARTIAL及具体缺口；不默认扩大模型、seed或Judge矩阵。
