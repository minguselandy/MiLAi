## 5. 拟实施合同

### 5.1 作用域：提示跟随请求，不改变存储绑定

修复 get 的 ABSENT/存在状态、`mcp_usage_contract.resume.arguments`、update 成功提示及错误恢复参数。
TASK 只能作为未指定 scope 的默认值；SESSION/PROJECT 调用返回相应 scope，不引导下一次切换。
每请求构造独立指导对象，不修改共享常量导致并发请求相互污染。

不改变 principal/project/scope_ref 派生、TTL、现有行身份或跨会话 Note 的存储方式。
SESSION 指当前可信绑定的会话范围，不能宣传为任意新会话都恢复同一 SESSION；任务续做默认 TASK。
普通目录按当前任务或已启用 Host 生命周期使用记忆，不把强制 TASK 读取应用到所有普通问答。
需要保证启动读取时仍由 Host 承担；服务描述不能证明模型已经调用。

### 5.2 Proposal：公开已启用操作的真实输入合同

| 操作 | 目标约束 | 证据约束 | patch 边界 |
| --- | --- | --- | --- |
| CREATE | 不指定已有 target_claim_id/expected_version_id | supporting_evidence_refs 非空 | subject_id、predicate、claim_type、payload、confidence 必填 |
| SUPPORT / WEAKEN / REVALIDATE / REGROUND / SUPERSEDE / CONTEXTUALIZE | target_claim_id 与 expected_version_id 必填 | supporting_evidence_refs 非空 | 按现有该操作校验，不把所有分支强制成 CREATE |
| CONTRADICT | 两个目标字段必填 | contradicting_evidence_refs 非空 | 按现有冲突记录合同 |
| NO_CHANGE | 两个目标字段必填 | 不额外捏造非空证据要求 | 按现有无变更合同 |

MCP 当前只开放上述 9 种操作；不因 Runtime 更宽类型包含其他枚举就自动开放新操作。
身份、项目、scope、authority 仍由 Host/Runtime 可信边界提供；CREATE 外部输入不要求模型填写 authority。
业务 payload 自由，不能为工具可读性冻结业务 State schema。

可机器表达的约束进入 Schema：UUID、长度、枚举、数组上限/唯一性及操作条件必填。
支持/反对集合不相交、权限、引用资格和当前 head 等跨对象规则保留服务端校验及准确字段错误。
SUPERSEDE 中已有的 OpenIssue 条件字段也要与 Runtime 对齐；不以“对象任意”隐藏实际生效的条件。

先检查实际宿主能否保留 `$ref`、`allOf/if/then`，再选择最小表示调整：
优先由现有模型生成可完整解析的 Schema；需要展开引用/操作分支时只在对外序列化边界处理。
不能假定改成 oneOf 或追加自然语言就一定对所有客户端有效；不另建手工 Schema 或重复的业务校验器。
保留旧合法调用与错误码；为真实已启用分支提供可执行合成示例，确认词不代表用户授权。

| --- | --- | --- |
| 字段或组合不合法 | INVALID_REQUEST / INVALID_TOOL_ARGUMENTS 等现有边界码，附字段 path/type/expected | 修正输入；不把 expected_version=0 与已有 state_id 的矛盾误报 CAS |
| 合法请求版本过期 | STALE_WORKING_STATE / STALE_NOTE | 同 scope 重新读取，再由 Host 合并；不能只抬高 expected_version 覆盖 |
| 同操作 ID 不同载荷 | OPERATION_CONFLICT | 核对原请求；新载荷使用新 operation_id，不自动随机换 ID 重试 |
| 超时/断线，提交未确认 | WORKING_STATE_OUTCOME_UNKNOWN / NOTE_OUTCOME_UNKNOWN | 原操作核对或受控原样重放；不当作未保存 |
| 读取不可用/拒绝 | 对应 UNAVAILABLE / scope/来源不可读状态 | 不转换成 ABSENT、MISS 或“没有记忆” |

建议冲突载荷示意，尚非当前响应：

```json
{
  "code": "STALE_WORKING_STATE",
  "scope": "SESSION",
  "expected_version": 1,
  "current_version": 2,
  "retryable": false,
  "recovery_action": "READ_AND_REBASE"
}
```

`retryable=false` 表示不能由通用重试器原样自动重发，不表示永久不可修改。
current_version 仅在有权披露且后端确实给出时返回；它是观察值，不保证下一次写入前不再变化。
不回显输入正文、token、数据库参数或其他主体的对象信息；字段详情按允许字段与约束类型投影。

Note 已有 `note_operation_get`；Working State 当前没有同名的独立操作查询工具，不能编造 next_tool。
Working State GET 仅能看当前状态，不能独立证明某次未知提交失败；保持原 ID/载荷的核对规则。
不因一次超时强制增加新接口、永久双请求保存路径或自动重试。

优先利用现有 MCP 结构化结果与 SDK details，保留 MCP isError=true、稳定 code 和兼容消息。
**纯文本改 JSON 不是天然兼容**：T0 明确旧目录/调用方的解析方式；若必须改变 content 形态或字段名，
先版本化合同并限定采用范围，不静默破坏 legacy。不得把后端 details 整包透传。

### 5.4 说明与指导：短、准确、不会自动升级操作

- 公共原则放 server instructions；每个工具只留用途、关键约束、作用域和必要风险提示。
- 统计实际 wire、宿主转换后说明的长度/重复次数；需要 token 数时离线计量，不发模型请求。
  不预设压缩比例，不为省字删除“Note-only、来源未查全、逻辑删除、当前授权”等关键边界。
- 普通读/写成功以结果解释为主，不无条件附带 proposal/review/revoke/cleanup 的操作邀请。
- 可选动作建议可以使用 `suggested_next_step`，但首版不把字段改名设为硬门；复用旧字段时同样弱化指令性。
  涉及正式治理/删除时明确 `requires_user_authorization=true`，仅表示要求，绝不是授权已满足。
- 普通已启用的 Note/检查点写入不因此变成每次都要单独弹确认；读取和必要核对也不贴错误的治理标签。
- 不长期同时返回两套完整指导；旧字段迁移须有兼容安排。权限、确认检查与当前用户意图边界保持。

### 5.5 删除与目录：准确披露，不扩张范围

保留 `milai_note_delete` 名称及现有 tombstone/历史保留行为；拟在其 deletion 状态中补充
`physical_deletion_supported: false`。get 已删除对象、delete 回执和 operation 回执的表达一致。
仍报告 logical=APPLIED、primary_storage=NOT_IMPLEMENTED、backup_expiry=NOT_SCHEDULED，不能升级为全量擦除。

完整高级能力继续遵循 [ADR-050](../adr/ADR-050-full-private-mcp-capabilities.md)。
普通接入推荐不请求不需要的管理 scope；不能追溯撤销或扩大现有用户 grant。
目录与 dispatch 共用有效权限检查；隐藏工具不是权限控制，手工调用同样必须拒绝越权。
当前 cleanup status 也使用 admin scope，不能仅为“状态只读”改成普通 memory.read。
独立管理界面是可选后续，不是本次必须开发的产品，也不是绕过宿主安全检查的路径。

## 10. 跨 session 检索：独立交付目标

### 10.1 要实现的用户体验

**会话 A 正确保存的记忆，在同一合法身份与私有空间的全新会话 B 中，只凭当前问题即可发现并读取，
不要求携带旧对话、旧 memory_id、previous_context_id、cursor 或检查点。**

最小路径：A 经公开 MCP 保存普通 Note 并取得提交确认 → A 结束 → B 使用新进程/新会话 →
按当前问题发现历史 → 根据搜索返回的类型化引用读原文 → 在首次相关回答/行动中正确使用。
“用已知 ID 回读”是另一项有用能力，但不能单独证明“不知道 ID 的跨会话发现”。

跨 session 不等于跨用户、跨租户或跨未授权项目；也不等于搜索整个工作站上的会话文件。
Note 的稳定身份来自可信主体与私有项目，不应随 session、客户端注册 ID 或一次 token 刷新改变。
权限重新计算：同一用户新 token 没有 Note 读权时应拒绝，而不是为了恢复效果绕过权限。
SESSION Working State 仍是会话范围检查点；不能通过把它改成全局共享来实现这个目标。

### 10.2 现有检索优化已经做了什么

| 项目 | 已有实现/证据 | 本次补充的产品验收边界 |
| --- | --- | --- |
| 跨对象发现 | `milai_memory_search` 并发调用 Note 与治理检索，各自检查权限 | 目标客户端必须真正获得该入口和所需读权；不能只看到旧 resolve |
| 查询衔接 | 普通目录说明保留 Note 路由；resolve 明确不搜索 Note；已知 ID 使用对应 get | 新会话不能先查错层，再把单次未命中说成“没有历史” |

| 隔离与冷恢复 | 已有 PG/HTTP 测试：新进程、新 token、服务重启后，仅 query 经统一入口发现已保存 Note | 是合成协议工程证据，不是目标 Agent 自主发现/正确使用通过 |

Note 首版保持短关键词/短语的字面搜索，Host 可提供 note_query；不自动拼接多语言词、不新增同义词表、
检索模型、全库遍历或隐式重试。词面不相交的语义遗漏是已知限制，不把跨 session 存储误称语义检索完善。
需要历史时才检索；工具可见不代表 Agent 会自主调用，Host 预取也不能冒充自主选择。

### 10.3 必须先对齐实际连接，而不只检查包版本

最新部署记录显示两条独立入口：7968 保持 MCP 0.1.11，7960 OAuth 已升级到 0.1.13，目录不同：

| 入口 | 保留目录 | 对跨 session Note 检索的含义 |
| --- | --- | --- |
| 7968 HTTP legacy | 13 工具 | 没有 Note 工具及统一 memory_search；只升级程序不能补齐这些能力 |
| `https://milai.aigcit.com:7960/mcp` OAuth | ordinary-memory-v1，注册 22 工具 | 0.1.13 移除整库清理提交，保留查询；Note 与统一检索不变；实际用户可见工具仍按权限过滤 |

依据：[HTTP 部署回执](../releases/MCP_0.1.11_HTTP_DEPLOYMENT_20260908.md)、
[OAuth 0.1.13 部署回执](../releases/MCP_0.1.13_OAUTH_DEPLOYMENT_20260908.md)。这是部署记录，不是目标客户端验收结果。
前次核查的目标宿主连接 7968；不得假定后来升级 7960 就已自动改变那个客户端的连接和私有空间。

CS0 先核对目标客户端实际 endpoint/catalog/tool names、有效读权及稳定身份绑定。
不要求为了读 Note 授予全部 12 个 scope；至少需要该路径的 Note 读取能力，治理分支可明确未授权。
选择现有 ordinary OAuth 连接作为首个跨会话 Note 接入路径；若用户要求继续在 legacy 入口提供 Note，
先另定兼容、身份和启用范围，不擅自切换目录或把 legacy 数据复制进 OAuth 私有项目。
旧入口与新入口的身份/项目不能因为“同一人使用”就自动合并；跨入口迁移不属于跨 session 检索本身。

当前 OAuth 部署回执保留外部撤销元数据合同缺口，真实用户登录/读取/刷新未完成复测。
CS0 如遇实际认证阻断，记录具体失败并按既有认证边界处理；不能降级到共享身份、去掉校验或把状态改为通过。

### 10.4 增量安排

| 阶段 | 工作 | 完成边界 |
| --- | --- | --- |
| CS0：接入确认 | 核对目标客户端实际目录、scope 与身份；区分 legacy/ordinary；必要的客户端启用变更先明确范围 | 新会话可见合法 Note 发现/读取入口；未通过则不开始公开写入试验 |
| CS1：最小缺口修复 | 复用已有统一查询、稳定 Note 身份和冷恢复夹具；只有复现通用缺陷才修改 MiLAi 对应层 | 不新建数据库/统一业务 schema，不把查询问题修成权限放宽 |
| CS2：无 ID 冷发现 | 合成 A 保存，关闭 A；B 不继承目标 ID、旧工具结果或查询状态，query → 返回引用 → get | 可核验同一对象/版本/正文；身份外用户仍不可获得该内容 |
| CS3：变化与降级 | 更新/删除/来源撤权、新 token、重启、查询未命中、来源超时、长片段及事件日期检查 | 查询和展开资格一致，负面回答限定范围，工程成本有界 |
| CS4：真实会话使用 | 用户另行放行后，按前序 U5 跑一条正常 A/B 链；复用合法已有 A 时不重复造记忆 | 记录实际模型输入和首次相关动作；不以脚本/预取替代自主调用证据 |

顺序为 CS0 → CS1（仅必要修复）→ CS2 → CS3 → CS4。现有本地证据可复用，但必须标明用例边界；
当前补充计划未执行，不能把现有 V12 PASS 自动复制给所有 CS/XR 项。CS4 继续零新增已授权额度。
此段不授权公网测试写入、客户端账号切换、部署或模型；执行时按具体对象/环境和既有授权门推进。

### 10.5 跨会话专项验收

| ID | 通过要求 | 证据边界 |
| --- | --- | --- |
| XR01 | 目标客户端显示所需 Note 发现/读取工具；实际范围可确认 | 当前注册 22 工具不替代用户 tools/list；也不要求最小读令牌看到全部项 |
| XR02 | A 保存确认，B 新进程/会话仅凭当前 query 发现，再用新返回的 ID/版本展开正确原文 | B 输入不得预置目标 ID、旧 cursor/context_id、旧响应或答案缓存；已知 ID 回读另计 |
| XR03 | 同 issuer/sub/私有 namespace 的新 token/新客户端不丢合法记忆，其他身份不能读 | token grant 变化仍执行当前权限；不把 client_id 当记忆身份，不复制旧用户数据救测试 |
| XR04 | 服务与客户端重启后仍能走 XR02；未提交和 UNKNOWN 不冒充已保存 | 本地隔离真实 PG/HTTP，不依赖进程内缓存；保留原提交核对语义 |
| XR05 | Note/治理一侧失败时保留另一侧结果和失败范围；空结果不宣称历史不存在 | 权限拒绝不换范围；必要追查有界，无默认 50 条全列和自动重试 |
| XR06 | 搜索命中后按类型和版本展开；长文关键否定/条件/日期真正呈现 | “这周”按提问时区与正文事件日期解释，记录时间不代替事件时间 |
| XR07 | 更新后默认读当前有效版本；删除/撤权后旧搜索引用和历史读取不泄露 | 不把 Note 逻辑删除称物理擦除；其他合法对象不受牵连 |
| XR08 | 工程轨迹列明模型零调用、一次查询的两路实际读取及后续展开/延迟/失败 | 小样本不是容量或总体省钱证明，不新增语义服务费用 |
| XR09 | 真实 Agent 的首次相关回答/行动正确使用 B 实际取得的证据 | 待另行授权；区分 AGENT_TOOL_SELECTION、HOST_PREFETCH 与脚本协议客户端 |

分层报告：`ENGINEERING_CROSS_SESSION_VERIFIED`、`TARGET_CLIENT_CROSS_SESSION_VERIFIED`、
`AGENT_CROSS_SESSION_USAGE_VERIFIED` 分别需要对应证据。仅有第一层，不写“真实 Agent 跨 session 已可用”；
第二层通过可说明特定客户端协议使用切片可用，第三层也不证明长期净收益或自动维护有效。
