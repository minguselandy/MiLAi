## 4. N1：先让拒绝可以解释，再修复误报

实际实现落点：Product `runtime/src/milai/testkit/retrieval_trace.py`、相邻 observer 与定向测试。Lab 只调用公开 testkit，不导入这些私有函数。

先固定 query、reference time、source snapshot、来源/投影身份、scope、D1 配置和预算，停止同实例的导入写入，区分三类问题：

- 数据/投影在三次读取之间变化：先修实验时序，不能删除 watermark/snapshot 校验。
- 非业务运行身份不同：先列出具体 JSON path 和关系，再决定是否是合法的比较规范化。
- 返回证据、顺序、内容、资格、continuation 能力或 repository 行为真实变化：继续拒绝，定位真实原因，不包装成中性。

拟补的响应诊断只输出有限的字段路径、类型、数量和摘要，不额外披露来源正文。已有 observer/repository 比较继续保留。

若实际差异确认为局部 continuation ID：

1. 验证其与同次 receipt、root、query、scope 的绑定关系；原始 ID 留在受控 artifact。
2. 只对已证明是 run-local 的标识建立明确对应关系；不能简单删掉 `continuation` 或按字符串相似度忽略字段。
3. 继续逐项比较 generation、available/reason、frontier/尝试/失效计数、来源身份、顺序、内容摘要及缺失/降级行为。
4. 更改公开 testkit 的摘要口径时记录新语义版本/兼容说明；旧 digest 和 Product-10 冻结实验不重新解释。
5. 真实 PG 验证绑定与同查询续取仍有效，错误 scope/query/root 或实质变化仍失败。不得改变 Context ID 的权限含义或对外生命周期来迁就观测。

详细复现矩阵与验收见 [Lab 实验合同](../../../MiLAi-Lab/studies/active/MILA_V02_LOW_COST_REUSE_PLAN.md#3-n1-行为中性诊断合同)。若该假设不成立，改查实际差异路径，不继续围绕猜测修改 Product。

## 7. N4：真正比较额外成本

每条历史先进行一次正常共同任务 G，交付真实文件，记录它自然产生的 State。将该完成点固定为共同起点；两个后续任务提前固定且对 G 不可见。

| 臂 | 实际任务文件 | 起点 State | 额外动作 |
|---|---|---|---|
| F：完整 A0 + 文件 | G 的全部实际产物，包括笔记 | G 实际完成后的 State | 无额外 checkpoint；仍有完整 GET/UPDATE 与查源能力 |
| S：相同 A0 + 文件 + 原样笔记 | 与 F 相同 | 从同一旧 State 经 N3 实际成功保存所得 | 一次显式、无模型的复制与公开提交 |

每条历史安排两个不同后续任务，分别从共同起点分叉：一个检验复用，另一个检验不同使用目的或已提供的新变化。保留允许的历史与普通工具；不能把 F 的文件藏起来。存在后续时间变化时，两臂收到相同的新来源，旧笔记不能被当成当前权威。

每种成本单位分别计算：

```text
Delta_save = 实测额外 checkpoint 的读取、封装、写入、确认与失败处理成本
Gain_2 = C(F_1) + C(F_2) - C(S_1) - C(S_2) - Delta_save
```

G 的正常工作/笔记生成成本在两个反事实路径中相同，比较时抵消，但仍完整记入本研究实际总成本；不能说笔记免费。复制若实际触发模型或额外摘要，计入 Delta_save 并标实现偏离，不能继续声称 zero-model。分支快照初始化是研究开销，单列且保留，不重复当成现实中每次续做必须发生的保存。

新实验不复用前轮整次生成扣费结果作为新配对，不改变前轮未回本终态。更多未来重访可能回本只可作情景分析，不能用外推次数替代本轮实际两个后续结果。

## 8. N5：有限扩展与保留规则

优先走保存候选确认：N4 质量无损、两条历史均达到 Lab 成本门槛后，在另两条 opened-development 历史上固定同一候选再做 2 × 2 × F/S；不能拿调参历史换问题当成独立历史。

如果 N4 不通过，只有 N1/N2 明确发现一般性问答缺陷时，才可选择 QA 小修复分支：4 对开发比较，通过后另 2 对冻结后复核。它是新的单一候选，不与保存/提示/检索量一起变化。两条分支共用 N5 额度，**本 Goal 最多选择一条**；选择及理由在其首次分配前记录。

保留规则概要：

- 先看来源支持、任务正确与原正确内容保留，再看成本；任何新增关键错误、越权或标签泄露停止候选。
- 保存路线须两条历史各自计入 Delta_save 后，两次后续总 token 至少降低 10%，在线墙钟净节省为正；未知成本不填零。N5 同口径复核通过才保留为有限场景的显式能力。
- QA 路线须开发 4 对至少 1 个净任务胜例、任务损失 0；中位 token/墙钟比均不超过 1.25，普通控制不超过 1.10；冻结后 2 对需再次出现至少 1 个任务胜例且无损失。只支持局部开发证据，不是泛化证明。
- 只有 trace 更完整、返回更多 ID 或写入更多内容，不构成任务净收益；工程改进仍可独立保留。

这些是本 Goal 的产品取舍阈值，不是统计显著性、正式 LME 分数或生产 SLO。预算不足、标签不可靠或没有保存机会时如实报告，不降低阈值换取正向结论。

## 9. 预算与执行保护

| 阶段预算 | 模型分配上限 | 说明 |
|---|---:|---|
| N0–N2 | 4 | 默认先做非模型复现/审阅；只用于必要 smoke、公开行为诊断或单独评分调用 |
| N3–N4 | 12 | 2 次共同任务 + 8 次 F/S 后续 + 2 次失败诊断/重试；N3 checkpoint 本身不得调用模型 |
| N5 | 12 | 保存确认：2 次共同任务 + 8 次后续 + 2 次预留；或 QA：4 对开发 + 2 对复核，后者无隐含重试额度 |
| 合计 | 28 | 不是必须跑满；未用额度不自动转入其他阶段 |

取消、失败、偏离均占分配；任何额外模型 reviewer/压缩器/生成器也占额度，不藏在“预处理”内。默认不启动子 Agent。已经发生的调用不能在修复后抹掉或计为 0。

沿用本机已验证的 Host/模型配置，首批前核对实际版本；两臂一致。默认 300 秒/模型会话、24 次工具动作 watchdog，每批最多 4 分配/1,200 秒累计在线预算，单 case capture/readiness 最多 300 秒。采用已经验证的串行 persistent-client、journal OFF，不再跑三组旧导入提速证明。

新增已知总 token 的启动闸门：累计已观测 input+output 达到 2,400,000 后，不再启动实验模型会话。它是完成/观测后的软停线，不是正在执行请求的硬上限；120k rollout 仍仅软提醒。模型已启动但 usage 不可得时先查证，不以未知为零继续扩批。记录实际超出与缓存子集，不虚构账单。

N1 的非模型真实接口诊断先限两批，每批最多 6 个 testkit 调用（一次含 normal/baseline/traced 三次读取），每调用 120 秒；源码/单测验证另记时间。第二批仍无新增定位信息时提交差异与未解原因，不通过无限重跑等待偶然相等。

只有当前 run 身份明确、所有前置分配有终态、来源/预算/安装核验通过时才能开下一批。扩充总预算、访问新的数据范围、公开部署、改变权限/Canonical/schema 语义不在本文默认范围内。
