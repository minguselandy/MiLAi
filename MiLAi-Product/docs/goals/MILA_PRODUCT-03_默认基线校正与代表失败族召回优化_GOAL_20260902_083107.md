# MILA-PRODUCT-03：默认基线校正与代表失败族召回优化

## 1. Goal

先让 Product 默认运行 Product-02 已选择的简单 B0/B1 行为，再对现有错误按首损分族，使用正式
Product acquisition 做只读机会诊断，只实现一个经过机会证明的通用优化。

目标不是重启 B2，也不是一次建成自适应 Memory Agent，而是：

```text
真实默认基线
→ 真实 pre-filter trace
→ 代表失败族
→ 一个简单 treatment
→ 单点、24、64、opened-128 逐级验证
```

## 3. 新发现的 P0 冲突

Product-02 的终态选择与当前配置默认值尚未对齐：

```text
selected B0:
  progressive_context_evidence_v0_1 = true
  LOOKUP → GOVERNANCE_ADMITTED_SOFT_RANKED

current Product default:
  progressive_context_evidence_v0_1 = false
  LOOKUP → DECISION_ACCEPTED_ONLY
```

`false` 实际触发了被否定的 B2 presentation 行为。任何新 retrieval experiment 前必须先修复
这一配置语义，不能一边宣称选择 B0，一边让默认安装运行 B2。

同时，当前名为 `raw_retrieval_trace` 的内容来自已通过 `_access_outcome` 过滤的 items，不是严格
意义上的 pre-filter candidate snapshot。下一次首损分析必须先补上真实 acquisition trace。

## 4. Research hypotheses

### P03-H1 — Selected-baseline reality

默认安装的 LOOKUP 路径应真实执行 B0/B1 的 governance-admitted soft-ranked Reader context；
STRICT 的 COMPLETE、Sufficiency 和 deterministic operator 仍只消费 accepted Binding。

最低证据：默认设置、capability trace、Context trace 和 local golden flow 一致；LOOKUP 不因空
EvidenceSet 清空 Raw Evidence；STRICT Wrong COMPLETE 仍为 0。

### P03-H2 — One simple residual improvement

在保持 B0/B1 Context 和安全边界不变时，一个由 official channel opportunity probe 选出的简单
treatment，能改善一个跨至少两种 query/source 形态的主失败族，而不降低全局 required-role
coverage 和 Qwen paired correctness。

Anti-claim：增益不是来自恢复 B2、增加无边界 Top-k/token、修改 Reader/Judge Prompt、重试、换
seed 或 case-shaped 规则。

## 5. Core scope

### In scope

- 将默认 Reader evidence policy 对齐到 B0/B1；
- 保留 strict accepted-only proof，不恢复错误 COMPLETE；
- 增加真实 `acquired → bound → reader-visible` 三层 trace；
- 从既有 opened 128 中选择多错误族代表病例做只读 official acquisition probe；
- 根据 probe 只实现一个 T1；
- 使用 synthetic/representative、24、64 和 opened-128 做工程验证；
- 失败后参考 Hindsight、ReFind、Mem0、Graphiti、OpenViking 的最小机制并继续。

### Out of scope

- 修改或重新启用 B2 hard-filter prototype；
- 500-case formal holdout；
- public API、PostgreSQL Schema 或 migration；
- 新权威 Store、全局 Graph、durable Formation projection；
- 默认多轮 search Agent、Reflect 或模型 `COMPLETE` 权限；
- 同时修改 retrieval、Context budget、Reader Prompt 与 Judge；
- 对 sealed case 写 synonym、entity、quote 或 ID 规则。

### P0 — 默认基线与可观测性校正

#### 目标

将模式显式化，移除布尔值反向语义：

```text
LOOKUP
→ GOVERNANCE_ADMITTED_SOFT_RANKED

STRICT
→ DECISION_ACCEPTED_ONLY for proof/operator
```

推荐使用一个内部 enum/policy，而不是继续让 `progressive_context_evidence_v0_1=False` 隐式
表示 B2。兼容旧配置的转换只放在 Settings 单一边界，不在 retrieval、resolve 和 Context 分别
增加 defensive branch。

新增三层 trace：

```text
acquired_candidate_trace
  official acquisition 返回、任何 semantic boundary 前的候选

bound_evidence_trace
  形成 MATCH Binding / EvidenceSet 的候选

reader_visible_trace
  实际进入 tokenizer/chat template 的 atomic units
```

#### 硬门

```text
Default LOOKUP boundary                    GOVERNANCE_ADMITTED_SOFT_RANKED
Default STRICT proof boundary              DECISION_ACCEPTED_ONLY
Empty EvidenceSet clears LOOKUP Raw        0
Strict Wrong COMPLETE                      0
Trace stage identity                       1.0
Reader-visible trace exactness             1.0
Scope/revocation leak                      0
```

P0 是 Product bug repair，不需要重新运行 Answer/Judge；先跑 targeted unit、golden flow 和 24 个
context-only scenarios。

### P1 — Representative failure-family opportunity probe

#### 输入

从 Product-02 opened 128 选择 12–16 个 Lab-only representative cases：

```text
F1 Discovery                 至少 6，覆盖 ≥4 query types
F2 Session-hit/turn-miss     至少 2
F3 Partial EvidenceSet       至少 2
F4/F5 Visible-but-wrong      至少 2 个负控
```

Product 只接收合成的 contract tests；真实 case selection、labels 和 scoring 留在 Lab。

#### Probe

所有 probe 调用同一个 official AcquisitionService，不实现 Lab-owned BM25：

```text
A0 current Raw FTS
A1 Evidence Dense
A2 Raw FTS + Dense independent small quotas / rank fusion
A3 session-hit 后 bounded same-session turn expansion
```

固定：scope、snapshot、candidate cap、hydration cap、timeout、无 Reader/Judge、无 retry、无
Canonical mutation。报告 `AcquiredExactTurnRecall`、`AcquiredRoleCoverage`、new region、重复率、
候选成本。

#### T1 选择门

只选择一个机制：

```text
新增 ≥3 个 required-role groups
AND 覆盖 ≥2 query/source types
AND 不依赖 case-specific cue
AND 不扩大 scope 或总 candidate ceiling
```

若没有机制通过，P1 记录 `NO_SIMPLE_CHANNEL_OPPORTUNITY`，转向 F4/F5 的 operator/Reader 专项；
不把 Dense、Graph 或 ReFind 强行加入产品。

### P2 — 单根因实现

根据 P1 结果，只允许一个 T1：

| Oracle 首损 | 可选最小 T1 | 参考项目模式 | 禁止扩张 |
| --- | --- | --- | --- |
| F1 channel miss | FTS/Dense 独立小 quota union + deterministic RRF | Hindsight、ReFind | learned router、query agent |
| F2 session hit/turn miss | same-session paired-turn bounded expansion | ReFind、OpenViking | 整 session 前缀、跨 session 拼接 |
| F3 partial roles | additive per-role breadth-first admission | Hindsight、OpenViking | accepted-only hard filter |
| F4 operator ready/Reader miss | operator result direct answer slot，Reader 只表述 | Hindsight Recall/Reflect separation | 再改 retrieval |

无论选择哪一个，均保持：

```text
EvidenceSet = priority/annotation signal
EvidenceSet ≠ LOOKUP deletion whitelist
STRICT operator inputs = AcceptedBinding only
```

## 7. 失败后的自动反思与继续

```text
失败
→ 定位 acquired / bound / visible / operator / Reader 中最早首损
→ 查询参考项目的对应最小机制，或记录 LOCAL_FIX_SUFFICIENT
→ 只改一个边界
→ 单 case + 对照 + 负控
→ 恢复当前阶段
→ 通过后自动继续下一阶段
```

参考项目用于当前修复，不是只放在最终升级：

- ReFind：session-hit/turn-miss、seen-region、一次 bounded reformulation；
- Hindsight：source-linked recall、Recall 与 Reflect 分离；
- OpenViking：breadth-first navigation、Raw evidence 作为最终证据；
- Mem0：ADD-only、scope/source metadata，不自动 promotion；
- Graphiti：occurrence/current time 分离、source-linked temporal candidates。

如果参考项目的完整系统超出当前首损，只借原则，不引入依赖。

## 8. 减少防御性编程与审计

- 一个 Reader evidence policy owner，不在三层重复判断；
- 一个 Governance Gate，不在 adapter/fusion/Context 重写 scope 规则；
- 明确捕获 timeout/unavailable；程序错误直接暴露，不用多层 `except Exception` 静默降级；
- 日常开发只更新本 Goal 的阶段表和一行 reflection；
- targeted/24/64 不创建 receipt hierarchy；只有 P4 保存标准 run/cases/metrics/terminal；
- 不重复已经通过的 635 Runtime、331 adapter 全量门；行为改动先跑受影响测试，P4 前再跑一次全量；
- 并行用于不同 cases/channels，禁止对同一 semantic failure 并发换 seed 或投票。
