## 1. 目标与执行边界

**让普通 Agent 不必理解 Evidence、Claim 和审核机制，就能正确保存、找到、读取、修改自己的记忆；
保留正式治理的独立入口，并让保存结果可以在真正的新会话中恢复。**

最小产品体验是：提交内容，获得稳定记忆 ID；按 ID 回读同一内容；按关键词搜索或分页浏览；
带版本条件修改；明确删除后可见性与清理范围。默认路径不新增总结、Reviewer 或语义提取模型。

本次用户要求是“生成 Goal 文档”。本文件是开发与验收计划，不代表代码已实现、服务已发布、
新工具已存在或模型实验已获授权。当前不启动开发执行、模型、服务或公网写入。
以后若明确要求执行本 Goal，先执行本地非模型开发；模型恢复和公网发布仍需分别明确放行。

本 Goal 将 [v0.2-06](MILA_V02_06_MCP插件真实使用与冷恢复_GOAL_20260908.md) 的 U1 接口工作前移并细化，
不重写其失败记录、累计成本、暂停状态，也不将其未完成的 U2/U3 或正式 D4/D5 补记为通过。
[产品闭环原规划](../MiLAi_产品闭环开发与实验规划_20260907.md) 的 Host/Runtime 分工保持。

## 3. 不变边界与明确不做的事项

1. 使用 MiLAi 自有 Runtime、PostgreSQL、SDK 和 MCP；外部项目仅作代码/接口设计参考。
   本文件不复核外部厂商当前能力，不接入 Mem0、Hindsight、Graphiti 等后端。
2. 正文自由表达，公共身份、来源、版本、权限和提交语义稳定。输入模型明确不等于业务 State schema 冻结。
3. Evidence 是观察，普通笔记是 `HOST_WORKING`，Canonical 才是经过治理接受的正式状态。
   不实现 `add → capture → proposal → auto approve`。
4. 可信主体、私有项目和允许范围由已验证登录态及服务端策略绑定，不接受模型自报其他用户或项目。
5. 权限、撤权、保留期和来源失效先过滤再呈现；新摘要不能通过回执、历史读、搜索或缓存绕过过滤。
6. 保留旧工具语义与认证 scope 交集；确认字面量不是当前用户授权的替代品。
7. 不新增 Hint、图结构、独立 Reader/Reviewer、每轮总结或自动维护；不启动新 LME 扩样、Formal 500 或排行榜比较。
8. 不强制每次保存后再 GET。正常成功回执应足够；冷恢复、异常提交核对等依赖场景才额外读取。
9. 不把实验单任务请求上限变成全服务锁。读取独立并发、连接复用；同一记忆局部 CAS，不同记忆不共享写锁。
10. 身份、删除、事务或存储结构变化先走 ADR 和适用迁移；不得修改冻结架构、重排旧迁移或直接删除不可变历史。

## 4. 拟实现的产品合同

本节为新能力的设计合同，不是当前已经发布的 MCP 工具列表。U0 冻结具体 schema 后才进入实现。

### 4.1 对象类型与兼容策略

| 对象 | 意义 | 精确读取 | 可修改性与边界 |
| --- | --- | --- | --- |
| Evidence | 不可变来源观察 | 拟增 `milai_evidence_get(evidence_id)` | 不原地改写；撤销仍走现有显式治理 |
| Claim / Canonical StateKey | 正式结论 | 保留 `milai_memory_get` | 继续 Proposal / Review / CAS |
| Working State | 当前任务/会话恢复检查点 | 保留 `milai_working_state_get/update` 合同 | 不拿一个检查点大 JSON 冒充任意多条笔记 |
| 普通记忆 Note | 可出错、可版本化维护的 Host 笔记 | 拟增 `milai_note_get(memory_id, version?)` | 外层 authority 固定 `HOST_WORKING`；独立 ID、版本和删除语义 |

首版普通记忆工具采用 `milai_note_*` 独立命名，避免把已有 `milai_memory_get` 静默改义。
产品仍称“普通记忆”；Note 是对象标签，不是新的推理模块。若后续改成显式 v2 接口，先更新兼容合同，
同一日常目录不并列发布两套同义 CRUD。

高级目录保留现有 13 工具语义。新增工具必须有版本化目录及逐工具 scope 映射、拒绝调用测试，
不得让旧凭据自动获得新写入/删除权。日常精简目录可另行显式选择；不擅自改现网默认目录或关闭高级功能。
目录裁剪不是权限控制，`tools/list` 与 `tools/call` 必须使用同一有效权限判断。

### 4.2 先验证存储能否承载，不默认新建后端

复用现有 Host Working 的权限、版本、幂等、审计和 PG 能力。U0 对下列条件逐项给出代码证据：

- 同一私有空间至少能有两条独立 Note，不占用或覆盖 TASK/SESSION/PROJECT 检查点。
- `memory_id` 是稳定 lineage 身份，版本独立；能按同一 ID 读当前/历史版本，且重新检查当前资格。
- list/search 能在授权范围内先过滤再分页，不先取全局 Top-N 再丢弃其他用户记录。
- 同一 Note 可 CAS，独立 Note 可并发；提交记录能区分幂等重放、冲突和结果未知。
- TTL、逻辑删除、来源撤权和物理清理的含义彼此明确。
- 不靠把所有笔记塞进单条大 State，或让模型构造可信 scope_ref 来绕过现有身份限制。

全部满足时复用现有存储；不满足时采用 MiLAi 自有 PG 内最小扩展，复用现有基础设施。
选择及理由写入一个 ADR，不为统一 CRUD 再造通用对象平台。需要迁移时追加新版本，并定义升级、
兼容、回滚/不可逆部分及真实 PG 验证；Schema NO-GO 不等于禁止经审阅的小型迁移。

### 4.3 普通记忆工具与最小输入

| 拟增工具 | 面向模型的核心输入 | 核心结果 |
| --- | --- | --- |
| `milai_note_add` | `content`；可选 `format`、`tags`、`source_refs`、`observed_at` | 新 `memory_id`、v1、提交回执；不生成 Claim |
| `milai_note_search` | `query`；可选过滤、数量、返回预算 | 有界片段、同一对象 ID/版本、来源入口、截断和索引状态 |
| `milai_note_list` | 可选过滤、数量、cursor | 不依赖相关性搜索的稳定分页 |
| `milai_note_get` | `memory_id`，可选版本 | 同一对象原文及版本；正文不可呈现时明确状态 |
| `milai_note_update` | `memory_id`、`expected_version`、`content`；可选元数据变更 | CAS 追加新版本；冲突不盲目合并 |
| `milai_note_delete` | `memory_id`、`expected_version`、明确删除意图 | 逻辑删除回执、直接读/检索阻断、物理清理状态入口 |

输入示意：

```json
{
  "content": "用户希望日常优先恢复精简 State，需要细节时再回查来源。"
}
```

这个示意描述内容输入体验，不承诺裸 MCP 在没有幂等标识时仍具备跨断线 exactly-once 语义。
第 4.5 节规定不同客户端的操作标识责任。具体长度、分页上限和可选格式由 U0 对照现有边界冻结；
不能先发布任意类型，再靠 Agent 从通用失败中猜约束。

来源缺省时记录为当前 Host 提交；`recorded_at` 为实际接收/记录时间，历史 `observed_at` 可以未知。
不得编造用户原话、历史时刻或文件版本。文本原样保存 Unicode、空白、换行和代码，不默认改写、总结。
初版可先支持 text/Markdown；JSON 等自由正文按声明格式保存，不要求某套任务字段。

来源引用只对声明的依赖提供机械保护，不能声称系统已经发现未声明来源。
已知 Evidence 使用精确身份；文件来源使用版本或内容哈希及 locator；仅路径不得冒充稳定版本。
Note 内声明的来源关系是 Host 声明，不是 Runtime 证明语义成立。

### 4.4 默认返回与分层读取

写回默认只返回身份、提交版本/摘要、必要状态及读取入口，不附完整审计轨迹或重复全文。
search/list 返回可直接判断的片段；get 返回原文或明确的有界分页。长正文不得静默丢失，片段不能冒充全文。
每条结果必须包含对象类型、稳定 ID、当前结果对应版本、来源入口及可展开引用。
search/list 后可按返回版本精确展开；不指定版本的 get 读取当时最新可见版本，期间有更新不算身份失配。
任何历史版本读取仍受当前权限、撤权与删除规则约束，不能以版本固定为由跳过资格检查。

拟议成功回执的关键字段如下；字段名最终以 U0 合同为准，以下不是现有接口输出：

```json
{
  "object_type": "HOST_NOTE",
  "authority": "HOST_WORKING",
  "memory_id": "opaque-id",
  "version": 1,
  "content_digest": "sha256:...",
  "operation_id": "stable-operation-id",
  "commit_status": "COMMITTED",
  "durable": true,
  "direct_read_available": true,
  "search_index_status": "PENDING",
  "read_tool": "milai_note_get",
  "read_arguments": {"memory_id": "opaque-id", "version": 1}
}
```

版本是本次提交版本，不是永久不变的当前 head。内容摘要可核对字节，不证明语义正确。
持久化、当前直接读资格、索引是否覆盖该版本分别判断；读后写依赖不能被异步索引滞后悄悄降级。
必要正文与提交信息真正持久化后才报告 `durable=true`；进程内排队不能冒充提交成功。

### 4.5 幂等、冲突与结果未知

- SDK/受支持 Host 在第一次发送前生成并保存 operation_id，重试、断线和进程续做复用该标识。
  自主调用裸 MCP 的客户端若不具备稳定注入能力，公开写入 schema 必须要求 operation_id。
- 不用随机服务器新 ID、JSON-RPC request ID 或内容哈希冒充跨请求业务幂等；相同内容的新保存可以是新意图。
- 同作用域、同操作 ID、同载荷返回原提交；同 ID 不同载荷返回 `OPERATION_CONFLICT`。
  重放回执仍需重新检查当前披露资格，不泄露已删除或已撤权正文。
- update/delete 校验精确 expected_version；冲突返回可安全披露的版本信息，由 Host 决定重新读取和合并。
  不自动改 expected_version，不自动覆盖另一 Agent 的提交。
- 超时、断线或取消后可能为 `UNKNOWN`。使用原 operation_id 的持久回执查询或幂等重放核对，
  不根据“当前 head 已变化”认定原请求失败，也不换 ID 盲重试。回执查询入口须在 U0 定义。
- 不强制普通非治理保存逐次用户确认；在用户启用的记忆策略内执行。删除及正式治理仍要求当前明确意图。

### 4.6 删除与来源撤权

初版普通 delete 明确作用于单个 Note lineage 的逻辑可见性：旧版本、默认 list/search、按版本读和旧提交
回执都不得再次披露被删除正文。历史审计和版本身份可依法定保留策略保留；不谎称已经物理擦除。
不得利用旧 update 重放复活 Note；需要恢复功能时另立显式合同，首版不自动恢复。

delete 不撤销共享 Evidence，不修改依赖该 Evidence 的其他 Note，不删除 Canonical/Proposal，
也不等价于 namespace cleanup。物理清理复用可靠任务及状态机制，分别报告主存储、派生副本、备份到期；
尚未实现或不适用的步骤明确报告，不能写成 COMPLETED。若首版只有逻辑删除，就明确产品限制。

对于声明了 Evidence 依赖的 Note，沿用 [ADR-041](../adr/ADR-041-working-state-disclosure-on-stale-references.md)
的保守披露原则：当前来源不可读时阻断整条不透明正文及片段，不仅返回警告。
同时覆盖 get/history/search/list/receipt/cache；不推断其内容为假，不宣称能从旧模型 Context 中擦除已呈现信息。

### 4.7 错误与精确读取诊断

可机器表达的类型、长度、正则、枚举、时间格式和条件分支进入 schema；额外交叉约束保留服务端校验。
CREATE 的 `subject_id/predicate/claim_type/payload/authority/confidence` 等必要字段须在对应输入分支明确，
不能把非 CREATE 的 target/expected_version 规则混入 CREATE。`payload` 不固定业务结构。

字段错误至少包含稳定 code、字段 path、约束类型和安全的 expected 描述。例如：

```json
{
  "code": "INVALID_ARGUMENT",
  "fields": [{"path": "source_type", "expected": "uppercase identifier; length 1..64"}],
  "retryable": false
}
```

优先透传 Runtime/SDK 已有的 path/type/details；不重复构建内部校验系统。
不得回显 token、完整输入、数据库参数或其他用户对象信息；业务错误保持 MCP `isError` 语义。

精确读取必须区分对象命中、Canonical eligibility、EXACT_STATE 绑定与任务语义充分性。
有资格的精确命中应正确完成对应绑定；未运行的语义判定明确标识未评估，不伪造 COMPLETE。
缺失、撤销、跨范围或时态不适用时保留真实失败，不能仅在 MCP 外壳改状态掩盖 Runtime 问题。

## 5. 开发增量与阶段门

只按本阶段相关的最小闭环实施；工程失败先定位、修复一般原因，再扩展验证。
计划顺序：`U0 → U1 → U2 → U3a → U3b → U4 → U5（单独授权后）`。
各增量通过后均应有可安装、可说明的交付，不等全部 CRUD 完成才修复已知接口错误。

### U0：冻结对象、兼容和存储选择（零模型）

- 保存当前代码/包 pin、实际工具目录与有效 scope 配置摘要；不得采集 token。
- 把 F01–F07 转成可执行的回归条目；原始报告材料未取得时明确 `REPORT_ONLY`，不阻塞独立合成复现。
- 对第 4.2 节存储条件给出结论；完成 Note 身份、版本、删除、来源依赖和权限 ADR。
- 冻结 `milai_note_*`、Evidence 精确读取、回执查询的输入/输出、状态和目录版本。
  明确新工具 scope 映射；没有映射的能力不注册、不允许调用。
- 明确本地隔离 PG/合成身份/临时文件边界与清理目标；不使用历史合成对象或公网私人数据作为可销毁夹具。

通过门：一个短 ADR + 一份可执行契约清单足够，不能以文档完备为由启动架构扩张。
若需数据库迁移，在这里确定最小方案，不能实施到一半再将单 State 假装成完整 CRUD。

### U1：修复 Schema、示例、错误与矛盾诊断（零模型）

- 复用领域约束生成公开输入模型；覆盖 source_type、source_context、时区时间、CREATE 与非 CREATE 分支。
- 修复全部相邻内置示例及文档；合法占位值替换后，经过真实工具参数解析与 Runtime 校验。
- 建立 Runtime → SDK → MCP 错误传递回归，验证客户端确实看到字段 path/expected，且不泄漏输入。
- 复现两种精确地址的 HIT/UNSATISFIED 矛盾，修复正确的绑定或诊断路径，并覆盖不存在与撤销情况。
- 说明 review 的 policy_version/reason_code 当前是审核记录标签，不是自动执行策略。

通过门：修复前夹具能稳定显示问题，修复后合法示例成功、非法输入准确拒绝；
旧工具行为兼容，真实结果与诊断不矛盾。不能只让字符串断言变绿而跳过真实绑定与 gate。

### U2：补齐 Evidence 的精确读取与类型引用（零模型）

- 复用 Runtime 已有 Evidence GET 能力。现有 SDK `get_evidence_metadata` 会移除 content，
  不静默改变该方法的用途；增加明确全文/有界内容读取方法及 MCP 入口。
- 验证私有项目、主体、保留期和撤权检查在正文披露之前执行；不能仅因租户内 ID 存在就返回内容。
- capture 与搜索返回类型化引用，明确 Evidence/Claim/State 的读取工具；混用 ID 给出安全错误。
- 提供授权范围内的有界 Evidence 浏览入口或明确的类型过滤分页入口，不通过空查询冒充 list，
  不以全局列表后过滤代替作用域内查询。Note 的普通 list 在 U3a 完成。
- 仅在所需新工具目录中开放新增读取能力；旧 memory_get 继续保持 Canonical 语义。

通过门：新建合成 Evidence → 返回引用 → 新客户端读回同一内容；搜索结果引用也可展开；
跨用户、撤销、不可读来源无正文泄漏。此阶段不自动生成 Proposal/Claim，不称为普通 CRUD 已完成。

### U3a：普通记忆保存、读取、浏览与搜索（零模型）

- 按 U0 存储决策实现最薄 Note 垂直路径：domain → repository/service → API → SDK → MCP。
- 同一空间可独立保存至少两条 Note；复用身份和版本机制，且不影响现有 Working State。
- add/get/list/search 共享同一对象身份与正文；默认使用精确读、范围词面检索，不启动 embedding 或提取模型。
- list 使用有界、稳定排序与游标；cursor 绑定授权域、过滤条件和必要快照/版本，权限变化后重新校验。
- 若使用派生索引，可靠记录输入版本与就绪状态；旧版本任务晚到不覆盖新版本。
  未建异步索引时如实报告实际直查路径，不为示例回执虚构后台队列。

通过门：内容输入后立即精确读取；list 能浏览、search 能命中并 get 同一版本；
来源缺省诚实、正文保真、所有资格过滤先于结果限额，Canonical 变化数为 0。

### U3b：版本修改、单对象删除与提交核对（零模型）

- 实现 update CAS、稳定 operation_id、提交未知核对和安全的历史版本读取。
- 实现单 Note 逻辑删除及精确状态说明；包含 delete/update 竞争、重复删除、旧写入重放和旧索引结果过滤。
- 覆盖新增写入指向已撤销来源的拒绝，以及既有来源后撤销对正文/片段/历史回执的披露阻断。
- 如确需物理清理，使用现有可靠持久机制或经 ADR 批准的最小扩展；不把后台内存任务当成已可靠交接。
- 在契约、工具说明和用户文档中一致说明逻辑删除、物理清理、备份到期及保留限制。

通过门：同版本并发修改最多一个成功；操作重放不增版本；UNKNOWN 不被当作失败重写；
删除后相关读取路径不泄漏，也不连带删除共享 Evidence/Canonical。不可实现的清理阶段不虚报完成。

### U4：真实工程闭环、并发与交付检查（零模型）

- 使用隔离真实 PG 和 HTTP MCP，至少两个签名测试主体、两个独立客户端进程，覆盖第 6 节。
  签名测试身份不能被写成再次完成了真实 OAuth 浏览器登录。
- 保存后终止原客户端，清空其会话/响应缓存，由新客户端按公开接口恢复；服务重启后再核对持久回执。
- 检查并发独立读取、同 Note 写冲突、不同 Note 写入，以及读写混合下的作用域隔离和有界等待。
- 先运行相邻测试，再执行变更包静态、类型、构建和适用的真实 PG 门；不启动无关模型或全量实验。
- 提供可安装包、兼容表和日常/高级目录使用说明；对旧目录、旧 API、Working State 做回归。

性能记录完整响应 P50/P95/P99、错误/超时、请求量、并发、连接等待、索引滞后和数据规模。
小样本尾延迟仅作诊断；失败请求不得静默从统计中消失。无关导入不应占用唯一读取队列。
不重新引入已被用户取消的 300ms 阻塞门；历史约 532.5ms 的特定配置接受也不是新路径容量保证。
发现全局串行锁、无界等待、跨用户干扰或明显回归时修复；不先上 10 万/100 万数据或大规模压测。

通过门：接口、数据完整性、授权、重启和局部并发正确；未运行的负载明确保留。
到此最多标 `ENGINEERING_COMPLETE_AGENT_VALIDATION_PENDING`，不能授予实际 Agent 使用或全 Goal PASS。

### U5：真实客户端使用切片与最终交付（当前不授权运行模型）

- 首先只读审计现有 G、R_host 的产物、首次实际输入和动作记录；符合新合同的证据可复用，缺口如实记录。
- 模型执行须待用户明确恢复并登记新批次。优先一个正常 coding G/R 链；若原 G 的身份、材料、权限、
  记忆版本均可合法复用，则只运行一个 R。协议/接口不兼容不能靠隐藏转换把旧数据冒充新 Note。
- 使用本地 vLLM 和真实客户端/HTTP MCP，保留普通文件与搜索能力；不能用固定答复模拟模型效果。
- `AGENT_TOOL_SELECTION` 与 `HOST_LIFECYCLE_PREFETCH` 分别标记。后者可以证明产品生命周期恢复，
  不可冒充前者的自主调用；模拟 Host 另列，不能替代原生客户端验收。
- G 只见当前正常任务，保存真正产生的约束/决策；R 是新进程、新线程、无 G 对话与答案缓存。
  处理组专有日志、检查器和预期答案不得通过共享文件、默认索引或自动摘要泄漏。
- 首次相关动作之前，所需内容必须进入实际模型输入；只命中 ID 或把工具结果截掉不能算恢复。
- 若证据已呈现而动作仍错，归因到理解/使用，不扩大检索；若没有调用/预取，不靠反复改提示制造通过。
- U4 包交付可先完成；真实公网新版本部署、写入、审核/清理和登录复测均不由此自动授权。

通过门：明确一种受支持接入方式，真实保存/冷恢复/首次相关行为闭环通过；所有运行与失败计入。
单链结论只能是该使用切片可用，不是自动维护、长期净收益或泛化成立。

## 7. 成本、暂停与停止规则

### 7.1 当前额度为零

本 Goal 文档没有授权任何新增模型生成、付费调用、公网记忆写入或部署。
前序 v0.2-06 的 784000 raw 等字段属于暂停前历史，不是可重新领取的余额。
本地 vLLM 同样有 GPU、token 和时间成本；无主 Agent 生成也不代表 embedding、rerank、提取服务免费。

U0–U4 以固定夹具和非模型工程测试推进，不启动 vLLM 生成，不调用外部 embedding/托管服务。
隔离本地 PG 和服务的启动、测试数据写入仅在后续明确实施指令范围内进行；本次生成文档不执行这些动作。

### 7.2 模型恢复后的单批合同（待授权，不预支额度）

不在本文件预置新的大额 token 上限，也不把过小且不足完成任务的试跑额度当作可用性验收。
获得恢复指令后，先用已有真实账本与请求长度估计，登记并获得明确上界后再发第一条生成请求：

| 必须登记 | 要求 |
| --- | --- |
| 唯一批次与输入 | 固定目录、任务、材料/实现摘要、主体/范围、记忆版本、接入方式 |
| 会话与请求 | 首批优先复用 G 只做 R；不能复用时最多计划一个 G/R 链，不并行铺多个条件 |
| 硬上界 | 会话数、请求数、累计 raw、单请求上下文/输出、墙钟、并发及零付费限制 |
| 失败处理 | 无隐式 retry、换模型、换目录重跑、重置账本或自动追加提示条件 |
| 停止与收尾 | 达限/拒绝/取消先结算在途请求；记录 UNKNOWN，不留下未结算并发 |

同一实验任务模型请求并发限制不限制 MCP 服务的多用户读取；两类资源分别记录。
预算不足时报告具体还差哪项，不边跑边自动翻倍；后续若获追加额度，原失败与累计花费仍保留。

### 7.3 成本口径与立即停止条件

分别记录摄取、首次写入、提交核对、恢复、回查、任务和维护的 token/延迟/调用数；
Provider usage、缓存命中与原始输入长度分开，不把 raw token 直接写成实际货币收费。
开发诊断、离线评审和协议适配成本另列，不能作为免费在线能力。

出现越权披露、错误 Canonical 提升、不可追踪的提交、数据损坏或共享服务影响时立即停止相关执行，
保留证据并修复；需要新的身份权限、迁移批准、公网变更或模型额度时报告并等待，不自行扩权。
读写契约未过门不启动 U5；低成本简单方案足够时不扩展语义机制。
