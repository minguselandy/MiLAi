# MiLAi：产品闭环开发、端到端实验与简洁创新规划

## 0. 执行结论与依据

下一轮应以**当前 A0 默认策略下，真实用户能够并发使用、可靠保存、退出后恢复并正确续做**为产品主目标。继续保留 D0–D5、公开接口、Host/Runtime 分工和独立归因；不重新建设 Memory 平台，不默认增加回查、Hint、图数据库、隐藏 Reader 或在线 Reviewer。

建议将任务拆成并行的产品基础服务收尾、受支持 Host 的真实闭环，以及一个延后验证的小机制研究。研究优化没有胜出不妨碍可靠基础能力交付；基础服务通过也不等于 Agent 续做正确。

## 1. 产品交付范围：基础服务与端到端能力同时推进

### 1.1 首版面向用户的产品承诺

限定一个已选定、能够实际观测输入的受支持 Host 和客户端组合：用户完成普通任务，Agent 产生正常产物；在有延续价值时通过公开接口保存；用户退出；新进程通过可信身份和已选任务恢复；用户只需提出正常续做要求，Agent 在必要时查源，完成可核验的后续产物。

不能要求操作者在续做时补贴旧对话、手填 Evidence ID、手选标准答案片段，或在后台替 Agent 更正 State。正常用户选择项目或任务是合法交互；若任务绑定有歧义，应明确选择，而不是暗中猜测。

对于不能提供生命周期接入的第三方 MCP 客户端，只承诺已测试的工具可用性及显式保存/恢复路径。不能仅凭 MCP description 保证自动保存与自动恢复；HOST_MANAGED 与 AUTO 的结论继续分开。[S2]

### 1.2 三项结论，不合并为一个 PASS

| 结论 | 最低证据 | 可对外描述的范围 |
|---|---|---|
| 私有 Memory 基础服务可试用 | 认证、隔离、持久化、恢复、容量内混合负载及基本运维闭环 | 限定版本、客户端和容量的候选服务 |
| 受支持 Host 的端到端使用成立 | 真实 G、公开保存、新进程恢复、首次相关行为和最终产物满足必要条件 | 限定 Host、任务类型和成本的 HOST_MANAGED 闭环 |
| 新策略有增量价值 | 公平比较、全部分母、负迁移和生命周期成本 | 仅实际被测试的策略和范围 |

基础服务门通过后可开展限定试用；“可靠续做的 Agent 产品”必须同时通过第二项。第三项不是基础产品发布的先决条件。Schema 冻结继续独立，维持 NO-GO。

## 2. 最小产品设计：不增加第二套认知系统

### 2.1 保留当前默认 A0

A0 是完整现有默认，不是无记忆组，也不自动等同于 D4 的 A=FLAT_PREFETCH。执行前固定其真实工具、提示、装配、版本与可用文件。默认策略修改必须有明确变更记录，不能更新后继续用同一个 A0 标签掩盖条件变化。

当前允许推进的变化是身份/恢复接入、明确的错误反馈、已证明的导入优化、独立读取并发和可靠操作回执。这些工程修正应先成为公平比较的共同基础，再单独比较分层或研究策略。

### 2.2 一条正常工作路径

```text
可信登录与任务绑定
→ 按当前默认装配恢复合法记忆
→ Host 正常工作；独立读取可并发
→ 需要时定向读取来源
→ 正常产物形成；只有存在延续价值才保存
→ 原件及提交事实可靠确认
→ 新会话通过公开接口恢复
→ 正确完成第一次相关动作与后续产物
```

不强制逐层读 L1→L2→L3；不每轮保存；不默认追加总结或反思调用。L1/L2/L3 是访问角色，不是三套新数据库。[S1 §3；S2]

### 2.3 将“操作事实”和“Host 结论”分开呈现

复用现有回执与状态观察，给 Host 提供简短、含义稳定的机械信息：本操作是否有确认、关联版本、当前观察到的 head、观察时间、允许披露的索引/可读状态和可定位依据。

这些信息只能来自 Runtime/公开回执。记忆正文即使包含相同键名，也不能覆盖可信元数据。历史叙事不自动转为当前系统事实；缺少可核验回执时不能让适配器根据文义生成权威结论。

下面是逻辑投影示例，不是接口 schema：

```text
本操作：已确认提交版本 V8，依据为可关联回执。
当前观察：时间 t 读取到 head V9。
可得结论：该操作成功；之后 head 已推进。
不能据此判断：V9 的业务含义、旧笔记对当前任务是否适用。
```

对 UNKNOWN，不把推测填成成功或失败。对全文已存但索引未完成，区分“直接读取可用”和“搜索尚未追平”。这些只是机械合同，不意味着内容语义正确。

### 2.4 未决问题局部保留，不让整个 Agent 停住

Host 可在原有自由文本或 JSON 中保留与任务相关的未决事项、依据入口及适用条件，不要求固定业务键。当前动作不依赖该事项时，继续其他工作；依赖时利用正常工具补充查证。

Runtime 只做已有权限、版本、引用和提交检查，不新增一个判断“任务依赖关系”的隐藏模型。版本相同不能证明语义正确，版本变动也不能自动说明所有结论失效。授权不足的内容仍必须在披露前隐藏，不能以待核验 warning 代替权限控制。[S2]

### 2.5 并发与后台加工

读取、原件持久化和派生加工使用明确的资源预算。不同用户和任务不得被全局 State 锁串行化；同一 State 的竞争继续使用条件提交，不自动语义合并。并行读取只用于互不依赖的请求，保持每项结果与原始调用关联；一项失败不能静默吞掉其他结果或把整包标为完整。

保存成功必须对应可靠持久化。索引、embedding、自动提取等可延后，但应能查询完成状态并防止旧版本加工覆盖新版本。需要立即消费刚保存的内容时，优先复用现有直接读取/版本定位，不为一个交接等待全部搜索索引。

不因本规划引入 Kafka、新图数据库、缓存集群或第三方后端抽象平台。若现有能力已满足，只补测试和观测。外部系统的 CAS、读后写和分层能力可以借鉴，但不是 MiLAi 可独占的创新。[W1、W2、W3]

## 3. 开发工作包与顺序

责任角色是建议的职责，不假设团队人数，不要求设置新的在线 Agent。相邻角色可以由同一开发者承担，代码审查和运行推理成本分别记录。

| 工作包 | 优先级 | 主要责任 | 依赖 | 最小交付与出口 |
|---|---|---|---|---|
| P1 发布身份与认证收尾 | P0 | Runtime/认证接入 | 当前部署资料 | 源码—构建—部署—配置—测试关联；真人刷新/撤销/冷恢复；旧入口和续期责任清楚 |
| P2 保存长尾诊断与单项修正 | P0 | Runtime/存储 | 固定负载与当前部署身份 | 两次未完成导入有终态；慢请求关键路径可解释；不降低持久性和150ms原门槛 |
| P3 默认 Host 的保存—恢复产品化 | P0 | SDK/Host | P1 的身份合同；现有公开保存 | 一个受支持入口；正常任务产物保存；冷启动无需操作员注入历史；错误状态明确 |
| P4 操作事实的稳定呈现 | P0/P1，取决于实际缺陷 | MCP/Host | SIM12 离线归因与现有回执 | op/head/时间/资格不混淆；无权威信息补造；纯机械回归先通过 |
| P5 服务端并发保护与混合验收 | P0 | Runtime/Lab | P2 观测、P3 请求路径 | 容量内稳定；过载明确拒绝；普通用户不被热点导入无限拖延；所有请求保留终态 |
| P6 真实产品链与正式实验收口 | P0 | Host/Lab/评价 | 对应安全、预算和版本门 | A0 真实冷续做；D4/D5分别记账与归因；限定结论不跨越证据 |
| P7 小机制研究 | P2 | Lab/研究 | P6形成可用基础、P4有残余错误信号 | 一个单因素机制pilot；简单控制足够则停止复杂方案 |

P1、P2、SIM12 离线分析可以并行；P3 不必等待所有性能研究结束才开发。P6 的本地开发链只需其相关工程/安全门成立，公网交付则必须满足服务门。研究和 D5 留出不是修复产品缺陷的日常测试材料。

### 3.1 P1：认证与部署收尾的边界

核验真人客户端保存—退出—新进程恢复、同一用户多客户端映射、两个用户隔离、令牌刷新/撤销和 scope/受众。并发刷新需要确认同一授权连接不会出现自竞争和凭据回退；不要把所有查询串行化来规避问题。

7968 的监听范围先盘点真实依赖再收敛；不根据监听地址直接断言已存在绕过。证书续期、告警、失败回滚和备份/恢复应有可检查回执。生产测试使用专用账号/项目；故障注入和高负载先在隔离环境进行。

元数据严格预检、真实撤销能力和客户端兼容性分别给结论。本规划不重复改变 OAuth 协议，也不将既有历史“未部署”文案覆盖删除。

### 3.2 P2：先定位 fsync，再优化

为现有 trace 增加或核对这些阶段：准入等待、执行器/线程池等待、文件角色、write/fsync/目录同步、数据库连接/锁/提交、回执与响应、后台加工完成。

必须知道长尾发生在原件、必要回执、目录、审计还是非关键实验日志。进程中同步 I/O 是否占住事件循环也要检查。没有这些归属，不决定磁盘迁移、扩大队列或提高并发。

修正采用“一项假设—一个差异”：原实现隔离负载、原实现混合负载、单项修正后相同混合负载。预先固定请求大小、读写比、到达率、并发上限、数据规模、运行窗口和终态观察窗口。终态后续澄清仍保留原超时，不能事后改为按时成功。

### 3.3 P3：产品可用性不依赖评测助手

固定一个真实 Host/客户端组合，不先建设多 Host 平台。应能查看本次使用的记忆及其来源、看到明确保存状态，通过正常权限路径更正记录。管理操作不开放超过当前 scope 的能力。

采用正常产物入口和通用保存约定，不按任务 ID 路由。没有候选允许不保存；自然已保存允许 no-op。不为提高保存率额外生成摘要，不把用户对记忆的更正自动扩大成 Canonical 修改。

### 3.4 P4：SIM12 先做离线错误表

对每个可核验错误关联：首次相关动作/交付位置、该位置之前的实际模型输入、可见来源和版本、错误判断、正确或仍未知的边界、是否存在一般性修复。

“六项 span 最终出现过”与“首次动作之前已出现”分别检查。若问题来自历史方案理解，而不是实时操作回执，不能用当前 Runtime 数据或评测 gold 给模型补一个结论标签。

如果现有接口已经充分表达而 Host 仍误读，进入小机制比较；如果接口缺少可关联回执，先修工程，不能把新增事实带来的提升命名为纯表示收益。

## 4. 性能与并发验收设计

### 4.1 请求类别与测量边界

| 类别 | 必测指标 | 备注 |
|---|---|---|
| L1/已知 ID GET | P50/P95/P99、成功与超时、版本/租户正确性 | 现有700次读取不自动覆盖其他接口 |
| 搜索与多引用读取 | 完整响应延迟、结果完整/部分状态、关键内容可用、输出字节与索引新鲜度 | 包括实际embedding/rerank等依赖，没有调用则不虚构 |
| State提交 | 可靠确认延迟、冲突、UNKNOWN、重放结果 | 不能将入队响应当提交完成 |
| Evidence导入 | 接纳、原件持久化、加工完成三个时间点，积压条数与字节量 | 大小分组，不能只报混合均值 |
| 真实Agent任务 | 首次相关动作、最终必要条件、端到端时间与总成本 | 不用GET延迟代替任务使用速度 |

读写性能目标使用现有有效合同；新接口没有冻结目标时保持待定，并在执行前确定。本文不把历史建议的50ms或30秒自动视为当前已接受门槛。U1中的150ms保存门槛继续保留，明确接口和大小范围后再比较。

### 4.2 首轮混合工作负载

| 负载/事件 | 要验证的问题 | 失败处理 |
|---|---|---|
| 两个真实授权域并发读取 | 服务端隔离、共享连接资源、结果对应 | 串用户立即阻断上线，不用平均成功率抵消 |
| 一个热点用户导入，普通用户读取/搜索 | 读取保护、每用户公平、导入准入 | 超出容量有界拒绝；正常用户不无限排队 |
| 同一用户两个Agent写同一State | CAS冲突与显式恢复 | 一次胜出、另一明确冲突；不盲目合并或覆盖 |
| 保存后立即冷读取与检索 | 直接可见性与索引滞后的区别 | 明确状态，不将搜索缺失解释为未保存 |
| 异步任务乱序完成/重启 | 派生索引版本、可靠任务恢复 | 旧任务不得覆盖新版本；无重复有效写入 |
| 撤权与缓存/派生读取 | 披露边界一致 | 所有服务端披露入口都执行资格检查 |

同时使用固定并发和固定到达率两种负载：前者观察资源规模，后者观察排队与过载。已有数据规模为起点，再加入一档声明的增长负载，不默认开百万级数据导入。服务端配额按请求数及必要的字节/任务成本限制，不能只靠客户端Semaphore。[W7]

### 4.3 不能排除失败的指标

建议增加“按时可靠完成比例”：在约定时限内获得可靠完成确认的合格请求数，除以全部合格请求数。容量内正常请求和故意超额请求分层报告；主动拒绝可证明过载保护，但不算正常服务成功。[W8]

延迟百分位同时说明分母，超时、失败和UNKNOWN单列，并保留从计划到达时间开始计算的端到端等待。48/50的缺失不能从摘要中消失，也不能未核验就判数据丢失。

## 5. 实验规划：先完成使用，再比较方法

### 5.1 将工程回归、产品试用与研究分开

| 实验层 | 现在要回答的问题 | 条件与单位 | 主要输出 |
|---|---|---|---|
| 离线诊断 | SIM12 的错误发生在哪里，必要证据是否及时可见 | 现有轨迹，不发新推理请求 | 错误—输入—证据—可知边界对照表 |
| 服务工程验收 | 并发、保存、恢复、认证是否可靠 | 真HTTP/PG和专用身份，模拟模型可用 | 回执、完整终态、容量与延迟 |
| A0产品闭环 | 当前默认是否能完成正常任务后的冷续做 | 真实Host、正常任务、新进程 | 正常产物、首次动作、完整成本 |
| D4/D5 | 分层及指定表示/家族范围是否成立 | 当前正式合同和独立授权 | 装配增量、限定迁移与成本 |
| 机制研究 | 小型交接改进是否独立减少已呈现证据后的错误 | 同起点、同来源、明确单变量 | 条件能力、负迁移、简洁性收益 |
| 后续持久价值 | 当前改正跨会话是否持续有效 | 更新前/后持久State独立分支 | 复发、重建成本、累计收益 |

只有第一、二层不需要新增 Agent 推理。外部索引/embedding有计费依赖时仍另列费用门。本计划不授权任何新请求。

### 5.2 最近一次模型额度申请：优先一条 A0 产品链

**建议的最小独立产品验收是 G + R 两会话。** G 完成正常前序任务并自然形成可复用内容；R 在新进程中通过当前默认 A0 续做。它不是 D4 的删臂版本，不计算 A/B 增量，不报告泛化。

若核对当前正式 D4 后，发现其中一臂与产品默认的实际配置完全一致，可直接以该臂提供相应产品链证据，避免重复 G/R；必须核验配置等价，不能假设 A0=A。

执行前冻结：Host/模型/工具与安装身份、正常来源与工作区、任务绑定、起止计时、每会话和批次费用上界、输入与输出控制、不可见评价资料、必要条件及失败终态。

建议首个任务选择与当前主要用户工作贴近的开发/工具任务，并有真实可执行产物检验。例：G 完成一个小型实现/配置修改并保留尚未完成的检查；R 在新进程继续修改和验证，须遵守前序约束。具体内容不得从未来评分答案反向生成。

最小通过条件：

1. 保存与冷恢复确由公开接口和同一合法身份/任务绑定完成，G临时上下文不继承。
2. 用户没有重新贴历史，操作者没有注入答案、来源ID或修复State。
3. 首次相关实质动作及最终产物满足预先列明的必要条件。
4. 必要来源在相关动作前实际呈现；没有凭撤权或未知状态补造结论。
5. 全部请求、恢复、保存、工具和失败成本计入冻结口径。

没有合格记忆产物时保留“无比较/保存机会”；任务成功不自动补成保存链成功。保存UNKNOWN不使用不确定H*伪造已确认冷恢复。

一次两会话成功仅支持这条链。后续扩大使用优先复用独立的D4/D5合格证据，而不是为每一份报告反复运行相同案例。

### 5.3 正式 D4/D5 不被研究干预污染

S1 中 D4 为同一 H* 上 G/A/B，A=FLAT_PREFETCH、B=STATE_FIRST；只改变装配。D5 为四条独立链及表示、结构变体。U1 报告了更新的编译产物，但没有提供 v0.26 完整配置；执行必须读取当前合同，而不是直接运行旧附件。[S1 D4/D5、§9]

一般性P1–P5修正应在比较前冻结并同时适用于两臂；不让B额外获得回查提示、规范化事实或更强工具。需要同时改变机制时另列系统级比较，不能继续声称是纯装配比较。

A0产品链成立而B仍失败/更贵：继续交付A0，不默认采用B；正式D4/D5依合同保留未通过的结论，不借用产品通过覆盖。

D5保留未参与调参的家族与任务。旧SIM和已查看答案的材料属于开发；D5修改后重新跑的旧例也不能重新标为留出。每条变体从同一G起点公开保存、独立冷恢复；只是输入包装差异被适配器消除时，只证明适配保真，不声称模型位置鲁棒性。

L1是否足够要在A/B前按真实初始输入核验，不能按预设任务标签自动归类。若G已把所有关键条件放进L1，就不把该链算成“必须展开”；不删改L1制造机会。

### 5.4 首次相关行为与评价边界

软件/工具任务优先使用实际工具参数、产物、测试结果或明确环境状态。研究/写作任务采用来源可核验的必要条件及有锚点的人工核验，无法稳定评价的整体风格或论证质量注明不评价，不用关键词命中假装全面正确。

不记录私有思维链。内部“理解正确”在没有可观察输出时不打分。草稿与交付的边界在运行前明确，失败后不能改称草稿。

UNKNOWN样例必须区分：真实底层结果是什么，与当前Agent凭已呈现证据能知道什么。裁判知道后台提交成功，不意味着未收到确认的Agent应该断言成功；巧合说中实际状态仍可能是无依据断言。

### 5.5 预算安排

| 工作 | 本提案建议的首批申请量 | 解释 |
|---|---:|---|
| 现有轨迹诊断、非模型服务回归 | 0次新Agent推理 | 仍记录计算、存储和可能的外部依赖费用 |
| A0产品G/R | 最多2会话 | 独立产品链；有等价D4路径时避免重复 |
| 正式D4 | 当前有效配置为准；旧附件为3会话 | 不自动继承旧额度，不变更为G/F/S |
| 正式D5 | 当前有效配置和各阶段门为准 | 旧附件的20会话仅是历史设计规模 |
| 小机制pilot | 产品基础成立后另行申请，见§7 | 不并入D4/D5，不自动追加Judge或备用模型 |

一次会话可包含多次真实请求，不等于一次发送。既有预算预约、未知usage保留、无隐式重试和无自动换模型继续沿用当前有效合同。不同用户/任务可并发；实验的单任务推理在途限制不能当作服务全局串行化要求。

## 6. 创新方向核对：将贡献缩小到真实残余问题

### 6.1 已有工作与最直接边界

| 近邻 | 已公开覆盖的机制 | MiLAi应避免的宽泛主张 | 可借鉴/对照 |
|---|---|---|---|
| Pydantic AI Harness Memory [W1] | CAS、幂等、持久回执及不同存储实现 | 首次事务化Agent记忆 | 工程合同及无额外模型的简单存储基线 |
| Lore [W2] | 作者公开描述seq/min_seq、covered_seq和原始尾部回退，实现交接可见性 | 首次读后写/可见性凭据 | 交接一致性参考；文档不是独立性能证明 |
| TierMem [W3] | 摘要/原文分层、ANSWER/ESCALATE、来源回退与合并 | 首次分层按需回查或成本敏感路由 | 只有研究路由时才适配，无需现在训练router |
| StateMem / StateMemWrapper [W4] | supersession、依赖重核、答案时状态结构与匹配控制 | 首次状态跟踪、局部失效或格式化状态 | 同证据条件下的状态理解对照 |
| StateAuditor [W5] | 状态到草稿反向审计、来源及时间校验、修复 | 首次区分来源验证与语义正确 | 审计对照，但额外调用和成本必须单列 |
| MemoRepair [W6] | 先撤下受影响派生链，再修复并按依赖重新发布 | 首次来源撤销后的级联维护 | 其完整影响来源假设需匹配，不能伪造同条件比较 |
| MemoryArena [W9] | 相互依赖的多会话记忆—行动任务 | 首次端到端Agent记忆评测 | 后续小规模外部迁移，而非现在全量跑榜 |

这些论文与官方资料说明近邻强，但不直接决定MiLAi没有研究空间。本次是面向最近邻的核对，不是穷尽所有文献的新颖性审定。

### 6.2 首选候选：观察边界保真的交接

**研究问题：当必要来源已经及时呈现，能否仅用现有操作回执、版本和观察边界的清晰投影，在不追加模型调用、不要求完整语义依赖图的条件下，减少跨会话首次行动中的无依据状态推断？**

它直接对应U1中的提交状态与持久化边界错误。创新假设不是“把JSON排整齐”，而是保留两个被自然语言摘要容易混淆的边界：

- 本操作的结果，与随后观察到的当前State；
- 系统实际发生的事，与当前主体从可用证据能够确认的事。

例如：回执较晚到达不意味着操作较晚发生；只比较同一作用域的版本，不把不同任务的V8/V9全局排序；看到head不自动确认某个先前operation；原件保存与索引可检索不是同一个状态。

最小实现是现有适配层的一个确定性呈现函数，输入为合法恢复内容与既有公开回执，输出为来源清楚的操作观察与未改写的记忆正文。不增加新的推理Agent、每轮审计调用、数据库实体、向量时钟协议或通用证明系统。

其保证只到机械归属、版本关系和披露边界；Host仍负责判断正文语义与任务关系。若来源是任意叙事而非可机械解释的回执，不能自动发放“已证实”的标签。

**新颖性尚未成立。** 简单合同说明若已足够，就采用该说明；效果若仅是工具文档修复，按工程改进交付。只有独立任务中明确改善首次行为、保持合理执行而非一律保守、并在冷恢复后持续有效，才升级为机制贡献候选。

### 6.3 第二候选：保留未决边界的选择性持久修正

只有首选机制在当前会话有效且出现跨会话复发时再研究。对同一旧State、同一实际证据、同一Host，比较普通简短更新与保持来源/范围/未决事项的局部修正。

不把“局部patch”本身主张为新算法；需要证明少修无关内容是否降低负迁移，并且收益覆盖写入和后续读取成本。Markdown/JSON继续合法，依赖字段按需而非强制。

语义纠正由Host正常工作产生，不追加另一个模型来写“更优记忆”。单次写回有益与自然自动维护净收益分别报告。[S2；S3]

### 6.4 可能形成的实验贡献

可以将真实故障轨迹抽象为一个小型、可执行、非私有的数据集：保存响应丢失、head推进、部分提交、索引滞后、无变化和应保留UNKNOWN。每例有真实服务操作、授权可见材料、首次行为边界与两套评价：底层执行事实、对当前证据而言可成立的判断。

改变响应到达顺序只有在因果关系和观察语义等价时才是等价扰动；改变真实事件顺序或撤销时点属于新条件，不能标成格式鲁棒性。无证据时应保持UNKNOWN，证据充分时应正常推进，防止全程拒答获得虚假高分。

在研究证据不足时，这套材料仍然有工程回归价值，不需要为了论文扩大成新平台。

## 7. 机制实验：一个小问题，三个简单对照

### 7.1 先区分修缺陷与做研究

如果操作事实呈现直接阻断目标产品链，必要的小额模型复现可作为开发工作先行；它不是独立确认，也不需要等待所有产品任务都通过。研究性扩样、外部benchmark和持久收益比较则排在产品基础之后。

优先修现有可定位的一般性问题，不承诺一定要产生算法论文。每个候选需说明删除它会恢复哪种真实失败；没有可观察行为收益，保留更简单方案。

### 7.2 三臂设计

| 臂 | 相同部分 | 唯一声明的变化 | 回答什么 |
|---|---|---|---|
| R0 原呈现 | 同一恢复起点、原始证据、工具、模型、上界 | 无 | 当前接口/Host参考 |
| R1 简单说明 | 同R0，合法来源不增减 | 最短的通用合同说明或同事实的自然语言说明 | 普通文档清晰化是否已足够 |
| R2 作用域化呈现 | 与R1相同的明确事实和定义 | 按操作、当前观察和来源边界组织，不混入业务结论 | 组织边界是否提供额外收益 |

R0到R1若包含机械预计算的新显式结论，标为“合同语义显式化”的复合干预，不声称纯格式收益。R1到R2才在事实与定义相同时检验组织收益。若必须引入额外检索、全局历史或评测标签，退出这一比较，另立信息可用性实验。

控制完整合法来源、任务、模型设置、提示位置、预算上界、可用工具和运行版本。记录实际输入长度，不为凑token等长加入无关填充。R2必须披露增加的token、时延和Host输出变化；没有额外调用不等于零成本。

### 7.3 第一批机制pilot的建议规模

作为另行申请的计划，可用4个独立历史上下文，每个3种呈现，共最多12次受控响应。它是单步/固定检查点的条件能力诊断，不是12条自然端到端任务，也不构成正式泛化统计。

建议覆盖：已确认操作且head推进；操作回执缺失应保留UNKNOWN；跨资源部分提交；没有需要修正的正常记录。尽可能复用实际观察到的自然错误；补充合成案例时明确标记controlled，不冒充自然发生。

不要先跑12次再无条件加seed、更多模型或Judge。此pilot只决定是否值得进入新的、另行冻结的确认设计。正文表达与运行逻辑不能包含案例编号分支。

### 7.4 指标与停止条件

主指标为首次相关行为是否在可见证据边界内正确。辅助记录无依据的成功/失败断言、错误归属、该执行而未执行、误改正确记忆、最终任务结果、token与时延。

- R1与R2都修复、R2无额外收益：采用更简单的R1，停止R2扩张。
- R2只在SIM12或单一模板上有效：保留开发修复，不作迁移主张。
- R2以更多拒答换取少犯错：检查实际任务完成，不能算产品成功。
- 证据已及时呈现，错误属于独立业务推理：回到Host任务推理，不扩检索。
- R2减少主要错误但破坏正确记忆或显著增加成本：不默认启用。
- 在独立任务和负控上均有收益：再适配最直接的StateMemWrapper等强基线，并分别报告调用、输入和预处理成本。

### 7.5 后续持久实验独立进行

当发生正确的当前修复且存在延续价值时，使用同一实际起点，分别从更新前H和更新后H′冷启动。两组拥有相同正常文件、合法历史、工具、模型和预算；不能通过删去原始笔记或checkpoint削弱H组。

它测一次持久更新的条件性价值，不是A/B分层比较，也不是自然自动维护总体收益。不要只给出成功修复子集，至少报告合格任务、修复发生、保存确认、可冷恢复、后续可评价各层分母。

若普通文件已经使两组一样容易完成，应保留这个负结果，它说明该次持久State更新的额外收益有限。多会话累计收益只按实际发生的后续使用计算，不把设想的未来复用次数当收益。

## 8. 核心指标、成本和结论

### 8.1 最小指标面板

| 维度 | 主指标 | 必须同时报告 |
|---|---|---|
| 服务 | 容量内按时可靠完成比例 | 请求类型、P95/P99、拒绝/超时/UNKNOWN、容量条件 |
| 端到端 | 冷恢复后首次相关动作及最终必要条件 | 实际完成链数、无机会、失败、未判定 |
| 记忆安全 | 无依据断言与连带损坏 | 正确执行率，避免全程拒答 |
| 跨会话 | 同一错误复发与复用成功 | 持久更新确认、后续会话数、负迁移 |
| 成本 | 正常链总费用/token/时间 | G与维护、重复输入、工具、索引、失败、未知费用 |

不通过工具调用数量或State版本增长评价记忆有效性；不用平均正确率抵消隐私越权或已确认数据丢失。

### 8.2 完整成本

正常链成本按实际组成记录：G任务与必要记忆形成、写入、每次冷恢复、来源读取、Host推理及必要维护。token、金额、时延、存储和本地计算分别表示，不混成一个无法解释的分数。

实验总账只计实际运行一次的共享G，加各臂和变体、失败、准备、导入、清理及未决费用。产品链口径中G不能因为共享而免费，研究总账中G也不能重复计费。[S1 §9.6]

辅助可报告：全部合格运行成本总和/正确完成任务数，包含失败成本；没有成功任务时该指标不可计算，不填零。对读多次才回本的方案，仅报告已观察复用次数与差值，以及条件化的盈亏平衡分析。

对于分层，分别给L1足够和实际需展开的链，避免用一类的低成本掩盖另一类反复检索。质量不等价时不只比较token比率。

### 8.3 状态与报告规则

沿用实际Goal的正式状态名，产品试用状态单列，不用新标签覆盖旧实验结论。保存/恢复、行为、分层增量、表示/家族迁移和成本逐项给结果。[S1 §5、§9.7]

D5的每个实例、变体不能当作独立任务家族；4链2家族只支持限定小样本证据。更正式的新颖性确认在pilot后独立设样本与可检测效应，不用小样本bootstrap制造确定性。

未运行、运行失败、合同不满足、关键观测缺失、合理不保存和任务失败分开。默认不追加Judge；必要人工核验只覆盖有来源锚点的评价，争议则保留NOT_EVALUABLE，不填PASS。

## 9. 最小改动与简洁性约束

默认读取/保存链新增模型调用目标为0。首先复用一个Host、现有Runtime/PG/MCP、现有公开回执和现有测试工具；同一个功能不在Lab私有实现与Product生产实现中维护两套语义。

新增代码优先只有：必要请求阶段观测、缺失的服务端准入控制、当前Host的生命周期接入，以及一个操作事实呈现函数。已有则补回归，不因提案重复实现。

不强制所有记忆使用业务schema，不每轮生成总结，不为一个UNKNOWN阻塞全部无关工作，不默认建依赖图，不同时接入多套Memory后端，不引入学习型路由。短期优化也不能通过删除来源、静默截断、减少授权校验或放宽持久化来实现。

协议和安全检查可以是确定性的硬约束；语义正确与适用性仍是Host工作，不能被一个“verified=true”总标记遮蔽。

## 10. 每个开发增量的验收卡

每项改动只需一张简短验收卡，附在现有PR/报告中，不创建审批平台：

```text
问题：来自哪个已观察失败或必要产品缺口？
假设：当前认为哪个一般原因造成？
改动：哪一层、哪一个行为变化？
共同条件：版本、身份、工作区、工具、预算如何固定？
回归：最小复现、正常负控、故障边界是什么？
观测：实际请求/回执/输入/产物/成本如何关联？
结果：通过、失败、未知分别是什么？
下一步：合并、回滚、继续诊断或停止复杂方案。
```

一般工程修复跑相邻测试；发布候选跑对应完整回归与真实PG边界测试。代码审查不是新增在线Reviewer，每个小步骤也不需要单独人工审批。生产风险操作、费用授权和研究冻结边界仍保持明确。

## 11. 建议的近期验收里程碑

### 里程碑一：候选服务可稳定试用

发布身份可核验；真人授权闭环与两用户隔离通过；旧入口和续期边界明确；混合写入原门槛及容量条件明确；失败有终态；备份恢复或数据导出能力有与产品承诺一致的证据。

### 里程碑二：默认Host真实冷续做

在一个受支持Host上，完成真实G、公开保存、退出、新进程恢复、首次相关动作与最终产物。用户不重复注入历史，操作者不修复状态。服务负载与Agent语义测试先分开定位，再做一条受控混合负载的联合产品链；联合测试新增模型会话仍单独授权。

### 里程碑三：限定范围迁移与小机制结论

依当前合同完成正式D4/D5或如实保留失败；默认A0不因分层假设自动替换。小机制另列同事实对照；只有在收益清楚且复杂度成本受控时合并，否则采用更简单的文档/呈现修复。

**终点是可用、可恢复、可持续续做的产品，不是必须得到某个特定Memory方法胜出的结论。**
