## 权限边界

- `milai_owner` 只用于 migration；在线进程不持有该 DSN；
- `milai_api` 只能执行 Evidence ingest 与 proposal 创建；
- `milai_steward` 只能执行 proposal review 与 Evidence revoke；
- `milai_worker` 只能读取 outbox/canonical 投影输入；
- `milai_audit` 只读，不进入在线写路径；
- 四个 Runtime login 均为 `NOSUPERUSER NOCREATEROLE NOCREATEDB NOINHERIT NOBYPASSRLS`；
- canonical、Context 和 deletion 表均启用并强制 RLS；
- transaction-scoped tenant/actor context 在 pool 归还时清除；
- API、Steward、Worker 与 Audit 对 ClaimHead、OpenIssue 和 EvidenceRecord 的直接写权限均为 false。

函数权限实测矩阵：

| Role | create proposal | review proposal | TX-05 revoke |
| --- | ---: | ---: | ---: |
| API | yes | no | no |
| Steward | no | yes | yes |
| Worker | no | no | no |
| Audit | no | no | no |

所有 `SECURITY DEFINER` 函数锁定 `search_path = pg_catalog, milai`，并在进入事务逻辑前调用
`assert_session_context`（TX-01 使用等价的内联校验）。
