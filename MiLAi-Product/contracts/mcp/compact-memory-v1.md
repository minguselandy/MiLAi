# Compact memory v1

Normative interface decision: [ADR-054](../../docs/adr/ADR-054-compact-memory-tool-catalog.md).
The [V02-09 Goal](../../docs/goals/MILA_V02_09_MCP工具精简与统一记忆入口_GOAL_20260908.md)
defines U01-U13 acceptance and separately authorized public activation.

`--catalog compact-memory-v1` is opt-in; it replaces, rather than augments, the selected
directory. Ordinary (22), legacy (13) and compact (at most 8) are separate catalogs.
The server uses generated finite Pydantic input schemas with no opaque unknown branch.
The release snapshot is generated by `tests/compact_catalog_export.py` through signed
synthetic initialize/tools/list, not a hand-maintained alternative validator.

All tool names have `milai_` prefix. Shared-tool visibility accepts any legal branch
scope; execution rechecks the selected private handler's scope. Private handlers are
not publicly registered. No Claim-key lookup, Proposal, Review, namespace submission,
raw Evidence text search, Note promotion or Evidence capture-status API is invented.

## Deployment scope profile

The union of scopes required by all eight tools and their supported branches is nine:
`milai.memory.read`, `milai.state.read`, `milai.state.write`, `milai.evidence.capture`,
`milai.evidence.revoke`, `milai.note.read`, `milai.note.write`, `milai.note.delete`,
`milai.evidence.read`. Configure this same set in the compact client request, server
enabled scopes, advertised metadata and exact-resource Auth registration.
Exclude `milai.proposal.create`, `milai.proposal.review`, `milai.operations.admin` from
this deployment profile; keep them available to separate advanced/legacy deployments.
Do not collapse nine operation permissions into eight aliases: tool visibility requires
any eligible branch, while each selected branch retains its original permission check.
An old eight-scope legacy grant lacks all Note scopes and Evidence read, so compact
shows seven tools and refuses Note reads. Reauthorization must actually grant the nine;
config edits, registration and successful login alone do not certify the resulting grant.
See ADR-055 for the configuration-only deployment alignment.

Writes require current authorization and operation_id; existing Runtime namespacing
preserves cross-catalog replay. CAS conflicts require READ_AND_REBASE with retryable=false.
Unknown Note outcomes point to memory_status with the original operation_id; missing
receipt does not establish failure. Evidence capture has only controlled exact replay.

Note delete requires current version and DELETE, is logical only, and blocks all
historical reads; physical_deletion_supported=false. Evidence revoke requires
reason_code and REVOKE; synchronous visibility and asynchronous purge remain distinct.
Copies do not create Note-to-Evidence provenance or automatic canonical authority.

Search is bounded dual-source discovery, excludes checkpoints and does not guarantee
exhaustive Evidence coverage. NOT_AUTHORIZED, UNAVAILABLE, TIMEOUT and MISS differ.
Use returned typed references; Note text/source pagination are independent and pin
version. Continue Note inventory only with the same filter/identity cursor; governed
continuation uses context_id, not a Note cursor. A miss never proves no history.

Public instructions are untrusted guidance, not authorization. Reference adaptation
touches only server-owned envelopes, never arbitrary user payloads or source_refs.
No tokenizer or actual-model performance claims follow from UTF-8 byte measurements.
