# 最终开发 Goal：Host 工作区策略的真实运行与行为探索

## 1. Goal 与交付目标

**把已有轻量原型接入真实模型和实际工作任务，让普通记录、普通复核与可替换候选共同参与开发；用任务质量、实际选择和完整成本决定保留、修改或删除什么。**

第一项可观察里程碑是：任务 A 的真实材料进入同一个 Host，模型自主产生可选工作记录，记录进入下一步输入，真实工具返回或明确标注的外生材料能够纠正它；随后形成同任务 NOTE／REVIEW／REGULATED 的可解释比较。不等任务 B 全部准备完，不以重跑 A—E 或全历史审计作为入口。

这是执行文档，不另造算法总方案。接口和边界沿用[设计 v0.1 修订 4](MILA_HOST_WORKSPACE_POLICY_DESIGN_v0.1_20260913.md)，具体选样沿用[首批任务附件](MILA_HOST_WORKSPACE_FIRST_TASKS_20260913.md)，已实现事实见[原型开发记录](MILA_HOST_WORKSPACE_PROTOTYPE_20260913.md)。

“最终”指本次开发职责、范围和收口口径已经明确，不表示认知政策、任务配置或创新主张已冻结。**本次只生成文档；开始执行需后续执行指令，不因本文件存在而自动启动模型、服务或后台 Goal。**

## 3. 固定边界，开放政策

### 3.1 程序必须保持的边界

- 语义判断属于 Host；Runtime 不成为隐藏推理 Agent。第一版不加第二模型、后台 summarizer、reviewer、router、图数据库、触发器 DSL 或训练流水线。
- 工作区仍为可选短 `text + focus_refs`，模型不能改任务身份、授权、来源版本、操作回执。原用户目标和当前要求在 State 之外保留。
- 新观察、未结操作和必要完整消息组不能被旧焦点过滤；旧正文可退出当前输入，但合法历史仍有读取入口。材料存在、已取得、已发送、被理解是不同事实。
- 材料快照的可披露性与事实当前是否正确分开。新观察使用新句柄；语义反证不等于撤销旧材料权限，不能靠自动隐藏旧判断制造“适应成功”。
- 旧 `work_update` 完整归档，但不逐版自动塞回普通历史。业务动作保留输出余量；记录超限可拒绝，不截断否定条件，也不因此重放已成功动作。
- 工作记录不授予事实或行动权威。`DONE`、`park`、`resume` 等文字不能触发程序级完成、切换或复活。
- 实验代码留在 Lab；不修改 Product 默认策略、Canonical、共享服务、公开部署或 Schema 冻结状态。公开持久化不是首轮前提。
- 模型只通过既有授权 vLLM HTTP 路径调用，不操作 GPU、驱动、容器中的设备或服务参数。凭据不进入提示、日志、任务包或 Git。

### 3.2 开发中可以直接调整的内容

提示、短记录表达、容量、focus 数量、近期窗口、COMMON／MANAGED 模式、任务材料规模、信息释放节奏、候选组合和探索先后均可调整。普通方案也可以改进，不能禁止它自然记录条件或旧新关系。

保留—暂缓—复查只是第一项候选。允许保留尚不能证明有用的新线索；保留不等于采信、调查优先权或行动切换。初步阅读、复现、了解接口都是合法工作，不要求每一步先有两个假设或都成为区分性检查。

每次修改只需留下：**观察到什么 → 改哪里 → 预期哪个行为会不同 → 如何核对 → 本次投入上界**。探索允许组合修改；组合有收益先报告组合，不强作单变量因果解释。

跨越安全/授权边界、修改共享产品行为、增加独立推理服务、训练、公开发布或超出本次已授权总资源，需要另行明确范围；不能以“保持灵活”为由自行扩大。

## 4. 推进方式：四个工作包，不是四道新准入门

| 工作包 | 实际工作 | 最小产物 / 本包结束条件 |
| --- | --- | --- |
| W1：A 与真实循环接通 | 打包最小真实证据、补 Provider/任务回调、接真实 tokenizer 和日志 | 第一条可回看的真实模型轨迹，或明确且有界的接入失败 |
| W2：A 的三政策比较 | 相同任务版本与机会下运行 NOTE／REVIEW／REGULATED | 三臂结果与输入差异可查，指出一个值得修改或停止的问题 |
| W3：B 或小型替代任务 | 有界准备可执行任务，各臂独立修改、测试；不等它才能开始 W1/W2 | 第二来源的三臂记录，或 B 不可用的具体原因与处理决定 |
| W4：针对发现的小迭代与收口 | 只对具体解释做追加对照、删减或同信息检查 | 当前最小实现、结果边界、失败与成本、下一步明确决定 |

W1 与任务打包可以交替推进，W3 不阻塞 A。W4 可在 A 的第一组有效比较后插入，不必等六条全跑完。COMMON_CONTEXT 不必先胜出；若问题正是旧正文持续占据输入，可以直接探索 MANAGED_WORKSET 组合。

## 5. W1：先让 A 成为真正能用的任务

### 5.1 最小证据包

从已定位的事务计时、客户端 GC、MCP 边界记录选取少量尾部请求与相邻正常请求，按一致规则提取。保留原行定位、请求关联、数值、测量版本、覆盖缺口和抽取理由；关联计算结果明确标为派生材料。

任务包只分模型可见任务/资料、回放或动作入口、模型不可见的评价依据。一个小 manifest 记录来源、必要文件 hash、提取规则和开发暴露状态即可；不哈希整个 Lab、历史账本或所有证据树，不建新 admission cache。

模型只看到字段白名单和中性句柄，不能读 `runtime.env`、secret、事后诊断报告、其他臂输出或 evaluator 文件。允许不同假设；不把“事务退出不是 fsync”等评分答案作为候选特供提示。计时字段自身的真实定义则应共同提供。

### 5.2 事件与行动语义

外生材料按预先写明的次序释放：事务记录 → GC 及对应请求 → MCP 边界记录。模型事先知道还会补充历史测量，但看不到未来内容。初始工作区为空，各臂自行记录；没有写入也是有效观察，不另立自然 Note 资格门。

开发默认每段最多 4 次正常决策，共最多 12 次；末段包括最终综合交付。可以提前阶段答复，不能因此失去后续批次；任务调度推进依据阶段结束或共同机会限额，不依据是否猜对、不依据 State 关键词。该安排是外生回放调度，不是固定认知阶段；若不适用，在下一比较前调整并留版本。

任务入口支持读已发布材料、允许范围内的计算、阶段答复和最终交付。未采集的现场检查只能成为建议或返回“无此观测”，不能用另一条历史测量冒充实际工具结果。三臂实际选择不同读取时，返回真实对应材料，不强行保持后续字节相同。

### 5.3 Provider 接线只补必要部分

复用一个既有可用 HTTP 客户端与其预算、超时、用量和停发规则，将其接到现有 `WorkspaceHost.step(generate=..., dispatch=...)`。不重新引入 V0222/V0223 的 admission 栈。

接线时必须落实以下未完成事项：

1. 使用当前选定模型的真实 tokenizer 与聊天模板计数；不能把 CPU 测试中的字符长度当模型 tokens。
2. 记录真实模型 ID、Provider profile、解码配置、thinking 配置和最终发送 body；Host 内的 `rows.request` 不是未经核对的最终 HTTP 请求体。
3. 一个正常决策调用同时处理可选记录与动作，不另加“先规划 State”“再修 JSON”的模型。格式或容量反复拖累任务时，缩小外壳或记录，不调出一个新 decoder 工程。
4. 输出预算包含业务动作、记录、外壳及实际适用的 reasoning 用量；配置预留不冒充字段级硬保证。完整输出截断不能猜执行片段。
5. 把内存 rows 接入现有 Git 外日志；在发送前记尝试，收到后补响应、用量，派发后单独补结果。发送状态未知不能填 presented，未知费用不能填零。
6. `Generation` 本身不阻止所有未知用量后续请求，必须保留原 Provider 的停发/核账行为。action validator 与 dispatcher 继续负责原动作范围和动态执行约束。

可先用 A 的前 1–2 次正常决策检查接线，不要求语义全对或强制写记录。若配置未改且轨迹完整，可以继续为同一开发臂；若中途改动，旧轨迹标 DEBUG/INCOMPLETE，不能拼成新版本完整比较。

一次只接这一个文本 JSON 动作 Host；原生 function/tool-call 等其他协议不是本轮任务。Provider 不可用时保留接线事实并停止真实请求，不操作 GPU，也不重开旧服务诊断项目。

## 6. W2：A 的公平三臂比较

| 臂 | 政策差异 | 共同能力 |
| --- | --- | --- |
| NOTE | 普通自由记录，自主决定写什么及怎样行动 | 可不写、可改条件、可选材、可读历史、可验证 |
| REVIEW | 同一次正常调用中结合当前证据复核记录 | 与 NOTE 相同，不强制额外调用或第二 Agent |
| REGULATED | 首个保留—暂缓—复查候选，也允许尚未验证的新线索 | 与简单方案相同，无额外来源、答案、调用或执行权 |

首个小比较默认 COMMON_CONTEXT。按任务初态、共同呈现规则、模型配置、工具权限、容量、机会和退出条件对齐；三个臂各有自己的空工作区、动作结果和日志。启动前写下运行顺序，不按看到的输赢调整后续输入。服务明显变化时如实标记比较限制，不偷偷替换失败轨迹。

用户目标、当前要求、共同材料的角色和相对位置保持一致，不能顺便把 REVIEW 的任务搬到更强角色。提示和记录长度不同计入实际成本；自由交互造成的不同结果属于处理后的差异，不伪造相同返回。

**这比较的是记录/使用政策，不是“有记忆 vs 无记忆”，也不是持久 Note 的因果效应。** 首批没有 N0 无记忆臂；不能把 NOTE 名称解读为已经完成公开 Note 冷读取。

A 的审阅同时看正向进展和错误边界：能否给出具体而有范围的定位；能否指出重要未决项和可推进的下一检查；是否把事务退出、handler 外差值或未观测 GC 武断命名成根因。合理假设不算事实采信，始终说“信息不足”也不自动算好。

区间算术可机械核对；诊断和检查价值由开发者结合原记录审阅，保留来源指向与分歧。不能称独立 human gold，不使用关键词匹配替代语义判断，不默认引入 LLM Judge。

## 7. W3：B 的可执行工作与有界替代

首选任务附件中的 `cancel-async-tasks`。执行时固定所用任务文件版本及必要环境，先验证一个单任务 CPU 入口和明显正/负例，不下载或部署整个 benchmark。官方 checker 尚未本地验证的现状不得省略。

每臂从同一代码初态和空工作区开始，在独立任务环境中修改与测试，收到自身实际 stdout/stderr、退出状态和反馈。检查真实任务调用、并发约束和取消清理，不仅检查输出字符串；模型不能改 evaluator 或读官方解答。

**临时目录不是安全沙箱。** 复用已有隔离执行能力，不给模型生成代码继承凭据、共享 Product 工作树、服务控制入口或任意联网权限。隔离能力不具备时，不直接在宿主运行不受限代码；可换已有安全环境内的小任务或标记 B 暂不可用。

开发初值为每臂最多 24 次正常决策。真实一次完成就记录没有明显维护机会，不强制先犯错。需要多次修订时观察是否保留既有约束、理解测试覆盖范围、重复已排除错误。必要复测不自动算浪费。

准备成本成为主要工作时，允许一个明确标注的简化派生版本、一个已有小任务替代，或停止 B。记录原来源和替换原因，不按候选输赢挑替代题。原版、派生版和替代 root 分开标识，不混报官方成绩。

该任务原生没有条件 A→B→A 或冷会话恢复机会；不计算不存在的重激活/Recovery 分母。任务 B 未完成不阻断 A 的开发，但最终必须明确“两来源比较是否实际完成”。

## 8. W4：每次只解决一个值得投入的问题

每个小比较后，阅读实际输入、短记录、展开材料、动作和结果，判断下一次该改哪里：

| 观察 | 可采取的最小下一步 | 不能得出的结论 |
| --- | --- | --- |
| 没写记录或记录无帮助 | 记录自然行为；有具体解释时调整政策或任务机会 | 不自动判整条 Memory 方向无效，也不代写理想记录继续算自主形成 |
| 有用记录没有进入下一步 | 修复输入或消费接线，再留新版本 | 不把未呈现问题叫认知惯性 |
| COMMON 中无差异，疑似旧正文干扰 | 直接做三臂公平能力下的 MANAGED 或最有信息的两臂组合比较 | 不要求 common 先胜出，不把组合收益拆成单规则功劳 |
| 选材漏证据或来源范围不清 | 修入口、覆盖标记或选材政策 | 不由 Runtime 判定哪条假设正确 |
| 记录改善、同信息 review 打平 | 分别检查记录形成与消费；保留形成成本，删除多余消费规则 | 不把候选生成的记录免费送给 baseline 后比较完整生命周期 |
| 质量相同但少重复 | 核对全部维护、读取、失败和工具成本 | 不只算成功调用或最后回答 tokens |
| 简单方案一样好且便宜 | 当前条件下保留简单方案；无新可检验差异则暂停候选版本 | 不是“State 一概无效” |
| 所有臂都很差 | 分解任务难度、证据、意图、编码、执行问题，必要时拆小 | 不是 Memory-use failure 的自动证据 |

首轮最多追加两个有明确新解释的小比较。每次只选一个已暴露 root，默认比较当前强简单方案与候选，或做一个同信息/去继承/去返回入口消融。需要第三臂时在同一追加包络内重分配，不把“检查一次”扩成全矩阵和参数网格。

可以同轮组合调整，但新的公平比较必须共用相应外壳、机会和资源配置。改过提示、任务、窗口或预算的轨迹不与旧版直接合并为统一胜率。发现记录或执行问题可以中止受影响轨迹，不为凑数继续无效生成。

关联调节、条件再检查、稳定性—可塑性、记忆—世界一致性和元记忆均保留为研究假设，不规定必须选出哪一项。人类记忆与 ADHD 支持方法只作功能启发，不主张临床效果迁移或直接操纵模型内部 attention。

## 9. 资源安排：明确默认值，但不把用满当完成

以下是后续执行指令可采用的开发包络，**本次文档没有实际分配请求**。开始运行前用一份短 run header 写明本次选择，不再做完整源码/历史准入扫描。

| 工作 | 默认规模 | 模型请求上界 |
| --- | --- | ---: |
| A 初始三臂 | 3 条轨迹 × 每条最多 12 次 | 36 |
| B 或其选定替代任务初始三臂 | 3 条轨迹 × 每条最多 24 次 | 72 |
| 独立调试余量 | 至多 6 次；包括不能归入完整臂的接线检查与失败尝试 | 6 |
| 初始包合计 | 两 root / 六轨迹是安排，不是六次生成 | **114** |
| 条件性追加比较 | 最多 2 包，每包至多 48 次；默认一个 root 的两臂 | **96** |
| 本轮默认规划总上界 | 只有有新问题才使用追加包，不自动耗尽 | **210** |

接线检查已包含在某条完整轨迹中时不重复收费；脱离轨迹的调试占 6 次余量。失败、拒绝、超时以及语义错误均消耗对应尝试配额，不补成“成功次数”。B 不做时不自动把它的 72 次转成无限 A 调参。

一个 root 的共同步骤上限可根据已见轨迹调整，三臂采用同口径，并在下一小比较前登记新版本、重算剩余配额；没有被调用的槽位就是未用。提高本次总上界、增加昂贵系统或进入独立确认需另定范围。累计 raw-token 历史账仍按实际记录，不以这个请求规划改写旧账。

配置从当前原型的 `work_tokens=512 / focus_refs=4 / K=2 / input_tokens=8192 / output_tokens=2048` 起步，动作预留 1024、外壳余量 128、目录默认最多 32 项。它们是可调开发值，不是认知规律；真实 tokenizer、完整 HTTP body 和模型上下文上限核对后才能使用。若 thinking 与输出共用限额，必须计入同一总量，不能隐藏额外生成。

默认单个模型请求在途，沿用可用 Provider 的明确单次 timeout，并为每条轨迹记录墙钟上限与工具 CPU 上限；这些具体值在首次发送前取自实际配置或显式设定，不能沿用未知默认。运行中不自动延长已触发的 timeout。允许在必要的下一版本改变资源配置，但不能追认上一次通过。

账务分列：实验模型 tokens/调用、工具与持久化工作、墙钟，以及开发 agent 用量；不相加冒充一个“模型成本”。Mock、HTTP 预检和实际生成分别计数。缓存优惠、未计费用与原始 tokens 分开，未知用量保留且依原规则停发核账。

## 10. 最小观测与研究判读

### 10.1 只保留能解释行为的记录

每条轨迹复用现有 logger，至少保存：

- root/来源 lineage、开发暴露状态、模式、政策和代码版本、模型/解码配置、预算与运行顺序；不保存明文认证头。
- 实际任务输入、阶段发布内容、Host 请求与最终 HTTP body、发送确认或未知状态、原始响应、逐版工作记录及更新拒绝原因。
- 已发布、实际展开、未展开的引用和必要范围；新观察和真实 action/result 的关联。来源资格与事实正确性不能混记。
- 实际动作、返回、代码差异/测试输出、阶段/最终交付、停止原因；已成功动作不因保存日志或记录失败而重放。
- 所有尝试的用量、延迟、工具成本和未知项。原始轨迹/任务数据在 Git 外，Git 只放代码、政策、必要 manifest 和紧凑报告。

代码快照只涉及本次入口与依赖变更，按运行版本留存；不每轮重建全仓证据闭包。不建立新的 reviewer/审计服务替代对几条轨迹的直接阅读。

### 10.2 不压成一个“创新分数”

分别报告三个维度：任务质量；关键选择与错误/重复；全成本。A 的证据诊断与 B 的可执行结果分开，不平均成一个 benchmark accuracy。

不奖励 State 长度、分支数、引用数或自报反思。记录全部分配与实际尝试，另列可解释配对子集及其客观原因；不因某次 NOTE/REVIEW 答错就删除该对。语义答错、无记录、记录不合格、工具失败和未知返回分别列出。

两 root 就是两个独立来源；三臂、阶段、重复、派生变体都不增加独立 lineage 数。首轮全是开放开发，不做显著性或无偏效果量主张。公共题本项目未使用过也不保证模型训练未见。

只有任务中确实出现相应机会才讨论稳定、修订、再检查或返回。旧路线重新可行但不符合当前目标时，不采用可能才是正确行为。条件重激活与错误恢复分开；未出现先前错误和后续纠正机会时，Recovery 不适用，而不是 0%。

## 11. 有界收口与创新判断

### 11.1 正常开发交付

本 Goal 的正常交付至少包含：可运行的 opt-in 原型与实际 Provider/任务接线；至少一项真实工作任务的完整三臂开发比较；B/第二来源的实际比较或明确有界处理记录；全部尝试账；一项有依据的保留/修改/删除决定。

默认争取两来源的六条起步轨迹，但 B 未完成时必须标为覆盖不足，不能称“两任务验证完成”。仅有 mock、单候选调试轨迹或缺臂时，不达到上述正常比较交付；可以交付有界失败/部分完成报告，不能把“报告写完”改成研究目标已实现。

不要求模型每题成功，不要求候选胜出，不要求所有机制机会出现。目标是形成可解释的开发判断，而不是把状态表变绿。

### 11.2 当前范围内可以给出的决定

| 决定 | 证据要求与主张范围 |
| --- | --- |
| 保留简单方案 | 在已运行任务和实现下无净增量；明确任务/处理机会，不否定整个方向 |
| 修改当前候选 | 有具体轨迹支持新的解释，下一次只验证该差异；不是无限寻找阳性 |
| 保留局部行为或效率假设 | 同任务公平比较有方向一致的行为依据，并计入完整成本；仍属 discovery |
| 保留组合信号 | 只证明记录与选材组合，不提前归功于某条规则 |
| 暂停 / 部分完成 | 缺少可用环境、输入链或预算，保留实际已运行与未运行，不能评价机制 |

发现信号后先问“删除什么仍不影响收益”，再考虑更多模块。若普通 review 消费同等信息打平，重新定位记录形成价值，不把结构包装成必要机制。

只有重复的局部信号值得继续时，才按候选实际操作核对最近公开方法、选择最接近的强对照（例如已讨论的 AdaptiveMem 使用政策），再决定有界 pilot。外部制品需核验版本、许可和接入公平性，旧文献名录不等于已经复现；本 Goal 不要求先接多个 Memory Store。

正式创新确认、未打开来源、跨模型、公开持久化/冷恢复与产品默认化属于后继范围。没有真实持久链就不主张长期记忆收益；没有同信息/资源对照与必要的独立验证就不主张新算法成立。

## 12. 工程检查与下一次执行入口

局部代码修改先跑邻近测试与受影响静态检查。工程交付按 Lab 规范列出 boundary、pytest、ruff、mypy、build 的实际范围与终态；一次有界检查未完成就保留未完成，不反复扫描旧证据直到得到全绿。没有改运行代码的文档修订只做文档检查，不以规划更新重启全量回归。

完整回归不是模型效果评分器；相关失败不能忽略，但与当前改动无关的耗时不会自动派生性能候选、缓存或另一套 Gate。动了共享执行边界则补对应风险验证，不借“可用性优先”跳过授权、消息完整性或真实结果检查。

执行时的第一组具体动作：

1. 对照上述已实现文件确认无重叠改动；不重跑旧 Gate A 或 WMA。
2. 提取 A 的小样本与来源映射，写共同任务、字段说明、外生释放规则及离线审阅项。
3. 在同一入口接现有 Provider、真实 tokenizer、日志与有限动作；只做相关 CPU 检查。
4. 有执行授权后，以 A 的小步真实调用观察接线，再完成该任务三臂；有问题就修该处，旧轨迹留存。
5. 用 A 的结果决定下一次小改动，同时有界处理 B；最后交付紧凑结果与下一步，不继续重写总方案。

建议只新增一个任务入口/提取脚本、必要任务 manifest 和一份开发结果记录；已有两钩子、三政策继续演化。结果记录保持“当前版本、实际运行、主要差异、失败/未知、成本、下一步”，不把本 Goal 追加成执行流水账。所有历史 Goal、停止证据与未知用量保持原样。
