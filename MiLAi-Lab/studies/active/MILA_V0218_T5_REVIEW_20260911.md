## 判据校准与运行边界

`t5-validation-v1` 使用同一现版 checker 全池重新执行 **49 个实际 SQLite 分支**：
Stable/Superseded/Unresolved 各 12，Irrelevant 10，Helpful 2，Resolved 1。
Stable/Irrelevant/Helpful 保留 A 动作可过；另三类中旧状态失败、预定脚本真实修订后通过。
这验证可恢复的动作环境，新增模型/Agent 恢复分母均为 0，不能冒充 Agent recovery。
Helpful 隐藏的是当前展示入口中的旧源信息，正常 history 与 A 业务记录两臂保留；
两例均属 journalism 上层聚类，尚未做 Helpful 模型实验，不主张普适收益。

12 个 profile 逐一验证 reset 同态、SQLite clone 的普通历史/业务记录一致、分支隔离、
CAS、动作/事件幂等及 ID 重用冲突、对象/任务作用域拒绝；递归 private/gold/future key
注入在读取/动作/发布边界失败关闭。Host 仅暴露公开读取与限定动作，不暴露私有事件发布器。
canary 验证的是字段/工具边界，不声称能解决任意自然语言 prompt injection。

每个 profile 的完整正例与 None/布尔/数字/字符串/列表/空记录、声明未执行、错对象均检查。
另有领域专用的缺失字段、错型/单位/时区/版本、否定/混合值、部分更新、未决与无限暂停、
重命名/无关事件/顺序/多合法解测试。确切算术只有一个数值时允许等价单位/合法次序，
不为凑“多解”放宽真值。25 项新跨根测试包含每域关闭 checker 的 12 种错误实现，
均被其独立已有正负 fixture 检出；原 8 种语义实现变异仍保留。
这些是有界反例覆盖，不是形式证明或“测试数越多越可信”。

世界转移只实现结构/CAS/受限写入，不导入 checker 的正确输出。独立字面 fixture 先于各根
模型结果冻结。后来扩展 checker 不重算旧模型分数；两个实际链审计重新加载各批封存代码，
与原审计逐字段一致。私有评价异常应单列 evaluator failure，未知域明确抛错，不默认为成功。

## 公开持久与两条自主链复核

三独立进程确实退出，版本/hash 一致，跨 scope 拒绝；Agent write/model presentation=0。
它不补自主 Note 分母。隔离服务已停止，持久卷保留。

T3-v3 与 T4-v1 共 4 个 A / 16 个 B：2 个 A 自写，2 个 NO_WRITE；
4 个 B 有逐字公开冷读旧 Note，4 个实际 HTTP 请求链具备旧 Note + 当前事实，涉及 2 个原 lineage。
请求文件 SHA、HTTP 200、Provider RESERVED/SETTLED、来源内容 SHA、不同 PID 及 A 精确版本
逐项重审；组装好、ID 命中、工具 HIT 或模拟 ACK 都不替代实际请求证据。
