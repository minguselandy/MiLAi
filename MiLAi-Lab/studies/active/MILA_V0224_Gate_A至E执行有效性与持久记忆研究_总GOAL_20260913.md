# V0224 总 Goal：从执行有效性到普通持久记忆的行为影响

## 1. 最终目标与当前起点

### 1.1 要完成什么

建立一个可复算、具有现实运行余量的实验工作点，并完成首批有效的
**N0 / N1 ordinary persistent Note / R1 ordinary review** 比较，回答：

> 在行动合同可执行、世界行为真值可靠、历史记忆和当前证据可追溯的条件下，普通持久 Note 是否改变了后续行为？
> 它改善了连续性、增加了错误影响，还是没有显示独立收益？普通复核能否解释或解决差异？

“成功完成研究”不要求发现新的 Memory 机制。有效的无差异、普通方案足够、局部收益或局部风险均可成为结论。

## 2. 研究原则：固定证据底线，允许方案改变

### 2.1 长期方向不变，但不预选机制

长期研究对象是 **Host-owned、可错且可修正的认知状态如何调节长期记忆对行为的影响**。
Runtime 负责身份、权限、版本、提交、预算和机械约束，不成为隐藏推理 Agent。

人类记忆与 ADHD 执行支持方法仅作为功能启发，不声称模拟大脑或把人类干预效果外推到 Agent。
association regulation、conditional reactivation、stability–plasticity、memory–world consistency、meta-memory
都保留为待检验假设；不要求先证明其中一个，才允许考虑另一个。

不提前增加 State schema、语义投影、评分器、触发器、Reviewer 或第二模型。
新的想法可以随时记录；涉及 Memory 效果的正式实验必须等到有效性条件成立。

### 2.2 两套工作合同

| 模式 | 可以调整 | 必须保留 | 结果能说明什么 |
| --- | --- | --- | --- |
| DEV / DISCOVERY | 一般性实现、公开提示表达、候选组合、局部复现、已开放案例的使用方法 | 所有实际输入/输出、版本、来源、成本、失败与权限边界 | 问题定位、工程可行性、候选信号；不是无偏效果量 |
| ADMISSION / CONFIRMATION | 仅执行已冻结差异；出现新修改则关闭当前实例、另立版本 | 完整矩阵、模型、策略、输入、判据、预算、顺序、停止规则 | 指定版本/范围的准入；独立确认另需未打开样本 |

**停止一个实例，不等于停止整个开发方向。** 开发失败应进入反思和最小修订；但不能修改已运行实例、无限重抽输出，或把多版本最好结果拼成 PASS。
质量门不能靠降低标准通过；若要研究新资源条件或新 testbed，另列条件并重新准入，不追溯改变旧结论。

## 4. Gate A：真实规模 cold admission 有余量

### 4.1 问题与实施

按 V0223 的 K0–K4 执行：冻结真实成本合同 → 无重型 profiler 的粗粒度测量 → 最小等价修订 → 完整 CPU 验收 → 决策。

必须覆盖旧准备前缀的 55 scopes、57 ledgers 和实际 5k+ 文件闭包，并复算精确文件数、bytes、JSON/JSONL 量及重叠结构。
55 是历史失败前缀，不是成功准备的固定总 scope 数，也不是统计独立样本数。

计量分开：引用/闭包、stat/read/hash、解析/复制、历史重建、动态 SQL/账务、最终收口、父子进程开销。
使用粗粒度 monotonic spans；嵌套 inclusive 时间不相加；记录未归因时间、探针成本、报告/退出和完整生命周期。
不把微型探针的 3.17×/2.51× 除到真实准入上，不把冷进程称为清空 OS 页缓存。

候选可为“只移除重型计量”。只有仍有主要可避免成本，才做同 scope、同 bytes、同用途的纯计算去重。
跨准入旧 PASS 缓存、漏依赖、跳过文件重新校验或改变动态安全模型不属于当前 A 子合同。

### 4.2 PASS

以下必须同时满足：

- A1：原/新完整闭包、语义校验、历史账、接受/拒绝及首因保持；
- A2：授权、stop、owner、CAS/head、operation/receipt、当前账本及收口后期限检查仍新鲜；
- A3：完整 16+80 参考、24 效果链、实际 16+24 冷进程、父 finish/gate 和独立回读完成；
- A4：原期限不变，满足下表余量，并有绑定执行 revision 的 terminal 工程检查。

| 计时对象 | 当前硬期限 | 当前余量门 |
| --- | ---: | ---: |
| 每条参考 Session | 60 秒 | 全部准入时间并集 ≤18 秒 |
| 单正式链的 CPU replay | 300 秒 | 该链及归属父准入合计 ≤90 秒 |
| CPU P3 / P4 阶段 | 1800 / 7200 秒 | 整阶段 ≤900 / 3600 秒 |

完整链/阶段还须在各自期限内结束；小样本以逐项/最大值判门，不伪称总体 P95/SLA。
CPU headroom 不保证真实 HTTP 一定通过。

### 4.3 遇到问题怎么调整

- 计量扰动大：停止当前测量实例，减少观察粒度并验证覆盖；不能扣除探针时间补成 PASS。
- 重复纯工作主导：依据计时选择一个最小改动，不增加第五层 adapter。
- 语义不等价：候选不能进入完整门，先补反例和保留动态检查。
- 最小修订后仍过重：输出简化 testbed 的备选方案、失去/保留的保证及代价，由新子合同决定；不原地加时。

V0223 v0.1 的“至多一个候选”约束的是该轮，不是终身只能修一次。
有新可区分证据时可以提出下一轮 A 子合同；须新版本、新差异、新范围，旧失败不动，不自动签发新资源额度。

交付：成本分解、等价/动态负控、完整 cold 证据、headroom、工程终态。
PASS 状态：`GATE_A_PASS / LIVE_NOT_ADMITTED / MEMORY_NOT_ADMITTED`。

## 5. Gate B：新正式 P3，16/16 full intent fidelity

### 5.1 进入条件与准备

A PASS；冻结唯一新正式实例，纳入最新账务/代码依赖；新 HTTP 范围、模型身份和容量检查成立。
沿用已选择的 B1+D11 作为初始工程候选，不重新把历史 diagnostic 当本轮成绩。

离线先验证：原请求→B1 呈现→D11 wire→完整后验合同的映射、full/finish、Unicode/转义、原来源和完整合法对象集合。
不修改业务值、删除干扰来源、trim/改大小写或用 enum/const 暗中塞入正确答案。
HTTP 身份只证明可见返回内容，不冒称完整镜像/后端鉴证。

### 5.2 固定矩阵与判定

原四个已暴露 roots × full/finish × 两遍 = **16 个新冷位置**。
完整目标、顺序、两遍安排、生成参数和评分在发送前冻结；每位置一次请求，无业务 dispatcher。

每份原文按顺序独立验收：

```text
HTTP / usage settled
→ strict JSON
→ complete authoritative Schema
→ authorized target + complete values / legal finish
→ applicable CAS / envelope constraints
→ raw evidence + parent acceptance before deadline
```

full 8/8、finish 8/8，合计 16/16 才通过；“Schema 合法但目标错”是 FAIL。
首遍全通过才运行第二遍。事后输出看似正确、13/16、跨版本累计 16 个成功都不算完整门。
任一非预期格式/意图/基础设施失败，停止该正式候选；保留已结算成本和未运行位置，C 不启动。

### 5.3 灵活修复但不抽签过关

可以回到已开放 DEV 夹具区分 wire、呈现、模型能力、deadline 和测量问题。
候选每次只修一个可解释的工程差异；不把“换 seed 再跑”当修复。
改变 prompt/wire/model 必须重做相关离线和容量检查，重新冻结后完整测 16 位置；不只补失败位置。
无充分依据时保留 `INTENT_FIDELITY_NOT_READY`，允许重新考虑接口方案，不启动 Memory。

## 6. Gate C：P4，24/24 known-intent execution

### 6.1 已知意图不等于隐藏逐轮答案

在 B 通过的同一兼容栈上，使用四 roots × 单写/双写/复杂完整文本 × 两冷进程 = **24 条链**。
每链最多 4 次生成，真实上界 **96 次**；80 个参考请求是机械合法路径，不是实际调用次数上限。

允许给定完整的用户授权动作意图，以隔离编码/执行能力；不由 evaluator 每轮代填“下一条动作”、当前 CAS 或正确回读。
模型依据公开版本、已执行回执和完整轨迹继续；身份绑定由 Host 完成，业务目标仍由模型编码。

### 6.2 逐链完整验收

```text
known intent
→ original model action encoding
→ complete validation / trusted identity binding
→ authorized dispatch
→ CAS + operation idempotency
→ receipt
→ independent current World readback
→ legitimate finish
```

要求目标、完整值、顺序、版本演进、操作记录、回执和最终世界效果一致。
同一重放不产生重复副作用；Note 保存/文字说 DONE/工具返回 accepted 均不能替代业务完成。
24/24 才通过；单链先错后被 harness 改值不算 PASS。失败后按冻结停止策略关闭正式实例。

在本阶段不主动加入新的故障/语义变化；错误恢复另在 D1 设定明确触发窗口。
真实未知提交先冻结写入、按公开 operation/status 接口只读查证，不能从当前 head 猜测“之前没成功”。

交付：每轮 raw、请求重建、合法派发、版本/receipt/效果和所有未运行位置。
结果只证明 `KNOWN_INTENT_EXECUTION_READY`，不证明自然任务或 Memory。

## 7. Gate D：没有旧 Note 时，稳定形成正确意图并完成任务

### 7.1 D0：从 Oracle 校准切换到自然任务

这是明确的合同切换，不是把 B/C 的成绩改名：

- 去掉 evaluator 提供的 `authorized_intent` 答案、gold next_action、参考输出和私有正确值；保留正常用户任务与全部合法来源能力。
- 保留公共 Schema、权限、版本、幂等和资源限制。公开错误只能给出合法类型/版本/状态信息，不能透露私有业务答案。
- 合法、已授权但业务上错误的动作允许在隔离世界中表现为可评分错误；不得被隐藏 gold gate 提前纠正。
- 重新验证无 Oracle 请求的容量、错误路径及所有实际启用的 Schema。启用 Note 工具不继承旧 `enable_note=false` 的覆盖声明。
- runtime/checker 分开：前者保证合法执行，后者用冻结环境真值评价是否做对；checker 的预期值不回流到模型。

这项切换需单列兼容性记录；有未覆盖合同，先完成局部增量校准，不拿 B/C 的八种 Schema PASS 笼统覆盖。

### 7.2 D1：错误恢复校准

在已开放 root 上，每根两种场景、两冷进程；四根最多 16 链，每链≤5次生成：

| 场景 | 外生事件与正确行为 |
| --- | --- |
| 版本变、业务前提未变 | 冻结时点发生版本变化，旧 CAS 确实被拒且无副作用；读取当前版本/公开资料，合法恢复和回读 |
| 版本与适用条件都变 | 新公开证据使旧动作不再成立；撤回旧尝试、核验/澄清或形成适用的新动作，不能只把 version 加一 |

错误必须实际触发，否则记 `NOT_EXERCISED`。至多三次后续生成完成必要修正，余下机会用于合法收尾。
预期一次 CAS 拒绝是该测试的观测，不是全局放宽错误规则；授权/未知用量/证据损坏仍立即停发。
只读版本恢复不等于有权重复业务写入。响应丢失/未知提交先做离线故障反例，未冻结恢复合同不接真实故障实验。

逐 root 四条均正确恢复或正确停止，才通过该 root 的 D1。未通过的 root 保留，不用总体平均掩盖。
如果仍使用已知初始意图，明确标注 recovery calibration；它不能计入 D2 自主任务能力。

### 7.3 D2：自然任务强简单基线

从当前四个已开放 roots、按发送前冻结顺序运行：

- **N0-exec**：无 A 会话继承 Note，正常用户要求、来源访问与工具。
- **R0-exec**：同样无继承 Note，加一个领域无关的普通复核政策，不是新的 State 机制。

四 roots × 两政策 × 两次独立冷启动 = 最多 **16 episodes**，每个≤16次生成。
两臂同模型、当前世界、合法来源、工具、资源上界；普通复核的生成也从同一机会数中扣除，不免费追加。
冻结且诚实标注 `HARNESS_PUBLIC_PREFETCH` 或自主读取；两臂相同。必须先证实必要公开材料进入输入，避免退回 acquisition 混杂。

评分依据环境 postcondition 和允许的多解，不要求唯一“标准推理”。合法澄清时必须满足未决世界状态，
不能一面问用户一面保持错误 confirmed=true 或继续提交。只说完成但世界未变即未完成。

**稳定的局部定义**：每个 root 两政策两冷遍共 4/4 完整任务 PASS，无未解决协议/身份/提交问题；
并具备该 root 的 D1 恢复证据。至少 **2 roots / 2 families** 满足，才有 `G_TASK_READY`。
这不是总体可靠率或外部确认；E 所用每一 root 均须单独满足，不借别根通过。

资格同时绑定已验任务、当前资料和动作合同，不是给 root 名字永久贴 PASS。
E 的新任务/事件若超出这些已验条件，先做增量 D 校准并冻结相应额度；不能仅凭同 family 就宣称自然基线稳定。

本总合同采用逐 root 准入，不要求所有四根都适合后续 Memory。D1/D2 中失败及未运行根全数报告，
选择规则在看到 N1 结果前固定，后续结论仅针对这批基线合格任务，不能外推为全任务收益。

### 7.4 失败路由

- 来源未取得/未呈现：修公共来源取得与覆盖；记 acquisition/presentation，不记 Memory。
- 已呈现但普通任务理解错误：记录任务使用/语义问题；可以在 DEV 反思、改普通提示，不提前增加 State。
- 再现重复非法动作：回 action-contract 校准。默认同一未恢复协议错误连续两次就收口该 episode，而不是耗尽16次；具体错误签名先冻结。
- 多根在普通复核下稳定完成：保留这个强基线进入 E，不为了创新故意削弱它。
- 不足两根/两 family：D 尚未通过。允许提出新的已开放任务设计或接口方案，但须前瞻冻结、重验对应能力，不偷偷消费 C 补足数量。

## 8. Gate E：普通持久 Note 对行为的影响

### 8.1 E0：可运行与可识别性预检

先验证：公开 Note 写入/提交回执、ID/版本精确读取、作用域隔离、冷进程、实际模型输入证据和独立业务 checker。
涉及此前未覆盖的 Note Schema/Provider 组合，先做零模型完整合同/负控及必要的有界 B/C 增量校准；其 live 次数须单独冻结，当前为0。
不能直接用私有数据库塞 Note，或者拿 Mock write 代替真实公开持久化链。

优先研究 **controlled consumption**：新 Host 通过公开接口取回指定的真实 A Note，并将同一当前合法来源集呈现给各臂。
取得规则只能由用户任务、已提交 Note 的公开 ID/版本和正常来源绑定决定，不用 gold evidence selector。
这控制 acquisition 混杂，但**不证明模型会自主触发召回**；自主召回是未来独立条件，不能混报。

冷恢复必须是新的 Host/模型上下文；不复制 A 的 assistant 轨迹、隐藏缓存或未提交工作板。
可以通过共同合法历史重新取得原资料，但不能让 N0 偶然读取实验处理用的 A Note。

### 8.2 M0：自然 A 和有效记忆机会

1. 在 A 输出前冻结每个 root 的世界 t0、当前任务、未来 Stable/Changed 事件与 checker；未来事件/答案对 A 隔离。
2. A 正常完成工作，自主选择是否写普通自由 Note。不给正确 Note、固定认知字段或“必须保存这个结论”。
3. 记录实际 save 参数、operation、提交/版本回执、t0 World 和当时可见来源；保存与业务成功分别验收。
4. 离线逐命题判断与后续行为有关的内容在 t0 是 supported / tentative / wrong / unresolved；未来变化不能倒推它当时就错。
5. 只有后来可能影响行为的旧命题当时有依据、已提交、来源和适用时点可追溯，才进入“曾正确记忆”消费分析。

NO_WRITE、提交未知、混合错误、t0 无法裁定全部保留，不能反复重生成直至获得好 Note。
来源中原样表达的未决/假设可以是正确记录，但不能把“记录了猜想”改称“猜想已经证实”。

为避免固定两题无 Note 就隐性补题，采用有界、前瞻的 M0 规则：
在 D 已合格、已开放的最多四 roots 中冻结候选顺序；每根至多一个自然 A，选择首两个满足 t0 资格且覆盖两 family 的 roots。
这是 B 行为之前的条件资格筛选，不看未来 N1 输赢；全部候选、A 成功率、自选写入率和排除理由公开。
候选耗尽仍不足，记 `MEMORY_OPPORTUNITY_INSUFFICIENT`，不补造 Note，也不打开保护池。

### 8.3 三臂与世界条件

| 臂 | 旧 Note | 其余来源/世界与执行 | 回答的问题 |
| --- | --- | --- | --- |
| N0 | 不继承/呈现 A 工作 Note | 同一 A 业务历史、当前世界和合法来源仍可查；不是无历史 Agent | 没有这份持久工作 Note 的行为 |
| N1 | 普通 Note 经公开接口冷取回并呈现 | 与 N0 相同的普通执行政策 | Note 的可用/呈现带来的整体行为差异 |
| R1 | 与 N1 同一份 Note 内容和版本 | 另加固定的领域无关普通复核政策 | 简单复核能否解决差异；不是特定 State 的独立贡献 |

R1 的提示不能含具体对象、事件答案、应该忽略哪条 Note 或强制“新的一定正确”。
可采用通用原则：依据当前任务核对记录与证据，保留仍适用的信息，对冲突/未决按普通任务规则处理。
N1/R1 相同读取结果不等于相同实际总成本；多一轮复核的输入/输出和时间全部计费。
相同预算上界也不等于实际计算量相同，因此 R1−N1 首先是政策组合效果。

每个入选 root 的首轮至少有：

- **Stable**：旧信息仍有效；不能靠永远不信 Memory 获得表面 plasticity。
- **Changed**：旧信息在 t0 合理，外生事件后被取代或适用条件变化；当前公开证据足够支持修正/澄清。

Helpful、Irrelevant、部分完成和 Recovery 可以作为以后探索条件，不在首轮临时插入。
同一 root 的变体、三臂和重复不是独立样本。

### 8.4 同源隔离和公开恢复

N1/R1 必须绑定同一个自然 A 产物，不能各自生成一份质量不同的 Note 后归因于消费政策。
各臂业务 World 和新增写入独立，不能让一臂修改影响下一臂。

执行前必须证明公开接口支持所选隔离办法：

- 优先从同一已提交、可精确定位且不被实验 B 改写的 Note 版本公开读取；B 新记录另入各自隔离 scope。
- 如需复制/恢复，只用已准入公开接口/公开 testkit，记录原 commit→目标 commit、内容等价和机械 ID 映射；
  标成 `DERIVED_NOTE_COPY`，不冒称同一原 ID 的冷恢复。真实原 commit 的公开冷读证据须另外成立，两类链分开报告。
- 若公开能力不能保证无污染配对，E0 不通过；不得临时读取私有表或静默修改 Note。

提交回执或 metadata 校验通过，不自动证明正文进入模型。必须关联公开读取返回、组装后请求、实际传输记录/响应，逐请求绑定内容 hash。

### 8.5 首批数量与冷复验

最多 4 个自然 A；目标接纳两根/两 family。
两根 × Stable/Changed × N0/N1/R1 = **12 个 B episodes**。
若首轮整体执行、隔离、旧新呈现和真值链有效，则无论谁输谁赢，按冻结反向/平衡顺序完整重复12个 B；不重写 A、不只重复有利位置。
全部路径最多 **4A + 24B = 28 episodes**，每episode≤16生成，最多448次；不是现在的实际 allocation。

普通业务错误是实验结果，不自动触发全批停止。权限、用量未知、隔离/证据损坏或公共执行合同失效则停止受影响批。
首轮关键有效性失败时不为凑数量进入第二轮；保留全尝试分母，修订后用新实例而非续填旧矩阵。

### 8.6 Memory 因果链和分母

```text
Experience at t0 → self-authored Note → committed
→ independent cold Host → public read → actual Note presentation
→ current evidence presentation → externally observable action
→ independent World truth → optional recovery observation
```

逐配对检查：旧 Note 的 t0 合理性、公共接口冷读、N1/R1 旧新双呈现、N0 当前证据呈现、动作合同与独立真值。
N0 不因为没有旧 Note 被判无效；它的无 Note 正是实验处理。
关键支持是否充分由离线冻结规则判定，不能由 evaluator 在线补给答案。

分别公布：

| 分母 | 用途 |
| --- | --- |
| 全候选 / D 合格 / A 尝试 | 看任务与基础设施适配性，不隐藏筛选 |
| A 自选写入 / committed / t0 合理 | 判断实际测到了什么记忆，而非假定一定有 Note |
| cold public read / actually presented | 区分取得、传输与消费；缺失不可当作惯性 |
| 有效配对 / 所有 B 尝试 | 分开完整流程结果和合格条件下的行为诊断 |
| 合法变化机会 / 实际错误偏离 / 实际纠正机会 | 分别用于 adaptation、interference、recovery，不混用 |

分母0报告 N/A。双呈现≠已经注意到，已注意到≠因 Note 改变行动；只用可观察输入、公开表述、工具行为及对照支持解释，不索取隐藏推理轨迹。
有效配对子集可能受取得/执行成功筛选影响，必须同时报告全尝试；不能把事后筛出的子集效果直接解释成总体因果效应。

### 8.7 指标与结论规则

主指标分别报告，不合成单一“创新分数”：

- Task success：完整世界 postcondition，含正确保持未决/澄清；
- First relevant action：首个与当前要求相关且合法的动作及时间；
- Continuity：必要历史复用、重复读取/重复业务工作与恢复成本；
- Stability：旧信息仍适用时正确保持，而非无谓重做/推翻；
- Adaptation：新依据充分后修正动作所需机会数，以及旧错误目标/确认/完成状态的残留；
- Interference：与旧 Note 一致但与当前合法证据冲突的动作；只有对照和轨迹支持时才称 memory-induced；
- Recovery：确有错误偏离且之后有充分纠正机会时恢复；无纠正窗口不计算；
- 成本：A 写入、冷读取、全部 B 请求、工具/重试/准备和生命周期成本。

| 观察 | 可以保留的结论/下一步 |
| --- | --- |
| N1 改善连续性且不损害适应；R1 无增量 | 普通 Note 的局部价值；保持简单，不硬造调控机制 |
| N1/R1 与 N0 相近 | 本范围未见独立收益；不等于所有记忆无效 |
| N0 正常，N1 重复旧动作，R1 能修正 | 局部消费政策问题；普通复核优先，不把复核包装为 State 创新 |
| 各臂共错 | 回到来源、理解、执行或真值问题；不能仅因 N1 也错而归因 Memory |
| 旧 Note 本身混错或没有有效双呈现 | 记质量/机会/有效性缺口，不计算记忆固着率 |
| 在多独立根/family 反复出现且强简单方案不能解释的差异 | 开放提出机制假设；仍不是独立确认或总体规律 |

两根两遍只是局部研究入口，不能以 2/2、4/4 或某个提示赢一次宣称新颖机制成立。

## 9. 反思、修订与重新准入：保持开发灵活

### 9.1 每次反思只产出一个最小决定

在首个非预期失败、完成一个有界 wave、成本异常或信号互相矛盾时，记录：

```text
Observation：原始证据说明了什么，哪些仍 UNKNOWN？
Earliest layer：最早可证实失败在哪一层？
Alternatives：至少区分工程/任务/记忆等相关解释，而不是先选机制。
Next test：能区分解释的最小检查是什么？
Change：改什么、保留什么、为什么不是题目特修？
Invalidation：哪些 gate/test/输入暴露状态需要更新？
Decision：继续 / 修复 / 新子合同 / 简化 / 暂停；下次复查点和资源上界。
```

不要求为每个小修复写长报告，也不重复整仓测试来代替理解原因。
连续两轮没有增加可区分证据时触发设计复审：删冗余、换诊断方法或暂停该路径，不继续无差别跑模型。
这是反思触发器，不是自动判研究方向无效。

### 9.2 修改的权限与范围

| 修改类型 | 开发阶段能否做 | 重新冻结/准入 |
| --- | --- | --- |
| 文档、计数/观测 bug、相同业务语义的局部实现修复 | 在已授权范围可直接做并留回归 | 改动分类与 hash；计量改变须重测 A 的相关结果 |
| prompt/wire/schema 实现、请求拼装、错误恢复政策 | 允许在已开放 DEV 中尝试 | 新候选版本；不能注入旧正式批；按下表重验 |
| source presentation、普通 review、Note 的保存/使用策略 | 可形成探索候选 | 新实验条件、同等信息/预算核查；不得混入已冻结 N0/N1/R1 |
| 更换任务/来源表示/World/checker | 可以提出并离线验证 | 新任务合同和 exposure；重验 D/E，必要时 C，不改旧评分 |
| deadline、调用额度、模型/服务、静态安全模型、保护池、Product/部署 | 不是普通 bugfix 权限 | 明确新范围与授权；不追溯放宽旧门 |

主 Goal 允许多轮“有证据的修订”，不限制整个项目只能尝试一次；每个具体批仍有限、有期限、可停止。
若一次执行授权预先包含多个修复 wave，可按条件继续；否则新增 live allocation 需明确确认。
不以“保持灵活”为理由无限重跑到全绿，也不以“冻结”为理由拒绝有依据的新设计。

### 9.3 依赖失效表

| 改动 | 至少需要重新验证 |
| --- | --- |
| admission/历史账/收口/进程编排 | A；影响行为/权限或原 live binding 的，B/C 和后续重新准入 |
| 模型、wire、生成配置、完整呈现模板 | B、C；同时重做 A 相关负载/容量校验，再验证受影响 D/E |
| 业务 action adapter、Schema、身份/CAS/receipt 合同 | 相关 A 语义、B/C 合同和效果、D/E |
| 自然任务普通提示/来源取得政策 | D；如影响编码/Schema/容量须回 B/C；对应 E 重跑 |
| 新启用 Note 工具、冷恢复、公开 API/pin | Note 增量机械/兼容准入和 E；若共用执行栈变动则回溯 C/D |
| Memory 候选政策 | E 的新臂与强简单对照；不自动抹掉未受影响的 A–D，但核对资源/合同差异 |
| checker / 标签错误 | 原 raw 保留，出具更正与敏感性分析；新 checker 条件重新冻结，旧实例不能静默变 PASS |

采用**最小受影响重验**：不必每次从 A 重跑所有历史，但必须有可审计的“为何此前证据仍适用”说明。
依赖 hash 不同且未完成影响分析时标 `STALE_FOR_CURRENT_REVISION`，不是当前 PASS。

## 10. 创新探索如何保持开放

Gate A–D 的工程改进只作为 supporting infrastructure。
Gate E 有效后，不把 RQ1、State 字段或某个漂亮单例设成唯一方向；优先找对连续性、修正、行动和成本真正重要的机会。

开放候选可包括但不限于：

- 联想激活与采信分离，暂存候选但不自动付出行动预算；
- 旧分支在新条件下重新激活，以及误唤醒/无谓重开；
- 稳定性—可塑性：保留仍有效经验，同时改变过时判断的行为影响；
- memory–world consistency：Note 的完成/确认与实际环境是否一致；
- meta-memory、外部化时机及普通笔记/提醒的更轻使用方式。

允许在已开放 discovery 上组合机制、改自然语言表达、复用失败案例；先观察现象，再做消融。
不要求所有候选一开始单变量，但任何 bundle 收益都先标 bundle，不预先归功某个部件。
Runtime 不承担语义 relevance/信念更新；Host 形成和修正可错认知产物，正常权限与来源仍在。

筛选同时考虑行为收益、跨任务重复、先行工作、简单性、生命周期成本和失败安全。
若普通 Note/普通 review 已解释效果，就保留简单方案；也允许发现“成本可降低而质量不降”的价值，不只寻找 harm。
选择候选后才做领域无关说明、强简单对照、机制消融和独立确认。

**当前主 Goal 不自动开放 C 或新增机制模型配额。** 独立确认需另冻候选、未打开 lineage、抽样/评价/预算和暴露记录；
当前 reserve 不是已合格 C。查新时以当时可核验的论文/官方制品为依据，不沿用旧新颖性判断。
机制最终不成立，也应交付有效实验、失败边界和可复用仪器，不为“必须创新”追加架构。

## 11. 分阶段资源规划

以下是**下一正式子合同的初始计划上界**，不是当前发送授权，也不是必须耗尽的额度。
累计 raw-token 硬上限继续为 null；请求、时间、服务、并发与停止规则仍有限。

| 阶段 | 初始任务/调用上界 | 时间与范围 |
| --- | --- | --- |
| A | 真模型0、HTTP0；K1/K2 和40冷矩阵按 V0223 | 60秒参考、300秒链、1800/7200秒阶段及原外层上限不变 |
| B | 16次生成 | P3阶段1800秒；每HTTP≤60秒；并发1 |
| C | 24链×≤4生成，≤96次 | P4阶段7200秒；每链300秒；每HTTP≤60秒；并发1 |
| D1 | ≤4根×2事件×2冷遍，≤16链/80生成 | 新子合同建议每链≤300秒；阶段上限发送前冻结 |
| D2 | ≤4根×2普通政策×2冷遍，≤16episodes/256生成 | 建议每episode≤900秒；按完整 root 配对分 wave，不拆掉失败配对 |
| E | ≤4A+24B，≤28episodes/448生成 | 建议每episode≤900秒；M0/首轮B/复验分别冻结阶段时限 |
| Note 增量校准/新诊断/机制探索 | 当前0 | 若需真实请求，先有单独差异、次数与授权，不能藏入既有上界 |

D/E 尚未执行；建议期限不是旧合同加时，也不是可以开跑的缺省值。
