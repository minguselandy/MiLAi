### 1.2 本次核查到的具体线索，不等于在线根因已确认

对冻结的实际 HTTP body、准备器及 wire 编译代码只读核对：

| 观察 | 证据含义 |
| --- | --- |
| 授权动作完整存在于最后一个 user 消息末尾的 `authorized_intent.authorized_action` | 不能预设“没有发送正确值”或“只要把意图放到最后即可修复” |

JSON Schema 的 `pattern` 在字符串任意位置匹配，并非默认整串匹配；因此 `\\S` 的业务语义不是
“只能有一个字符”。[JSON Schema 官方说明](https://json-schema.org/understanding-json-schema/reference/string#regexp)

本次还静态查阅了历史版本对应的上游 XGrammar v0.2.3 源码：`GenerateString` 的 pattern 分支把
正则转换结果放在 JSON 字符串引号之间并提前返回；长度分支另行生成字符串规则。
这使“生成约束与完整校验器的字符串语言不一致”成为有代码依据的待检验假设。
[上游固定版本源码](https://github.com/mlc-ai/xgrammar/blob/v0.2.3/cpp/json_schema_converter.cc#L1395)

**以上不是当前服务选择了哪个后端的证明。** HTTP 身份没有提供完整进程/配置鉴证，历史库版本和
上游源码也不等于正在执行的解码路径。不能在本轮文档中宣布已确认线上 XGrammar 根因。
vLLM 的结构化输出由后端处理；本批继续以实际 HTTP 行为作运行证据。
[vLLM 官方说明](https://docs.vllm.ai/en/latest/features/structured_outputs/)

## 5. P1：小型字符串语义 HTTP 诊断

### 5.1 完全无业务副作用的四条件

各请求只有一个合成 `text` 输出字段，完整权威合同始终为：string、`minLength=1`、`pattern="\\S"`，
另保持原 required / additionalProperties 约束。目标字符串明确给定，按精确复制评价。
**四条件模型可见 messages、完整权威 Schema、参数、预期值完全相同，仅 wire 两个关键字不同。**
使用统一、真实的机械说明；不能在某一条件额外提示正确策略。

| 条件 | wire pattern | wire minLength | 所回答的问题 |
| --- | --- | --- | --- |
| D00 | 原 `\\S` | 原 1 | 复现合成合同下的表现 |
| D10 | 移到输出后校验 | 原 1 | 仅 pattern 是否足以解释差异 |
| D01 | 原 `\\S` | 移到输出后校验 | 长度约束的独立诊断 |
| D11 | 移到输出后校验 | 移到输出后校验 | 简单 string 生成能否保真，完整业务规则仍验收 |

三类固定夹具：

- T1：多字符 ASCII 地址及普通多词文本，用 `example.invalid`，不用本次任务的收件人或业务答案。
- T2：中英文/非 ASCII、引号、反斜线、换行/制表符；目标是解码后的同一字符串，不比较 JSON 转义写法。
- T3：前后空白、标点和内部非空白字符；不允许通过 trim 获得表面一致。

P0 确定每类唯一实际字符串/hash，所有目标在完整合同下合法。重复键、空串、全空白、类型错误、
超长/枚举/锚定 pattern 等作为**本地验收负控**；不要求模型生成危险动作，不将它们混进复制正确率。

首遍顺序为 T1→T2→T3，每类 D00→D10→D01→D11，共 **12 次**。
只有首遍至少存在一个“D00 该夹具未保真、某个移出条件对同夹具保真”的配对差异，才启动
预先冻结的第二遍完整 12 次，按反向条件顺序减小固定先后偏差；不只重跑有利单元。
每次一个新客户端进程、一次生成，不继承先前响应。最多 **24 次**，不是统计确认。

### 5.2 内容失败与停发必须分清

P1 只接 `transport → raw evidence → offline validation`，**不连接 Session、World 或 dispatcher**。
HTTP 成功且 usage 可信时，短字符串、错误值、非法 JSON、完整 Schema 不通过可作为预定诊断结果，
记录后按冻结顺序继续；不能把它们释放为合法动作，更不能修改输出。
这需要显式的诊断 runner/结果类型；不能修改旧生产验收逻辑来“允许错误通过”。

HTTP/传输异常、新未知、证据丢失、用量违规、授权/配置漂移、越界行为均立即停止整批。
任何失败都占一次尝试，重发不能充当对照。同一有限矩阵观察预期内容差异不是自动重试。

### 5.3 决策规则

- 首遍无配对改善：不消费第二遍，不宣称 grammar 根因；保留 `NO_DIFFERENTIAL_SIGNAL`，转提示分支的规划。
- 进入第二遍后，候选必须三夹具两遍 **6/6** 精确保真，且至少一夹具相对 D00 的改善两遍一致。
- 多个条件合格，选移出关键字最少的；同样少时固定 D10 优先于 D01，D11 最后。
  D00 同样 6/6 时不选择更复杂策略。没有合格条件就不进入完整动作修复复验。
- 报告“当前 HTTP 条件下的字符串约束相关行为差异”，不凭此定位具体内部后端、证明全部语言等价
  或报告无偏效果量。二者都失败时保留模型/呈现/服务组合未分解，不开发 State。

`G_STRING_SIGNAL` 只允许提出一个兼容候选，不表示完整动作或执行门通过。
