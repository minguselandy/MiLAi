# V02-15 R1 机制卡与 R2 选择备忘

依据：[完整执行记录](MILA_V0215_EXECUTION_20260910.md)及四版不可覆盖的输入、State、

## R1：现象、解释与反例

### C1 可纠正检查点 bundle（A+C+E，含可选外部化）

- 来源观察：repair1 的 CHECKPOINT 4/6，和 NOTES 同分、少3次生成；pipeline相关变更
  1/1 正确，NOTES 错误、REMINDER 未交付。初看可能是返回入口或收敛政策起作用。
- 反例：该组初始前提不满足时提前选 publication；无关变化时改查 exporter。
  delivery 诊断2/2无交付；readiness 诊断1/2，弱于NOTES/REMINDER各2/2。
- 竞争解释：输出顺序与收尾协议、决策词义、额外提示长度、偶发采样/服务执行差异、
  可选笔记内容不同；目前没有分离“分支返回线索”这一组件的增量。
- 成本：repair1 49,382 raw 看似较低；delivery 74,817 反而最高；readiness 17,493
  高于 NOTES15,873、REMINDER16,288。不能据此宣布跨异质 run 的严格 Pareto 排序。
- 状态：**PARKED_THIS_VERSION**，不是否定 A/C/E 全部研究方向。
- 下一次能区分：在已稳定交付底座上用同信息普通笔记对照；外生安排真正有返回入口的
  多分支中断任务，比较可错返回规则与普通提示。若要执行，另定新 discovery batch。

### C2 普通适用性提醒（E 的最简单替代）

- 来源观察：repair1 REMINDER5/6，高于另两组4/6；grant三阶段均能纠正过期规则。
- 反例：pipeline相关变化未交付；delivery诊断仍把已签批解释为等待approval。
  readiness下与无额外提醒的NOTES同为2/2，未显示该提醒的必要性。
- 解释：通用证据核对可能已足够，而非 meta-memory；没有错误策略与无关变化的独立
  归因确认。StateMem/RuleMem 等已有当前规则/取证指导近邻，不能把提醒命名为创新。
- 状态：**KEEP_AS_SIMPLE_COMPARATOR**，不选为 MiLAi 新机制候选。

### C3 自选写入的完整生命周期（B）

- 来源观察：所有组可以保存普通 State；实际发生52次模型自选成功写入，39次新Host
  启动，跨阶段读回与最近成功公开写入的ID/版本/payload相同。
- 反例：有的组只存了“接下来查源”的入口而未存最终证据；delivery/CHECKPOINT
  已把正确决定写到State仍未交付。写得更多不等于任务更好或恢复更省。
- 解释：笔记持久化正确是工程事实；本批所有合法源短且可重新取得，没有隔离中断分布、
  note信息量与政策贡献。readiness/NOTES不写新笔记仍成功，只说明该短探针不需要强制保存。
- 状态：**OBSERVED_MECHANICAL_USE / NO_BENEFIT_CLAIM**。
- 下一次能区分：更长的外生中断任务，提前匹配中断分布；普通笔记、固定检查点、自选保存
  比较全成本，并观察未保存/错误保存。不得只选已保存成功的组安排恢复。

### C4 候选混入因果判断与交付协议的竞争解释（A + 支撑层）

- 来源观察：delivery/NOTES/pipeline/phase2 将明确“无当前证据”的旧类比纳入最终
  exporter判断，并假设不存在于来源的自动触发机制；不是单纯没有读到来源。
- 反例：三组在grant都识别Call E规则不适用于Call N；不是统一污染。
- 输出层观察：旧action-first可生成正确decision、反复更新State却保持read/空read。
  所有这些attempt仍按原终态保留，没有从隐藏decision字段“抢救”成已交付。
- 诊断：三组共同恢复readiness-first/最终槽后6/6交付，但CHECKPOINT仍跳前提。
  因同时变了输出顺序、空read约束和请求上界，不能单独量化哪项造成改善。
- 状态：**SUPPORTING_PROTOCOL_CORRECTION / NOT_NEW_MEMORY_INNOVATION**。

目录中的 D 发散宽度调整未被本批单独探索，其他新候选也没有被禁止；“未选”不是“已反证”。

## R2：六维筛选与明确决定

| 维度 | 当前证据 | 选择影响 |
| --- | --- | --- |
| 行为增益 | 检查点的局部胜例伴随早期/无关变化损失，最后对照低于普通笔记 | 无稳定增量 |
| 迁移范围 | 两个合成根、相似前提工作流；后续反复用同一pipeline | 不支持外部泛化 |
| 新颖性 | 记录、提醒、规则修正、分支线索均有近邻；未识别独立新增控制关系 | 不能主张创新 |
| 简洁性 | readiness诊断普通笔记2/2且未写新State，更多控制提示1/2 | 保留强简单对照 |
| 成本 | 检查点成本排序随版本翻转；保存/恢复完整费用已计，不只报下一次读取 | 没有稳定生命周期收益 |
| 失败安全 | State未越权，但出现过早publication、类比固着与有笔记无交付 | 不能以无业务执行代替决策安全 |

**本批选择0个候选进入R3；终态 NO_PROMISING_CANDIDATE_IN_THIS_BATCH / KEEP_SIMPLE。**
理由是增量不稳定、最近邻差异未成立及强简单对照已足够，而不是剩余额度不足或必须跑满。
原90次分配实际用了88次；未用2次不滚存。本批没有尚待执行、预先承诺的独立确认样本。

R3/R4合同只对被选候选建立；因此本批无确认包/确认生成，也未读取任何旧保护题池。
R5只对保留候选的持久/产品主张触发；当前不作此类收益主张，无默认切换或发布操作。
以上是该批研究的合法零候选收口，不把整个记忆研究永久关停，也不把工程通过替代R3–R5。
