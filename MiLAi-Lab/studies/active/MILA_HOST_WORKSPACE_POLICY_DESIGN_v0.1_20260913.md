# MiLAi Host 工作区策略：第一版落地设计

## 1. 最终决定

本设计固定最小接口与执行边界，不冻结认知政策。开发允许调整提示、记录表达、工作集配置、任务材料和探索顺序；任务不要求复现预设的暂停—恢复流程。每次迭代保留实际版本、输入输出、失败与成本，以工作质量和实际选择判断价值。简单方案与候选共同发展，局部无差异不自动否定方向，局部收益也不提前确认为创新。

实现一个嵌入正常 Host 决策循环的可选策略：**一份可替换政策、一份短工作记录、调用前后两个钩子**。同一个模型在正常选择下一动作时，顺便决定是否修订记录、下一轮希望重新展开哪些已有材料。

首个可替换候选是可逆的记忆使用控制：必要条件失效时停止沿用，阻塞消失时重新检查，当前依据充分时才考虑重新采用。它不是写进程序的固定认知流程。联想不自动变成采信，暂缓不等于永久遗忘。这里的“注意力”指读取、调查与行动机会的分配，不指 Transformer 内部 attention 权重。

第一版放在 **MiLAi-Lab 的 opt-in Host 原型**，不直接成为 Client 默认功能。产品已有公开读写、来源取得和动作执行能力继续复用；Runtime 不新增语义判断、路由模型或业务状态字段。候选有收益后，才考虑把通用钩子迁入 SDK，研究政策仍独立版本化。

`focus_refs` 必须能够改变下一轮实际展开的历史，不只是向全量历史追加材料。首版同时提供真正的有界工作集与共同材料对照，使用相同钩子。探索可以直接测试政策与工作集的组合，不要求先证明单独政策有效；有信号后再分离记录形成、使用政策和选材的贡献。

设计修订 2：纠正初稿“只追加历史材料、正文移出推迟到后续”的取舍。未选历史可以退出本轮工作集，但不删除原始记录；`COMMON_CONTEXT` 是归因对照，不是开启真实工作集管理前必须通过的门。

设计修订 3：首批按用户选样建议采用“真实证据回放＋小型可执行工程任务”，三臂从空工作区开始，先用共同呈现规则、不固定五轮。参见[具体候选、信息释放与评分安排](MILA_HOST_WORKSPACE_FIRST_TASKS_20260913.md)。这是本批选择，不改变前述可直接探索组合的灵活性；候选材料已定位，任务包尚未完成。

设计修订 4：采纳可演化政策与小循环开发。只局部修订本文件和任务附件，已实现 Lab 最小原型，47 项邻近测试通过；全回归部分通过后有界停止，未完成。不发模型请求、不修改服务、不重启 A—E。参见[实现与检查终态](MILA_HOST_WORKSPACE_PROTOTYPE_20260913.md)，不能由 CPU 接线推导模型效果通过。

## 3. 最小数据对象

模型只提出下面的可选工作产物；空更新是正常结果。

```text
work_update = null
           | { text: string, focus_refs: string[] }
```

`null` 保留两个内容；非空对象完整替换两个内容。`{text: "", focus_refs: []}` 只清空本地工作区，不删除任何 Note、原始事件或真实任务状态。

`text` 是供以后续接的简短公开工作记录，不是完整思维链。它可以包含当前问题、采用依据、仍需核对的条件、少量暂缓路线和返回入口，不强制每轮填满模板。

`focus_refs` 是 Host 已公布的材料句柄，按希望展开的顺序排列。模型不生成真实路径、权限、版本或 Evidence UUID；Host 把句柄映射回已知的具体来源及版本。未知句柄不会触发任意文件读取或联网。

Host 另行维护可信外壳，尽量复用已有任务、请求和操作元数据：

```text
task binding / policy version / local revision
input request id / presented observation position
reference registry / disclosure dependencies
optional persisted state identity and version
```

这些不是新的认知字段，也不由模型填写。原用户目标、最新要求、授权、未结业务操作及真实执行回执继续由原 Host 保管，不能被 `text` 覆盖。

开发初值可取 `text <= 512 个实际模型 tokenizer tokens`、`focus_refs <= 4`，同时受当前请求容量约束。这是可调整的 Host 本地配置，不是产品 Schema，也不是人类认知研究导出的最佳值。超长时拒绝整份更新、保留旧版并给出简短反馈，不从尾部硬截断否定条件。无变化不增加工作区版本或持久化写入。

### 三类引用必须区分

- **关注引用**：模型想在下一轮展开什么，可增可减，不代表相信。
- **披露依赖**：这份派生记录可能含有哪些受权限约束的来源内容，不能因失去关注而删除。
- **执行回执**：真实动作的状态，不是模型所写“完成”的证据替身。

首版无需依赖图。更新记录时，Host 可保守继承前版披露依赖并加入本轮实际提供的来源；不更新则沿用原依赖。保守集合不证明语义支持，但避免只检查 `focus_refs` 后泄露已经写入正文的旧材料。外部文件、Note 与 Evidence 用各自原有资格路径，不伪装成同一种 ID。

## 4. 两个钩子与单次决策

```text
原 Host 获得用户要求、工具结果或外部观察
  → before_model：插入可错工作记录，按配置展开引用
  → 正常模型调用一次：可选工作区更新 + 原动作/回答
  → after_model：机械接收工作产物，拆出原动作
  → 原 Host 校验与派发，保存真实结果
  → 下一轮；真实结果有机会纠正旧记录
```

### 4.1 `before_model`：不让旧焦点挡住新事实

保留原任务、授权消息的角色和顺序。工作记录作为明确标识的可错数据进入固定插槽，不作为高优先级指令。政策来自受控配置，不从 Note 中加载；原文中的指令也不能经工作区转写获得更高权限。

必须保留本轮新观察、最近一组完整 action/result、未结操作状态以及工具协议要求的消息配对。新观察不能因旧 State 的“不相关”判断被过滤。大结果沿用当前合法分页，显示部分覆盖与继续入口；部分可见不能被包装成完整呈现。

材料展开复用来源接口和发送前资格检查。只有实际发送得到相应确认，才记录呈现回执；`assembled`、`acquired`、`presented` 分别记录，不把任何一个标为“模型已经理解”。

### 4.2 `after_model`：更新与执行互不冒充

本版使用与当前 Lab 思路一致的响应外壳：

```json
{
  "work_update": null,
  "action": "原动作名称",
  "arguments": {}
}
```

这里是设计示意。`action/arguments` 仍由当前任务合同定义，最终回答也沿用原交付形式；工作区内容不得混进业务参数。所有比较臂使用同一个外壳，都允许输出工作记录。嵌套对象有本地格式合同，不等于新增 Runtime 语义 Schema。

先解析完整响应，再分别验证工作产物与原动作。工作产物只检查类型、容量、引用和绑定；不认证“已验证”“已完成”等语义。合格动作仍按原合同执行一次，不因工作产物不合格而改写业务值、增加权限或重复动作。

若完整 JSON 不可解析，无法可靠分离动作，则不派发；不从坏消息中猜测可执行片段。若只有工作产物不合格而动作能独立验证，丢弃该更新，保留原工作区，正常处理动作，并在下一次已有决策机会反馈一次问题。不另起修复模型，也不自动重放成功的业务操作。

旧 `work_update` 完整保留在逐轮档案，但普通历史只回放原动作与真实结果，不逐版重复发送旧工作记录。给业务动作单列输出预留量，可选记录不能占用该预留；生成上限包含动作、记录和外壳余量，记录可为 null。预算配置不保证模型不会截断，完整响应不足仍不猜测动作，也不自动重试。

新记录是截至本次输入的判断与计划，不包含本次尚未执行的结果。Host 保留“先于哪个 action/result 生成”的机械位置，下一轮把真实回执单独呈现。模型若提前写了 DONE，应作为错误记录观察；不能靠 Host 语义改写掩盖它。

### 4.3 同调用能力不能靠设计宣告通过

当前已有 `review + action` 的本地代码先例，但新外壳仍需一个邻近的解析测试和小型真实 HTTP 冒烟验证。沿用可用的 Provider 输出方式，保留后验完整校验，不新建复杂 regex/decoder 调参工程。

若某 Host 只能通过独立 `state_update` 工具来更新，记录真实额外交互，作为另一实现条件；首版不同时开发所有兼容层。若新外壳反复不稳定，先缩小输出形式或回退到同调用短工作文本，不重建准入平台。

## 5. 政策正文与真正的算法差异

建议初版政策如下；它可替换，不承担权限或评分功能。

```text
工作记录是可错的续接材料，不是事实或授权的权威。

围绕当前会改变下一步选择的不确定性工作。已有材料足够时先使用；
需要调查时优先选择能区分主要解释的检查，不为了发散而增加查询。
初步阅读接口、复现症状、了解材料分布也可以是合理步骤，不要求先有两个假设。

只在依据、适用范围、暂缓原因或返回入口发生有用变化时更新短记录。
需要时可以保留尚未验证、但可能改变问题理解的新线索；暂时不能证明其价值，
不等于必须丢弃。保留线索不自动获得调查优先权，也不构成结论。

必要条件失效，停止沿用；阻塞消失，仅触发重新检查；
当前依据充分且符合任务，才重新采用。新证据也可以揭示未预先记录的风险。
被证实错误的内容应更正，不应全部保留成以后再用的路线。

只记录已经收到的结果。动作未执行只能写计划；没有有用变化可以不更新。
证据不足时使用合法查询、试验或澄清；停止不等于证明完成。
```

关键变化不是增加标题，而是让上一轮记录参与下一轮的复核、取材和动作选择。代码保证记录确实输入，不能保证模型一定使用；行为变化需要实验测量。只证明“提示存在”或“State 已写入”不算机制生效。

不要求输出长理由、全链推演或隐含思维过程。记录只服务于后续行动所需的可见依据、未决项和返回入口。

程序只处理输入、引用、容量、消息完整性及动作交接。不按关键词、固定无进展次数或 State 的 DONE 字样推导暂停、恢复、完成；不强制分支数。政策和任务都可修改，评价不奖励指定标题或机制术语。

## 6. 工作集管理：真正改变输入，但不混淆贡献

提供两个本地配置，使用同一套钩子，不开发两套系统。

| 模式 | 材料处理 | 可以回答什么 |
| --- | --- | --- |
| `MANAGED_WORKSET` | 保留受保护输入、短记录与近期完整交互；旧材料正文按上一轮 focus_refs 展开，未选正文不自动重发 | 记录政策与实际工作集管理的组合是否有价值 |
| `COMMON_CONTEXT` | 在固定轨迹或受控回放中提供共同任务/证据；记录 focus_refs，但不让它改变材料 | 分离选材影响后，记录形成或使用政策是否仍有价值 |

### 6.1 单一组装器的输入边界

```text
本轮请求 = 原有可信目标/有效约束/工具合同
         + 当前可错工作记录
         + 本轮新观察及未结操作状态
         + 最近 K 组完整 action/result 交互
         + focus_refs 选中的历史片段
```

开发起点可取 K=2，按任务容量配置；这不是固定认知规律。已包含在近期窗口的相同来源/版本/范围不重复展开。近期窗口外未选中的正文保留在原记录中，通过既有合法读取能力仍可恢复，不在下一轮自动全量重发。

用户当前要求、有效授权和新观察不参加模型的淘汰选择；尚未结算的动作及协议必需配对也不因超过 K 被丢弃。组装按原角色和完整消息组操作，不能仅删一个 tool result 或留下孤立 tool call。若选定 Host 的消息合同不允许这种重组，该接线不能声称支持 managed workset；先采用其合法的完整消息组边界，不去改 Provider 或 Runtime 协议。

引用按模型所给顺序在剩余容量内展开；放不下的正文延后并显示原因/继续入口，不临时由第二模型排序或摘要。受保护输入本身超限时沿用已有合法分页或显式停止，不靠隐蔽删除最新证据腾空间。呈现摘要只需记录选中、实际展开、未展开的句柄及范围；不把全部历史元数据再次堆进每个请求。

Host 必须保留一个原有的历史索引/读取入口，使不在 focus_refs 中的路线仍能被重新找到。小任务可以直接提供有界中性材料目录；大任务沿用既有分页目录或 search/read，不要求扫描全文。目录不能含 gold、预期暂停/恢复标签或实验者给出的语义优先级。

这里的“移出”仅指不再自动展开正文，不是删除原始事件、修改事实地位或注销路线。模型可以重新选择旧句柄，也可以使用普通工具读未选材料。空 focus_refs 表示暂不额外展开，不表示没有其他证据；已读过也不构成永久屏蔽。

### 6.2 只做选择性呈现，不额外建设 folding 引擎

首版不做历史摘要替换、多层压缩树或分支图。短 text 已经是同一次正常决策产生的工作产物，原文仍可查。focus_refs 的变更足以让下一轮材料集合变化，不需要新增组件来实现“真正生效”。

三种政策在 managed 模式下都有相同的引用选择、历史读取和工作区更新能力，不能只有候选拥有选材权。它们可能选出不同材料，这是组合行为结果而非共同输入实验。自由交互中，不同动作也会产生不同观察；只有固定轨迹/回放或实际核对相同的输入才可称“共同材料”，不能只凭组装器相同就这样标注。

`focus_refs` 只作用于下一轮，不能为本轮尚未取得的事实提供依据。并发只读仍允许；先前真实写入不会因认知分支切换而回滚。

## 7. 持久化与恢复：现有接口足够，但不是首轮探索前提

第一步只使用 Host 内存和既有逐轮记录，验证跨步骤的控制作用。它应称为 `IN_PROCESS_WORKSPACE_POLICY`，不能称为已验证跨会话长期记忆。

需要真实续接时优先使用公开 TASK Working State，不每轮额外写一份 Note：

1. 在已有中断、交接或压缩边界保存工作区，Host 附加可信绑定、确切版本和 operation_id。
2. 新 Host 重新建立当前身份与任务绑定，通过公开 GET 恢复，原用户要求单独读取。
3. 从可用的原观察记录定位 checkpoint 之后的工具结果或未结操作；没有可靠记录时重新查询当前世界，不声称无损恢复。
4. 当前材料资格重新核对；来源失效、过期、撤销或版本改变均显式处理。随后让同一个 Host 决定旧记录是否仍适用。

持久化外壳使用 Host 自己的 payload 命名空间，例如 `workspace_policy_v1`，不占用现有 task identity 或 StateDelta 的字段含义。读取现有 head 后只机械替换自己拥有的命名空间，保留其他 Host 内容及披露依赖，再执行现有完整 payload CAS；不得因插件保存而抹掉原 Working State。开发实验优先使用独立任务绑定。命名空间版本是 Host 载体格式，不是 Runtime 新语义对象。

当前 Working State 是任意 JSON、完整替换、exact CAS，权限为 `HOST_WORKING`；payload 上限 65,536 bytes，声明的 Evidence 引用上限 1,024。SESSION/TASK/PROJECT TTL 分别为 24 小时/30 天/365 天。不能用它承诺无限期持久化，也不能为避开过期偷偷切到 PROJECT。参见 [ADR-034](../../../MiLAi-Product/docs/adr/ADR-034-host-cognitive-affordance-layer.md)、[实际模型](../../../MiLAi-Product/runtime/src/milai/domain/host_cognitive_state.py)。

读取时，已撤销/不可读的声明 Evidence 会导致整个 payload 被隐藏。`payload_withheld` 不是空工作区，更不是删除授权；不得拿缓存正文绕过。Runtime 只识别既有保留引用合同，Host 外部文件或独立 Note 的派生披露仍由原公开接口及可信 Host 资格路径负责。参见 [ADR-040](../../../MiLAi-Product/docs/adr/ADR-040-working-state-payload-fidelity.md)、[ADR-041](../../../MiLAi-Product/docs/adr/ADR-041-working-state-disclosure-on-stale-references.md)。

如需长期独立归档，可明确使用普通 Note；现有 Note 没有自动 TTL，但不自动继承或替代任务 checkpoint。首版不实现双写。来源依赖超出既有上限时不能静默删掉引用；保留可支持的本地工作或明确不保存，不扩 Runtime 容量来支撑首次探索。

“观察位置”仅说明哪些输入已发送、哪个结果尚待下一轮处理，不证明这些事实已被记录吸收。事件日志也不等于任意全文材料库；引用必须能定位到合法可读的内容。

## 8. 失败处理要简短且可用

| 问题 | 首版处理 |
| --- | --- |
| 文本超长、未知引用、更新版本不匹配 | 保留上一份有效工作区，简短反馈；不另起模型修复 |
| 引用变更、撤销或失去权限 | 不继续披露旧正文或其受限派生记录；按原资格路径重新取得或显示不可用 |
| checkpoint CAS 冲突 | 公开读取当前 head；首版单写者不自动语义合并，不覆盖其他 Host |
| checkpoint/业务提交结果未知 | 按原 operation/receipt 合同核对；不生成新 ID 重复提交，不声称完成 |
| checkpoint 保存失败但业务成功 | 分别报告；可继续的当前会话与“可冷恢复”承诺分开，不重执行业务 |
| Provider 超时、用量未知 | 保留尝试与未知用量，沿用现有停发/核账规则，不隐藏重试 |
| 新记录语义错误 | 当前观察继续可见，由 Host 修订；计为候选失败，不让 Runtime 代替纠正 |
| 插件反复拖累任务 | 关闭插件、回到原 Host；保留该次失败，不再叠加 Reviewer |

工作区可用性降级不意味着放宽动作授权。涉及来源权限、动作完整性或未知副作用时，继续沿用原来的安全停止；只是不把可选记录的格式错误升级成整套重复执行。

## 9. 最小开发落点

最小实现限定在以下路径；具体已实现能力和未接入部分由开发记录说明。

| 落点 | 内容 |
| --- | --- |
| `src/milai_lab/methods/workspace_policy.py` | 小工作区对象、更新接收、引用选择协议、输入组装的纯逻辑 |
| `configs/policies/workspace/` | 普通 Note、普通 review、候选三份可替换政策 |
| `tools/workspace_policy_host.py` | 把两个钩子接到一个选定的现有 Host/provider/source 路径；不新建服务或通用框架 |
| 邻近 unit / integration tests | 只覆盖新插槽、时序、引用、失败回退及一次实际循环 |

Lab 包不能直接 import `milai_client` 或 Runtime。纯逻辑使用小协议/回调；公开 SDK 接线放在 Lab `tools/` 边界，沿用当前隔离方式。产品代码和所有旧实验原型保持原样，避免重新解释旧实验处理。参见 [Lab 边界](../../AGENTS.md)。

初版不引入 LangChain 作为新依赖。两处钩子只是本地函数；未来接 LangGraph 等 Host 时再映射其生命周期。也不同时开发六个适配器、自动维护器、关联图、触发器 DSL 或学习策略。

## 10. 验证与探索：先有可观察的处理差异

### 10.1 先用很少的工程检查证明接线

用可控响应验证：上一轮更新进入下一轮；null 保留；新观察不受焦点过滤；切换 focus_refs 后旧正文退出、新选正文进入下一请求且原文仍可读；完整 action/result 配对不被破坏；工作区错误不重放动作；计划不覆盖真实回执；关插件恢复原行为。随后仅对新输出外壳做小型 HTTP 冒烟。调用、来源读取和真实发送分开计账。

不继承整套 admission 扫描、全量历史哈希或 A—E 矩阵作为前提。复用已有机械边界，在新变更处测试；文档定稿不跑全仓回归。若开发同时变更共享产品边界，再按该变更风险补相应测试。

### 10.2 三个政策从第一天并列

| 臂 | 记录与使用政策 |
| --- | --- |
| `NOTE` | 普通自由记录，可自然记条件、未决项、下一步，也可以不更新 |
| `REVIEW` | 同一次正常调用中，结合当前证据复核旧记录再行动；不强制额外 Agent |
| `REGULATED` | 本文依据驱动的保留—暂缓—复查政策 |

三臂共享模型、动作机会、工具能力、工作区容量、近期窗口规则和响应外壳；都可更新 text 与 focus_refs。可以直接在 `MANAGED_WORKSET` 中做组合探索，再用 `COMMON_CONTEXT`、固定轨迹回放或同信息对照定位贡献；也可按当前诊断需要先做共同材料，不设必经顺序。不同政策可以产生不同工作记录并独立发展，不能互相偷取答案。R1 不被人为加昂贵额外调用，普通 Note 不被禁止写关系或条件。

首批用两个不同工作任务、每题三臂，形成六条开发轨迹；初始工作区为空，由模型自行形成记录，不另设“必须自然写出合格 Note”门。一个任务侧重证据诊断续接，另一个侧重实现/维护中的历史判断复用，不要求每题包揽稳定、变化、恢复和干扰。按各任务正常完成需要设置共同步骤上限，不固定五轮，也不再把六轨迹写成固定 30 次生成。实际运行前明确步骤与资源；本文件不分配请求。

六条是起步安排，不是每次迭代必须跑满的矩阵。一个任务先可用就先调试；效果判断保留同任务公平对照。接线失败可停止受影响轨迹，修复后另留版本；调试、未运行和未配对项如实记录。根据任务实际出现的跨步依赖、稳定、变化或返回机会观察，不要求首批覆盖全部机制类型。

允许使用已知旧记录或小型构造世界，明确标为 controlled discovery，不能冒充自主 Note/真实持久化。也可直接用已有外部任务，前提是处理变量和行为答案清楚。每步重新提供全部答案所需事实的简单 A→B→A，只能测条件推理；要研究跨步记录，需要有早期观察/已排除尝试的复用机会，同时让各臂拥有相同的合法历史访问能力。

环境只提供事实和合法动作，不提示“现在 park/recover”。相关选择自然存在时，按真实结果判断它是否适用；不强制制造错误路线或返回流程。把业务选择与参数/权限拒绝分开记录。

### 10.3 先看行为，不只看最后答对

按实际机会记录错误沿用、不必要切换、重复工作、首次错误动作和最终任务结果；条件变化后，观察能否重新评估旧路线，并作出符合当前目标的采用或不采用决定。提出未证实的解释不等于将它采信为事实。无依据采信按可见行为与证据判断，不能依据模型自报“我受旧记忆影响”作因果结论。

条件重激活与错误恢复分开：A→B→A 可以全程正确；Recovery 必须先有错误，再有足够纠正机会。成本覆盖记录输入输出、引用展开、读写、失败与重试、延迟；不把同一个模型误说成没有额外 token，不设模型 Judge 作为首轮默认依赖。

### 10.4 有信号后只拆最有信息量的部分

- **同信息普通 review**：只移交当时已产生的记录内容，不提供未来信息。若打平，说明特殊消费规则未显示额外价值；仍可研究记录形成的价值，但必须计入形成成本，不把此消融当免费生命周期 baseline。
- **去掉复查入口**：检查它对正确重激活是否必要。
- **不继承上一份工作记录**：检查效果是否其实来自每轮普通提示。若历史中仍有旧全文，明确它不是彻底无状态消融。
- **材料展开开关**：用相同政策比较固定材料与 focus_refs 展开；这估计的是选材增量，不偷换成 State 独立效应。

不要求四种消融全部先跑完才允许修改候选。探索允许换任务、提示、记录容量和组合；保存版本、真实输入输出及修改理由，失败不得覆盖。若要主张可重复优于 baseline，再冻结候选和强简单对手，使用未参与调试的独立任务。跨会话公开持久化放在这之后验证，不成为第一天的入口障碍。

开发打平先区分：任务没有产生相关需要、处理没有实际启用、或有机会却无净收益。这限制当前主张，不自动否定整个方向；也不能把每个负结果都解释成任务不合适。有具体可检验的新解释才修改，没有就暂停该版本并保留简单方案。只在选材模式赢就报告选材/组合收益；只在构造规则题有效就保留局部结果。不用更大的 benchmark/Judge 成本掩盖没有政策差异的问题。

## 11. 可借鉴结构与创新边界

官方 LangChain 文档提供 before/after/wrap 生命周期钩子，说明这种集成位置已有通用形式；本版不因借用形式而引入其框架。[官方 middleware 文档](https://docs.langchain.com/oss/python/langchain/middleware/custom)。

AgentFold 已将上下文管理指令与下一动作放在同一次响应中，并通过训练获得该行为；本版可借其执行结构，但不能据此保证普通模型仅靠提示就可靠，更不能把“同调用管理上下文”当新颖性。[AgentFold 论文 §3.3–3.4](https://arxiv.org/html/2510.24699v1)。

HiAgent 已用子目标组织工作记忆、摘要既往工作并保留当前相关交互；工作分层本身不是本版独有贡献。[HiAgent 论文](https://arxiv.org/abs/2408.09559)。

首次设计只核对上述与首版实现直接相关的公开资料，未做新的完整 prior-art 排除或外部方法复现。AdaptiveMem、CUPMem、TEPA、MemR³ 等仍按候选实际操作差异选择对照；不能因为“自由文本、Host-owned、没有图”就宣布创新。首轮不为了外部 baseline 新接一组记忆系统。

真正待验证的主张只有：**同样的可用材料与资源下，最小的记录形成/修订/使用循环，是否比普通记录和普通复核少犯旧方向错误、少重复工作，并保持正确的稳定与重新采用。**

## 12. 交付与停止范围

开发交付以可开关原型、三份政策、邻近测试和能决定下一次改哪里的记录为主；六轨迹可逐任务推进，不把填满表格当完成标准。工作区和选材都可以关闭；不删除已有 Note、不迁移 Schema、不接管默认 Host。

遇到问题允许改变实现与政策，但先问它是否影响正在测量的决策规则，再改最小范围。输出格式不稳定，不开发第二个 Agent 来补；来源取得成为主失败，不把它叫记忆惯性；普通复核足够，不强选复杂候选。

研究收益、产品集成和发布是三件独立的事。本次进入本地原型开发；新增模型/Provider/Product 请求为 0，未更改任何运行中的服务，未追认未知用量，也不由 CPU 接线测试签发实验效果结论。
