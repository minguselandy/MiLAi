## 1. 主目标、研究门槛与非目标

目标：先建立可负担、可审计的执行工作点，再用普通 Note 与普通 review 找到可靠的 Memory-use 行为边界；只有强简单方案仍不足，才探索最小调控机制。

必须区分两个门：

| 门 | 要证明什么 | 不要求什么 |
| --- | --- | --- |
| Memory 问题发现 | 当前任务本来可完成，加入过去正确的 Note 后出现方向明确、可追溯的错误影响 | 不要求 ordinary review 也失败 |
| 机制必要性/价值 | 候选超过强简单 review、适用性提醒与相关公开方法，或可靠性不降且完整生命周期成本更低 | 不要求复杂 State 必须胜出，也不要求准确率成为唯一收益 |

`N0 正确 / N1 stale-wrong / R1 正确` 可以支持局部 Note 消费问题，但同时支持先使用普通复核；不是 State 创新成绩。
Gate D 的无旧 Note 能力校准，与 Gate E 的有旧 Note 处理比较分开。不能把“R1 在所有 Memory 条件必须正确”设为 E 的进入条件，再要求候选在同一批准确率上超过它。

优先研究问题是：**旧经验仍有历史价值，但当前条件暂不适用时，能否停止照搬；条件恢复后，能否重新利用，而非永久遗忘？**
这只是优先假设，不是预定算法。association、conditional reactivation、stability–plasticity、memory–world consistency、meta-memory 继续开放，允许证据改变优先级。

非目标：不新增 Runtime 语义裁决、不新增 Canonical 权威或业务 State schema、不做 context projection、不换 Memory Store、不训练模型、不一次接入多个外部系统、不把 receipt/CAS/readback 工程改进包装为记忆机制。

## 2. 最小路线与资源释放

```text
A 真实规模冷准入与余量
  → B 新正式 P3 16/16
  → C P4 24/24
  → D 去掉意图 Oracle 后的自然任务与恢复能力
  → E 普通 N0 / N1 / R1 的最多 24 个冷恢复会话
  → 有界结论：KEEP SIMPLE / 有效性不足 / 值得探索的局部问题
  → 仅条件满足时另开机制探索与独立确认
```

只规划两项执行工作包：W-A 有界执行恢复，W-E 等待准入的三臂小试。B/C/D 是两者之间不可跳过的资格链，不是省略的工作，也不因本文自动获得调用额度。

| 阶段 | 通过要求/建议规模 | 放行依据 |
| --- | --- | --- |
| A | 当前合同的真实规模、完整冷链、动态负控和量化余量 | 当前有效 A revision 与 terminal 证据 |
| B | 4 已开放 roots × full/finish × 2 遍 = 16/16 新位置 | A PASS + 新 scope + 明确 HTTP 范围 |
| C | 4 roots × 3 路径 × 2 遍 = 24/24 新链；≤96 次生成 | 同一兼容栈 B PASS |
| D | 每根恢复与自然能力合格；至少 2 roots / 2 families | 去 Oracle 的新任务合同与逐 root 证书 |
| E 提案 | 2 families × 2 独立 roots × 2 世界 × 3 臂 = 24 B；另≤4 A | **4 个实际合格根**、自然 Note 与 E0 机械/呈现资格 |
| 后继机制/确认 | 本文分配 0 | 单独的候选、范围、停止条件与新授权 |

所有“计划上界”不是当前 allocation。累计 raw-token 硬上限保持未设；单请求/会话/阶段时限、调用次数、并发、服务和未知用量停止条件仍需冻结。

## 3. W-A / Gate A：有界恢复，不继续横向扩建

### 3.1 当前合同不能被研究建议追溯替换

当前 R04 按其既有合同验收。本文不把建议的“20 次测量”替代已经要求的完整 40 冷进程，也不把原 18 秒准入并集门放宽成 30 秒或“只要不到 60 秒”。
R03 已采用单列的静态证据 authority 合同；不得把不同 authority 模型的结果称作无差异的加速。R04 的同 scope 去重也不能扩张成跨 scope 的 PASS 缓存。

如果当前工作点仍失败，需要另开恢复任务时，建议前瞻绑定**最多两轮测量—最小修正—复测**；轮次跨该任务的 revision 累计，不能每换版本就归零。
本提案不自动增加这两轮。达到边界且没有可用余量，交付 testbed 简化方案、保证差异和代价，停止该合同下的效果实验；研究方向本身不因此判无效。

### 3.2 测量与修正合同

- 使用粗粒度 monotonic wall-clock spans：scope、文件 stat/read/hash、JSON/JSONL parse、history reconstruction、SQL/ledger、最终 revalidation、进程启动/等待/退出。
- 报告 inclusive、exclusive、重叠并集与总墙钟未归因余量；父子 spans 不能简单相加。不用全函数 profiler 的倍率倒扣真实运行时间。
- 固定实际规模：55-scope 历史失败前缀、57 ledgers、当前精确文件/字节/依赖闭包；同时测完整成功路径，不能以失败前缀替代终态成本。
- 基于测到的主成本项只修一个最小差异；优先删除重复计算，不预设 cache、新 adapter 或新审计层是答案。
- 不变数据的复用必须有明确定义的不可变边界、来源绑定、失效规则和竞争修改反例。authorization、CAS/head、operation/receipt、world version、动态 scope、stop 状态在适用边界始终 fresh。
- 预计算、封包、准备、批准等待和父收口分别列出并计入所属生命周期；不把成本移出计时区再声称消失。

如采纳新的 20 次复测建议，须在运行前冻结身份/顺序、fresh process、batch-cold/Host-cold/warm 口径、资源上界与所有超时的保留规则。报告逐次、中位数、最大值；不以 20 次估计生产 P95/SLA。
若拟与完整 40 冷进程共用数据，必须在发送/计时前证明两者测量单元相同并明确映射，不能跑完后选最快的 20 次。

### 3.3 余量与反例

继续满足现行硬门，并增加可解释的资源分账：

```text
admission union + generation reserve + execution/readback reserve + margin
    ≤ 原 60 秒 reference Session 合同
```

reserve 来自已有可核验记录及保守假设，在新的复测前冻结；资料不足记 UNKNOWN，不能伪造延迟分布。CPU mock 不能证明真实 HTTP 余量必然足够。

至少测试权限撤销、world/head 变化、操作已完成、重复提交、动态 scope 变化、静态输入被修改、收口超时。既测试正确动作，也测试 Schema 合法但业务目标/值错误的动作。
语义首因、完整输入闭包、账务、动态检查不能因提速弱化；authority 改变必须显式作为新实验合同，旧门不追认。

交付仅需：一份成本表、一份最小差异与负控、一份真实规模 terminal/余量结论；原始证据链接出去，不继续追加多层框架。

## 4. Gate B / C：严格恢复意图与执行有效性

### Gate B — P3

沿用经诊断选定的 B1+D11 作为起点，冻结新实例。保持合法来源、完整对象集合和目标值；不得用 enum/const 偷塞唯一正确业务答案。
每位置依次验证：HTTP 与用量结算 → strict JSON → 完整后验 Schema → 完整授权目标和值/finish → CAS/envelope → deadline 内 parent acceptance。
full 8/8、finish 8/8，合计16/16。无业务写入；一次非预期失败按正式合同停止，未运行项保留。不能拼接旧12个 PASS或多 revision 的最好结果。

### Gate C — P4

四根、三路径、两冷遍，24条链全部通过。链级目标为：

```text
known intent → original encoding → trusted identity binding → dispatch
→ CAS/idempotency → receipt → independent world readback → valid finish
```

身份由可信 Host 绑定；模型形成业务 payload。harness 不修正错误值，不用私有答案充当恢复提示；业务完成与 Note 保存彻底分开。
≤4次生成/链，≤96次；80参考请求不是实际调用上限。未知提交先做公开只读状态核验，不猜测无副作用并重试。
24/24 只建立 known-intent execution 工作点，不建立自然任务或 Memory 成绩。

## 5. Gate D：没有旧 Note 时，从证据自然形成正确动作

1. D0 去掉 INTENT_ORACLE、evaluator 正确目标/值/下一步；只保留正常任务、授权范围、公开 Schema 和可观察证据。
2. 零模型确认合法但错误的动作可以进入隔离世界并被独立 checker 判错；不能由隐藏 gold guard 在业务派发前纠正。
3. D1 每根验证“仅版本变”与“版本及业务适用条件都变”，各两冷遍。拒绝必须实际发生、无副作用、可读机器错误；正确恢复或保持未决，不只机械加 version。
4. D2 采用无继承 Note 的 N0-exec/R0-exec；同任务、来源、工具与预算，每政策两冷遍。每根4/4自然业务 PASS，且其 D1 合格，才获局部任务证书。
5. 至少两根两 family 才有最低 `G_TASK_READY`；这**不等于**本提案 E 所需的四个独立根已经齐备。

每个 E root 的 Stable/Changed 具体条件都须在 Note 处理结果出现前证明相应无旧 Note 能力，不借同 family 的别根证书。新世界/来源/任务变化触发最小增量校准。
原 D1/D2 规划最多4根、80/256次生成；若现有已开放根无法形成“两 family 各两根”，先提出新的 D 范围和额度，不能改 lineage 名称凑足数量、也不能直接启用 C。

协议、取得、呈现和一般理解失败分别记录。重复同一未恢复协议错误按冻结规则收口；执行有效性失守时停止效果归因，不能把更多错误填入 Memory 分母。

## 6. W-E / Gate E：4 根、24 个 B 会话的三臂小试

### 6.1 与原 Goal 的明确差异

| 项目 | v0.1 规划 | 本提案 |
| --- | --- | --- |
| 独立 root | 2根，覆盖2 family | 4根，2 family 各2根 |
| 冷 B | 2根×2世界×3臂×2重复 =24 | 4根×2世界×3臂×1 =24 |
| 波次 | 同两根完整冷复验 | 每波两 family 各一新根，共12 B；两波最多24 B |
| 自然 A | 最多4个候选，选首两个合格根 | 最多4个冻结根，各一个 A，不事后补根 |
| 独立单位 | 2 | 4，不是24 |

本提案用任务异质性替代首批同根重复；不能同时声称取得了两遍复现。若需要冷重复，须另列新有界合同和成本。
所有四根和波次顺序须在首个 A 输出前固定。每根无 Note/错 Note/提交不明，都保留；不得反复生成、手工修 Note 或替换根来凑“4个有效”。
可按预注册有效性停止规则提前结束；所有未运行项为 NOT_RUN，完整目标未达到时不能仅凭已有12个会话宣称24会话试验完成。

### 6.2 研究问题与三个臂

本轮当前证据足够支持 N0 完成任务，主要测试 Note 的错误影响，不声称覆盖长期记忆全部收益。

| 臂 | 处理 |
| --- | --- |
| N0 | 不呈现 A 的工作 Note；同一历史来源和当前证据仍合法可查 |
| N1 | 与 N0 同一普通执行政策，加上公开冷读取的 A Note |
| R1 | 与 N1 同一 Note 版本和当前材料，加一个领域无关的普通复核要求 |

R1 默认在**同一次正常决策调用**中复核，不强制额外调用或第二个 Agent；允许模型在共有机会预算内自然读取/行动。实际花费仍完整计入。
可在开发冻结时使用普通表述：“结合当前任务检查旧记录哪些仍有依据、哪些不再适用、哪些尚不确定，再完成任务；不要自动沿用，也不要无故丢弃仍适用的经验。”
不能根据单题错误为 R1 添加具体实体/关系/正确方向；R1 不强制“新的一定优于旧的”。

N0/N1 的差异首先是提供该 Note 的整体效应，包含文本负荷；不能自动把每个新增错误都解释为认知惯性。
R1−N1 首先是普通使用政策的效应，不是特定 State 表示的收益。

### 6.3 形成曾经正确的真实记忆

- evaluator 在 A 前冻结 t0、未来 Stable/Changed 世界及 action-level checker；未来事件和答案不进入 A。
- A 正常工作并由独立 readback 验证业务效果；Agent 自主决定保存哪些有复用价值的信息。允许全根相同的收尾提示，不代写目标命题。
- Note 必须经已准入公共接口提交；操作/回执/ID/版本/原始内容绑定。离线核验与后续行动有关的命题在 t0 有依据、适用范围明确可判。
- 暂定假设可如实记录为暂定，但不能把“曾记下猜想”当“猜想曾正确”。混合错误、NO_WRITE、未知提交都属于机会/质量缺口。
- 不让未来正确答案反向决定 A 写什么，不对 evaluator 不喜欢的 Note 反复重试。

### 6.4 世界、冷边界与行为真值

每根产生 Stable 与 Changed 两个分支。Changed 的子类型在运行前固定为事实 supersession 或条件 applicability shift，分开报告；不能将“事实仍真但当前不适用”统称为假事实。
优先复用现有 testbed 中配置/依赖适用性、完成状态失效/回滚等可验真家族；这些是候选任务形态，不是已经拥有四根合格任务的声明。

三个臂在同一分支使用相同世界初态、当前合法来源和实际呈现内容，分离业务 scope 和所有新写入。相同自然 A 产物用于 N1/R1，不能各生成一份。
新 Host/模型上下文只通过公开接口冷读，不复制 A 的隐藏状态或未提交轨迹。若采用 harness 公共预取，诚实标为 `CONTROLLED_CONSUMPTION / PUBLIC_PREFETCH`，不声称自主召回已经成立。
没有 gold 选源、按答案截取或语义 projection；冻结的公共来源呈现规则保持两侧事实可达。
关联 commit → public read → assembled request → actual wire 的 hash/bytes，分别证明 Note 与当前必要证据真正送达。
原 commit 冷读与公开派生 Note 副本分开标注，不能以同内容冒称同 ID 原始持久化。

checker 用实际世界 postcondition、授权副作用、完整对象状态和独立 readback 判定；合法但错误的动作仍计错。文字说“已修正/已完成”、Note 写入或 tool accepted 都不代替业务效果。

### 6.5 有界执行与两波规则

最多4 A +24 B =28 episodes。若沿用 Gate D 已验证的每 episode≤16生成，则最多448生成；这是容量规划，不是当前许可，更不是24次调用。
前置 Note 增量校准、Provider/tokenize/身份探针、模型 Judge、等长无关 Note 对照、再次冷重激活均不藏入448；需要时另冻范围，当前 allocation=0。
具体 episode/phase deadline、剩余输出预约与服务容量必须在发送前绑定；不能把建议900秒自动当成已经批准的期限。

波1包含两 family 各一个根。波2包含预定的另两根：

- 波1合同/账务/隔离/呈现/真值有效时，无论 N1 输赢，运行波2；不依据效果选择是否复制阳性。
- 有效性或安全失败，停止受影响批并反思；普通业务答错是数据，不自动停止全研究。
- 若无自然合格 Note、不能建立有效双呈现或公开隔离能力不足，按已冻结资格规则停止/标未运行；不从 C 补位。
- 任何合同修订都另开实例，不把新结果补进旧波矩阵。

### 6.6 分母、指标与结论

同时报告全候选、A尝试、业务成功、自选写入、正确命题、commit、冷公开读、Note实际呈现、当前支持实际呈现、全部B分配/尝试、有效配对、最终效果。
有效子集与全流程结果并列；分母0为 N/A。资格筛选与子集结果不能冒充总体无偏效应。

主指标分别为：首次相关行动/首次错误副作用、最终 World success、旧 Note 方向一致的 stale action、Stable无谓重做、修正机会数、实际恢复、全生命周期成本。
最终成功不能抹掉早期错误承诺；“读到 Note”不等于“Note 导致行动”。不索取或保存内部隐藏推理，使用可回放输入、工具行为、公开说明和对照。

| 配对现象 | 研究结论/下一步 |
| --- | --- |
| N0/N1/R1 都正确 | 当前条件未发现目标问题；KEEP SIMPLE，不立即加复杂度求阳性 |
| N0正确、N1旧方向错误、R1正确 | 局部可纠正消费问题；ordinary review 优先，非新机制证据 |
| N0正确、N1/R1均错 | 难例入口；先排除额外输入干扰、理解与适用性问题，不立即认定机制必要 |
| 各臂共错或执行链失守 | 返回最早可证实失败层；Memory归因INCONCLUSIVE |
| Note形成/双呈现未成立 | MEMORY_OPPORTUNITY_INSUFFICIENT；不能报告“惯性率0%” |

四根只够局部诊断。需要跨根重复和旧行动方向性才升级问题信号；可另设等长无关 Note 负控区分一般干扰，其额度和顺序必须前瞻确定。

## 7. Gate E 之后：强对照优先，机制保持开放

先比较本地 N1/R1，再按现象引入公开策略。已完成的[公开基线审计](MILA_V0224_PUBLIC_BASELINE_AUDIT_20260913.md)区分同输入政策、完整记忆系统和外部 benchmark，三类结果不可混用。

后续世界扩展分清：

- Helpful：记忆提供额外有效历史或显著降低重建成本；与当前证据足够的 harm 分母分开。
- Temporary applicability：条件 A→B→A，最后再次冷恢复，检验经验可以重新被利用。
- Recovery：确有错误行动后，又有充分纠正机会，检验能否修复；**不等同于**无先前错误的条件重激活。
- Irrelevant/Conflicting：不因表面相似或仅仅较新就错误推翻仍适用经验；Stable始终保留。
