## 固定设置与暴露边界

首组保持 `milai-rwc-v0.4`、`hiagent-method-adapter-v0.6`、`om-sync-port-v0.1` 不变。
任务是已暴露开发题 `multi-source-data-merger`，固定 Terminal-Bench 2 commit
`2fd12b88aafdd04a52c298e3940bcb189f9766d6`，任务文件与此前原生运行散列一致。
Harbor 0.23.0 使用独立 CPU 容器、原始 Dockerfile 的本地重建环境和原生 verifier；
不是官方预构建镜像排行榜复现。

三臂顺序在发送前固定为 SIMPLE → RWC → OM。每臂所有角色共用 32 次生成上限；
SIMPLE/RWC 的 feedback batch 为 3、可选交付复核上限为 1；OM 保留 12k/16k/recent2。
沿用 Qwen3.6-35B-A3B-FP8，窗口 65,536，temperature=0、top_p=1、seed=213、thinking=false。
Provider 实际报告版本 0.27.1；不假定相同解码参数会生成完全相同的轨迹。
Actor/Controller/摘要输出上限分别为 4096/2048/1024，OM 维护为 2048。

迁移候选 `git-multibranch`、`constraints-scheduling` 已在本版第一份模型结果前固定。
其任务入口、指令与 CPU Dockerfile 在本地存在；它们来自历史清单，只能称开发迁移。
迁移和续接包关闭未分配，不能将候选已选定写成迁移已完成。

### 可观察行为链

SIMPLE 首个脚本执行失败，随后重写并形成可解析产物。最后的 Frame 已要求交付，
Actor 仍追加了多次输出检查，直至 closing 调用才提交。该轨迹支持结束机会实际生效，
也暴露了重复验证；不能把额外检查都算作无用维护，或将预算保留归为特殊政策收益。

RWC 的 H006 回执列出了同值却被报告为冲突的条目，Controller 第 17 次调用指出此问题，
Frame 第 18 次调用促使 Actor 修改脚本。这是实际记录—行动联系；后续修复却引入
JSON 序列化失败，再次重写时丢失此前确认的输入映射，不能据前一段联系主张净收益。

第 29 次 Controller 输入包含新的 H010 执行失败及卡片目录；完整输入映射仍在
`card:1`，但只显示了截断预览，卡片正文未选入材料。原输出将中间 DataFrame 的缺列
推断成来源本身缺列，要求默认补空并广泛重写。旧依据并未被真实来源变化推翻。
这是本轮选定的 N1/N4 局部诊断点，不是 Host 丢失新反馈的工程故障。

两种 Workspace 方法均只出现一次 `CONTROL_DEFERRED`，其后频繁切换 subgoal，
触发摘要和提前维护。batch=3 在这些实际轨迹上没有形成每三步才维护的节奏；
没有同期 batch=1 对照，不量化批处理的净效应。RWC 另有两次控制输出被拒绝：
回读参数类型错误、指定未公布卡片。接受/拒绝次数均不作为语义质量分。

OM 的首次合并也遗漏了输出主键，随后自修并交付。12k 阈值自然触发两次 Observer，
没有 Reflector。第二份观察把来源中的用户 104 错记为 102，最终 Actor 输入中的
新原始回执仍保留正确四用户结果，final 没有跟随错误三用户摘要。
因此 OM 的原生成功也不能证明观察日志准确或长期记忆可靠。

## W2/W4：同一故障的两次局部形成—消费诊断

预先登记比较原政策与 `source_preserving_r1`：新失败涉及派生产物时，保留仍有依据的
输入属性，并先定位中间变换；修复应保留无关的已确认映射和约束。
规则不含任务 ID、具体字段、答案或隐藏测试要求。

固定原 RWC 第 29 次请求之前的真实前缀。离线重建逐项匹配 29 个请求输入和
10 条完全相同的执行动作回执，不重新调用模型生成前缀。之后仅为 Controller 和
共同 Actor 生成下一动作，所有新动作都不执行。各分支保持原检查点的剩余额度，
两分支的记录均由模型生成，不提供研究者编写的理想记录。

预测是依据保留/回读会改变下一动作；若只使记录变长、仍丢失已确认映射，或行动不变，
则不保留增量收益主张。这是记录形成与后续选材的组合诊断，不单独归因于 Actor 消费。
没有等价业务环境分叉，也不修改公开恢复绑定，诊断不填写原生成功分。

| 诊断与分支 | Controller → 共同 Actor 的实际结果 | 生成 | 输入 / 输出 tokens | 总 tokens |
| --- | --- | ---: | --- | ---: |
| D1 原政策 | 接受“来源缺列”解释；Actor 生成补空、重写脚本的命令 | 2 | 8,087 / 1,609 | 9,696 |
| D1 source_preserving_r1 | 记录仍推断来源缺列；Actor 改为重新查看源文件 | 2 | 8,254 / 352 | 8,606 |
| D2 原政策 | 再次接受“来源缺列”解释；Actor 再次生成补空、重写命令 | 2 | 8,110 / 1,724 | 9,834 |
| D2 record_lookup_r2 | 尝试 RECALL，但 refs 使用对象列表；整项更新被拒绝，Actor 改为重新查看源文件 | 2 | 8,125 / 368 | 8,493 |

D1 改变了下一动作，但未选择/回读已有完整映射记录，也未可靠区分原始来源与中间状态。
它只支持“更谨慎的重新探查”这一局部选择差异，不能称作记忆复用或端到端效率收益。

因此在运行前登记 D2：若新解释将替换旧输入判断，先核对未展示的已有记录正文，
不能从截断目录预览推断细节缺失。D2 的 Controller 使用了合同不接受的
`refs:[{ref,start,length}, ...]`，Actor 实际收到
`REJECTED_PREVIOUS_WORKSPACE_RETAINED / UNPUBLISHED_WORKSPACE_REFERENCE`。
它没有消费候选新记录或真实回读结果。Actor 的变化可能来自拒绝反馈，不能归为
候选记忆形成有效；这也不是语义规则已被干净否证的实验。没有第三次调词或补调用。

四个分支全部保留，每分支 1 次 Controller + 1 次 Actor，实际新增业务动作均为 0。
原 28 次前缀生成只在 W1 账中记一次，前缀重建是精确离线回放，不是免费生成。
各分支仍看到原检查点 4 次剩余额度，未给耗尽的原生候选补额度。
这些较短的下一动作输出没有包含完成重写/重查后的后续成本，不能用 token 差称效率收益。

## 覆盖、保留与停止决定

| 问题 | 本轮结论 |
| --- | --- |
| 工程可用性 | 真模型下 SIMPLE 的末次交付机会生效；RWC 最后仍要执行时得到诚实 INCOMPLETE。两者不是都正常完成。 |
| 完整 RWC 价值 | 本题未超过 SIMPLE 或 OM；当前工作点选择 OM，RWC 保持显式研究选项。 |
| N1 依据范围修订 | 有真实的历史输入依赖与新失败，候选没有稳妥保留并复用已确认映射；两次修订没有形成可推广的候选。 |
| N2 联想/投入/采信分离 | 卡片存在、未选正文可读，但没有合格的替代路线收益对照；目录与正文差异本身不证明机制价值。 |
| N3 可逆再判断 | 没有真实阻塞消失/旧路线返回机会；不建立分母，不报告 0% 成功率。 |
| N4 未决项到行动/交付 | 有“发现冲突问题→Frame→修改”的实际链，但后续修复失败，没有净完成收益。 |
| 贡献拆解 | D1 有下一选择变化；D2 被格式拒绝反馈混杂。未单独识别形成、Frame、连续继承的因果贡献。 |
| 迁移/新颖性 | 未执行迁移、续接或近邻正文/代码新增比对；不支持泛化或独立创新主张。 |

没有从两次诊断中选定可升级的 RWC 政策，故不把局部选择变化直接推到完整配对，
也不以寻找正面任务为由启动两道迁移题。未使用位置按原规划关闭，不转为第三次调词、
其他任务或新模型。保留 v0.4 / v0.6 现有代码及原政策，实验候选全文与失败在证据中留存。
这落实的是当前版本和开发投入选择，不要求 N1–N4 全部留下，也不声称方向已被否定。
