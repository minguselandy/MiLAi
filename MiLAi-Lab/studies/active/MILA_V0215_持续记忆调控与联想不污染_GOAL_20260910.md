## 1. 目标与本次修订

**以 State 为外部工作记忆的研究载体，开放探索记忆使用、注意力、联想、外部化、分支和
问题求解之间的关系；先发现值得解释的行为差异，再选择最简、最有增益、最有新颖性的
候选进入严格验证。不先指定哪一种机制必须成功。**

研究哲学：**先探索现象，再抽象机制；先允许组合出现，再消融简化；先发现什么有用，
再决定什么值得成为 MiLAi 的创新。** 工程仍为 supporting infrastructure，不退回工程完善主线。

## 2. State 是研究载体，不是预定算法

`S_t → memory-use policy → observable behavior` 是研究关系，不是需要实现的 Runtime 算法。
State 可以是一小段自然语言、自由 JSON 或普通笔记；也允许比较无显式 State 的简单方案。
不预设 `S=(goal,focus,candidates,branches,conditions)` 是最优结构，不要求六个模块齐备。

| 可变研究维度 | 可探索的问题 |
| --- | --- |
| 联想激活 | 词面、语义、时间、类比、反事实、旧失败路线中，哪些关联在什么时候有帮助？ |
| 注意力稳定性 | 新想法出现后保持当前焦点、切换或允许抢占，各自会带来什么行为？ |
| 工作记忆外部化 | 写目标、未决问题、候选、返回入口，还是不写？何时写比写什么更重要？ |
| 可逆分支 | 何时继续、暂存、恢复；软返回线索是否有用，错误线索能否被新观察推翻？ |
| 发散—收敛 | 固定或自选探索宽度、处理顺序与交付时机，何时减少固定思路或过度探索？ |
| 跨会话使用 | 什么只在当前会话有用，什么值得保存；恢复以后是否真的减少重复工作？ |
| Meta-memory | 关于“当前如何使用记忆、这种策略何时需要重核”的记录，是否改善实际行为？ |

这些是研究维度，不是待交付模块清单，也不是已证明的人类认知模型。
Host 解释和修订 State；Runtime 继续负责可信身份、权限、版本、CAS、提交与来源机械边界。
控制记录也是可错的低权威记忆，不能把“已解决/别再查/直接提交”升级为授权或来源过滤权威。

本 Goal 不新增 Product Store、MCP 工具、Runtime schema、Canonical 自动批准或默认维护政策。
不训练控制器，不部署公网；研究实现和评价归 Lab，Product-backed 试验只走固定公开接口。
默认复用单 Host 和已有组件；若探索涉及额外模型角色，必须在授权范围内显式登记、全额计量，
不能隐藏成免费的 Reviewer。候选策略不应依赖私有 Product helper 或 benchmark-specific routing。

合法来源保持可访问；本版仍不把语义 Context projection、裁剪反证或折叠历史作为研究机制。
正常按需读取不是 projection；不同探索 run 的真实输入可以不同，但必须记录差异。
记录的是外显工作产物、短状态、待证假设与工具行为，不要求导出完整隐式推理。

## 3. 文献核对与候选差异

以下保留 v0.1 于 2026-09-10 核对的近邻记录，本次不新增文献效果结论。
它是探索地图，不是候选准入白名单，也不是同条件复现或全面新颖性检索；
不将不同 benchmark 的论文分数与 MiLAi 小样本直接横比。

| 近邻 | v0.1 核对的覆盖范围 | 本 Goal 如何避免重复宽泛主张 |
| --- | --- | --- |
| [Remember When It Matters](https://arxiv.org/html/2607.08716v1) | 独立 Memory Agent 维护 bank，并选择提醒或保持沉默；含 full-bank、always-inject 等消融 | “主动/选择性记忆干预”不是新点；也不能把它描述为只读、不维护写入的机制 |
| [MemoBrain](https://arxiv.org/abs/2601.08079) | executive memory 组织依赖与中间进度，并管理工作上下文 | “执行记忆/认知控制”本身已有近邻；MiLAi 不将裁剪或折叠上下文作为干预 |
| [StateMem](https://arxiv.org/abs/2608.19652v1) | 显式跟踪 supersession、关系依赖，另有现成记忆系统 wrapper | “State 可更新/保留关系”不是新点；候选差异是控制判断及其可纠正使用 |
| [RuleMem](https://arxiv.org/abs/2609.03915v1) | 从历史归纳自然语言规则，指导取证与回答 | 不把“记忆规则指导推理”当核心差异 |
| [MEMO](https://arxiv.org/abs/2609.07471v1) | evidence extractor 与 query-conditioned manager 共同选择和组织文本/图像证据 | “按问题组织 evidence”不是新点；本版不把 carrier/layout/projection 作为研究机制 |
| [ReDNA](https://arxiv.org/html/2605.28465v1) | 分离发散生成与收敛选择，使用失败记忆；在交互任务上评价 | 不能只将发散/选择分开就称新；尤其不能只拿一个弱单查询方案作对照 |
| [DCR](https://arxiv.org/abs/2608.15303v1) | 多候选探索与 reconciliation；recursive DCR 按分歧分配额外计算 | “自适应探索计算”已有直接近邻，候选 D 若进入确认，须独立比较且计入控制成本 |

这些工作提示可探索的差异，但不预先规定最后必须采用哪一种机制。联想不立即承诺、
可纠正控制、跨会话恢复与 meta-memory 都仍是候选问题；R2 应按实际观察更新近邻比较。
单 Host 是简洁性选择，性质组合也不是“首次”的证明；不做 projection 不单独构成新颖性。

人类研究仅提供启发：[Gilbert](https://journals.sagepub.com/doi/10.1080/17470218.2014.972963)
实验涉及记忆负担/干扰与意图外部化；[语义觅食研究](https://pubmed.ncbi.nlm.nih.gov/22329683/)
观察局部与跨区域搜索。这些结果不能直接证明 Agent 的 offloading 或换支有效。
用户提出的“记录干扰念头、延迟行动”作为设计启发保留；
[Safren 等的研究](https://jamanetwork.com/journals/jama/fullarticle/186469)是整体 CBT 方案的
随机对照试验。v0.1 页面抓取未完整取得其模块正文，不把具体组件效果写成已复核的结论，
更不作 ADHD 治疗、类脑还原或临床效果迁移主张。

## 4. 两套合同：探索与确认分开

| 事项 | Discovery：R0–R2 | Confirmation：R3–R4 |
| --- | --- | --- |
| 目标 | 找现象、失败和信息量高的下一次探针，不预估无偏总体效果 | 对已经选中的问题做可归因、有界验证 |
| 策略 | 可改 prompt、State 表达、组合机制、探索宽度、保存/恢复方式 | 冻结主变量与行为政策；改变则开新版本 |
| 任务 | 可换类型、复用已打开案例、选择失败继续诊断 | 冻结题池、资格、cluster、抽样和所有适用分母 |
| 对照与模型 | 保留不可覆盖的参考快照；可探索不同对照/模型，变化逐 run 登记 | 固定强简单 baseline、模型、工具、输入条件与合法能力 |
| 资源 | 各 run 可不同，受已授权 batch 与物理上限约束，实际开销全记 | 同一配对使用预注册资源合同，或明确研究质量—成本曲线 |
| 评价 | 允许探索新指标和修订解释，旧评价和依据保留版本 | 生成前冻结指标、评分、争议、停止、分析与 evaluator 隔离 |
| 允许的结论 | “该版本在这些已打开案例出现某现象/值得继续” | “在冻结条件及已报告边界内得到某项证据” |
| 不允许的结论 | 不能用精选胜例宣称 unbiased effect size、泛化或因果优越性 | 不能失败后换题/调参，再仍称同一次独立确认 |

探索期可以回看已打开案例的 gold 做离线理解，不能把 gold、case ID、题专属同义词或正确
路径嵌入在线通用策略来“修好”题目。允许根据失败修改**领域无关**政策并再试；这种重试是
新的探索 run，必须保留原失败与研究者已知内容。Oracle/受控注入仅作为明确标记的诊断，
不能与自主运行混算。旧保护池不会因为研究模式改名而自动开放。

### 三条始终不开放的边界

1. **安全与权限不开放**：State、来源和研究提示不增加身份/作用域/行动授权。低门槛联想
   不等于允许无依据高风险行动；实验默认使用沙箱回答/动作意图，不执行真实业务变更。
2. **证据可审计、可回放**：所有实际输入、外显 State、来源版本、工具调用/返回、模型输出、
   运行版本与成本留存，不能覆盖失败。回放指可重建当时输入与外部事件，不承诺随机模型
   逐字再现；无法捕获的实时依赖必须标明。凭据不进入研究记录，敏感来源按原授权保存。
3. **结论与阶段一致**：探索可以大胆，结论必须保守。发现集不转成未打开确认集；
   所有探索版本/失败成本留在总账，不只交付最佳 seed、最佳 prompt 或最佳几个任务。

## 5. 候选目录：可以组合，不设依赖门

| 候选 | 开放问题 | 可选的简单对照；不是首轮必跑清单 |
| --- | --- | --- |
| A Association without Immediate Commitment | 联想可先出现但不立即检索、换支或采信，何时有价值？ | 普通多查询/普通笔记；“不污染”是待测维度，不是代码保证 |
| B Adaptive External Working Memory | 什么值得外部化、何时值得写；是否固定阶段保存就足够？ | 无控制保存、always-save、固定检查点 |
| C Reversible Cognitive Branching | 暂停不丢入口，新 observation 下能否正确恢复而非频繁误唤醒？ | 同信息普通笔记、普通恢复提示 |
| D Adaptive Divergence / Convergence | 怎样调整探索宽度、稳定性与停止时机，而非固定先发散后收敛？ | 固定单路、固定多路、固定发散—收敛 |
| E Meta-Memory Regulation | 关于“如何使用记忆”的可错记录，能否让 Host 重核当前记忆策略？ | 普通来源核验提醒、简单适用性说明、无 meta-state |

旧 RQ1–RQ4 分别映射 A–D；E 为新增方向。A 失败不阻断 B/C/D/E，C 可先于 A；
不要求先找够外部 relation failure 或先证明 Focus State。允许 F/G、新组合或完全不同的
轻量表示，但不因此扩张 Product 架构。选择顺序由当前观察和预期信息量驱动并简记理由。

例如“生成几个候选 + 暂存未选方向 + 当前只查一条 + 失败后恢复另一条”可以先作为
`A+C bundle` 探索。记录它有趣在哪里、改变了什么、有哪些替代解释；不因多变量直接判
无效，也不将成功先验分给其中某个字段。随后才拆解生成、记事、换支和恢复的贡献。

候选登记至少含：来源观察、版本/父版本、改变项、预期行为、真实观察、反例、实际成本、
下一次想区分的解释和状态。状态可用 `IDEA / OBSERVED / REVISED / PARKED / DROPPED /
SELECTED_FOR_PILOT`；这些是研究日志标签，不是 Runtime 状态机。
允许最终没有候选值得确认，不设“必须找到创新”的验收要求。

## 6. 研究漏斗与回退

下述 R0–R5 是本版研究阶段，不是历史实验中同名的单轮 R0 回答条件。

| 阶段 | 工作与自由度 | 交付/转移条件 |
| --- | --- | --- |
| R0 开放探索 | 可选任务、策略、表示、组合、检查点和恢复方式；以行为信息量选择下一步 | 形成可追溯 interesting effects / failures；可随时切方向，不要求固定样本数 |
| R1 机制归纳 | 从若干观察提出竞争解释，组合/拆解/重命名候选 | 形成候选机制卡：现象、机制假设、替代解释、反例、下一次区分方法 |
| R2 创新筛选 | 比较行为增益、可迁移性、新颖性、简洁性、成本与失败安全 | 可选择 1–3 个候选，也可零个；不是所有 A–E 必须过关 |
| R3 有界 pilot | 为已选候选新立冻结合同，试验主变量、强对照与评价 | 得到稳定性线索或负/不确定结果；不把小 pilot 当论文级证明 |
| R4 独立确认 | 机制冻结后才使用独立未打开任务；不再边测边调 | 输出有限条件下确认、负结果或不确定性，完整报告所有尝试 |
| R5 持久/产品验证 | 对保留下来的候选验证正常来源、真实冷会话、生命周期成本和产品集成 | 才讨论是否值得成为 MiLAi 默认；不是自动部署/Schema 冻结 |

R0↔R1 可反复；R2 可以淘汰大多数候选，也可以要求回 R0。R3/R4 的失败不能改写，
但可以暴露为后续 discovery 材料并回退研究。下一次独立确认必须另找未打开 cluster，
不在已经看过结果的确认集上修补后继续声称独立。

R5 是持久/产品**主张的验收位置**，不是“此前不准探索冷恢复”。B/C/E 在 R0 即可测试
外部化和冷会话；其结果标探索，之后按所选主张重新归因确认。会话内收益不能代替持久收益。

## 7. R0 如何启动而不重新制造准入阻塞

### 7.1 最小准备

后续获得执行范围后，只准备第一个可运行、可观察的小 batch：

- 固定不可覆盖的 Product A0/研究参考快照与运行底座指纹，复用现有记录器和公开接口；
- 选择一个当前最想理解的行为问题、少量可用任务和可选候选，不要求五个方向全覆盖；
- 保存本 batch 的任务来源、暴露状态、权限、模型和预算，检查输入/呈现/交付/成本记录；
- 运行一个能区分某种解释的探针，观察后可以改下一 run，不为补齐固定 6 题继续消费。

这里的“固定”指**保存当时事实**，不表示整个 discovery 的 task/prompt/model 永远不变。
预计信息量可以用一句理由表达，不要求训练 information-gain scheduler 或量化新控制器。

### 7.2 Benchmark 是行为探针

| 任务来源 | 可能观察的行为；不承诺一定出现 |
| --- | --- |
| 软件调试、故障调查 | fixation、竞争解释、证据积累、换支与返回 |
| 记忆 QA/多会话材料 | stale belief、遗漏约束、关系误用、过早结束 |
| 研究/调查任务 | 证据冲突、候选污染、过早收敛 |
| 长程/中断任务 | 未来意图、外部化、恢复位置与重复工作 |

可使用已打开 benchmark、自然任务和清楚标注的合成/受控 probe；允许复用 V02-10 等旧
开发案例理解机制，不能把它们重新称为外部自然失败或独立确认。自然/合成、文本/多模态、
QA/动作意图/真实执行分别登记，不混成一个总体 accuracy。
不默认下载所有 benchmark、建立新环境平台或打开 Horizon/Mem2Act/LME 旧保护池。

探索可以按观察换题、偏向有信息量的失败，也可以回测同题；选择理由和选择时已知内容
必须记录。重复 seed/同源变体仍属同一 cluster；不得用高重复数伪装泛化。
当前不冻结新的 discovery/confirmation 分割。决定进入 R3/R4 后才按主张建立新前瞻合同；
已打开、近重复或共同根来源的案例不能再进入声称未见的确认分区。

## 8. 固定观测方式，不冻结认知策略

### 8.1 复用最小记录合同

每次发送前登记 `run_id / phase / candidate_version / parent_run / change_reason`，
模型/模板/采样、Host/adapter/build 指纹、基线标识、任务/来源版本、当时可见材料、
预算及暴露状态；发送后追加实际请求、工具子调用、返回、呈现回执、输出、终态和用量。

外显 State 保存前后版本、内容与实际使用位置；区分候选、取得材料、实际呈现与最终采信，
不猜测模型隐式理解。记录格式本身不是研究 State 的必填 schema。
复用既有账本/回执；必要扩展采取兼容的附加字段，旧事件不可原地重写，不为日志另造平台。

所有失败、超时、没保存、没查询、无答案、主动停止和费用未知均有终态。源导入、Host 在线
取得/写入、持久恢复和离线评价分账。Provider 用量与开发代理劳动不混加。
原始来源及 Provider transcript 位于 Git 外的受控制品目录；Git 只留 compact manifest、
hash 和结果索引。操作 ID 重试复用，实验 variant 另有 ID，不以重试掩盖语义失败。

### 8.2 探索评价允许变化，但不覆盖旧判断

可先采用粗标签与逐例分析，随新现象新增指标、修订 rubric 或补充参考答案；每次评估标明
版本、时间、可见信息和理由。修订后可统一重评旧 run，但原分数和原解释保留；
未重评的版本不混算。事后定义的指标明确 `POST_HOC_EXPLORATORY`。
线上 Host 不获得 evaluator-only gold/人工纠错；评审辅助模型也须获准并计成本。

| 可观察维度 | 记录重点与误读防护 |
| --- | --- |
| 行为/任务 | 首次相关行动、正确澄清、交付、目标漂移、重复工作；格式通过不是语义通过 |
| 证据取得与使用 | acquired/presented、非重复有用支持、适用性；命中文档 ID 不是证据已使用 |
| 承诺与污染 | 无依据采信、可追溯候选→事实混淆；提出假设不等于采信，一般幻觉不自动归因候选 |
| 分支与修正 | 何时暂停/恢复、正确重开、无必要重开、旧控制是否被反证纠正 |
| 外部化与恢复 | 什么写了、没写、为何可观察地写；冷恢复后是否少重复/少误用 |
| 开销与复杂度 | 全部生成/工具/保存/恢复/评价成本，新增依赖、提示长度与模块数 |

可以报告同一已打开案例的具体改善/退化及比较，但标为探索观察。无可裁定采信单元、
无中断或无返回机会时相应率为 N/A，不以“没有回答”赢取零污染。分母公开：
任务、cluster、run、版本、attempted/delivered/scorable/disputed；这些不是随机样本总体。
不强制每个 run 同时优化六项，也不把候选数量、State 更新次数当收益。

## 9. 资源与执行边界：允许变，不等于无限调用

保持 `cumulative_raw_token_cap: null`；不恢复 20k 或整 Goal 累计 raw 硬上限。
v0.1 的 6-generation / 4-search / 8-read / 108-total 计划全部退役，不能当已获调用分配。

实际启动时，为获准 batch 登记模型/服务容量、请求数或时间边界、单次输出预约、源返回
与并发、记事/持久化范围、重试和收尾方式。探索 run 可在该范围内采用不同配置；
修改在下一次发送前记入新 run/version，不覆盖上一结果。超出授权范围不得自行扩额。

无需让所有探索 run 同预算，也不强制填满额度；不同成本的现象先按 quality–cost trade-off
展示，不能只报质量后声称效率获益。R3/R4 再按选中问题冻结公平资源上界或成本曲线。
功能/信息价值优先，token 后优化不等于隐去写入、重复输入、控制判断与评价的代价。

模型物理 context、输出预约、最终交付机会、服务容量、权限和未知用量停发仍执行。
单任务模型在途控制不限制多任务/独立工具并发；并发必须符合服务容量并记录实际重叠。
未知提交不能伪称成功，未知 usage 不能当零；先核对旧请求再继续，不用隐式 retry 清洗失败。
本文当前未授权任何生成或持久业务写入，也不启动/停止共享模型、公网或他人服务。

## 10. 从现象到候选：R1/R2 的选择方法

R1 不急着给每个现象起新术语。先问：是取得更多材料、多一次复核、更明确证据提示、
输出合同修复、额外计算，还是值得进一步研究的控制关系？竞争解释并列，允许组合继续存在。
机制拆解可以用删减组件、替换为普通笔记/提醒、同信息不同使用、冷/热恢复对照；
这些是研究选择，不是每次试验必须完整跑的因子矩阵。

R2 用多维 Pareto 视角筛选，不按一个综合权重或 accuracy 排名决定创新：

| 维度 | 筛选问题 |
| --- | --- |
| Behavioral Gain | 改善是否体现在真实可观察行为，而非 State 更整齐？是否保留负例？ |
| Generality | 是否在不同任务/独立来源出现相似现象，适用范围是否清楚？探索复现仍不叫总体泛化 |
| Novelty | 与最接近工作相比具体少了/多了什么；是不是已有提醒、笔记或计算增量？ |
| Simplicity | 删掉控制字段、额外角色、存储/检索模块后，效果是否仍在？ |
| Cost | 质量—开销是否有吸引力，收益是否来自更多计算，完整生命周期哪里还未知？ |
| Failure Safety | 错 State、错候选、无关 cue、新反证下是否更固着、污染或越界？ |

成本/收益不同时，保留非支配方案及不确定性，不凭几个异质案例宣布严格 Pareto 支配。
可以优先“小 State + 现有 Host”的方案，不强迫每条方向都变成模块；候选 A 也可直接淘汰。
R2 的输出是 0–3 个候选及选择/未选理由、最强替代解释、下一步冻结验证方案，
而不是“创新已成立”。数值门槛与正式样本量留给具体问题，不继承旧两域/六例/两例净胜门。

## 11. 确认合同：R3/R4 才冻结什么

每个被选候选单独建立 confirmation package，至少在对应运行开始前固定：

- 机制、主变量、是否仍为 bundle、主比较、最强简单替代解释及可接受的主张范围；
- Product/Host pin、模型/模板、工具与权限、来源/初始记忆、记事/保存能力和所有实际输入差异；
- pool revision/hash/license、exposure/cluster 排除、资格、排序/抽样、目标样本数与停止规则；
- 任务成功、主/次指标、适用分母、评分/争议、盲评限制、evaluator 隔离及缺失数据处理；
- 请求/输出/工具/时间/并发和全成本统计；运行顺序、随机性/重复及分析方式；
- 原始制品位置、冻结 hash、运行授权和变更/污染处置。

采用 frozen-pool sequential acceptance 可以避免先赌死几个题号；资格只用结果前可知信息。
一旦 ACCEPT/开始运行，错误、无答案、超时、争议不能删除补题。任务/共享源按 cluster 保守
隔离，R4 正文/gold 在候选冻结前不打开；评测人员需提前看正文时必须与调参侧隔离并记录暴露。
已打开 run 不能因换标签或改 seed 变成独立确认；受保护旧题池按原合同保留，不能自动借用。

R3 不是单变量算法的强制证明：bundle 可以先筛整体，但必须承认无法拆分原因。
要声称某个组件独立有价值，应安排消融；新 schema/存储名称不等于新机制。
R3/R4 只允许修一般执行缺陷；影响语义、输入、资源或公平性时冻结新版本，旧有效/无效
记录分别保留，新版本不得覆盖旧确认分母。模型失败不是协议无效。

本 Goal 不固定全局 M2−M1。若选择候选 A，旧 B0/M1/M2 可作为模板：所有组共享已修复的
取得/澄清/交付底座，M1 也能多查询、记普通笔记并遵守证据规则，允许它自然 parking。
此时 M2−M1 比 M2−历史弱 A0 更能检验增量；若选择 B/C/D/E，则改用适合该问题的对照。
历史 A0 保留原快照，新普通研究 Host 必须另有版本，不能通过偷偷修好 baseline 或削弱对照造收益。

必要时比较最近邻方法；适配版公开删改及额外成本，不把删掉关键模块的版本叫官方复现。
小 pilot 的阳性仅用于继续；没有显著差异不等于证明等效。R4 负结果/不确定性如实收口，
允许 KEEP_SIMPLE、回 R0 或停止候选，不为继续研究而保证一定要选出赢家。

## 12. 持久性、可纠正性与产品价值的主张要求

本节是**准备提出相应结论时**的要求，不限制 R0 从 B/C/E 起步：

- 持久使用：真正新 Host，清空旧会话临时 Context，保留共同合法来源；处理组专有日志、
  已生成控制笔记不能泄漏给对照。同信息普通笔记/State 的读取机会相当，再比较使用政策。
- 条件重激活：相关 cue、无关变化、稳定状态、错误旧“别再查/已解决”都应覆盖。
  Recall 以外生应重开机会为分母，Precision 以实际重开为分母；只比较各组自行 park 的
  分支有处理后选择偏差。候选被恢复不等于事实被采信。
- 外部化价值：中断/复用分布对组匹配且事前固定，不能只在 adaptive 已保存后安排中断。
  计构造、保存决策、写入、恢复、维护及重复工作；不只比较下次读了多少 tokens。
- Meta-memory：既要看正确重核，也要看无关变化时是否稳定、旧记忆策略错误时是否可纠正；
  普通“先核对来源”若足够，就保留简单方案。
- 产品价值：机械保存正确、探索场景成功、QA 正确都不能分别代替自然端到端和生命周期收益。
  默认启用/发布仍需单独产品合同；研究通过不会自动修改 A0 或解除 Schema NO-GO。
