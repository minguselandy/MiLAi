## 为什么继续而不宣布成功

C2 在同一日程更新 root 的两次冷运行都通过，N1/C1 都失败；新闻最终质量则三臂都通过，
且新闻更新第二次 N1 更省调用。C1/N1 在新闻也自然保存 Note，因此“有检查点”与“没有检查点”
不能仅由指令名称区分。C2 可能只是促使模型多做了一次普通复核，并非独立的新状态机制。

## 拟定最小矩阵

仍用原两个已暴露日程/新闻 lineages，Stable/Superseded/Unresolved 三种适用世界，
各 root 一个新自然 A，所有 B 共享该 A 原样可选 Note 和真实业务/历史。
不因为 A NO_WRITE 或失败换题；不复用最佳 A。未决世界在 T5/E0 已固定，不根据 C2 Note 制造。

| 臂 | E2 中的作用 |
| --- | --- |
| N1 | 已统一选定的普通 Note 强简单基线，额外来源呈现与其他臂相同 |
| C1 | 原冻结 audit 提示，移除 C2 的检查点要求；仍允许自发保存，实际行为单列 |
| C2 | 原 E1 audit+自由检查点提示保持不变，检验原信号而非事后优化新版本 |
| R1 | C1+一次简短普通任务相关信息/工作复核 Note，不要求旧新链、依赖或操作状态结构；与 C2 有同保存和生成机会 |
| P1 | 原论文 StateMemWrapper 的披露概念适配：按来源演变/有效约束概括当前可用状态，再执行；同样一次公开 Note 与同生成机会 |

P1 不是官方实现/成绩复现：依据[官方 v1 Appendix F](https://arxiv.org/html/2608.19652v1#A6)，
该 wrapper 在单次 QA 内提交摘要后作答；这里改为动作世界中的公开 Note 和真实业务动作。
新增保存调用必须计入同一 episode，不能称原方法本来额外花一次 LLM 调用。
未定位匹配官方实现的缺口保留，不声称胜过完整 StateMem，更不把第三方 store 接入 Product。

## 必须排除取得差异

E1 的大部分必要来源已实际呈现，但自主读取顺序和次数仍有差异。E2 采用单列的
`MATCHED_PUBLIC_INFORMATION` 条件：在 B 首次生成前，真实读取全部普通 current/policy/records/history，
将未经语义筛选/裁剪的响应及版本/hash共同呈现给所有臂。只读接口，无额外模型推导或理想 Note。
源文本仍是数据，不是系统指令；未来事件、checker、私有正确答案绝不加入。
这些预读记作 HARNESS_PUBLIC_PREFETCH，不伪称 Agent 自主取得，也不在动作图中算自主检索收益。
它们的字节在每条真实请求中审计，来源读取和重复输入分别计成本；普通后续 read 工具仍保留。

这是新的同信息控制条件，不把 E1 普通入口成绩和 E2 预读成绩直接并为一个效应。
默认 Host 不启用预读；新分支须证明无配置时原始请求保持不变。
所有臂使用同一新接线版本，并重新运行本矩阵中的 N1；不只给候选额外事实。

## 机会、判据与退出

拟定 2 A + 2 roots × 3 worlds × 5 arms = 32 episodes，16 次生成/episode，共最多 512 次；
每 episode 900 秒，批次 30600 秒，单请求 60 秒/输出 4096/串行、累计 raw cap=null。
普通复核与结构复核都消耗同额度；实际 Note 是否写、保存次数、输出长度、输入/时间可不同，
等机会不能冒称实际 token 或 GPU 计算完全相等。不得让任一模型助手在工具中免费复核。

完整 checker/动作轨迹、首次正确动作、无必要暂停、真未决的实际澄清、已知事实保持、重复写入、
冷链/全部尝试和成本都保留。阈值不是“C2 笔记更长/更像状态”，而是真实工作相对对照的差异。
若 R1 或 P1 可解释相同收益，或 C1 去组件没有稳定退化，删除/降级 C2 的机制主张。
未决/Stable 损害不能被更新胜例抵消。先完成 E2 全矩阵再决定 0–3 候选卡，最多 2 个 E3；
不预设一定晋级，不用没有 C 的事实替代这轮有界筛选。

如果仍有独立作用信号，按 Goal 的 E3 冻结 pilot 做两次有界暴露 D 复验，并明确 C=0 的确认缺口。
若没有，E3/E4 可以 NOT_TRIGGERED，E5 仍必须给出完整负/工程/不确定决策。
本设计本身不使 E2 变为完成，也不修改 A0/产品权限/API/schema、旧保护池或公网部署。
