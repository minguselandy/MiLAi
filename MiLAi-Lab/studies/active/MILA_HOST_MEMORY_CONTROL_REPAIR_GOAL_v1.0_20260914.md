## 3. 实现约定

工作区包含短记录、独立卡片、Frame 和机械 revision/事件位置。模型提出更新，Host 分配身份。
Controller 与 Actor 使用同一模型，调用类别和输出上限分别记账；原始目标和新观察直达 Actor。
回读只接受已公布句柄，结果有出处；读取限额不等于证据穷尽。归档不删除原始来源。
最终草稿最多一次专门复核（可配置），后续修订不重置总额度。Controller 的 DELIVER 仅在交付阶段有效。

公开检查点适配放在 tools 边界，Lab 核心不 import 产品包。保存保留其他 Host 状态；
受限 payload 不当空白；未知写入先检查公开可观察状态，未明确结果不重发。
实际固定版本没有 Working State operation 查询接口，因此使用 head 内 operation ID 与摘要
做正向确认；标记缺失或不可读仍然 UNKNOWN，不编造其他查询能力。
来源过大使用既有持久来源或明确容量失败，不能悄悄裁剪或扩大产品限制。
显式交接保留同一个业务环境；不提供无依据的任意崩溃 exactly-once 承诺。

## 4. 本次资源与运行边界

开发测试和公开恢复接口检查优先零模型。产品检查使用独立实例或独立合法绑定，先验证本轮产品 pin。
本次指令下的小范围模型开发检查新增上限：两个现有可用任务 × 两个同结构方法，每轨迹最多 64 次，
合计最多 4 条轨迹 / 256 次生成；Actor、Controller、摘要、复核及失败共享该上限。
这是本次开发分配，不继承任何已关闭实验余额。原生任务时限保持，模型串行，仅使用已有 HTTP 服务。
不操作 GPU、重启共享服务、发送外部消息或部署产品。环境失败保留，未解决不反复消耗模型重试。
修订政策时分开记录版本，不能拼出“最佳总成绩”。未知生成用量停发核对；未用额度在交付时关闭。
