# MILA-V02-19：外部行为失效区间发现、开放机制探索与条件确认

## 1. 目标与本次交付

**使用已固定并完整取得的外部 corpus，寻找普通 Note 与普通复核仍不能解决的重复行为失效；先建立可信失败图谱，再决定是否需要新机制。**

研究对象不是预设的 Control State、C3/C4 或新的 Memory Store。Memory–World inconsistency、过时确认、虚假完成、适用性漂移、旧计划延续和恢复失败首先是**现象标签**，不是已成立的机制或因果解释。

本 Goal 包含 F0–F6 及最终收口：清点、封存、强简单基线、失败归纳、条件探索、创新筛选、条件确认。执行时不能只交付一个索引就声称完成行为研究；也不能为完成阶段编号强造候选、消耗确认集。

**本次仅交付详细规划及文档索引同步。F0–F3 未执行，F4–F6 条件未触发；没有创建新题池、打开新任务正文、启动服务或发送实验模型请求。** 后续明确执行本 Goal 时，先封存具体批次、核验依赖与权限，再按阶段门推进；本文件不是正在运行的预算预约。

研究问题：

1. 在正常来源与工具可用、旧 Note 和当前证据真实呈现后，N1/R1 会在哪些行为条件下反复失败？
2. 失败属于来源取得、任务/判据、业务执行、一般推理，还是有对照依据的 Memory 影响？
3. 哪些跨独立 lineage/family 的模式不能被普通复核、正常工具接线或更多相同机会解释？
4. 只有出现这样的模式，最小候选能否改善真实行动，且不损害 Stable/Helpful 条件？

允许最终得到“没有可晋级模式”“只有工程问题”“候选未确认”或有边界的正信号。不以必须产生创新为完成条件。

## 4. 行为类型索引与失败图谱必须分开

### 4.1 行为条件 taxonomy：不读取模型结果来标条件

每 root 可多标签，标 `SUPPORTED / ABSENT / UNKNOWN`，不强制八种条件都存在。
标签依据任务/环境合同与来源定位；不把“看起来容易难倒 R1”作为纳入标准。

| 行为维度 | 需要的外部依据 | 负控/限制 |
| --- | --- | --- |
| TEMPORAL_SUPERSESSION | 某值在 t0 成立，合法事件在 t1 明确替代；可核对时间和对象 | 晚出现不自动更权威 |
| APPLICABILITY_SHIFT | 旧事实仍真，但对象/版本/条件变化导致不适用 | 不能把所有新事实都标 supersession |
| DELAYED_CORRECTION | 偏离后存在预定、合法、可行动的纠正窗口 | 仅有错误提示、无剩余动作机会不成立 |
| MULTI_SOURCE_CONFLICT | 可定位的不同来源、权限/权威/时间与未决处理规则 | 不预设唯一来源排序适用于全部任务 |
| PARTIAL_COMPLETION | 可核对已完成和未完成对象；事件只影响部分工作 | 正确行为不要求无意义重做全部对象 |
| INTERLEAVING | 实际任务/事件交错和返回点，不只是同题分段 | 同一根的阶段不新增样本 |
| STABLE_CONTROL | 旧约束仍有效，有明确应保持的外部状态 | 不能通过“永远怀疑 Memory”得高分 |
| HELPFUL_HISTORY | 历史合法且有价值，当前界面不直接展示，普通历史入口仍可用 | 不人为封死 N0 的合法来源 |

### 4.2 运行后 morphology：先记首次可证实失效层

建议初始 failure code：`TASK_OR_CHECKER_INVALID`、`INFRA_OR_RESOURCE_STOP`、`NO_WRITE`、
`SOURCE_NOT_ACQUIRED`、`PRESENTATION_INCOMPLETE`、`ACTION_CONTRACT_ERROR`、
`GENERAL_REASONING_ERROR`、`STALE_CONFIRMATION`、`FALSE_COMPLETION`、`APPLICABILITY_DRIFT`、
`OLD_PLAN_PERSISTENCE`、`RECOVERY_FAILURE`、`UNNECESSARY_REOPEN`、`UNKNOWN/DISPUTED`。

前几类是有效性/入口状态，不与后续语义标签混成一个互斥“Memory failure”桶。保留 earliest-verifiable layer 和后续可并存标签。
例如：

- “已提出澄清”与“旧承诺仍活动”分别记录；前者不抵消后者。
- `FALSE_COMPLETION` 要有实际声明、对应对象/版本和不满足的外部 postcondition，不能只因输出短就判定。
- Note 的错误完成声明没有被随后冷 Host 读取，最多是 memory-write / execution inconsistency，不是其长期传播证据。
- 同一错误在 N0 也出现，不能继续默认以持久 Memory 解释；查任务、工具语义、一般执行/推理。
- 新观察充分性、旧 Note 当时正确性无法裁定时保留 UNKNOWN；不通过提高标签“置信度”补有效分母。

`Memory–World Consistency` 是本节现象集合的工作名，不是新 Runtime 检查器、必填 schema、主创新或预选唯一方向。

## 5. F0：全 corpus inventory，但不做全量语义暴露

### 5.1 两层索引

**公开中性 catalog**：固定 revision、文件 hash/size、opaque root ID、来源 lineage、已有中性 family/template 标识、
资产存在、模态、原生服务依赖、解析状态、许可记录与已知 exposure。只读允许字段，第三方 task.py 不因清点而被执行。

**evaluator-only semantic catalog**：具体事件、正确行为、gold、来源充分性、行为条件与 checker 预期。
与 Host/候选开发上下文隔离，不把有诊断价值的列顺手打印成模型可见摘要。

全量文件清点不等于全量任务语义阅读。处理方式：

1. 先依中性 metadata 和已知暴露账划出旧 D、候选 D_new、候选 C；再人工查看 D 的正文、事件和判据。
2. C 的正文如需机器读取，只能由已在 D/合成夹具校验的确定性准备/评分程序隔离处理；不调用额外 LLM 标注。
   开发者在 F6 前只见 hash、总数和非语义资格状态，不见具体任务/正确更新/逐题诊断标签。
3. 若没有可用的中性行为 metadata，不为了“按行为分层”先把 C 逐题语义标注给机制设计者。
   退回按现有中性 family/资源条件分层；C 行为分布由冻结程序事后分项报告。
4. 某 root 必须经设计者手工读题、改事件、补 gold 或定制 adapter 才能运行，它只能归 D/EXPOSED；不能仍称 sealed C。
5. 程序可以机械识别重复/模板关系，但不向开发者显示 C 内容。单独给出处理代码/hash、输入访问日志和输出允许字段。

构建者、评价者、机制设计者是否同一人必须披露。另起一个进程、隐藏文件名或让另一代理总结正文，都不能自动构成独立盲审。
本轮不要求也不授权委派代理阅读 C。

### 5.2 exposure 与独立性账

至少区分 `HASH_ONLY`、`NEUTRAL_METADATA_ONLY`、`TASK_TEXT_OPENED`、`EVENT_OR_GOLD_OPENED`、
`MODEL_RUN`、`UNKNOWN_EXPOSURE`。最后一类保守排除 C；“没有新模型调用”不等于未暴露。

下载/逐字节 hash 不是语义暴露；看到任务正文、未来事件、正确答案、针对该题的适配常量或检查预期则是。
回顾 V0217/V0218 及更早研究的源文件访问、已打开制品清单和派生代码；不只排除曾跑模型的 12 个 ID。

独立单位用原始 lineage 与共享生成模板/核心事件的关联组。实体改名、种子、世界变体、重复、另一个文件名不增加独立性。
跨 corpus 的重复来源也要关联。无法确认共享关系的 root 标 uncertainty；不能凭 path 不同宣布独立。
通用 transport/checker 框架相同本身不自动合并全部 root，但语义模板相同要分层报告并防止跨 D/C 泄漏。

F0 输出：中性 manifest、暴露/排除清单、lineage grouping 规则、lane/profile/资源兼容矩阵、
来源/许可/哈希引用和未解决项。**当前这些 V0219 产物均未生成，不声称剩余 88 个 ClawMark task 都是合格未暴露样本。**

## 6. F1：新的前瞻 D/C 合同

### 6.1 先冻结过程，再顺序接收

封存 `pool_contract`，至少包含：候选全集 hash、revision、exposure manifest、lineage/group 规则、
中性分层字段、eligibility predicate、排序/分组 seed、各 lane 目标 accepted 数、pool exhaustion 规则、代码版本。

排序建议采用无歧义 canonical encoding 后的：

```text
rank = SHA256([goal_id, pool_version, substrate_revision, lineage_group_id, seed])
```

用不同固定 salt 做 split 和组内顺序。关联组整体分配；每个足量分层默认约 2/3 D、1/3 C，
稀少层的整组分配规则先写明。对照/变体/重复继承根分配，不二次抽签。
该比例是规则，不承诺当前 corpus 有足够 C，也不等于 D/C 必须都实际运行完。

逐顺序 `ACCEPT_STATIC / REJECT(reason) / HOLD`，只用前置许可、资产、模态、上下文容量、
适配完整性、观察可区分性、可评分性和暴露条件。**禁止按 A 是否写 Note、R1 是否失败、gold 内容或预期机制收益挑题。**
被拒绝者保留清单，接受达到目标或候选池耗尽即停止；不能悄悄追加新的 pool revision。

### 6.2 规模与封存层级

| 部分 | 起始计划，不是既成可用规模 | 使用方式 |
| --- | --- | --- |
| D_old | V0218 及其他已暴露根 | 零模型接线/判据回归；需要重跑另标旧根，不计新独立发现 |
| A-lane D_new | 目标 12 新原 lineage，覆盖至少 4 个可区分 coarse family；4→8→12 的顺序前缀 | F2/F3 开放发现；不足时报告实际数，不用同模板变体凑数 |
| A-lane C_reserve | 从剩余未暴露关联组封存；规划目标至少 12 原 lineage、尽量跨 4 family | F6 前不消费；规模/功效不足则只支持有界复验，不宣称正式总体确认 |
| L/S D | WMA 先 4、最多 8 个不同历史根；Supersede 先 4、最多 8 个时间线根 | 两 lane 分开；共享模板另计，不硬称 8 独立机制任务 |
| L/S C_reserve | F1 能做到盲隔离则封存，否则明确未建立 | 不自动与 A 共开；无跨 lane 主张时不强跑 |

目标 D 和 C 来自全集，不仅从刚好选中的 12–20 个适配根里再分。若全部可用任务经手工适配都已暴露，必须承认 C=0。

F1 的 C 是**静态可运行的保留池**，不是“已成功写入并双呈现”的行为合格池：

- `Seal A` 冻结候选全集、顺序、静态规则与隔离。
- F6 在任何候选结果前，由冻结程序形成 `Seal B`：本次确切静态 accepted 列表、世界、臂、重复、checker 与统计合同。
- 实际 NO_WRITE、读失败、截断或未呈现是运行结果，留在 all-attempt 分母；不能换下一个 root 来保证 P 链成功。

这避免把只能运行后知道的变量当作抽样条件。C 在本轮机制开发中不得用来调 prompt、恢复策略、adapter、top-k、预算或评分。
候选没有晋级时，整个 C_reserve 原样保留。

### 6.3 暴露后的处理

C 的内容或逐题结果提前进入设计者上下文，标 `EXPOSED_AFTER_SEAL` 并保留原因；
不能改名重新封存。新的确认集只能来自预先隔离的独立 reserve 或新的前瞻合同。
一般机械准备可以访问 C 文件，但错误日志不得吐出正文/gold；泄漏检测失败立即停发。

同 family 不等于完全无依赖。报告原 root、关联组、语义模板和 coarse family 的全部数量；
只有真正 family-disjoint 的部分才可称跨家族 holdout，不把普通同家族新 task 称 OOD。

### 7.2 消费诊断优先：MATCHED_PUBLIC_INFORMATION

每个 root/自然重复先运行一份共同 Episode A：正常工作，可自主保存，不给正确 Note、不规定内容/模板，允许不写或写错。
在 A 后固定实际世界与 Note，以相同预定外生事件派生 N0/N1/R1 的 B。
同一 root/world 的业务起点和普通历史相同，只有 Note 暴露与政策按定义变化。

为避免又退化成 pagination 实验，主消费 profile 在 B 第一次生成前由共同 harness 通过**普通公开接口**取得
事先声明的 current/policy/records/history 等合法资料，并原样送入实际请求；不是用 gold 选需要的片段。
这继承 E2 的同信息原则，但每个新 substrate 的来源覆盖须重新验证，不能假设四个接口足以覆盖全部任务。

- 预读源集合/顺序/分页策略在结果前固定；全字节、版本和范围核验。所有臂同等获得资料，harness 读取单列成本。
- 大资料不能完整装入冻结上下文时，记录不兼容或另建正常检索 profile；不静默截短、更换目标位置或裁剪反证。
- 后续真实新事件仍经共同公开接口/通知送达，不能只更新私有 world 再要求模型适应。
- 自主 acquisition lane 可另行预登记；与共同预读的结果分开，不把 harness 取得归给模型或 MiLAi 检索收益。
- 世界变体必须有外部任务依据并在 A/Note 产生前冻结；无法自然实现的变体标 NOT_APPLICABLE，不改题来专门反驳 A 的 Note。

首波优先每 root 一个 Stable 和一个自然变化世界；无这种配对的任务进相应单独 profile，不伪造 Stable。
Helpful、未决、无关/适用性及 recovery 根据已有可行合同补入单列 probe；不把世界变体当新 root。

### 7.3 严格的持久与行为回执

记录 `AGENT_NOTE_MUTATION → committed version/hash → A process exit → fresh B → public read → actual sent bytes`。
作用域、版本、公开发布件、身份和旧/当前资料的发送 hash 都可核验；组装日志、文件路径和假 ACK 不算实际呈现。
私有 evaluator、gold、未来事件、root regime label 不进 Host。

Note 同一并不表示 Note 原本正确；逐个相关命题离线核对 t0 的事实/支持/适用性，错误或混合 Note 分项记录。
没有实际写入时不强填一条，也不重新跑 A 直到写出“合格 Note”。

自然 A 失败保留，按前冻规则继续可运行的 B 并标共享错误起点；世界根本不可继续则全部臂记共同起点失败。
若需要人工合法起点来测消费，另开 `EXPERIMENTER_SEEDED_DIAGNOSTIC`，不能补自主 P 分母。

同一个 A/Note/world 下的重复只测条件重现；重新运行 A 才测试自然写作变异。两者区分记录，均不增加 root N。
N0 在 B 中可以形成新工作产物；若再跨冷边界，不继承其持久工作 Note 的规则继续生效，普通业务历史不删。

## 8. 行为真值与有效性门

复用 V0218 的隔离世界、公开记忆传输、完整 checker/反例方法，不让旧 G_TESTBED 自动覆盖新 root。
新 adapter/checker 属于 Lab；一般机械接线修复双/三臂共同验证并保留旧失败，F0–F3 不开发记忆干预。

模型前为每 root/profile 冻结：世界转移、可见性、动作合同、多种合法解、完整对象 postcondition、不变量、
源时间/权限/权威、模态、澄清条件与纠正窗口。标签不能替代证明正确行为。

必须包含以下校准：

- 正确状态/多解/合理不行动；空字段、错误类型/单位/日期、只声明未执行、部分更新。
- 提交澄清但仍保留失效承诺；Note 写 DONE 但业务未修改；重复动作、过期版本、错误对象。
- 否定/引用旧值/正误并存/未决，不用命中目标词替代语义判断。
- 无关更新不应破坏稳定状态；充分资料不奖励无限暂停，真正未决不惩罚合法核验。
- reset/clone/跨臂隔离、泄漏 canary、操作重放、公开读版本、完整呈现、实际业务 postcondition。

环境执行器与 checker 的预期应有独立来源，避免共用错误常量互相自证。
天然多模态任务缺图片时标 MODALITY_UNSUPPORTED；预定义 text-supported 子集另名，不偷偷做 OCR/caption。
WMA 禁用 private-gold answer fallback；Supersede 不使用旧 matcher 作为新的语义真值。
ClawMark 局部 True 不能覆盖缺失完整业务约束；修改过的 checker 结果不冒充 native rubric。

确定性部分先冻结单测/反例；需要语义裁定的部分先指定 correct/incorrect/unknown/disputed 规则，
说明裁定者是否盲于 arm，保留来源/动作定位。不将同一开发者复核称独立人审；没有 Judge 授权就不调用 Judge。

## 9. F3：失败图谱、因果层级与完整分母

### 9.1 每条 episode 至少能关联的证据

```text
pool/seal/revision → lineage/family/profile/variant → A and actual Note
→ commit/public cold read → old Note and current source sent receipts
→ action sequence → environment snapshots/postconditions
→ first failure / correction opportunity / later repair
→ scorer/rater/version → requests/tokens/time/failure costs
```

既报所有静态接受/实际尝试，也报以下逐层数量：A 可运行、A 实际写入、提交可证、旧 Note 当时正确性可裁定、
冷读成功、旧 Note 呈现、当前必要证据呈现、可行动冲突/稳定机会、错误行动、纠正可用、实际恢复。
`NO_WRITE`、未知提交、截断、缺图、服务错误、预算停止、任务歧义不得从 all-attempt 分母消失；零条件分母为 N/A。

### 9.2 不把 present 当 caused

| 证据层级 | 能说什么 | 不能说什么 |
| --- | --- | --- |
| 世界/任务存在更新 | 某种行为条件可测 | 模型已经取得并理解更新 |
| 旧 Note + 新证据双呈现，外部状态错误 | presented-but-wrong / Memory–World mismatch 描述 | 错误必然由 Memory 引起 |
| 匹配 N0/N1、相同 A/世界的行为差异 | 该条件下 Note 暴露的有界影响线索 | 小样本或一次随机差异就是普遍惯性 |
| R1 同信息仍失败且跨根重复 | 普通复核未解决的候选 failure regime | 该 regime 必然需要 State 或属于新问题 |
| 最小干预、等机会对照、消融与未打开确认 | 与冻结机制相符的有界效用证据 | 单靠效用证明新颖性或上线价值 |

任务状态与记忆状态不一致要分别量化方向：Memory says DONE / world not done；Memory stale / world updated；
world correct / Note stale；两者都不完整。只有后续真正读取该 Note 并影响行动，才研究传播。

主图谱记录：完整成功、首次相关正确动作、第一次失效层、错误活动状态持续步数、虚假完成、
不必要重开/澄清、重复业务动作、最终恢复和完整成本。用可观测行为，不要求模型提供隐藏推理。

恢复率先报 all-cause；无偏离或无真实窗口时 N/A。不同臂出错集合不同，不能直接比较各自“已犯错者”的条件恢复率作因果结论。
共同错误起点的恢复 probe 必须单列，它能测恢复能力但不能证明初始偏离由 Memory 诱发。

### 9.3 概率与统计的主张边界

`P(failure type | behavioral regime)` 是研究目标；F2/F3 默认提供的是**已纳入 D 的描述性比例和计数**。
D 的顺序分流、择有信息量场景继续研究及非结果静态筛选仍改变了观测人群，不能把发现集比例写成全 corpus 自然发生率。
多标签可重叠，给出每类分母和 UNKNOWN 数；按 root/关联组汇总，另报 variant/repeat，不能按 30 个 B 宣称 30 独立任务。
正式泛化率需要独立、冻结且有代表性依据的 sampling/analysis contract；不通过一个总体均分掩盖 family/profile 差异。

## 10. 从 F2 分流到 F3/F4：不是追着分数扩大样本

每个完整 wave 结算、三臂结果和失败链审完后，再决定下一预登记分支。具体 root 顺序来自 F1，不按答案挑下一个题。

| 当前现象 | 下一步 |
| --- | --- |
| 主要仍是来源未取得、缺图、协议/checker/预算错误 | 保留 supporting failure，暂停该消费 profile；先一般性校准或退回不兼容，不新增 Memory 机制 |
| N1 失败但 R1 能解决 | 记录 ordinary-review engineering gain；不以该现象为由调 C2 |
| 已实际激发持久链的有效范围内，三臂均好，没有重复可用失效 | 可在当前有界波次结束后 KEEP_SIMPLE；不强跑到 12 根或消费 C |
| 全部 NO_WRITE 或没有旧新双呈现，尚无有效 Memory-use 分母 | 记录机会/呈现缺口；不能用“三臂均好”认定普通持久 Memory 已足够，也不强造 Note 补门 |
| R1 在有效双呈现条件下仍有重复模式 | 按固定 D 前缀扩大至下一波，覆盖独立根/家族和 Stable 控制 |
| 只有一 root 或同模板反复失效 | 保留 case-specific observation，不满足跨根入口；不把重复叫外部确认 |
| 有跨根模式但 N0 同样失效 | 可研究一般 action/execution 问题；Memory 专属因果主张降级，不强改标签 |
| A-lane 模式需要生命周期/替代条件的边界对照 | 单列启动已登记的 L/S 小波；不把另 lane 分数拼到 A |

F3 交付所有模式及未归因项，**不一边聚类一边回写旧 prompt/checker 来改善基线分数**。
改变 task/判据/Host plumbing 时登记新版本、新共同 baseline；旧波结果与成本保留。

### 10.1 进入开放机制实验的候选现象门 G_REGIME

至少满足：

1. 同一可操作的行为失效在 **至少 3 个不同原 lineage、至少 2 个 coarse family** 中出现；共享语义模板另披露，不能靠变体/重复凑门。
2. R1 在这些案例中确实运行、具有正常能力/足够机会，问题未被普通复核解决；不是只跑 N1 就推定 R1 会失败。
3. 对 Memory-use 主张，旧 Note 与相关当前支持确实呈现、行为可评分且仍有行动窗口；任务/来源歧义不是更早解释。
4. 存在仍有效旧信息的控制和可合法修正/暂缓的行动，不通过“无解”或“永远不行动”制造模式。
5. 卡片给出全部分母、反例、可替代解释与原始定位；该门只允许小型机制探索，**不证明它是总体主要瓶颈或独立创新**。

F3 允许零合格模式。新的非预设模式也可以晋级，只要满足相同证据标准；不要求叫 Memory–World Consistency。
仅一般 action 问题可列 supporting research，但不得自动占用 Memory 机制确认池。

## 11. F4：有依据的开放探索，不预设 C3/C4

过 G_REGIME 后，才在 D 上尝试改变行为。研究对象可以是自由 Note、普通提醒、轻量复核、
可修正的使用政策或其组合；没有六个必须开发的 State 模块，也不先规定关系字段或算法。

探索期允许改变表达、步骤、组合和选取已打开案例，**固定的是实际输入/来源/动作/版本/成本记录**。
每次运行前写最小 mechanism card：动机、作用时点、具体差异、预测行为、反证、臂/根/资源；
结果出来后可以开新版本，不改旧 manifest，不把 discovery 说成 unbiased effect。

首个探索批最多 4 个候选版本，各先 2 个已打开根的适用世界；有可解释现象可登记一次冷复验。
这不是强迫跑满四个，也不是无界搜索授权。拟新增方向先结算当前批并写信息增益理由。
C2 旧结果可作反例；没有新的跨根动机，不通过加字段/微调提示反复重试原日程根。

不得通过 State 裁剪合法反证、提升来源权威或增加权限；不新增 Runtime schema/Memory 服务内部认知模型。
如果只需现有公开 API 的正常业务修复即可解决，按工程收益处理，不包装成机制。

## 12. F5：机制归纳、强对照与创新选择

候选首先面对 R1，而不是仅面对无 Note 的 N0。若 D 显示 N1 比 R1 更合适，可在 pilot 前冻结
统一的 S*，但不得逐题选较弱对手；报告候选相对 R1 与 S* 的完整矩阵。

至少排除以下解释：

- 信息更多：同一 A、Note、当前来源、工具/事件对齐；候选额外查得内容的收益单列 acquisition/use 联合效果。
- 多想一轮：普通复核与候选有相同生成/检索机会，候选所有新增调用计账；实际 token/耗时不假称相同。
- 格式只是改名：记录 R1/N1 自然保留关系/核验动作的频率；不把无显式字段当作模型完全没做。
- 组件可删：去掉最关键操作/提示，若无稳定退化，保留更简单方案，不称该组件必要。
- 一边界投机：同时检查 Stable/Helpful、足够证据的执行与真未决的暂缓，报告 trade-off。
- 与近邻重合：候选明确后才进行对应原始论文/代码查新、版本定位与对照；记录实现差异，不以新名字证明新颖。

先允许 bundle 产生有趣现象，再拆解；不要求 F4 首日完整 factorial。优先低复杂度、行为明确、成本可解释、失败安全的候选。
如研究写作/维护而非 B 消费，应另开独立自然 A 的端到端对照、计全生命周期成本，不能偷换共享 A 的估计对象。

输出 0–3 张最终卡，最多 2 个进入已暴露 D 的冻结 pilot：每候选最多 4 根/至少 2 family、2 次冷运行，
比较 R1/S*、候选及一个最有信息量的消融。复验不用来计算新独立 N，第二次不利结果保留。

卡片至少包括：失效模式、最小机制、作用层/信息差异、预测/反证、全部版本与成本、根/模板/family、
成功与失败案例、普通复核解释、消融、安全边界、近邻、未解决混杂和是否晋级。
效用与新颖性分轴；近邻概念适配不能冒充官方复现，更不能据它的失败主张超越完整方法。
没有合格候选直接最终收口，F6 NOT_TRIGGERED，C 不打开。

## 13. F6：最多一个候选的独立有界确认

只有 F5 选出候选且满足盲隔离/真值/资源条件才启动。机制冻结在 C 的正文、逐题事件/gold、模型结果反馈给设计者之前。

`confirmation_contract` 至少冻结：

- 完整候选、R1/S* 与必要消融/近邻的代码/prompt；实际模型、template、工具/来源、公开件版本。
- Seal A/B、精确 static accepted roots/关联组、世界与重复、分层/聚合权重、顺序随机化与所有拒绝理由。
- 一个主行为终点、最小有意义改善、区间/检验方法、功效/精度依据、Stable/安全/虚假完成护栏及多重比较处理。
- NO_WRITE、呈现失败、未知用量、资源截断、DISPUTED 的处理；all-attempt 与条件结果同时报告。
- 固定最大请求、动作/纠正机会、时限及技术故障重放规则；不按中途胜负加题或停在峰值。

默认每个 root/world 2 次冷运行，以 root/关联组做配对汇总；重复嵌套在 root，不能扩充为独立样本。
12 个保留根只是规划起点，不保证功效；不足时标 `BOUNDED_REPLICATION / INCONCLUSIVE`，不得确认后倒填阈值。
若一个候选只在某 regime 合理，适用条件必须在机制冻结前定义，由隔离的固定程序选择；不向设计者泄漏未入选 C 的语义。

只做一套已冻候选，不在 C 失败后拿 C 调参、改 checker、换候选再报首次确认。
评分歧义暴露后，原确认按预冻争议规则或无效处理；语义改题后该组变为开发资料，新的确认另需未暴露组。
自然未写/未呈现不能按静态不合格替换。C 的保存内容不得由 evaluator 补造。

报告完整配对胜/平/负、root/family/profile 分项、效果与不确定性、全流程/条件分母及成本。
Recovery 条件选择偏差、同 family 依赖、单一模型和适配损失仍须披露。
即使有有界正信号，也不自动构成产品上线、普遍人类记忆理论或 ADHD 干预证据。

| F5 | 最多 2 候选，各至多 4D / 2 次冷运行，基线/候选/主消融；其余对照按信息价值显式列出 |
| F6 | 最多 1 冻结候选，完整静态 accepted C、冻结臂/世界、2 次冷运行；无候选为 0 |

默认每 cold episode 最多 16 次生成，预留末次交付及存在纠正窗口时至少 2 次行动机会。
任务确需 32 次，必须在 batch/model 结果前双/三臂一致冻结并说明原因；不能只给失败候选加机会。
起始输出预约 4096、单请求等待 60 秒、episode 900 秒；执行时依实际 provider 合同预检完整 prompt+schema+输出容量。
发生真实截断/次数耗尽保留为资源失败，不作纯 Memory-use failure。

批次 `max_requests = compatibility + Σ episode_generation_cap`，共享 A 只计一次。
例如 28 episodes ×16 = 448 次预约上界（兼容另加）；不是预计实耗，也不是必须用完。
批次 deadline 在 manifest 中由 episode 数和资源容量计算。普通独立 read 初始最多 4 并发、模型生成初始 1；
只有容量验证后才可显式放宽，不把此实验配额解释成 MiLAi 服务全局串行锁。

**累计 raw-token cap 始终为 null；功能/研究有效性优先，token 最后优化。**
但每批仍有请求/时限/动作上界、停止理由与结算；累计不限不等于无限重试、无界探索或免费隐藏模型。
未解决的未知用量/未知业务提交不自动重试。所有失败、技术重放、保存/维护、公共预读、重复输入、评审成本全部保留。
实验 Provider 与代理劳动分账；本地 GPU 不等于无成本；共享 A 同时报配对复用口径和完整生命周期摊销口径。

## 16. 产物、收口标签与完成判据

以下是计划产物，**本轮只创建本 Goal 与文档索引，不预造结果或伪造 seal**：

| 产物 | 最小内容 |
| --- | --- |

| Pool & sampling contract / Seal A/B | 完整顺序/资格/分配/目标/耗尽规则与代码/hash；计划数与真实接受数分开 |
| Adapter / checker acceptance | 新根差异、源/事件/观察/动作真值、多解、缺陷反例、冷持久与实际呈现校验 |

| Failure regime map / cards | 最早可证实失效、重复性/独立性、反例、UNKNOWN、因果等级、G_REGIME 决定 |
| Candidate / ablation / prior-art / selection | 所有候选及淘汰、简单解释、最小机制、消融、成本、安全、查新与确认缺口 |
| Conditional confirmation | 仅触发时生成冻结合同与完整结果；未触发明确 NOT_TRIGGERED，不伪装完成 |
| Final decision / audit | 能主张什么/不能主张什么、原始定位、全部用量、残余风险、服务停止与保护池状态 |

收口标签分轴使用：

- `FAILURE_REGIMES_RECORDED`：已有有效基线与图谱；不等于新机制存在。
- `KEEP_SIMPLE_NO_QUALIFIED_REGIME`：在实际有效范围内没有跨根、R1 未解决的可晋级模式；不是所有 State 无效。
- `ENGINEERING_GAIN_ONLY`：可用改进由取得、协议、执行/普通复核解释；不包装为 Memory 创新。
- `KEEP_SIMPLE_NO_CANDIDATE`：模式值得研究，但本批机制未越过强简单对照。
- `PROMISING_NOT_CONFIRMED`：D 有增益，独立 C/功效/近邻/消融仍缺。
- `BOUNDED_MECHANISM_SUPPORT`：冻结差异、消融、独立任务与护栏满足预定要求，限定模型/任务/profile；新颖性仍独立陈述。
- `VALIDITY_GAPS_RECORDED / INCONCLUSIVE`：题池、行为链、判据、资源或盲隔离不足；零分母不是零效应。

1. F0/F1 有真实可核对的 inventory/暴露/封存或明确不足，不只写计划。
2. 至少完成一个有效有界 F2/F3 波次，给出基线/图谱/全分母及分流决定；未能运行行为链只能交付准入部分，不能称研究已完成。
