合取筛选。每根含初始、无关通知变化、同对象当前版本变化三个阶段。所有材料及参考答案由
研究者事前编写/阅读，未开保护池；所有压力/阶段仍属同两个根，不冒充独立 N=36。

NOTES 和 NOTES+REMINDER 分组报告，后者仅加固定领域无关适用性提醒。保留自由笔记、
公开 TASK HOST_WORKING CAS、正常 inventory/search/read/分页、真实请求呈现回执、

无隐藏 Reader/Judge、无新 State/schema。所有阶段都是新 Host 进程，继承会话消息为 0。

## 3. 最早失败层与证据

- 7 次高压失败：读取/检索没有取得目标数值行，`RETRIEVAL_OR_REPRESENTATION_FAILURE`。
  来源真实存在，目标版本和规则已读；PARTIAL 被误扩展为全来源不存在。6 次提前停止，
  另 1 次重复 offset 0 后耗尽最终槽；资源压力只记次级，不将同次失败重复计数。
- 1 次弱压失败：trace NOTES p0 只读 source-03，没发起 registry/dictionary 读取，
  `ACQUISITION_NOT_ATTEMPTED`。还有 6 次请求空间，不是容量不足。
- 28 次正确交付：逐字节/版本/连续范围核对必要支持，并核对实际请求与 HTTP usage 回执，
  之后非盲审阅解释。不是仅“答案碰巧对”或“source_id 出现了”。

8 次失败均为不当全局缺失断言，不是合理 SOURCE_UNAVAILABLE 澄清；承认未获证据本身
是安全行为，但错误声称合法可读资料不存在，并不能完成这些可裁定任务。
没有充分目标支持呈现后的错误使用，没有交付协议/工程失败，没有独立资源停止。
不计算未经 claim-unit 标注的统一污染率，首次可见错误及次级症状见逐行图谱。

搜索的一个重要限制：这批正文触发 `FULL_HISTORY_FITS` 返回整文件位置，而非命中行，
并仍标 `source_coverage=PARTIAL`。它扫描了文件但没有把全文送给模型。
因此“调用过搜索”不能算找到目标，成功也不必归功于精确检索。
这是工具表示与 Host 覆盖理解的共同诊断对象；本阶段未修订搜索政策去追求胜例。

## 4. 旧前提、重复与反例

两个根上重复的是“部分读取→全局缺失”，共享相同来源布局与普通工具，因此异质性有限。
高压仍有 5 个成功反例，回退有 11 个成功；相同规则下并非稳定全部失效，不报告通用阈值。
弱压 NOTES 单次失败而 REMINDER 正确，可标 `SIMPLE_REMEDY_AVAILABLE` 的探索性反例，
但高压提醒更贵且正确数更少，不能得出提醒的稳定优劣。

最关键的限制是所有模型 note 都为空。旧阶段 final 并未注入下一冷 Host，也没有保存旧笔记，
所以存在同对象外部更新，却没有被恢复的旧判断可持续支配行动。12 个更新阶段有 11 个
取得新支持并答对，另 1 个没取得新数值；旧前提保持的合格机会分母为 0，不是“记忆固着率 0%”。
机械冷恢复通过与语义记忆调控有效是两回事；本批既不支持 memory-induced，也不能排除它。
