# MiLAi 复杂原生任务工作区政策探索：实验总结

## 1. 结论摘要

**本轮按有界探索收口，决定为 KEEP_SIMPLE：保留普通 NOTE/REVIEW，不将 REGULATED_0/1/2 或复杂工作区维护设为默认。**

在已运行任务、当前模型与实现条件下，两次政策修订没有显示超过强简单方案的可迁移净收益。并发任务中 NOTE 完整通过，候选没有；数据合并中候选与普通 REVIEW 同样通过、成本略高；数据库恢复没有取得有效原生评分，不能构成完整的效果对照。

需要同时保留两条边界：

- 本轮已经从固定定位问答进入真实终端工作，模型实际调查、修改并接收自身动作的反馈，不再只是 Note 接线测试。
- 14 条共同 Host 轨迹只有一次工作区更新，主动选材和显式回读均未发生。因此，这是对**当前提示型政策及其实际使用方式**的有界负结果，不是“充分实现的记忆调控机制已经被证明无效”，也不是“普通方案能解决所有复杂任务”。

实验共 16 条模型轨迹、337 次生成、5,754,068 raw tokens，全部生成用量结算。工程首次全回归为 **4,443 通过、1 失败、1 跳过**；失败模块原样复跑 10 项通过。不能把两次结果拼成一次全绿回归。

## 2. 研究问题与实际实现

原 [Goal v1.1](MILA_HOST_COMPLEX_TASK_POLICY_DISCOVERY_GOAL_20260914.md)探索三个相互关联的假设：面向后续决策保存依据；按新反馈的影响范围修订判断；按当前需要调整工作集细节。它们是可替换政策，不是 Runtime 中的认知状态机。

实际交付包括：

- [终端会话](../../tools/workspace_terminal_session.py)、[Harbor 外部 Agent](../../tools/workspace_harbor_agent.py)和[运行入口](../../tools/run_workspace_native.py)，连接已有 WorkspaceHost、Provider、tokenizer 和日志。
- NOTE、同调用 REVIEW、REGULATED 候选共用动作接口、工具权限和任务初态；没有额外解题 Agent，也不禁止普通臂自然记下约束或选择材料。
- 原生容器执行真实命令，原生 verifier 检查结果；另有两个 Terminus-2 系统参照尝试，单独报告，不混入纯政策比较。

| 条件 | 实际配置 |
| --- | --- |
| 模型 | `Qwen3.6-35B-A3B-FP8`，thinking=false |
| 解码 | temperature=0、top_p=1、seed=213；不据此假设生成完全确定 |
| 容量 | 实测窗口 65,536；输入保护 61,440；输出预留 4,096 |
| 工作区与来源 | 默认保留可容纳历史；工作区机械容量 2,944 tokens；终端回执初始最多展示 16,000 字符，提供完整回读 |
| 任务环境 | Terminal-Bench commit `2fd12b88aafdd04a52c298e3940bcb189f9766d6`；Harbor 0.23.0；Python 3.12.11 |
| 执行 | 原生 CPU/内存约束及 900 秒 Agent 时限；串行模型调用；无 GPU 操作 |

没有恢复 512-token 业务交付门、强制 K 遗忘或累计 raw-token 硬门。但真实上下文和输出容量仍有限，数据库任务确实受到超窗、截断影响，不能把这些失败当成容量无限下的政策表现。

预构建镜像不可达后，使用原始 Dockerfile 与记录了 digest 的镜像源本地构建；临时网络使用不重叠子网，未清理共享网络或修改共享服务。因此本轮是**本地重建环境上的原生评分**，不是官方预构建镜像的排行榜复现。三个零模型 smoke 的失败及成功均保留，不计入模型轨迹。

## 4. 三臂结果与两次规则修订

### 4.1 有评分的任务

下表列共同接口修复后的比较；最初漏填超时参数的失败及首次 REVIEW 另计入全尝试账，没有被复测覆盖。原生 reward 为整任务判断，括号内是同一任务的测试细项，不是独立样本。

| 任务 | 臂/版本 | 原生 reward（检查通过） | 生成 | raw tokens |
| --- | --- | --- | ---: | ---: |
| 并发取消 | NOTE | 1（6/6） | 18 | 148,084 |
| 并发取消 | REVIEW | 0（5/6） | 8 | 27,714 |
| 并发取消 | R0 | 0（4/6），达到生成上限 | 64 | 1,600,309 |
| 并发取消，源任务修订 | R1 | 0（5/6） | 8 | 57,004 |
| 多来源数据合并 | NOTE | 1（3/3） | 10 | 74,222 |
| 多来源数据合并 | REVIEW | 1（3/3） | 7 | 29,331 |
| 多来源数据合并，首次迁移 | R2 | 1（3/3） | 7 | 29,681 |

并发任务中，R0 将一条完全相同的命令执行了 50 次；R1 源任务修订后没有相同命令重复，8 次生成交付，但仍未通过所有取消边界检查。这个变化值得记录，却没有超过 NOTE，也没有通过重复实验排除生成波动。

数据合并的三个产物在用户记录和冲突内容上相同。R2 比 NOTE 少约 60.0% tokens，但比同样成功的 REVIEW **多 350 tokens，约 1.2%**。因此没有强简单对照下的净效率收益。该任务的数据规模也未形成明显长期记忆压力。

### 4.2 数据库恢复：有失败行为，缺少有效原生评分

NOTE、REVIEW、R1 均在看到 WAL 文件后打开数据库，再检查时原 WAL 已消失；NOTE 另执行了截断 checkpoint。之后各臂继续处理剩余基础记录。R2 增加保护输入的提示后，仍未执行相应保护。

| 数据库尝试 | 生成 | raw tokens | 停止及评分状态 |
| --- | ---: | ---: | --- |
| NOTE | 28 | 545,417 | 输入超窗；未评分 |
| REVIEW | 23 | 281,374 | 输出截断，动作不完整；未评分 |
| R1 首次迁移 | 28 | 393,662 | 输出截断，动作不完整；未评分 |
| R2 源任务修订 | 38 | 1,062,260 | 输入超窗；未评分 |

可以确认的是关键输入丢失、未完成恢复及容量/格式停止；不能把它们写成已经收到 verifier 的 0 分，也不能将多臂共同出现的输入损失归因为候选 State。

### 4.3 规则形成与迁移不能混算

| 版本 | 从哪里修改 | 改变的规则 | 非调试任务上的首次观察 |
| --- | --- | --- | --- |
| R0 | 初始设计 | 依据、范围、联想线索、探索宽度、返回条件与选材组合 | 未取得配对收益 |
| R1 | 并发任务 | 删除部分未发挥作用的要求；强调检查覆盖、结果差异及下一动作影响 | 数据库：没有形成工作记录，输入丢失且未获评分 |
| R2 | 并发与数据库任务 | 不确定探查前保护唯一输入，保留恢复入口，输入缺失时先调查 | 数据合并：通过，但与简单臂同分，且未使用工作区 |

数据库已参与 R2 修改，不能再称为 R2 的迁移任务。R1 的数据库轨迹与 R2 的数据合并轨迹，也不能拼成同一冻结政策的跨任务成绩。

## 5. 创新探索实际上检验到了什么

[操作审计](/cra/memory/mx_memory/evidence/workspace-host/complex-native-20260914/workspace-operation-audit.json)显示，14 条共同 Host 轨迹中仅发生一次工作区替换，后续 7 次调用携带该记录；主动 `context` 选材与显式 `read` 回读均为 0。这里的 0 指专用工作区操作，不代表模型没有通过终端读取文件。

唯一记录出现在 R1 并发任务，先于同轮命令回执生成；之后实现改变，记录未持续修订。它并没有展现稳定的“新结果到来—识别影响范围—修订记录—改变后续选择”循环。

| 研究判断 | 当前证据 |
| --- | --- |
| 候选政策的实用增量 | 未显示超过 NOTE/REVIEW 的可迁移净收益 |
| 按影响范围持续修订 | 没有充分行为实现，不能仅靠记录非空确认 |
| 主动材料选择/外部注意力分配 | 本轮没有实际使用，缺少该处理的效果证据 |
| 条件重激活/错误后恢复 | 没有成立的相关机会与轨迹分母，不报告虚假的 0% |
| 泛化 | 各版本首次迁移边界已记录，但没有同一候选跨根净收益 |
| 新颖性 | 现有记录/保护提示未展示独立贡献；公开近邻未完成同条件方法对照 |
| 持久记忆与产品能力 | 没有本轮公开冷持久化或跨来源验证，不改变产品主张 |

因此，**KEEP_SIMPLE 是当前配置与开发投入的选择，不是对长期记忆调控方向的普遍否定**。R1 的局部重复减少不升级为稳定能力；R2 在合并题打平也不能证明保护输入规则有效。没有值得继续拆解的已实现收益，本轮未追加消融。

## 6. 原生参照及成本总账

Terminus-2 两次尝试均为数据库任务。第一次传输适配未正确衔接容量恢复，并强制 JSON，属于接线失败；修正后共有 64 次调用，其中 28 次主决策、36 次短摘要回退。完整摘要未实际生成，不能将这些回退称为 36 次完整多阶段摘要。

修正参照同样未恢复 WAL，也没有产出 `recovered.json`。原生 verifier 下载 Python 超时，测试未启动，故原始 reward=0 不用于效果比较。**本轮未取得能证明新 Host 不劣于原生 scaffold 的有效评分参照。**

| 账务范围 | 轨迹 | 生成 | 输入 tokens | 输出 tokens | raw tokens |
| --- | ---: | ---: | ---: | ---: | ---: |
| 共同 Host：主比较、接口复测、两次政策修订 | 14 | 250 | 4,176,274 | 110,720 | 4,286,994 |
| 首次原生参照接线失败 | 1 | 23 | 649,069 | 26,283 | 675,352 |
| 修正原生参照，verifier 环境失败 | 1 | 64 | 759,640 | 32,082 | 791,722 |
| **全部尝试** | **16** | **337** | **5,584,983** | **169,085** | **5,754,068** |

全部 337 次生成结算，未知生成用量及在途生成均为 0；辅助 `/models`、`/version`、`/tokenize` 请求没有完整逐次统计，**337 不是全部 HTTP 请求数**。没有美元费率，美元费用未知，不表述为免费。

模型 HTTP 累计约 1,852.10 秒；16 条模型试验 wall time 累计约 2,797.71 秒。它们不包含全部镜像、安装、开发和回归成本，不是完整项目耗时；工具用时 68.40 秒只覆盖共同 Host，参照工具时间没有同口径数据。回归分片并行，不能把各分片耗时相加当成项目历时。

开发代理另计：**用户最终回报为 1,134,908 tokens、约 1 小时 46 分钟**。现有[平台计数快照](/cra/memory/mx_memory/evidence/workspace-host/complex-native-20260914/development-goal-meter.json)是更早的 active 中间时点，不据此冒充独立复算最终数；开发代理用量与 Qwen 实验用量不混账。本总结编写也不是上述已关闭实验的新轨迹。

## 8. 收口、未完成项与保留资产

完成的是 3 个任务根上的有界方法探索、两次政策修订及参照尝试，不是计划中 12 个任务或完整第二来源验证。

保留普通 NOTE/REVIEW、可替换原型、真实终端入口和全部失败证据；不默认启用 R0–R2，不扩 State Schema，不改变 A0、共享服务或产品数据。任务容器已退出，未使用的规划位置关闭；剩余 38 条轨迹位置和 3,503 次规划生成空间均不是可自动继续消耗的额度。
