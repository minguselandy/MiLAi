## 2. 两条工作线，不让支撑工程替代研究

| 工作线 | 范围 | 交付及主张边界 |
| --- | --- | --- |
| Track A：Supporting baseline | 核对/最小修正 partial coverage、source continuation、absence claim 的合同 | 共用的取得与知识边界正确性；不是 State 创新，也不要求先做全量检索平台优化 |
| Track B：Persistent memory use | 自然产生未决工作、自选普通 Note、冷恢复后观察连续性与适应性 | 记忆实际存在并呈现后的行为图谱；不预设必须出现 inertia 或必须选择机制 |

Track A 可先用旧轨迹和零模型工程测试准备；Track B 的任务设计可同时进行。
B 只要求相关来源、提交和呈现链可信，不等待修完所有搜索、吞吐、BGE 或公网接线问题。
共同底座有缺陷只阻断受影响的比较；修复后开新版本，不将修复收益计给 N1。

“Memory Stability–Plasticity Regulation”是研究问题，不是已成立的方法。
Continuity Benefit 与 Inertia Cost 分别观测，不直接相减成没有共同单位的 Memory Value 分数。

## 3. Track A：覆盖校准的最小合同

当前源码的局限可定位到
[FileSources.search](../../tools/v0214_source_binding.py)及
[retrieve](../../src/milai_lab/methods/acquisition_use.py)：
FULL_HISTORY_FITS 表示内部预算可容纳完整候选范围；外层不返回 span 正文，仍标 PARTIAL。
**搜索扫描过、返回整文件定位、到达某页 EOF，均不等于模型已完整阅读所有相关来源。**

后续获准实施时，只核对以下边界；本文不宣称这些修复已完成：

| 条件 | 必须诚实表达 |
| --- | --- |
| 搜索返回定位/扫描统计 | 区分内部 scanned、返回的 matched/located 范围、已取得和实际 presented |
| 分页读取 | 跟随实际 next_cursor，记录 source/version/start/end；JSON 上限不是正文长度，UTF-8 字节不是字符数 |
| 尾页 COMPLETE | 只证明该页到 EOF；若前面有空洞，累计覆盖仍未完整 |
| 重复页、换版本、失效或权限变化 | 不累加重复覆盖，不跨版本拼接成完整来源；重新资格核验，不扩大可见范围 |
| 覆盖不完整且没找到 | 可以说“当前已查范围未找到/尚缺材料”；不能改写成“所有来源都没有” |
| 覆盖完整且没找到 | 仅在明确范围、版本与检索/判定条件下形成有界缺失结论；完整覆盖不是语义不存在的充分证明 |

正向任务取得充分证据即可完成，不强迫每次读到 EOF。缺失结论应限定到当前合法、可核验
来源集合；不能泄露被拒绝范围，也不能把撤权/超时/暂不可用伪装成 ABSENT。
Runtime 只验证机械证据，不凭一个 COMPLETE 字段替 Host 判断任意语义不存在。

复用 F1/F2、重复 offset、跨 UTF-8 页、末页空洞、版本改变等回放，检查实际发送及返回合同。
零模型通过只能证明工程合同，不证明模型已学会校准；需要模型时另计有界开发诊断。
不添加 Reviewer、隐藏 Reader、题专属关键词、自动无限 retry 或新认知 schema。
B 的新 observation 可由环境正常直接交付两组，避免再次把核心研究变成长文件找答案。

## 4. 任务必须值得延续，但不强制写什么

阶段 A 需要有真实可观察的中间产物：已做过的比较、暂定假设、失败尝试、待外部信息的计划
或仅局部适用的经验。任务在 A 有合理进展，但尚有未来工作，不再是每阶段完全自包含的短 QA。

可以告知自然交接/恢复边界并提供普通保存机会，**不能承诺或强制模型一定记 Note**。
不发“写下假设 X / 必须使用 PARK / 记录这三个字段”等内容指令，不按参考答案补写笔记。
普通笔记可以自然含不确定性、来源、适用范围或返回条件；不得禁止这些内容以削弱基线。

| 语义演化场景 | 正常任务事件 | 同时需要的反例 |
| --- | --- | --- |
| 旧判断遇反证 | A 的合理暂定判断在 C 遇到足以挑战它的新观察 | 新观察支持旧判断或信息仍不足，保持/暂缓可能正确 |
| 旧经验仅局部适用 | A 的 workaround 在环境/版本改变后未必仍适用 | 环境无关变化时不应全面丢弃有效经验 |
| 暂停任务恢复 | A 已完成一部分，后续依赖在 C 就绪或改变 | 重复工作与必要重核分开；旧 next step 可能仍正确 |
| 多个记忆竞争 | 同一合法任务下不同时间、范围、可信度的记录共存 | 最新记录可能更弱/无关，不能把 recency 当事实权威 |

按单一场景或小组合开始，不强制四类全跑；来源保持可读，不以扩大长度和尾部距离作为主变量。
可以用已打开任务和新合成根；来源/任务/参考答案在每条 A→C 轨迹前版本化。
未来事件、到达时点和版本依赖先定义，不看 A 的答案后专门生成“能推翻它”的真相。
探索中更换事件脚本须开新轨迹并披露已知结果，不能冒充自然到达的外部反证。

## 5. 最小闭环：共同 A 后的配对冷恢复

首版采用**共同上游、冷恢复分叉**，降低两次独立写出不同笔记的混杂与成本。

1. **A 自主工作**：一个普通 Host 正常使用来源，产生工作产物，自主决定是否保存普通 Note。
   保存通过现有公开接口；内容为自由文本，不代写、重写、修正或补齐“理想 Note”。
2. **冻结交接点**：保存正常产物、合法源历史、实际笔记版本/hash/提交回执；
   WRITE_FAILED、COMMIT_UNKNOWN、NO_WRITE 均保留，不能被替换成有笔记的成功案例。
3. **B 中断/交错**：结束原 Host，执行预定义的间隔活动或环境变化。短期模拟标明范围；
   不以空等、虚构日期或复制同进程上下文宣称长期冷恢复。
4. **C 两臂恢复**：同一环境快照、当前目标、合法来源和新 observation，分别启动新 Host；
   N1 恢复 A 的普通笔记，N0 不携带该工作笔记。先核对实际模型请求，再评价行为。
5. **后续使用**：记录首次相关动作、是否修正/保留旧判断、是否重复工作及最终交付。
   不以读到 Note、写出“已理解”或改了版本号替代正确行为。

| 条件 | 本次恢复边界 | 其余能力 |
| --- | --- | --- |
| N0 — No carried persistent note | 不携带 A 的可选工作 Note；正常产物与历史仍可查 | 正常工具、来源、交付、推理与当前工作能力不削弱 |
| N1 — Ordinary persistent note | 公开读取并实际呈现 A 自主提交的普通 Note | 与 N0 相同，不添加 applicability/uncertainty 等候选调控提示 |

**这里 N0 是“本次恢复没有该 Note”，不是“从任务起点禁止记忆的独立 Agent”。**
A 的生成与写回开销是共享上游/反事实准备成本，首版比较回答“这次普通笔记的带回与使用有
何作用”，不回答自主写入政策或完整 MiLAi 的端到端净收益。N0 仍可能从正常历史重建同样
信息；这是强简单对照，不应为放大效应隐藏正常历史。

恢复后两组保持相同普通工作能力；若继续允许自选新笔记，记录为下游行为。
首版不自动把 C 后新 Note 带入下一次对照：研究多轮累积需另登记新分叉与处理历史。
若未来要比较从起点独立运行的“从不保存 / 普通保存”政策，另用自然端到端合同，
包含所有 NO_WRITE 与写回成本，不把本次共同 A 的条件比较冒充该结果。

## 6. 既保证呈现，也保证没有旁路泄漏

### 6.1 中性、确定性的恢复

N1 通过可信主体/项目/任务绑定与现有公开 inventory/get 或已绑定的 checkpoint 引用恢复，
不是让 evaluator 挑最有帮助的 Note ID。选定任务槽/整个小笔记集合的规则在 A 之前固定，
按当时公开版本取回；禁止按笔记“正确程度”选择内容或裁剪有害部分。

首版是 **HOST_ASSISTED_NOTE_PRESENTATION**：Host 确定性装配授权笔记，
不是模型自主召回能力实验，也不声称当前公网已有此默认行为。
两组使用相同恢复模板/位置与通常的“不可信历史、不能授权”说明，N0 如实得到该分支无 Note。
相同新 observation 以相同正常渠道和次序提供，两组保留完整合法来源访问。

记录 durable receipt → recovered version/bytes → 实际发送 request/hash → transport receipt。
仅 acquired、构造好 payload 或文件里有路径均不算 presented；禁止静默截断。
超出预定正常容量就记录 PRESENTATION_BLOCKED，不能按 gold 删 Note。
PRESENTED 不表示理解或采信；实际支持反证也必须核对，不能只保证旧笔记进了请求。

### 6.2 真实冷隔离与正常来源

新 Host 不继承旧会话消息、进程状态或 evaluator 内容；模型服务可共享，但旧消息不注入。
冻结源/产物/任务、笔记分支、合法索引范围、缓存键及实际初始输入，分别记录 scope。
同源版本可复用机械缓存，但不得跨 N0/N1、跨授权域返回处理组内容。

N1 专属 Note、写入请求/回执正文、自动摘要及派生索引不能经共享文件或日志进入 N0。
公共源快照以 A 的正常工作产物/原始历史为界，候选笔记及其加工物放在独立分支；
完整原始实验轨迹离线留存，不作为隐形在线来源。A 的正常需求、决策和工具事实不能因
“可能帮助 N0”而删去。若正常历史本来包含与 Note 同义的信息，允许 N0 正常重建，
并如实报告信息冗余；无法隔离处理组副本则标 CONTAMINATED_PAIR，不计算笔记暴露差异。

不通过删除真实用户数据建立 N0；使用专用合成作用域/公开分支能力。
若现有公开接口不能合法构造一致快照，就记录后端限制，不直接写 Canonical 表或私有存储。
Note 自述身份、权限、下一步指令不能覆盖可信会话授权。真实破坏性业务执行不在本 Goal 内；
行为验证默认 action intent 或可恢复的隔离环境操作。

## 7. 未写入不是可以悄悄排除的样本

“任务有保存价值”是设计预期；“Agent 真的写了且恢复呈现”是需要测量的事实。
所有 A 尝试保留在流程账本，不能只报告筛出的有 Note 案例。

| 分母/状态 | 如何使用 |
| --- | --- |
| 所有接纳并运行 A 的轨迹 | 报告任务、写入机会、NO_WRITE、错误/未知提交及实际消耗 |
| 自选成功持久化的轨迹 | 记录未改写的 Note，完整与错误内容都保留；不是所有任务总体 |
| 冷恢复且旧 Note 实际呈现 | 才进入持久笔记使用的条件诊断；恢复/呈现失败仍留在总流程分母 |
| 旧判断与新证据有可裁定关系 | 才计算保持/修正的机会；标支持、反驳、无关、范围变化或不可裁定 |
| 两臂输入合格且均可评价的对 | 才作配对描述；失败/不可裁定不伪装成 0，也不能无声删除 |

NO_WRITE 的轨迹可继续观察无笔记续做，但不花两份相同输入去制造 N0/N1 比较；
记为 NOTE_USE_NOT_EXERCISED。可以调整下一条任务的自然未决性或换场景，记录适应性选择，
不能强制补写、追问到写出理想笔记，或只留下有 trade-off 的任务。

即使所有合格题都写了 Note，结论仍只覆盖这个条件样本和探索流程。
结果可为“未激发自选笔记”“已有笔记未有效呈现”“普通 Note 足够”，不要求必有新机制。
旧保护池保持封存；同一根的事件版本、重复冷启动与多条笔记不是独立样本。

## 8. 分别观察连续性与适应性，不预设记忆有害

| 观察 | 可见证据及边界 |
| --- | --- |
| 冷恢复与首次相关动作 | 是否接上正确问题/工作位置、保留有效约束；未执行的意图不冒充实际业务结果 |
| 重复工作 | 重做已完成比较/定位的动作与成本；必要重核不算浪费 |
| 修正速度 | 从有效新证据实际呈现到首次符合新条件的动作，分别计步骤/工具/耗时；无修正也保留 |
| 旧判断残留 | 新支持足够时仍用旧前提行动或解释；只引用旧 Note 不足以证明受其支配 |
| 无必要重检/错误重开 | 旧判断仍成立或更新无关时，有无丢掉有效工作、无端重启路线 |
| 工作与候选边界 | 是否把暂定假设升格成事实、未确认经验扩大适用范围；不以候选数量衡量收益 |
| 完整成本 | A 取得/生成/写入、B、C 恢复/重取/重复输入/交付分账；评价、基础设施另账 |

为每条轨迹保留当时的成功/合理澄清判据、有效新证据和事件版本；
优先确定性动作/参数或来源可核查结论，非盲语义审阅注明身份与争议。
只记录外显行为与短工作产物，不要求导出隐式推理；指标事后新增标 POST_HOC_EXPLORATORY。

预先就错误的 Note 与 A 时合理、C 时失效的 Note 分开；前者可能是错误传播，
不能全部叫 stability/plasticity tension。反证缺失、获取/呈现失败、一般推理、交付和资源
仍按最早可证实层分类，不把工具修复后的正确率当记忆机制收益。

N1 在“继续做”上更好、在反证下更差，才是值得分析的 trade-off 候选。
N1 好且无适应性代价则 KEEP_SIMPLE；两组同错先查普通推理/来源；N1 单纯更差也先记录
有害笔记暴露，不虚构已经证明连续性增益。零适用机会报告 N/A，不报告 0% 惯性/错误重开。

即使同源配对出现 N1 更差，也先称“普通 Note 暴露下的探索性行为差异”。
memory-induced inertia 的稳定解释还需检查笔记本身错误、重复输入、位置/长度、模型变异及
其他上下文锚定，并在不同根上复现；本阶段不新增匹配占位文本等额外臂来凑因果结论。
持久化可恢复与笔记影响行为分开，不能据此声称 MiLAi 存储优于相同内容的普通版本化文件。

## 9. 成本、随机性与采样边界

每个获准 batch 在发请求前记录模型/tokenizer/提示/工具/版本 pin、采样参数、
上下文与输出预约、最终交付空间、请求/时间/并发范围。两臂具有相同预算上界和能力，
实际花费分别报告；N1 的恢复与额外文本不免费，不为“同 token”删掉 N0 正常来源。
共享 A 成本记一次；分臂生命周期估算写清分摊假设，不把共享准备费用隐藏或重复相加。

先用本地 vLLM，不默认付费模型或 Judge；“本地”仍有算力与时间成本。
