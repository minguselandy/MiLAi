## 2. 研究对象：环境正确性，而非规定正确的认知过程

统一链路为：

```text
外部任务与世界 W0 → Episode A 的真实工作 → 自选保存（允许 NO_WRITE）
                              ↓
                提交与版本核验 → 结束原 Host
                              ↓
                  从同一边界派生配对世界
                              ↓
           确定性外生事件 → 新 Host / 合法来源与旧 Note
                              ↓
          实际呈现 → 真实动作 → 环境后置条件 / 轨迹检查
                              ↓
             如存在纠正机会：新观察 → 后续动作 → 恢复检查
```

### 2.1 两种真值必须同时成立

世界转移为 `W(t+1) = T(W(t), event, action)`；但评分还必须结合任务要求、权限和 Agent
在该时点可合法取得的观察。**世界已经变化，不等于 Agent 已被告知或已经读到变化。**

T0 同时冻结：

1. **环境真值**：版本化对象、外生事件、动作效果、时间及不变量。
2. **可观察与合理行动合同**：哪些事实通过什么正常接口可见，什么时候应核验/澄清，哪些行动此时有充分依据。

两个世界若具有相同可见前缀，却要求相反的确定行动，必须先提供可区分的合法观察，或允许合理核验/SUSPEND。
不能凭隐藏 gold 惩罚模型没猜中；也不能把当前公开事实全部私藏后声称只有 Memory 能完成任务。
环境日期、时区、对象范围或原任务文字互相冲突时，先登记歧义、冻结解释或拒绝该 profile，不能看结果后改题。

### 2.2 五种 outcome 是离线行为语义

| Outcome | 可检查行为 | 不能用作替代证明 |
| --- | --- | --- |
| KEEP | 旧信息仍有效时，执行与当前约束一致的行动，不无故破坏已完成工作 | 输出“保留”或重复旧 Note |
| USE | 历史有效信息支持正确行动，减少重复定位或补足当前工作入口 | 行动恰好与 Note 一致就称 Memory 因果 |
| REVISE | 在足够新证据之后，行动反映当前状态，停止执行过时方案 | 只改笔记文字，环境动作仍旧 |
| SUSPEND | 证据确实不足时，不做无依据承诺，采取合同允许的核验、澄清或暂缓 | 永远拒绝行动；证据充分后仍无限澄清 |
| RECOVER | 已偏离后获得合法纠正机会，实际执行修复且满足恢复后置条件 | 说“已纠正”，或最后正确就抹去先前错误 |

这些标签可以在同一轨迹的不同时点出现，不是互斥 Agent 指令，也不是 Note/State 必填 enum。
评分允许多个合法动作/方案；不要求 Agent 产生 focus、park、trigger、confidence 或任何预设思维结构。
只记录外显工作产物、选择、工具行为和结果，不要求隐藏推理过程。

### 4.2 世界变化轴，不等于记忆机制轴

| 配对世界 | 固定环境关系 | 正确行为及控制作用 |
| --- | --- | --- |
| Stable | 旧信息在当前对象/范围仍正确 | KEEP；防止“永远不信 Memory”获得虚假优势 |
| Helpful | 历史信息仍正确，能减少重建；当前界面不直接展示，但正常授权历史仍可查 | USE；衡量连续性，不故意封死无 Note 条件 |
| Superseded | 旧信息在 A 时确实成立；外生事件在 B 前/期间改变它，当前证据可核验 | REVISE；区分曾正确与从一开始就错 |
| Irrelevant / Conflicting | 对象/条件不适用，或存在尚未消解的冲突 | 按合同忽略、核验或 SUSPEND；不能简单把“最近”当作“权威” |

Stable 与 Helpful 可以重叠，Irrelevant 与 Conflicting 需分开子标签；不得把四个名字当作必然互斥的自然现象。
每 root 检查四种变体可行性；不自然成立的变体标 `NOT_APPLICABLE` 并解释，不强造 Memory-shaped 题。
核心覆盖必须包含同源 Stable/Superseded 配对，以及跨 root 的 Helpful、适用范围、真正未决条件。
若只覆盖一个子集，只发布对应子测试床，不称四世界覆盖完成。

外生事件、时点、可见入口与允许行动在读取 Agent Note/答案之前冻结。不可根据模型写了什么，临时制造
反证或把真相改成另一答案。事实在 A 成立不代表自写 Note 一定准确：错误/无关 Note 单列，不能算 supersession。

## 5. 普通 Note 与真实冷持久化合同

### 5.1 首轮只比较记忆可用性，不比较新机制

Episode A 使用正常 Host、正常任务/来源与可选自由文本 Note；只说明可保存有续做价值的信息，不给目标内容、
正确关系、强制模板或“必须写一条”的评分要求。沿用可运行的公共接口，不以自动 approve 创建 Canonical。

在同一 A 边界冻结实际自写 Note 后，克隆世界为两个 B 条件：

- **N0：无该持久工作 Note**。不携带 A 的 Note/隐含消息；仍允许读取同样的合法历史、环境与工具。
- **N1：普通持久 Note**。通过 MiLAi 公开接口精确读回 A 的提交版本，按共同 wrapper 在真实 B 请求中呈现。

这里 N1 的启动展示由 harness 固定，是为了排除“没看到”的混杂，**不是自主检索收益证明**。
Note 内容是 A 自主产生的，展示政策是实验控制的，两者分别标记。
其他固定提示、模型、工具、事件、生成机会/时限一致；Note 与读取造成的真实输入/延迟差异计入成本，不用假填充掩盖。
各臂执行顺序交错/随机化规则预先记录，避免共享服务负载或顺序成为隐含解释。

该配对估计的是 **相同已生成 Note 的条件暴露差异**，不是“全自主写入+召回+维护”的端到端净效应。
这一限定适用于 T3/E0 暴露诊断；自然调用政策与新 Memory 机制由本 Goal 后续 E1–E4 单列，不能混入基线分母。
N0 在冷会话内新写内容不算非法；若比较继续到后续冷边界，N0 不继承其工作 Note 的规则必须提前声明并计账。

### 5.2 严格区分写入来源、恢复与呈现

- `HARNESS_INGEST/SEED`、`AGENT_NOTE_MUTATION`、业务环境动作分别记账；零模型造一条 Note 验接线不算自选写入。
- T0 锁定实际工具/action、载体、租户/项目/任务及版本语义。若沿用旧实验的 TASK Working State 承载自由笔记，
  必须明确载体差异，不冒充 Note CRUD，不把它自动命名为 Control State 机制。
- 保存至少核验 operation、提交版本、内容 hash、持久性与公开精确读；提交未知不能当成功，也不能以当前 head 否定未知提交。
- A Host 实际退出；B 使用新的进程、session/message 上下文与请求身份。可继承哪些普通文件/缓存明确列出并检查跨臂泄漏。
  多 stage、更换标签或调用 `end_session` 不足以证明冷启动。
- 记录 `committed → cold public read → actual request bytes/hash → transport dispatch`。
  旧 Note 和足以改变判断的新 observation 都要定位到真实发送请求；路径、ID、工具 HIT、组装成功及模拟 ACK 均不充分。
- transport 失败/响应未知另列；“实际呈现”不等于理解/采信。截断、缺图或误版本均保留在呈现失败层，不计 Memory use 错误。

自写 Note 中“曾经正确”的语义依据，由离线可追溯来源片段与任务合同裁定；自由文本不能用命中一个词自动证明。
需人工语义裁定的部分在生成前指定规则与争议流程，保留 `UNKNOWN/DISPUTED`，不偷偷调用 Judge。
若全部 NO_WRITE，结论是自选持久记忆行为链未被激发，不能报告 inertia=0%、强填正确 Note 或为凑分母补题。
另做实验者注入只可命名为 consumption/transport diagnostic，不补充自主 P 分母。

## 6. 行为 checker：先校准尺子，再运行 Agent

### 6.1 环境与评分器不能互相自证

先从外部任务要求编写可检查的语义预期，再实现转移和 checker；保留来源定位与不确定项。
评分器读取独立的实际环境快照/动作账本，不读取模型的“完成”宣告；避免转移器和 checker 共用同一个错误答案常量
导致自洽假阳性。逐项人工复核与独立 fixture 预期先于模型输出冻结；无独立复核时明确标开发自审。

完整判断至少包含：动作目标/身份/权限、所需字段、类型/单位/时区、前置版本、约束、不变量和最终状态。
允许多种正确方案，不指定唯一 action trace。单个局部 checker 的 True 不能绕过完整 rubric 的其他必要条件。
确定性评分仅覆盖已形式化的任务部分；自然语言含糊、相互矛盾的任务不能靠加强 regex 假装有真值。

首个 scheduling 纵切可复用已打开的 ClawMark 日程/房间变更关系，但须先核验日期与文字约束一致性、
时段完整性、冲突和作用对象；现有 `_s2_c04_rescheduled` 对空 start_time 的局部命中只作回归反例，
不能把缺时段判为完整日程成功，也不能把该函数的局部缺陷推广成全部 ClawMark 行为结论。
依据：[原始局部函数](../../../evidence/v0217-admission/20260910/clawmark/tasks/executive_assistant/task2/task.py)。

### 6.2 每个 root 的最小反例与不变性检查

| 组 | 必测边界 |
| --- | --- |
| 正向与合理不行动 | 多个合法解；充分证据下正确执行；真未决下合法澄清/SUSPEND |
| 缺失/伪完成 | 缺字段、空值、仅声明未执行、错误类型/单位、部分更新、重复提交、过期版本 |
| 语义假阳性 | 否定、引用旧值、未决表达、正误值并存；自然语言不能只因包含目标词得分 |
| 对象与适用性 | 对象交换、跨任务泄漏、范围/时区/版本不匹配；无关新事件不推翻有效旧信息 |
| 稳定性与修正 | Stable 不应要求重做全部任务；Superseded 不应继续旧动作；证据已充分时不奖励无限暂缓 |
| 变形与独立复算 | 合法重命名、无关数据插入、非因果顺序变化、不同合法计划；预期随真正语义变化而非表面词变 |
| 执行与隔离 | reset 可复现、配对 clone 内容可核对、动作幂等、版本冲突、服务失败与 checker 异常不算任务语义失败 |

用刻意变异的错误实现/输出确认 checker 能失败，不以“测试数量增加”代替覆盖。
上下文/工具注入 canary、private-gold/future-event 隔离和目标作用域检查必须失败关闭。
原生反例、适配前后 fixture 和已失败版本均保留；一般修复重新跑全合同，不能题 ID 特判。

## 7. 纠正机会、因果与分母

### 7.1 Recovery 必须真的可行动

纠正事件采用预定时间表，或预注册的环境反馈函数 `feedback(actual_action, world)`；同一规则用于所有臂。
可根据真实动作给业务错误反馈，不能根据私有正确答案或某臂失败临时喂一个提示。
只发送环境当时合法可见的事实；checker 评分、未来步骤和理想 Note 不进入 Agent。

恢复窗口需有剩余行动次数/时间，环境也必须可恢复；先记录错误影响，再记录修复动作及后置条件。
不可逆错误、无纠正证据、未呈现、预算终止分别列出，不能混入“没有恢复”。
若模型从未走偏，恢复条件率为 N/A；**测试床可用不要求模型先犯错**。
零模型脚本可验证错误→反馈→修复的环境通路，但不能冒充 Agent recovery。

### 7.2 同时报全流程和条件分母

至少保留：候选/筛查/静态可运行 root、实际 attempted root/variant/arm、NO_WRITE、真实提交、冷读、
旧 Note 正确性可裁定、旧 Note 呈现、新证据呈现、合法冲突机会、实际偏离、可恢复机会、最终行为。
另列 acquisition、presentation、evaluator、infra、预算与争议；失败不从总流程分母中消失。

| 指标 | 分母和可作结论 |
| --- | --- |
| Stability | 仍有效、Note 实际呈现且行动可评分的机会；记录正确保持与不必要重做 |
| Plasticity | 旧 Note 曾正确，替代证据已充分呈现且仍可行动的机会；记录正确修正及到修正的步骤/成本 |
| Stale-action rate | 上述可裁定更新机会中，仍执行过时动作的比例；先作描述性行为统计 |
| Memory-induced interference / Entry | 只有匹配 N0/N1 暴露对照或其他明确因果依据，才称 Note 改变了行为；单臂一致性不够 |
| Recovery | 已偏离、纠正依据已呈现且有行动窗口的机会；若不能证明偏离由 Memory 引起，只称 all-cause recovery |
| Continuity gain | 同 root/世界 N1 对 N0 的重复定位、完成步骤、时间和生命周期成本差异；不把同根阶段当独立样本 |

零分母输出 N/A；不输出 0%。完成率另以全部尝试为分母报告，不能只展示成功保存/成功呈现的幸存子集。
首次相关行动、传播链、最终状态分别报告，避免最终修好掩盖早期损害。
不把六项压成总分；12–20 root 是建设覆盖，不预先承诺有统计效力、普遍性或 Stability–Plasticity trade-off。

| E3 有界冻结 pilot | 最小候选是否可重复，比较合同是否可执行？ | 最多 2 候选，在 D 的未用于该候选调参部分或明确 exposed repeat 上跑固定配对 | frozen protocol 与 pilot；选 0 或 1 个进入独立确认，不把重复当外部确认 |
| E4 独立确认 | 冻结差异在未打开 lineage 是否仍存在？ | 最多 1 个冻结候选 vs 冻结强简单 baseline；必要的已声明消融/近邻，不临时加臂 | all-attempt root 配对结果、不确定性、安全/成本与反例；不得确认失败后改合同重算成功 |
| E5 创新性判断与收口 | 值得保留什么、主张到哪、下一步做什么？ | 复算全部账本、有效性、因果、近邻差异和完整成本 | §17 决策报告，正/负/不确定均可；不自动发布、切 A0 或冻结 Schema |

E0/E1 不以某一机制先成功为前提。T3 若已经产生符合 E0 冻结条件的基线记录，可以作为已暴露资料复用；
必须注明来源、不重复算请求和独立样本；不同模型/输入/预算不能直接拼成同条件基线。
E1/E2 零候选可以直接进入 E5，E3/E4 标 NOT_TRIGGERED；不能为完成阶段编号继续消费。
G-TESTBED 未通过时，E0–E4 不得冒充已执行；可以交付有效性阻断报告，但整个“实验创新判断”仍未完成。

### 13.1 E0：普通笔记必须是强 baseline

- **N0**：§5 的无携带工作 Note，正常历史与工具仍可用。
- **N1**：§5 的普通自写 Note，冷启动公开读回并实际呈现。
- **N2**：与 N1 完全相同的 Note、来源和工具，仅增加一句领域无关提醒，例如：
  “历史笔记可能过时；请结合当前可核验信息完成任务，不足时核验或澄清。”
  提醒在结果前固定，不含对象、事件、当前答案、目标行为标签或特定失败修复。
- 每个 root/replicate 先取得一份共同 A，再派生 N0/N1/N2 的 B 世界；A 的执行/写入成本单列且只记一次。
  N2 的提醒不回溯改变共同 A，也不把写作政策差异混入消费比较。
- 首波在 2 个 D root、Stable/Superseded 两种可行世界、3 臂、1 次冷重复上运行。
  有效后按冻结顺序最多覆盖 6 个 D root，再补 Helpful/适用范围/未决 probe；不是直接全池全组合运行。
- 第一次正确动作、业务后置条件、重复工作、错误延续、新证据后的修正、保存/查询/生成成本分别记录。
  所有条件都没保存，或新证据没实际到达，则记 opportunity/acquisition gap，不报告 State 无效。

N0 不是待击败的唯一基线。候选主比较必须面对 N1/N2 中经 D 选择并在 E3 前冻结的强简单方案 S*；
若两者近似则选择更简单/成本更低者，并披露选择过程。禁止逐题挑表现较弱的一臂给候选当对手。

### 13.2 E1：开放策略，但固定证据记录

先根据 E0 的行为与成本图选择探索入口；允许探索连续性/效率，不要求先制造一批错误。
候选可包括不确定性表达、适用条件提醒、可逆暂停/恢复、选择性外部化、旧新理解并存、meta-memory、
联想不立即采信及其组合。这是可变候选菜单，不是需实现的模块列表，也不是必选 State schema。
若普通 Note 已足够，允许零机制；不得故意削弱 baseline、藏当前证据或加无解压力来制造需求。

每个候选版本发请求前记录：观察动机、预计影响的行为、具体 prompt/policy/code 差异、改变哪些信息、
新增模型/工具机会、运行 roots、资源与反证条件。发现后可以改版本，不回写旧 manifest。
首轮最多 6 个候选版本；每版先用 2 个 D roots 的适用配对世界，出现可解释现象再做第二次冷复验。
如有新方向，可关闭旧 discovery batch 后登记新的有界批次；不把一次开放授权解释成无限搜索。

State 保持自由文本/轻量 JSON，由 Host 生成；Runtime 不理解业务语义、不把建议升级为权限。
不裁剪合法反证、不做语义 Context projection；正常检索、按需读取与控制策略分别记录。
若候选增加角色/模型步骤，所有调用计入同一资源账；不是免费的 Reviewer，也不自动改多 Agent 产品架构。

### 13.3 E2：先拆解释，再决定是否值得叫机制

每个有趣 bundle 至少回答以下适用项：

| 拆分 | 必须排除的更简单解释 |
| --- | --- |
| 同信息、不同使用提示 | 收益仅来自多保存了一个关键事实，非控制政策 |
| 相同推理机会的普通复核 | 候选多一次生成/检索，所以更好；控制步骤本身未证明 |
| 去掉候选的关键组件 | 名为 park/resume 的模块可删除且效果不变 |
| 自由 Note / 一句提醒 | 只是改名或格式强制；模型本来已自然保留同样关系 |
| 同一冷边界与同源范围 | 收益来自 harness 多带了历史、其他臂丢状态或错误 scope |
| Stable + 更新/未决控制 | 通过永远怀疑或永远相信 Memory 获得单边高分 |
| 近邻最小实现/复现 | 已有方法可同样解释或达到该行为，只有新命名 |

不要求一开始做完整 factorial；根据候选差异选最有信息量的消融。
若删除组件没有稳定退化，删掉它，保留更简单版本；无增益也保留记录。
**同一 memory/evidence 下的消费比较**与**从 A 开始改变写作/维护的端到端比较**是两种 estimand：
后者要让各臂独立形成 Note、计全生命周期成本；前者不能声称 adaptive offloading 整体更优。
如候选主要改变检索所得内容，只能先称 acquisition/use 联合收益；必要证据已呈现的对照另测，不能直接归因为注意力。

E2 候选卡至少包含：
观察的 failure/机会、最小操作、作用时点、反证预测、强简单对照、消融结果、原始 run IDs、
适用范围、已失败版本、成本、安全风险、近邻差异与未解决混杂。可以选 0–3 个，E3 最多推进 2 个。

### 13.4 E3/E4：冻结后再做确认，不能把复验名称当证据

E3 默认每候选最多 4 个 D roots、至少 2 个 family，每个适用世界做 2 次固定冷运行；
优先跑 S*、最小候选、最有信息量的一个去组件对照。随机种子相同/temperature=0 的重复只测运行稳定性，
不当作新增独立观察。对结果不利的第二次不得删去或继续重复直到成功。

E4 前必须冻结 `confirmation_contract`，包括：

- 单一候选与具体版本、S*、主比较、近邻/消融是否纳入，以及每臂改变和不改变什么。
- 全部 root/lineage、world variants、重复次数、呈现政策、种子/顺序、实际模型/provider/tool 状态。
- 一个候选特定主指标、最小有用增益 `delta_min`、稳定性/任务成功/安全护栏、成本可接受边界。
  这些值依据任务损害与 D 结果在 C 打开前决定，不能最后挑最好看的指标。
- 评价/争议与缺失数据规则、主要统计单位、置信区间/配对方法、多重比较处理、停止/技术故障修复政策。
- 软件/世界/checker/来源 hash、最大请求/时限、实际输入长度与输出预约、最终/恢复机会。

E4 使用新 C 的全部已冻结合格 roots，默认每个 root/world 2 次冷运行；不看中间正确率决定加题或停在峰值。
按 root 给出配对胜/平/负、效果大小与不确定性，world/family 分项；不能把 4 worlds × 2 repeats 当 8 倍 N。
小 C 只支持有界复验；即使全部通过，未证明跨模型/领域普遍性。确认所需功效不足须标 INCONCLUSIVE。
多个候选/主指标的正式比较需在冻结时控制多重选择；探索性指标不得在结果后升格主指标。

安全越权/数据泄漏立即停发。纯基础设施问题可按冻结规则修复并重放配对臂，失败仍留总流程账；
若改变会影响语义的 checker/任务/模型/机制，原确认标失效/受污染，不能在同一 C 上继续报首次确认。
若缺真正未打开的 C，可交付 D 的机制筛选与确认缺口，不把新 seed 或实体改名伪装独立任务。

## 14. 指标、评分与因果判断的进一步约束

沿用 §7 的 Stability / Plasticity / stale action / Recovery / Continuity 和全流程分母。
另外记录 TaskSuccess、首次相关正确动作、无依据采信、无必要重检、重复业务动作、耗时与完整成本。
无依据采信需有可复核的行为/来源定义，不能从模型“想法数量”或一段解释直接推断。
所有探索结果明确标 EXPLORATORY；人工语义裁定说明是否盲于 arm、冲突怎样解决；Judge 默认仍为 0。

恢复是条件事件：不同政策的首次错误率不同，其“已犯错的人群”也不同。
不能只比较各臂各自出错后的恢复百分比就称候选有因果恢复优势；同时报告全部 root 的错误与最终修复结果。
若专门测试恢复能力，可预注册共同的环境偏离起点与相同纠正证据，单列为 recovery probe；
这不再证明该偏离由 Agent 自身 Memory 造成，也不增加自然记忆惯性的分母。

机制获益必须能在动作/外部状态中看到，不能只表现为字段更整齐、回执更长、State 更新更多。
候选让 Plasticity 变好但 Stable 明显受损，应报告 trade-off，而非宣称全面优越。
候选质量相同但成本高，不选复杂方案；质量明显改善但成本增加，可保留功能价值信号，
同时明确未证明经济回本。失败安全红线不因平均分提高而豁免。

## 15. 本地模型运行计划与预算合同

仍使用已获同意的本地 vLLM 路径。当前文档没有实际发请求；执行阶段根据下表生成批次 manifest，
测试创建与 G-TESTBED 通过后即沿 E0–E5 推进，不要求再写一个空白“未来实验”计划。

| 批次 | 默认规模/上界 | 不应自动执行的内容 |
| --- | --- | --- |
| V 模型兼容与 T3 | 兼容最多 2 次生成；T3 两 D root，Stable/Superseded，N0/N1，1 次冷运行 | 不取 gold 判断兼容性，不开放 C |
| B 基线 E0 | 首波 2D × 2 worlds × 3 arms × 1 次；最多扩大至 6D，补充世界另列 | 不同时全量跑 12–20 roots，不把 NO_WRITE 换题 |
| D 发现 E1 | 首批最多 6 个候选版本，各先 2D 的适用世界；有现象再做 1 次复验 | 不承诺全部候选都值得继续 |
| A 消融 E2/E3 | E3 最多 2 候选，各最多 4D，S* / 候选 / 1 个主要消融，2 次冷运行 | 其他消融先问它排除什么解释，不机械全组合 |
| C 确认 E4 | 最多 1 个冻结候选，完整冻结 C，S* 配对，2 次冷运行 | 候选失败不换另一个吃同一 C；无候选则 0 次 |
| J 评价 | 确定性 checker + 明确标注的离线语义复核 | 新 Judge / embedding / OCR / caption / 训练默认为 0 |

每个 cold Episode 起始机械上界建议为 **16 次生成**（含决策、记忆控制与最终交付），
其中预留末次交付和存在时至少 2 次纠正/恢复机会；有界任务确需更长时，先在 batch 冻结前调整为 32 并给出依据。
起始单请求等待 60 秒、Episode 时限 15 分钟，不能用原 native runner 的隐含 7200 秒冒充已限定。
工具动作数/并发、文件/数据库/网络资源也由任务合同限定；查询 timeout 不代表后台动作必然停止。
未走完任务因计数/时限被停，归资源截断，不归为 Memory use failure。

运行前以实际 requests/prompt 预检输入和输出容量；现有 provider 固定 `max_tokens=4096` 与模型身份等约束，
新配置若超出该合同，应先做一般接线修订和测试，再冻结双方同一 provider 版本，不在单臂静默修改。
不得用不断重复 schema/历史耗尽 context，然后称复杂 Memory 无效；共同 plumbing 修复要两臂一起回归并保留旧失败。

按已列 cold Episodes 计算而非拍定累计 token 数：
`max_requests(batch) = compatibility + Σ episode_generation_cap`。
例如 E0 首波共享 2 个 A，加 2×2×3=12 个 B；16 上界时为至多 224 次生成，
这是**预约上界，不是预计都要消费**；可复用的 T3/A 记录扣除一次并列清单。
后续重复/额外保存/近邻的生成一律计入相应 Episode 或显式控制调用上界，不藏在工具里。

初始仅一个根实验在途，公共 source/tool 独立读最多 4 并发；本地模型生成初始串行，
待测得资源余量并登记容量后可放宽到两个隔离 root。此处是实验调度，不限制 MiLAi 多用户服务并发。
每批开始登记请求数和墙钟 deadline，耗尽即结算；是否开下一有界 discovery 批按证据决定，
而不是因为累计 token 无上限就无限运行。未知用量未结算时不自动重试模型或重复业务写入。
用户强调的 **累计 raw-token 硬上限保持 null，功能与研究有效性优先、token 最后优化** 不变。

## 16. 创新性核查：实验增益与 prior art 差异是两个轴

实验只能检验效用与机制解释，不能单靠 accuracy 证明“首次提出”。
E2 在候选内容明确后补全文/代码核查，E4 后刷新一次；保存检索日期、论文版本、实现 revision、
相同点、真实差异和仍未找到的证据。当前只能做有界近邻核对，不声称穷尽全部工作。

2026-09-10 本次核对的官方摘要提供以下最低约束；不沿用论文分数作 MiLAi 同条件比较：

| 近邻 | 已覆盖的宽泛主张 | 候选应回答的差异问题 |
| --- | --- | --- |
| [Remember When It Matters v1](https://arxiv.org/abs/2607.08716v1) | 独立 Memory Agent 更新 bank，决定提醒或沉默 | 若只增加主动提醒，区别在哪里？单 Host 的成本优势需实测 |
| [MemoBrain v1](https://arxiv.org/abs/2601.08079v1) | 依赖感知的 executive memory 与工作上下文管理 | 仅把“执行记忆”改叫 Control State 不构成新机制 |
| [StateMem v1](https://arxiv.org/abs/2608.19652v1) | 显式 supersession、关系依赖及已有 memory 的轻量 wrapper | 仅更新状态或保留关系不是新点；控制行为/冷恢复差异需消融 |
| [RuleMem v1](https://arxiv.org/abs/2609.03915v1) | 历史归纳规则用于证据检索与推理 | 规则提示的候选是否只是更简单复现，是否真有独立新作用 |
| [MEMO v1](https://arxiv.org/abs/2609.07471v1) | query-conditioned evidence 选择、模态/布局组织 | 本研究不做语义 projection；“不做 projection”本身也不是新颖性 |
| [The Compliance Trap v1](https://arxiv.org/abs/2607.10608v1) | E-P-R 轨迹级 memory consumption 诊断 | 测试床不能声称首次研究记忆影响/传播/恢复；新增可核验链与评价有效性是什么 |

以上差异问题是研究推断与待验证问题，不是这些论文“没有某能力”的排他证明。
若候选落在关联/发散等其他方向，按候选重新查直接近邻，不因不在本表而默认新颖。

有信号后至少选一个直接近邻作为比较对象：优先可复现官方实现；若资源/许可不适配，
可以做披露删改的概念级对照，但不能标官方复现，更不能据此宣称优于完整原方法。
若一个直接近邻复现是建立相对主张所必需且本轮未完成，则创新判定保留该缺口。
不因研究近邻就把第三方 memory store 接成 Product 默认。

分开判定两类潜在贡献：

- **机制贡献**：最小操作改变了可评分行为；强简单 baseline 和等推理机会解释不足；
  消融支持操作有作用，未打开 lineage 仍有信号，且与最近邻有可陈述的非命名差异。
- **测试床/方法学贡献**：外部任务派生、可观察行为真值、反例校准、真实冷持久与配对世界确实形成可复现新覆盖。
  需要说明相比 E-P-R/现有 benchmark 多测了什么、适配丢掉什么；“自己造了一个 checker”不自动成为贡献。

人类/ADHD 只保留为启发，不从这些工程实验推断人脑机制或临床效果。
普通 Note/简单提醒胜出时，保留简单方案；这是有效研究决策，不是为了论文必须继续造复杂机制。

## 17. 创新性决策、完成条件与产物

### 17.1 最终结论等级

| 决策 | 至少需要的证据 | 允许主张 |
| --- | --- | --- |
| BASELINE_SUFFICIENT_IN_TESTED_SCOPE | 有效 E0 未显示需干预的失败/成本机会，E1/E2 明确记录零候选动机 | 保留简单方案；没有运行复杂干预，不声称已证明所有候选无增益 |
| KEEP_SIMPLE_NO_CANDIDATE | 有效 E0、完成有界候选实验/筛选，本批复杂候选无稳定优势 | 关闭当前候选/任务范围，保留简单方案；不泛化为所有 State 无效 |
| ENGINEERING_GAIN_ONLY | 行为改善来自取得、接线、交付或同信息提醒，未有独立新机制依据 | 有用工程结果，不包装成认知创新 |
| PROMISING_NOT_CONFIRMED | D 上有作用与消融线索，但 C/直接近邻/功效不足 | 有候选值得进一步验证，不称创新已成立 |
| BOUNDED_MECHANISM_SUPPORT | 主比较的增益与不确定性满足预冻要求、关键安全/稳定护栏不过界，C 与消融支持，近邻差异清楚 | 支持明确模型/任务/profile 下的机制贡献；不自动外推产品和普遍性 |
| TESTBED_CONTRIBUTION_CANDIDATE | 无机制胜出，但测试床覆盖、评分有效性与复现差异有证据 | 测试床贡献候选，须外部复核，不替代机制成绩 |
| INCONCLUSIVE / VALIDITY_BLOCKED | 有效分母、评分、呈现、样本、资源或独立性不足 | 说明没有足够证据作创新判断；不说机制失败或验收已完成 |

多个标签可分轴共存，例如 KEEP_SIMPLE + TESTBED_CONTRIBUTION_CANDIDATE。
不能预设 BOUNDED_MECHANISM_SUPPORT 为必须达到的结果。

### 17.2 全 Goal 的完成判据

1. 建设阶段有实际可执行产物和 G-TESTBED 证据，不能只靠单测通过。
2. 已运行 E0 的有界强简单基线，记录真实写入/呈现/动作及全流程分母。
3. 已完成一批 E1/E2 开放发现和筛选，或用有效 E0 证据出具 E1/E2 零候选评议，说明未发现值得干预的机会；
   后者标 BASELINE_SUFFICIENT_IN_TESTED_SCOPE，不冒充复杂干预的负效应实验。
4. 有合格候选时按冻结合同执行 E3；是否进入 E4 有明确判定。无候选不强跑确认；
   独立确认不足时可收口为“候选未确认”，不得收口为机制已证明。
5. E5 出具带原始 run/hash 索引的创新决策报告，包括负例、因果/近邻缺口、成本和下一步。
6. 账本全部结算或明确未知及影响；本批自有服务安全停止、证据保留，A0/公开部署/Schema 不变。

只有 T0–T5 完成时，**整个研究 Goal 仍未完成**。
零自写/零双呈现只允许有效性报告，不把 E1/E2 自动记为零效果已完成。
研究可以有边界地得到负/不确定结论；未执行必需实验、请求仍未知或缺少创新判断报告，不能因为用量大就标完成。
