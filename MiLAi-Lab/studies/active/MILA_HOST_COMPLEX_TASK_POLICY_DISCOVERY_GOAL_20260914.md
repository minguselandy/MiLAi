# 复杂任务上的工作区调控方法探索 Goal

## 1. 本轮要改变的不是定位提示，而是求解政策

**目标：利用复杂任务的真实反馈，发现能够跨任务复用的求解政策：保留仍有效的工作，修订受影响的判断，按当前需要展开细节，并改善下一步选择。**普通 Note、同调用 review 与候选共同发展；工作区是方法的载体，跑完任务表不是方法发现本身。

不再追加内部长尾定位题、R/EXPLAIN 数字复测、FULL/NO_HANDOFF 文本消融或无损 Note 接线实验。它们的历史结果保留，但不再充当本轮创新探索的主任务，也不作为复杂任务启动前的资格门。

本文件是新的待执行研究合同；本次只更新文档，未启动模型、容器、服务或回归。旧 Goal 已关闭的请求余额不转入本轮。执行时按波次记录实际配置和预算，而不是把下文规划上界当作已经获得的执行结果。

开发固定权限、输入来源、真实动作结果与账务；**不冻结认知流程**。允许修改提示、记录表达、选材方式、任务顺序和机制组合。每次变化留下版本与理由，不要求所有任务表演“暂停—恢复”，不要求 baseline 先稳定失败才允许候选探索。

**方法应该泛化，运行中的 State 应该具体。**通用政策不规定各任务采用相同判断或步骤；它让 Host 从当前任务和反馈中形成适用的记录。`REGULATED_0` 只是起点，其初始规则可以被修改或删除，不是必须保住的答案。本次 v1.1 在原 Goal 内调整方法定义、迭代迁移和贡献判读；不新增任务清单、准入门或预算。

## 2. 首个方法：证据驱动的可逆工作区调控

暂名 `REGULATED_0`，是可替换候选，不是已成立的新算法。优先假设为：**面向后续决策的依据记录 + 按影响范围修订 + 按工作需要调整材料粒度。**研究对象是历史判断如何持续影响下一动作，以及新反馈应改变其中哪一部分。

在正常 Host 调用中，同时产生下一动作与可选工作记录更新：

```text
当前目标 + 新工具结果 + 可见历史/来源 + 上一份工作记录
    → 同一 Host 正常决策
    → 可选记录修订、后续材料选择、下一工具动作或交付
    → 原生环境实际执行
    → 新结果进入下一轮，并可推翻记录
```

记录仍是自由文本及来源引用，不加入认知 enum、分支树、打分器或 Runtime 语义裁决。记录是可错的工作产物，不要求输出完整思维过程。

### 2.1 可产生实际行为差异的政策

1. **保留当前承诺的依据和范围。** 不只写“做过什么”，还记下什么结果支持当前路线、哪些约束仍未检查。任务简单时可以不记或不更新。
2. **允许低门槛新线索，但不自动采信。** 类比、失败经验和替代解释可以暂留；想起它不等于立即查它，更不等于接受其结论。
3. **按影响范围修订行动依据。** 新反馈只否定局部时，缩小、拆分或撤回受影响判断，保留仍有依据的部分；必要条件不再成立，应停止照搬，不必等找到新方案才撤回旧方案。暂时不适用、执行失败、事实错误与目标变化不能一概处理成“整个旧方案失效”。
4. **用反馈调整探索宽度。** 初期允许理解接口、复现问题和开放调查；预测落空、约束冲突或路线受阻时考虑替代路线。已有证据足以行动时收敛，不规定每轮几个假设或几次失败后换支。
5. **保留返回入口，再检查而非自动恢复。** 旧路线可能重新有用时，先核对当前条件与目标。复查条件不是封闭清单，也不是自动执行触发器。
6. **按当前需要调整细节，并与下一轮输入实际耦合。** 未决工作可保留具体条件和结果，暂时稳定的部分可退到结论范围与可读入口，需要时重新展开；不默认越短越好或每轮压缩。新观察、当前用户要求、工具回执与未完成交互始终受保护。

首个候选允许把上述政策与实际工作集选择作为一个 bundle 同时尝试。**不要求先在 COMMON_CONTEXT 胜出。**如果只在组合条件下有收益，先报告组合收益，之后再拆记录形成、消费与选材的贡献。

### 2.2 从求解困难到可迁移的更新规则

以下是待检验假设，不是三个必须开发的模块，也不是给 benchmark 注入的解题提示。具体约束和依据只能由 Host 从共同可见任务与真实结果中识别。

| 真实轨迹中可能出现的困难 | 候选改变的操作 | 迁移预期与反证方向 |
| --- | --- | --- |
| 记录复述了过程，却丢失“为什么选它、验证到哪里” | 记录选择以支撑后续决策为目标，保留依据、覆盖范围和未决条件，而不以复述所有历史为主 | 调试后更少破坏已确认要求，数据处理中更少重建来源选择依据；若同成本下选择与工作质量不变，则无增量 |
| 一次新失败导致全面推翻，或局部通过被扩大成全部成立 | 按新结果影响范围修订，保留仍成立部分；未知影响允许继续查证 | 从边界测试失败迁移到局部来源冲突、外部条件变化；若只是少检查而漏掉实际依赖，则该规则失败 |
| 摘要丢失当前关键细节，或旧正文长期占据输入 | 按下一决定需要选择细节与展开来源，不固定摘要长度或强制正文退出 | 从调试错误细节迁移到数据样本、服务返回；若节省 token 却增加错误或重建，总体不保留 |

“保留仍有效”不能机械等于“没有明确反证就继续信”。代码、数据版本或环境依赖发生变化时，先前测试结果的适用性也可能失效；无法确定影响范围可以扩大复核。范围判断本身由 Host 完成，允许被后续反馈纠正，代码不按关键词/任务 ID 推理依赖。

**内层适应**是同一模型、同一政策在运行中更新 State 与行动；**外层改进**是研究者看轨迹后修改政策或实现。两者分别记录，不能把逐题调提示称作 Agent 自主适应。当前不接自动提示优化器，也不为迭代增加独立反思 Agent。

### 2.3 与上一轮的本质差异

| 上一轮 | 本轮 |
| --- | --- |
| 读固定测量、生成定位交付 | 操作原生代码、数据或服务，多轮接收自己动作的结果 |
| 形成稿之后有/无一段交付 | 每一步都可能修改记录、调查路线、实现与验证选择 |
| `focus_refs` 没有参与后续实际工作 | 选择的历史材料确实影响后续工作集，原材料仍可合法取回 |
| 逐项定位判断和文本措辞 | 原生任务产物/测试结果为主，关键选择和完整成本解释差异 |

若工作区再次始终为空，仍报告完整任务成绩；另查明该通道是否被使用。允许在下一开发版本明确鼓励形成续接记录，或调整同调用输出方式，**但不能免费代写目标记录、强迫通过写入资格门，或把未使用的控制通道称为已经验证的机制**。连续两版没有实际政策差异，应更换可检验的操作差异，而非继续消耗同题复测。

### 3.1 主数据集：Terminal-Bench 2 固定任务快照

这些任务名称均来自固定仓库；例如[并发任务合同](https://raw.githubusercontent.com/harbor-framework/terminal-bench-2/2fd12b88aafdd04a52c298e3940bcb189f9766d6/cancel-async-tasks/task.toml)与[多来源合并说明](https://raw.githubusercontent.com/harbor-framework/terminal-bench-2/2fd12b88aafdd04a52c298e3940bcb189f9766d6/multi-source-data-merger/instruction.md)已核对。候选全部列明 CPU 环境、GPU=0；财务文档任务还需可用的文档/OCR工具，不能假装文本模型已经看到图片内容。

第一组三臂从 `cancel-async-tasks` 开始；原生环境若不可用，按同组预列顺序换至可用任务，留下环境失败原因。后续两组各完成一个任务后即可开始比较行为，不等待 12 个全部就绪。不得按候选胜负选题；基础设施不兼容可替换，已取得的模型失败不可消失。替换后更新清单版本，缺少配对按未完成报告。

Git 部署两题等可能存在近缘任务，应合并相应 lineage/模板簇报告；12 个 task id 不自动等于 12 个独立统计样本。原生任务如果没有条件恢复机会，就不报告 reactivation 指标；也不为展示机制擅加一个“现在恢复”的阶段。

任务用途随**政策版本**区分为“参与该版本修改”和“仅检查该版本迁移”。只需在已有运行清单注明，不新建密封池。在一组形成规则改进后，优先把不变的核心政策带到另一组；目标任务只改工具/来源映射，不加入专用求解步骤。若随后根据目标轨迹修改政策，该任务即成为后续版本的开发依据；保留首次迁移结果，不能将修订后成绩追认成未调试迁移。读过 metadata 的任务可以提供开发迁移证据，但不称独立确认。

## 4. 三臂：方法从第一天与强简单方案一起跑

| 臂 | 政策差异 | 共同能力 |
| --- | --- | --- |
| NOTE | 常规求解与自由笔记，不额外要求认知调控流程 | 当前任务、普通历史、原生工具、合法来源、可选记录与材料选择 |
| REVIEW | 每次正常决策中结合当前反馈复核旧判断、约束与实际完成情况 | 同上；不另起 Reviewer、不故意多一次模型调用 |
| REGULATED_0 | §2 的依据/适用性/可逆返回政策，允许组合使用实际选材 | 同上；额外记录、读取、检索与失败尝试全部计入成本 |

三臂同模型、解码设置、任务初态、工具权限、动作接口及资源上限；普通臂可以自然写条件、暂缓、复查和选材，不能禁止它们“想出候选的做法”。原生 instruction 与当前要求保持相同角色和位置；候选没有更强的授权提示或免费未来信息。

**默认保留装得下的普通历史与原材料。**候选可以主动让旧正文退出当前工作集，这是显式研究处理，不是所有臂预先被迫的遗忘。各臂有相同的管理能力和可恢复来源入口，默认和实际选择都记录。若比较同时改变政策与默认工作集策略，标为 bundle；COMMON_CONTEXT 是可选拆解，不是前置胜出门。

各臂产生不同操作后，环境返回各自动作的真实结果；共同的是初态与规则，不是强制输入正文始终相同。不向错误动作播放专家正确动作的结果。失败输出、超时和无记录尝试都进入全尝试账。

初期进程内记录即可，不要求先通过自主 Note 写入、真实冷持久化或旧 A–E 链。多步效果不能冒充跨会话效果；确实执行了公开保存/冷读取后，才另报持久能力。

三臂共用新 Host，首先只支持这个 Host 内的政策比较。首个原生入口可用后，可在一至两个已列任务上加入 [Terminus-2 原生参照](https://www.harborframework.com/docs/agents/terminus-2)，检查自建输出外壳是否妨碍正常任务，格式负担或全臂异常失败时优先使用；不为每题增设第四臂或新准入门。使用相同可支持模型、任务和合理资源口径，差异记为系统级而非纯政策效应。该参照可能触发额外摘要调用，必须按固定版本实际记录全部调用与成本，不预设零开销，也不将额外调用移植成 REVIEW 的强制负担。所有参照消耗占 §6.2 既有预留，不增加预算。

## 5. 最小开发落点：一条原生任务桥接，不再造测试床

复用 [workspace_policy.py](../../src/milai_lab/methods/workspace_policy.py)、[workspace_policy_host.py](../../tools/workspace_policy_host.py)、[Provider](../../tools/workspace_task_provider.py)和现有三份政策。新增一个 Harbor 外部 agent 入口，在公开 `BaseEnvironment` 中执行终端动作，任务结果交还原生 verifier。入口名称和具体签名以安装并固定的 Harbor 版本为准，文档不冒充已有 API。

需要原生 tool-call 消息时保留其完整成对协议；不能将它们塞进当前仅支持文本 JSON 的 hooks 后声称无差异兼容。优先选择当前 Provider 已支持的单调用动作+工作产物形式。不得为这个适配迁移整个 Host、引入多模型路由或重建 action Schema 体系。

必要接线检查仅回答：能否执行一个合法命令、取得真实结果、运行原生 verifier、将本轮记录/选材传入下一调用。已有可复用测试直接复用；环境安装按官方方式进行，已验证静态制品不在每一步重新扫描整库。

若模型编码遇错，只通过正常可见错误反馈尝试修正；每次生成和重试计费。不自动重放状态未知的动作，不为可选记录错误重做已成功业务动作。可恢复的格式错不要求整个研究重过几十项门；泄露、越权或不明副作用则停止受影响执行。

隔离由标准任务环境提供。不得运行 privileged 容器、挂载宿主工作区/凭据/容器管理 socket 给模型，或把容器内服务暴露公网。模型凭据留在可信 Host，benchmark 命令只能作用于隔离任务。可按官方任务需要安装依赖/使用受限网络，不能修改共享 vLLM 或直接操作 GPU。

接线开发超过一个工作时段仍没有第一条原生复杂轨迹，应报告具体阻塞和最小替代接入方案；**不能再以旧定位题或 CPU 回归数量作为本 Goal 的主要交付。**有真实权限缺口再请求方向，不绕过隔离。

## 6. 开放探索循环与资源安排

### 6.1 先看真实轨迹，再选择下一次修改

1. **首个任务三臂，找实际困难。** 完成最小接线后立即做完整原生任务；不预先跑 oracle 意图矩阵，也不等所有任务或全回归结束。看任务产物、行为分歧和不必要工作，而不只查工作区是否非空。
2. **从困难提出通用规则，立即检查迁移。** 出现可解释问题就修改候选，并带到另一任务组，不等待第一波六题跑完。例如“局部失败后丢失仍有效要求”可导出范围修订规则，再在另一组检查局部冲突处理；这是迁移假设，不是给目标任务提供答案。目标任务先固定该版本，与相同工具下的简单政策比较。
3. **在第一波内迭代，最多两轮实质修订。** 第一波最多 18 条主轨迹，修订重跑计入预留。允许组合改变，只重跑有信息价值的对照。臂顺序轮换，无自动 best-of；各版本和用途分列，不汇总每题最好政策作为一个方法。
4. **用预列扩展任务检查选定版本。** 不按首波胜负替换任务；优先保留核心政策，工具/来源适配与语义改动分开。开发暴露不追认为密封确认，迁移中发现新问题仍可回到外层迭代，但不能抹掉原结果。
5. **按信息价值拆解或跨来源。** 组合有信号才选择最有用的消融；ClawMark 迁移不要求候选先赢。没有可检验的新解释时停止当前版本，不用相同输入抽取偶然优势。

每次修订在现有运行说明里写一段即可：**观察到了什么具体困难 → 改变哪种通用更新操作 → 为什么可能迁移 → 下次在哪个不同任务检查**。仅增加“更仔细”或任务专用答案不算方法进展。不增加模板服务、自动优化平台或认知模块；有用的规则可以少于初始设计，甚至最后只剩普通 review 与来源索引。

以上是迭代安排，不是 5 个新的 PASS Gate。候选可以失败，baseline 可以失败，局部问题可以修；但未完成的配对、未运行的第二来源不能签发完成。

### 6.2 规划上界，不是必须消耗的额度

| 工作 | 轨迹规划上界 | 每轨迹模型生成上界 | 调用上界 |
| --- | ---: | ---: | ---: |
| Terminal-Bench 第一波：6 × 3 | 18 | 64 | 1152 |
| Terminal-Bench 扩展：6 × 3 | 18 | 64 | 1152 |
| 规则修订、复测、拆解或原生参照，合用预留 | 12 | 64 | 768 |
| 条件性 ClawMark：2 × 3，全阶段合计 | 6 | 128 | 768 |
| **全部规划上界** | **54** | — | **3840** |

第一波中的首个三臂已包含在 18 条内，不重复计费。跨组迁移优先使用未运行的主清单位置；重复、接线模型调试、原生参照或外部政策移植占 12 条预留，不另设隐藏账户。ClawMark 的 128 是整个任务全部阶段之和，不是每阶段重新获得 128。54 条轨迹/3840 次生成仅为规划天花板；是否继续由下一轨迹能否改变方法判断决定，不为填满表格消耗位置。

64/128 是宽松开发保险丝，不是认知步骤要求或“复杂任务应在多少步解决”的结论。优先沿用原生 task 时限；若当前服务吞吐需要时间倍率，在新波次开始前对所有臂统一写明，另报本地配置成绩，不能在候选将超时后单独延长。若所有臂普遍被限额截断，应先报告截断，再前瞻调整相同预算；不通过缩短任务或隐藏未完成来制造收益。

仍沿用已确认的容量原则：启动时读取实际 Provider/model 配置，当前历史实测窗口为 65,536；不照搬通用代码的 8192/512 默认值。输入上界由实际窗口减真实输出预留得到；初始输出预留可沿用 4096，任务需要变更时整波共同调整。可见工作记录长度是软建议，**不因超过 512 就拒绝业务交付**，不填满窗口，不为候选切掉 baseline 关键历史。

不新增累计 raw-token 硬门，也不把“模型支持 65k”理解成每轮必须用 65k。按每波实际输入/输出、生成次数、工具用时、环境准备与复核成本记账；启动下一波前根据已发生用量更新预计剩余成本。不一次自动排满 3840 次请求。

模型实验只走现有授权的 vLLM HTTP；模型/endpoint 确认不涉及 GPU 诊断或共享服务重启。默认串行，已有容量允许时再有限并发。未知生成用量或状态不明时停发并保留记录，不自动重试。环境准备、原生 verifier、代理开发成本与模型账分列。

## 7. 效果评判：先回答工作是否做得更好

下列维度分别依据已有任务结果和轨迹解释，不合成“创新分数”，也不各建一个评分器：

| 判断 | 所需证据 | 不足以支持它的情况 |
| --- | --- | --- |
| 有效性 | 强简单对照下的原生任务结果、约束与全尝试成本 | 记录更漂亮但行动与结果不变 |
| 运行适应性 | 固定政策下，新反馈引起恰当局部修订，并保留仍有效部分 | 开发者逐题改提示；一有新消息就全部推翻 |
| 泛化性 | 同一核心政策迁移到未用于该版本调试的任务/问题组 | 每个任务专用政策的最优结果汇总 |
| 接口适配性与可用性 | 换环境主要改变工具/来源映射；正常动作不被维护开销拖累 | 为每个 benchmark 重写求解流程或人工整理理想记录 |
| 创新性 | 对近邻方法有具体操作差异及独立、成本可解释的收益 | 自由文本、新名字或一次击败 NOTE |

### 主结果

- **原生任务结果**：成功与否、原生 reward、独立子条件、实际文件/服务效果。原生单分数和复核争议分列，不把最终正确掩盖早期错误副作用。
- **完整代价**：所有输入/输出 tokens、模型调用、工具操作、耗时、失败重试；工作记录生成/维护、主动重读与额外选材都计入。相同成功任务的成本和全尝试成本都报，避免只选择便宜成功样本。
- **分组配对结果**：各 root 三臂结果、胜/平/负、版本和停止原因。按原始任务/近缘簇解释，不把每个工具步骤、checker 或重跑当独立样本。

### 用于解释差异的轨迹审阅

围绕真实行为选关键时点：是否忽略仍有效的约束，是否将局部测试通过误当整体完成，是否重复没有新信息的失败尝试，是否在新结果出现后合理换方向，是否恢复了仍有用的旧路线。必要验证、缓存失效后的重读不是浪费；产生假设也不等于采信假设。

同时查看记录和输入变化，但**不按 State 字数、分支数量、指定关键词或“我反思了”给分**。只对实际出现的机会报告分母，先前没有错误就不算 error recovery；原生任务没有条件恢复也不硬算 reactivation。

每个臂保留输入、动作、真实结果、工作区、实际展开来源与原生终态。开发者按固定问题审阅匹配成功、匹配失败和分歧轨迹，尽可能隐藏臂名；不能只展示候选最好的一条。首轮不默认用 LLM Judge，native evaluator 有疑点时复核受影响产物，不增加反复补评调用。

### 可能的结论

| 观察 | 解释与下一步 |
| --- | --- |
| 多个原始任务质量改善，成本可接受 | 保留候选、做最小拆解和迁移；仍是开发信号 |
| 成功率相近，但少重建/少无效尝试且总成本下降 | 保留效率假设，检查稳定性和成本归属 |
| 只有 managed bundle 改善 | 报告记录+选材组合，不归功于某句暂停规则 |
| REVIEW 同样好且更便宜 | 当前工作点保留 REVIEW；没有独立机制收益 |
| 工作区不同但行动、产物、成本无增量 | 删除无用部分；有具体解释再修，不以“写入成功”结项为研究成功 |
| 全臂失败或全臂轻易成功 | 报告完整结果，判断能力/难度/机会；可前瞻换研究条件，不能按候选胜负筛数据 |
| 执行环境失败 | 与方法失败分开，保留未完成项；不把它改写成 Memory 失败或机制探索完成 |

## 8. 创新性评判：从组合收益收缩到最小贡献

“自由文本”“Host-owned”“可逆”“聚焦”都不是自动成立的创新。首批不要求先完成全面查新才能跑，但提出贡献前必须说明与普通 review、已有适用性/工作记忆/上下文管理方法的操作差异。近邻来源沿用[设计文档](MILA_HOST_WORKSPACE_POLICY_DESIGN_v0.1_20260913.md)，实际纳入外部政策前重新固定原文、许可、版本和成本，移植不冒充完整复现。

按实际起作用的操作选择近邻，不等全部开发结束才核对，也不先集成一排名为 Memory 的系统：

| 近邻 | 已覆盖的相关方向 | 本候选要进一步回答什么 |
| --- | --- | --- |
| [HiAgent](https://arxiv.org/abs/2408.09559v1) | 以子目标组织工作记忆、保留当前相关轨迹并摘要历史 | 依据与覆盖范围记录，是否比普通子目标/进度摘要有增量 |
| [AgentFold](https://arxiv.org/abs/2510.24699v1) | 学习主动、多尺度整理历史上下文 | 按决策需要选择细节的操作差异是什么；提示型实现不能冒充其训练方法 |
| [MemR³](https://arxiv.org/abs/2512.20237v1) | 证据缺口跟踪与检索/反思/回答选择 | 是否超出一般缺口驱动，真正改善了行动依据的局部修订 |
| [ACE](https://arxiv.org/abs/2510.04618v3) | 通过生成、反思和整理，增量维护可用策略上下文 | 当前任务内的影响范围修订与经验上下文维护有何操作差异及收益 |

这些是论文层面的近邻定位，不是可运行 baseline 认证或文献空白证明。选中相关操作后，先写清“何时、用什么反馈、改变什么记录或动作、比现有方法多了什么”，再选择最轻可比移植；其调用和形成成本计入既有预留。删去训练、状态或额外调用的移植必须说明差异，不能直接套用论文成绩。

有可解释信号后，从下列选择最多两个必要拆解，不预设全部都要完成：

- **同信息 REVIEW**：仅使用当时已产生的内容，不向过去回填未来记录；检验是否只是有用记录内容，而非特殊消费政策。
- **保留政策但不跨步继承记录**：检查记录连续性的增量，必要重建成本照计。
- **保留记录，取消主动工作集选择**：检查是否主要是上下文选择收益。
- **去掉暂挂原因/复查依据**：只在任务有真实返回机会时检验，不能强造恢复事件来证明必要性。

同信息 REVIEW 打平时，优先删除无用的特殊消费规则，继续单列记录形成规则是否有价值及其成本；不因此宣称形成与消费都无效。取消跨步继承仍打平时，收益可能是当前回合求解政策，而不是 State 连续性。固定记录消费只能在相同、当时可获得的环境/历史处比较，不将候选后续特有结果免费送给另一条已分叉轨迹。消融用于删减方法，不为每个部件另造一道证明题。

候选先与简单方案共同探索，不以 R1 必须失败作为入口；独立创新主张则必须击败最强简单方案，或证明相同可靠性下的真实生命周期效率。小样本差异、同输入波动与开发挑选不能称确认。跨来源和公开冷持久化只在确实运行后报告，不用首轮多步成功代替。

## 9. 固定边界、灵活开发与交付

允许：版本化修改政策与可见工作产物、使用已有管理能力、按实际需求调整整波共同容量/预算、选择复杂任务的合法工具、删除无效模块。组合改变可以探索，但按组合解释。

不允许：任务答案写入政策，按 task id 硬编码语义，改 verifier 让候选得分，查看隐藏 solution 后给候选暗示，给 REVIEW 增设独立高成本 Agent，静默丢失失败，用缩短上下文制造优势，改 Runtime 语义权限或真实产品默认。

工程检查服务于可用性：代码更改先做邻近测试和原生入口 smoke，安全/账务成立即可开展有界开发轨迹；完整代码交付按 [AGENTS.md](../../AGENTS.md) 完成边界、pytest、ruff、mypy、build。纯提示/任务清单迭代不每次重跑耗时全库；本次文档变更只做链接/格式与计划一致性检查。静态依赖审计不嵌入每轮模型决策。

最终交付围绕最小有效规则，而不是矩阵完成率：

1. 一个接到原生复杂环境的可替换政策原型；
2. 一份任务/版本/配置清单及完整原始轨迹目录；
3. 一个原生效果、关键行为与完整成本的三臂结果表；
4. 一份最小规则结论：发现了什么通用更新操作、在哪些非调试任务检验过、何时没有必要或失效、维护代价多少，以及哪些初始部件被删除；没有找到有价值规则也如实记录。

执行目标是形成“真实困难—规则改进—同版本迁移—保留或删除”的可解释证据。第一波六题及扩展是可用资源，不是每轮必须跑满的结束条件。若关键问题已得到有依据的回答或已无值得继续的假设，可有界收口并列出未运行位置；运行失败只报告阻塞/停止，不以工程通过替代研究。没有迁移证据就不宣称找到跨任务方法，没有净收益也不强选候选。**主要交付是规则及其适用边界，结果表是依据；既不要求创新必然存在，也不以未用满配额判作研究失败。**
