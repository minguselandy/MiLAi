# 复杂原生任务上的政策探索

执行[研究合同](MILA_HOST_COMPLEX_TASK_POLICY_DISCOVERY_GOAL_20260914.md)。这次已经接入真实 Terminal-Bench 环境、执行模型选择的终端命令并调用原生 verifier。结论为 **KEEP_SIMPLE**：保留普通 NOTE/REVIEW，未找到值得默认启用的可迁移候选规则。普通 NOTE 在首题全通过，复杂候选反而陷入重复；精简规则在源任务上减少重复，却未迁移到数据库恢复。三组主比较、两次修订及两个原生参照尝试均已结束，全部工程检查已取得终态。本次是有界研究收口，数据库未评分尝试、参照验证器失败及跨来源未完成不被追认为效果验证成功。

配置与版本见[运行清单](../../data/manifests/workspace-complex-native-20260914.json)，评分有效性与成本见[精简结果](../../data/results/workspace-complex-native-20260914.json)；[完整证据目录](/cra/memory/mx_memory/evidence/workspace-host/complex-native-20260914)包含每次实际模型生成的 HTTP 请求、原始响应、用量账本、终端回执、Host 输入、工作区前后状态、原生测试、产物及失败。各波 `implementation/` 保存实际代码和政策快照；[机器汇总](/cra/memory/mx_memory/evidence/workspace-host/complex-native-20260914/native-summary.json)由原始记录生成。

## 原生入口与共同条件

上游任务固定为 Terminal-Bench commit `2fd12b88aafdd04a52c298e3940bcb189f9766d6`。官方归档中的 948 个非 solution 文件逐个匹配该 commit 的 Git blob hash；没有阅读 solution，也没有把研究者看到的 metadata、verifier 或答案放进模型输入。Harbor 固定 `0.23.0`，许可证 Apache-2.0，独立 Python 3.12.11 环境及依赖锁留在仓库外。

[终端会话](../../tools/workspace_terminal_session.py)、[外部 agent](../../tools/workspace_harbor_agent.py)和[运行入口](../../tools/run_workspace_native.py)复用既有 WorkspaceHost、工作区钩子、tokenizer 与 Provider。模型代码只经公开 `BaseEnvironment.exec` 在任务容器中执行；没有宿主裸跑、额外解题模型或自建语义 checker。[Harbor 官方外部 agent 接口](https://www.harborframework.com/docs/agents)

共同模型为现有 `Qwen3.6-35B-A3B-FP8`；启动时实测窗口 65,536，输入保护上界 61,440，输出预留 4,096；temperature=0、top_p=1、seed=213、thinking=false。沿用原生 CPU、内存和 900 秒 agent 时限，零 GPU；串行模型调用。所有臂默认保留可容纳的历史，均可主动选择工作集、读回原始回执、写或不写记录。没有强制 K 遗忘、512-token 业务交付门或累计 raw-token 硬门。记录的独立机械容量为 2,944 tokens；单次终端回执初始展示最多 16,000 字符，并提供完整回读。

预构建镜像因 Docker Hub 连接超时不可达，改用原始 Dockerfile 本地构建，基础镜像从可达镜像源取得并记录 digest。Docker 默认地址池耗尽后，仅给本轮临时网络指定与现有网络、路由不重叠的子网。实际容器审计确认无特权、GPU、公开端口或非试验日志/产物挂载。没有清理共享网络或修改共享服务。因此本报告是**本地重建环境的原生评分**，不是官方预构建镜像排行榜复现。

三次零模型 smoke 的结果分别是镜像拉取失败、网络池耗尽、原生 `pwd` 成功且未实现任务获 verifier 0 分。失败均保留。首次三臂中 NOTE 与 REGULATED_0 漏写必填超时参数，未派发便停止；随后共同接口将该参数改为可选、默认 30 秒，并反序复测三臂，计入预留预算。这个接口修复不算政策改进，原失败也不被替换。

| REGULATED_2 | cancel-async-tasks、db-wal-recovery | 增加不确定探查前保护唯一输入、保留恢复入口、先调查关键输入丢失 | 源任务仍未执行保护；数据合并首次迁移通过，但与两个基线同分且未使用工作区 |

R1 的 db 首次迁移结果完整保留。db 结果驱动 R2 后，db 才成为 R2 的开发来源，不能继续称作 R2 的迁移验证。R2 的数据合并任务在运行前冻结政策。不同版本不取各题最好成绩拼成一个方法。

在 cancel 的共同接口复测中，NOTE 为 6/6 原生检查通过，REVIEW 为 5/6，R0 为 4/6；R1 源任务修订为 5/6。R1 的一次记录先于同轮命令回执形成，随后实现发生改变却一直未更新，不能把“记录非空”当作范围修订机制有效。

db 三臂都先列出了 16,512 字节的 WAL，随后打开数据库，再检查时原 WAL 已消失；NOTE 另执行了截断 checkpoint。三臂之后都继续分析剩余五条基础记录。REVIEW、R1 最终因 4,096-token 输出截断而无法解析完整动作；NOTE 因真实输入超窗停止。**这些尝试没有原生 verifier 分数，记为未完成/未评分，不伪造 0 分回执。**即使后续能生成形式正确文件，也不能掩盖前面的输入损失。

## 判读口径

原生细项只解释失败，不作为独立样本。共3个原生任务根，覆盖实现、状态恢复、数据约束三组；重复源任务不是新 lineage，也不足以支持统计显著性或普遍泛化结论。执行期间研究者已看到臂名，不能宣称独立盲评；使用原始回执、产物及原生测试约束判读，不按笔记字数、状态词或自称反思计分。

真实轨迹没有主动 `context` / `read` 选材操作，也没有成立的挂起后返回机会；返回重检分母不成立。单次源任务重复减少不能排除生成波动。首题没有候选与 NOTE 的匹配成功对，因此不报只挑成功轨迹的成本优势。没有候选机制收益需要拆解，因而未追加消融；未使用的主清单和扩展槽位不自动填满。

## 最小规则结论

**主实验决定为 KEEP_SIMPLE：保留普通 NOTE/REVIEW，不把 R0/R1/R2 或更复杂工作区维护设为默认。**这不是“工作记忆无用”的结论：候选很少形成记录，主动选材从未发生，预期机制没有得到充分行为实现。

“记录检查覆盖和结果差异”只在 cancel 源任务上伴随较少重复，在未调参的 db 上未显示迁移收益；“不确定探查前保护唯一输入”在其开发来源上就未被执行，merger 的通过不能证明这一保护规则有效。未调参任务具体是 R1 的 db、R2 的 merger，不能把二者合成同一冻结政策的跨任务成绩。

初始组合中的低门槛线索、探索宽度和挂起返回要求已从 R1/R2 删除；保留下来的依据/范围与恢复提示也没有获得默认启用所需的效果证据。原型保留为可替换研究入口，不改变产品行为。维护成本包括新的原生桥接、严格格式/容量失败处理、记录进入后续输入的成本和版本审计；不能只看短笔记自身的长度。本轮只有一次记录更新，却仍出现错误解释持留，不能声称零风险、已实现自适应或新增认知能力。

## 条件性第二来源与近邻

ClawMark 固定本地 commit `d1b641b3171e584e69a3763c269069f32a13b574`。按实际 task.py metadata 检索，至少两阶段且仅依赖 filesystem/email/calendar 的候选共 3 个；选取不同职业的 `eda_task1` 与 `journalist_task5` 作运行适配审查。它们均为多模态任务，不能用文本模型假装已读取图像。原生 orchestrator 调用容器内 OpenClaw；现有 Harbor Host 尚未接入其阶段回调，原生镜像还包含语音模型与多工具安装。当前只完成配置审查，没有运行任务、后端或发邮件，跨来源效果未完成。

主动摘要、工作记忆和选材已有明确近邻：[HiAgent v1](https://arxiv.org/abs/2408.09559v1)以子目标组织工作记忆，[AgentFold v1](https://arxiv.org/abs/2510.24699v1)训练多尺度历史折叠。本轮没有复现这些训练或状态结构，也未移植其政策。另核对了 [MemR³ v1](https://arxiv.org/abs/2512.20237v1) 与 [ACE v3](https://arxiv.org/abs/2510.04618v3) 的摘要入口；这不是全面查新或完整方法对照。当前“记录检查范围、避免无信息重复、保护可恢复输入”属于普通求解实践，不能因为采用自由文本工作区就声称新颖。

## 原生参照与最终实验账

Terminus-2 的原生策略包含交互终端、完成确认及额外摘要调用，本轮使用既有 Provider 的计费适配记录全部调用。原生提示、tmux、解析和摘要流程沿用 Harbor 0.23.0；传输适配及整个系统与共同 Host 不同，不能当作纯政策对比或未经改动的 LiteLLM 复现。[原生说明](https://www.harborframework.com/docs/agents/terminus-2)

第一个参照尝试用23次生成、675,352 tokens 后，在真实上下文边界停止；它也先打开数据库而失去 WAL。适配层当时没有将 Provider 容量异常转换成原生恢复信号，并对所有调用强制 JSON 输出。这是参照接线失败，不作为有效原生基准分数。修正版本恢复原生文本响应、容量/截断异常和全部已结算用量汇总；四项 MockTransport 协议检查通过，原始失败与费用保留。

修正后的参照实际产生64次调用、791,722 tokens，其中28次主决策为765,145 tokens，36次短摘要回退为26,577 tokens。完整摘要在生成前因上下文容量被拒，随后短摘要可以生成，但未使主任务恢复推进；不能将36次回退写成36次完整的三阶段摘要。所有调用共享64次上限，没有免费摘要。它同样丢失 WAL，也没有产生 `recovered.json`。Harbor 留下的原始 reward 为0，但验证器下载 CPython 时超时，测试没有启动，故本报告将其记为**验证器环境失败、未获有效原生评分**。不把该0分用于质量配对，也不凭产物缺失冒充测试回执。[评分有效性审计](/cra/memory/mx_memory/evidence/workspace-host/complex-native-20260914/native-reference-score-validity.json)

## 工程验收与收口范围

邻近20项测试与最终边界、ruff、mypy、构建已通过。全回归固定收集4,445项，主分片已完成4,442项：4,440通过、1项既有可选Host SDK跳过、1项40毫秒超时测试失败。该次记录显示超时发生在请求载荷写入后、发送预留落账前；单独复跑其原模块10项全部通过，源码未改。保留首次失败，判为时序敏感的未复现失败，不声称首次全绿。慢测分片3项全部通过。全量首次结果为4,443通过、1失败、1跳过；该失败的原模块复跑10项通过，两份原始结果均保留。[完整覆盖与复跑审计](/cra/memory/mx_memory/evidence/workspace-host/complex-native-20260914/regression/regression-coverage.json)
