# MILA-V02-20：动作执行有效性校准与 Memory 复验准入

## 1. 目标与本次交付

**先证明本 behavioral testbed 能稳定地把正确意图执行成真实、合法、可核验的业务变化，再判断是否恢复 Memory 消费实验。**

这不是修 MiLAi 产品、开发新 Memory 机制、扩 benchmark 或重跑 V0219 原批次。
要校准的是 Lab 的 action adapter、模型可见写入合同、版本/错误回执和真实执行通路。
既有 Product 持久化、OAuth/MCP、身份隔离与 A0 默认不改变。

本 Goal 的基本链为：

```text
明确正确意图 → 实际模型输出 → 编码/参数验证 → 身份与版本校验
             → 真实环境提交 → 回执与公开回读 → 实际完成
                         ↓ 可修复错误
                 明确拒绝 → 核对新观察 → 合法重试
```

执行研究分三层：

1. **合同校准**：直接脚本能否正确执行、拒绝非法请求、保持权限/CAS/幂等边界？
2. **已知意图执行**：真实模型拿到明确正确的动作要求后，能否稳定编码、提交、回读及恢复？
3. **自然任务执行**：不给答案/动作计划，仅提供充分当前事实，无旧 Note 的正常 Host 能否完成业务任务？

第三层仍包含正常任务理解，不冒称“只测编码”。只有前两层通过不能自动开放 Memory 复验。
通过重新准入后，本 Goal 才安排旧 D 根上的有界 N0/N1/R1 复验；不开发候选、不打开 C。

**当前只交付详细 Goal 与索引。V0–V4 尚未执行，V5 条件未触发；模型/Judge 新分配 0。**
后续明确执行本 Goal 时，先封存具体批次与资源清单再实现/运行；不能把计划中的门、修复或模型结果写成已完成。

## 2. 固定继承结论

依据 [V0219 最终决策](MILA_V0219_INNOVATION_DECISION_20260911.md)、
[完整基线](MILA_V0219_BASELINE_RESULTS_20260911.md)与[失败图谱](MILA_V0219_FAILURE_MAP_20260911.md)：

- P1 反复非法动作跨 4 个原 root / 3 个 family；24B 全有协议拒绝，共 274 次，其中身份字段违规 156 次。
- 28 episodes 全用满 16 次生成；名义次数充足不等于 Agent 已有可靠的实际执行能力。
- 12B 有旧 Note/当前来源双呈现，但三份 A Note 均混合正确/错误，第四根 NO_WRITE；N0 也出现相近错误。
- P2/P3/P4 的部分轨迹值得保留，但未排除协议、共同业务历史、一般推理和判据争议。
  `G_REGIME=FAIL`、合格 Memory 模式 0、Memory causality `INCONCLUSIVE`。
- 26 个为 `RESERVED_UNVERIFIED` 候选，static accepted C=0；candidate 57 及其后新正文不打开。
- V0219 的 448 次 / 9,820,337 raw tokens、原意图/动作/判据/争议与终态保持原账；本 Goal 不重新计算其胜负。

本次结论必须分三层保留：**重复现象成立；Memory 因果未成立；机制准入未通过**。
不改写为“普通 Note 已足够”“R1 无效”或“所有 State 无效”。
V0218 的 C2 保持不晋级，不因执行层修复而自动复活该机制。

## 3. 已核对的执行层边界与待校准项

当前 [Host](../../tools/v0218_host.py) 经 [V0219 wrapper](../../tools/v0219_host.py) 使用：

- 外层 `action`，内层 `arguments_json: string`；只约束外层 JSON，内层还需二次解析。
- 工具描述给出参数名称，但不同 action 的真实必填/类型/身份规则并未全体现在可机器读取的 action schema 中。
- [World.act](../../tools/v0218_world.py) 禁止 `data` 含 `object_id/scope/version`，随后由执行器把 `object_id` 加入存储记录。
- CAS 使用当前**整个隔离 World 的 version**，不是单对象版本，也不是 Product Note 版本。
- `put_record` 替换该对象记录并清理其 pending；`request_clarification` 只创建问题，不自动取消旧活动记录。
- 保存 Note 与业务动作分开；`finish` 结束会话，但不能保证对象完整或业务正确。

这些事实说明可能存在“展示的完整存储对象”和“允许写入的 payload”之间的可用性错位；
尚不能未经实验断言某一个修复会解决全部 274 次拒绝。
V0 须把实际发送 schema、公开对象合同、解析器、executor、错误回执逐项对齐，而非只改一段提示。

## 4. 新 Lab action contract：原则与最小候选

### 4.1 安全身份、业务目标与可写字段分开

| 信息 | 谁决定 | 模型可见/可写边界 |
| --- | --- | --- |
| tenant、project、task/scope、服务凭据 | 可信 Host/已授权实例 | 不由模型请求选择或放进 data；必要的作用域说明可见，不暴露凭据 |
| object_id / 业务目标 | 模型在当前合法对象集合中选择 | 仍是明确顶层动作参数；不能把“身份安全”误用为禁止模型选择业务目标 |
| operation_id / 幂等标识 | Host 对每个逻辑动作分配 | 同一次未知传输重试复用；不是每次网络尝试重新生成 |
| expected_version | 已取得的明确 World 版本 | 明示整数、版本域和观察来源；不从 Note 版本或对象显示字段猜测 |
| data / 业务内容 | 模型根据任务决定 | 只接受公开声明的可写业务字段，不混入存储元数据 |
| Note 版本、Note 内容 | 独立公开记忆接口 | 不替代业务版本、业务提交或业务完成 |

`scope` 等不得仅从 JSON Schema 隐藏后就认为安全：executor 必须再次校验。
模型带入越权字段/跨 scope 目标时应无副作用地拒绝，不能静默剥除字段后继续执行。
若迁移期要兼容重复顶层/内层 object_id，应另立显式版本合同；首版不靠自动纠正掩盖失败。

### 4.2 优先减少二次编码，不放松语义边界

拟建 Lab 协议使用具名结构化参数，避免把整个业务对象再编码为 JSON 字符串。
例如下面仅是**接口形态示意，尚未实现**：

```json
{
  "action": "put_record",
  "arguments": {
    "object_id": "record_example",
    "expected_version": 7,
    "data": {"status": "pending"}
  }
}
```

V0/V1 应产生一致的三份合同：

1. **Read model**：公开读返回的对象/元数据、World version 与来源定位。
2. **Write model**：每个 action 的真实必填、类型、长度、可写字段/业务对象类型；拒绝未知参数。
3. **Receipt/error model**：是否执行、operation、提交版本、错误类别和可恢复条件。

从同一公开类型定义生成模型可见 schema、参数校验与示例，合同测试核对 executor 一致性；
但业务语义 checker 保持独立，不共用私有答案常量互相自证。
不要只将 `arguments_json` 改成任意 `object` 后宣称已修复 schema。

对象集合和各类合法业务字段可来自公开任务合同；schema 不可由私有 gold 缩成唯一正确动作/答案。
枚举类型和格式限制只表示**合法表达范围**，不替模型选择实际当前值。
结构合法但业务错误的值仍可提交到隔离环境，由独立 checker 离线判错；不能让工具替模型推理业务答案。

优先继续使用已有本地 Provider 的结构化输出通路，只改 Lab action 表示和验证。
若实际 provider 不支持所需 union/schema，应保留兼容诊断，先收敛为可验证的具名工具合同；
不悄悄回退双层自由字符串、引入额外修复模型，或同时更换模型/工具协议后作单变量主张。

### 4.3 CAS、幂等与未知提交

- 首版沿用 World 级 CAS，公开命名其版本域，不擅自改为 record-CAS；不同 scope 仍独立。
- 基于 V7 的写入遇到 V8 必须返回冲突并不改状态；不能自动读取最新 V8 后照抄旧意图提交。
- 合法重试顺序为：已知拒绝 → 公开读取/核对相关当前状态 → 重新确认动作仍适用 → 新逻辑动作提交。
  机械绑定可使用**已读取的**版本；绝不能用提交时的最新 head 偷换因果前提。
- 同一 operation、同一完整请求重放返回同一提交结果；相同 operation 不同请求拒绝。
- 请求超时不等于未提交。未知结果先查已持久回执或重放完全相同的幂等请求，不要求模型重新发一份相似动作。
  若当前 adapter 无法可靠处理，明确 `COMMIT_UNKNOWN` 并停发；不能凭当前 head 或缺失客户端响应推断失败。
- 版本冲突后的修正请求与“未知传输的相同请求重试”分开，不复用 operation ID 隐藏不同载荷。

不改变 Product 的 CAS/权限/幂等实现。需要增强的本地回执、字段错误、operation 查询均在新 Lab adapter 中实现，
保留冻结 V0218/V0219 代码；不得编辑已封存依赖以让旧实验通过。

### 4.4 错误应可恢复，但不能携带私有正确答案

拟建错误至少表达：`code`、字段路径、期望类型/规则、`committed`、`operation_id`、版本域、
是否可恢复，以及需要重新读取还是原请求重放。拒绝与未知用不同状态。

```json
{
  "code": "VERSION_CONFLICT",
  "committed": false,
  "expected_version": 7,
  "current_version": 8,
  "version_domain": "WORLD",
  "retryable": true,
  "retry_requires": "READ_AND_REVALIDATE"
}
```

`retryable` 不意味着自动批准下一次写入。只返回当前调用者有权知道的信息；错误不得回显凭据、
私有 gold、完整 checker 或下一步标准答案。格式校验可以告诉字段错在哪里，不能补造正确业务值。

### 4.5 真实业务效果与完成声明分账

机械写入成功必须有 operation receipt、提交版本和可独立读取的环境效果。
`save_note` 成功不能返回业务已完成；`finish` 至少与离线 `TASK_PASS/FAIL/UNKNOWN` 分开。

本轮不加入“知道所有正确业务后置条件、自动代替 Agent 完成任务”的控制器。
如需要公开的只读状态查询，只暴露正常记录/已执行操作，不调用私有 checker 给模型喂解。
澄清、取消/降低确认、更新业务是不同效果；不把 request_clarification 悄悄扩成自动撤销。

## 5. V0/V1：零模型合同校准与最小 Lab 实现

只使用 V0219 已暴露的四根及无研究答案的合成接口夹具；不重新筛选 corpus、不打开 candidate 57 或 26 reserve。
按既有顺序固定房地产、投资分析、人事 task4、人事 task5；仍为 4 roots / 3 family，不改独立性计数。

模型前先交付：字段所有权/Read–Write–Receipt 对照、公开 schema、变更 diff、版本域、正确/错误动作夹具、
无副作用拒绝、operation 重放、冷进程回读、reset/clone 和真实落盘验证。

最低测试矩阵：

| 场景 | 必须观察到的结果 |
| --- | --- |
| 合法创建/替换、完整记录、跨对象两步写 | 真实环境改变、版本递增、准确回执；读到实际提交内容 |
| 中英文、引号/换行/反斜线、嵌套结构/空值/数值边界 | 仅按公开类型接受或拒绝；不靠静默字符串修补丢语义 |
| data 含身份/版本、跨 scope 目标、未知字段 | dispatch 前或 executor 拒绝，状态/ledger 无业务变化 |
| 存储对象直接用作写 payload | 明确指出只读字段；公开示例不能引导这种错误 |
| stale version / 空版本 / Note 版本误用 | 明确版本域/类型错误，无覆盖；合法更新路径可复算 |
| 同操作重放、同 ID 不同载荷、提交后响应丢失 | 不重复业务效果，不猜测提交失败，未知状态可查询或安全停发 |
| 业务动作 / Note 保存 / 澄清 / finish | 各自回执及真实影响不混同；Note/DONE 文本不能骗过完整 checker |
| canary、private-gold、跨臂、源码/配置漂移 | fail closed；异常日志不泄漏私有材料 |

零模型机械 PASS 为必要门，不等于真实模型能使用接口。
采用新的 Lab 模块/入口封存改动；当前旧 Host、World 和 Provider 源文件是历史依赖，优先不原地修改。
如必须共用通用 helper，版本化并保留旧模块/已运行快照；新模型运行前固定所有依赖与差异。

## 6. V2：已知正确意图的真实模型执行

### 6.1 明确承认这是 Intent Oracle，不是自然能力成绩

这里允许从已审核的 evaluator-known 合法动作构造明确任务指令，例如指定合法目标与完整正确业务值，
让模型完成编码、提交、回读及结束。这些是有意提供的 oracle intent，不能拿来证明检索、推理或 Memory 收益。

转换器只导出该次授权动作必需的普通值/条件；不把 checker 代码、未来事件或隐含评分标签带入请求。
另存 `INTENT_ORACLE` profile、来源/审查记录及完整输入 hash。V4/V5 绝不继承这些正确动作提示或缓存。
未决/有语义争议的字段不得冒充唯一正确动作；选用明确合法实例，不能改判 V0219 原 9 项争议。

### 6.2 固定小矩阵与门槛

四个原 root 每根 3 条短链：单对象创建/更新、同域不同对象的顺序写、带复杂合法文本的完整写入。
各做 2 次新进程运行，共 **24 条链**；每链最多 4 次生成，统一由公开观察提供合法初始版本。
链长设计须事前允许完成所需写入、公开回读与 finish；不能设计成至少 5 步却只分配 4 次。

先运行固定前两条 smoke，计入 24 条而不是额外免费样本。出现第一个非预期协议错误即停止该候选批，
保留已尝试、未运行位置和费用，回 V1 处理一般合同问题；不把失败换成另一个合法题，也不先跑完剩余几十次来收集同一错误。

`G_KNOWN_INTENT` 要求本候选完整矩阵：

- **24/24** 链的意图内容、业务目标与顺序被忠实表达，全部必要动作首次合法执行、效果及回读一致。
- 非注入协议拒绝 0；身份/跨 scope/错误目标写入/重复提交副作用 0；未知提交或未结算用量 0。
- 保存 Note、虚假完成或“看起来格式正确”都不能替代实际环境效果。

这是所选短链的严格工程准入阈值，不是用 24 个小样本证明总体成功概率接近 100%。
原 root、链、重复分别计数，不把 24 叫 24 个独立外部任务。

## 7. V3：已知、可修复错误的真实恢复

V2 通过后，用同四根各 2 个恢复场景、2 次冷运行，共 **16 条链**，每链最多 5 次生成：

1. **可安全重新核对的 stale version**：预定无关事务使 World 版本变化，目标事实和授权意图未改变。
   首次拒绝是预期刺激；模型收到结构化错误，公开读取，核对仍适用，重新提交并回读。
2. **语义前提确已变化**：在模型意图提出后按预定事件改变相关公开条件。
   正确行为不是盲目把 expected_version 加一，而是停止旧写入、核对变化，按明确任务前提请求澄清/重新授权。

第二类使用简单、已明示的动作适用条件，不需要长期记忆或复杂推理；但如模型没有正确核验，
应标 retry-policy/use 错误，不能全部记为 JSON 编码失败。两类结果分开，不用“成功提交率”奖励不应提交的请求。

故障发生时点/对象/可见变化在结果前固定，不能看模型输出后挑一条容易恢复的错误。
自然模型未发到目标动作导致故障未触发，要记录 `NOT_EXERCISED`，不能算恢复通过。

`G_RECOVERY` 要求：16/16 按场景完成合法恢复或正确停止，所有应触发错误都有真实拒绝/无副作用证明；
收到明确拒绝后在至多 3 次后续生成内完成该场景所需修正/核验动作，余下机会用于回读和结束。
不得重复完全相同的已知非法请求；语义变化时旧动作不得提交。

另外用零模型故障注入核验 malformed payload、scope 伪造、丢失回执/进程重启和未知提交，
不为测试安全拒绝而让模型学习绕过权限。若需真实模型负向注入，先另封存场景/次数，不从 16 条正向恢复中隐藏增加。
恢复刺激、普通动作请求、保护性拒绝分母分开；不把预期的一次拒绝计作协议退化。

## 8. V4：自然无旧 Note 的业务执行重新准入

### 8.1 不让 Oracle 成绩冒充正常 Host 能力

使用四个已暴露根的原完整业务对象要求和充分当前来源，**不给 V2 的正确动作计划/标准答案/唯一值**。
对 V0219 明确过度约束的争议字段先冻结 source-grounded 多解/UNKNOWN 处理；不能看本次答案后改评分。
保留所有缺失对象、真实交付、澄清及来源义务，不缩成一条已知正确写入以获得“全任务 PASS”。

两个臂：

- **N0-exec**：无继承工作 Note，正常来源/工具/业务工作能力。
- **R0-exec**：同样无继承旧 Note，使用 R1 原 `AUDIT + REVIEW` 的普通复核政策；
  允许在本会话保存自由复核，但没有来自 A 的持久 Note。

`R0-exec` 是本 Goal 的 no-carry 对照，不改名替代 V0219 的有旧 Note R1。
两臂得到相同完整当前资料、动作 schema、业务起点与生成机会；所有预读明确记 `HARNESS_PUBLIC_PREFETCH`。
独立进程/scope，Oracle 缓存和正确答案文件不挂载到这些任务；来源回执证明实际发送。

### 8.2 范围和通过条件

先固定每根一个完整当前任务 profile，四根 × 两臂 × 两次冷运行 = **16 episodes**，每个上界 16 次生成。
第一波原顺序前两根，完整跑完两次冷矩阵后再判断其余两根；不以选择性成功输出代替完整对照。
若同类非预期协议失败再次出现，立刻暂停该 adapter 候选，不复现 V0219 的 28 个 episode 全撞到上限。

分别判断：

- `EXECUTION_LAYER_READY`：V1/V2/V3 通过；不能因此宣称业务理解可靠。
- `TASK_PROFILE_READY(root)`：该 root 两臂两次共 **4/4 完整业务 PASS**，无未解决协议/身份/提交问题；
  真未决场景按已冻合法澄清/暂缓合同评分，不要求无依据填确定值。
- `G_ACTION_EXECUTION`：至少 **2 个不同原 root、2 个 family** 达到 TASK_PROFILE_READY，
  且计划进入 V5 的具体 roots 均通过；安全与提交护栏零违规。

剩余根的普通推理/业务失败保留，不与通过根合并宣称全部 profile 已可研究 Memory。
按结果获得可用 profile 是**显式、已暴露的条件准入**，不代表总体抽样、不算新确认池。
如果 V2/V3 好、V4 仍差，结论是 execution encoding 可用而 task competence 不足；停止 Memory 复验，不增加新 State。

## 9. V5：门通过后的旧根小型 Memory 复验

### 9.1 只恢复消费诊断，不自动恢复创新探索

优先 V0219 已有真实双呈现的 root，但必须同时过 V4：房地产、人事 task4、人事 task5，按旧序选择，
最多 2 根且至少 2 family。不能因人事两根通过就称跨两家族。
若不存在满足条件的两根，只做已有准入结果交付，不扩新前缀、打开 reserve 或降低门槛。

为避免把旧执行器造成的污染起点当成记忆效应，首轮用新校准执行层产生**新的自然 A**，
正常工作、自由可选 Note；不提示正确记忆内容，不把 V2 Oracle 写进 Note，不强制保存。
所有旧 A/Note 和 V0219 结果保留。若另复用旧混合 Note，只能命名为单独的 mixed-memory consumption diagnostic。

新 A 的完整业务状态、Note 相关命题当时的正确/错误/未决分别评价。NO_WRITE 或 A 未完成不能换根、重跑 A 直到成功。
可继续的 B 保留 all-attempt 结果；不能运行的分支标起点无效。相关旧命题未曾正确，不纳入“原本正确后失效”的条件分母。

每根从同一 A/业务历史派生 Stable/Changed × N0/N1/R1，首轮 2A + 12B = **14 episodes**。
R1 保持原普通复核语义，N0 仍有同等合法历史；N1/R1 实际通过公开接口恢复 A Note。
事件在 A/Note 生成前固定，旧 Note 与当前依据真实发送；新 schema/adapter 对所有臂一致。

只有首轮执行/冷链/判据有效时，按事前约定再做**一次全部配对 B 冷复验**，12B，不重抽更好 A。
第二次触发只看有效性，不看 N1 是否更差或能否出现创新；两次均属已暴露条件重复，不新增独立 root。
所有 B 最多 16 次生成，额外 Note/read/review 均计机会和完整成本。

### 9.2 解释边界

| 结果 | 允许的解释 | 不允许的解释 |
| --- | --- | --- |
| N0/R1 完整正确，N1 重复沿用过时有效记忆 | 有界 Note 暴露/使用政策的不利影响线索；继续查输入、业务历史、成本与随机性 | 一次胜负就证明 memory-induced inertia 或需要新 State |
| N1/R1 正确，稳定和更新均满足 | 普通笔记/复核在该条件足够，保留简单方案 | 所有任务/模型已证明无需调控 |
| 三臂均错，但编码/提交有效 | 进一步定位一般任务理解、业务语义或 use failure | 自动将三臂共错称作 Memory harm |
| 再次出现大批协议拒绝/资源截断 | 该 profile 重新暂停，执行门外推不足 | 把错误记为 State 无效或只给一臂续预算 |
| 无自写/无双呈现/旧命题本来错 | opportunity/presentation/mixed-memory 诊断 | 以零分母报告零惯性或补正确 Note |

N0/N1 比较的是在同一自然 A 起点的 Note 暴露政策，保留了共同业务历史，不是“有记忆 vs 完全没历史”。
跨臂 token 长度和实际行动路径可能不同，报告条件影响，不臆测内部认知过程。
R1 解决 N1 的错误首先是普通复核收益；不能把 R1 临时重命名为新 Memory mechanism。

本 Goal 最终不运行新 State、C2/C3、消融或 C 确认；如出现有效重复 Memory-use 模式，输出机制研究入口建议，另冻结研究合同。

## 10. 观测、判分与门的完整性

新增分解：

```text
Available → Acquired → Presented → Interpreted → Action intent
→ Action encoding → Contract accepted → Environment effect → Recovery
```

只记录外显动作意图/短工作产物，不要求隐藏推理。自然任务的“意图正确”不能由研究者猜测，
有明确输出证据才赋标签，否则 UNKNOWN；V2 的 oracle intent 是另一独立已知输入。

每试验连接：root/profile、意图来源、可见 schema、实际 HTTP 请求/响应、解码结果、字段错误、
dispatch 是否发生、可信 scope、读版本/提交版本、operation、前后状态 hash、业务 ledger、公开回读、最终判据、用量。

统计至少区分：

- `Intent fidelity`：是否忠实表达已知意图；语义值错与格式错分开。
- `First-attempt contract acceptance`：合法意图首提交接受率；负向注入拒绝另报。
- `Effect fidelity`：提交后的真实效果与意图一致；仅收到 200/成功文本不够。
- `Recovery`：预定刺激确实发生、可行动、正确核验及有限步修复；语义变化时正确不提交也可 PASS。
- `Task success`：完整对象/字段/消息/条件，不以局部写入替代。
- `False completion / wrong-scope effect / duplicate effect / silent rebase`：独立安全与执行护栏。
- 全部尝试、未运行/停止、NO_WRITE、实际双呈现、争议、资源/未知提交和总成本。

各门的条件率与 all-attempt 同报，零分母 N/A；脚本、合成意图、自然业务、Memory 消费四套成绩不混合。
冷重复不是新增 task；两个 HR 根仍同 family；小矩阵不称统计证明。

## 11. 有界运行与迭代合同

| 阶段 | 起始上界 | 无条件不得做的事 |
| --- | --- | --- |
| V0 合同审计 | 旧四根/旧失败回放；生成 0 | 新 corpus 筛查、打开 reserve |
| V1 最小 Lab 实现/校准 | 脚本/schema/身份/CAS/未知提交；生成 0 | 修改 Product 或旧冻结代码让原结果过门 |
| Provider 兼容 | 必要时最多 2 次合成请求，全部计账 | 偷换模型、cloud/Judge fallback |
| V2 已知正确意图 | 24 链 × 至多 4 次 = 96 次生成 | 明知合同失败后继续全矩阵撞墙 |
| V3 恢复 | 16 链 × 至多 5 次 = 80 次生成 | 把预期拒绝当失败；盲重基版本 |
| V4 正常任务 | 16 episodes × 至多 16 次 = 256 次，分两波 | 以 Oracle 成绩替代；只重跑成功根 |
| V5 首轮消费 | 14 episodes × 至多 16 次 = 224 次 | 不过门、强造 Note、扩新根或开 C |
| V5 条件冷重复 | 12B × 至多 16 次 = 192 次 | 看正负结果决定重复或换 A |

上述是各阶段**最大预约**，不是当前分配、预计实耗或必须运行的总量；不提前把所有后续请求一次性解锁。
兼容、技术失败、重放、Note 写入/维护、普通复核的额外生成都计入显式批次，不使用隐藏模型修复器。

每个候选开始前封存 adapter/schema/provider/world/checker、根/动作/顺序、模型/template/config、cap/时限和反证。
首轮最多两个 Lab 协议候选版本；每次修复有一般合同原因，不改答案、筛选更简单 root 或按 id 特判。
第二版仍不稳定时，交付阻断层与证据；继续换协议/模型/扩大资源需要新前瞻批次，不无限迭代到通过。

首次非预期编码/合同失败暂停 V2/V3 候选批；未知提交/用量、越权效果或泄漏立即停止所有相关发请求。
有界自然任务中同类协议错误复发即暂停该 adapter，不等到每个根都用尽 16 次。
无法恢复的业务语义失败与协议失败分开；一般修复重新冻结并共同重放比较臂，旧失败保留。

沿用已获同意的本地 vLLM 路径；历史 Provider 锁定 Qwen3.6-35B-A3B-FP8、4096 输出、60 秒请求等待，
这些是既有代码参数，不代表本次已验证在线状态。执行前用实际输入/输出预约核验上下文、模型与工具兼容性。
短链起始每 trial 最多 300 秒，自然 episode 最多 900 秒；batch deadline 按显式数量计算。
模型初始并发 1，独立普通读最多 4；按已验证资源容量才可放宽，实验限制不扩展为产品全局锁。

**累计 raw-token 硬上限继续为 null，功能/实验有效性优先，token 最后优化。**
不限累计 token 不能取消阶段门、次数/时间边界或未知用量停发。完整输入重复量单列，
不靠删反证或降低完整业务要求来节省费用，也不把重复 schema 花费伪装成机制推理成本。
实验 Provider、tokenize、下载/准备、CPU/GPU/墙钟、代理劳动分账；未计量的成本如实未知。

## 13. 交付物、终态与完成判据

拟交付物，不代表目前已存在：

1. Action contract audit：Read/Write/Receipt、身份/目标/版本域、已知拒绝复现与最小差异。
2. 新 Lab adapter 与公共 schema/错误/示例；等价性、权限/幂等/CAS/未知提交的零模型正负校准。
3. 冻结 Intent Oracle corpus/短链矩阵与真实模型结果、完整账；与自然题严格隔离。
4. Recovery matrix：预期刺激、公开反馈、错误后机会、实际修复/正确停止及剩余问题。
5. N0-exec/R0-exec 完整业务矩阵和逐 root 准入卡，普通语义失败/协议失败/争议分账。
6. V5 触发时的冷 Note/当前来源/动作/状态配对结果；未触发写明原因，不伪造 Memory 效果。
7. 最终有效性报告：已通过哪一层、剩余混杂、C=0/保护状态、全部用量与自有服务收尾。

终态分开：

| 标签 | 含义 |
| --- | --- |
| CONTRACT_CALIBRATED_ONLY | 脚本合同通过，真实模型使用尚未通过；不开放 Memory |
| KNOWN_INTENT_EXECUTION_PASS | 已知正确意图稳定执行，正常任务能力尚未证明 |
| EXECUTION_READY_TASK_NOT_READY | 编码/恢复有效，但自然无旧 Note 的业务能力不足 |
| ACTION_EXECUTION_GATE_PASSED_LIMITED_PROFILE | 只对达到门的已暴露 profile 有效，不泛化全部 corpus |
| MEMORY_RECHECK_KEEP_SIMPLE | 有效小型复验中简单方案可用，无新机制研究授权 |
| MEMORY_USE_SIGNAL_NEEDS_NEW_CONTRACT | 执行稳定后出现有界重复线索，仍非新颖性/因果确认 |
| VALIDITY_BLOCKED / INCONCLUSIVE | 合同、自然任务、Note/呈现、评分或资源不充分；不是 Memory 零效果 |

只有文件/schema 或单测通过，不是 Goal 的模型有效性工作完成。
执行阶段必须完成有界真实模型校准及明确的后续门判断；门不通过可以如实交付有界失败诊断，
不得把“暂停扩样”包装成动作层已可靠。门通过且 V5 条件满足时，应实际完成已冻复验与结论，不能只留下未来计划。
没有合格 V5 roots/没有 Note 时，不以填答案或换题达成完成；标对应准入缺口，不宣称 Memory 研究成功。

所有终态要求失败、未运行项、未知用量/提交影响和权限/服务收尾明确。
**本 Goal 判断实验执行有效性，不要求提出创新，也不允许据通过门就部署或冻结 Product Schema。**
