## 1. 当前结论

**MiLAi 已从“具备记忆协议和存储能力”推进到“可选 Host 来源取得与交付闭环在本地可运行”。
工程可用性已有实质进展，但 State 调控的独立收益、自动维护收益及产品整体长期净收益仍未证明。**

当前最强的工程正面证据仍是 V02-14 的来源取得、必要澄清、完整调用意图、显式 Note 保存、
真实冷 Host 恢复及并发隔离。V02-15 已实际探索检查点/提醒/普通笔记，但没有选出
值得确认的新机制；不能将工程通过改称 State 创新成功，也不能将本批负信号推广为
“所有 State 无效”。最后 NOTES/REMINDER 各 2/2、CHECKPOINT 1/2 是同一已打开合成案例
两个阶段的复查，不是两项独立外部任务的效果。

最新模型实验 V02-16 再次暴露来源取得/覆盖判断问题，却没有形成“持久笔记 → 实际呈现 → 行为”的
可裁定链。无笔记不是错误本身，但这些自包含任务不能回答记忆是否制造惯性；
有效分母为 0，不是固着率 0%。V0217 随后发现公开候选的全链与评分有效性缺口；
下一阶段先构建可校准的行为真值与真实持久链，不继续加长来源或调整 State 找机制。

## 4. 最近真正完成了什么

### 4.1 先分清“没去读、没读到、读到仍用错、没有正确交付”

V02-12 的六个最终答案均未调用工具；另两题只查空 Product store，没有进入普通源文件。
这不足以证明 Product 检索差，更不能证明 State 的关系信息缺失。完整原件可访问与必要
支持实际进入请求是两件事。[V02-12 归因报告](MILA_V0212_RESULTS_20260909.md)

V02-13 因而引入 A0/R1/O。第一波一题 A0 没取得历史，另一题文字回答包含正确线索却没有
提交有效业务调用；两题 R1/O 均正确。后两题分别存在主体歧义和缺失业务 ID，Oracle
在生成前即判不充分，不能算“充分证据下模型失败”。
见 [首波](MILA_V0213_RESULTS_20260909.md)、[P3](MILA_V0213_P3_RESULTS_20260909.md)。

当前采用的归因链是：

```text
来源合法且可用 → 取得原文 → 实际呈现 → 理解/适用性判断 → 澄清或完整交付
                                                        ↓ 有延续价值且获授权
                                                   保存 → 冷恢复后使用
```

任一上游环节未成立，不能直接归因给下游 State/注意力。Oracle 也必须先通过充分性审查；
即使 Oracle 仍答错，也还需排除一般推理、任务合同与评价歧义，并不自动证明需要 State。

### 5.3 本轮探索最重要的收获

不是“类脑 State 已被证实”，而是**识别了哪些失败不应由新增 State 结构解决**：

- 源文件从未被读取，应先修来源入口与 Host 取得政策，不能用更丰富的 State 字段掩盖。
- 主体或业务 ID 根本缺失，应澄清；不能让结构化输出制造一个值以满足 schema。
- 已有答案线索但调用为空/重复，应修交付合同；不能将其计为检索或记忆语义失败。
- 冷启动取回字节正确却误用控制关系，是另一层问题；现有受控负例值得保留，但尚不足以扩架构。

截至 V02-14，执行路线从 State 假设回到了取得/交付瓶颈，并完成了可用的本地底座。
根据用户随后决定，V02-15 已开展并收口一批开放机制探索；后续研究仍不要求先补完
所有工程未验证项，也不因本批零候选重新强制 RQ1 先成功。
旧负结果只约束既有候选；既不禁止探索其他方向，也不因新立项而追溯改判旧结果。
本文不作论文级新颖性判定，近邻地图与主张边界记录在 V02-15 Goal。

旧 E1/动态 A/B 的结果不是整个研究路线的串行准入门；V02-15 曾允许改策略、尝试 bundle。
V0217 已完成有界能力审查，仍无完整 P 链。当前 V0218 先构建外部任务上的行为真值测试床，
不自动继承机制调优或旧 N0/N1 执行授权。先校准环境、可见证据与完整动作判据，再验证冷链；
discovery 不能直接支持默认启用、架构扩张或稳定因果主张。

State 驱动的语义 Context projection 在当前研究合同中已排除；旧原型保留但不计验收。
这不等于禁止正常按需检索，也不等于禁止 Runtime 的派生索引或 BGE 向量降维投影。
这些机制的对象不同，不能仅因都叫 projection 就混为一谈。
