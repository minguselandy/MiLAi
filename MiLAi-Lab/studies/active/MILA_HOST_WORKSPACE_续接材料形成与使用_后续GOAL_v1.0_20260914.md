# 后续 Goal：续接材料的形成、范围保持与实际使用（v1.1）

修订 v1.1：采纳“可用上下文优先”。移除固定 8k/16k 输入门、512-token 交付硬门和默认只传短稿的历史丢弃；受限续接变为可选、单列的实验条件。文件入口路径保持不变，当前版本以 frontmatter 为准。此次仅更新未执行规划，不修改旧实验条件、结果或运行代码。

## 1. 目标与本次选择

**利用已经可运行的 Host 接线，在模型实际可用上下文内允许正常工作，探索不同的交付形成政策是否改善后续判断、证据适用范围保持和实际成本；没有净价值则保留简单方案。**

本 Goal 不再问“模型会不会自发填写 work_update”，也不重新比较一次相同的 COMMON/MANAGED 开关。首个新假设是：

> 普通阶段回答已经在承担续接，但容易丢失对象、测量范围或未观测条件。在原材料和普通历史仍可容纳、可以正常使用的情况下，用同一次正常调用形成保留这些边界的交付，后续同一普通消费政策是否更少错引、遗漏或过度推广？

这是依据最新轨迹提出的**形成政策假设**，不是已成立的 Memory 机制，也不是给 REGULATED 增加字段再测一次。使用现有 `stage_answer.arguments.text` 承载交付；三臂使用同一载体、历史保留规则和消费政策，实际差异发生在前段如何工作及形成交付。首先估计形成政策在正常上下文条件下的整体效果，不能单凭差异归因于一份短稿；必要时再拆解信息渠道。

主比较不为制造记忆需要而先让模型遗忘。若完整任务材料在当前服务容量内，允许保留；小窗口、只传交付或短稿硬限只能作为另行声明的受控探针，不能冒充模型容量不足，也不能成为主比较必须先通过的条件。

原始联想、适用性、暂停/再检查等方向仍可演化；本次先选择能直接解释已有错误、且无需新增平台的一个切片。认知政策不写成 Runtime 状态机。

**本文件只生成后续规划，不启动平台 Goal、模型、Provider HTTP、服务或后台任务。后续执行指令与具体 run header 才建立实际运行范围；旧批次余额不自动继承。**

## 3. 固定实现边界，允许政策演化

- 只复用[任务入口](../../tools/run_workspace_task_a.py)、[Host 钩子](../../tools/workspace_policy_host.py)、[工作区核心](../../src/milai_lab/methods/workspace_policy.py)和[Provider 适配器](../../tools/workspace_task_provider.py)。允许必要的任务续接分支和小配置，不搭通用交接平台。
- 同一个模型、正常调用；不增加隐藏 summarizer、Reviewer、router 或训练。Host 作语义判断，代码只搬运原字节、控制范围并派发已有动作。
- 用户目标、最新要求、授权和新观察在交付之外保留。交付作为标注为可错的数据进入输入，不提升为 system 指令或事实权威。
- 初步阅读、复现、探索新线索和不更新都合法。不要求固定分支数、统一思考阶段或出现 park/resume 等词语。
- 主比较默认保留能容纳的已发布任务原材料和普通交互，不启用 K=1/K=2 裁剪或只传交付。原始材料和完整日志不删除；模型也可用同一目录/读源能力恢复历史。新观察不被旧交付过滤，业务结果不因认知切换回滚。
- 只有模型形成的**简短可见工作产物**被使用，不索取、保存或评价完整隐含思维过程。
- 仅既有授权 vLLM HTTP；不操作 GPU、不修改共享服务、不新增公网依赖。凭据不进入模型、任务包、报告或 Git。
- 不运行不受限模型代码，不写 Product 私有表，不改 Canonical、产品默认或 Runtime 语义 Schema。

开发可改变提示、表达、容量、任务/事件安排及比较顺序，但每次保留“观察 → 修改 → 预期行为差异 → 核对方法 → 投入上限”。允许有解释的组合探索，不把组合收益提前归给单一规则。未修改的简单基线不应被故意削弱；也允许普通方案随开发改进。

## 4. 首个比较：正常上下文、共同消费政策与不同形成政策

### 4.1 三臂的真正差异

三臂得到同样的交接任务要求：在当前工作段结束时，简洁地交付后续工作需要的进展材料，长度服从内容需要；内容由模型决定。交付不是实验者写的理想 Note，不要求保存某个指定结论，也不要求把可正常保留的历史压成唯一续接材料。

| 臂 | 前段形成政策 | 后段消费政策 |
| --- | --- | --- |
| N：普通交付 | 用普通 NOTE 政策整理对后续有用的进展、依据或下一步；可自然写条件和未知项 | 同一个冻结的普通 NOTE 消费政策 |
| R：普通复核交付 | 在同一次正常决策中普通复核已有理解，再形成交付；不多一次调用 | 同上 |
| S：范围保持交付 | 一个可替换的轻量候选：保留重要结论对应的对象/条件和证据覆盖，区别观测、解释与未决项；更正已知误读 | 同上 |

S 的初始通用政策可以很短：

> 为后续工作保留最有用的结论及其适用边界。只在会影响后续判断时写明对象、条件、来源和未观测项；不要把一组材料的结果推广给另一组。明确更正已知误读，保留可能值得重新检查但尚未成立的线索。无需固定栏目，不求面面俱到，不把下一项计划写成已完成。

此提示不含 A 的数值、字段答案、root ID、预期下一动作或未来观察。真实字段定义共同提供。范围保持本身不作为新颖性主张；S 可以输给普通 NOTE/REVIEW，也可以在开发中被删减或替换。

消费阶段只统一切换实验用形成提示为共同消费政策；不借移除提示清空普通历史、用户要求、真实动作或材料。各臂自产交付和此前动作历史可能不同，消费者可以选择不同动作；这些后续差异是整体处理结果，不强行回放相同工具返回，也不声称只有短交付一个通道造成差异。

### 4.2 一条轨迹怎样运行

```text
相同初始任务与已发布历史材料
    → 同一 Host 在前段正常读源、计算、判断
    → 模型以 stage_answer 交付进展材料，简洁但不强压到 512 tokens
    → Host 原字节保留该交付，不替模型改写
    → 后段输入：当前目标 + 新观察 + 可容纳的原材料/普通历史 + 交付
    → 同一普通消费政策正常读取/计算/最终交付
    → 用原始材料、实际选择和任务结果判读
```

首选 A 的一个**明确标注的新续接开发版本**：前段使用原先前两批已发布材料，后段加入第三批新观察并完成全任务综合。原字节与来源映射复用；本轮改变工作段边界和交付合同，不和上轮混报胜率。它仍是同一个已暴露 lineage，不是新任务来源。

工作段分界在发送前由任务安排确定，所有臂相同，不按模型答对与否、不按关键词或是否写记录推进。前段最多 4 次正常生成，后段最多 4 次；阶段交付不是整个任务完成，final 必须由后段实际生成，不拿前段文字改标 final。

默认 `NATURAL_CONTEXT`：后段继续同一逻辑任务，按共同规则组装实际可容纳的前段原材料、普通动作/结果和回答历史。重新组装请求不等于清空历史或真实冷恢复。`COMMON_CONTEXT` 可作为现有实现起点，但必须把它继承的自设输入门限对齐到本次实际容量规则；不是直接运行旧默认命令就符合 v1.1。

“完整”仅指当前任务中已发布、合法可披露的材料和交互，不是把整个仓库、未发布观察、凭据或 evaluator 填进上下文。相同原文不必机械重复多份；已有交付在普通历史中出现时不再额外复制一份来放大权重。各臂使用同一呈现规则，并保存最终请求来核对。

首轮不设有限 K 来淘汰旧交换，也不只提供历史句柄代替本可保留的正文。新观察直接呈现，历史目录/读取仍可用。若完整请求确实超出服务可用容量，则按第 7 节共同处理，不静默切换 managed 或只删 baseline 的正文。首轮 A 仅只读回放；未来的未结业务操作和回执仍须单独保护。

交付按统一位置和角色传递，标为 `HOST_CAPTURED_STAGE_OUTPUT`，只呈现一次。它是模型生成、任务要求下交付的文本，不是模型自主调用持久 Note 工具。每臂使用自己的原文，不互借高质量输出；原文进入日志和后段请求的对应关系可直接核对。

不设 512-token 交付硬门。可使用共同的“尽量简洁”提示，或把约 512 tokens 标为非强制目标；超出该目标不拒收、不扣成格式错误、不阻止后段呈现。只计实际长度、质量和成本，不奖励短本身。

最终响应仍受真实服务容量及本次足够容纳正常交付的共同输出上限约束。因输出截断、不合法消息、权限或真实容量而不可使用时保留原文与原因，不截掉尾部否定、不人工修成理想稿、不自动追加修复生成。可继续的轨迹使用已有合法历史完成任务；无交付或局部失败不删除整条记录，也不伪造成功交付。

不要求附加 `work_update`，也不把它与 stage_answer 重复生成。若模型另有可选更新，原样记账，三臂采用共同的工作区可见规则；不得让只有 S 获得额外通道。不得把较长 stage_answer 转存到现有硬限 512 的 workspace 后再拒收；交付可沿普通历史保留。若本次实际启用独立工作区，需显式配置其机械容量，不能把继承的 512 默认值伪装成软目标。

### 4.3 为什么这不是再次做存储往返实验

处理变量是**前段工作与形成交付的政策**，不是换一个保存/读取接口。必须先能指出三臂在什么指令上不同、哪些实际交付和选择不同，才解释后续结果。主比较保留正常历史，所以结果是这一政策在正常上下文中的整体效果，不自动成为短稿独立消费的因果效应。

如果三臂最后生成相同内容，或不同内容没有改变任何有价值的选择，应如实记录“本例处理差异不足/无净增量”，不能仅凭三个名称或字节搬运成功声称机制生效。

显式要求交接改变了研究对象：本轮可以回答“在交接任务下怎样形成和使用短材料”，不能回答“普通 Agent 会不会自主决定外部化”，不能据此追认前 61 次空 work_update 为成功。

### 4.4 可选受限实验，不作为默认工作点

仅在出现具体的新问题时，可以在第二包中选择 `RESTRICTED_CONTINUATION`：例如仅传交付的受控上下文切换、共同固定窗口，或明确的短稿硬预算。一次选择一个主要限制，除非明确声明组合探索；不默认同时压到 K=1、512-token 稿和小输入窗口。

限制的对象、数值、为何需要它、来源是否仍可读以及各臂相同的能力/资源规则，均在新比较前登记。只有容量利用率降低不算成功，仍须检查任务质量、错误、重复工作与全部成本。受限结果与正常上下文分开报告，不合并胜率或声称“因三臂同限，结论就可推广”。

主动选材/压缩也可以作为政策干预探索，但不能借提高 input_tokens 之名保留隐含 K 裁剪。若只在强制缺失历史或很短交付时出现优势，结论仅限该受限条件；要声称正常大上下文也需要此机制，仍需对应证据。没有现实资源/交接动机，不为制造 baseline 失败而增加限制。

## 5. 只允许一个有信息量的后续比较

读完首个三臂比较后，可选下面**一项**，不是全部展开，也不要求 S 先胜出：

| 新观察/问题 | 可选后续 | 解释边界 |
| --- | --- | --- |
| 单根无差异，但有具体理由认为它缺少后续判断依赖 | 一个已存在、低成本的独立来源，继续三臂 | 不按输赢挑题；没有便宜任务就不扩建平台 |
| 形成政策下的后段选择不同，值得定位贡献 | 在独立来源检查，或固定当时交付、前段普通历史与新证据做消费对照 | 尚未证明仅由短稿导致；复用稿形成成本单列，不当作免费端到端策略 |
| 所有前段都误读关键证据 | 在当前原材料仍可见时，比较普通复核与一个通用解释提示 | 这是解释/形成诊断，不叫持续记忆固着 |
| 前段正确、交付正确、后段仍误用或遗漏 | 固定同一稿与新证据，比较两项最小消费政策 | 才开始隔离消费问题；不能回填未来纠正信息 |
| 正常上下文同样好，需判断真实交接/资源约束下是否有价值 | 一次明确标注的受限续接、去交付或选材对照 | 不同时展开全部条件；受限收益不能替代正常上下文结论 |
| 没有具体新问题，或普通方案可靠且更便宜 | 不启动第二包 | 直接形成 KEEP_SIMPLE 或暂停当前版本的决定 |

独立来源优先选已经可读、可以确定性核对或已有安全执行入口的实际工作任务。普通方案可以公平完成；不要求任务故意制造暂停/恢复。来源没有就记录覆盖不足，不为原 B 建沙箱、不拉起整套 benchmark，也不从最终修复反向伪造“历史原版”。

开发原型和配置准备若已经成为主要工作，停止该分支并说明缺少什么现成能力。最多选一个替代任务；替代发生在查看其政策结果前。A 的改写、不同边界、重复运行都不增加独立来源数。

## 6. 最小实现与检查

预期新增只有一份可替换的形成政策、现有任务入口中的小型续接选项和必要的容量配置；消费者复用既有 Host/Provider。也可用一个邻近的小 runner，但不改写旧 runner 的已报告默认语义。当前代码仍有 8,192 输入、2,048 输出、512 工作区等机械默认；文档修订不意味着代码已放宽。新入口须实际传入配置并核对请求，不能让 Provider 允许大窗口而 Host 仍在旧小门限拒绝。

必要的 CPU 检查贴近实际接线：

- 同一交付原字节进入后段且不重复；在真实容量允许时，超过 512 tokens 的合法交付不被拒收；空稿、服务截断和无效消息分别记录。
- `NATURAL_CONTEXT` 中较早的正文与普通交互确实保留，K 不参与筛选；只移除实验形成提示，不借此清空历史。当前任务、字段定义、新材料、权限和原材料读取规则仍一致。
- 新观察直达；历史入口真能返回对应原文/动作记录，不用 source dependency 列表冒充正文已经呈现。
- 交付和 final 生命周期明确；可选产物失败不重放成功动作；未知副作用/未知用量沿用安全停止。
- 精确 tokenizer 核对最终 HTTP 消息与输出预留；在实际服务容量允许时，超过 8k/16k 的请求不被旧 Host 门限拦下；真实容量越界仍须停止或事前改共同任务合同。
- 受限探针如被选择，实际输入须证明限制发生在哪里；只改 input_tokens 不能当作已关闭 K 裁剪，标签也不能代替正文核对。

这些是邻近实现检查，不签发新 Gate 证书、不扫描全仓证据树。一次真实接线检查可属于完整轨迹；改版前缀不得拼接到新版结尾。

文档-only 修改仅查文档。后续代码修改先做邻近及受影响检查；收敛后的工程交付按 [Lab 规范](../../AGENTS.md)记录 boundary、pytest、ruff、mypy、build 的范围和终态。可复用已验证的固定清单分片方式，核对完整覆盖；不得每改一句政策重跑 4,424 项，也不把历史 PASS 冒充新修改的 PASS。原 exit 139 若再次实际影响执行，单独定位受影响问题；没有复现不主动扩展崩溃诊断项目。

## 7. 资源与可调整边界

本轮是**新规划上限**，当前实际 allocation 为 0。后续获得执行指令时用一个短 header 固定本次选择：任务/代码/政策版本、上下文条件、历史保留规则、公共消费者、运行顺序、实际容量及其依据、输出预留、调用/费用/时间边界、凭据来源但不记录凭据值。

| 工作 | 默认规模 | 生成上限 |
| --- | --- | ---: |
| 比较 1：A 正常上下文续接版本 | 3 臂 ×（前段最多 4 + 后段最多 4） | 24 |
| 唯一条件性比较 | 一个独立 root 三臂，或当前 root 的一个消费/受限条件对照 | 24 |
| 独立调试 | 不能归入完整轨迹的接线尝试，含失败 | 4 |
| 合计 | 不转用旧余额，不为用满而运行 | **52** |

少于三臂的第二包不必花满 24 次；所有失败、拒绝和调试生成占对应额度。发送前失败另计 CPU/HTTP，不虚增生成数。最多两轮有明确理由的代码/政策修正，修正后的调用仍在总额内；用尽则报告已有结果，不自动补齐。

### 7.1 模型容量、实验条件和费用上限分别处理

默认复用已有模型/Provider 路径与解码政策，但**执行时核对当前部署的有效上下文容量**。使用既有 Provider 核验及可核对的运行配置，保存值、来源和时点；不把模型宣传窗口、上轮 65,536 或用户提到的增大幅度直接当当前可发送值，也不为读取容量操作 GPU/重配服务。

设 `P_actual` 为最终完整消息经真实 tokenizer/聊天模板计数的输入，`O_reserve` 为本次允许的最大输出，`M_guard` 为尚未纳入精确计数的必要余量，`C_effective` 为当前已核对的有效窗口。发送需满足：

```text
P_actual + O_reserve + M_guard <= C_effective
```

模板和 generation prompt 若已计入 P_actual，不重复扣同一开销。后续若启用 thinking，相关生成须按 Provider 合同计入输出/上下文与成本，不能成为隐藏预算。容量无法核对时先解决这个局部配置问题，不猜一个模型上限。

| 配置层 | v1.1 的处理 |
| --- | --- |
| 输入上限 | 按当前有效容量减去输出及必要余量配置，不另固定 8,192/16,384；只发送本任务实际材料，不为填满窗口添加无关文本 |
| 历史 K | 主比较不启用有限 K；保留能容纳的已发布任务材料和普通历史。K 只属于明确选择的受限/选材处理 |
| 交付长度 | 简洁是软目标；512 不作为接受、呈现或成功的硬门。实际长稿按完整成本评价 |
| 输出上限 | 保留可配置、共同且足以容纳正常动作和交付的有限上限；2,048 不是不可更改的设计常量。`max_tokens` 不等于实际生成量 |
| 独立工作区/引用数量 | 如实际启用则显式配置机械容量并记录；不让旧 work=512 或 focus_refs=4 间接删掉主比较的正文或合法交付 |
| 总资源 | 继续有界管理 52 次生成、实际 tokens、时间及已授权费用；不靠静默缩小某臂上下文满足总账 |

运行前结合实际任务材料和正常输出需求确定 O_reserve，不需要把它机械设成整个剩余窗口。若实际轨迹触顶/截断，记录为输出或容量受限，不当正常语义失败；在剩余包络内可统一制定下一版本，不能给失败臂现场补长输出后追认原比较通过。

若完整合法任务请求确实装不下，先明确报告超限位置；可在新版本为各臂共同拆分任务、使用已有分页，或转入明确受限条件。不能自动只留短稿、丢掉新观察或单独削弱 baseline。若真实总费用预算不足，减少后续比较/请求或提出新的资源选择，不隐藏历史裁剪。

### 7.2 公平性与运行保护

主比较使用相同可用容量、工具权限、输出/调用上限和历史规则，报告实际 tokens；不要求三臂消耗完全相同。若另做固定总 token 的效率比较，须另标资源条件，不能为了凑齐实际 token 数临时截短 baseline。相同上限不意味着相同信息处理，也不自动赋予受限结果正常场景的外推资格。

默认单请求在途，保留调用、工具 CPU 和墙钟上限。上轮单次 60 秒、轨迹 900 秒、工具 CPU 10 秒只是历史参考；本次更大的合法请求和输出须在发送前选定合理的共同时间预算，不能继续用不适用的小窗口 deadline 制造失败。时间包含两段正常生成和读源，不在中断时重置已耗时间；事后不能延长旧实例再追认通过。超出已授权总资源、增加共享服务/隔离环境或产品写入需另定范围。

输入/输出及 reasoning（若后来启用）均计入实际用量；tokenizer、身份检查与生成分别计数。未知用量或未结算状态停止新请求并核账，不写零、不自动重试。实验账记录共享生成一次的真实费用；消费对照复用稿时，策略账另说明形成成本和摊销，不能每个派生臂重复收取实际账，也不能从策略成本中抹去形成。

主 agent/任何另获授权协作者的用量、实验模型、工具/存储和墙钟分账。文档不因过去曾有 subagent 审批而自动授权新委托；开发标注也不升级为独立 human gold。

## 8. 观察与判读：先定位错误发生在哪一步

每条记录只需现有 logger 加少量连接信息：形成输入/原始响应、交付字节和来源位置、后段实际 HTTP body、新观察、读源/计算/行动及结果、最终回答、全部成本和版本。原始材料及轨迹在 Git 外，Git 存必要 manifest 和紧凑报告，不复制整个历史运行目录。

| 层次 | 要问的问题 | 禁止的归因捷径 |
| --- | --- | --- |
| 原始理解/形成 | 材料在场时已有哪些正确结果、哪些误读？交付有没有保留范围与未知？ | 形成时已错，不叫后段遗忘 |
| 传递 | 哪份交付、新证据、旧正文/历史和读取入口确实发送？是否有主动裁剪或真实容量问题？ | 保存成功或上限很大不等于实际全文已经呈现 |
| 后续消费 | 先前正确的内容是否仍被恰当使用？新证据是否使解释更新？ | 只看 final 错，不推出 Memory harm |
| 工作结果 | 是否给出具体而有边界的结论、可推进的下一步或正确世界结果？ | 谨慎到不工作不算胜出；假设不自动算采信 |
| 全成本 | 包含形成、消费、重复读源、失败和交付，是否有净价值？ | 短稿更短或某一次更快不自动等于效率收益 |

所有分配和尝试进入总结果；前段误读、空稿、输出截断、真实容量超限和未完成都保留。超过非强制 512 目标不是失败或排除理由。另列“前段相关信息正确且已呈现”的消费分析子集及具体排除原因，不按消费者答对与否挑分母。不把字节相同等于理解相同，不依据模型自述判定影响。

A 的数值/关联可机械核对，诊断价值和范围由开发者逐条对照原记录；评分答案不进入提示。保留分歧，不默认增加模型 Judge，也不用出现 scope/unknown 等词作为得分依据。任何确定性“正确”仍要覆盖整个任务要求，而非只挑候选保留的一条数字。

首批是开发证据，无统计显著性或跨任务泛化主张。正常上下文和受限条件、不同任务/政策版本、输出机会的运行分开报告；工作段、分支和重复不当作独立样本。先前受限运行仍是有效的条件性证据，不作废、不按新额度追认，也不合并为新主比较胜率。先前普通政策失败和此次成功全部并列，不能只保留漂亮的最后一对。

## 9. 完成、停止与真正的后继条件

### 本 Goal 的正常交付

1. 一个可运行且默认不接管产品、实际执行容量配置与完整历史规则的续接入口，或有界接入失败说明。
2. 至少一个正常上下文条件下的完整三臂形成政策比较；若未完成，只能交付部分/失败结项，不能用受限探针代替主比较完成。
3. 第二包的实际记录或不启动理由；是否有第二来源明确列出，不以“处置完成”冒充跨来源验证。
4. 全部尝试、实际用量、形成/传递/消费错误定位，以及保留、修改或删除的具体决定。
5. 本次变更对应的工程检查终态；不将代码通过当作研究收益。

成功不要求 S 胜出、不要求任何 work_update 被写入、不要求机制类型齐全。若普通交付/普通复核一样好且更便宜，就完成 KEEP_SIMPLE；若只有一个已解释的局部现象，就保留有边界假设，不提前成为默认能力。没有新可检验差异，或有限修正后仍主要测到形成误读/接口问题，即暂停当前候选，不追加第三包。

正常上下文已足够时，这本身就是有价值的取舍依据，不需要继续缩小窗口寻找阳性。只有明确资源或交接问题，才做一次受限探针；其成功不能单独支持“必须增加 Memory/State 调控”的主张。

### 不属于本轮必须完成的内容

- 只有局部现象值得重复，才用未参与调试的独立来源检查稳定性，并核对最接近的最新公开政策/方法。当前没有做新查新或外部复现，不能主张范围保持概念新颖。
- 只有明确候选与强简单对手值得比较，才冻结确认合同；不先建立大量“合格 C”或要求所有 baseline 全对才允许探索。
- 只有实际收益涉及跨会话连续性，才另接现有公开持久化/冷读取，证明提交、真实新 Host、实际呈现、当前证据与行动结果；本轮普通任务续接或可选的控制性上下文切换都不能替代这条证据链。
- 产品 opt-in、默认化和发布另行决定，既不由短稿质量也不由本 Goal 关闭自动触发。

**后续顺序仍是：观察现象 → 找最小有用变化 → 必要的同信息/资源对照 → 独立验证 → 与主张相匹配的持久化验证。不是必须先造一个 State，再为它填满全部实验。**

## 10. 首次执行的最短清单

1. 只核对本次要改的入口/政策/测试和现有成功结果，避开他人工作树改动，不重做旧工程验收。
2. 将 A 的已存在来源映射复用为正常上下文续接版本，明确原材料/普通历史保留、交付一次呈现、共同消费者与原文读取；不向模型提供离线标签。
3. 落实可配置的 Host/Provider 容量，检查无隐含 K 裁剪/512 拒收；执行时核对实际窗口与输出/时间预留，写入 header 和最多 52 次新包络。没有执行指令不发请求。
4. 运行首个正常上下文三臂比较，读实际形成稿、完整输入与后段行为，先定位错误环节；仅在有新信息时选择一个后续包，受限条件显式单列。
5. 完成检查与紧凑结果报告，同步当前状态并关闭本轮；历史 Goal/失败原样保留，不持续向本规划追加流水账。
