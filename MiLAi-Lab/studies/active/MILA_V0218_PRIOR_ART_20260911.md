## 两个直接比较边界

StateMem 的 [wrapper 说明](https://arxiv.org/html/2608.19652v1#S6.SS4)使用 transcript、
retrieved chunks 与问题，在原回答调用内完成 trace/resolve；同篇另设 generic extraction 控制。
与其相比，本轮“原始自写 Note + 当前公开动作环境”并非相同输入/任务，不能照搬论文收益。
如采用状态复核思想，必须明确源事实作用域/权威、真实工具执行与版本，不以最新字符串一律覆盖。
本轮任何额外模型复核都应计账，并与同信息、同调用机会的普通复核比较。
此为适配设计推断，不是宣称原方法不支持这些边界。

Proactive Memory Agent 的 [方法 §3](https://arxiv.org/html/2607.08716v1#S3)
区分记忆维护与暂时介入，允许不提醒；因此固定一句通用提醒只是简单比较器，不是它的复现。
本文关联 [作者仓库](https://github.com/yifannnwu/proactive-memory-agent)；
仅定位，不宣称已审计/运行该实现。第三方多 agent 架构不因此成为 Product 默认。

## 测试床差异与仍未证明的主张

Compliance Trap 的 [方法与控制任务](https://arxiv.org/html/2607.10608v1#S3)
已经覆盖 action-level 配对及可控陷阱，其 RCR 涉及 Judge 分类，不能把我们确定性动作错误数叫官方 RCR。
本轮不同点是外部 task 派生的完整对象判据、原始缺陷反例、真实自主 Note 冷 CRUD/实际字节链、
以及合法现状和未决/无关/Helpful 对照；这些是本轮可核验的实现差异，尚未证明学术新颖性。
MemTrapBench 匹配可执行制品仍未定位，不因看过论文就改成已下载/官方复现。
若声称超越任何最近邻，仍需同条件实现/对照或明确保留该缺口。

后续候选须从全部 E0 行为/成本图出发；如果收益仅由参数澄清、普通复核或同信息提醒解释，

其 wrapper 在同一次回答先提交限长的状态演变摘要，再决断；普通抽取对照匹配上下文、
调用、格式和篇幅，不含状态链或优先规则。该方法足以否定“先概括旧新关系再行动”本身的新颖性。

这是有界定位结果，不是证明代码不存在。

对本轮的设计推断：C2 若有信号，E2 应与普通证据/行动复核及状态追踪概念对照比较。

必须披露它增加的实际保存/生成步骤并匹配普通复核机会，命名为概念适配而非官方复现。
同样，不因本轮具有真实冷 CRUD 和环境 postcondition，就声称原作者从未研究持久化/行为。
候选收益、组件必要性与相对新颖性仍需各自证据；本段没有新模型/近邻效果数字。
