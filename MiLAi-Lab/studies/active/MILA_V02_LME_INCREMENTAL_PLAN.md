# MILA-V02-02：LME 复杂案例与延续收益实验规划

本计划对应 [开发 Goal](../../../MiLAi-Product/docs/goals/MILA_V02_02_LME复杂任务驱动的增量开发_GOAL_20260905.md)。已按条件出口完成，见[执行记录](MILA_V02_LME_INCREMENTAL.md)与[14次分配总账](MILA_V02_LME_INCREMENTAL_RESULTS.json)。L0来源缺陷修复后通过；L1保留标签分歧与候选池不可观测，L2/L3不进入。独立导入提速核对通过；L4两次真实更新与四组U/V完成，8次后续正确但两条历史均未回本。下述规则保持原预定口径，不将阶段不进入改写为六对验证，也不以显式保存冒充自然维护。

## 1. 问题与证据等级

| 实验 | 回答什么 | 不能回答什么 |
|---|---|---|
| 原生 LME 当前任务 | 复杂历史下是否能取到必要材料、正确答题、控制成本 | 保存是否对未来任务有用、自动维护是否可靠 |
| 公开接口/同证据重放 | 缺口在发现、准入/呈现，还是来源理解；普通查询是否足够 | 受控指令自然会触发、oracle 材料在真实运行一定可得 |
| LME 衍生 U/V 续做 | 一次真实更新在不同后续任务中是否回本 | 原生 LME 分数、独立任务数量翻倍、生产任务泛化 |

主端到端臂走真实完整 Host 与锁定公开接口，标 `PRODUCT_BLACK_BOX`。公开只读 trace 用于 `PRODUCT_TESTKIT`；离线 selector union、证据 oracle、参考 Host 等另标 `SIMULATION` / `RESEARCH_PROTOTYPE` 或相应条件诊断。运行路径真实并不使小样本结果自动成为确认性效果证据。

## 2. 数据选择与暴露控制

起点为已有 [opened-development selection](../../data/labels/product05-openworker-lme-selection.v0.1.json)（当前 25 个 case 条目）及历史明确开放的开发片段，身份参考 [数据 manifest](../../data/manifests/longmemeval-s-cleaned-500.json)。既有 selection 的 25 例并不等于 25 个盲样本；历史 128 例同样已属 opened development。

| 集合 | 建议组成 | 使用限制 |
|---|---|---|
| D：开发集，6 例 | 跨会话集合/计数、多证据组合、时间关系、知识更新各 1；普通用户/助手查找各 1 | 可包含已知失败，用于定位与调试；公开选择依据，不估计自然失败率 |
| V：冻结后复核，6 例 | 同样保留 4 个复杂案例和 2 个普通控制；与 D 不重叠 | 不参与本轮策略设计；先固定 case 清单，后运行/评分；记录过去是否已被阅读或计分 |
| R：衍生续做，2 条历史 | 有可复用变化的复杂历史，优先时间更新与多证据组合 | 与原生成绩分开；同一条历史下多个任务按一个 case cluster 报告 |

类型是 Lab 的选择与分析维度，不是 Product 新的封闭路由 enum。按既有元数据与允许的 source-only 审阅确认复杂性，保留原语言、日期、完整 case 历史和干扰信息；不按“候选能答对”挑样。不足的类型、无法判断的标签或 V 机会不足，在分配前说明，不从 Formal 偷补。

优先复用已经导出的开发 source-only 包。旧 runner 会先解析 `population_500` 再取子集，不能直接沿用后声称“未访问 Formal 源文件”。如确需新抽取，用独立受限导出步骤按白名单投影，记录底层源文件访问与导出哈希；Host/Runtime 只收到该 case 允许的来源字段，不挂载完整 population、参考答案、answer-session 标记、turn 标签或 scorer。导出与评分进程不作为在线 Agent 工具。

源文件曾被机器读取、开发样本已暴露、Formal 未正式评分是三件事，分别记录；本研究不新增 Formal 全量读取/评分工作，不声称严格盲留出。

## 3. 固定 A0 与候选定义

主基线是 [v0.2 保留的完整 A0](MILA_V02_MEMORY_FLOW.md)，而不是旧 LME “仅 resolve / 最多两次调用”的受限模拟：

- 使用相同 Host 二进制、模型/推理配置、完整 MCP catalog、prefetch/revalidation、task binding 与合法文件/搜索能力；以实际安装核验为准。
- 默认把该 case 的同一份 source-only 历史文件提供给两臂，也通过公开捕获供 MiLAi 检索。禁止 benchmark 全库、标签和其他 case 串入执行目录。
- 原生问答默认以同样的空 State 开始；不能给候选额外预制答案摘要。若测试已有记忆，先生成一个共同的非 oracle 起点并另列分层。
- B1 只改变 L1 找到的一个一般性机制。A0/B1 的公开能力、来源集合、任务文件、初始 State、预算相同，目标行为及由它引起的输入/输出差异明确记录。
- Product 行为变化时保留两臂各自的安装 artifact/pin，不用已改源码运行“旧 A0”；Lab-only 策略变化时 Product pin 应一致。每次效果运行前验证。
- D1 配置固定并记录；同查询用对应 `previous_context_id`，改写查询不携带旧查询的 predecessor。D2 不公开接入 Context/frontier。
- 不恢复上一轮 A1/H1 长提示，不同时调 Host 提示、召回量、来源和保存格式。不通过 case ID、gold term、扩大 top-k、换 seed 或单臂追加预算补分。

两臂都能直接查源完成任务是有效结果。如果 MiLAi 缺口只在禁止文件的配置下出现，将其作为受限诊断单列，不以此证明完整 Agent 的任务增益。

首轮采用固定许可的去标识开发来源与隔离项目，不包含动态权限/撤销变化试验。读取与引用仍须符合当前资格，State 中的警告不提供披露许可；本轮不能据此宣称撤销后派生内容清理或传播已验证。

## 4. L0–L3 执行顺序

1. 新建研究专用 pin、配置、隔离实例与运行目录；保留前轮已停服务、数据库卷与原始结果。验证安装身份、source-only 挂载和错误回执，不默认复跑全部历史实验。
2. 复用 [历史 LME trace](MILA_LME_CODEX_BEHAVIOR_SIMULATION_20260905.md) 做 L1 诊断；旧结果只用于发现问题。公开查询重放不读取离线答案来改写查询。
3. 如需同证据包或完整正确材料诊断，单列条件与材料来源；gold-assisted 包只在 Lab 诊断，不进入主 A0/B1，也不能成为 Product 策略模板。
4. 修复一般原因，先做定向测试；冻结唯一 B1。D 的 6 对先排顺序、后运行，每批 2 对。不得用 L0 smoke 或历史 A0 配上新 B1，冒充同配置公平比较。
5. D 满足本计划门槛才进入 V。V 的 6 对另行固定臂顺序、输入、预算与评分；运行后不再针对它调参。若更改行为，当前 V 失去复核身份，原结果保留。
6. 并发只在已声明服务容量内；默认串行 Host，最多两对构成一批。臂顺序事先平衡或随机固定，记录运行时间和缓存状态；不按效果重排或选择重跑结果。

只增加测量而不改行为的修复也保留版本与原因；原 trace 不足的运行不自动变成有效配对。基础设施失败和语义失败分别记录，但两者都进入总分配与总成本。

## 5. 评价：先任务，再机制与成本

主要结果是来源支持的任务正确性及首次外显实质判断。参考答案、官方题目条款与允许来源用于离线评价；EM/F1 只作辅助，避免把正确的自然语言句子判成能力失败。明确记录评价者为模型/本线程 Agent/人类中的哪一种；model-assisted turn labels 不称人类 gold。分歧和不可评分案例在配对表中保留。

每例至少记录以下内容：

| 维度 | 最小记录 |
|---|---|
| 输入/资格 | case、来源包与文件哈希，Product/Host 配置，实际初始 bootstrap，工具目录 |
| 取证 | 每次实际 query、predecessor、返回 source/turn refs、公开文本与截断；文件读取的可核对片段 |
| 证据缺口 | 必需来源命中、必要片段在返回文本中的覆盖、首轮/累计增量；候选池仅在公开 testkit 可观察时报告 |
| 行为 | 首次外显判断、最终正确/部分/错误/合理弃答、无依据断言、时间/去重错误、任务完成情况 |
| State | 旧/新内容与版本、来源、实际 diff；未尝试/no-op/成功/冲突/失败/结果未知分别记录 |
| 成本 | capture、projection 尾部等待、Host/bootstrap、在线墙钟、工具动作、input/output、cache 子集、失败和重试 |

后续逐请求实际模型输入不可直接观测时保持 `UNOBSERVED`。工具返回关键片段只叫“返回可见”，不能直接叫“模型已呈现/已读”；更不能仅据此把错误归咎于推理。不采集私有思维链。

不把来源命中当关键片段覆盖，不把 key refs 新颖当证据完备，不把正确引用当完整集合证明。复杂 case 同时报告必要项覆盖与任务正确性；正确记忆/普通查找控制不能被复杂案例的平均分掩盖。

### 5.1 保留候选的开发决策规则

下列阈值是本轮可用性决策值，不是显著性、统计功效或生产 SLO。D 与 V 分别评价；两批均满足才保留有限范围的候选。

- 硬门槛：无标签/越权泄露、无静默覆盖、无新增关键错误或正确控制退化；所有实际失败保留。若有效配对不足或决定性标签不确定，结论为不足，不追认通过。
- 质量路线：6 对内净任务胜例至少 2，且任务损失 0；全体配对 token 比与在线墙钟比的中位数均不高于 1.25；普通控制 token 比中位数不高于 1.10。
- 效率路线：无任务质量损失，在线墙钟比中位数不高于 0.80，token 比中位数不高于 1.05，普通控制在线墙钟比中位数不高于 1.10。即使通过，也仅支持该配置与任务分布。
- 只有关键片段覆盖改善、没有任务或效率收益时，标 `MECHANISM_GAIN_ONLY`；不据此默认启用。

任务胜例是 A0 未完成/错误而 B1 正确完成，反向为损失；部分结果与不可判定另报，不事后修改二值规则。比值分母为对应 A0，零值/未知不填补。除中位数外报告每例和最大开销，避免均值隐藏个别失控。

capture 优化独立于上述在线门槛：用相同完整输入、相同捕获/投影/检索结果核对，报告至少三次受控计时与范围。只有准备耗时改善时称“导入提速”，不称“问答净收益”；缓存/复用的命中与冷启动结果分开。

## 6. L4：一次真实更新能否跨后续任务回本

L4 是独立的小型条件价值探针，不用“自然保存更多”替代。即使 B1 未保留，只要 A0 存在符合条件的真实更新，也可用 A0 做此探针。

1. 在 R 的每条历史内固定当前任务、时间边界和两个不同后续任务，评价条件先封存。后续问题/答案对本次更新生成器不可见。
2. 优先使用自然发生的、有来源支持的更新。若需要显式要求整理恢复笔记，标 `CONDITIONAL_UPDATE`，不称自然维护；没有实际成功更新则该链不进入 U/V。
3. 初始记忆只来自当时已出现的历史与任务，不读取未来 session/答案。按日期追加来源的衍生实验记录 cut point；人为新增变化或注入错误必须另标构造，不能混入自然失效主分母。
4. U 为真实保存前内容，V 为同一条链实际保存后内容；通过公开接口初始化各自隔离分支并映射来源引用。分支版本如实记录，不回退共享 head。
5. 每条链的两个后续任务分别从同一 U/V 起点分叉，使用新会话/新 home、相同任务文件、来源集合与权限；第一个后续中的新 State/文件不传给第二个。因此本轮估计的是“一次保存的两个不同重访收益”，不是完整纵向自维护效果。
6. 保留 A0 本来拥有的全部工具和真实任务文件。需要核对当前来源仍可查；V 不能偷偷多拿未来信息，U 不能少拿已有任务产物。
7. 分别核对正确内容保留、旧结论修正、来源归属、未来变化后是否误用、无必要更新时的额外成本。只换问法重复原答案属于缓存探针，不能充当两个续做任务。

每条链、每种成本单位独立计算：

```text
saved_memory_net_gain = C(U-followup-1) + C(U-followup-2)
                      - C(V-followup-1) - C(V-followup-2)
                      - C(generate-and-commit-update)
```

前后两边共同发生的当前任务成本不重复加入；能分离的新增生成/提交成本全计，无法分离就保守计入整次产生更新的会话并说明。V 重访中的 bootstrap/阅读/再保存已在该会话成本内，不重复加算。token 与墙钟分别计算，缓存 token 不另加到 input，不用估算价格伪造账单。

只有两条链均无质量损坏，且计入更新后的 token、墙钟净收益均为正，才称本小探针观察到成本回本。若收益仅在少犯错误而非省成本，逐例报告质量收益和代价，不声称已回本。机会不足或仅一条更新时仅报告局部事实。

通过也不直接上自动维护：下一步先与“旧 State + 普通简短任务笔记”等简单恢复方式比较，再决定是否需要可选 Host checkpoint。两条历史不构成普遍收益、表示优势或稳定性证据。

## 7. 资源、产物与终态

模型分配预算与 [开发 Goal](../../../MiLAi-Product/docs/goals/MILA_V02_02_LME复杂任务驱动的增量开发_GOAL_20260905.md#6-预算与停止规则) 一致：第一轮最多 16，冻结后复核最多 12，U/V 探针最多 12；总计最多 40，未进入的轮次不消耗。独立模型评分/更新生成如需启动同样计入额度；不默认增加 Judge 或子 Agent 运行。公开查询重放、数据准备与本地测试不算模型启动，但另设超时并计时间。

每会话默认 300 秒、24 次工具动作 watchdog；每批最多 4 次、1,200 秒在线预算。初次 capture/readiness 最多 300 秒/case，投影未 ready 不带病进入效果比较。软 token tracking 不当硬限制，未知 usage 保持未知。总预算耗尽时给出证据不足或基线结论，不用追加样本替代停止决定。

执行时新增一份本研究配置/专用锁、每批分配 manifest、一个紧凑结果表与终态报告即可；不要求重建框架。manifest 记录选择/暴露、输入哈希、版本、臂顺序、预算、评价来源与允许结论。拟生成的文件在实际创建前不写成已存在或已封存。

源码与定向单测按 Product/Lab 所属仓库保存。原始来源、外显 transcript、运行 home、数据库、Provider 用量与完整 trace 放 Git 外；紧凑分配、指标、失败记录与结论进 Lab。禁止保存凭据、把同一运行重复计分或删除失败证据。

退出时报告全部分配的终态、有效配对、任务/机制/保存三个分开的结论、总已知成本与未知项。只停止本研究可核验的进程与服务，数据默认保留。Product-11 旧封存、Formal 评分、公网和 Schema 均不因本计划变化。
