# MiLAi Host 记忆调控：开发规划 v1.0

## 1. 开发目标与工作方式

**目标不是再跑一轮提示比较，而是完成一套可运行的 Host 算法：独立维护、工作安排、实际选材、候选暂存、可逆回读、有界交付、检查点恢复。** 创新增量逐项加入这套实现，简单效果检查伴随开发；完整版本形成后再做系统性的 benchmark 研究。

架构依据：[详细架构 v0.2](MILA_HOST_MEMORY_CONTROL_ARCHITECTURE_v0.2_20260914.md)。该架构中的流程、内部类型与新增路径是本次设计，不冒充已有接口。

本文件不启动代码执行、Provider 请求或新实验，不继承已关闭 Goal 的额度。后续开发可以在明确授权的资源包络内连续推进，不需要每个正常函数调用或每个组件小变化都重新制定 Goal。

**完成架构不以候选胜出为条件；完成效果确认也不能由架构全绿替代。** 允许先集成组合，再根据实际行为删减；不要求每个局部先超过 baseline 才继续开发，不因一次打平立即停止整条路线。

## 3. 首版完整范围与暂不建设的内容

### 3.1 本轮实现范围

| 能力 | 必须落实的运行行为 |
| --- | --- |
| 生命周期维护 | 新反馈进入 Controller；不依赖 Actor 自选一个写记忆字段 |
| 决策工作记录 | 形成可错的依据、范围、未决项和当前位置；可保持不变 |
| 当前工作安排 | Controller 给出问题、意图与材料引用，实际进入下一 Actor |
| 工作集管理 | 选中原文展开，未选旧正文退出自动回放但仍可合法读取 |
| 候选与返回卡片 | 线索可暂存，记录可更正，旧路线可展开后重新判断 |
| 交付处理 | 最终草稿使用同 Controller 作有界接受/修订/继续决定 |
| 检查点 | 本地保存/恢复和公开 Working State 适配；来源可恢复性分开核实 |
| 可用性与简单对照 | 关闭插件可回原 Host；新架构普通政策与候选共享能力 |

这些能力是交付对象，不是要求模型在每个任务中全部使用。实跑未自然出现的功能，应区分“实现已验证”和“行为尚未观察”。

### 3.2 不以“架构完整”为名扩张

首版不开发图数据库、自动训练、多 Agent 讨论、语义依赖 DSL、统一置信度评分器、后台观察服务、全局自动提示优化、全 benchmark runner 或新的 Judge 平台。

已有摘要缓存和原生 verifier 继续用；兼容新框架只保留接口，不一次适配所有框架。多模型蒸馏/同调用融合/跨任务经验库可以后继研究，不作为本次完成条件。

## 5. W1：完整循环应怎样写

### 5.1 核心数据与纯逻辑

新增或扩展 `controlled_workspace.py`，提供：WorkspaceSnapshot、MemoryCard、FocusFrame、ControllerProposal 及机械更新接收。允许记录不变，允许 Frame 变化，卡片不要求固定栏目。

模型只能引用已公布句柄，Host 分配新卡片 ID 和 revision。scope/权限/目标版本来自 Host。语义内容自由，不能按关键词或任务名称自动产生“暂停”“验证通过”。

开发时优先小快照加整条卡片替换。只有实际重写成本成为问题再引入更细 patch；不要先建设一个通用编辑语言。

### 5.2 生命周期与调用

`workspace_control_session.py` 复用现有客户端，每批新反馈最多一次正常 Controller 调用；后续显式回读或交付请求属于单独可见事件。重装同一输入不再次调用；失败结果不覆盖旧状态。

ACT 后调用 Actor，原业务动作与原执行路径不变。所有真实反馈不仅进入 Controller，也以受保护观察进入 Actor；实现不能只给 Actor 看维护者改写后的版本。

控制输出和业务动作分开解码，减少可选记录抢占动作容量。ModelPort 使用同一模型 profile，但为控制和行动分别记录输入/输出上限和实际用量。

### 5.3 最小邻近检查

只需覆盖本次新增风险：新反馈不丢；同一批不重复维护；Frame 确实进下一请求；来源引用合法；动作不因工作区错误重放；Controller 失败的回退明确标识。尽量直接扩展已有测试，不新建统一“执行证书”。

真实短片段记录成功或失败即可，不要求强制非空更新。若更新为空但 Frame 已决定了合理材料与动作，该部分方法仍在运行；若两者都无实际差异，则定位政策/输入，而不是继续耗尽任务额度。

## 6. W2：创新政策先做具体增量，不做规则堆叠

### 6.1 依据维护

从原始动作与观察提取会影响后续选择的事实、限制和未决项；不把代码意图升级为测试事实。新观察只改变部分依据时，可以缩小范围或拆分结论，不必整体换路线。

评价行为时，不预设“缺少专项测试”唯一意味着继续测试。模型可能采用其他合理证据、承认限制或继续工作；关键是最终选择与任务要求、证据强度一致。

### 6.2 Frame 与实际任务动作

Frame 是短的当前问题和下一步目的，不是长计划书。Actor 可选择具体命令，也可以根据原始新观察修正意图。不要编程成 `if "未测试" in note: run_tests()`。

记录版本、Frame、实际输入、动作之间的关联直接沿现有 logger 保存。它帮助定位增量是否运行，不把“字段非空”视为效果。

### 6.3 交付循环

把“最终草稿”从“立刻停止进程”中分离，接入同 Controller。有界一次复核为开发初值；复核后继续工作不自动重置复核额度。停在未知状态时交付有边界结果，不声称已完成。

这里不是加入独立评分器。其调用属于方法成本，不能放到离线评价账。普通控制对照有同样复核机会，不人为让它更弱或更贵。

## 7. W3：真实工作集与返回能力

### 7.1 工作区不是另一份不断累积的全历史

旧 Controller 文本完整归档，但正常输入只提供当前有效版本；真实动作和观察保持关联。当前活跃内容、必要近期消息与新观察受保护；旧正文按 Frame 选择展开，完整来源可取回。

已有历史在容量内全部保留的模式仍可作为诊断，但正常 RWC 必须真正改变材料展开，不能只追加一段焦点文本。

### 7.2 RECALL 作为真实操作

使用既有来源/段编号读取原文；未知句柄显示问题而不是任意联网。读取到原记录后让 Controller 再判断，这次模型调用照计；同一页面重复请求不是免费重试。

Actor 可以沿已有 retrieve 入口提出回读，Controller 也可以主动选择。两者最终映射同一个 SourcePort，不建立互相不兼容的两套档案。

### 7.3 返回卡片

卡片中的线索不自动进入当前主要上下文。退出焦点不等于无用，回到焦点不等于当前可采用。旧卡片若错误，应修订而不是永久保留为“也许以后有用”。

恢复分支时环境状态保持真实。测试不允许用恢复旧容器快照伪装认知恢复；确实用快照回放时另标 replay 条件。

卡片上限采用容量配置，不要求每轮几个分支；目录过大用现有分页，不新建关联图与语义排序系统。

## 8. W4：持久化必须真的能接续

### 8.1 先区分两个适配实现

- **Local checkpoint**：开发环境的持久文件/既有 artifact store，验证序列化、来源归档和游标续接。
- **Public Working State checkpoint**：现有 MiLAi 公开保存/读取，核对 scope、CAS、引用披露及 TTL，验证新 Host 冷读取。

二者可以共用同一 CheckpointPort，但结果不能混报。完整首版目标包括公开适配；真实接口缺口使其未完成时，明确记录缺口，不让本地通过代替公开完成。

### 8.2 开发事项

保存工作区之前确认必要来源已持久归档；临时文件路径不可充当长期引用。保存带事件位置的快照，未维护的新工具结果可从原日志补回，避免“动作成功但 State 还没写”造成静默丢失。

恢复不从 State 猜业务副作用。存在未知操作时走原 operation/status 合同；没有可靠结果时保持未知，不能自动重新执行。

插件仅替换自己的命名空间，保留其他 Host 状态。CAS 冲突不自动语义合并，payload 受限不当空白。无需为首次接入修改 Runtime 字段或上限。

### 8.3 冷恢复小检查

选择可保存、可继续的现有任务安全边界，停止旧 Host，保留真实任务环境和合法来源。新 Host 读取检查点并接收当前观察，通过同一循环继续。

检查“引用可读/事件续接正确”与“下一步质量改善”分开。主动设置中断是开发适配，不声称原 benchmark 本来就在评估跨会话 Memory。

## 9. Baseline 的保留与比较顺序

不重新启动一次从零复现 HiAgent 的项目；R1 已给出 H_ONCE 的实际入口。先复用，再以源码差异说明是否改变了行为。

| 比较对象 | 何时使用 | 回答什么 |
| --- | --- | --- |
| H_ONCE | 完整方法工作后少量原生任务 | 新方法组合相比现有已运行工作记忆方法是否值得 |
| INCREMENTAL | 维护变化需要回看历史解释时 | 更特殊维护是否比普通增量摘要增加价值 |
| WORKSPACE_SIMPLE | 新架构集成创新政策时的主要配对 | 在相同调度、卡片、选材、回读、复核能力下，候选政策是否有增量 |
| 原生普通 Host | 出现怀疑外壳/工具负担的问题时 | 是否只是改进了自己引入的受限 scaffold |

不每次运行全部模式；不削弱普通方案的自然能力。H_ONCE 缺少某新能力时，比较属于组合；要拆政策贡献，使用同结构 WORKSPACE_SIMPLE。各方法额外调用如实计入，不删除已有算法的必要步骤来制造“单调用公平”。

近邻来源与设计差异见架构文档。HiAgent、Mastra、MemR³、ACE、AgentFold 是学习和对照材料，不是每个都必须集成的依赖。没有拿到指定版本的完整实现，不称忠实复现。

## 10. 随开发做什么测试，暂时不做什么实验

### 10.1 三层证据

| 层次 | 合理方法 | 能说明什么 |
| --- | --- | --- |
| 机械正确性 | 可控响应、原轨迹回放、局部 unit/integration | 调用时序、选材、消息完整性、回读、保存恢复按设计执行 |
| 局部行为可用性 | 一个真实检查点后的少量模型步骤 | 模型是否采用能力，下一步如何改变，是否带来明显负担 |
| 整体任务效果 | 少量完整原生任务和强简单配对 | 新方法组合是否完成工作、代价如何；仍是开发观察 |

实现中的 mock 可以指示一次回读，以检查技术路径；效果轨迹不能代模型写理想工作记录或提供未来答案。实际自主使用、用户显式要求恢复、受控响应触发分别标记。

### 10.2 先用现有、已可用的任务

`cancel-async-tasks` 是已暴露调试题，适合验证接线和真实反馈使用，不再作为唯一创新证明。`multi-source-data-merger` 可利用前轮已运行资产，检验是否只有写代码类任务能使用政策；其历史成功和小规模限制也须保留。[R1][R2]

`query-optimize`、`build-cython-ext` 的环境/下载失败已经出现，未解决前不反复消耗模型尝试；准备不依赖模型的资源可按原任务合法方式缓存或复用，环境版本差异记录一次，不更改任务答案。[R1]

完整候选形成后，再从现有固定 benchmark 中选一项未用于当前政策调试且环境可用的任务，保持同一政策。元数据已读不等于独立确认；公开未调试也不保证模型训练未见。这里追求开发迁移，不追认确认集。

### 10.3 简单效果判读

每个增量只围绕一个问题观察：**这次增加的能力改变了哪一步？变化让工作更接近完成，还是只增加文字/调用？**

有必要时做一个共同起点的两方法续接；共用前缀来自哪种方法、是否含候选生成记录写清楚。续接仅解释该检查点之后的增量，不能作为完整生命周期成绩。

一条轨迹没有真实返回机会，不能计算重激活率为 0；一个原生任务未评分，不能伪造 reward 0。局部子测试通过数不是独立任务数。重复命令也可能是有效验证，需结合状态变化与问题判断。

### 10.4 暂不做

不为每个微调重跑六臂或全任务集；不为了填表启动 12/54 条轨迹计划；不每次失败重写 Judge；不为了覆盖所有机制添加假事件；不在完整方法尚未工作时开展统计确认。

## 11. 配置与资源规划

以下是配置语义建议，不是可直接运行的现有配置文件，也不是本次模型授权：

```yaml
method: milai-rwc-v0.1
model_profile: inherit_current_verified_profile
controller_model: same_as_actor
controller_schedule: new_feedback_batch_and_lifecycle
projection: managed
policy_bundle: rwc_controller_plus_common_actor
summary_cache: reuse_h_once_trial_local
checkpoint: interruption_handoff_or_explicit_save
final_review_rounds: 1
consecutive_recall_expansions: 2
workspace_capacity: inherit_working_host_then_tune_soft_targets
actor_output_capacity: inherit_working_host
controller_output_capacity: set_explicitly_for_small_control_payload
run_limits: supplied_by_authorized_run_configuration
```

`final_review_rounds` 和回读次数是防跑飞的可调开发值，不是认知规律。禁止以每次 Frame 变化重置总预算或复核额度。

初次实现测试可优先零模型；每个开发切片需要真实行为时先给一段短调用包络。完整任务沿原生时限与统一总生成限制，Actor、Controller、摘要、复核及失败调用共享，不能给新增维护开隐形无限账户。

旧报告的 64 次/轨迹只能作为历史参考，不自动成为新架构的等效动作机会；新增 Controller 后应显式分列实际调用类别，必要时前瞻调整共同配置。不能在候选即将超时后单独延长，也不能把多次调用称作一个 Host 步骤而漏记。

成本用量分别记录实验模型、工具/来源、持久化、环境/verifier、开发代理。无费率不估美元；未知用量停发核对。静态 profile 校验不每轮重复整仓扫描；真实动态权限照旧检查。

## 12. 代码任务的交付标准

### 12.1 功能完整

同一个方法入口可以完成：启动、真实观察、维护、Frame 装配、Actor 动作、回读、最终交付提议、有界结束、保存与恢复。关插件可以回原入口，旧方法默认不变。

卡片更新不要求模板，机制不按 task_id 硬编码。控制不是仅追加文字；选材确实改变输入；返回确实读取原材料；恢复确实处理未观察完的事件。

### 12.2 工程检查适量

每次实现改动做邻近测试与受影响静态检查。纯政策修订不重复全仓长回归；代码版形成交付时按仓库规范完成相应完整检查，保留真实终态及未完成项，不重复刷 PASS。

失败处理不破坏既有工具、权限、动态版本与安全隔离。原生容器不能访问宿主凭据/源码私密区或管理 socket；开发优先不等于绕过必要边界。

### 12.3 使用说明足以交接

说明如何从已有入口选择方法、选模型/政策、运行一个原生任务、查看当前焦点与原始记录、暂停保存、恢复、关闭插件、读成本账。命令与实际参数以最终源码为准，不把本文拟议名称当已存在 CLI。

### 12.4 研究状态诚实

分别标识：implemented、unit-exercised、replay-exercised、live-exercised、locally-helpful、not-supported。标签仅用于交付描述，不建设新证书服务。

没有自然触发的能力不称“模型已善用”；已经运行且没有收益的政策不称“未测试”；完整组合的一次失败不追溯否定全部单项，完整组合一次获胜也不分摊为四个创新都成立。

## 14. 开发中的修改、停止与收缩

允许调整卡片表达、投影粒度、Controller 提示、维护批次、回读方式与完整组合。每次有具体观察和版本；不同版本不拼成最佳总成绩。

当问题只是格式与容量，不开 decoder 专项；当环境不通，不叫 Memory 无效；当记录表达更丰富却不影响动作，修改控制联系或缩减它，不继续堆提醒。

当候选在同等能力的普通控制政策下没有净价值，可以保留新架构中确有用途的基线能力，关闭特殊规则；不要求为了创新将其设为默认。若共享候选记录使普通 review 打平，先删除特殊消费部分，再判断形成/维护的价值与成本。
