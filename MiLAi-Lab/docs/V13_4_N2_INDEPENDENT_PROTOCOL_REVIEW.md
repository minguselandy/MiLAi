# v13.4 N2 独立协议审查

结论：现有 32 个 RFC 实质更正候选可进入**单一自然来源家族的 T0 适配与可解性审计**。它们尚不构成计划四层各 8 条、128 个已标注 query、32 个已证实语义独立历史，或 G1 已成立的证据。不能仅凭 compact manifest 断言该家族完全不可能包含时间／范围歧义；同样不能用“有技术更正”证明目标关系歧义存在。

本次是独立于主协议作者的开发协议审查，不是语义 Judge 或第二位独立标注者。只读计划第 07–13 节、来源 acquisition/freezing manifest 及元信息；未读 RFC/erratum 正文、source-view 正文或 query/gold，未调用模型，未修改现有 requirements 或源码。

依据：[原计划](MILAI_FOLLOWUP_RESEARCH_DEVELOPMENT_PLAN_v13_4.md)、[取得清单](../data/manifests/v13-4-t0-acquisition.json)、[取得前冻结](../data/manifests/v13-4-t0-acquisition-freeze.json)。本审阅取得清单 SHA 为 `1c3f9e5a9588345a0f6c884e4017df50f69f158a2f61865bdc16fc7e6daebcb6`，取得前冻结 SHA 为 `ee8db657a6228778c30655a52de259cb94d51e43dacd5404d3c1fbe86323ffcc`。

## 当前证据及其限度

清单记录 36 份原 RFC、68 份官方 erratum，32 个实质更正候选及 4 个有记录的简单／不适用排除；32 个候选对应 32 个 WG/update 组件标签。当前 T0 准入、query、writer metadata 调用、独立标注均为 0。32 个候选中 15 个只有一份 erratum，7 个有两份，6 个有三份，3 个有四份，1 个有五份。原 RFC 大小为 28,360–1,593,486 bytes。

这些计数不能证明四层分布。单份 erratum 也可能需要原文背景，多个 errata 也可能只是互不依赖的若干错误；数量不能判定充分集合。WG/update 组件仍需加入语义依赖、共同任务模板和派生关系，不能为了保持 32 而拒绝合组。共同网页格式本身与共同语义题目模板应区别登记，避免既凭同一 HTML 模板夸大相关性、又把反复套用同一语义问题模板伪装成新任务。

当前材料属于一个技术标准／勘误工作流。根据这一来源选择方式，可以预见“原文写了什么、公开勘误要求改成什么”可能大量由完整更正直接解决；这是一项待正文标注和 B1/B2 实验确认的推断。不得将普通技术推理困难、候选漏掉长文片段或正文装不下，改称“变化／纠错／范围关系仍有歧义”。现有清单记载的 TBD 更正与 PDF/HTML 适用范围是值得保留的真实限制，尚不足以证明需要 8 条不充分或 8 条互补历史。

## 顺序冲突的最小处理

建议采纳 Root 提议：**N2 先执行一次预先冻结的极简 query-free Writer 形成并封存，然后才生成 T0 问题**。在主协议中明确登记这是将 N3 的“形成子步骤”前移，用于保证第 05/10 节的因果顺序；不是提前开展 T1 信号实验。G1 前不训练 predictor、不作 T1 优势判断、不修改 selection、不根据问题或答案修补 metadata。费用、失败和 unknown 全部保留。

这个调整保留第 10 节同一批 T0 开发历史，也保留 metadata 实际先于未来 query。替代方案先做只有公开字段的 T0、再另取 T1 新历史，消耗更多来源且偏离“对 T0 历史形成”；不能声称已对同一 T0 问题证明前瞻形成。若选择后者，需要单独明确修订，不能把事后 replay 记成先于原 query 的形成。

前移形成至少满足以下顺序，元数据冻结之前不创建自然问题或 E*：

1. 冻结来源资格、已有曝光、联合组与保留／替补规则。保存本批确属开发的事实，不回收为正式测试；保留全部排除及已读来源。
2. 冻结 query-free 分段、原文到段的 hash/codepoint `[start,end)`、HTML 到可读文本的映射、公开字段和关系边生成规则、失败处理。先分段再有问题；后续不能按 gold/E* 裁正文。
3. 冻结 Writer schema/prompt/model/参数、每个事件前缀可见哪些材料、输入上限与调用计划分母、解析失败为 unknown／回退的规则。只允许历史和公开来源字段，禁止 evaluator 适配标签、四层归属、预想问题、答案、充分集合、未来状态。metadata 形成和普通索引成本全部计入。
4. 对同一预先固定集合按同一规则形成一次，保存每次输入／输出／时刻／成本／失败和 metadata hash。不能只对后来准备出题的片段形成，也不能让未选正文的语义解析在后续 query 阶段免费发生。需要超限分块时，规则和调用数量在看问题前确定；未知请求或失败不择优重试。
5. 封存全部 metadata，再以独立 Writer/Evaluator 输入路径生成自然 query，随后建立 E* 与评分规则。query 作者仅依原历史和冻结的任务目标，不依 metadata 预测结果、任何方法排名或先跑的 Reader 答案挑题。没有真正独立第二标注者时，仍标单人开发审查。

取得前 freeze 的 `new_model_http_allowed=false` 等字段属于已结束的 acquisition 阶段，应原样保留。新 N2 协议应显式规定本阶段 Writer 调用权限与费用，不能通过改旧 freeze 解锁。

## 来源时间与形成边界

官方 publication、reported、verified 等时点属于来源声称的记录事件，不是自然语言规则的 valid_time。observed_at 保持真实 HTTP 收到／受控 ingestion 时间；不能把现在下载到的 Verified 状态追填到早年的 report_date。query 若问旧时间点，只能用当时确实可见的状态版本；没有旧页面快照时应标缺证。

若按先原 RFC、后 errata 的归档导入顺序回放，必须明确它是受控 ingestion 顺序，记录真实回放时间与实际 HTTP 收到时间；不能称重现了历史用户接收顺序。每次 Writer 只能看当前已导入前缀。若先在全部档案可见后形成一次元数据，应明确这是当前归档形成边界，不能称原 RFC 最初发布时就已形成这些字段。

公开 erratum 的章节指针可在该 erratum 已出现后形成共同关系索引，不能提前指导尚未出现该 erratum 的原文形成。多处同文／定位失败保留歧义，不能由 evaluator 悄悄给 Writer 指正确 span。

## B1/B2 与候选池的最小共同合同

原 RFC 是可追溯档案，不应整本作为唯一可选证据单位。公开固定分段允许完整段落、章节和长段落的机械分块；不删约束、不做 query 定向压缩、不把不同来源内容混成一个无身份片段。官方 old/corrected/notes 都保留来源及跨度。单个必须完整送达的单位仍过长时，明确报告分段或 packing 限制，不能归为 G1 的关系机制缺口。

共同普通检索只运行一次，冻结候选 IDs、分数、上限 K、tokenizer、预算和候选外遗漏口径。完整更正链扩展必须是所有臂共享的公开关系图／同候选闭包；若扩展导致超过 K，截断／成组预算策略事前冻结，不能只给 B1 完整链或只给 B2 额外来源。source/section 指针是公开内容时可以合法使用，但不能把 evaluator 找到的 gold 章节注入共同检索。

**B1** 在普通检索和共享可见关系上保留原始声明及其更正，完整装包且报告遗漏。一个 RFC 的多个 errata 不天然构成按日期或编号排序的连续修订；没有明确同一目标或 supersession 证据时应呈现分支，不制造 `erratum A → erratum B`。

**B2** 只在同一候选和同一实际 query-free 字段上使用明确时间／范围线索；unknown 不当作不相关，不能免费多调一次规划 LLM，也不能把 published/verified 当生效时间。B1 能获得相同 metadata，差别是冻结的使用策略。共同 Q0/Q1、Reader、prompt、可读材料预算与 metadata 占用相同；如果 B2 只有 unknown，就如实退化并说明，不强造差异。

B4 主 approximation 定义应在 N2 准入前锁定，未满足自然语言结果模型条件则保持不可运行／近似；T0 的 B1/B2 审计不能成为“优于通用主动取证”的结论。FullArchive 只在实际可装入时作另计费用的诊断；超上下文必须明确缺失，不能用未声明的摘要／分批整合代替完整档案。

## Query、E* 与分层

四种 query 是当前明确结论、陈述历史、根据当前更正追溯适用、跨范围／对象。它们是 evaluator 的任务维度，不是运行时标签。RFC 的自然引用可作为问题所指对象，但不能注入 gold source ID、标准动作或隐式检索路由来指定答案；只问某 erratum 的 corrected 字段时，应如实标为直接读取控制。

每条 query 至少记录：合法截止时间、archive 可解／不可解／未知、答案模式、允许部分答案、剩余不确定性及理由、兼容解释、直接／部分／无关／误导／重复来源、最小充分集合族 E*(q) 的原文跨度与完整性状态。共同已读材料 C 也要冻结；已包含在 C 中的依据不重复要求另读。

E* 不能默认总为 `{RFC 原文, erratum}`。如果 erratum 自含 old/corrected/notes 已充分，应允许它是 singleton；如果原文及官方引述是等价可替代依据，应保存替代集合。只有各个子集确实不足、联合后解决同一问题的约束时才标互补；两段位于不同文件并不自动互补。用删除每个必要成员的证据审查证明最小性，不能把 Reader 恰好答对当充分性标注。

缺少完整集合标注时保留 unknown：命中一个已核实充分集合可证覆盖；未命中已登记集合，但仍可能有遗漏替代集合时，不能强计 0。不可解 query 覆盖为 N/A，不是 0 或 1。全文不足只针对给定档案和截止时间，不能声称世界上没有信息。没有合法证据的合成隐藏真值不进入强制回答得分。

四层各 8 条是计划建议的起点，不能从结果反推层归属或为凑数修改原史。先做所有 32 候选的实际适配审查，再报告自然分布和缺口。若该来源家族缺互补／真正时间范围歧义／自然不充分案例，保留其 T0 家族审计结果，另按前瞻资格修订取得合适独立来源；标记构造诊断可以补机制控制，但不能替代自然发生率，也不能将未满足的完整 T0 目标标为完成。4 个已排除的简单来源继续留曝光账，不再因 B1 成功而剔除正常／无歧义控制。

## 最小执行与决定

在上述形成时序和合同冻结后，完成候选历史的 query 与单人开发标注，单列尚不能自然形成四类问题／尚不能判定集合的缺口。先通过机械 span、视图隔离、预算、候选一致及只读检查，再以原始答案执行 B1/B2 配对 Reader。原计划 32×4×2=256 Reader 是待满足的计划分母；未准入、不可生成、不充分、未运行分别保留，不靠缩分母报完整。

最早断点按档案缺证、候选漏证、包装漏证、证据解释错误、关系假设遗漏报告。G1 的正证据须同时证明：目标问题存在会改变答案的关系歧义；所需消歧材料在合法档案；同预算完整链／时态仍有可重复缺口；缺口不能只由本研究的人为分段／整本超限或实现不完整造成。基线足够就 Simplify；自然来源不适配则先收缩该家族结论／补来源，不强造 M 获胜任务。

T0 只作开发审计；不将一个技术标准工作流外推为个人记忆、未见工作流、正式泛化或产品可靠性。G1 之后才分析已经封存的真实 metadata 信号并启动 T1；H1/H2/H3 各自两轮已曝光修订上限继续有效。T2/T3 所需新历史、第二家族、最近邻、公有迁移、正式聚类配对统计和效用非劣均未由本审查满足。
