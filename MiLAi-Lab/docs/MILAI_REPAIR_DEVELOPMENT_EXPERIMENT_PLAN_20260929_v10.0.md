## 1. 决策摘要与执行边界

### 1.1 本计划要完成什么

本计划把上一轮分析转成可实施、可验证、可回滚的修复工作，而不是再写一份完整平台建设路线。

优先完成三件事：

1. **停止模型输入中的程序标签被当作可复述正文反复放大。**先处理输出可靠性，不顺带宣称解决额外动作。
2. **单独处理任务完成后的不必要业务变更。**区分第一次越界行动、模型再次提出相同操作、传输重试和真实未知结果。
3. **查清并修复 MemSyco 范围控制退化。**区分来源限定未保存、已保存但未正确采用、呈现影响和 Judge 边界，不能直接归因为检索漏记录。

随后按证据推进写入责任、精确对象发现、时间表达和 SimpleMem 预算适配。保留 State–Attention 作为研究方向，但不让它承担已经定位在输出、执行或资源层的错误。

### 1.2 本文不是恢复指令

当前 Goal 在来源报告中为 `PAUSED_BY_USER`。本文仅生成新规划，不恢复实验，不修改源码，不合并 PR，不改变服务，不重放已有业务，不下载模型。[S01]

实际开始前需要新的明确授权，并确认其覆盖哪些工作包。若只授权离线开发，则不能据“后续条件满足”自动发送真实 Host、embedding 或 Judge 请求。

历史文档中的 `Continue`、`ACTIVE`、条件路线和待办不能覆盖用户暂停。本文也不将尚未执行的138单元 SimpleMem 开发表当作必须立即完成的欠账。

### 1.3 最重要的执行调整

| 旧风险 | 本计划要求 |
|---|---|
| 遇到失败就重写 Memory 架构 | 固定现有架构，每次只修改一个有证据支持的变量 |
| 一条失败取消其余全部研究 | 普通语义失败保留并继续安全、独立的冻结任务；执行失控只阻断受影响范围 |
| 新标签、新字段默认有益 | 任何进入模型输入的文字都是行为变量，必须有对照 |
| 强制写入、自动补答案制造成功 | 只依据真实动作和公开任务验收，不做隐藏答案修正 |
| 小切片全对就认定稳定 | 区分机械正确、局部修复、独立确认和产品准入 |
| 等所有任务满分才进行研究 | 合同正确后，失败本身就是有效证据；不以满分替代归因 |
| 原生 baseline 调参后继续沿用原名 | 原样版本与预算/接口适配版本分开命名、冻结和报告 |

### 1.4 与统一 V8/V9 的关系

本文是统一 V8/V9 的**修复执行层补充**，不是覆盖原计划及结果。已完成的 MCP 功能链、benchmark 接入、五方法主表和 SimpleMem 工程不重复开发。

原计划中的 U3、U4、U5、U6 继续保留；本计划以 R0—R7 定义当前优先修复。附录 A 给出映射。功能修复不需要以 MiLAi 胜出为前提，也不自动构成新的算法贡献。

## 3. 保持的架构与禁止的捷径

### 3.1 保持当前成熟底座

继续复用 LangGraph Agent、真实 MCP、严格 Memory CRUD、Store、checkpoint、RequestContext/Renderer、实际业务工具、来源与回执、原生scorer和连续账本。不增加第二数据库、常驻Reviewer、全局仲裁器或另一套记忆运行时。

```text
合法来源 / 实际观察
        ↓
同一逻辑 MemoryService（增、删、改、查）
        ↓
当前任务工作视图 / 必要时 State–Attention
        ↓
同一 ReAct Host
        ↓
原生工具执行与真实回执
        ↓
任务继续、维护或明确未完成
```

工作状态可缓存有依据、带作用域的当前事实；不要求只能保存指针。但不能独立长期维护另一份“当前真相”，也不能把assistant旧说法或错误提案认证为事实。

### 3.2 六项不变量

1. **历史真实性：**原始用户、assistant、工具正文和身份保留；修复只改明确声明的模型视图或执行策略。
2. **副作用真实性：**提案、尝试、成功、部分成功、失败、未知分开；世界满足某条件不替代正常终答和完整生命周期。
3. **信息权限：**runtime不读rubric、gold、未来episode和评分器状态；公开题目中的业务规则仍必须遵守。
4. **时间语义：**收到信息的时间不是信息适用时间；旧观察不是实时状态；当前值与历史值都可能是合法查询目标。
5. **范围语义：**相关不等于适用，适用不等于应压过当前任务；临时要求不自动变成长久偏好。
6. **成本真实性：**计入所有实际Host、writer、selector、embedding、Judge、重试与中断；不通过清零或缓存偏置制造优势。

### 3.3 禁止作为本轮修复的做法

不得全局删除模型已生成的标签、自动替换业务key、从评分器识别“任务已完成”、在成功世界状态后直接补终答、用同参数去重拦截一切合法后续动作、给候选免费后台写入、只给中断方法增加额度、改变外部基线后仍使用原名称。

不将“少一次调用”当作最高原则；也不将“多一次校验/反思”当作可靠性保证。两者均以完整任务结果与总成本检验。

## 6. R1：assistant 标签回流修复

### 6.1 目标与假设

**事实：**当前`MemoryBoundaryView.project()`向assistant请求副本添加两类角色标签，工具调用历史还经`assistant_call_labels`进入renderer；真实模型随后重复输出相同标签。[S06][S07]

**假设H-L：**逐assistant正文标签增加模仿与回流风险。删除这类程序附加正文可能减少重复输出，但不保证修复第一次额外动作，也不保证消除所有解码重复。

### 6.2 最小改动

建议新增一个明确实验开关，名称仅为提议：

```json
{
  "assistant_role_labels": "native_roles_only"
}
```

枚举值建议为`legacy`与`native_roles_only`。旧配置默认`legacy`，使历史recipe不静默变更；不要复用`compact_v6`开关一次改变多个变量。

在`native_roles_only`路径：

- 不再给普通assistant正文拼接`[ASSISTANT HISTORY - prior model output]`；
- 不再给带工具调用assistant正文拼接`[WORKING HYPOTHESIS]`；
- `assistant_call_labels`不产生上述附加项；
- 原生`role/content/tool_calls/id`保持，JSON-action历史编码本身保持；
- 用户/工具材料、current_request placement、compact/full投影、system协议与工作状态结构不变；
- 不删除system工作状态中的同类标识。本轮只检验逐assistant附加行为，不能报告为“完全无标签”。

配置校验应验证枚举并纳入方法identity；不因现有字典允许额外字段而跳过合法值检查。

### 6.3 文件与边界

| 位置 | 本次职责 |
|---|---|
| `methods/memory_boundaries.py::boundary_policy()` | 新选项校验与旧行为默认 |
| `methods/memory_boundaries.py::MemoryBoundaryView.project()` | 控制程序附加assistant标签 |
| `methods/request_context.py::render_request()` | 验证不经其他分支重新附加；尽量不改编码结构 |
| 当前boundary/renderer测试 | 增加legacy等价与候选精确差分 |
| 现有freeze/manifest | 记录开关、请求差异、源文件身份 |

这是行为修复，不标作“完全等价重构”。legacy路径要求字节等价；候选路径要求**只有预声明的标签差异**。

### 6.4 绝不实施的内容

不执行`replace('[WORKING HYPOTHESIS]', '')`清洗整个历史；不裁掉模型已生成的异常输出；不添加stop字符串遮住截断；不调整temperature、repetition penalty、thinking或输出上限；不顺带压缩记忆和工具目录。

用户或工具真正引用同样字符串时，内容必须保留。含有这些字符串的回答不自动算失败；按当前任务与重复结构判断。

### 6.5 零模型测试

覆盖空assistant正文、自然正文、单/多tool calls、JSON/native历史、用户字面引用标签、工具正文含标签、当前/历史提问、读写后续接、namespace隔离。

机械验收：

1. 原graph/checkpoint哈希不变；
2. 无候选外的正文、参数、ID、顺序变化；
3. 工具容量按真实新请求重新计数；
4. 旧recipe输出与旧实现一致；
5. 多次render同一输入不会累加内容；
6. 原始模型输出不经过后处理变成“正确答案”。

### 6.6 RT-L：两级验证，分别报告

**L1：固定前缀诊断。**建议预选6个前缀：来自三条异常arc的首断点附近前缀，以及三个合法对照。两种标签条件各做两个事先登记的重复，共24次首响应调用。若前缀无法合法重建，减少范围并在冻结前说明，不编造。

该层不执行提案工具，只看第一步行为、重复标签/普通重复、输出完整性和动作提案。它不计作工具执行、持久化或完整arc成功。

**L2：完整预防验证。**在L1没有出现新的明确风险、并取得真实执行授权后，建议三条已知异常arc加一条合法多步变更对照，两个条件各从独立初态完整运行一次，共8条arc尝试。一个arc内部所有原生episode保持；这是已曝光回归，不是独立泛化。

原有模型生成的标签如果已在真实历史中，候选不擦掉它们。完整预防从新隔离初态运行；固定污染前缀只能证明污染条件下的行为，不能代替预防实验。

### 6.7 结果决策

- 若重复/截断减少、反向控制保留，但额外动作仍在：只接受标签/输出修复，R2保持未完成。
- 若两条件都无故障：证据不足，不能据本批宣布因果成立；不追加抽样直到得到有利结果。
- 若候选改变了当前/历史、引文或任务行为：定位该变更，保留legacy，不用追加提示救分。
- 若出现新危险动作：停止该轨迹的真实变更；不取消与其隔离的离线/只读工作。

候选晋级需机械合同全部通过、完整回归未出现新的严重副作用、目标故障有可复查改善。小样本门槛是工程决策，不是总体可靠性或统计优越性证明。

## 7. R2：额外动作、任务结束与恢复

### 7.1 必须分别处理三件事

| 类型 | 如何识别 | 能做的确定性处理 | 不能保证 |
|---|---|---|---|
| 同一请求传输重试 | 已有稳定operation identity/幂等键、同一执行意图 | 按已声明工具合同复用/核实结果 | 不识别新的多余提案 |
| 新call重复已完成效果 | 新call ID，但显式任务、目标、前态和已知效果可核对 | 在允许幂等/工作流声明的范围内限制重复变更 | 相同参数并不总是不合法 |
| 第一次额外操作 | 工具不同或目标不同，用户任务未授权该效果 | 可信应用权限可限制；开放语义仍须Host判断 | 不能由去重或scorer自动解决 |

来源报告支持第一项不是本次七次部署的主要原因。[S02][S04] 当前已有journal能力是否足够覆盖具体路径，在R0检查；不要未经核对就承诺具备exactly-once。

### 7.2 第一项修复是让已发生的结果可被正确消费

先核对已完成set_config/update_ticket的真实回执是否在下一请求、字段是否可解释、未完成操作是否仍被误表示为待办。已有operation audit和ToolMessage优先复用。

若确有表达缺口，可提出一个很小的“实际完成效果摘要”候选：只从真实回执确定性生成当前操作结果和未完成执行项，不声称整项用户意图已完成。这是新的呈现变量，必须与R1标签开关分开。

不新建全局任务规划器；不要求模型填一份`completed/receipt_refs`来认证自己；不重复存储完整世界状态。

### 7.3 执行保护只在明确合同范围内生效

当应用已提供可信的`operation_id`、一次性命令类型、允许的变更集合或已确认任务边界时，可在原执行器入口执行相应约束。它不能来自benchmark gold、答案、成功checker或临时关键词推断。

开放自然语言下，没有可靠任务授权映射时，记录`AUTHORIZATION_UNDETERMINED`或等价诊断；不能把模型自己写的“已授权”当成程序证明。

若无法安全判断新的变更是否有必要，可以在应用扩展轨道暂停进一步变更并如实返回未完成，而不是继续部署或假装任务成功。**安全停止是风险控制结果，不是业务任务通过。**

### 7.4 防止错误的全局去重

判定需考虑用户/任务/操作身份、目标、前态或版本，以及工具是否声明幂等。必须允许：

- 用户后来明确请求重新部署；
- 目标版本或状态已经变化；
- 合法工作流需要多次同名操作；
- 成功一步之后执行不同的必要下一步。

`deploy(latest)`中的`latest`可能随时间改变；不能仅比较字符串就认定效果等同。没有真实解析结果时，不制造确定性相等。

### 7.5 benchmark 两条轨道

**原生轨道：**保留原world/tools/checker与任务权限，修复呈现或Host行为；不得在运行时调用checker决定结束。

**保护扩展轨道：**所有比较方法得到相同保护接口，分别记录提案、实际执行、阻止、未完成和原生分数。不能把被程序取消的错误动作当作Host从未提出。

第一次额外部署、新call重复部署、合法再次部署三种用例都需要覆盖。只拦截重复七次而允许第一次越界，不能称额外动作问题已经解决。

### 7.6 partial/unknown恢复

先使用隔离本地业务世界，预先声明故障点，不对真实生产服务制造事故。

最小用例：

1. 主动作成功、附属动作失败；新进程仅完成剩余部分。
2. 请求发出后结果未知；先通过合法查询确认，再判断是否重试。
3. 工具失败但无副作用；允许正确再次尝试。
4. 任务已成功，后续独立新请求要求同参数操作；不得被永久去重。

每项检查实际world、准确对象、操作journal、回答、持久维护和重开后的行为。不能把“重开时找到checkpoint文件”当成恢复通过。

### 7.7 交付与回滚

交付行动分类表、执行合同、最小补丁、机械反例、沙箱轨迹及风险残余。若保护误拦合法操作，退回观测模式或关闭该保护候选，保留证据；不要扩大语义分类器掩盖误拦。

R1/R2未确认前，不将当前Agent用于真实有风险的变更服务。

## 8. R3：记忆范围与适用性修复

### 8.1 离线审计覆盖全部20道范围题

不只分析14个失败，必须包括6个通过例。按题/来源组建立：

| 字段 | 含义 |
|---|---|
| source_span | 原始主体、受众、范围、时间、条件、否定/不确定性所在片段 |
| source_access | 合法来源实际是否可取得；没有原制品则记缺失 |
| formed_record | 对应真实记录及原ID，不人工改写 |
| qualification_status | 限定保留/缺失/变宽/错误归属/未知 |
| delivered_record | 实际HTTP中交付的内容，不用检索日志替代 |
| current_request | 当前服务对象、目标及明确约束 |
| answer_behavior | 使用、过度使用、忽略、请求澄清或其他 |
| judge_basis | 原生Judge判定与rubric依据，保留歧义 |
| earliest_supported_breakpoint | 最早有证据的断点；不能确定时记UNKNOWN |

“全部持久记录交付”与“全部来源信息保留”分开填。[S02][S04]

### 8.2 修复路线F：形成时扩大了原意

仅当审计确实定位到主体/范围/时间/确定性扩展时进入。

最小候选保持现有文本record和CRUD，调整形成合同，使记录保留必要限定，不比来源表达更强。来源缺失时不补造scope；暂定推断仍可记录，但明确不是用户直接陈述。

示意：

```text
来源：这次给客户的简报尽量短。
错误概括：用户喜欢所有说明都简短。
允许表达：本次客户简报采用简短表达；未据此推断用户的一般偏好。
```

此示例不是benchmark原题。新writer只见相同合法archive与已有记录，不见当前待测问题、gold或未来任务。

先不引入复杂schema或原子事实数据库。若增加来源引用，必须是真实片段身份；操作provenance与semantic support分开。不能自动把当前轮所有来源挂到所有结论上充当证据。

**变量限制：**只改形成合同或一个记录粒度规则；不同时改reader、展示位置、检索与预算。两个因素确有必要时分两步实验。

### 8.3 修复路线P：限定存在，但reader仍用错

固定bank、准确正文、record IDs、合法内容、reader模型、问题、scorer与预算。只冻结一个呈现变量，例如记录容器或同一材料的相对位置，不同时更换标签、顺序、内容与作用域过滤。

当前MemSyco原生reader与formatter由固定上游函数加载。[S08][S09] 改其系统提示或载体属于`presentation_extension`，不能悄悄回填为原主表方法。

若候选需要原始限定片段，则另列`evidence_augmentation`，让对照获得同等访问权和可比预算；这不是同bank纯呈现消融。人工理想记忆用于oracle上界时，明确排除出可部署主方法。

### 8.4 不确定时不要同时实现F和P

若来源审计无法区分形成和消费，先进行单一、可观察的固定bank呈现诊断；它若无效，保持原因未定。不要同时重写writer和reader后只报告总分提升。

同族Judge的影响通过冻结输出后的盲人工复核单列，尤其检查“题目未给选项但回答请求选项”等边界。不得反复换Judge、重评同一题直到得到希望的结果。

### 8.5 RT-S：建议规模与反向控制

开发诊断建议：20道范围题全部保留，再按事前规则选3道当前偏好与3道正确个性化题，共26题；候选与前任各一次，共52个查询输出。来源组相关性单列。

- 路线P复用相同冻结bank，不重新形成。
- 路线F两臂均从相同原history重新形成，计入全部形成费用；旧结果只作历史参照。
- 主体/群体要求、临时/长期、当前/历史三类反向控制都必须存在。
- 若资源不足，先缩小**运行前声明的完整实例数**；不根据输出选择子集。

新增输出按同一原生Judge配置单次评分，另留盲审结果。记录26题是开发集合，不称未见。

### 8.6 晋级规则

源限定保真机械/人工审计通过；范围误用有逐题可解释改善；当前偏好和正确个性化没有通过普遍少用记忆而退化；记录增长和总费用可接受。

这些小样本不支持“没有退化”的总体统计证明。若改善只发生在旧开发题，保持开发候选；下一步必须独立确认，不能再添加更多例外规则。

## 9. R4：写入责任与对照合同澄清

### 9.1 先描述比较对象，不先增加writer

现有源码在MemSyco采用无问题的归档形成；MERIT ordinary由Host自主CRUD并可访问完整合法历史；外部后端采用回合边界维护。[S08][S09]

它们可做系统比较，但不能用同一表直接推出“哪个记忆更新算法更好”。ordinary0 CRUD说明当前策略没有维护专门记录，不等于存储坏了，也不自动证明需要增加一个维护模型。

### 9.2 分开两种实验合同

| 合同 | 共同条件 | 能回答什么 |
|---|---|---|
| `host_direct` | 相同自然用户任务、world、权限、合法历史；Host自主调用CRUD | 自主形成、动作选择与完整可用性 |
| `backend_boundary` | 相同已取得轨迹、固定摄入边界、共同reader/Host与预算 | 后端表示、更新和材料使用的差异 |

自动边界形成不是“Agent识别了保存意图”。凡增加边界维护均使用新recipe身份，并完整计费，不从旧ordinary列直接改名。

### 9.3 条件性最小实现

只有当前问题确实涉及写入责任时，复用现有`form()`、相同MCP/Store/strict CRUD，实验一个普通边界维护版本。它与Host主动写入不要在同一事项上同时独立维护。

写入输入只包含已取得新观察及相关旧记录；不读gold/未来。允许NO_CHANGE，负例包含引文、临时、只读、未采纳建议。

若由应用可信入口明确要求保存，可测试同步命令入口；若仅由Host先识别才触发，必须承认“Host根本漏识别”时该机制不会触发。不能用离线标签补这个逻辑缺口。

### 9.4 完成标准

形成责任、材料权限、缓存和费用可解释；没有重复writer；能分开回答后端能力与自主Agent能力。该工作包不需要把CRUD次数做大，也不预设额外维护调用一定划算。

## 10. R5：对象发现、时间与输出合同

### 10.1 对象发现：不要让模型复制未见过的key

本次`coffee`失败首先检查原生工具是否支持列举、查询或通过错误回执给出合法key。只有实际可取得的信息才能用于目标选择。[S04]

最小流程：

```text
自然语言事项
→ 原工具合法查询/目录/已有真实回执
→ 选择准确既有对象
→ 原生更新
→ 核查实际影响对象。
```

若原工具缺少发现能力，保留原benchmark结果并报告限制。新的typed-ref/list工具是接口扩展，要共同开放给各方法；不能从隐藏DB/gold生成正确ref。

反例：两个同名对象、不同owner、不存在对象、已删除/已换版本引用、显式创建新事项。不要通过把所有未知key都拒绝而破坏合法CREATE。

### 10.2 时间表达：来源时间不等于处理时间

保留：原始时间表达、真实可得的事件/观察时间、明确时区、实际处理时间；无法确定绝对日期时保留不确定性。[S04]

自动落定相对时间只有在来源提供足够锚点且规则符合任务合同时才进行。历史记录中的Friday不能仅因为runtime今天是某日就被任意落定。

Mem0原pin与原生提示保持原样。任何新增时间处理均命名为MiLAi适配或Mem0-temporal-adapted，不改原baseline。缓存identity包含实际使用的时间上下文，不能复用另一日期生成的材料却假称同一条件。

### 10.3 格式与政策冲突

千位分隔、大小写等原分保留。用户明确要求原样发送时，验证精确文本复用；用户没有明确的隐藏格式要求时，补诊断，不给writer增加题目专用规则。

政策与checker冲突时，保留原生未达目标与实际政策依据。不得为通过分数移除政策、强行退款、改权限或事后修改checker。

### 10.4 交付

对象/时间/格式问题各有独立首断点和对应合同。除非某一项已触发后续任务失败且具备合法改进路径，否则不展开大规模工具重设计。

## 11. R6：SimpleMem 预算协同

### 11.1 原样基线保持

原SimpleMem使用固定`db80b6...` core text、共同最终reader/Host，planning/reflection开启、最多2轮，所有公开消息共享12次生成。[S05][S10]

pilot中7次原生检索生成＋5次Host生成耗尽容量；实际每消息自动检索一次，续接复用材料。该中断不是已确认的缓存/计账bug。其MemSyco回答无Judge分数，不能写成“语义试跑通过”。

### 11.2 新配置不能直接改旧POLICY常量

`simplemem_native.py::validate_simplemem()`对原POLICY做精确校验。[S10] 所以预算适配应是单独recipe/显式验证分支，而不是修改常量让历史配置静默改变。

第一候选建议仅调整一个已确认可用的公开参数，例如关闭reflection，保持planning、top-k、内部temperature、writer、reader、总12次限制与工具不变。先核对上游构造器支持方式；未核对前不写成可直接执行命令。

不同时扩大总额度、降低top-k、修改温度和替换答案生成器。原样条件继续保留为`simplemem_text_native_config`或等价身份，适配版明确带后缀。

### 11.3 任务优先预算是后续独立变量

将“希望给Host留出几次调用”作为调度目标，不是完成保证。若要设置阶段子预算，必须在总额度内预先声明，拒绝的阶段返回真实未完成。

不能截断SDK内部结果后假装检索正常完成；不能失败时悄悄改成其他retriever；不能自动补最终答案。必要的完整业务查询仍可能超过保留额度，应如实记录。

调整总额度需要对相关比较方法共同建立新预算表；旧12次结果不修改。只有资源问题得到明确解释后，才考虑这种预算曲线，不将其作为临时救分。

### 11.4 RT-B：最小原生与适配比较

建议从原已曝光`arc5-000`与另一事先选择的完整arc开始，两配置各一次，共4条arc尝试，使用新隔离world/Store，不续接旧中断。

先记录：检索各阶段调用、Host行动调用、写入维护调用、实际任务成功、政策冲突、未完成、材料覆盖及总tokens。需要MemSyco效果时另取完整题并沿原scorer评分，不把非空回答当质量通过。

若只是检索减少但任务质量下降，不能采纳；若任务完成改善且费用可接受，可以进入受限开发比较。原计划138单元只有在配置身份、预算与质量信号明确且重新授权后才启动。

### 11.5 成本验收

每个HTTP对应唯一ledger计费；阶段标签互斥，不把native内部调用再作为额外统计重复加总。缓存命中、query重用、原生有限重试各自可观察；未测物理I/O、GPU小时和美元费用仍为unknown。

## 12. R7：确认实验与 State–Attention 后续

### 12.1 不再马上重跑五方法全矩阵

标签修复只与其前任比较；范围修复先与同bank/同writer前任比较；预算适配只与原样配置比较。强简单基线保留为参照，但不必为每一处小修改重新形成60份全部历史。

需要新的确认表时，建议最小三臂：**冻结候选、直接前任、StrongRawRAG**。若候选就是该简单方法，合并重复臂，不强制创建新机制。

### 12.2 独立确认建议

在不读取结果的前提下，从未参与修复选择的来源组冻结：

- MemSyco：20个scope＋10个valid selection＋10个personalized use，共40题；如来源组不足，调整后再冻结，不假称独立。
- MERIT：三域各easy/hard一条完整arc，共6条、通常30个episode；使用新的固定实例但明确仍是同一生成器模板家族。

这是建议的开发确认规模，不是统计充分性的保证。正式论文样本量需要基于目标效应、来源组数、方差和成本另行规划。

### 12.3 质量与风险门槛

机械合同和信息隔离必须通过。确认集中，未请求危险变更、跨owner效果、虚构执行成功等严重问题单列，不允许被总正确率稀释。

普通回答失分仍然报告，不要求所有原生benchmark达到100%才承认功能可用。若关键故障复现，退回相应修复包，保留其他已成立工程结果；不更换整个方法，不把一次失败解释成自动停止全部研究。

小样本零事故只支持“该确认集中未观察到”，不等于安全保证。确认集曝光后转为开发集，不能继续用于最终独立结论。

### 12.4 第二模型是定位工具，不是统一后置关卡

如果相同材料在同一模型出现明显输出/停止不稳定，可以申请一个不同模型家族的小型诊断。使用相同合法工具、任务和方法，兼容性变化另记身份。

不要求当前模型全部满分才允许排除模型特有问题；也不以换强模型后的成功替代对原模型失败的解释。没有服务/费用授权时保持NOT_RUN。

### 12.5 State–Attention 的研究空间保留

当前方法最值得继续验证的是“认识如何适用于当前任务”，不只是“找更多材料”。State可维护局部目标、约束、工作事实的来源/版本和未决问题，Attention据此组织材料。

重新做A/U比较的入口可以是：真实取材遗漏、范围冲突、当前/历史竞争、或总成本压力；不要求物理上下文一定超限。但必须有一个具体可测缺口，不能为了模块出现而强制调用selector。

读取A在同bank、同合法候选、同reader/Host下比较普通query、同State信息的query增强和独立选择。更新U固定前态、新事件、CREATE权限和维护合同；空U仍允许新事项形成。

若简单范围表达或普通query已足够，关闭额外selector是当前设计的合理实现，不等于放弃长期研究目标。接口/预算修复本身不能被包装成State–Attention算法收益。

## 13. 统一实验、评价与成本合同

### 13.1 先冻结，再调用

每批冻结源码、配置、真实模板/模型小资产、工具目录、数据ID/来源组、合法历史、作用域、初始world、预算、顺序、重复次数、scorer、主要结果和停止边界。

原始数据/已曝光回归/新确认分别登记。相同数据换seed或字段值不构成新任务家族。temperature=0不等于已证明完全可重复；重复必须事前安排，保留全部结果，不挑成功重跑。

### 13.2 固定前缀与完整轨迹不得混用

| 模式 | 输入与用途 | 不可声称 |
|---|---|---|
| 离线重放 | 真实冻结请求或合成合同，零HTTP | 模型语义有效 |
| 首响应诊断 | 合法相同前缀，提案不执行 | 业务/持久化成功 |
| 前态克隆诊断 | 同一实际已取得world/bank的隔离副本 | 自主形成了该前态 |
| 全链回归 | 新隔离初态，完整arc执行 | 未见泛化 |
| 独立确认 | 未参与修复选择的来源组/任务实例 | 任意分布或产品保证 |

跨方法在线轨迹从同一合法初态出发，之后各自获得真实动作结果；不能把候选执行后才得到的信息复制给未执行该动作的对照。

### 13.3 保留原生评分与补充诊断

继续分别报告MemSyco三个任务；MERIT episode、dependent、arc、pre_satisfied和未知；不要合成未定义总分。

附加指标包括：

- 标签异常复述、一般重复、截断及完整回答；
- 第一项未请求动作、累计额外动作、阻止次数、合法动作误拦；
- 原始限定保留、持久误泛化、当前范围误用、正确个性化保持；
- 实际CREATE/UPDATE/DELETE/NO_CHANGE、准确目标、记录增长；
- 工具提案、执行、world、维护、恢复的分层结果；
- 资源耗尽阶段、材料覆盖、全部调用与成本。

程序能证明引用存在/写入发生，不自动证明来源支持/用户意图完成。七层通过率是条件结果，不按独立概率相乘。

### 13.4 未知与中断

保留原计划分母、已评分失败、HOST_INCOMPLETE、BLOCKED_EVIDENCE、BLOCKED_ENVIRONMENT、NOT_RUN、NOT_TRIGGERED。安全拦截后的未完成不当成完成。

原五方法表的未知不被新运行填补；新确认可以给成功率下上界。沿用既有统计时，配对端点不完整则不输出普通完整配对CI，不删除问题凑齐样本。[S03]

没有显著差异不表示等效；声称不劣需要预设界限与足够精度。小型修复诊断优先报告逐对变化和严重错误，不为漂亮p值选择分析方式。

### 13.5 运行中的故障处理

| 情况 | 处理 |
|---|---|
| 正常语义答错 | 记录，继续其余独立安全冻结任务 |
| 合同输入缺失/gold泄漏/错误owner | 停止受影响批次，作废污染结果或标明不可比，不覆盖旧记录 |
| 不受控真实副作用 | 停止当前可变更链，保全实际world和journal；隔离后处理 |
| 容量耗尽 | 保留已发生效果及未完成；不临时加额度 |
| 一次HTTP传输失败 | 按预冻结重试规则；未知副作用先核查；实际请求均计费 |
| 新候选门槛不满足 | 保留局部结论，停止该变体扩大；不自动取消其他已授权独立诊断 |

### 13.6 成本基线与互斥计账

暂停时连续账本：[S01][S03]

```text
generation requests = 5,992
generation tokens   = 10,921,341
embedding tokens    = 416,802
ledger SHA256       = 2ef3e45b0150cb6c5cc2c47dc0f0493497157e84dae0a9e991d71b1181113e3c
```

统一Goal已增加2,691请求、6,716,138 generation tokens、393,232 embedding tokens。下一次本机执行只能在实际最新账本上追加；别处独立复现使用明确新账本，不伪称接续。

每次实际生成归属且只归属一个主费用阶段：formation、maintenance、retrieval planning/reflection、Host task、recovery、Judge。原生子调用和父阶段不能重复收费。内部reasoning已包含在completion时不再次累加；服务未单列则标unknown。

缓存冷建/热读、物理与逻辑I/O、HTTP与进程wall、MCP/backend inclusive时间分别报告；重叠时延不相加成独立时间。用户开发代理用量不混入runtime实验费用。

### 13.7 首批成本控制

先做零模型R0/R1/R2/R3审计；真实调用按最小诊断逐批开启，不立刻重跑690单元或138单元。

预算估算使用实际所选前缀/arc的tokens与调用分布，不能用全表均值替某一高成本任务。计算式可沿用：

```text
计划调用 = 实例数 × 方法数 × 预定重复 × 各实例冻结的调用上限
计划tokens = 各请求实际计数的输入估计 + 输出预留 + writer/检索/Judge费用
```

这是计划上界/估算，不是未来实际费用承诺。精确绝对费用需在执行合同填写；本文不擅自更改已有12次公开消息上限。

## 15. 验收与首批执行清单

### 15.1 四层完成不能合并

| 层 | 完成含义 | 不能推出 |
|---|---|---|
| 机械合同 | 固定范围的输入、身份、执行、隔离、计账正确 | 模型语义可靠 |
| 局部修复 | 目标故障在预设诊断中改善，反例未被破坏 | 跨任务稳定、方法新颖 |
| 独立确认 | 未用于选择候选的来源组中结果支持改进 | 任意场景安全、产品成熟 |
| 研究贡献 | 强对照/消融支持一个清楚的机制结论 | 自动Product GO |

### 15.2 不以改名替代修复

每个问题按如下闭环处理：

```text
真实失败
→ 可核验首断点
→ 至少两个竞争解释
→ 一个最小改动
→ 正例与反例
→ 真实任务和总成本
→ 采纳 / 保留未定 / 回滚该变体。
```

没有正收益时，停止当前变体扩表，不自动停止整个Agent Memory研究。不得为了延续原假设立即增加下一层reviewer/selector；也不得因一个接口问题失败就切换全部研究主题。

### 15.3 首批建议执行范围

**批次A：仅离线，最先授权。**

- [ ] 核对用户恢复范围、代码/数据/私有制品和连续账本。
- [ ] 建立R0差异清单及现有失败分类。
- [ ] 实现R1唯一标签开关，完成legacy等价和候选预期差分。
- [ ] R2核对首次额外部署与已完成结果的实际输入链，不实施自动保护。
- [ ] R3完成全部20道范围题来源—形成—交付—回答审计。
- [ ] 产出下一批真正需要区分的问题、调用估算与反向控制。

**批次B：标签修复的受限真实验证。**

- [ ] 独立冻结L1前缀、重复、顺序、24次首响应诊断范围。
- [ ] 明确L2完整arc是否另需授权及其风险隔离。
- [ ] 旧失败原样保留，不清洗污染历史，不自动调用原生产业务。
- [ ] 本批不加入writer、SimpleMem预算或动作保护变量。

**批次C：按离线结果选择一个语义/执行候选。**

范围形成、固定bank呈现、动作继续/停止或合法对象发现四者中，优先选择证据最清楚的一项。不要同时实施后再解释总分。

**批次D：资源与第二外部系统。**

R6原样/适配配置身份明确后再运行小型对照；不直接启动138单元。预算适配不作为修复MiLAi标签问题的前置条件。

**批次E：独立确认与U6补充报告。**

确认已采用修复的组合身份；维持强原文/摘要对照；只在具体缺口下继续A/U和第二模型，不扩张无关平台功能。

### 15.4 本修复阶段最小结案产物

需要一份完整报告说明：哪些已实现、哪些只分析、哪些运行、哪些阻断；每类首断点发生在哪层；每个候选实际改善/退化及其成本；原分数和未知如何保留；哪些研究主张仍不成立。

用户暂停时可以合法交接，但必须写“暂停交接”，不能把未完成工作包登记为通过。按冻结条件关闭一个无效变体也不等于长期研究目标达成。

### 15.5 最终开发原则

> **先修会放大错误和产生额外副作用的运行边界，再修记忆形成与适用性；基于同一批真实证据做小步改动，用反向控制确认没有换一种方式犯错。保留原架构和State–Attention方向，但任何新增机制都必须有具体需要和独立收益。**
