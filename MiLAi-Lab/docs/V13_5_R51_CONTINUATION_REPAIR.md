## 实现与边界

可选 `request_mode=current_request_native_v7` 在当前输入中单独声明是否允许解析此前未完成的明确记忆请求。只有允许续办时，才使用现有有界材料解析；模型选择实际交付的历史 user 片段，组合层通过公开 `MemoryService.source_fragment` 重新检查 owner、bank、原文、区间和可见性，缓存重开也复查。来源身份验证不证明语义理解或完整授权正确。

当前纯查询、明确不保存和仅继续业务的限制优先。若业务操作已具体声明，解析不能扩张它；历史来源也不授予遗忘权限。已有记录可以保持不变或实际 confirm_existing_memory；一个成功回执不能说明另一个尚未保存的事项已完成。实际业务结果只能由实时查询／工具结果支持，原请求仅标识要做的记忆工作。原 unknown journal 保持 unknown，不能用新查询伪造原回执，也不能重放已完成业务。

没有新增任务队列、服务或持久化模块；旧 v1–v6 和默认入口保留。仅 Lab 选择该新 profile 时改变续办的工具权限判定；Product Schema/API/权限/Canonical 不变。原普通系统提示、模型、计账、8192 材料／8192 输出／65536 容量、24 次生成、3 次追加读取及一次格式重提额度不变。
