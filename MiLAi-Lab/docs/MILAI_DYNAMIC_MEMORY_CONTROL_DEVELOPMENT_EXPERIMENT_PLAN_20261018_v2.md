## 0. 开工摘要：先做一个能改变执行路径的系统

### 0.1 本轮主要交付

**一套薄的动态记忆循环、一组共用操作、一个Laya决策适配，以及六条连续开发历史的真实Host运行。**

同一问题在不同状态下至少能够出现以下不同路径：

```text
已有适用解释：打开已有视图 → 交回Reader
缺少某份来源：检索／补读 → 根据新材料再次决定 → 交回Reader
旧解释受新事件影响：取得变化证据 → 刷新局部视图 → 交回Reader
当前仍不足：继续取证，或交回Host说明当前信息边界
```

这些是应当能够发生的路径，不是按题号硬编码的四个模板。最终以实际动作、交付材料和任务结果判断，不以路径看起来不同证明动态控制有效。

### 0.2 相对v1的调整

| v1中的组织方式 | v2的决定 |
|---|---|
| 先接动态字段和固定选材，再发展视图，最后考虑统一控制 | **先开发统一的状态—操作—反馈循环**，读取和视图作为可执行能力接入 |
| 固定四段作为近期主要运行形式 | 固定四段仍是必要基线；动态策略实际操作数由状态决定 |
| 先用简单调度，等各组件成熟再扩大Jev职责 | 简单调度与Jev使用同一操作库；Jev首轮即有真实运行入口，但零样本仅作诊断 |
| 训练主要预测下一段 | 增加“下一项操作＋实际目标／范围”的监督，保留段落选择作为子任务 |
| 主要评价选材、缓存和维护各自的成绩 | 首先评价任务全过程，再用组件干预解释收益来自哪里 |
| W1—W6近似顺序推进 | 改为D1—D6功能切片；训练、视图优化和写端扩展不阻塞最初循环 |

**保留的原则：开发优先、强简单基线、正常Host可用、旧来源和提交边界复用、结果允许否定假设。**这些原则来自用户已明确的工作方式，不应被扩展成新的审核工程。[A1][A2]

### 0.3 首批边界

第一阶段控制读取、视图使用和视图刷新；既有来源捕获与明确保存／更正／遗忘请求照常由原能力处理。第二阶段才学习可选语义维护的时机与范围。动态控制不等于立即让同一个checkpoint接管所有记忆行为。

不先新增审核Agent、第二记忆库、第二账本、任务总线或通用自愈平台。无需先让旧实验全绿；必要回归随修改完成。真实错误进入原执行反馈，既不吞掉，也不自动改名为成功。

## 2. 研究问题：动态控制何时真的有价值

### 2.1 主问题

**在持续到达的新事件与任务中，能否根据当前可见状态选择必要的记忆操作，减少无效读取和重复解释，同时保持实际状态与任务结果的正确性？**

动态性不是增加分支数，也不是每次都调用控制器；它是让不同状态得到不同且有效的处理。简单任务应允许短路径，困难任务应允许投入更多计算。

| 假设 | 拟议机制 | 主要证据 | 可能的负面结论 |
|---|---|---|---|
| H1：反馈闭环优于一次路由 | 每次实质性操作后更新观察，再选择下一步 | 同能力与预算下，实际任务成功或成本改善 | 固定／规则策略已足够，复杂控制没有必要 |
| H2：Jev适合作轻量操作策略 | 有限动作读出替代生成式控制调用 | 与生成式动态控制质量可比、总控制成本更低 | 输入理解成本过高或决策能力不足 |
| H3：语义状态区别有增量 | 使用已读内容、来源时间、作用域和实际操作反馈 | 必要前提变化时正确换操作，无关变化时避免重算 | 收益主要来自静态排序或机械版本信息 |
| H4：复用与局部刷新有长期价值 | 复用有效解释，只为相关变化重新解释 | 连续历史中任务保持正确，累计成本出现优势 | 漏掉新例外、刷新过多或成本未回本 |
| H5：维护时机可以学习 | 在来源已保留前提下，选择立即或按需综合 | 后续使用改善，必要更新不遗漏 | 学成不维护或过度维护，损害后续任务 |

H1—H3是第一轮研究重点。H4以现有视图为起点；H5在读取闭环可用后开展。它们不是要求一篇论文同时证明的五项贡献。

### 2.2 创新边界

Jev-Mem已经提出System-One控制记忆构建与动态检索；AgeMem已经把记忆操作纳入Agent策略。**“动态Agent Memory＋Jev”本身不能单独作为新颖性。**[P1][P2]

本计划拟争取的实质差异是：

**在真实形成的不完美记忆上，用执行反馈驱动复用、补证和局部重计算；既测下一步决策，也测连续任务后果和累计计算。**

新点应最终落在状态表示、动作价值学习、变化适应或计算复用中的一个明确机制。统一接口、字段增加、普通CE和多槽缓存都可以有工程价值，但不自动构成算法创新。

## 3. 目标架构：统一循环，稳定执行器

```text
当前请求／新来源到达
        │
        ├─ 原来源捕获、可见性和必要操作边界
        │
        ▼
形成当前可见决策状态 z_t
        │
        ▼
同一操作目录 A_t：取证／用视图／刷新／交接……
        │
        ▼
策略 π：规则、Jev或生成式对照，三者可替换
        │
        ▼
原检索／证据交付／查询视图／Writer等执行器
        │
        ▼
真实操作结果与实际新材料 → 更新 z_(t+1)
        │
        ├─ 继续／改走另一操作
        └─ 交回原Reader或Host
```

### 3.1 职责划分

| 部分 | 负责 | 不负责 |
|---|---|---|
| 动态循环 | 观察、调用策略、执行动作、接收结果和终止交接 | 推断业务事实、另建事务系统 |
| Jev策略 | 从当时提供的有限动作中选择操作和目标 | 生成新事实、伪造来源、授予权限 |
| 检索和证据工具 | 定位、打开、扩展实际材料 | 用离线答案构造“最佳候选” |
| 视图／Writer | 构建或修订来源绑定解释 | 把执行回执当语义正确证明 |
| MemoryService／原运行时 | 原始捕获、版本、可见性、授权与提交 | 通过新增语义规则代替模型学习 |
| Reader／Host | 依据实际交付完成回答或原有授权任务 | 把控制器的“充分”判断当作额外证据 |

### 3.2 一个操作完成后，才重新决策

控制发生在信息或任务状态改变的边界：新请求到达、检索返回、材料打开、视图读取／刷新返回、维护实际提交或明确失败。序列化、去重、计量、同一来源的ID映射等内部步骤不额外调用Jev。

初版只做串行循环。批量打开少量材料可以作为一个明确宏动作，但不默默让某个方法独享批量能力。若后续加入并行操作，要单独评估信息依赖与真实并行成本。

### 3.3 统一循环不是强制共享一个checkpoint

读取操作、写入时机和细粒度Impact可以使用不同的明确训练任务；它们共享操作接口和来源语义即可。优先用一个Laya操作策略完成读取／视图切片，不先同时训练全部生命周期。

保留现有open-only选材器为可选子执行器。操作策略选择“获取一个证据批次”时，可调用该子执行器；其全部成本必须记入该操作，其他方法也获得相同能力机会。不能把两次决策装作一次前向。

## 4. 最小决策状态：观察充分，不追求全知

概念上写为：

\[
a_t\sim\pi_\theta(a\mid z_t,\mathcal A_t),\qquad
z_{t+1}=\operatorname{UpdateObservation}(z_t,a_t,o_{t+1}).
\]

`z_t`只是可见观察的投影，不是完整真实世界或一张永远正确的记忆图。`o_(t+1)`来自实际执行结果，不来自策略对结果的预测。

### 4.1 建议字段

| 字段组 | 最小内容 | 来源与解释 |
|---|---|---|
| `task` | 原始请求、查询时点、用户明确的时间／主体范围、当前模式 | 保留最终问题，不用内部目标替换；解释字段注明解释性质 |
| `visible_evidence` | 实际已打开材料的ID／版本／范围／正文、角色与来源时间 | 只含真实交付；目录标题不等于正文已读 |
| `pending_candidates` | 可访问候选引用和当轮决定实际展示的字段 | 若控制器看了全文，该输入计算已发生，必须计量 |
| `views` | 候选视图作用域、版本、使用依据、未处理事件引用、结构可读性 | “绑定未变”不是“语义已验证正确” |
| `new_events` | 已到达且相关候选发现可见的来源引用与必要正文 | 不含未来事件；不只局限于旧支持图的边 |
| `last_result` | 上次动作、实际结果状态、新材料／实际提交版本、错误或未确定结果 | Writer提议不等于实际提交；超时不等于没发生 |
| `budget` | 剩余操作／输入预算、已发生计算、预留Reader能力 | 成本估计标为估计，不能把未知费用写零 |

不每轮调用一个大模型重写“全局状态总结”。程序提供能确定的版本、到达位置、已读范围和回执；语义内容只展开当前判断必要的部分。初版状态暂时不压缩，先获得可靠行为，再优化压缩和复用。

### 4.2 明确保留的状态区别

- 当前事实、未来生效规则、后来更正的历史事实、当时实际存储内容，是不同任务。
- 来源报告时间、系统捕获时间和生效时间不同；缺失时间保持未知，不由保存时钟填充。
- 用户报告、第三方转述、工具观察、模型推断保留身份；角色本身不自动证明真实性。
- “候选池没有找到”“已读材料不足”“当前检索已耗尽”“全部可见历史确实没有”不能混成同一个布尔值。
- “当前视图没有已知未处理事件”只能描述已检查范围，不能推导没有尚未发现的新例外。

这些区别沿用项目既有语义边界，不需要再造一套事实本体。[A2]

### 4.3 控制器可见与Reader可见分开记录

操作控制器若查看候选全文，已经做了相应理解计算。Reader最终只看到部分材料，不代表整个流程只处理了该部分。原回执里分别记录控制输入与实际Reader交付即可，不增加另一套访问账本。

不得把控制器的中间推断无标识地注入Reader当新证据。需要传递任务解释时，保留解释身份及所依附的实际来源。

## 5. 操作合同：先少而清楚，再依据失败扩展

### 5.1 第一阶段：读取与视图操作

| 动作族 | 一个具体动作包含什么 | 执行后观察 | 不是何种声明 |
|---|---|---|---|
| `SEARCH` | 当前问题／已观察线索、既有检索路由、有限返回规模 | 实际候选与已搜索范围 | 检索无命中不是事实不存在 |
| `READ` | 已存在的来源／历史／上下文范围引用，或明确证据批次 | 实际正文、版本、角色、范围 | 目录命中不算完成读取 |
| `USE_VIEW` | 现有可打开视图引用 | 实际解释及来源绑定、当前可见性结果 | 选择复用不证明解释正确 |
| `REFRESH_VIEW` | 已知作用域／视图引用、本轮实际新来源与必要旧支持 | 解释生成结果、实际保存版本及未解决项 | 调用成功不等于语义修复成功 |
| `HANDOFF` | 交给原Reader／Host，附当前材料与有界信息状态 | 正常回答、说明不足或Host后续处理 | 不是控制器自己作最终事实判断 |

`SEARCH`复用已有检索，不由Jev凭空生成任意查询文本。首版候选查询来自原请求及实际已观察内容；若需要学习查询生成，作为独立生成能力计费，并在各比较方法中同等开放。

`READ`可具体指向历史版本或扩展前后上下文，无需另增十个动作类型。动作粒度以一次可观察、可计费的实际执行为单位。

### 5.2 第二阶段：维护时机与范围

| 动作族 | 目的 | 约束 |
|---|---|---|
| `MAINTAIN` | 让原Writer处理已到达的事实／更正和相关范围 | 新含义由Writer生成；原来源绑定和提交继续执行 |
| `DEFER_INTERPRETATION` | 来源已保留，但可选综合暂不执行 | 明确待处理范围；未来实际事件或查询时再处理，不承诺后台任务 |
| `CLOSE_MAINTENANCE` | 返回本次已完成与未完成事项 | 依据实际回执，不把“决定结束”当请求已满足 |

**明确保存、更正或遗忘请求不能靠`DEFER_INTERPRETATION`悄悄跳过。**第一阶段继续使用原已支持路径满足这些请求；第二阶段允许改变处理方式和范围，但遗漏明确义务计为失败。来源捕获与昂贵语义整理不是同一件事。

遗忘操作的权限和可见性处理不交给新的学习型策略自行改写。按需视图不得重新暴露原机制已撤销的内容。

### 5.3 一次选择一个完整的有限动作

首版将具体动作序列化为有限候选，例如：

```text
a0: READ 当前候选c3的原始上下文
a1: SEARCH 当前问题的实际历史来源，返回下一批候选
a2: USE_VIEW 已有项目A规则视图v7
a3: REFRESH_VIEW v7，使用本轮已到达事件e12及实际旧支持
a4: HANDOFF，按当前材料进入Reader
```

这些动作由当时存在的工具、引用、范围和预算构造，不使用离线正确目标生成目录。Jev一次选择动作ID；程序执行其已绑定参数，不让模型生成陌生record ID或任意SQL。

动作目录只按能力、权限、引用可用性和实际预算排除不可能执行项；**不在目录生成器中提前编码“此视图语义足够，所以其他动作不提供”**。后者会把要学习的问题偷偷做完。

动作族、候选目标和处理规模可以在以后分层选择，但首轮不先引入三层路由模型。目录过大时用各臂共用的既有候选形成缩小范围，并明确报告候选机会；不枚举全部证据子集。

### 5.4 三种结束必须分开

| 结束含义 | 处理方式 |
|---|---|
| 结束当前取证 | `HANDOFF`进入Reader；控制器可给有界充分性估计，但Reader按真实材料判断 |
| 结束当前维护 | `CLOSE_MAINTENANCE`返回实际保存／修改结果与剩余事项 |
| 物理预算耗尽 | 原循环输出`budget_exhausted`，按已预留Reader／Host能力交接；不标为语义充分或全部来源耗尽 |

“交回Reader”可以成为待训练动作，但现有旧STOP权重不得不经新任务训练就当作该动作的可靠判断器。handoff过早导致本可完成的任务丢失，应记为控制策略错误，即使Reader对不足子集的拒答本身正确。

## 6. 循环如何运行：反馈改变路径，而非预先写完流程

### 6.1 概念伪代码

以下仅说明拟议职责，不是现有函数签名或可直接运行的CLI：

```python
state = observe_current_request_and_memory(request, existing_runtime)

for step in range(config.max_control_steps):
    actions = build_available_actions(state, existing_tools, remaining_budget)
    if not actions:
        return handoff_actual_state(state, reason="no_available_operation")

    selected = policy.choose(project_control_state(state), actions)
    if selected.kind == "HANDOFF":
        return existing_reader_or_host(state, selected.handoff_context)

    result = execute_with_existing_boundary(selected)
    state = incorporate_actual_result(state, selected, result)

    if result.requires_existing_unknown_resolution:
        return existing_unknown_result_path(state)

return handoff_actual_state(state, reason="budget_exhausted")
```

正常结束动作与预算检查属于同一薄循环，不加独立审核层。动作错误用原错误路径返回；确切失败之后仍有其他正常操作时，策略可以改走实际可用路径。未确定的副作用不能被当作“失败、可以重新执行”，继续使用原未知结果处理。

### 6.2 防止把动态循环变成重复计算

同一版本同一范围已经打开的材料，不作为重复打开的普通候选；扩大上下文或读取其他历史版本仍是不同操作。这是材料集合语义，不是内容指纹机制。

同一视图无新输入的重复刷新没有新的执行对象时，由操作目录不重复提供；出现新来源或此前未读的支持时可再次刷新。需要通过重复采样估计生成方差时，在独立实验协议中明确，不把它藏在正式策略自动重试里。

初版建议最多8次控制决策，最终Reader所需额度在原预算中预留。8是开发起点，不是最优参数。未用完的额度不强制消费；预算用尽时也不能编造充分性。

### 6.3 不允许隐性生成调用

候选构造、作用域识别或状态摘要若实际调用模型，均属于方法计算。首个切片优先使用原问题、已有任务字段、实际引用与已读正文，不为Jev每次选择再增加一个大模型“提前分析”。

`USE_VIEW`必须走实际打开路径；`REFRESH_VIEW`才允许触发解释生成。初版即使仍使用原单槽，也要把这两个操作分开。若旧函数把二者合并，可在原文件内拆出共用函数，不在外层复制第二份缓存。[R4]

### 6.4 事件输入与读取输入

**读取请求**进入读取／视图循环。**新来源输入**先沿原授权路径捕获，再决定可选解释是否现在执行；第一阶段这部分仍用原维护方式。第二阶段将相同循环复用于维护模式，仅提供该模式实际存在的动作，不让读取问题中的假设被当作新事实提交。

**混合请求**保留原Host已经解释的保存、回答与行动义务。循环可以安排它们的顺序，但不能用“已回答”冒充“已经保存”，也不能以一次`HANDOFF`自动关闭未完成义务。

## 7. 开发切片：把动态控制放在第一步

### D1：薄循环和实际Jev调用

**目标：不训练新模型之前，先让真实Laya在操作目录上产生可执行选择。**

开发内容：

1. 在`methods/`增加一个共用的动态循环与最小状态／动作类型；具体操作仍调用旧执行器。
2. 为Laya增加操作候选到既有typed-choice协议的薄适配，复用原provider和回执计量。
3. 同一个循环支持简单规则策略与生成式策略对照；不在三个runner中复制流程。
4. 从真实Source和查询开始，执行至少一次“操作结果返回后再次决策”，再交给原Reader。
5. 接入正常Lab Host；实验脚本仅提供事件顺序与配置，不独占算法。

现有open-only checkpoint可以继续为READ批次内部排序，但不能不改问题合同就直接解释为操作策略。D1的操作选择先使用原始Laya权重或明确标名的初始化权重，记录为零样本可用性诊断；错误本身用于形成新的操作训练数据。

如果真实Laya资源当时不可用，可以先用规则策略闭合执行接口，并保留未运行的Jev条件。Mock只验证接口，不能写成Jev实际效果。

**最小产物：一个共享循环、一个Laya薄适配、一份配置、一条真实闭合历史。**不先建设新训练环境、缓存平台或全流程自动标注服务。

### D2：六条连续历史，展示真实路径分化

| 开发历史 | 状态变化 | 应获得的正常能力 |
|---|---|---|
| A/B审批规则 | 共用规则；只改A；未来生效 | 根据查询日期和作用域取证／复用，B不被连带修改 |
| 项目负责人 | 当前调整与后来纠正旧起始日期 | 区分现在、纠错后历史与当时保存状态 |
| 用户与第三方偏好 | 本人陈述、他人情况、工具观察混合 | 不用错误主体材料完成问题 |
| 替代支持 | 一条支持撤回，另一路支持仍在 | 不把失去一个证明等同结论为假 |
| 跨主题与新例外 | A→B→A；无关事件与新例外交错 | 复用旧解释，但相关变化后补证或刷新 |
| 重开与明确操作 | 保存、更正、查询、重开继续，包含遗忘请求 | 真实状态可继续使用，旧视图不绕过遗忘与版本边界 |

建议每条8—12个来源事件、4—6个任务。六条是开发材料，不是外部benchmark或泛化样本。故事中的离线预期答案、家族ID和正确路径不得进入运行输入。

**先执行固定流程、规则动态、Jev零样本三种策略的首批真实路径；生成式动态作为同操作库的教师候选与对照尽早加入。**不要求六条全对才允许继续开发；先修影响正常链路的实际问题，再进入操作学习。

一条具体的路径对照应能展示：相同查询在来源完整、支持缺失、已有适用视图、刚出现新例外四种状态下，采取不同操作。不要强制唯一顺序；多条合法路径只要有效且成本可解释即可。

### D3：操作策略的领域监督与自身轨迹

在D1/D2产生的真实决策状态上增加操作标签，结合新的训练家族形成数据。训练之后用自己的动作继续执行，不只在教师前缀上计算接受率。

训练主对象是`z_t + A_t → action`。目标范围来自当时真实引用；具体新事实仍由原Writer生成。读取选择与操作选择分别报告，不将其准确率混成同一分母。

详细训练方案见第9节。首轮普通CE与基础权重对照足够，不自动加入RL、价值网络或新的大规模组合损失。

### D4：让复用与刷新真正省工作

第一条动态路径成立后，再从原`query_structure.py`的单槽扩成有界两槽，随后可扩到4槽，仍使用原Store。先展示A→B→A不必反复覆盖；槽位上限和淘汰策略在所有控制臂保持相同。

新事件发现采用两条共用通道：已用支持的实际版本／可见性变化，以及旧支持之外的相关作用域候选。第二条先复用现有检索和明确任务对象，不把词面相似当作支持关系。Jev决定是否刷新，但新例外必须有机会进入其可见状态。

首版直接消费正常调用已经捕获的新来源引用；重开后复用原存储恢复。若确实缺少增量读取接口，才在原Service补窄接口。不要每个问题重复全库枚举再声称减少了计算，也不把新事件发现的工作藏到免费预处理。

**局部刷新能力与刷新策略分开比较。**所有策略共用同一刷新执行器，才能把差异归到控制选择；全量／局部输入本身另作小型因素对照。

### D5：扩展到可选维护时机，而非立即扩大Impact

读取控制基本可用后，增加`MAINTAIN/DEFER_INTERPRETATION/CLOSE_MAINTENANCE`。先研究稳定高复用与低复用、频繁变化的信息是否适合不同解释时机。

原D0直接Writer路径必须保留；旧Impact权重的必要根和保持覆盖不足，不能借读取成绩升级采用。范围选择正确而Writer仍写错时，修Writer任务与语义粒度，不加Jev复核层掩盖错误。

显式保存与更新的真实结果仍要返回用户。延迟的是可选综合，不是记录用户要求的事项或执行已获授权的必要更正。没有后台调度能力时，待处理信息只在下一次实际请求／事件到达时消费，不能承诺稍后自动完成。

### D6：集成与保留验证

把少数候选策略接回同一个Lab Host，执行跨会话读取、事件到达、重开继续和一个原有沙箱工具任务。主实验从相同来源和空状态开始，各臂独立演化；实际before可能分化，不能再称逐步同前态因果对照。

保留共同before的单步干预作为诊断，回答“换对这一个操作是否有用”。两种证据分别报告。

## 8. 示例：动态流程应如何处理时间、来源与作用域

以下是设计示例，不是现有实验结果，也不是正式运行时关键词规则。

**初始来源：**A和B目前都按1000元门槛审批。  
**新来源：**2026年10月18日报告，从11月1日起只有A改为2000元，B不变。

| 到达任务／变化 | 合理操作空间 | 不应发生的事情 |
|---|---|---|
| 10月18日问A当前门槛 | 读取／复用带时态规则的解释，交回Reader | 把未来2000元套成当前值 |
| 11月2日问A门槛 | 已保存完整规则时可以复用；仅保存旧当前值时需重新解释 | 把时钟跨越自动伪造成一条新来源 |
| 问B是否变化 | 使用B范围及新来源限定，不必重建所有项目 | 因共享旧规则而同步改B |
| 新补充说政策仅适用于差旅 | 补读政策上下文；局部刷新A适用范围 | 仅因source版本没变就忽略新例外 |
| 问“10月18日系统实际记了什么” | 打开实际历史版本 | 用纠错后的事实替代当时保存状态 |
| 另一无关项目增加联系人 | 处理其来源，A视图可以不刷新 | 每条新消息都触发所有视图重写 |

保存的是带生效范围的规则还是已经求值的当前结论，会影响应采取的操作。任务状态应明确视图内容和引用，不能只提供一个笼统`valid=true`。

同理，撤回一个支持后若另有独立来源，可能只需更新支持而不改结论正文；若没有充分支持，应保留未知，不自动生成反命题。控制器决定处理范围，具体语义由原执行器完成并以实际后状态评价。

## 9. 训练设计：从段落标签转向操作后果

### 9.1 模型与起点

继续使用项目已有开放Laya基础权重与原生有限动作接口。Laya是Jev类开放实现，不等于TypeSafe原版权重。操作策略、已有open-only选择器和生成式Writer分别命名，避免训练了A而服务仍调用B。[A2][R2]

首轮从同一个原始基础checkpoint训练操作策略，使用原生encoder和头；已有选材checkpoint可作为随后单独的初始化对照，不在主比较中一臂从BASE、一臂从更充分的任务权重启动。

发布权重的概率不直接当决策可靠性证明；训练首轮使用明确动作选择。只有引入概率阈值策略时才需要相应的独立校准与覆盖率评价，不能用温度调整代替行为学习。[P3]

### 9.2 一个训练样本是什么

```text
历史／来源家族标识（仅离线划分）
当前真实请求与决策前可见状态
当时实际提供的动作目录
可接受动作集合，或带明确依据的动作偏好
被执行动作与实际结果（用于轨迹及后果监督）
当前／后续任务结果、语义状态变化、分项计算
标签依据、含糊mask、是否仅作诊断
```

`gold`、未来任务、生成器正确状态、标准证明路径和评判解释不进入策略输入。后续结果可以用于离线训练，但不能提前作为当时模型“已经观察到”的状态。

同一查询在以下对照中应产生不同的监督：已有可靠来源／缺必要来源；视图只缺时间范围／完全没有视图；新事件与任务相关／同名但不同主体；操作已提交／仅返回提案；可复用规则／过期当前结论。

### 9.3 标签从哪里来

**第一来源是来源可核对的任务状态与实际操作结果。**规则策略和生成式策略可以提供示范，但其输出只是候选，不自动成为gold。

同一状态可能允许“直接读原文”或“打开已有解释”两条有效路径。正确性标签允许多个动作；成本偏好由实测或明确估计另记，不把唯一教师路径当作唯一合法流程。

缺少依据时遮罩该操作标签，不机械标为`HANDOFF`、`DEFER`或“不需要维护”。若多个动作后果尚不明，保留部分监督：例如可以确定必须获得时间信息，但无法确定两种检索路由谁更便宜。

普通来源片段的“有用性”不能直接等同终局效用。完整池无法回答时，读到一个部分前提可能有信息价值；但它是否值得本任务继续投入，要看任务合同，分层记录而非自动给正任务奖励。

### 9.4 三阶段训练顺序

| 阶段 | 训练内容 | 主要评价 |
|---|---|---|
| T0：零样本与监督试片 | 基础权重操作选择；少量可核对示范的CE | 是否能理解操作合同，必要操作漏选与过早交接 |
| T1：广家族监督 | 更多独立事件／任务结构，普通CE与选项置换 | 跨家族操作选择、语义变化适应和自身轨迹任务结果 |
| T2：自身轨迹数据聚合 | 在训练家族上运行当前策略，对其真实访问状态补标 | 教师前缀与自身前缀差距是否缩小 |
| T3：任务后果优化，条件启动 | 少量同状态分支比较，必要时再引入策略优化 | 当前及后续任务收益是否抵消控制／维护成本 |

T0不是只运行接口就宣称训练完成。T1/T2是主训练工作；T3只有在标签和反馈足够可靠、明确存在长期信用分配问题时开展，不是为了“创新”自动上RL。

普通soft-CE是首版。对多合法动作可另比较集合似然：

\[
L_{\text{set}}=-\log\sum_{a\in A^+(z)}\pi_\theta(a\mid z),
\]

但此前集合损失的局部信号不能被当作本任务已经成立。新增关系目标必须给普通CE相同数据，不把额外示范数量当作损失函数贡献。

### 9.5 操作效用与信用分配

可用如下研究目标组织轨迹，但不要求立即实现单一混合奖励：

\[
J(\pi)=\mathbb E\left[\sum_t\gamma^t
\left(r_{\text{task},t}-\lambda c_t-\mu d_{\text{state},t}\right)\right].
\]

其中任务收益评价当前与后续实际任务，`c_t`计实际控制／读取／生成成本，状态损伤包含错误更正和非目标内容损失。参数与成本单位在开发数据上确定，正式比较同时公开分项，不把综合分数当唯一结果。

不能简单奖励“少做操作”：永远交接或永远延迟可能很便宜，但丢掉可完成任务。也不能把最终回答失败平均归罪于所有中间动作：选择正确后Writer／Reader仍可能失败。

需要估计一个动作的后果时，可在实际before副本上执行少量不同动作，共用下游模型和控制设置；结果仍受生成随机性影响。只在预声明的训练／开发分支上做，成本全部进入原记录。主连续轨迹不获取这些未实际执行分支的信息。

### 9.6 状态适应的关系监督

新增成对样本应同时包含两类关系：

**必要改变：**只替换已知前提、来源时间或操作反馈，导致不同动作才有效；要求双侧正确，而不只是动作不同。  
**不必要改变：**别名、等义措辞或无关事件变化，仍存在相同有效操作；允许不同但等价的合法路径，不强制字符串一致。

开发测试必须包含自然轨迹。把材料复制为中性observed标识的受控探针可以保留，但它与自然状态分布不同，不能单独证明完整状态能力。

### 9.7 数据规模与训练预算

建议先准备24个训练家族和8个开发家族，另保留六条功能开发历史为回归。该规模只用于确认监督和动作合同，不以数千相关前缀冒充大规模独立数据。

随后目标扩到128个训练家族、32个开发家族；需要概率校准时另保留16家族。正式确认建议事先保留48个历史家族，能力和资源不足时如实缩小并报告区间，不补抽“容易支持方法”的案例。这些是规划数量，不是已创建数据或统计功效承诺。

使用原训练器的事件／家族权重、完整输入检查和选项目标同步置换。先统计有效样本、动作族分布、最长状态和实际设备，再确定更新数。开发可保留学习曲线，确认使用事先声明的选择规则，不后看保留集挑seed或checkpoint。

首轮资源允许时用种子0开发，确认用0/1/2全部结果。相同数据的控制策略比较尽量匹配更新数与初始化；更新数相同但tokens、可训练参数或下游调用不同，继续分别披露。

## 10. 数据与Benchmark：静态能力辅助，动态任务主验证

### 10.1 数据职责

| 数据来源 | 用途 | 不承担的结论 |
|---|---|---|
| 现有MuSiQue／2Wiki训练材料 | 补证、主体／属性关系和来源充分性辅助任务 | 不直接提供完整操作控制或长期维护标签 |
| 新连续历史与现有实际运行轨迹 | 操作顺序、反馈、复用、刷新和实际维护后果 | 开发者合成故事不冒称自然总体 |
| MemOps可核对事件片段 | 当前事实、计划、确认、更正和选择性变化的素材 | 原操作标签不能直接映射成唯一控制路径 |
| MEME等动态记忆场景 | 级联、缺失、删除及变化后使用的外部回归／新切片候选 | 给定正确依赖图不等于从原文形成状态 |
| 一个跨会话行动资源或原沙箱任务 | 检验记忆行为是否支持后续实际执行 | 工具参数命中不等于真实外部业务成功 |

外部资源的任务定位沿用前序研究[A3]；本轮未重新下载全部数据、核实所有授权或确认每个训练入口可运行。接入时只选择与当前机制直接匹配的一个资源，不把全面复现文献表作为开发前置条件。

### 10.2 新动态任务的构造单位

一个数据单位是**一条独立来源历史中的任务及其实际决策状态**，不是一条问题、一个模型调用或一个前缀。

至少覆盖六类变化：主体／属性区别、当前与未来／历史、条件和例外、替代支持、跨主题复用、明确保存与后续使用。补充困难任务时增加独立关系结构和表达，不仅替换姓名、金额或日期。

同一故事模板的语言变体、不同前缀和顺序改写保持同一家族。可交换顺序只用于真正独立事件；共享总量、同一属性覆盖、相对日期和因果前后不能机械交换。

### 10.3 来源、证明与判分口径

来源合同允许已提供前提下的关系合成、指代、日期／数量比较，不允许凭世界知识填充缺少的身份、地点或时间连接。存在非唯一答案、替代证明或题意限定时，保留说明及适当mask，不强造一个无条件gold。

操作训练的目标是合法且有效的下一步，评价则需同时查看终局任务。已充分状态、来源不足状态、预算耗尽和当前仍有补证机会应分别统计，避免多数类掩盖失败。

读源完整不等于理解正确。选中了材料但Reader误解归属或数值范围时，另记使用错误；来源没有被选择时，不能把正确拒答升级成系统成功。

### 10.4 划分与保留

先按原始历史／来源／结构家族划分train/dev/calibration/test，再导出前缀、改写和自身轨迹。跨工作树存在相冲突的保护身份时，按原保护范围处理，只核对本轮实际使用数据，不重做无限历史审计。

旧LongMemEval、本项目已使用的MEME／MemConflict，以及已反馈的保留面板沿用原暴露身份，作为回归即可；不能改名或重抽相同来源后称未见。具体本地暴露范围来自前序审查，不等于这些公开基准对其他研究者永久失去价值。[A3][A4]

新保留数据事先登记来源家族和抽样原则。该轮结果可以影响下一版，但下一版需要新的保留家族或明确标为回归。当前冻结实验的历史有效性不因之后看到结果而消失。

### 10.5 标注工作不应压倒开发

先为六条开发历史建立可核对的关键状态和任务预期，直接运行。训练扩大时再按家族抽样审阅完整来源与动作；运行后优先复核方法差异、关键损伤和事先声明的抽样。

重复响应不重复逐字人工评分；同输入可共用首次回应的判断。确认阶段可对一部分关键来源独立复核，但不为此增加在线Judge／审核Agent，也不要求完成整库人工标注才能开始D1。

## 11. 核心对照：同能力，不同控制方式

### 11.1 四条主线

| 条件 | 控制方式 | 共用能力 | 主要问题 |
|---|---|---|---|
| **C0：固定流程** | 预设检索／打开k段／交回Reader；维护使用声明的固定配方 | 同Source、检索、视图、Writer、Reader和授权机会 | 没有动态策略时最简单方法能做到什么？ |
| **C1：规则动态** | 根据视图存在、已检查到的新事件和预算执行简单规则 | 与C2/C3同一操作目录和执行器 | 收益是否只是因为允许复用和切换路径？ |
| **C2：Jev动态** | Laya选择具体操作；基础权重与领域CE分别命名 | 同目录、同执行反馈、同输入投影原则 | 学到的动态决策是否有新增价值？ |
| **C3：生成式动态** | 生成式模型返回同一个有限动作目录中的选择 | 与C2同操作语义、候选机会和生成执行器 | Jev是否在可比任务质量下更省控制成本？ |

C3的控制模型与后续Reader即使使用相同基础服务，也分别计量调用，不能因“本来已有大模型”当作控制免费。C2不另串联旧控制器复核；C3不独占更强查询改写或更多历史来源。

C0不必故意弱化为只会读原文。先保留现有dense固定4；需要比较视图收益时，补一个预声明的固定视图流程。相同资源上限不等于固定流程必须用完全部资源，但不能只挑一个明显不适合全部任务的k。

### 11.2 简单规则动态参照如何定义

规则只使用程序可得的操作状态和预先确定的调度，不用benchmark答案或人工正确图。一个可实现的起点是：

- 有可打开的目标视图且已检查范围内没有未处理事件时尝试复用；否则使用固定检索／取证配方。
- 已知依赖版本变化时调用同一刷新执行器；找不到视图时按固定规则构建或读原文。
- 取证达到预设小批次或预算后交回Reader；不根据隐藏支持标签判断充分。

这些是可失败的启发式，不是给规则臂免费正确范围。作用域候选发现和新来源扫描与其他方法同等计费。

### 11.3 三个实验批次，不做一次性大矩阵

| 批次 | 建议规模与方法 | 主要产物 |
|---|---|---|
| E0：正常开发 | 六历史；C0/C1/C2零样本先运行，再补C3 | 实际循环、首次路径、可用性和明确错误 |
| E1：操作学习与反馈 | 新train/dev；C1、C2基础与CE、C3；固定共同能力 | 分项操作结果、自身轨迹、任务和成本 |
| E2：连续复用确认 | 新保留历史；C0强固定、C1、事先选定C2配方、C3 | 相关变化／无关变化下的任务—状态—成本曲线 |

首个开发预算可取每条4个任务、3种策略，即72个Reader位置；捕获、检索、控制、刷新和维护调用另按实际路径计。加入C3后对应96个Reader位置。位置数是计划工作量，不是独立样本或必定发生的请求数。

确认实验不必携带全部历史模型。用开发集按预先确定规则选择少量配方，再在保留集报告全部声明种子；不要从保留成绩挑最佳模型或最有利运行。

### 11.4 预算比较

初版可使用相同的每任务资源上限与最多8个控制决策。固定方法额外保留k=2/4/8的成本—质量点，动态方法按状态消耗0至实际预算允许的读取量，不强制恰好四段。

**不能把“相同操作次数”当作公平计算。**一次视图刷新可能比一次原文读取昂贵得多。记录实际编码序列、生成、检索、存储工作和墙钟，再比较质量—成本曲线。若尚无准确跨模型成本标尺，分别报告不同工作量与实测时间，不发明统一FLOPs。

同一查询中为最终Reader预留相同可用容量。对动态方法的公平限制是同等信息与工具机会、明确资源约束，不是和固定方法做同样的步骤。

### 11.5 单步干预与完整轨迹

**共同before干预**：从一次真实形成的状态复制，替换某个操作，观察哪种选择改善后续结果。可以帮助标注和定位，但不把人工修好的状态提供给主方法。

**独立连续轨迹**：各策略从相同来源序列和空库出发，自己选择操作并形成状态。此时后续before不同，是策略后果，不再宣称每一步严格同输入。

缓存／生成首响应可在完全同输入的纯读取评价中复用以节省研究费用；每方法独立成本需加回它本来需要的工作。主连续轨迹中的状态修改不能因为“类似”就引用另一臂的成功状态。

## 12. 机制实验：只针对当前问题增加对照

### M1：反馈闭环是否必要

比较完整动态策略与同一操作能力的一次路由／预设后续策略。任务包括首次检索缺时间、打开后发现同名主体、新事件使原视图不适用等。逐个观察实际新信息是否正确改变后续操作。

若只是首次路由不同，而后续动作与反馈无关，不能把收益写成反馈控制。一次性流程在简单任务更好时保留为可用模式。

### M2：语义状态是否比机械状态有增量

完整状态与重新训练的简化状态策略比较。简化版保留真实版本、候选ID、预算和上次操作结果，去掉已读正文或语义解释；两者同数据机会、标签处理和预算。

隐藏正文可能使部分标签不可辨认，这就是信息贡献的一部分，但不等于简化模型优化失败。冻结模型上删字段的探针只作输入敏感性诊断，不代替重新训练的控制。

原生头与普通线性动作头的比较应使用本轮操作数据，而不是复用旧静态任务的普通头作为匹配消融。初始化不同则如实说明，避免纯架构因果结论。

### M3：复用与刷新策略是否有效

在相同槽位容量和相同生成执行器下，比较每次重建、简单按需刷新、Jev动态复用／刷新。负载至少包含稳定重复、多主题切换、相关更新密集和无关事件密集。

单纯多槽容量收益与语义刷新范围收益分开。只按旧支持检查的对照用于暴露“新例外不在旧图中”的问题，但不要把该弱策略当唯一对手。

### M4：既有信息已经足够之后，还应做什么

沿实际轨迹标记最早已有充分来源的时点，再检查后续读取是否增加无关干扰、改善解释或浪费计算。该标记是离线来源评价，不给控制器实时提供oracle充分性。

同时统计过早交接：全池确有答案而尚未交付时进入Reader，即便Reader正确拒答，也属于可能的策略损失。真正来源不足、预算确已耗尽、没有可用工具等情况另列，不与过早停止混算。

### M5：可复用计算是否有净收益，条件启动

只有确认控制器反复处理候选全文占据重要成本时，才分离稳定来源编码与任务交互。冻结表示缓存可按实际来源版本复用；权重或投影改变时重新编码，不将依赖上下文的隐藏状态直接当作独立来源表示。

比较包含首次编码与维护成本的一次排序、多轮全文控制和表示复用控制。若一次排序已达到相同质量，应采用简单模式，不为了动态性保留无效多轮。

## 13. 评价：动态路径必须完成真实任务

### 13.1 四项主结果

| 结果 | 判定对象 | 常见伪替代 |
|---|---|---|
| **任务成功** | 当前与后续回答／沙箱行为满足来源中的主体、属性、时间、条件与引用要求 | 只命中答案字符串、对自己制造的空证据正确拒答 |
| **实际状态有效** | 必要维护完成，非目标含义保持，来源与版本关系正确 | JSON合法、提案成功、命令退出0 |
| **有效复用／刷新** | 复用或刷新后的解释能正确支持本次任务，未漏新例外 | 缓存命中、少调用Writer、标签“valid” |
| **完整计算** | 控制、取证、构建／维护、Reader、索引与必要加载 | 零生成token、只统计Reader末次调用 |

不把以上强行合成一个“MiLAi准确率”。源内成功、不足时正确拒答、含糊／限定回答、格式错误和缺答分别记录。

### 13.2 动态控制专属诊断

- **必要操作漏选**：应取得材料或处理明确更新时未执行，导致可完成任务丢失。
- **不必要重计算**：无关变化或已适用解释被重复处理，但没有任务增益。
- **反馈利用**：同请求在实际新结果不同后，能否双侧选择有效下一步。
- **错误交接**：还有可用且必要的补证机会，却提前结束取证。
- **条件正确性**：角色／时间／范围变化时操作适用性是否同步变化。
- **路径成本**：完成任务所需的实际步骤、最大／平均控制输入及长尾延迟。

路径多样性、动作熵或不同操作占比只能描述行为，不是正确性指标。所有任务都立即交回Host可能非常稳定，但不代表高质量控制。

### 13.3 可选延迟维护如何评分

来源已按请求保留，派生解释明确待刷新，且不以旧状态误导用户时，延迟综合本身不计为语义损伤。后续任务实际需要该解释时，策略必须通过刷新或显式原文路径完成；相关计算归入这一策略。

明确保存／更正／遗忘请求的遗漏不能改称“延迟维护成功”。正常混合原文回答和状态受限诊断分开：原文补答可以挽救系统任务，但不能给错误维护状态加分。

用于检测遗忘和历史状态的问题不能在问题里重述应被忘记的答案，或附带刚发生变化的全部前提来补救未维护状态。

### 13.4 累计成本与交叉点

\[
C_{\text{workload}}=C_{\text{capture/index}}+C_{\text{control}}+
C_{\text{read}}+C_{\text{build/refresh}}+C_{\text{writer}}+C_{\text{reader/host}}
+C_{\text{required load/recovery}}.
\]

训练、教师分支、标签准备和研究探针另外报告，不抹除，也不重复摊入每次线上请求。方法独立成本与研究实际付费次数分别报告，避免相同输入跨臂复用造成虚假零成本。

对每条真实变化历史，改变查询复用次数、主题切换和事件密度，观察质量可比时何处开始回本。没有交叉点就报告所测负载未回本，不只选稳定重复场景展示。

同时报告冷启动、稳定重复、相关变化后任务。线上共驻时间只有实际测过才声明；顺序运行的暖组件之和不是生产端到端延迟。

### 13.5 统计与审阅

以独立历史／来源家族聚类；同故事多个问题、多个前缀和不同训练种子不增加独立来源数量。报告所有声明种子和稀缺分层，区间宽时保留不确定性，不把不显著解释成等效。

确认阶段应在看保留结果前说明主要质量与成本标准。成本优化的可接受质量差异依据任务用途设定，不事后调整以通过。格式或语义失败计入原结果；修复实现后另记新版本，不补成同版首响成功。

这些字段落实后再提供真实启动命令。不要在未实现前宣称执行`--dynamic-jev`就能运行。少量明确配方优于大量互相依赖的布尔开关。

### 14.2 测试随改动完成

优先检查动作ID与实际参数映射、训练／推理投影、结果反馈、USE与REFRESH分离、预算交接、Source可见性、实际提交反馈以及Host重开继续。再做所触达的静态与边界检查。

无需为每个内部纯函数复制校验层；真实模型运行也不需要等全仓重构完成。相关测试和小规模真实反馈应同步推进。正式候选交付时再按原流程跑合适CI，测试数量不作为方法效果。

### 14.3 首次结果与运行资源

复用原回执和原连续账本；不新增SHA／checksum／替代内容指纹门禁。真实失败、未知用量和部分结果保留。批次出现明确实现问题时先修正常路径，使用新运行身份验证，不无限自动重试旧根。

资源以实际机器和授权为准，不假设旧GPU、端口或暂停任务现在可用。不恢复其他工作树，不新建模型服务作为默认前置步骤。本文只提供后续实施规划，没有启动任何工作。

## 15. 里程碑与结果驱动的转向

| 里程碑 | 应交付什么 | 完成的含义 |
|---|---|---|
| M0：一个真实动态循环 | 共用状态／动作、真实Laya选择、一次执行反馈、Reader交接 | 运行能力成立；不要求模型已经可靠 |
| M1：六历史正常Host | 多种实际路径、保存与读取、至少一次重开继续 | 功能可使用、主要错误可定位 |
| M2：首版操作CE | 新任务标签、基础与微调权重、同操作库真实轨迹 | 训练实际执行；效果单独判断 |
| M3：动态对照 | C0/C1/C2/C3的开发任务与完整成本 | 区分动态能力、策略学习与后端成本 |
| M4：变化与复用 | 相关事件刷新、无关事件不必重算、后续任务验证 | 获得或否定H3/H4机制证据 |
| M5：保留与交付 | 新保留家族、声明种子、真实任务／状态／成本结果 | 实验完成；论文优势仍以实际结果判断 |

不要求等待M5才交付正常可用切片。D5维护扩展及计算表示复用是后续独立工作，不阻塞M0/M1；若已有反馈指向它们是主要瓶颈，再改变优先级。

### 根据结果调整研发

| 观察 | 下一项具体改动 |
|---|---|
| 规则动态与Jev相当且更便宜 | 保留规则可用路径，研究仅在语义歧义状态调用Jev的价值，不增加复核链 |
| Jev动态明显优于固定，但不优于规则 | 将收益归为操作能力／调度，而不是模型创新 |
| 生成式动态更准而Jev更便宜 | 定量研究质量—成本取舍；后续有标签再研究选择性升级，不默认无限回退 |
| 各控制器选对动作，执行器仍错 | 改Reader／Writer／视图表达，固定策略继续比较 |
| 刷新频繁且无复用回报 | 重新分配提前维护与查询解释，保留原文路径 |
| 原支持图没有覆盖新例外 | 修实际新事件候选发现，不继续仅优化已给定候选的分数 |
| 只在不足池动作分数提高 | 调整任务效用与类别覆盖，重点看可完成任务是否改善 |
| 过早handoff稳定发生 | 增加来源充分／缺失的真实状态训练，不只调温度或阈值 |
| 已有充分解释之后仍重复取证 | 检查状态可见性和训练中完整状态覆盖，测后续多读的影响 |
| 静态一次排序已经够好 | 作为简单模式保留；只在需要反馈的任务中采用动态循环 |
| 未见任务上均无收益 | 缩小或重定义决策任务，保留负结果，不通过反复挑数据维持预设架构 |

这些是研发判断，不是新的一串自动拒绝门禁。开发代码、实验记录和科学结论分别维护；负结果不意味着正常功能不能交付。

## 17. 可用性和论文主张分别组织

### 17.1 可用性目标

用户可以在正常Lab Host中提出问题、保存事实、补充变化、切换任务和重开继续；系统根据实际信息决定复用、补证或刷新，而不是所有请求都执行同一套昂贵流程。

保留简单策略并不损害可用性。只要复杂策略没有稳定优势，就可以作为显式实验配置，不切换默认；不为了保持“处处使用Jev”的叙事牺牲正常任务。

### 17.2 优先争取的论文主线

**面向持续变化记忆的反馈条件操作策略：学习何时复用、取证和局部重计算。**

成立至少需要：真实执行反馈对策略有增量；前提／时间／范围变化能够触发正确操作；无关变化不导致不必要重算；完整质量—成本曲线优于强简单控制，或明确展示有价值的适用范围。

若收益仅来自收窄任务到固定预算选材，应据实写成选材学习；若收益仅来自多槽，应归为系统工程改进；若普通头解释全部增量，不宣称Jev专用架构独立优越。

本轮不要求发表一个涵盖所有记忆功能的总系统。先形成一个可被否定、可复现、能在正常使用中产生价值的机制，再决定论文范围。

### 17.3 最重要的验收问题

> **相同任务在不同真实记忆状态下，系统是否能够选择不同且合理的操作；这种选择是否比固定流程、简单动态规则和生成式控制更有价值？**

路径不同只是观察；任务、状态和完整计算才是答案。
