# MiLAi 后续改进规划
## 从代码轻量化到可验证的 State–Attention 记忆方法

**版本：** v1.0　　** 日期：** 2026-09-27　　** 范围：** MiLAi-Lab / RESEARCH_PROTOTYPE

**文档状态：规划稿，不是执行授权。** 本文不恢复已暂停的研究 Goal，不合并 PR，不调用模型或业务服务，不修改共享部署、历史结果、原始数据及旧 v27 草稿。

本 Markdown 是可供仓库审阅的规划源稿；Word 为阅读与批注版本。建议后续经授权放入 `MiLAi-Lab/docs/MILAI_NEXT_IMPROVEMENT_PLAN_20260927.md`。本次未发布该仓库文件。

## 0. 执行摘要与优先级

**推荐路线：先关闭依赖与 CI 缺口，再完成结构整理；行为改进另立变更身份，按“CRUD 合同 → 写入责任 → 局部维护 → State–Attention → 连续任务”逐级推进。** 不将尚未验证的单写入模式、局部 entry 或检索策略直接设为默认。

| 顺序 | 工作包 | 主要产物 | 进入下一步的条件 |
|---|---|---|---|
| 1 | WP0：验证环境与 PR 闭环 | 依赖—源码—测试对应表；实际 CI 结果 | 当前必需检查完成，跳过和未运行不算通过 |
| 2 | WP1：结构与导航轻量化 | 薄 CLI、集中装配与汇总、简洁活动指引 | 同一输入下请求、顺序、回执和计账保持一致 |
| 3 | WP2：严格 CRUD 薄适配 | 明确 CREATE/UPDATE/DELETE 语义及真实回执 | 锁定依赖下可重复验证，不增加静默修补 |
| 4 | WP3—WP5：最小行为候选 | 写入责任对照、局部维护、薄 State–Attention | 同信息对照显示值得继续的信号 |
| 5 | WP6—WP7：真实使用与研究确认 | 材料消费诊断、成本分解、连续任务比较 | 方法效果、执行可靠性与成本分别有证据 |

**当前最直接的阻断不是 LSA 单测失败，而是默认 Lab 类型检查环境缺少被检查模块所需的可选依赖。** PR #51 的 LangMem 专项通过，总 gate 仍失败；PR 保持 Draft、未合并。该状态在本次文档编制时再次核验。[R1][R2]

**三个不可牺牲的边界：** 不删除反证或历史失败来“简化”；不让模型自报成功替代真实提交与执行；不把所有未知都转成拒绝或永久遗忘。简化目标是减少重复责任，而不是降低正确性要求。

**研究目标仍保留完整记忆动作空间。** CREATE、READ、UPDATE、RETRACT/DELETE 和 NO_CHANGE 都要能自然发生。State–Attention 研究的是如何选择操作与材料，不是将系统重新缩成只做 Revision，也不是要求每轮完成一套固定工具流程。

## 1. 事实基线与版本隔离

### 1.1 当前已确认、未确认和禁止外推的内容

| PR #51 | 控制器与纯协议分离；局部集合构造优化；4 文件变更 | 等价重构候选，不是方法收益 |

| 专项 CI | foundation 12、LSA/application 80、read-probe 7 通过 | 对应冻结环境下的工程证据 |
| 总 CI | 默认 Lab Mypy 报 7 文件、14 项错误；后续步骤未完成 | 合并阻断仍存在，不能借专项通过绕开 |
| 研究结论 | 16 轮及复盘尚无稳定未见收益 | State–Attention 保持候选身份 |

PR 后两运行文件合计为 587 行，原控制器为 512 行；其中 controller 为 376 行、protocol 为 211 行。两文件字节数从 29,116 变为 28,826。不能以控制器变短宣称全仓缩减约 27%，也不能推断模型 token 或时延已经下降。[R1]

### 1.2 最新实验负面证据必须保留

最新 E2 在线比较中，pre_model 与 turn_end 均为 strict 7/11、完整轨迹 0/2；生成 tokens 分别为 54,453、33,039。两条已暴露脚本上低约 39.33% 的用量没有带来质量改善，并且维护节奏、形成内容与错误路径同时变化。[R3]

两组维护器都曾正确形成 2→3→4，但后续实际动作分别使用了 5 或 3；另有正确复数正文已可见、动作 key 仍单数化的失败。因此，形成、取材、消费和行动必须分别诊断，不能把所有问题都解释成检索不足。[R3]

### 1.3 历史 contextual 报告只作为经验输入

附件中的 v6/v7/v8 属于较早 contextual 路线。v8 提供创建、原卡修订、真实业务回写和恢复的限定证据，但其成功路径 State off，不是当前 LSA 控制器的独立效果证明。旧版 patch、finish_turn 或空删除缺陷不能未经代码核对就列为当前 LSA 的“已实现”或“仍存在”。[R8][R9]

本规划只读核验了当前 PR、运行状态、依赖配置、总体报告及锁定 LangMem 的相关源码；没有重新执行上述模型实验、测试或业务动作。后文工作包均为建议实施。

## 2. 目标架构：成熟底座之上的薄研究层

### 2.1 复用什么，不再重造什么

保留现有 LangGraph/LangMem 的公开消息、Store、checkpoint 与 ReAct 接入；保留业务工具、准确事件身份、合法历史、用户隔离、真实回执和连续计账。Product、Lab、Archive 继续遵守既有职责边界。[R4][R10]

目标运行结构为：**可信输入/业务观察 → 当前任务状态 → 按需读取或业务行动 → 真实结果 → 必要的记忆维护 → 继续任务。** 没有决策缺口时允许直接行动，没有可保留的新认识时允许零写入。

| 对象 | 唯一职责 | 不应承担的职责 |
|---|---|---|
| 原始观察 | 保存实际收到的内容、角色、事件与工具结果 | 自动认证其全部自然语言为真 |
| 持久理解 | 保存可复用、可修订的事项及依据 | 复制全部对话与所有临时推测 |
| 局部 State | 表达本次目标、临时约束、活跃引用、待决问题 | 再独立维护一份相同事项的长期真值 |
| 工作视图 | 按当前任务解析并呈现必要材料 | 成为第三份独立更新的事实库 |
| 执行/实验记录 | 表示实际操作、版本、失败、用量与评分 | 默认作为额外可搜索历史提供给某一实验臂 |

“一个事项有明确的持久写入责任”不是“一张卡覆盖全部内容”，也不是只能有一个 State。允许多个局部任务态和多个有不同范围的事项记录；需要避免的是同一含义被多条独立维护路径反复改写，而没有清楚的交接规则。

### 2.2 完整 CRUD 与生命周期

**增：** 新事项或明确值得保留的信息；补充依据未必需要复制正文。**查：** 发现、读取、当前版本与范围解析；不能将入口句柄当成已读正文。**改：** 同一事项的内容、范围、时间或依据变化。**删：** 区分退出当前视图、撤回派生理解与明确授权的受管遗忘。**不操作：** 没有实质变化时继续任务，不强制新增一次模型调用。

Attention 的关注集合不是写权限或删除范围。新输入即使不影响当前行动，也可能需要长期保存；物理或范围性删除不能只处理当前 top-k。程序验证身份和执行范围，Host 判断语义，二者都不应被对方的状态字符串替代。

## 3. WP0：修复依赖与验证矩阵，关闭合并阻断

**类型：工程验证变更。优先级：P0。前置：无。** 首先在独立环境核对 main 与 PR head 的相同检查，区分既有缺陷、PR 导入影响和环境差异。文件未修改不等于故障因果已经证明。

### 3.1 最小实施方式

从现有 import、pyproject 和 CI 命令建立一份小型对应表，不新增通用插件注册器。每个活动模块必须由至少一个安装了其真实依赖的检查环境负责；纯标准库协议和核心入口应继续在不安装 LangMem 的环境中检查。[R4][R5]

| 验证环境 | 安装范围 | 必须覆盖 |
|---|---|---|
| core | 基础依赖＋dev | 核心导入、边界、纯协议、共享工具、可发布构建 |
| foundation | core＋baseline-langmem | LangGraph/LangMem 适配、LSA、application、history 与相应可选源码 |
| external | core＋实际需要的外部组 | mem0_native 等外部路径；确实还依赖 LangMem 时显式同时安装 |

优先采用静态、可审查的文件/目录分组和已有命令。普通依赖升级、框架迁移与 CI 修复分开；不为消除当前警告就顺带迁移 create_react_agent 或重算全部锁文件。

### 3.2 需要特别防止的“假绿”

不得全局 ignore_missing_imports；不得只扩大 Mypy 排除目录而不增加真实检查归属；不得用安装时 editable build 成功代替最终 wheel/sdist 构建。排除递归发现也不一定阻止类型检查器沿 import 进入模块，必须检查实际被检查文件与缺依赖位置。

纯协议 71 项要在项目锁定 pytest 环境实际执行。现有专项只明确执行了其原测试分组，不能假定新增测试已因此覆盖。可选环境必须检查实际收集数，避免整文件 importorskip 造成零覆盖但 CI 显示绿色。

### 3.3 验收与回滚

验收：必需 job 全部达到各自声明目标；coverage 映射无遗漏；全量 Ruff、适用的类型检查、纯协议与既有集成、归档边界、最终构建分别有记录。Product 身份和历史制品保持不变。按测试变化风险扩大验证，不为文档发布反复重跑相同批次。

回滚：CI/依赖分组以独立提交撤回，不改变运行数据库。PR #51 仅在所需 gate 完成并经正常审阅后才能合并；文档不授权自动 merge。

## 4. WP1：继续结构轻量化，但不再以移动代码为成绩

**类型：等价结构变更。前置：WP0 验证方案明确。** 保留 PR #51 的 protocol/controller 分工，不继续拆成十几个小包装类。现有 schema、错误名与兼容入口已有使用者，变更必须有迁移理由。[R1][R6]

### 4.1 收拢两个职责中心

`tools/run_local_state_attention.py` 应逐渐只承担参数解析和调用公开 runner；配方解析、身份装配和结果汇总放到现有包内相应职责处。先复用已有实现，仅在没有明确归属时新增一个窄模块。不得新旧入口各保留一套可运行算法。

`integration.py` 保持公共 hook、真实事件进入和工作视图注入；不承担评分，不自行生成业务事实。`bank.py` 保持存储及精确提交语义，不加入模型调用。`protocol.py` 只维护模型可见合同，不读取 Store 或据题号选择提示。

### 4.2 活动文档减负

将 AGENTS 中活动边界与历史执行记录分开。活动入口只保留当前状态、不可变边界、必要命令和明确链接；历史记录迁移须保留原内容和恢复路径。尤其保留 PAUSED、Product NO-GO、旧 v27 草稿及未启动阶段的限制，不让摘录后遗失暂停状态。

仅整理有实际引用核对的文件。旧报告、manifest、失败清单、未跟踪用户工作、第三方目录及运行制品不因“看起来重复”被批量删除。

### 4.3 等价性的检查范围

比较同一输入下完整请求、字段与候选顺序、U/维护/A 次序、来源范围、pending、容量占用、回执和 trace。时间戳、随机 ID 等非语义值若需规范化，必须明确列出；不能将差异过滤规则用于抹平业务字段变化。

源码身份本身变化是预期结果，新运行需新身份；旧实验得分继续归属原源码。模型提示、默认策略、阈值、预算、实际可见材料发生变化，则该提交转为行为变更，不再称“等价重构”。

验收指标以独立语义写入路径、重复逻辑位置、调用层数、可选依赖负担和测试可定位性为主。行数、文件数与字节数只作为描述，不设机械缩减比例。

## 5. WP2：在锁定上游之上增加严格 CRUD 薄合同

**类型：行为修复，独立于结构 PR。前置：WP0。** 本次已核对锁定 LangMem 提交 `9d033b4…`：其同步与异步 UPDATE 路径检查 ID 是否提供，但未先确认目标存在，随后调用 put/aput。UUID 格式合法不等于该 memory 已存在。[R4][R7]

这不是未经核验地指责整个上游，而是 MiLAi 的“准确原对象更新”要求与轻量 Store 写入语义之间的差别。必须在实际集成路径复现后增加薄适配，不 monkeypatch 第三方包，不更换整套存储。

| 操作 | 最小合同 | 明确禁止 |
|---|---|---|
| CREATE | 由程序产生新 ID；回执说明实际新增 | 将未知 UPDATE 静默转为 CREATE |
| UPDATE | 在当前 namespace 确认目标；执行实际变化；若已有版本合同继续保留 | 用其他用户、消息 UUID 或不存在 ID 覆盖/插入 |
| DELETE | 按当前权限及目标范围执行，区分不存在与实际影响 | 根据含空字段或模糊状态词触发清理 |
| READ/SEARCH | 返回真实对象身份、内容/范围及可展开入口 | 将标题当作业务主键或将链接当已读正文 |
| NO_CHANGE | 不改变业务/记忆状态，不强迫额外推理 | 把无变化算成一次语义修订 |

首次只补存在性与回执语义，不新增要求 Host 对每个写入执行额外 READ 的全局门槛。现有已读要求若存在则保留；身份和版本由程序交付，模型不负责猜 UUID。

**验证：** 同步/异步一致，已有与缺失目标、错误 namespace、格式合法但非 memory ID、空删除、真实删除、Store 异常，以及本次调用没有产生副作用的情况。错误明确返回；不要把提交拒绝中的提议参数重新包装成已确认事实。

单写者的先检查再写入不是多进程 CAS；不能因此升级并发保证。外部原生 LangMem 基线可保留原语义，但需标注。用于机制归因的各臂共享同一薄合同，避免候选独享更安全工具。

## 6. WP3：先验证写入责任，再决定是否改变 State 的形态

**类型：算法/执行策略候选。前置：WP2；需单独实验授权。** 最新 E2 支持“多个解释表达发生竞争”的风险，但没有隔离双写、时点、标题和 Host 推理能力的各自贡献。不得先宣布“只留一个写入者即可解决”。[R3]

### 6.1 两步而非一次大迁移

第一步固定存储表示、源前缀、工具能力与任务，比较不同写入责任安排。第二步只有在责任清楚后，才检验将 State 中重复事实改为当前记录引用。不能在同一个胜出结果里同时归因两种改动。

| 候选安排 | 说明 | 对照边界 |
|---|---|---|
| Host 主导 | 业务 Host 通过统一入口选择持久 CRUD | 不因节省调用而忽略明确“请记住” |
| 边界维护主导 | 明确事件/轮次边界处理新观察；Host 可表达需维护的事项 | 不把此模式伪装为与自由 ReAct 完全相同的策略 |
| 当前重叠模式 | 保留历史结构作为对照 | 不人为降低材料质量以制造候选胜出 |

这些是系统策略对照，若工具呈现或持久化权限变化，必须明确记录。三组都须有完成合理增删改查的途径，而不一定向模型暴露完全相同的编排形态。

### 6.2 建议目标，而非直接设为默认

一个逻辑入口决定同一持久事项的提交；State 保存当前目标、临时约束、活跃引用和待决问题。允许多个局部 State，不要求“一人一张卡”。引用持久记录时保留版本和必要的当前片段，不在另一个 bank 里独立维护同一数量或业务状态。

若确实需要缓存理解，明确它是派生视图、基于哪个版本、何时需重新核对。单写入责任可以跨多个函数实现，也不等于必须只有一次模型调用。

**验收：** 明确长期约定不漏存；临时要求不永久化；不同 owner 不串用；有来源的新变化可影响后续任务；同一事件不因两条维护路径重复应用；任务质量与成本分别报告。失败时保留简单模式，不增加新的语义仲裁 Agent。

## 7. WP4：薄 State–Attention 的算法规格

**类型：方法候选。前置：读写底座已固定。** 本文保留 State–Attention 为研究目标，但不预先接受“独立 U 模型＋维护模型＋独立 A 模型”是最佳实现。当前控制器确有这些阶段；其成本与价值尚未完成固定 bank/前态比较。[R3][R6]

### 7.1 两个不同集合

工作状态建议表示为 `S = (goal, temporary_constraints, active_refs, open_questions)`。真实观察记为 O，当前持久 bank 记为 M。

**读取集合 A：** 服务当前问题及决策缺口。**更新候选集合 U：** 来自新观察可能影响的旧事项。两者不要求相等，也不能因为 U 为空就禁止 CREATE；当前任务不相关的信息仍可能需要保存。

第一版以现有检索形成两类候选：A 使用原问题、明确实体与必要 State 线索；U 使用真实新观察与已有事项。独立模型 selector 只作为可关配置，不先设为默认。小 bank 的全读是必须保留的强对照。

### 7.2 不自我确认的 Attention

原问题与实体锚点始终保留。State 中“尚未检索”不能变成“不存在”；猜测不得变成硬过滤。关注某条材料不等于采用它；不适用于当前行动的旧记录仍可作为核对范围和变化的材料。维护错误的根因要靠实际反证检查，不能只按与 State 一致度排序。

一个 ReAct 回合可以为空焦点，可以直接业务查询，可以搜索/读取，可以提出记忆操作或完成任务。确需记录 State 变化时，优先与普通行动在同一轮表达；不强制固定 State→search 开场，也不宣称这种合并没有 token 成本。

### 7.3 操作后的反馈

READ 增加实际可见依据；UPDATE/RETRACT 使依赖旧版本的工作判断重新核对；CREATE 也可能因新反证使“已有材料足够”失效。只跟踪当前实际使用的少量引用，不构建全库因果图。

程序可以使旧充分性绑定失效，不能自动认证新的解释正确。移出 active_refs 也不等于旧文字已经从模型 transcript 中消失；如涉及真正上下文裁剪，必须另立对照。

## 8. WP5：局部维护与事件时间语义

**类型：行为候选；对应旧计划 E1，尚不能称已完成。** 较早 contextual v8 的 patch 已有实际使用，但不能未经适配把它视为当前 LSA bank 已具备相同合同。当前规划在 LSA 上先实现最小可比较能力，不回流整套旧 runtime。[R3][R8]

### 8.1 局部内容变化

以可独立修订的事项为单位，允许对已交付目标版本表达明确片段修改；原片段不唯一、范围不清、影响跨句或发生广泛变化时，允许核对后完整重写。局部修改的目的不是字符最少，而是只改变依据要求改变的范围。

未指定的正文可由程序保留；已有来源谱系可明确继承，但不能声称本轮重新审阅了全部旧来源。新增/撤回依据、主体或有效范围变化必须明确。若现有记录只是引用列表，不自动把它推断为 AND/OR 支持组。

**对照：** 同粒度整体更新、普通 patch、候选局部表达。若普通 patch 已足够，不再叠加支持图以制造新机制。验收同时检查变化和无关信息保持，不能用拒绝所有修改换来“零破坏”。

### 8.2 事件一次执行不等于语义一次消费

保留 D0 的准确事件集合/编辑位置重试标记；相同文本的不同真实事件仍需分别生效。改变事件批次组合并不自动得到语义幂等保证。[R3]

pre_model 与 turn_end 都作为显式配方保留，当前默认不在结构 PR 中切换。描述视图时说明事件是已经被维护应用、还是尚待处理；但不得据此硬编码“加一”、金额或 benchmark 词。

业务成功但维护失败时，保存真实结果，续接处理未完成维护，不重新执行业务。只有 intent 或实际结果未知时，按原能力核对，不伪造 exactly-once。旧 snapshot 回滚不能回滚外部世界；恢复计划必须保留这一区别。[R8]

## 9. WP6：材料角色、精确身份与行动消费

**类型：行为诊断＋经验证的最小呈现改进。** 正确 State 后仍执行错误值，是当前优先问题；标题单数化与动作 key 改写的因果关系尚未确认。[R3]

### 9.1 四种材料必须可区分

| 材料 | 可支持的结论 | 不能直接支持 |
|---|---|---|
| 用户输入 | 用户提出了要求或报告了经历 | 业务已执行成功 |
| 工具实际结果 | 本次执行或查询返回的字段及部分副作用 | 用户已经满意、后续世界永不变化 |
| 助手提案/旧答案 | 当时提议或回答了什么 | 当前状态的独立权威依据 |
| 当前 State/记忆 | 系统当前采用的可修订解释 | 无需再核对的客观真相 |

复用真实 tool_call_id、状态和字段进行投影，不新增审核模型。失败回执不能全部丢弃：失败前可能已有真实副作用。提议参数与执行结果分开呈现，但不静默篡改原始回执。

### 9.2 精确实体不是生成标题

工具提供的 ID、key 和准确字段保留为可引用信息，标题只作导航。固定正确正文，分别测试原标题、源字段标题和无 State 原前缀；若 Host 在全部条件下仍改错参数，应如实定位为消费/生成问题。

不自动把单数改成复数，不建立题号例外或 gold 同义词表。若提出使用源句柄构造动作参数的新接口，应给所有比较臂相同能力，并作为明确的工具合同变更。

### 9.3 精简材料的次序

先做同一响应内准确对象/版本/范围的重复去除，再减少空字段、重复元数据与不影响当前用途的展开。保留当前/历史、角色、作用域、争议和必要更正。不得通过删掉反证或旧历史，只给候选更容易的材料。

旧 v6/v8 的输入成本占比和回执负担只提供优化方向，不作为当前 LSA 的成本测量。当前优化必须依据对应冻结请求重新计算。[R8][R9]

## 10. WP7：测量复杂度，而不是追求表面瘦身

**类型：测量与有限性能优化。** 当前 bank 扫描和多阶段控制是测量候选，不是已证明的主要瓶颈。只有测得持续影响，才增加索引、缓存或提交增量；每加一个缓存同时增加失效责任。[R6]

| 指标层 | 建议记录 | 解释边界 |
|---|---|---|
| 代码/职责 | 活动入口、独立语义写入路径、重复规则位置、必需依赖 | 行数下降不直接等于复杂度下降 |
| 执行 | Host/U/维护/A 各阶段调用、首次合法提案、拒绝后修复 | 工具返回不等于状态改变 |
| 材料 | 输入/输出 tokens、实际正文/元数据、候选和已读范围 | 序列化字节不等于物理磁盘 I/O |
| 存储 | get/search/put 次数、扫描行数、测得 CPU/wall 时间 | 不用调用数量直接推断 GPU 成本 |
| 任务 | 原生成功、实际世界变化、恢复、维护完成 | 业务通过不能覆盖错误记忆 |

费用维持原连续账本，真实运行使用新 namespace，不清零历史也不把旧成本再次相加。生成、embedding、Judge 与开发代理费用分列；unknown usage 保持未知，不能补零。累计预算政策不由本文更改，单次请求与工作流容量仍应匹配实际模型能力。

设总来源形成成本为 C_build，持续维护成本为 C_maint，N 次使用成本为 C_use(i)。报告 `C_total(N)=C_build+C_maint+sum(C_use(i))` 及每次复用摊销，不只展示一次查询便宜。缓存冷/热、共享/独立启动分别说明。

本地优化先选一个测得热点，例如一次操作内重复扫描；保持结果顺序、来源集合、恢复与删除可见性。若没有明显收益，则不新增持久索引。配方、检索阈值和模型调用节奏不与纯 CPU 优化混在一个比较中。

## 11. 实验分层：以最小可证伪切片恢复研究

所有下述真实模型或业务实验均需新的明确执行授权。已暴露 MERIT seeds 0–4、旧文档与旧 MemSyco 个例继续属于开发；准备了 MemoryArena 资源不等于完成原生评估。[R3]

| 实验 | 首先固定什么 | 比较什么 | 目的 |
|---|---|---|---|
| X0 合同/等价回归 | 固定程序输入与合成响应 | 旧/新结构、CRUD 边界 | 先排除工程污染，不计任务准确率 |
| X1 正确 State 消费 | 固定合法前缀、正确正文、工具与任务 | 角色呈现、标题、写入责任分别干预 | 区分时点、双写、身份与 Host 行为 |
| X2 局部保持 | 固定前态、新事件、相同事项粒度 | 整体更新/普通 patch/候选局部维护 | 变化与未变知识是否同时正确 |
| X3 A 选择 | 固定同一 bank、冻结写入 | 全读、普通检索、同 State 查询增强、A selector | 排除形成过程差异 |
| X4 U 选择 | 固定更新前态和新观察 | 全候选、U、U=A、oracle U | 检验独立更新范围和创建机会 |
| X5 连续在线 | 同一初始世界、合法历史、工具和配方 | 简单基线与一个通过筛选的最小候选 | 检验闭环、后续复用和总成本 |

X1 不把所有干预展开成大矩阵。先据真实断点选择一项，并保留一个反例；首响应正确后必须继续验证实际动作。X3/X4 的 oracle 只用于诊断上限，不能进入主方法成绩。

在线运行中行动不同会产生不同观察，允许自然分叉；不能把候选行动才取得的结果强制喂给基线。反之，静态 A/U 归因必须固定前态，不能用独立形成的两个 bank 声称纯 selector 效果。

每个切片产生：冻结配方、源输入身份、完整失败与成本、分母说明、逐例差异和一个可执行结论。基础设施失败与正常语义失败分开；一次失败不终止整个研究，但禁止无诊断地重复同题直到通过。

## 12. 强对照与论文主张的对应关系

**主假设：在相同 CRUD 能力与合法信息条件下，薄 State–Attention 和明确的记忆维护责任，能否兼顾选择性适应、有效知识保持与生命周期成本？** 它是待验证问题；统一 CRUD、显式 State 或使用成熟框架均不能单独成为创新。

| 需要排除的解释 | 必须保留的对照 |
|---|---|
| 原始历史本来就足够 | full history（容量允许时）、强原文检索 |
| 只是显式写了工作笔记 | 同内容 State 文本＋强 ReAct |
| 只是更好的 query | 同 State 的普通查询增强 |
| 只是记录拆小/少重写 | 同粒度普通更新、普通 patch |
| 只是多花计算 | 给简单基线相同额外预算做回看/rerank/重建 |
| 只是多模块同时启用 | 各模块独立与共享依据的耦合对照，必要时才增加 |

强原文与候选须有相同合法历史和副作用恢复机会。Archive-access 与仅保留已保存材料的 Retained-memory 设置分开报告；运行日志是否可被 Host 搜索，也必须一致声明。

外部基线按准确 commit 和实际配置运行。已有依赖锁中的 LangMem 与 Mem0 可优先复用；只取其组件即称适配版，不冒称完整复现。上游 UPDATE 的语义差异需要披露；原生系统比较和共享薄合同的机制比较不混为一表中的同一归因。[R4][R7]

首先在现有真实应用/原生任务上形成有效比较，再考虑一个未见模板集合和第二模型家族。MemoryArena 或其他环境仅在实现与官方评分可用时接入；不能把资源下载、wrapper 接线或模拟回执计为 benchmark 完成。[R3]

## 13. 验收标准与 Go / Pivot / Stop

### 13.1 工程完成与研究完成分别验收

| 门槛 | 必须满足 | 不足以替代它的证据 |
|---|---|---|
| G0 可验证 | 依赖矩阵明确、所需 CI 完成、构建与边界有记录 | 某个专项绿色或文件能 import |
| G1 可继续工作 | 正常 CRUD、真实结果、部分失败续接不丢失 | 助手说“已经完成” |
| G2 可归因 | 固定 bank/前态、同信息和预算下能定位收益来源 | 分别形成后的小样本总分 |
| G3 值得保留 | 在任务质量与总成本上有实际价值，或清楚的适用边界 | 调用更少但关键任务更差 |
| G4 可支持论文 | 未见任务与跨模型确认、强外部对照、局限与失败完整 | 开发题反复通过、已有功能清单 |

可将约 5 个百分点的有用质量差异，或在预声明不劣界限下约 20% 的生命周期成本下降，作为项目投入信号。这是建议的筛选标准，不是顶会门槛，也不是几十个样本就能可靠确认的统计结论。

### 13.2 决策含义

**GO：** 强简单对照不能解释主要收益；有效知识保持和正确更新同时受益；额外计算已计入，连续动作仍成立。

**PIVOT：** 只有局部 entry 有效就研究局部保持；只有接口有效就按系统改进定位；只有 oracle A/U 有效就定位 selector 形成；只有成本有效就报告效率边界，不强称算法质量领先。

**STOP 当前机制主张：** 足够精度的对照仍显示简单方法持平或更好；移除核心机制不影响效果；收益完全来自信息权限、更多计算或更少采用记忆。小样本“不显著”本身不是否定证据；暂停一个机制不意味着删除平台或失败历史。

统计以 arc/用户/共享历史为聚类单位。重复生成测随机性，不增加独立场景数。报告效应量和置信区间，不把 temperature=0 等同确定性，也不把未评分当正常判错。

## 15. 实施协作、交付模板与范围控制

**组织建议：一名源码/接口负责人，一名独立运行与分析负责人；小任务可由同一人顺序完成。** 这是工作职责，不要求部署运行时多 Agent。只有明确独立切片才并行；真实模型调用仍按现有服务能力与授权约束执行。

每个工作包的交接保持八项：问题及来源、变更类型、准确改动路径、输入/输出合同、已运行与未运行验证、结果/成本、剩余风险、下一步决策。不要复制整段历史对话或为每个小失败制造一个新框架。

所有新增任务先回答：它在修复可复现程序缺陷、降低已测量负担，还是区分一个具体研究假设？三者均不是的任务退出本期。维护方便与论文贡献分开；不因为近期主要改哪一块，就把那一块预定为创新点。

建议最终只形成少量稳定产物：本规划、依赖检查对应表、薄接口说明、冻结实验协议、逐例结果与总体结论。数据/源码身份和运行参数以机器可读现有 manifest 为准，避免 README、脚本与报告各自维护一套配置真值。

**当前不做：** Product 迁移、全链物理删除保证、分布式事务、通用图数据库、多模态、学习型 selector、常驻审核 Agent、夜间全库反思、未经批准的第二模型下载/部署、全部 16 轮重跑。这些不是被永久否定，而是尚无证据成为本轮前置条件。
