## 第一批可验证改动

- WP00：现有执行循环可选输出候选菜单、投影、策略和实际操作的嵌套计时；原生采集入口
  分开记录来源目录、最终证据包装和 Reader 请求容量。所有阶段为 inclusive 区间，不将
  父子相加；仅准备请求时端到端和外部 GPU 成本保持 unknown。
- WP01：复用 `control_input`，增加对象投影；所有公开集合逐项保留，显式区分候选、控制器
  观察与当前交付。监督/来源分组/未来字段不进入编码输入，旧 Laya/dual/joint 保持原路径。
- WP02：实际来源形成 R2 完整段落与 R3 完整已捕获 turn。范围通过原 MemoryService READ
  重开；不截断超长段落。段落完整不等于语义充分，其他段落中的例外必须实际展开。
  `source_directory_only` 为显式新信息条件，避免把整篇来源在初始事件里免费交给控制器。
- WP03/WP04：同一个训练入口新增 `objects` readout，分别支持独立对象池化 MLP 与
  query-conditioned latent 工作槽、交叉 attention 和完整绑定指针。使用冻结可替换编码器，
  不新增来源访问或执行器。超过对象容量明确失败，禁止静默删对象。

新对象 MLP 与 latent 的参数/计算不相等，首轮只验证可学习性与实际接线。没有参数匹配、
同架构可用暖启动、实际新来源任务对照，不能用训练排序分数证明 attention 的独特贡献。

该小块是已曝光 TRAIN 的瓶颈诊断，不能作为新来源确认或泛化成绩。

随机抽取 1 状态，共 64 状态；抽样不查看分支得分。它们是旧协议实际状态，包含原有合法
观察，不冒充新 R2/R3 低信息状态或新的 D0 来源。使用同一冻结 E5、同一数据/日程，
MLP 与 latent 各固定 seed0、96 更新、batch16、LR3e-4；固定终点，不挑最优 checkpoint。
latent 起点宽 128、4 heads、8 slots、2 blocks、FFN512；此为有限诊断，后续规模/深度
实验仍需实际容量表。标签只定义 h2 的已执行结构进展，不宣称完整 Reader 任务效用。
首块限制在 1 个分配 GPU 小时内；不将计划 240 小时包络视为必须或已授权消耗量。
