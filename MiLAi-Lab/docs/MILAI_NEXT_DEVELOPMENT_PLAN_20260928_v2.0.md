## 4. 方法收敛：State–Attention 与完整 CRUD

【建议目标】在真实ReAct中，用当前任务选择读取材料A，用真实新观察确定更新候选U；普通Host或既定边界策略在共同工具合同下完成CREATE/READ/UPDATE/DELETE/NO_CHANGE。A与U有不同依据，不需要每次都用两个独立模型调用求得。

```text
O_t = 当前合法、尚待处理的实际观察
A_t = ReadSelect(query, state_directory, budget)
U_t = UpdateSelect(O_t, state_directory, budget)
M_(t+1) = Maintain(M_t restricted to U_t, O_t, create_allowed=True)
V_t = Deliver(actual selected records, current or frozen epoch policy)
Host(V_t, legal history, task) -> memory action / business action / answer
```

以上是规划接口，不是已经验证的算法。U为空必须允许CREATE；A为空可以是合理结果。操作权限仍由执行层限定，Attention不授予删除权；无变化和被拒操作不伪装成实际写入。

| 操作 | 最小职责 | 需要防止的错误 |
| --- | --- | --- |
| CREATE | 新事项或有价值的新理解；保留实际来源。 | 把无候选U解释成禁止创建；新增重复计划。 |
| READ / SEARCH | 取得当前任务所需内容与精确身份。 | 选择过就宣称读过；读过就宣称采用。 |
| UPDATE | 改变已有事项的内容、范围或依据。 | 用message UUID作memory ID；缺正文擦除原值。 |
| DELETE / RETRACT | 按既有授权和对象范围退出或清理。 | 当前不相关直接删除；将撤链接等同删除原来源。 |
| NO_CHANGE | 没有必要持久改变时继续任务。 | 为了少错而拒绝全部必要更新。 |

首版保持现有两库表示，用host_both与overlap作候选；不默认改成纯引用State，也不新建第三事实库。公共执行回执、来源、namespace、版本和恢复能力对各臂共享。表示改造必须另有证据，不能与A/U实验一起改变。[R3][R6]

### 剩余首断点及最小处理

| 断点 | 最小核对/建议 | 不能这样处理 |
| --- | --- | --- |
| 局部成功后只关注State | 沿现有共享回执交付各对象真实状态：未改、已改、拒绝、未完成。 | 程序根据正确State自动改ordinary，或自建两库事务。 |
| 错误提案污染后续判断 | 保留原错误，并明确它是拟议参数/拒绝，不是业务事实。 | 删除失败回执、把所有tool文本默认当真。 |
| 精确对象参数改写 | 核对用户/实际工具身份能否原样引用；标题只作导航。 | 题号分支、gold key替换、单复数自动纠正来买分。 |
| 增量重复或漏消费 | 区分真实新事件与已ack来源；检查当前State时点。 | 把同文本的不同真实事件去重。 |

这些是建议诊断，不是已经确认的唯一根因。WP6的六条后续响应都忠实报告实际ID、数量和标签结果，但严格任务只1/6；修复执行忠实性不能代替修复行动选择。[R5]

### 最小实验与退出条件

先零模型审计既有前缀/回执；只有存在明确待区分因素才新调用。一次只改变一个材料角色或共享回执投影，保持正确正文、合法旧历史、业务工具与原评分一致。首响应选工具必须实际续接到真实结果；部分成功后的未知结果不得盲目重做。

> 若在正确材料、清楚身份和正常工具合同下仍持续做错参数，应将其记为Host消费瓶颈；不要继续为同一题加提示、标题变体或更多记忆模块。后续保留原分数和竞争解释。

### 运行合同

若按上述两前缀与五条件执行，首轮为10条读取路径，不等于10次模型调用或10个独立样本。同一初始bank复制到独立scope，不允许各臂先分别形成自己的State再声称纯读取比较。只读切片冻结维护；事件、ID/revision目录和常规工具说明对相关臂一致。普通检索的实现若尚未可用，先实现一个共享路径，不只给候选更强后端。

每条轨迹保留所选ID、实际交付正文/版本、继续READ、最终答案与全部费用。一个非预期ID若确实包含必要事实，不仅因ID不匹配判为缺失；A选中不等于材料真正进入HTTP，更不等于模型因果采用。

### 评价与判据

主看原任务或独立诊断rubric的答案/行动正确、必要事实实际呈现和总调用成本。empty A若随后依靠合法原文完成，按真实路径计；不能把“没用State”直接判错。超过容量需记录实际截取和缺失，不能默默删掉难材料。

> Continue：在同信息普通query或同State增强之上出现可解释收益。Pivot：增强查询已持平，则取消独立A调用，保留简单读取。小bank全读足够仅说明当前任务条件，不证明所有规模无效；不以两个前缀宣布显著性。

## 9. N3 / X4：固定前态，测更新U而非读集合复用

WP4准备的前态包含handout、field、welcome三个State。第一前缀的新观察改变field数量与目的地，而当前回答仍针对handout；第二前缀引入新的accessibility contact，当前任务不变。第二项为构造新事项，不伪装自然连续轨迹。[R6]

| 实验臂 | 操作合同 |
| --- | --- |
| U0 全候选 | 维护器可见全部当前State，CREATE仍可用。 |
| U1 独立更新U | 根据真实新观察与目录选需核对对象，不以当前query限制更新。 |
| U2 U=A | 使用本臂真实A结果及其成本；不能把正确读mask手工注入。 |
| U3 oracle U | 独立人工/离线标注的诊断上限；明确提供的额外信息，不能列为主方法成绩。 |

### 共享能力与冻结

两个前缀与四条件形成8条维护诊断，不等于8个独立样本。保持相同前态、事项粒度、来源身份、writer policy、时点、模型和普通整体维护合同。沿C4决定默认不用新patch配方；所有臂保留一样的严格CRUD和来源权限。U只限制需要核对的旧对象集合，不限制新事项创建。

若实际A与U相同，原样报告，不强迫两种集合不同。对全新事项正确结果可以是空U+CREATE；只读任务并不意味着后台真实新约定无需保存。Oracle mask来自独立诊断标注，不从运行中的评分rubric读取或传给其他臂。

### 联合验收

同时检查必要变化、无关旧事实保持、误改、重复CREATE、来源关系、真实提交与剩余pending。拒绝全部操作不是保持成功；只把State改正确却让ordinary损坏，也不能被全局“完成”标签掩盖。

固定前态的单次提案属于维护诊断，不冒充完整Host任务。若比较拒绝后修复，另冻同等继续读取/修复机会和总预算；不要看到某臂失败后只给它补一次调用。

> Continue：U减少无关重写或维护负担且不漏必要变化。Pivot：all或U=A已足够，则不保留独立U生成阶段。若oracle也无法改善，先看维护器选择/表达与记录粒度，不继续训练selector。

## 10. N4：有限交付版本反馈——独立且可选

当前只是WP4中的有界设计，未实现验收。本机制只记录哪些State版本实际进入Host请求或成功READ；不追踪普通memory或全部原始历史，不建立全库依赖图。[R6]

### 建议的最小语义

| 事件 | 反馈行为 | 边界 |
| --- | --- | --- |
| A选中但没交付 | 不登记已交付版本。 | 选择不等于看到。 |
| UPDATE / DELETE | 标记相关已交付引用changed/missing。 | 失效提醒不证明新解释正确。 |
| CREATE | 标记inventory_changed，旧选择可重新考虑。 | 不是自动发现反证；无关CREATE会有保守提醒。 |
| NO_CHANGE / 拒绝 | 不制造对象已变的反馈。 | 基于实际提交，不基于模型声称。 |
| 恢复不明/上限/元数据失败 | coverage保持unknown，真实已提交变化保留。 | 不为简化把unknown改unchanged。 |

只复用当前scope/meta的有界线程/回合记录。两臂共同呈现ID/revision，不能让反馈臂独享对象定位能力。复用现有观察/回执，优先少量函数，不新增常驻服务或“使用过”事实库。

### 必须保留的turn_end语义

回合开始的旧快照正文按原协议保留；提醒只作为旁边状态，不能悄悄重抓当前正文。显式READ可以取得新版本，旧快照也可能仍在transcript。较新READ不证明旧版本被放弃；重新显示旧快照不能清掉失效标记。[R6]

### 验证及开关规则

先做交付后UPDATE、DELETE后READ、空A后CREATE、无关CREATE/NO_CHANGE四组窄检查，外加一次恢复和一次超限unknown。若这些机械合同不成立，不运行模型对比。模型提醒实验只在固定已发生的UPDATE/CREATE后续接，开/关共享候选和材料；费用另记。

> N4不作为X3固定bank和X4更新选择的前置增强。选择实验先使用同一反馈设置；提醒收益不得计为U维护收益。若提醒只增加回看而无任务价值，关闭而不是继续增加“反思”步骤。

## 11. N5 / X5：用连续ReAct检验真正可用性

目标是补齐WP3长期写入责任、X5/G3/C6和WP7的证据链，不是把C3b两次维护或C4四个提案扩大命名为长期任务成功。现有11消息X5草案仍未冻结、未实现，不按“已有计划”自动执行。[R1][R7]

### 最小连续任务单元

| 阶段 | 要观察的行为 |
| --- | --- |
| 形成与首次复用 | 真实长期约定进入对应owner；下一任务无需用户重复背景。 |
| 局部变化与任务外更新 | 改该改的事项；当前未读取的真实新事项仍能保存。 |
| 临时要求与owner隔离 | 临时覆盖不变成永久默认；不同owner不串写、串读。 |
| 实际业务与部分失败 | 真实工具/SQLite副作用；错误动作按真实结果计，真实ID保留。 |
| 恢复与再次复用 | 若出现或定向注入中断，保留已发生动作；不重做未知副作用。 |
| 有授权的退出/遗忘 | 使用原合同区分撤链接、退役与清理；不扩展全链物理删除保证。 |

优先使用已支持原生任务的完整单元；无法覆盖的owner/临时要求/遗忘需求另列开发诊断，明确哪些是构造请求。不能为了凑覆盖改写原benchmark输入却沿用原生成绩。

### 方法与运行

第一轮只选一个简洁基线和一个通过N2/N3筛选的最小候选。host_both与overlap仍是职责选项，不是预定胜者；若同时比较writer与selector，应拆批或做明确因子设计，避免差异全绑在同一候选。短历史允许完整合法上下文时，保留其强参照。

各臂同初始世界、合法历史、工具能力与恢复保障。之后动作可自然分叉，不把候选产生的工具结果强行注入基线。任务不要求固定工具顺序；用户未要求记忆时允许零写入，但明确长期变化不能漏记。业务完成、Host完成、维护合同完成、各库正文正确分别报告。

> 验收：同一冻结版本连续运行到预定终点；每次调用有作用或可解释失败；已执行业务不会为修记忆而重复；必要变化进入后续行动；全部形成/维护/重读/恢复成本计入。单条失败不终止全研究，但停止无诊断地重试同题直到通过。

## 12. 可用性边界：少做确定性搬运，不替模型猜答案

【建议】以“程序处理执行事实，Host处理语义选择”为职责边界。现有共享writer与严格工具已经减少两套实现漂移；不再因为一次语义失败重建Agent runtime。[R1][R3][R9]

| 场景 | 应怎样继续 | 不能宣称什么 |
| --- | --- | --- |
| 查不到记忆但当前输入足够 | 直接完成任务，记录实际没有命中。 | 不能断言用户从来没有历史。 |
| UPDATE被拒而新事实可见 | 当前任务可使用合法新输入；明确持久维护未完成。 | 不能声称“已经长期记住”。 |
| 业务成功、记忆未修完 | 保留真实业务回执，只恢复未完成维护。 | 不能回滚数据库后重做业务来伪造干净成功。 |
| 普通memory与State暂不一致 | 返回具体对象状态和实际缺口，必要时READ。 | 不能因为State正确就自动覆盖另一库或判整体完成。 |
| 来源可以读但没绑到记录 | 可作为本次新依据；撤回时检查当前链接。 | 可见不等于已绑定，继承不等于本轮重新审阅。 |
| 精确参数已有真实身份 | 原样交付可引用身份，保留原工具合同。 | 不得自动词形修正或将生成标题当实际key。 |

### 最小业务日志与恢复

沿用已有BusinessActionJournal、ToolNode和应用世界。在冻结的合成实验世界中，通过原工具校验的提案按原合同执行和记分，不为候选自动纠正；实际业务始终受授权与参数约束。工具成功不证明符合用户意图；模拟业务SQLite写入不等于外部物流履约或Product验收。[R5]

### 不提前搭建全量语义系统

不引入事实真假关键词、总是优先State的仲裁规则、按文本去重事件、全库图、第二审核模型、无限反思或隐藏fallback。源身份、owner、权限、实际提交和已发生副作用仍须保留。可用性优先不是放宽错误输入为成功，而是把失败影响限制在真实范围。

### 新增运行采用实际分段与复用口径

```text
C_lifecycle(R) = C_form + C_maint + sum(C_use, 1..R) + C_recovery
C_amortized(R) = C_lifecycle(R) / R
```

实际账单先按provider request ID去重。Host/U/maint/A按真实请求互斥归类：同次请求承担多个逻辑角色只记一次。准备embedding、失败、拒绝后修复、空维护和真实重读全部计入；Judge属评估开销另列。共享seed或缓存可单列独立部署估计，但不重复加进已付总账。

## 15. Go / Pivot / Stop：用证据裁剪方法

| 阶段 | 继续条件 | 转向或停止条件 |
| --- | --- | --- |
| G1 运行准备 | N0身份明确，受影响检查通过，C5变化已审查。 | WIP身份不明、输入越界或评分泄漏：停止该批运行并修复。 |
| G2 选择机制 | N2/N3至少解决一个简单对照未解决的缺口，或等质明显减负。 | 普通query/全读/all足够：删掉独立selector，不硬凑成功。 |
| 反馈子门槛 | N4机械反馈准确，且模型续接更可靠/更省。 | 只增加提醒和重读：维持关闭。 |
| G3 连续任务 | 同版本全流程可完成；必要变化保留且用于后续行动，费用完整。 | 单步收益被维护成本抵消：收缩接口，不用单步图表掩盖。 |
| G4 独立确认 | 新任务族与第二模型出现同方向或清楚边界。 | 只在暴露前缀或特定表达成立：不能认领通用新方法。 |

### 何时否定哪一个假设

标题-only修复与本轮patch默认收益主张已经Pivot，保留接口不继续变体。[R4][R5] A/U独立收益尚未测，不能提前宣判无效；但oracle选择也无收益时，应优先检查维护/消费瓶颈或任务覆盖，而非追加selector训练。

host_both是便宜的候选起点，不是批准为长期默认。若其未来一致性或漏维护更差，应保留overlap或更简单底座。若State始终不能胜过强完整历史/普通记忆，停止“当前State方法优越”的主张，不否定仓库的工程价值。

### 失败后的动作

一次失败先定位源事件→提案→提交→材料→业务→回答中的首断点；确定程序缺陷单独修复并冻结新身份。只有预先说明的修复对照才新增调用，不轮换样本、偷偷改rubric或只保留成功重试。继续与否基于证据和成本，不使用“一次失败立刻终止所有开发”的机械规则。

## 17. 回到论文目标：一个可证伪命题，而非系统清单

> 候选scientific claim：在同等合法信息和CRUD能力下，按当前任务选择读取A、按真实新观察选择更新U，能在特定持续任务条件中减少无关维护与取材，而不损害必要适应、有效信息保持和后续行动。此命题尚未得到独立证据支持。

本轮未重新检索前沿论文，因此本规划不新增“首次”“SOTA”或近期工作缺失能力的断言。统一CRUD、局部patch、版本反馈和工程日志分别存在并不自动构成新算法；创新选择要由N2/N3/N5的受控结果决定。

| 主张 | 最低证据 | 不能替代的证据 |
| --- | --- | --- |
| A有独立作用 | 同bank、强普通query与同State增强、相同实际预算。 | 各自建库的总分。 |
| U有独立作用 | 固定前态all/U/U=A/oracle，含当前任务外变化和CREATE。 | “更新次数变少”。 |
| 形成可解释边界 | 任务规模/变化密度/复用频率有依据的分组；质量与成本一起报告。 | 一个空维护前缀节省。 |
| 真实Agent可用 | 完整任务世界与后续复用；误用、owner、恢复和费用。 | Store写入成功或某次工具返回success。 |
| 可投稿泛化 | 冻结配置后的留出任务族，相关强外部对照，条件触发后第二模型。 | 换seed仍复用同模板却称新领域。 |

若只有公共接口/职责表达产生收益，就按实际机制定位系统或实证贡献；若普通全读/更新已足够，就缩小或停止选择机制，而不是为了方法名添加训练、更多Agent或更复杂图。研究总目标保留，但论文内容由证据裁剪。
