## 1. 本轮决策

### 1.1 保留方法，先消除妨碍比较的共同实现问题

四组设计继续保留：

| 组别 | 表示 | 更新操作 | 主要比较意义 |
|---|---|---|---|
| B0 | 文本单元 | 对目标记录全量重写 | 普通文本维护对照 |
| B1 | 与 B0 相同的文本表示规则 | replace／insert／delete | 文本局部编辑的作用 |
| B2 | 内容、条件及适用关系 | 对目标记录全量重写 | 条件表示的作用 |
| M | 与 B2 相同的条件表示规则 | replace／append／override／retract | 同表示下条件化局部算子的作用 |

“共同实现”指共同来源、时间规则、基础检索、持久化、预算原则和 Reader，**不要求四组看到包含全部无效动作的同一 schema**。各组应获得一个合理、可执行的接口。[S3][S6]

### 1.2 研究假设不变，但分开三个层次

- **可用性假设：**去除重复输入、缩小动作目录、使用局部短引用，可以使真实输入更稳定地被处理。它属于共同工程改善，不是 M 的独占算法贡献。
- **方法假设：**在共同接口可用之后，局部编辑比整记录重写更少损坏未改语义；条件化局部编辑还能改善例外和撤销的维护。
- **应用假设：**改善后的记忆能支持更好的自然 QA 与工具任务，不只是内部状态或评分格式更漂亮。

未开源或发表状态未核实的论文保留为相关工作，不作为必须复现的阻断项；是否重叠看具体计算机制，而非名称。创新可以来自表示与编辑算子的有效组合，但须通过对应对照解释其作用。

### 1.3 保留已经完成的工作

普通 ID／不可变版本迁移、CAS、所有权隔离、真实回执、历史、遗忘、partial／UNKNOWN 恢复和两个业务工作流继续复用。P1 不重新做一遍；E0 已有真实预测和评分，不重新包装成尚未接通。[S1][S2]

v13.4 的 Simplify 仍然有效：它退出的是当时未建立重复机制的复杂关系消歧选源分支，不是否定条件化局部编辑。T1–T3 不恢复。[U1]

### 2.2 已确认事实与待验证原因

## 3. 对当前运行的处理：不热改、不拼接，也不为凑齐表格盲目扩大

本文不自动暂停运行，也不默认撤销原计划。

**已完成 B0/B1：**原始输出、评分、失败和费用永久作为 v1 结果保留。

**若 B2/M 仍在运行：**继续原计划时只完成原 v1，不在中途修改输入、schema、提示或评分。它最终回答的是“v1 整体实现表现如何”，不自动构成干净的算子归因。

**建议的计划调整：**若实际运行仍反复出现同类输入／接口故障，可在明确执行该调整后，于会话边界结束 v1，记录实到进度及未运行范围，然后进入 v2。这个决定依据已暴露的共同实现缺陷，不依据 M 输赢；不删除已完成结果，也不伪造四组齐全。

v2 使用独立实验根和现有连续账本；不往 v1 的语义库继续写，也不与其争用同一个串行模型执行通道。已有原文可按许可与只读方式复用，生成后的状态不跨组复用为主实验初始状态。

**原计划差异要明确登记：**v1 结束方式、v2 接口变化、是否提供额外旧来源正文、输出评分适配变化。用一页变更说明即可，不扩展为新审批体系。

## 4. R0：先回收已有实验的信息价值

### 4.1 输入组成分析，不调用模型

复用 `delivery.json`、实际 request 和 before/after 状态，按现有 tokenizer 记录：

- 总输入大小，以及新来源、旧文本、结构、证据表、schema 的分段大小。
- 单元数、关系数、检索记录数、最大单条记录大小和首次容量失败位置。
- 重复的正文／结构文本及重复来源元数据；用普通结构比较或直接读取，不生成摘要指纹。
- 原始输入已准备、已发送、有响应和已完成维护分别占多少。

整体请求大小以完整渲染后的 token 数为准。分段计数用于解释，不能假定各段相加必然精确等于完整模板的计数。

比较随会话推进的增长情况。没有实际轨迹支持时，不声称“局部编辑必然单调增长”。

### 4.2 拒绝提案分类

从已有日志先选一个固定、覆盖不同用户和阶段的小样本，核对：

| 类别 | 需要确认的内容 |
|---|---|
| 动作不属于本组 | schema 是否展示了该动作，模型是否按其结构正确填入 |
| source_ref 被当 evidence_id | 是命名空间混淆还是猜造引用 |
| 历史引用未发行／不可见 | 当前材料是否实际展示过，是否已经遗忘 |
| 目标单元／记录错误 | 是否属于实际读取版本，是否存在同批重叠更新 |
| 其他 | 记录原始具体原因，不把所有问题都命名为“来源幻觉” |

不根据报告倒造原模型提案。拿不到原件时注明“无法复放”，另写的合成例必须另标身份。

### 4.3 最小交付

一张按用户／会话的可用性表，一份拒绝类型样本说明，一份输入组成图或表。复用现有 analysis 模块，不新建日志平台。

## 5. R1：把内部复杂结构从模型接口中移出去

### 5.1 每个方法只展示自己的动作

对模型的公共目录拆成四个薄适配，内部仍可复用现有执行器：

| 接口 | 允许的输出 |
|---|---|
| B0 | create、rewrite、no_change；仅文本单元 |
| B1 | create、edit、no_change；edit 仅 replace／insert／delete |
| B2 | create、rewrite、no_change；内容、条件、关系 |
| M | create、edit、no_change；edit 仅 replace／append／override／retract |

create 与已有记录更新也分开表达。模型不需要填写无关字段；程序填充已有记录版本和不变的服务字段。错误操作不自动转换成另一操作，更不能把 rewrite 悄悄改成 patch。

schema、提示中的操作名和示例由同一组定义产生或在普通测试中一起检查，不维护多份容易过期的动作清单。

### 5.2 结构化生成：使用现有提供方能力，不新增校验层

当前 E1 把 schema 写进提示，HTTP 只要求 `json_object`。新候选优先将各组实际 schema 交给当前部署支持的结构化输出接口。[S5]

vLLM 官方提供 JSON Schema 等结构化生成能力；实施时以本地安装版本实际支持的参数为准，不因文档更新就升级模型或服务。[S8]

先用最小正常请求验证四组、空提案、多操作和 Unicode。若当前部署不支持某种复杂 schema，就把接口简化为其支持的结构；不悄悄退回只生成 JSON，再宣称与受约束模式相同。

结构化输出约束的是可执行结构，不证明事实正确。主比较的每组都应有合理接口，而非强迫输出相同长度或无效动作。

### 5.3 模型使用短引用，程序保留普通持久 ID

示意：

```json
{
  "new_evidence": [
    {"id": "e1", "role": "user", "date": "2030-04-02", "text": "次数改成每周三次，其他不变。"}
  ],
  "records": [
    {
      "id": "r1",
      "units": [
        {"id": "u1", "role": "content", "text": "试运行计划每周两次", "support": ["h1"]},
        {"id": "u2", "role": "condition", "text": "开始周未确定", "support": ["h1"]}
      ],
      "relations": [{"type": "modifies", "from": "u2", "to": "u1"}]
    }
  ],
  "prior_support": [
    {"id": "h1", "role": "user", "body_delivered": false, "use": "existing_support_only"}
  ]
}
```

这是新接口示意，不是现有 CLI 输入。日期和文本为构造例，不来自隐藏标注。

映射放在现有 attempt／delivery 记录中：`r1 → record_id 与实际读取 revision`，`u1 → unit_id`，`e1/h1 → 实际来源片段`。不生成另一份 SHA，不要求模型输出长 UUID、内容摘要和重复版本。

短引用只在其请求上下文中有效。执行器使用保存的映射完成精确解析；版本冲突仍由原 Store 提交边界处理一次。未知引用不做字符串相似匹配。

### 5.4 当前证据与旧支持不能混用

- `e#` 是本次实际交付的原文片段，可被模型选择为新变化的依据。
- `h#` 是已有记录的支持关系。未改单元可以直接保留它；仅出现元数据不能被称为再次读过原文。
- 若新解释需要重新理解旧来源，应通过共同的来源读取路径提供正文，再标记实际交付；四组享有相同规则。
- 元数据相同、引用存在，只证明引用关系，不证明新文本受语义支持。

第一轮接口对照不额外给某一组旧正文。若后续启用旧正文补读，作为明确的新共同输入条件，不将其收益算作 M 独有优势。

### 5.5 不再加防御性框架

保留一次真实的边界解析、owner／可见性、版本提交与业务权限处理；删除同一份内部数据在多层反复证明相同事实的代码。优先让结构可生成、引用可选择，而非增加拒绝分支。

不增加投票、常驻 review、新状态真相库、自动语义“纠错”或候选审批程序。

## 6. R2：先实现等信息精简，再解决长历史可处理性

### 6.1 第一步：不改变候选池的表示精简

保持同一候选 ID、顺序、来源范围、字段文本和关系：

- 文本组给一份带单元短 ID 的文本；不再同时给整段 content 和重复的 unit.text。
- 条件组给一份结构视图；不再附加同内容的完整渲染副本。
- 支持关系通过短引用关联；源属性在表中出现一次，不在单元、关系和历史列表中重复携带。
- 与语义决策无关的内部存储路径、操作回放字段留在服务端。

这一步减少的是重复表示，不删语义证据，不做摘要，不改变单元划分。模型不再需要的审计字段移出上下文，不能因此宣称“所有字节仍全部交付”。

### 6.2 第二步：对完整请求安排工作集

新来源只有 4,096 tokens 不代表完整请求一定能容纳。准备阶段根据实际模板计算：

```text
输入 = 系统说明 + 各组 schema + 新来源 + 目标旧记录 + 必要支持信息
总需求 = 实际输入 + 输出预留 + 现有合理余量
```

优先先压缩重复表示；仍然超限时，再使用统一工作集规则：

1. 先沿自然消息／段落边界划分新来源，保持时间顺序、角色和必要相邻条件。
2. 检索只使用已发生的新消息，不使用参考更新、未来问题或 gold。
3. 相关旧记录按同一检索规则排序，在实际容量内形成可处理工作集。
4. 需要多批目标时，显式安排未处理目标及必要上下文；重复来源输入记账，不把它当新增事实。
5. 涉及同一记录的依赖更新顺序执行，后续以真实最新记录为输入；不在同一旧版本上盲目并发提交。

当前会话的已计划子批次应在该会话评价和下一会话摄入之前完成或明确记为未处理。不能收到后续事实后再回填先前状态，并把它当作当时已经正确形成的记忆。

优先让“一件可独立维护的事项”成为合理记录，不让一个用户的全部经历堆到单条记录。但初始拆分规则要对同表示两组保持一致，不在实验中为了救某一组静默重新组织旧库。

### 6.3 防止借容量修复改变 B0/B2 的定义

B0/B2 对选中目标记录仍生成完整新表示；不能把未显示的正文自动拼回去，却继续叫全量重写。

如果一条目标记录本身超过可处理容量：先改共同初始事项划分，并在新运行重建四组；已经运行的记录不事后重拆补分。若仍无法处理，如实记该事项未完成，并保留其他独立事项的正常执行。

不同方法自己的记忆状态大小可以不同；共同的是容量规则与信息权限，不强求主实验每次候选文本相同。相同 before 状态的接口诊断另列，不能代替各组自己演化的完整历史。

### 6.4 HTTP 前失败不是“已消费新事实”

改掉“容量未发送也永久消耗来源机会”的默认路径：

| 情况 | v2 行为 |
|---|---|
| 准备后发现未发送且超限 | 重新安排本次工作集，不产生模型重试或费用；确实无法安排则记录未处理 |
| 已发送，已收到完整响应，选择 no_change | 记为模型明确不维护；仍需评价是否遗漏重要信息 |
| 已发送但输出截断 | 保留失败，不能从半截 JSON 提交；进入已声明的显式恢复路径 |
| 模型调用结果未知 | 不冒充没有发生，也不静默再调；使用原请求状态报告未确认 |
| 数据库已提交，回答未完成 | 保留提交，恢复回答；不重做写入或业务 |
| 业务效果未知 | 继续现有实时发现与 journal 恢复，不盲重放 mutation |

主四组首次比较不新增语义重提。真实功能路径若允许用户触发后续恢复，应保留首次结果与恢复结果两列，不能择优报告。

### 6.5 必须留意跨边界语义

拆分不能丢掉“除了……”或其被限定的主句。遇到跨段约束可显式重叠交付边界内容，重复只算一次来源事实；按实际调用计算成本。

不同工作集发生多次创建的风险要由正常事项检索与真实已提交状态处理，不能靠 benchmark 的实体名称白名单。工程目标是正常可用，不是承诺自动理解任意跨段语义。

## 7. R3：完成条件化局部编辑，而不是继续堆提示

### 7.1 保留四组方法差异，先观察真实编辑粒度

`replace` 当前替换整个单元。若一个单元混合频率、时间、否定和多个事项，局部操作仍可能改坏整段。[S4]

第一步统计单元字符／token 长度、关系数、实际修改比例，以及删除或新增了哪些限定。不要直接把 unit 数变多当作改善。

第二步才在开发数据上尝试共同事项划分：能独立变化的内容分开，必要的限定保持关系；对难拆或关系不明确的内容保留完整语义单元。禁止为了得到指定答案按 benchmark gold 拆单元。

同一表示的两个组使用相同形成提示与划分规则：B0/B1 一致，B2/M 一致。随后各组自然演化，不互相复制优化后的状态。

### 7.2 三类支持关系分开

| 内容变化 | 保存规则 |
|---|---|
| 完全未编辑的单元／关系 | 原文与其仍可见的支持原样保留，不要求模型重抄 |
| 修改了命题，但保留其部分旧条件 | 新变化选择新证据；保留的条件仍关联旧支持，不能只有新数字的来源 |
| 新建局部覆盖／条件连接 | 对覆盖范围和新增关系提供依据；旧条件存在不等于当然适用于新对象 |

记录级 `source_refs` 可以继续用于历史导航，但它不是“所有子句都被全部来源支持”的证明。撤销见证可以留在操作历史；失效单元退出当前事实视图，历史仍可查。[S3][S4]

新接口优先让模型选择 `keep_support` 或已交付证据的短引用，程序解析实际片段。它表达模型的支持选择，不是新的语义认证层。

### 7.3 用同一条构造历史验证算子含义

以下是开发行为例，不是 HaluMem 原生题：

```text
初始：项目 P 的试运行每周两次，开始周未定，节假日暂停。
更正1：次数改为每周三次，其他不变。
更正2：夜班每周四次，白班照旧。
更正3：从下周一开始，节假日也照常。
更正4：取消夜班特殊频率，夜班恢复一般安排。
```

| 时点 | 应实现的变化 | 必须同时保留或释放的语义 |
|---|---|---|
| 更正1 | 2→3 | 项目范围、试运行、未定开始周、节假日暂停不丢 |
| 更正2 | 夜班局部覆盖为4 | 白班仍为3；适用的共同条件保留 |
| 更正3 | 明确开始时间、取消节假日例外 | 不误改频率；不把所有旧条件机械锁死 |
| 更正4 | 撤销夜班覆盖 | 当前夜班恢复一般安排，历史四次仍可追溯 |

撤销局部例外不等于撤销一般规则；取消一种偏好也不自动表示喜欢其反面。

### 7.4 单层 override 是当前声明范围，不扩写为普遍能力

第一版继续使用已实现的一层覆盖。嵌套或相互重叠的例外无法明确表达时，保留原文与不确定性、返回有限回答；不静默展平为全局替换。

模型在普通文本条件中处理领域语义，执行器只应用选中的结构操作。没有目标证据时不新增领域规则；不用项目名、RFC号或故障标签路由操作。

只有实际数据反复出现单层无法表达的正常任务，再单独设计更一般关系。不要为“泛化”预先建设任意深度规则引擎。

### 7.5 方法目标与反证

目标是同时提高新要求完成、正确撤销和未改语义保持，最终影响实际问答或行动。

若普通 B1 与 M 同样好，接受 B1；若 B2 已达到 M 的结果，把贡献定位在条件表示，不把全效应归因于局部算子；若收益只来自共同接口修复，就作为功能改进交付。

这不是要求失败后停止所有研究，而是把下一项方法改进建立在真实剩余错误上。

## 8. R4：三种评价对象，三张结果表

### 8.1 兼容官方输入，但不混淆其含义

当前官方提取输出可以包含更新后完整记录及接受的 no_change。某些空检索更新会进入 formation 分母；所以 B0/B1 的 formation 分母不同。原官方结果保留，不追溯改写。[S2][S6]

v2 为每次维护同时保存：

| 输出视图 | 内容 | 用途 |
|---|---|---|
| `official_extracted_compat` | 按原适配规则构造的作者 scorer 输入 | 与 v1 的官方口径并列，明确含义与限制 |
| `delta_view` | 实际 create／replace／append 的新正文、显式撤销和关系变化；no_change 单列 | 本次变化是否有来源、是否落实请求 |
| `state_after` | 实际提交后的完整当前记录，含必要历史链接 | 合法旧内容是否保留，当前冲突与范围是否正确 |

`delta_view` 优先从实际操作和状态差异得到，不增加一个模型“总结本次变化”来制造新的评价对象。关系变动不能只输出孤立数值，应保留被修改命题的必要上下文。

主公开表继续使用作者任务与评分规则。delta／状态评价是明确命名的补充协议，不把自定义高分冒称原生 benchmark 成绩。

### 8.2 HaluMem 的更新诊断与自然 QA 分开

作者参考更新内容只在维护结束后用于声明的检索诊断。它不能进入 Writer、改变候选更新目标、写回记忆、改变后续可检索状态，或生成会影响后续维护的访问优先级。[S6]

每次更新同时报告：全部机会、有效判定、空检索、缺失旧参考与 Judge 不可用。空检索不消失在分母里，也不自动都记为“幻觉”。

形成分母另增加一份按数据元信息预先确定的固定类别计数，说明本次测的是初次事实、更新还是其他。该补充计数不覆盖官方动态分母。

### 8.3 旧事实只能根据实际旧支持判断

完整状态评价使用该组实际 before／after、新对话和 before 实际引用的旧来源。旧来源也缺失时标记支持未知，不默认旧状态正确；也不能只看本次会话就把真实旧事实判为幻觉。

官方参考与角色归因存在分歧时，保留作者得分和来源忠实性两列。源材料不支持用户明确说过的数字，不能写成“用户已确认”；不能为提高 MiLAi 得分修改 gold。[S7]

### 8.4 别让大记录产生天然的评分劣势或优势

记录级准确率容易受记录粒度影响：一条含十个事实的记录有一个错误，与十条小记录中一条错误，不是相同计数。

保留作者指标，同时在固定原生机制切片中按实际命题与条件评价。不得为获高分把同一事实重复拆成多条；也不能因整记录重写输出更多文本，就把重复旧内容当作更多成功形成。

### 8.5 同家族评价保持透明

只用现有 Qwen3.6 家族。Writer、Reader、Judge 的角色、提示和实际输出分别保存，Judge 不独立。固定一小批通过、失败和分歧样本进行人工复核，不只复核 MiLAi 的失败。

运行时的支持核对与评价 Judge 分开；主四组不额外增加 reviewer。不同语言的同义变体不当作独立模型家族或独立原始历史。

## 9. R5 实验安排：先修接口，再跑完整四组

原有 E0–E5 名称及交付任务保留。本文使用 `R0–R5` 标识工作包、`v1/v2` 标识实现条件，不重新命名旧结果为新成功。

### 9.1 阶段 A：接口与容量诊断

先在已曝光开发材料中固定不超过 24 个调用前样本：6 个容量失败、6 个动作类型错误、6 个来源选择错误、6 个正常控制。尽量覆盖四用户与不同历史长度；同一样本重复出现时按唯一来源统计，不足不凑数。

容量样本先做零模型对照：原输入与紧凑输入在相同实际状态下渲染和计数。去重和短引用映射不改变事实文本、关系或候选次序。

动作和引用用少量真实 Writer 测试新旧接口。样本可按对应方法测试，不必每项都做四组笛卡尔积；新接口真实支持的 M/B2 再加入少量新形成和更新的正常请求。

**推进要求：**构造可执行且可容纳的正常请求，不再系统性触发跨组动作或引用命名空间错误。所有新来源仍有实际处理路径。这里的通过是限定接口能力，不宣称一般语义正确。

### 9.2 阶段 B：共同修复的可用性 pilot

使用预先固定的四用户历史前缀，覆盖开始形成、开始更新和首次明显状态增长。必须从各组自己的空库顺序形成，不把 v1 某组的好状态当作所有方法的理想初始库。

比较次序：

| 条件 | 改动 | 目的 |
|---|---|---|
| I0 | v1 原输出／原调用前材料 | 保留首次实现证据 |
| I1 | 仅各组 schema＋短引用 | 检查动作与来源接口 |
| I2 | 加等信息去重视图 | 检查输入构造问题 |
| I3（确有需要才做） | 加共同容量工作集／明确旧正文补读 | 检查长历史可用性 |

不要求把每个 I 条件都跑完整 277 会话。已有记录可做离线诊断；真实模型只做能区分原因的小比较。I3 改变候选选择或信息交付，应单列，不与 I2 的纯表示精简混称。

### 9.3 阶段 C：v2 的 E1 四组完整开发比较

接口可用后，固定一个共同输入版本，再执行四个用户全部 277 会话：B0、B1、B2、M 各自从空库开始，按相同公开日期顺序摄入，沿用原问题与作者评分规则。

同一组中不热改提示、接口、预算、单元划分和 scorer。算法错误、写入遗漏、截断和未处理来源均留在完整分母。

核心配对：B0→B1、B0→B2、B2→M、B1→M。B2/M 共享表示与渲染；B0/B1 共享文本形成规则。

“相同源信息”指相同合法输入与可用规则，不代表组间演化后的记忆和检索结果必然一致。接口诊断中的相同 before 比较单独报告，不能据此替代端到端结果。

### 9.4 阶段 D：E2 原生状态与 E4 连续漂移

先复用已审查的 32 个机会，不再次按方法结果挑选。它们来自四用户、十二会话，不是 32 个独立历史。[S7]

按每组真实状态报告：

- 初始目标是否存在；不存在的原因是否为之前形成失败。
- 本次真正变化有没有完成。
- 有依据且仍适用的非目标内容是否被损坏。
- 取消是否生效，旧值是否仍被当作当前事实。
- 后续自然问题是否答对且没有无依据强化。

NeverWrite 和 RetainAll 从同组实际 before 状态构建，是退化诊断，不获得 gold 初始化。缺乏有效旧事实时不填“损坏率0”。

连续漂移复用全部实际会话的轨迹。累计损坏事件与独特受损事实分开；无法可靠关联事实身份时，不猜造唯一受损事实数。

### 9.5 阶段 E：受控机制补充，而非伪造原生题

已准备的 3 个故事簇、10 个变体历史继续作为受控补充，明确覆盖原生短名单没有的 scoped override、全局改动影响局部例外、撤销和历史更正。[S6]

按既有协议，这组受控确认在最终候选与共同 Writer 固定后运行，不用其结果继续挑选候选。R3 的构造说明或为接口开发另写的例子属于开发材料；若与确认故事实质相同，就登记其暴露，不能再把它称作未用于设计的新确认。

故事只向 Writer 提供发生的对话、角色和日期，问题与要求留给评估。每个变体形成自己的记忆；中英文改写、轻微措辞变化和独立顺序交换共享原故事簇。

这部分能解释算子是否按预期工作，不能证明该机制在自然用户中的发生率。若只有受控补充有优势，论文也应明确适用范围。

### 9.6 阶段 F：E3 保留来源与外部比较

在方法与实际配置固定之后，再访问 16 个保留 HaluMem 用户。主确认至少包括 B1、M；若主张局部算子的独立收益，还必须包含 B2。若主张超过普通重写，再保留 B0，而非只挑最有利对手。

保留用户结果出来后不用于继续调参。出现新失败可记录并形成后续独立开发批次，不覆盖此次确认。

LongMemEval 使用已确定的 28 问与 1,354 个历史会话出现，原 10 问完整回答审查保持。它属于描述性外部子集，不称500题全量或独立未见测试。[S6]

共用 filler 会话与共用答案证据不是同一依赖。必要时新增基于既有元信息的依赖敏感性说明，但不能凭新分组抹去此前实际内容暴露，也不能把一个已暴露子集事后改名为独立盲测。

外部组继续为普通原文 RAG、滚动摘要、作者 A-MEM 适配、最终 MiLAi 候选。当前 A-MEM 是计账回调适配，不称未修改的云端原论文复现；保持原生扩展和实际送达材料的区别。[S6]

### 9.7 阶段 G：E5 同版功能回归

最终候选通过正常 Host 完成已准备的135个旧案例，其192条用户消息等计量沿原输入保留；旧兼容性检查不计为真实模型通过。[S2]

另在候选固定后创建实质不同的新功能故事，覆盖：保存、更正、范围撤销、当前／历史、只读、遗忘、partial 和中断续办。消息数在执行前记录，不按结果增删。

v7 恢复原保存请求、文稿审批绑定实际版本、已成功业务不重放、当前禁止优先均为现有能力回归，不另建恢复平台。

功能版本可以采用最终表现更可靠的 B1，而不一定是 M。创新结论不足不妨碍交付有效功能；方法得分改善也不自动代表 Product 可发布。

## 10. 指标与结论：可用性、语义和任务效用并列

| 指标层 | 必须报告 | 不允许的替代 |
|---|---|---|
| 实际可用性 | 原始输入总量、已发送／有响应比例、容量失败、格式／引用／动作拒绝、未处理事项 | 用“会话complete”冒充形成成功 |
| 变化正确性 | 新要求完成、合法取消、无依据新增、非目标损坏、支持缺失 | 用操作接受率或写入数冒充正确性 |
| 持久终态 | 当前与历史、当前冲突、支持继承、遗忘后不可见 | 用最后一句答对覆盖错误记忆 |
| 任务结果 | 作者QA、完整回答、真实工具结果、多余提案与实际副作用 | 把guard挡住的错误算模型正确选择 |
| 使用成本 | Writer、Reader、Judge、重读／恢复、失败与未确认调用 | 因少执行任务而宣称更高效 |

主表包含所有预定机会，成功子集仅作诊断。不要只比较各方法都碰巧成功的交集，再称整体可靠性改善。

按用户配对，四个开发用户的区间仅描述性；大量问题和10,000次重采样不会创造新的用户。16个保留用户也按用户报告，是否能支持某个差异以实际区间与设计为准，不承诺预定显著性。

来源审核与官方标签有分歧时分列结果。未评分、缺旧状态和支持未知不是零错误；失败与尚未运行也不是同一状态。

**本阶段优先通过标准：**没有新的严重隔离／重复副作用回归；正常输入实际可处理；语义质量与任务效用有可解释结果。成本降低、主会论文级新颖性和跨家族确认不是本轮功能准入条件。

## 12. 简洁但有效的功能测试

优先使用现有测试框架增加以下行为，不要求新增完整测试平台：

| 测试族 | 代表行为 |
|---|---|
| 四组可执行接口 | 各组正常形成、更新、no_change；模型目录中没有本组不支持的动作 |
| 短引用 | 新证据、旧支持、同名不同请求、重新打开后使用原映射；不模糊猜ID |
| 输入表示 | 去重后事实文本和关系仍可获得；巨量旧记录不会使整个来源被静默跳过 |
| 处理进度 | HTTP前重新规划不产生模型费用；部分批次失败不能冒充完整维护 |
| 支持继承 | 改频率保留未知时间来源；明确取消允许撤销；旧支持不是新事实证明 |
| 覆盖语义 | 一般范围、局部例外、例外撤销、共享条件、全局更正同时影响实际目标 |
| 评分对象 | no_change不算新写入；官方、delta、完整状态独立；空检索不丢分母 |
| 正常恢复 | 保存成功而答复失败不重写；业务unknown先查；只读／遗忘边界保持 |

脚本响应／单测只证明确定性代码路径；真实模型的小型请求和完整公共历史另外报告，不把测试数量累计成方法样本量。

## 15. 创新、泛化与取舍

### 15.1 本轮明确支持的研究主张

**研究问题：**连续更正时，条件化局部编辑是否在落实新要求的同时，减少未改语义的附带损坏，并正确处理局部例外与撤销？

**可证伪预测：**共同接口可用之后，M在相同表示下应比B2更少损坏无关内容；在范围化任务上应比B1更准确处理内外范围，且不能靠拒绝或不更新取得表面优势。

不把短引用、schema分组或删重复元数据作为新记忆算法，它们是公平的共同可用性基础。若收益仅来自这些改进，仍然交付功能结果，但研究主张相应收缩。

### 15.2 泛化安排

核心编辑器不识别用户姓名、数据集ID、RFC编号、预订或文稿专用名词。领域信息来自普通原文与应用适配，不来自实验标签。

先验证不同用户和连续变化；再通过已有中英改写、独立事项顺序交换与两工作流检查。变体共享来源簇；一个模型家族结果不称跨模型泛化。

当来源不足、重叠例外或历史纠错不可判定时，保留所知部分和不确定性。不能用“未知”回避明确的新要求，也不为保持旧状态拒绝合法撤销。

### 15.3 决策表

| 结果 | 决策 |
|---|---|
| 共同修复仍不能稳定处理输入 | 继续修接口和工作集，不扩大到保留用户 |
| B1已实现与M相同收益 | 采用B1，保留条件化研究记录，不强造M优势 |
| B2≈M且优于文本组 | 主要贡献归于条件表示，不归于局部操作 |
| M减少损坏但遗漏更多真正更新 | 处理过度保守，不宣布整体改进 |
| M只在作者受控例外上有效 | 定位为特定机制结果；公共主表照实报告 |
| 真实原生更新、保留用户及未来任务均改善 | 形成有证据支持的方法结论 |
| 新变化仅提高官方分数，却破坏来源角色或限定 | 不作为功能成功；报告协议与来源差异 |

不因一篇未开源或未正式发表的论文提前否决方法；也不隐去实质相同的公开机制。以可运行的强简单baseline和清楚的算法差异推进。
