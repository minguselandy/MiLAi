# MiLAi 规模化证据学习：开发与研究结果

**状态：本轮研究执行已关闭。两候选外部链路、确认评估、已测阶段结算与逐项核对完成；总体稳定优势未获支持，局部能力链的范围如下。**

本轮按2026-11-11 v2规划完成了可运行的执行优化、3k→10k→36k操作数据与长训练、真实反馈和自身状态对照、交付／已知证据／持续更新探索，以及固定新来源确认。主要结果是：执行效率确有改善，数据与训练规模已实质扩大；总体任务或完整成本优势尚未成立，但在一个预先抽定的新确认来源上，已观察到受控的完整动作变化、关键证据补齐和实际答案改善。方法保持通用，没有题号专用规则、在线gold或后确认调参。

## 2. 训练指标如何连接到实际任务

36k论文参考DEV在三个完整遍次为129／131／132（分母278）；MuSiQue参考面板从181/423上升，u565为341，固定最终点为318。它表明部分参考操作能力可学习，也表明更长训练未保持所有早期提升；不能用参考接受率替代Host成功。

S2反馈与继续SFT的完整参考DEV终点为110／124。冻结编码器流程保持133/278，但在64个实际DEV状态上的完整首选与S1/u101初始化全部相同，属于保留初始行为。该开关也关闭编码器dropout，不能解释成严格dropout匹配的纯参数因素实验。

成本反馈只将已有TRAIN中94个充分材料、完整受支持答案的质量平局改为观测资源方向，原输入、顺序、重放、起点和更新预算相同。成本关系排序由41/94增至75/94，131个反馈TRAIN状态中55个首选变化；实际DEV首选相对原反馈变化14/64，但没有稳定任务增益。初始34/64对32/64的表面优势，经四个差异状态全部10个分支的统一来源核对后变成33/64对33/64。原评分视图保留。这一结果说明需要分开看pair排序、完整首选、实际交付和答案，不应将评分不一致包装为改进。

I2的一个材料改善案例最终与简单全量交付得到相同包，不能据此声称学习选择的独特收益。I1修复了续跑把已知证据条件下的查询重新替换为原始查询的问题；实际129分支、预定96个主要槽位的反馈仍只有2个已知、0个方向关系，未据此启动无信息的更大同池拟合。

## 3. 固定新来源确认

96篇论文在模型与协议冻结后导出正文，每篇原顺序首个问题。其研究身份是confirmation，与本轮TRAIN来源无原ID重叠；原生数据集TRAIN标签不代表本研究训练暴露，也不证明隔离了模型预训练。四个候选、主／次比较、Host、预算、32次额外读出和8个来源复核位置均提前固定。

## 4. 一条范围明确的局部能力链

预定复核位置12、论文1607.03542的问题是“使用哪个知识库”。S3两臂共有S2/u51初始化、23个有标签TRAIN来源的每族数量、108条重放和相同更新／曝光预算；区别是108个自身到达的不同参考状态，对照为87个旧S1状态及21次明确重复。

1. 两臂先执行相同SEARCH、READ 2；直到下一次决策，三个实际模型输入和完整合法菜单逐项相同。
2. 自身状态模型选择READ 8，旧状态模型直接HANDOFF；READ 8相对HANDOFF的logit差分别为+0.9811和−0.5736。
3. READ 8取得本研究方法段明确提到Freebase的原文，随后交付。旧状态模型只有泛泛的相关工作描述。固定上下文基线执行四次读取，也缺少该当前工作见证。
4. 自身状态和36k模型的Reader在两次预定调用中均依据该见证答对Freebase；固定基线两次无法确认本研究的KB，旧状态首次无法确定、第二次失败。

这是一条“新状态经验→完整动作变化→补齐交付→实际任务改善”的局部证据链。没有题号专用规则、在线gold或事后改模型。其泛化范围只是一个未进入本研究训练／选择的新论文来源、一个问题及两次既定读出；不证明跨seed稳定优势、总体确认胜出、预训练隔离、自主业务收益或完整成本优势。对照的数据长度和不同状态覆盖不同，不称纯loss或FLOPs实验；相同模型输入不等于整个Store内部状态逐字节相同。

证据：[完整轨迹、输入等同性、实际见证与两次答案](/data/milai-experiments/20261111-scalable-evidence/qasper-confirmation96-source12-mechanism-v2.json)。

## 5. 持续更新应用

16个来源、每来源5个连续请求的两臂适配比较已关闭。参考适配臂完整／部分／错误／失败为17／21／28／14；继续重放为22／16／23／19。来源平均完整回答差−0.0625，区间[−0.25,+0.125]，没有总体收益。两臂在31个目标事实变化位置均没有完整回答。

两臂在这些位置各有242条Source成功捕获。参考适配臂23个位置在没有记录到检索或控制器调用时已完成Host回答，另4个首次失败、4个激活控制器；重放臂为19、10、2。激活的少数位置也未成功。多数更新失败不能被描述为Jev在实际机会中拒绝REFRESH，但这不免除系统端到端失败，也不授权强制调用检索。

这些历史是构造且已暴露的TRAIN来源，不是200–500条自然独立轨迹或新确认。参考适配的一个初始状态见证改善与后续稳定复用是局部案例，不能覆盖目标更新失败。
