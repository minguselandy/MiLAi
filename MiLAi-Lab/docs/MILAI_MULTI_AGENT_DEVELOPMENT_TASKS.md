# MiLAi 多Agent开发任务卡

> 配套[全功能架构与开发总规划](MILAI_UNIFIED_MEMORY_ARCHITECTURE_AND_BUILD_PLAN.md)。这是可分发的开发任务，不表示已启动Agent或写入远端仓库。

## 0. 全员共享上下文

**目标：**完整实现Grounded Memory、Verified Object References、Semantic/Episodic Memory、Grounded Revision、Lifecycle Recovery；先形成普通Host可持续使用的功能版，最后集中测试与改进算法。

**基线：**2026-10-07本次读取PR #85头723ceca，开发代码830d23a，旧集中实验dffc232。开始实施时重新读取实际代码；不要用报告头替代实验运行身份，不修改已运行产物。

**已完成，不要重造：**共同维护recipe、普通Host接入、dense检索、条件／例外操作、来源角色／时间、提交后视图刷新、Append-only、predict／score分离。当前目标是完善语义与生命周期并补齐认知整理、激活和模拟。

**共同约束：**

- 一个逻辑MemoryService；模型与Store由调用方传入，不创建新事实库、审核Agent或模型服务。
- 原文、真实回执、owner、版本及实际业务引用保留；不使用SHA、内容指纹或逐文件摘要门禁。
- 规范接口在负责边界检查一次；内部少做重复解析与全对象比对。正常功能直接实现，避免防御性分支堆积。
- 语义泛化不依赖benchmark标签、特定人物、领域关键词或隐藏gold。自然语言解释可以未知，业务结果必须有实际来源。
- 开发期只做直接受影响的导入／类型／格式及现有检查，一个正常使用示例；不先跑四组Judge、不扩测试矩阵。
- 不以多UPDATE、多condition、多通过回执定义成功；追加式事实记忆保留为合法强对照。
- 每个Agent一个worktree／临时目录／数据库。生成服务与共享实验资源由集成者统一调度，不能擅自终止已有运行。
- 不提交私有原文、gold、HTTP、reasoning、数据库、密钥或服务配置。Git提交号可用于版本说明，不建立新的校验制度。

## 2. Agent A：Grounded Sources、Episode与有限整理

### 输入

总规划第5、7节；现有SourceEvent、来源存取、可见性与forget实现；共同维护函数；当前来源归属错误案例。

### 独占范围

拟新增`memory/episodes.py`、`methods/consolidation.py`及专用使用示例。其他来源相关文件由Integrator先明确分配，不能自行改contracts/service。

### 具体实现

- 用实际source_refs组织Episode：事件、参与者／主体、情境、时间、实际结果、可见性；不复制多份原文。
- 原文保存与语义结果分开；保留reported／inferred／observed属性及其真实来源。
- 在同一Store保存episode索引，正常查询可以从Episode回到真实来源。
- 实现有限`consolidate`：读取指定事项或未整合的实际事件，提出整理候选，调用D提供的现有维护／提交接口；无永久后台Agent。
- 明确用户更正立即处理，不要求先积累若干次；多次情境不能自动晋升永久偏好。
- 遗忘后Episode、派生索引与整理输入同步不可用；内部回放不产生新独立支持。
- 只整理用户可见事实和实际结果，不把隐藏推理链当作episodic内容。

### 正常使用示例

一条具体会议安排成为Episode；用户随后明确“以后都按这种格式”时形成语义偏好；撤销该偏好不删除会议历史；遗忘会议来源后相关访问被撤销。

### 完成标准

真实持久化、可读取、可整理、可遗忘；不是只有分类字段。可以先保留已知抽取误差，不能用Reviewer循环代替实现。

### 依赖

Integrator给基本Source/Episode字段，D给公共维护回调，B给真实语义视图。E的激活不参与来源真伪判断。

## 3. Agent B：Grounded Revision与时间／范围逻辑

### 输入

总规划第4.5、8节；现有content／condition／modifies／overrides、当前applicability投影；范围过度推导、来源归属与复合条款丢限定案例。

### 独占范围

`memory/edit_units.py`、`methods/edit_memory.py`、`methods/edit_features.py`。不改中央Host／runner，不新增常驻语义核对器。

### 具体实现

- 让独立变化的断言和必要限定保持清晰：同范围改值、局部覆盖、共同条件变化、合法撤销均复用既有操作。
- 新值或关系选择新支持；未改限定保留原支持；取消依据不必重新证明一般规则的具体值。
- 固定输出只含需要生成的内容；不让模型重复填实际ID、角色、版本和捕获时间。
- 强化实际关系的只读投影：一般规则、当前例外、共同条件、历史、未解决项。不得把整体次数分配给每个成员。
- 区分报告时间、显式事件／有效时间和版本时间；未知保持未知；晚出现但明确回溯的来源允许说明过去。
- 撤销例外不能复活已过期一般规则；不同行为范围的冲突不能直接last-write-wins。
- 保持B0/B2全量重写、B1/M局部更新的真实机制区别；不为全量组自动补它没生成的正文。

### 正常使用示例

先形成有明确逐班次适用性的通用安排，增加夜班例外，调整共同开始时间，撤销夜班例外；当前与历史均能由实际关系呈现。另给整体总量例子，确认不输出每成员同量的推断。

### 完成标准

编辑与读取共享同一语义关系；来源／时间／范围都在正常调用中使用。未解决的自然语言关系不静默变确定。

### 依赖

A提供真实来源和情景；D调用模型并传入当前来源；Integrator整合投影到普通Host与benchmark。

## 4. Agent C：Verified References、实际结果与Recovery

### 输入

总规划第6、9节；现有ObservationProfile、业务对象、journal、部分成功、W1/W2/W3恢复和遗忘路径。

### 独占范围

Integrator指定的`application/`对象、结果、journal和恢复文件。可增一个薄适配模块，但不创建第二任务平台或事实数据库。

### 具体实现

- 用实际应用lookup／回执发行VerifiedObjectRef；identity、permission、current state分开。
- 让新应用通过lookup／execute／observe／discover合同接入，不修改记忆核心。
- 结构化保存部分结果，实际已成功的步骤不被总结成失败；只有未完成步骤进入续办。
- 恢复用户完整请求项，包括实际结果保存与反馈，不仅恢复一次业务调用。
- 区分模型请求未知、语义提交未知、业务效果未知。业务未知先发现；已确认语义提案可用旧操作ID查结果；明确新语义尝试保留旧失败。
- 当前只读、取消保存、访问撤销优先于旧任务；恢复不自动继承历史写权限。
- 将业务与记忆效果分开呈现给Host，避免由模型猜测实际执行状态。

### 正常使用示例

实际预订成功而标签失败，进程重开后查真实状态，只补标签，并保存实际结果。最终明确业务完成与记忆提交情况；用户改成“只查状态”时不再执行mutation。

### 完成标准

两个既有沙箱可用同样合同；不重复效果；模型或最终答复失败不抹掉真实回执。未知有正常的显式继续路径，而不是永远停在错误状态。

### 依赖

Integrator拥有VerifiedObjectRef定义；D提供维护结果和显式resume接入；A处理来源／forget。

## 5. Agent D：共同维护、Host、检索与工作上下文

### 输入

总规划第3、5、7、9、11节；最新`edit_maintenance`、`functional_edit_memory`、`retrieval`；紧凑输入与applicability漏接修复已有代码。

### 独占范围

`methods/edit_maintenance.py`、`methods/functional_edit_memory.py`、`memory/retrieval.py`。中央runners/functional.py和benchmark入口由Integrator整合。

### 具体实现

- 两种recipe与Append-only继续共用原文、必要近期语境、实际旧状态、模型回调、提交和Reader。
- 抽取候选临时保存；候选为空不强制漏掉原文信息；候选非空也不强制写入。
- 批量候选定位与合并提供直接接口；同一目标一个修改容器。先复用现有dense，不同时引入reranker／多后端平台。
- 容量预览使用真正发送的原文、候选、旧语境与schema；不为节省输入删关键来源；一次过大按正常边界分批。
- 实际维护提交后刷新本轮当前视图；历史快照保持。把相同applicability接到Host与benchmark。
- 记录本轮已读的对象／版本／游标进展；无新增证据的循环读取转向利用已读材料或诚实说明不足。
- 复用C的正常resume，不把未提交请求永远当完成；不无限重试或重放未知业务。
- 调用E的纯激活／效用接口，但保持dense共同对照，不把可用性分数当真值。

### 正常使用示例

一条消息同时改变就业状态和健康计划；原文与候选送达，相关旧事项被定位，实际提交后立刻可查询新状态，用户追问原情况能读历史。普通Host与predict路径返回同种关系信息。

### 完成标准

不存在只在专用实验脚本能工作的关键能力；调用方只负责模型传输和资源，不复制语义维护逻辑。

### 依赖

B先交确定性编辑／投影接口；A提供来源／Episode和整理范围；C提供副作用与恢复合同。

## 6. Agent E：激活、概率效用、隔离记忆模拟

### 输入

总规划第4、10节；现有dense及统一API；认知与校准文献仅作为设计依据。

### 独占范围

拟新增`memory/activation.py`、`harness/memory_simulation.py`和少量示例。不要直接修改B／D的核心文件。

### 具体实现

- 实现可解释时间衰减和使用激活；时间单位和初始参数明确公开。
- 只根据实际反馈更新用途估计，未知不当负例；不把模型自述或一次泛化QA成功当校准标签。
- 同一来源的摘要／复述／内部回放不重复累积为新证据。使用激活与命题真实性分开。
- 置顶规则、未完成任务、可见性和业务权限不受概率排名覆盖；低激活不是删除授权。
- 模拟器支持独立owner／临时Store／虚拟时钟、普通事件输入、实际状态轨迹；评价真值与运行输入分离。
- 支持小型可组合经历：新事实、间隔、明确更正、范围例外、撤销、遗忘、沙箱中断。
- 实际经历回放通过A的consolidate执行；模拟不会向真实库写入或调用真实业务。
- 只做能运行的简单模块，不新增神经网络训练、通用脑仿真、随机噪声生成平台或自动技能Agent。

### 正常使用示例

在虚拟时间中多次取用一条记忆，观察激活变化；长时间不使用后仍能按明确问题找到它；显式遗忘后即便历史高激活也不能取回。输出轨迹而非声称模拟人脑成功。

### 完成标准

激活与效用有真实实现和观察输出；模拟调用共同功能而不是直接填gold状态；普通服务不依赖模拟器才能运行。

### 依赖

A给真实事件来源索引，D给公共检索／维护入口，Integrator给独立沙箱配置。

## 7. 并行推进与集成顺序

```text
Integrator：一页共享接口与文件所有权
        ├─ A 来源／Episode／整理 ─────────────┐
        ├─ B 修订／时间／范围 ───────────────┤
        ├─ C 对象／实际结果／Recovery ───────┤
        ├─ D 共同维护／Host／检索 ───────────┤
        └─ E 激活／效用／隔离模拟 ───────────┤
                                             ▼
                                 Integrator逐能力合流
                                             ▼
                                   一个全功能配置
                                             ▼
                            五条冒烟 → 集中predict／score
                                             ▼
                         一个主要断点／一轮改进 → 再评价
```

不要求A完成全部语义质量评价后B才开工，也不要求旧完整benchmark评分结束才允许D改源码。共享真实模型资源的顺序约束与代码开发并行性是两件事。

### 每次交接模板

```text
能力：

可执行示例：
实际做过的检查：

```

没有完成就明确说未完成；不以新建文件、stub、通过模拟回调或测试数量当作真实模型效果。

## 8. 最后集中测试，不再由每位Agent维护独立测试计划

工程合流后集成者运行统一五条冒烟，接着选择一个候选跑公开开发集。Worker按最早断点修其负责部分。正式四组、Append-only、必要消融、65／277、保留用户及外部任务集中安排，不让每个开发任务重复全部实验。

**完成开发的目标是“全部能力可用且能观察真实结果”；测试随后回答“什么机制更可靠、哪里会失败、值得保留什么”。**
