### 1.4 新开发口径

本轮“全部功能”指第5—10节列出的有限产品能力均有真实可调用路径，包括保存、组织、修订、使用、遗忘和恢复。它不指对任意自然语言都能给出确定正确结论，也不把远程身份认证、任意业务接入和分布式exactly-once列成本地Lab的隐含任务。

## 3. 总架构：一套记忆服务，两个时间尺度，三类状态

### 3.1 核心方案

**保留真实事件；按来源整理可修订语义；按时间和范围生成只读视图；通过真实对象和回执驱动行动。**

```text
用户消息／真实工具结果／合法外部文档
                 │
                 ▼
       SourceEvent：实际来源与访问范围
                 │
         ┌───────┴────────┐
         ▼                ▼
   情景记忆 Episode   当前候选变化（临时）
   原事件索引与经历          │
         │                 ▼
         │       定位相关语义事项与必要原文
         │                 │
         │                 ▼
         │       普通编辑／条件化局部编辑／追加
         │                 │
         └────────┬────────┘
                  ▼
        一个 MemoryService＋既有 Store
   来源｜情景｜语义记录｜版本｜可见性｜索引元数据
                  │
         检索＋显式时间／范围解析
                  ▼
       当前／历史／来源／例外只读视图
                  │
                  ▼
          Host 工作上下文与回答
                  │
          Verified Object Reference
                  ▼
        实际业务工具与Action Journal
                  │
          结构化实际结果＋真实回执
                  ▼
        Grounded Revision＋剩余任务恢复
```

旁路只有两条：**会话后有限整理**消费真实历史；**隔离记忆模拟器**生成沙箱经历用于后续实验。两者都不能直接制造真实业务效果。

### 3.2 三类状态，不能互相冒充

| 状态 | 存什么 | 权威范围 |
|---|---|---|
| 持久记忆 | 原文、经历、语义解释、历史、来源关系 | “系统观察／保存／解释过什么”；不保证世界真值 |
| 执行状态 | 待完成请求项、模型阶段、实际工具回执、结果确认 | “实际执行到了哪里”；不充当用户偏好或常识 |
| 工作上下文 | 本轮已交付的记录、适用关系、实际对象及缺失材料 | 本轮使用的只读视图；可重建，不是另一长期事实库 |

索引、向量缓存、激活计数可以放在同一Store的专用namespace中；它们是可重建辅助状态，不接受业务事实的独立写入。

### 3.3 数据身份延续现有代码

继续使用现有 `SourceEvent`、`VerifiedObjectRef`、`ObservationProfile`、MemoryService和操作回执，不重定义同名对象。[S4][S5]

只补有明确用途的可选语义信息：

| 语义对象 | 必要信息 | 程序／模型职责 |
|---|---|---|
| SourceEvent | 原文、来源角色、实际捕获时间、已知事件时间、owner | 程序捕获；模型不可生成来源身份 |
| Episode | 参与者／情境、相关事件、实际结果、可见性 | 事件关联可模型建议，原事件仍保留 |
| SemanticRecord | 自足断言、必要条件、实际来源、事项、版本 | 模型提出解释，程序提交版本 |
| Assertion | 陈述者、命题主体、reported／inferred／observed／uncertain、时间／情态 | 来源角色来自程序；主体和语义关系仍由模型判断 |
| Applicability | 明确适用条件、有效区间、覆盖和撤销关系 | 程序只计算已被明确表达的关系 |
| ExecutionRecord | 请求项、对象引用、阶段和实际回执 | 应用编排负责，不从自由记忆文本推定 |

不要强制每条普通事实填写一整套本体。没有明确值的字段保持未知；不要为了填schema而推测生效时间或命题主体。

### 3.4 事件与当前语义视图的关系

记作：

\[
S_t=(E_{\leq t},M_t,O_t,J_t),\qquad
V(q,t)=\operatorname{project}(E_{\leq t},M_t,q)
\]

其中E为允许保存的来源／经历，M为可修订语义记录，O为可信对象引用，J为执行记录；V是当前问题的只读投影。

这个表示只是职责描述，**不要求四套数据库或新增全量事件溯源框架**。现有记录与历史能够承载的继续使用。遗忘后的事件不可被投影或重放恢复；“append-oriented”不等于对用户遗忘请求永久不可删除。

## 4. 人脑认知、概率和逻辑怎样进入代码

### 4.1 认知启发的定位

互补学习系统研究提出快速学习具体经历与逐渐整合结构化知识的分工；ACT-R相关研究将记忆取用与练习、延迟、关联等因素联系起来。[C1][C2] 本版将其转换为软件设计假设，**不声称SQLite对应海马体，也不声称复制了人脑机制**。

| 认知启发 | MiLAi中的具体实现 | 必须避免的误用 |
|---|---|---|
| 快速经历与较慢整合 | 先保存事件和情景；明确更正立即处理；会话结束后有限整理未整合事项 | 不让用户的明确保存／更正等待“睡眠”才生效 |
| 情景与语义互补 | 一次会议限制保存为情景；跨情境规则以来源关联语义记录表达 | 一次情境不能自动晋升永久偏好 |
| 来源监控 | 区分谁说、说谁、观察还是推断；保留原文与归属 | 多次复述不能让助手推断变成用户确认 |
| 激活与遗忘 | 根据真实取用、时间衰减管理默认检索优先级与冷存储 | 少被读取不等于事实过期，更不等于允许物理删除 |
| 回放与再整合 | 在显式整理任务中重读有关原事件，提出可修订解释 | 重读一次不是新的证据；不重复业务动作 |

来源监控理论在本次核查中以书目信息／公开摘要为依据，不将其当成已经验证的Agent算法。[C3] 回放可参考优先记忆访问研究，但本版的有限整理策略属于工程设计，并未完成其神经模型复现。[C4]

### 4.2 第一版认知机制要少而完整

本轮实现三个可调用能力，而不是增加很多空模块：

1. **`consolidate`**：接受实际事项或事件范围，重读可见来源，整理语义候选，沿用同一编辑器提交；可由会话结束显式调用。
2. **`activation`**：根据真实时间和过去有效取用计算可解释激活值，支持冷／热索引管理；不参与对象权限。
3. **`simulate`**：在隔离实例中按虚拟时间生成／回放事件，观察记忆变化；任何模拟产物不混入真实用户库。

这三项工程能力都在功能版本中实现；默认服务仍可使用简单dense策略。启用认知排序或整理策略的具体参数，留给集中实验选择，不因模块可调用就宣称它们改善任务。

### 4.3 激活分数：衡量可用性，不衡量真实性

可采用如下简化启发式：

\[
a_i(t)=\log\left(\epsilon+\sum_{k\in H_i}
  \left(1+\frac{t-t_{ik}}{\tau}\right)^{-d}\right).
\]

H只计被允许记录的真实使用或来源接触；内部重放、缓存重读和同一次请求的重复页不能无限加分。\(\tau,d,\epsilon\) 是公开工程参数，不标成已拟合的人脑常数。指数或幂律版本可在集中实验中比较，第一版只实现一种。

首版排序继续以语义匹配为主；激活用于解释、冷存储选择或次级排序。时间限定、可见性和业务身份不由激活改变。长期少用但显式置顶的偏好和未完成任务不能因低激活从功能路径消失。

### 4.4 概率：分开“有用”与“真”

第一版可实现一个小型Beta-Bernoulli效用估计：

\[
\hat p_i^{\rm useful}=\frac{\alpha+s_i}{\alpha+\beta+n_i}.
\]

s为有明确反馈的有效使用次数，n为有明确正／负反馈的次数；未知、没有引用、一次偶然QA成功均不自动构成负或正标签。冷启动先验为工程参数并展示样本量。它表示在已定义反馈协议下的用途估计，**不是“这条记忆为真的概率”**。

对事实可信度，先保存支持来源、反证和未解决分歧。没有校准数据时，概率字段为空或明确标为未校准分数，不人为规定“user=0.95、assistant=0.6”。神经模型校准研究可指导后续评价，但不能直接为LLM自由文本的置信度担保。[C5]

若未来引入贝叶斯证据合成：

\[
\log O(c\mid e_{1:n})=\log O(c)+\sum_g \log LR(e_g)
\]

必须明确似然如何获得、来源g何时可近似独立。同一事件的摘要、重复引用和派生记录属于同一来源链，不能重复相乘。本轮不把未校准的事实后验设为自动提交、自动删除或业务授权的门槛。

### 4.5 数学逻辑：局部适用关系，而非无限证明器

对一个有来源支持的断言，区分：有支持、有反证、二者都有、当前不足。它们是证据状态，不是四种执行权限。缺少支持不推出反面成立，冲突也不推出任意结论。

显式覆盖的计算规则：

- 只有明确存在的 `overrides(exception,general)` 且问题范围满足例外条件，才使用局部例外。
- 撤销例外移除其活动覆盖作用；仍有效的一般规则继续可用。
- 一般规则本身已经撤销或过期时，撤销例外不能让它自动复活。
- 多条不可比较的重叠规则保留分歧；不按最新字符串或最高置信分数任意选胜者。
- “总体每周三次”不是“每个成员每周三次”。只有明确的逐成员规则才可分配。

Logic-LM提供了语义转换与确定性执行分工的先例；本版只执行现有结构中的有限关系，不复制其完整求解器或自修正流程。[R7]

## 5. Grounded Memory：完整来源与可靠形成

### 5.1 全部目标功能

原始消息／工具结果捕获，来源正文及区间读取，陈述者与命题主体分开，事实／计划／偏好／推断表达，原文保存与语义提交状态分开，多语种输入、未知信息表达、owner隔离、导出与恢复。

### 5.2 本轮实现

**来源捕获复用现有SourceEvent。**身份、时间、来源角色由程序填入，模型只选当前请求内短引用。原文没有送达，不用索引metadata假装完成来源核对。

**形成原语不强迫生成长JSON。**模型输出自足断言与必要变化。程序补记录ID、版本、实际来源角色、已知捕获时间及事务结果。不能把一段话所有可能属性都变成必填字段。

**归属伴随每个断言。**如果数值来自Assistant解释，就不能因为用户说“收入增加”而把该精确数值绑定为用户自述。有多个来源时分别保存支持角色，不强制选一个来源覆盖所有子句。

**原始保存与语义成功分离。**用户可得知“原文已保存，结构化记忆待处理”，而非无条件“全部记住”。无变化记录、实际失败和未知均有明确回执。

**内容粒度按独立变化决定。**例如收入数值与季节波动既有关联，也可能独立变化：模型可以选择值作为content，把季节条件关联保存；难以可靠拆分时保留自足原句，不强迫错误原子化。

### 5.3 来源重用而不重复验证

外部输入与提交边界做必要的访问、版本和结构检查一次。内部使用规范对象，删除沿调用链重复序列化和全对象比对的习惯。不得用新SHA或“更严格的hash”替代接口整理。一个来源ID的存在性检查不能冒充自然语言蕴含证明。

### 5.4 完成定义

正常Host和benchmark同一事件路径能真实保存来源、形成或追加记录、返回诚实状态，重启后可查原文和语义结果。来源不完整时仍保留可用原始信息，而不是整条消息消失。

## 6. Verified Object References：把“记住”与“真的能执行”分开

### 6.1 复用现有合同

现有 `VerifiedObjectRef` 已明确是可信应用观察，不等于授权或当前实时状态；`ObservationProfile` 已有对象ID路径、字段、资源版本、有效时间和部分结果描述。[S5]

本版把这些能力落实为可复用应用适配合同，不再让核心认识“reservation”或“审批”关键词。

### 6.2 必须完成的行为

| 功能 | 具体要求 |
|---|---|
| 发现对象 | 由可信应用绑定、实际lookup、工具回执或合法机器引用发行ref |
| 解析模糊称呼 | 允许语义检索找到候选，实际工具确认；多个候选无法确定时询问，不模糊改写exact key |
| 执行业务 | 工具接收ref，适配器解析真实external_id并检查当前权限 |
| 查询新状态 | 引用身份可复用，但缓存字段不冒充当前世界状态 |
| 部分结果 | 结构化保留每一步effect，不由自由摘要压成整体成功／失败 |
| 撤销／过期 | ref可记录失效或重新发现；不把名字相同视为同一业务对象 |
| 多owner | 业务引用及来源遵守owner边界，与记忆内容相似度无关 |

### 6.3 最小业务适配接口（设计语义，不是新增全套框架）

`lookup(reference)`、`execute(operation_id, ref, action)`、`observe(receipt)`、`discover(operation_id, ref)` 即可覆盖现有沙箱。具体函数名称由集成者映射到现有模块；不为了命名一致改所有目录。

一个新业务工作流应只新增适配器和事实字段映射，不修改记忆编辑器、检索器或范围推理核心。先以已有两个沙箱证明这个边界；真实外部账号接入需要明确授权，不属于本次文档自动执行范围。

### 6.4 不采用概率授权

有用性0.9、来源可信0.99或多数Agent同意，都不能发行对象引用或证明实际副作用。执行判断只依据当前业务合同与真实可观察结果。

## 7. Semantic/Episodic Memory：快速经历、可变解释与有限整理

### 7.1 两种记忆是职责，不是互斥分类考试

情景记忆保存某次具体事件、参与者、情境、时间、原始来源和真实结果；语义记忆表达跨会话可使用的偏好、计划、约定和当前解释。同一原事件可支持二者，无需复制多份原文。

一次明确的长期偏好可以直接形成语义记忆，不必等待重复三次。多次相似经历也不必然推出永久规律；推导出的模式标为inferred，保留适用情境。

### 7.2 三个操作

**摄入。**所有允许保留的实际事件进入来源；有价值经历形成Episode索引。语义形成仍采用当前两种recipe，保留比较选择。

**整理。**`consolidate`只接收变化的事项、未整合事件或用户指定范围。在会话结束或明确维护命令时调用现有模型／编辑器；一次提出一次编辑，无常驻reviewer。

**回忆。**问题检索语义事项与必要Episode，保留当前、历史、计划、来源和实际效果的区别。没有当前语义解释时，可以从真实事件回答，明确其依据。

### 7.3 防止无谓新建和大卡的双向约束

不要强制“找得到旧事项就update”；相关但独立的经历可以追加。也不要给每句话创建一个新事项。暂态候选定位到实际旧事项后，把同一事项相关改动归并到一个编辑容器；不同事项保持独立。

若消息包含多个主题，先实现批量候选检索和合并接口；默认可沿用一次合成查询以保持当前对照。集中结果确有主话题掩盖时，切换逐候选定位，并作为共同能力给各方法使用。

### 7.4 遗忘、冷存储、过期必须区分

| 操作 | 含义 | 不应发生 |
|---|---|---|
| 低激活／冷存储 | 默认较少召回，原事件仍允许访问 | 自动说历史不存在 |
| supersede／失效 | 某断言不再作为当前解释，历史可查 | 物理删除整段历史 |
| 用户遗忘／访问撤销 | 根据明确范围阻断未来使用及派生缓存 | 会话后整理或恢复重新带回 |
| 物理擦除 | 需要存储、备份、日志策略明确支持后才能承诺 | 用可见性隐藏冒称所有副本已删除 |

物理擦除的范围必须真实描述；本地Lab先完成现有Store、历史响应及缓存的可见性闭环，提供导出／清理接口，但不承诺控制外部备份或服务商日志。

### 7.5 认知增强的取舍

整理、激活与回放能力先实现为小函数和显式服务操作；不预先部署后台守护平台。运行时遇到查询，不因为“记忆被唤醒”自动修改其内容；只有真实新信息或明确整理任务才修订语义记录。

## 8. Grounded Revision：可组合局部修订与时空语义

### 8.1 一次修订应完成什么

新值落地；未改限制不丢；来源归属正确；有效时间明确或保持未知；历史能够解释过去；如果冲突无法解决，不伪造统一结论。

### 8.2 继续复用已有操作

| 操作 | 目标 | 程序保证的范围 |
|---|---|---|
| 同范围改值 | 修改特定content或明确子部分 | 未选内容不重复生成；结构保持不等于语义证明 |
| 增加局部例外 | 明确范围中的替代安排 | 保存一般规则及明确共享的条件 |
| 修改共同条件 | 更新已存在的共享限制 | 使用实际关联边，不按相似词扩散到所有事项 |
| 撤销例外 | 移除局部覆盖作用 | 保留仍有效一般规则，不复活已撤销规则 |
| 追加事件／新事项 | 新信息无需覆盖旧记录 | 来源和发生时间仍可查 |
| 更正历史错误 | 明确否定先前记录的正确性 | 保留旧陈述为历史，当前解释引用真实勘误 |

复合条款只改一个数值时，不能默许模型重写全部限定。第一版保留能独立变化的content／condition和来源关系；对仍为复合文本的局部替换，提供明确选段或由模型一次给出替换内容，实际非目标损坏留给集中评价。不叠加“保持性审核Agent”。

### 8.3 三个时间含义

- `observed_at`：系统实际获取来源的时间。
- 来源中明确的事件／生效时间：事实在描述世界里何时成立。
- 记录版本时间：系统何时维护了某种解释。

不必增加完整双时态数据库，只需允许断言保存实际可知时间及其依据，历史读取按所需含义选择。未知起始时间不能自动变成负无穷；“计划下月开始”不等于现在已生效；到达计划日期也不会自动证明事情已经完成。后来的回溯来源可以说明过去，但必须有明确回溯内容。

### 8.4 不用重演整段历史来回答每个问题

对于已存明确覆盖和有效期，提供只读适用视图。模型仍需判断自然语言查询与范围是否匹配，但已选择的关系解析可以由纯函数完成，输出当前规则、活动例外、适用条件、历史与未解决项。

普通append-only只读组也可按其实际事件重建解释；不能暗中借用M预维护的正确状态。使用哪种读时重建策略要公开，双方都允许真实原文访问。

### 8.5 语义证据与取消依据分开

“取消夜班例外”是修订动作的依据，不一定支持一般频率的具体数值。一般频率仍来自旧的有效来源。更新时允许复用旧支持并引用新撤销事件，不要求新消息重新背诵所有旧限定。

这是减少“当前证据要求导致合法保持遭拒”的关键；保留旧支持只在真正未改部分使用，不能把旧来源挪给无关新断言。

## 9. Lifecycle Recovery：恢复完整请求，而非盲目重放调用

### 9.1 当前实现基础

共同 `maintain_event` 已保存阶段、提案、操作ID和回执；未确认模型阶段不会自动重发。[S4] 这保护了已有结果，但“保持incomplete”不等于完成用户任务。新版本要把明确的继续入口接到已有恢复能力，不另建队列平台。

### 9.2 必须区分的恢复情形

| 中断位置 | 应有行为 |
|---|---|
| 原文保存前 | 未承诺保存，正常报告失败或继续输入 |
| 原文已保存、模型尚未调用 | 可从原始事件继续，不丢来源 |
| 模型请求已发、结果未确认 | 保留首次未知；若无法查询原结果，可由用户／调用方显式发起新的语义尝试，不重放业务动作 |
| 提案已保存、记忆提交未确认 | 先按已有操作ID查询实际提交；已提交则使用回执，否则按事务结果继续 |
| 部分业务已完成 | 发现实际世界，继续未完成步骤，已完成步骤不重复 |
| 记忆与业务成功、最终答复失败 | 重新组织真实结果，不把成功动作再执行一次 |
| 续办请求限制变化 | 当前“只读／不保存／取消”优先，原待办不能自动恢复旧权限 |
| 来源已遗忘 | 缓存提案与回执视图遵守当前可见性；必要时说明无法继续相关语义整理 |

生成请求重复与业务mutation重复不是同一种风险；不能用一个“unknown一律永远停住”策略代替正常功能。新尝试使用新attempt身份、保留旧未知和费用；科研首尝试结果仍不覆盖。

### 9.3 请求剩余项用既有journal表达

一个请求可以包含查询、业务动作、保存实际结果、反馈四项。每项由真实回执标明confirmed／partial／known-no-effect／unknown／cancelled等必要状态；不要求再增加大型状态枚举平台。

模型的计划是请求解释，不是权限来源；实际世界状态和操作完成性仍由适配器确立。[S5]

### 9.4 视图一致性

维护提交完成后，当前轮的普通只读视图刷新；先前发行的历史快照不改。Host已经有的材料标明版本与来源，重复读取必须能指出缺失的对象、下一页或新版本；已送达且无新增信息时优先用现有材料回答或说明不足。

不通过无限增加读取上限解决循环。也不禁止所有重复读取：真实发生版本变化、权限变化或查询不同历史时，重新读取有正当用途。

### 9.5 程序化结果摘要

预订已完成而标签失败时，先输出结构化事实：预订confirmed、标签failed／pending、记忆committed／incomplete。模型可以解释它们，不负责重新判定它们。借此避免“部分失败”在长文中被压成“全部失败”。

## 10. 记忆模拟：实现机制可观察性，不制造人工优势

### 10.1 两类回放严格分开

**实际经历回放**：由consolidate读取真实已保存事件，整理语义解释，不重复实际工具副作用，不增加独立证据次数。

**隔离模拟**：在独立namespace／临时数据库中，用虚拟时钟和沙箱适配器产生经历。模拟来源明确标记，其ref只在沙箱应用中有效。不能进入真实owner库，不能调用真实外部mutation。

### 10.2 模拟器是薄适配器

输入为普通事件序列；调用与Host相同的ingest／maintain／recall／resume路径；输出实际状态变化和任务结果。不要另写一套能够直接填入正确状态的“模拟记忆算法”。

事件生成器与评价真值分离。运行时只见事件和合法任务，不能见gold、未来查询、完整隐藏世界或用于评分的规则。虚拟时钟提供普通日期，不用隐藏时间标签给方法特权。

### 10.3 初版覆盖的自然过程

| 过程 | 观察点 |
|---|---|
| 反复独立经历与明确一次偏好 | 是否保留频率信号，同时允许一次明确指令形成规则 |
| 时间间隔与再次使用 | 激活如何变化，冷存储能否重新取回 |
| 一般规则与局部例外 | 有效范围不被扩张 |
| 后来更正过去／未来生效 | 区分观察时间和有效时间 |
| 相同内容不同来源 | 能否保持归属，不把复述当新确认 |
| 中断与部分业务 | 是否继续剩余任务，不重复效果 |
| 遗忘与再次提及 | 旧记录不复活，新的明确来源可以正常形成新记录 |

第一版实现少量可组合事件构造器与一条可浏览轨迹，不先做几十种随机扰动。模拟用于机制解释，公共benchmark用于可比结果，两者分别命名。

### 11.3 对外能力集合

建议向调用方呈现下面的概念接口；实际名称优先映射现有方法，不另造重复SDK：

| 能力 | 说明 |
|---|---|
| ingest | 捕获真实事件并返回来源结果 |
| maintain | 使用选定recipe形成、修订或追加 |
| recall | 按实际问题、时间、范围返回可用证据和当前／历史视图 |
| consolidate | 在明确范围内整理真实经历，沿用相同提交路径 |
| forget | 执行现有可见性撤销与派生清理 |
| resume | 从实际阶段与回执继续允许的剩余工作 |

业务ref的lookup／execute／discover属于应用边界，不混入通用记忆CRUD。测试模拟器调用这些相同能力，而不是专用“正确答案接口”。

### 11.4 简洁性原则

规范对象在边界验证一次；错误直接返回负责阶段和实际结果。保留现有事务、访问限制、操作身份，不在每一内部函数重新证明来源字节。优先组合函数，不建立深继承层。可选参数必须对应真实用户用途或已存在对照，停止增加实验性开关笛卡尔积。

修改构成一个完整能力包后再写一条有信息量的提交，不为每次报告复制多份当前状态。当前说明保持短，历史留在版本记录与结果目录。代码复现只记录普通源码版本、配置和实际命令，不建立新的摘要核验制度。

## 12. 多Agent并行开发：并行写不同模块，串行整合共享边界

### 12.1 采用1名集成者＋5名开发者

这是开发组织方案，不是运行时Agent数量。现有代码Agent环境可直接执行，OpenHands只是可参考的工作区与工具接口项目，不是必须迁移的平台。[R6]

| 角色 | 主要交付 | 独占写入范围 |
|---|---|---|
| Integrator | 小型共同合同、普通Host／benchmark合流、版本整合、最终配置 | `contracts/memory.py`、`memory/service.py`、中央runner与配置；共享文件只有其一位主写者 |
| A：来源与经历 | 情景索引、来源归属、有限整理与遗忘传播接口 | 新`memory/episodes.py`、新`methods/consolidation.py`；其他来源模块先登记后独占 |
| B：语义修订与逻辑 | 自足单元、局部编辑、时间／范围／例外投影 | `memory/edit_units.py`、`methods/edit_memory.py`、`methods/edit_features.py` |
| C：对象与恢复 | ObservationProfile适配、部分效果、剩余任务与显式继续 | `application/`中本轮相关文件，现有journal／恢复实现；不复制contracts |
| D：维护与Host适配 | 两种recipe、按候选定位、紧凑输入、刷新当前视图与读取进展 | `methods/edit_maintenance.py`、`methods/functional_edit_memory.py`、`memory/retrieval.py` |
| E：认知辅助与模拟 | 激活／效用、冷存储建议、虚拟时钟、隔离事件流、使用示例 | 新`memory/activation.py`、新`harness/memory_simulation.py`及专用示例 |

B和D需要同一edit API时，先在一页接口约定中确定参数，由B实现，D调用。E给D提供纯排序函数，不直接修改retrieval文件。A的consolidation调用D的公共维护，不反向复制runner逻辑。

### 12.2 协作规则只保留六项

每人一个worktree／分支／临时库；共享合同由集成者维护；修改前登记文件所有权；每个能力包提供实际可运行示例；只运行自己的必要检查；由集成者合并和执行公共冒烟。

不要五个Agent同时改`service.py`，不要每人写一份AGENTS或总规划，不要把一个bug交给多个reviewer无限投票。代码审查在交接时进行一次；发现真实错误直接补丁修复。

### 12.3 模型资源与实验隔离

代码编写、静态分析和本地模拟可并行。真实Qwen／BGE请求受现有服务与资源约束统一调度，各开发者不能各启一个模型服务或抢同一个数据库。已经运行的评分保留；源码开发不等待全部旧评分结束。需要释放资源时，由运行负责人在明确边界处理，不由worker杀进程。

### 12.4 交接格式

只需：完成的用户能力、修改文件、一个运行示例、已知缺口。接口变更附具体参数差异。禁止用“测试300项通过”代替“用户能做什么”。配套任务卡可直接分发，任务清楚后无需再创建专门的多Agent管理平台。

## 14. 开发期最少检查，集中实验在功能版本之后

### 14.1 开发期仅三层

**个人改动：**导入／编译、相关格式／类型、直接受影响的现有测试；没有需要就不新增测试类。

**能力交接：**一个正常输入示例，检查实际持久结果；不会为了错误枚举写几十个防御性分支。

**集成完成：**统一执行下面五条完整冒烟。不把五条变成五套批准流程。

| 冒烟 | 主要行为 |
|---|---|
| 保存与重启 | 用户陈述→原文＋语义→重启→当前／原文查询 |
| 更正与历史 | 多事项消息→找到相关目标→更正一处→保留未改限定→查过去与当前 |
| 例外生命周期 | 一般规则→局部例外→共同条件变化→撤销→范围查询；包含整体与逐成员区别 |
| 可见性与未知 | 纯查询不写；来源不足保留未知；遗忘后不复活也不声称从未存在 |
| 实际业务恢复 | 真实对象→部分效果→中断→发现→只做剩余项→诚实反馈业务和记忆状态 |

语义错误记入现有问题表，其他冒烟继续；跨owner暴露、损坏持久数据、重复不可逆副作用先阻断对应路径。无需新增几百条验收项。

### 14.2 集中测试的顺序

1. 一个完整候选跑已曝光开发历史，先取得完整错误画像；预测和Judge分开，减少无谓重复。
2. 根据最早断点只改一个主要因素：输入／定位／维护／来源／视图／恢复。
3. 共同实现稳定后再跑B0/B1/B2/M与Append-only；所有组用相同合法输入、模型及公平预算，Reader与正常能力共同。
4. 保留一个候选沿自身历史继续65／277，65是同一条长运行的观察点，不另计一套独立样本。
5. 冻结后才读取16个保留用户；外部LongMemEval和实际RawRAG／RollingSummary／A-MEM对照随后进行。
6. 同一候选完成普通Host旧功能回归及少量实质新故事；测试发现的语义问题进入下一版，不覆盖首版结果。

原32机会／12会话／4用户机制与漂移、LongMemEval28题／1,354历史及原10答案、Host135案例／192消息是既有范围，不在开发前新增更大矩阵。[S2] 28题不能报告成官方全量成绩；保留集用过调参后不再称未见。

### 14.3 主指标

| 维度 | 评价问题 |
|---|---|
| 新要求完成 | 明确新值／计划／事件是否实际进入可用记忆 |
| 非目标语义保持 | 未更正且仍有效的限定、主体、归属与时间是否损坏 |
| 适用性 | 一般／例外、当前／历史、计划／完成是否正确 |
| 用户任务 | 最终回答和真实动作是否完成需求 |
| 可用性 | 未处理、重复读取、截断、错误拒绝、恢复所需步骤 |
| 来源与权限 | 来源归属错误、错误对象、重复副作用、不可见内容复活 |
| 资源 | 实际模型、编码、token、时间；记录但不要求本轮降成本 |

不以UPDATE次数、condition节点数、相同字节、拒绝率或成功提交数代替语义有效性。无变化可以正确也可以漏写；append-only可以有效也可以产生冲突，均按任务与状态评价。

### 14.4 最小方法消融

主四组已经区分文本／条件表示与全量／局部更新。追加式事实记忆是强对照。认知机制只增加以下有针对性的比较，不跑所有开关组合：

- 已选维护recipe与另一个recipe：同前态和随后独立完整历史分别评价。
- 原关系呈现与实际适用视图：固定状态、问题与材料规模，隔离Reader作用。
- 普通dense与dense＋激活：只在正确记忆存在且长期取用有压力时比较；别为制造优势主动破坏基础检索。
- 无会话后整理与有限来源整理：看新要求、非目标损坏及重复证据处理，不只看摘要更短。

参数优化与概率校准在开发数据进行。抽样随机性、用户／历史簇和重复运行要报告，不用单模型自审假装独立Judge。

## 15. 创新落点：一个主方法问题，不把每个工程模块都写成贡献

### 15.1 建议主张

> **来源关联的可组合记忆再整合：在保留真实经历的基础上，通过局部语义变化和显式适用关系维护可用视图，使连续更正、局部例外与撤销不破坏仍有效的其他语义。**

可检验的贡献包含：

- **写入机制：**模型只生成被改变的语义，未编辑部分与实际来源延续；明确区分替换、局部覆盖和撤销。
- **写读一致性：**同一组实际关系同时用于更新和只读呈现，而不让Reader重新猜测其含义。
- **长期组织：**快速事件捕获与有限来源整理配合，区分使用激活、证据强度和事实适用性。

认知理论、贝叶斯公式、事件溯源和图边本身不是原创性证明。创新成立需要相对于普通局部编辑、强追加式与实际原文检索的额外净收益。

### 15.2 对负结果的处理

普通局部编辑足够，就采用它；强追加式更可靠，就将语义视图定位为按需优化；激活没有改善取用，就保留最简单dense。**软件五条主线仍然完整，研究结论不要求所有候选模块都胜出。**

未开源论文按明确披露的机制讨论，不假定其所有声称均已解决，也不要求复现后才允许开发。保持自主提出机制、清楚比较和诚实报告的研究信心。

v13.4的Simplify继续保留：它限制的是当时没有建立必要性证据的复杂关系消歧选源分支，不否定本轮局部修订、认知组织或普通检索改进。[S8]

## 16. 最终交付与范围收敛

### 16.1 工程交付

一个普通Host功能配置、同一MemoryService下的五主线、实际来源与关系可浏览、显式继续与遗忘路径、认知整理／激活／隔离模拟入口、predict／score工作流、迁移说明和简明问题表。

### 16.2 实验交付

同版本主对照、完整分母和实际结果、来源／状态／最终任务分开评价、必要消融、保留及外部证据、真实费用与未知、可运行而不含私密原文的复现说明。

### 16.3 明确不做

不新增SHA校验或替代哈希；不建第二事实库；不增加常驻审核Agent；不硬编码benchmark任务、人物、关键词、gold和例外答案；不为未来扩展搭空平台；不把全部测试前置；不把多Agent协作变成每次修改都要委员会审查。

远程多租户认证、分布式exactly-once、参数化记忆训练、真实脑仿真和任意外部副本物理擦除不作为本地完整功能版的隐藏任务。架构为它们保留合适边界，但本轮只实现有实际调用需求的能力。

**执行原则：先把已有代码连接成一套完整系统，再利用集中测试决定哪些认知机制与编辑算子值得留下。**
