Authority: the user's finite 2026-09-22 batch and subsequent explicit permission
to use historical bundle adoption/rejection **as a proxy only**, with paired

## Fixed question and method

Can a deterministic **exact-version bundle adoption propensity** improve native
paired quality/cost over static retrieval? It is not observed use or causal reward.
The immutable allocation SHA is
`90877f1f6506974edb84b773ea356be687e59038136d0801a0b4d299ff392e26`:
24 independent DB/OS DEV/VALID positions, eight fixed repeats, 32 pairs/64 arms.
The existing frozen order and arm counterbalancing are unchanged. No replacement,
TEST, main confirmation, Travel, RESERVE or SUPPORT memory bank is admitted.

Candidates come only from unchanged v0.6 VALID bank versions. Exclude the current
task's entire source cluster, including indirect retrieved-material ancestry and
feedback ancestry. Score source records by the existing instructed BGE cosine
query and stored 1024-dimensional record embedding. Common retrieval is **cached
only**: 21 queries have verified existing instructed BGE vectors; OS 120/226/2
abstain in both arms. This is missing-cache abstention, not a semantic no-opportunity
claim. DB query-vector receipts happen to reside in old projection directories;
no SUPPORT bank, context or label is loaded from those runs. No new embedding or
rerank calls are needed. Cache reuse is an explicit deployment limitation.

Compare variants from the top two source records. Each full record bundle is a
variant; a historical nonempty adopted subset is another exact bundle. STATIC
selects the first source record's full bundle. Proxy score is exact-bundle
acceptances/(acceptances + complete rejections). Partial selection supports that
exact subset only: no per-item reward and no rejection of the full bundle. Unknown
scores are UNKNOWN, not zero. If STATIC is unknown, or there is no strict known
improvement, UTILITY stays STATIC. No task outcomes enter this rule. No online
updates, maintenance, adoption model, extraction, revision or self-judge calls.

The context uses existing ReasoningBank consume wording and exact card text;
the common native action-aware policy/action-budget facts stay enabled, as in
v0.6. Only the selected bundle differs. Candidate pool, model, tools, task, native
limits and feedback are identical between arms. Changes in context length are
the declared selection intervention, not a separately tuned token budget.

## Pre-outcome denominator and decision rules

Four independent OS positions change selection (428/242/355/467), none in DB.
Only OS 428 is conservatively admitted to the mechanism-effect denominator:
two nonempty applicable bundles differ on relevant primary/secondary membership
verification, and have distinguishable proxy values. Its fixed repeat is the
only repeated changed opportunity. The other three changes lack established
meaningful alternatives; record their quality, harm and costs in overall totals,
not as mechanism evidence. All 64 frozen arms remain in execution accounting.
Denominator notes are frozen before requests; IDs never route the selector.

Primary quality: paired native correctness (UTILITY minus STATIC), with failed,
unfinished and unscored arms disclosed separately, never silently dropped or
rescored as success. Report all 24 independent pairs and repeats separately,
domain-wise, plus the pre-admitted opportunity subset. Paired regression is a
STATIC-correct/UTILITY-not-correct completed pair. Unscored is UNKNOWN.

Primary cost: total new reported generation tokens per arm, including every role;
report prompt/output components, failed/unknown upper bounds, all auxiliary HTTP,
embedding/rerank, end-to-end arm wall time including native initialization and
release, plus shared preparation/verification costs. Historical cache creation is
sunk and not charged as new: disclose it separately as **not remeasured**, never
claim a fresh-retrieval saving from cache reuse. Unknown totals remain UNKNOWN,
alongside known subtotals and conservative charged upper bounds. Provider latency
and native wall time are descriptive, not token-cost substitutes. No monetary
cost is invented without a billing contract.

Observable use remains UNKNOWN unless independently supported; explicit model
mentions are at most self-reports, not causal credit. Version-bound settled
actor-input receipts prove exposure only. No outcome reward is spread across cards.

An exploratory direction signal requires no native-quality regression, fewer
total charged tokens on the meaningful changed original AND its fixed repeat,
and no safety violation/unknown usage. One independent eligible task cannot
establish general benefit even if this signal holds. No promotion or transfer
admission from this batch. Otherwise KEEP_SIMPLE / benefit not established;
no result-conditioned expansion, retuning, extra repeat or replacement.

## Runtime identity, limits and stopping

Solver only Qwen3.6-35B-A3B-FP8 at loopback 7860/v1. Existing M1 actor temperature0,
top-p1, seed213, thinking off, output4096, context65536; other role profiles remain
unchanged but are unused. Native LifelongAgentBench commit
`d6f19b42eb358d9150379f0c68c2985c5a867520`, unchanged parsers/scorers; DB3 and OS5
native interactions, OS command timeout20s. Docker image IDs and executable/source
hashes are bound in the external admission. Only authorized IDs reach native
scoring; evaluation/gold fields do not reach selection or model input.

One hard-coded batch root, one persistent budget database, exclusive batch/arm
start markers. No replay or automatic retry. All outbound Provider requests pass
the guard: 400 text slots/3,000,000 tokens; 128 embeddings/50,000 tokens; rerank0;
528 total. Tokenize/model-info conservatively count against text slots as auxiliary
HTTP with known zero inference tokens; thus the guard may stop before 400 actual
generations. Failures keep their usage or known reservation upper bound.
Four hours start on the first auxiliary model-info request (stricter than starting
at generation); do not send after deadline, extend, or make up unexecuted arms.

Stop the batch on quota/time, invalid identity/provenance, unknown usage/invalid
receipt, unexpected runtime exception, or an isolation/authority safety failure.
Native scored incorrect/invalid-action results are retained and do not trigger
replacement. Persist current/failed/unfinished evidence and complete costs.
No shared service configuration, historical artifact, Product API/schema,
permission or Canonical state is changed. No automatic next research allocation.
