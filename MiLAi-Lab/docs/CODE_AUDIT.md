# Legacy experiment code audit

Audit date: `2026-09-01`  
Source: `/cra/memory/mx_memory/MiLAi`  
Mode: read-only structural audit

## Findings

The legacy repository is not a viable source for a Git history split. Its Git index has
only six tracked files while almost all runtime, evaluation, test, document, and artifact
content is untracked. The split therefore uses a byte-preserving migration manifest into
fresh repositories.

Before filtering, the principal generated areas were approximately:

| Area | Size / count |
| --- | ---: |
| `var/` | 5.8 GiB / 73,991 files |
| `runtime/` | 1.3 GiB, including local venv and runtime artifacts |
| `integrations/` | 826 MiB, including per-package venvs |
| `evals/` | 238 MiB, of which one DG10 venv was about 214 MiB |
| root scripts | 639 files including generated bytecode |
| root Markdown | 97 files |

About 4,005 receipt-named files existed versus roughly 252 terminal-named files and 58
run-locks. This is evidence amplification, not useful source organization.

## Coupling

A structural scan of evaluation, script, and root-test Python found:

- 213 files importing `milai`;
- 457 importing `evals`;
- 306 importing `scripts`;
- 275 modifying `sys.path`;
- 25 containing an absolute `/cra/memory/mx_memory` path;
- 48 importing private product symbols.

Product source did not import evals, which is the correct direction. Some product tests
did import evals or root scripts; those tests are preserved here as historical
experiment-coupled assets and must not remain active product tests.

Provider and benchmark configuration was duplicated across many DG/lifecycle modules.
Model IDs and `127.0.0.1:7860` were hard-coded in dozens of files. The active Lab package
therefore centralizes endpoint configuration and keeps dataset roots in manifests.

## Migration decision

The archive copies human-authored source and compact fixtures but excludes:

```text
.venv, caches, bytecode, wheelhouses, build/dist, var, logs,
model weights, release/submission archives, and large benchmark corpora
```

No archived module is imported by active code. The existing `EXPERIMENT_AUDIT` documents
are retained as a DG17-era audit, not represented as a current whole-Lab verdict.
