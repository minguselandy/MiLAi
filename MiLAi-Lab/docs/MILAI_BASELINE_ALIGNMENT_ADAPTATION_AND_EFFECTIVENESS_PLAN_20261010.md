## 1. 本轮决策：换验证路径，不换总方向

当前不再优先增加新的检索器、反思 Agent、概率评分、图数据库或更多结构字段。首批交付三个可运行对象：

| 对象 | 作用 | 首版要求 |
|---|---|---|
| **强简单 RawRAG** | 检验合法原始历史本来能回答到什么程度 | 原文／完整交流单元检索，直接 Reader；不经过 MiLAi Editor 或二次 Selector |
| **Hindsight 原生实现的本地适配** | 提供独立于 MiLAi 共同链路的外部参照 | 保留原 retain/recall 方法；适配已有模型端点、独立 bank、时间和费用；不转换成 MiLAi 条件图 |
| **MiLAi 纯记忆适配入口** | 把现有形成、修订和读取接到同一比较协议 | 复用已有benchmark的纯记忆路径；对外提供薄接口，不重建流水线，也不引入普通Host的业务意图分类 |

同时继续完成普通 Host 的保存、更正、历史、实时核对、遗忘和恢复；这条工程工作线不必等待论文比较结束。

**最终要回答的主问题：**

> 在相同的历史可见范围、明确的来源条件和可比较的资源下，MiLAi 的来源关联局部修订，是否比原文检索、强追加式记忆和普通编辑更可靠地落实变化、保留仍有效含义，并支持后续问答？

这不是预设 MiLAi 应当获胜。外部系统尚未在本环境复现，不能将“论文有高分”写成“当前已有一个通过的外部基线”。同样，方法尚未显示优势，不等于项目的全部功能没有价值。

### 1.1 保留的五条方向

- **Grounded Memory**：原始来源与派生解释分开，保留主体、角色、时间、模态和适用范围。
- **Verified Object References**：业务身份来自可信绑定或实际工具观察，记忆自由文本不创造业务现实。
- **Semantic/Episodic Memory**：经历能够保存并被找到，语义解释可以修订；仍是一个逻辑 MemoryService。
- **Grounded Revision**：改变需要改变的含义，保留仍有效的内容；支持合法更正和撤销，而不是一律保持旧文。
- **Lifecycle Recovery**：按照实际回执继续剩余工作，区分已完成、部分完成、已知无效果和未知效果。

这些来自项目既有目标。[H1] 外部对照使用自己的隔离存储，不等于在 MiLAi 产品内部增加第二套竞争事实库。

### 2.4 对旧 RawRAG 与外部入口的必要反思

所读 `runners/edit_external.py` 的 `reader_payload()`调用共同 `reader_messages()`，`bound_author_context()`还会限制作者检索得到的笔记出现次数。它适合“外部记忆＋共同Reader”比较，但不等于完整原生端到端结果。[G5]

## 3. 相关方法的选择：一个简单参照，一个独立完整参照

### 3.1 首选 LongMemEval 官方检索—读取实现

LongMemEval发表于ICLR 2025，提供 turn/session 粒度检索、BM25及dense检索、事实扩展索引、直接或证据整理式Reader，以及独立评价代码。[R1][R2]

本轮分两种名称运行：

1. **作者实现原生配置检查**：在依赖和服务可用时保留作者流程；没有原模型时，不承诺复现论文分数。
2. **RawRAG-local**：复用作者的数据组织与检索—读取路线，连接现有Qwen/BGE或已有BM25；明确记录模型替换，不冒称原分数复现。

首版先做原文检索。事实扩展索引是后续一个可选因素；不得把官方提供的预生成扩展缓存用于不匹配版本的数据，也不得将答案相关标签带入索引。

### 3.2 首选 Hindsight 作为独立外部系统

Hindsight发表于ACL 2026 System Demonstrations，开放实现，提供retain、recall、reflect及多路检索。其论文结果证明该路线值得检验，不代表现有Qwen端点能直接达到其原成绩。[R3]

首版使用**公开SDK／原生服务**，不抽取类体后重写核心。外部进程与可选依赖隔离，避免把其数据库和模型依赖全部并入MiLAi核心安装。

明确两个外部结果：

- **Hindsight-native-local**：保留作者的形成、召回及其基准推荐回答流程，只替换无法直接使用的模型／部署设置，并列出差异。
- **Hindsight-recall＋common-Reader**：保留其原始召回输出，使用共同Reader。它用于分离记忆后端与回答器作用，不能称完整原生系统。

若当前公开基准本就采用recall后独立Reader，按实际代码记录，不为了凑“原生”强制调用reflect。reflect产生的是模型答案或推断，不能伪装成未生成的检索证据。

### 3.3 暂不并行部署更多平台

MemOS可作HaluMem作者表的后续参照，Mem0、A-MEM、SimpleMem既有适配继续保留。Mastra观察式记忆留作后续简单路线对照，不在首轮再增加Observer/Reflector实现。

外部服务暂不可用时，记录该配置未运行；RawRAG与MiLAi适配继续推进。不能把外部复现变成另一个无限阻塞的准入流程，也不能凭低分删除外部方法。

## 4. 三条评价轨道：不要再合成一个模糊的“效果”

| 轨道 | 问题 | 固定什么 | 允许什么不同 |
|---|---|---|---|
| **N：原生系统检查** | 作者完整方案在当前可获得环境能否工作？ | 选定数据版本、合法历史、作者API与流程 | 作者推荐模型、检索和内部调用；差异全部记录 |
| **C：共同条件比较** | 同一环境下MiLAi的记忆方法有没有净收益？ | 历史可见性、Reader／Judge、输出规则、主预算和来源条件 | 后端内生组织；必须记录内部调用和实际材料量 |
| **F：Host功能验证** | 用户的保存、核对、修改、遗忘、恢复能否真实完成？ | 当前权限、真实对象、原业务流程和来源 | 仅本轮声明的交互修复 |

**N不产生“同模型算法排名”；C不冒称论文严格复现；F不以记忆QA高分替代真实业务效果。**

C中再次区分：完整后端比较与单机制比较。完整后端可以保留各自检索；要归因于MiLAi编辑算子时，必须固定共同的候选／正文、形成方法和Reader，而不是只固定模型名称。

## 5. Benchmark协议适配：先对齐时间、来源、预算和评价边界

### 5.1 HaluMem：主实验采用在线前缀，不能见未来

HaluMem论文规定按时间顺序写入会话，在相应会话处理后立即评价形成、更新与QA；作者实验的更新评价检索10条、QA检索20条。[R4]

新runner组织为：

```text
for each isolated backend/user/repetition:
    for session in chronological_order:
        ingest(session.dialogue_only)
        await_actual_ingestion_completion()
        save_actual_maintenance_output()
        answer_only_questions_attached_to_this_session()
        freeze_this_session_evaluation_view()
```

这里的`await_actual_ingestion_completion()`是能力说明，不是新API名称：优先同步写入；异步后端使用实际操作完成状态，不用固定sleep猜测。检索索引和方法所声明的整理阶段是否完成，按该后端真实合同处理并记录。

关键规则：

- 方法得到实际对话及公开时间，不得到参考记忆、`is_update`、`original_memories`、答案或未来问题。
- 本次问题只用于查询与回答，不回写成下一轮历史；模型生成的测试答案也不写回。
- 数据文件中的正常原始对话按协议进入历史；不要将独立评价问题与其参考答案混入。
- 后续会话的回溯报告只能在其真正到达后使用，不能提前给早期问题。
- 全档案回顾式QA可作为另列辅助设置，但不能代替在线主结果。

OmniMemEval所核对的`hm_streaming.py`先加入某用户全部会话，再搜索全部问题；这是该代码版本的实际顺序。其成绩不能不加区别地与在线前缀结果混用，也不能据此宣称该框架所有版本或所有后端都存在同一问题。[R7]

### 5.2 身份元数据：两种设置分开，不偷偷补姓名

HaluMem官方Mem0适配器从`persona_info`提取姓名，放入user_id和QA上下文标题，并配置只从用户消息形成记忆；MiLAi的`ObservedSession`则明确不提供persona。[R5][G3]

本轮共同条件主设置保持**source-only**：不提供额外persona，采用无语义的实验用户ID；主体来自实际消息。否则无法判断身份形成与归属是否有效。

作者原生配置检查可保留其明确使用的姓名元数据，但结果必须标记`author_metadata`。如需量化该差异，只增加一个固定材料的小对照，让被比较方法得到相同的元数据，不能只给某一方法补姓名。

不要把这一差异直接称为作弊，也不要声称它解释了所有差距。

### 5.3 QA K值与最终token预算不能混在一起

| 参数 | 含义 | 首版安排 |
|---|---|---|
| 内部召回数量／深度 | 后端搜索多少候选 | 作者原生按作者配置；共同条件记录实际值 |
| `qa_top_k` | 请求返回多少结果 | 对支持计数的接口，新增QA20配置；旧K10保留为旧设置 |
| 更新评价K | 对更新后的状态做参考查询 | 作者口径保持10，仅评价使用 |
| 最终输入预算 | 模型真正收到的完整消息与工具 | 使用实际模板计数，各材料及元数据都计入 |
| Selector | 检索后是否再生成选择 | 新直接读取对照关闭；MiLAi staged继续作为独立交付因素 |

20条短事实、20个片段和20张大事项卡不是相同信息量。Hindsight使用`max_tokens`而非等价的top-k，不能把`max_tokens=4096`称为K20。原生配置保留其逻辑；共同条件以最终实际字面材料预算比较，并同时记录返回数量。[R6]

不机械把旧运行K10改成20。新增配置从独立状态运行；资源不允许原样交付时显式记录缺答或启用预先声明的分页策略，不能静默截断后假称完全对齐。

### 5.4 LongMemEval：采用明确版本，遵守每题历史边界

使用既有注册的LongMemEval开发列表与实际数据路径，确认是原版还是cleaned版。现有28题仅是开发／迁移检查，不称500题结果；原10题答案检查也不替代整个官方评价。[G2][R2]

每个case独立bank，按公开时间喂入其全部`haystack_sessions`，写入结束后再给当前问题。方法不得看到`answer_session_ids`、`has_answer`或参考答案。`oracle`文件仅用于隔离Reader诊断，不能作为普通检索成绩。

原生完整上下文放不进现有窗口时，记为该配置不可执行；RawRAG仍可正常比较。不要截掉早期历史后称FullHistory。

已有 `history_components()`可以辅助识别重叠；开发／确认划分沿用已登记来源重叠关系。重复问题、共享历史和多次生成不视为独立用户。

### 5.5 更新评价中的参考查询只能留在评价层

作者实现会用参考更新内容查询更新后的记忆。这个查询用于**评价已经形成的状态**，不是让Writer提前知道要改什么。[R5]

适配时：在该会话状态上只读取得评价结果；不得将这次参考查询的结果回流到后续正常方法状态、导航、访问激活或反思缓存。能够使用只读快照就使用现有快照；后端检索有副作用且无法隔离时，改用独立评价副本或将该操作级分数记为不支持。

QA、更新状态分数和显式执行UPDATE的次数分别报告。追加式方法可以在回答时正确区分新旧信息；不能因没有UPDATE操作而直接判定其方法失败。

## 6. 适配架构：薄入口，不把外部系统强行改成MiLAi

```text
                     合法的ObservedSession
                              │
                 同一时间顺序／独立实验实例
                ┌─────────────┼──────────────┐
                ▼             ▼              ▼
           RawRAG-local   Hindsight本地    MiLAi纯记忆
           原文索引      原retain/recall   原MemoryService/Editor
                │             │              │
                └─────────────┼──────────────┘
                              ▼
                原样检索材料＋可选原生答案
                              │
                 共同Reader或明确原生Reader
                              ▼
                    独立预测产物与事后评价
```

外部实例只属于该对照臂。它不会成为MiLAi第二个长期事实权威，也不能凭其输出生成VerifiedObjectRef。

### 6.1 最小适配合同

下面是**拟议行为合同，不是声称仓库已有同名API**。优先映射现有类型和函数，只有缺口才新增少量TypedDict/Protocol。

| 行为 | 输入 | 返回 | 不该做什么 |
|---|---|---|---|
| `ingest` | 只含合法对话与时间的ObservedSession | 原生写入结果、完成状态、已知用量 | 不接收当前QA/gold；不让MiLAi重新编辑外部事实 |
| `retrieve` | 问题、查询时间、声明的返回预算 | 原生文本／事实、真实返回ID、实际来源关联（若支持） | 不自动summary、不套MiLAi Selector、不伪造片段引用 |
| `answer_native`（可选） | 当前问题、同一可见bank | 原生答案、实际工具／模型用量 | 不把生成答案伪装成检索证据 |
| `export_session_output`（可选） | 会话身份 | 实际新增输出／事件关联 | 不把整个终态当成本会话抽取结果 |
| `close` | 本实验实例 | 资源关闭 | 不调用生产账户的全量删除；测试清理不能外溢 |

核心入口只需要ingest/retrieve。后端不支持逐会话导出时，操作级指标为N/A，QA仍可评价；不能为了统一表格，让包装器生成一份它从未产生的“抽取输出”。

后端返回的文本不是原始来源：无原文映射时按`retrieved_memory`交付，可以参与该后端原生QA；不得伪装成User或Tool的已验证原文。来源完整性是独立指标，不通过严格过滤把对照臂的主要输出全部抹掉。

### 6.2 Hindsight适配的六个易错点

**① 一用户一臂一重复对应独立bank。** LongMemEval每case独立。不要仅用tags默认匹配实现多用户隔离；tags可影响原生整理和查询语义。

**② document_id不能只用用户ID。** 当前官方retain文档说明，相同document_id默认替换旧文档及其相关记忆。逐会话写入应使用稳定的会话／事件ID，避免每次写入覆盖整段旧历史；不传ID则可能重复写入。这个选择必须先实现正确。[R8]

**③ query_timestamp不是访问隔离。** 它给相对日期与近期性提供锚点，不证明已排除未来来源。因此时间安全由逐会话bank状态保证，而不是先全量写入后加一个日期。[R6]

**④ 预算分开计。** 官方recall的主`max_tokens`只覆盖事实文本；chunks和source_facts另有预算，元数据也需要计算。原生模式保留作者设置；共同模式计算真正送给Reader的完整消息。[R6]

**⑤ 同步完成与费用透明。** 首版优先同步retain。确需异步时跟踪实际operation，确认完成后再答当前会话问题。内部生成、embedding、rerank和reflect都属于该方法成本；取不到的用量写未观测，不填零，也不阻止开发适配本身。[R8]

**⑥ context／metadata也是模型输入。** 官方retain会将这些字段提供给抽取模型，因此只能放实际来源已知的中性信息，不能把题型、更新标签、答案实体或未来事件塞入metadata。timestamp采用实际公开会话时间作为明确的报告锚点；未给定的生效时间仍未知，不让默认的机器当前时间替代历史日期，也不把一个会话锚点断言为其中所有事实的发生时间。[R8]

接入已有模型端点时，通过公开配置完成。原生依赖需要不同embedding或reranker时，先记录并保留原生对照；换成BGE的结果另叫本地同资源移植。不要通过猴子补丁改变原检索再声称原样运行。

### 6.3 原生与薄适配的等价检查不需要大量模型重跑

先保存一次原生调用的合法输入和实际返回。在不发新模型请求的情况下，将同一返回经薄适配交给Reader，确认顺序、文本、时间及截断标记没有改变。

如薄适配本身不增加调用，直接复用该原始返回用于适配观察，避免再构建一遍bank。需要研究生成波动时，预先固定重复次数，不挑一次好结果作为原生基准。

发现适配丢字段、改变角色或正文，即修适配；发现原生本就缺来源映射，即如实记录能力边界。两者不能混淆。

## 7. MiLAi的具体调整：对外变简单，内部能力保留

### 7.1 复用现有纯记忆路径，只补对外适配门面

**不能把当前benchmark说成必须经过业务分类。**现有配置已经区分functional与benchmark入口，本轮要做的是将已有纯记忆方法接入新的共同比较入口，而不是把它从Host中重新实现一遍。[G2][G3]

适配门面复用：

```text
ObservedSession
  → 现有Source捕获
  → 现有单轮／两阶段维护recipe
  → 现有实际提交
  → 普通检索
  → 直接Reader或已有staged读取
```

它不经过普通业务Host的保存意图分类、CURRENT应用计划、业务工具选择或遗忘凭据复制。实验配置已经声明这些历史用于记忆评测，这并不等于任意真实用户消息自动获得业务权限。

普通Host继续保留现有权限、对象、journal和恢复路径；两入口共用记忆实现，不要求两入口承担相同控制任务。

### 7.2 直接读取是正式对照，不是调试后门

新增一个明确的delivery设置：在已选择的合法检索结果能够放入时，直接交付给共同Reader，不额外调用Selector。

已有staged/state_driven作为独立候选；容量续读复用新代码。在无法完整交付时记录实际行为，不为了直接模式消除来源或例外。

直接模式不是默认一定更优；它用于回答：**第二次模型选择是否降低了本来足够的证据覆盖？**

### 7.3 语义状态与原始事件可以并存，但不能隐式补答案

原始Source/Episode仍被保留。语义形成失败不能删除原始事件；允许正常Host显式回原文核对。

共同实验分开：

- `semantic-only`：只看实际形成并检索出的语义状态；
- `semantic+source`：允许从当前合法历史正常检索原文。

首轮主比较选定一种并固定。只给MiLAi增加原文兜底而不说明，或检索失败后由评价器指定正确来源，都会破坏归因。

“原文保留”与“原文能被一般查询找到”是两项能力；不要把索引仅来自已提交描述的路径当作无条件原文兜底。

### 7.4 聚焦一个研究机制：来源支持的局部语义修订

首版不再增加新算法名。保留当前Editor并收敛其任务：

- 程序提供实际旧值、支持、ID和版本；模型只表达新增、更正、撤销及保留集合。
- 普通全量重写仍决定完整保留集合；引用式keep减少重抄，但未列内容不能被程序偷偷补回。
- 局部方法保留未编辑部分；发生局部规则变化时，也需要处理实际受影响的旧总述。
- 当前新消息中“可能、考虑、希望、已经”保持其原有强度；不因抽取结构化而自动变成确定事实。
- 旧肯定证据不支持新的撤销；旧支持可解释历史，新变化有其实际依据。

**需要检验的关键权衡：**减少附带损伤，不应以漏掉合法更新为代价；及时更新，也不应以删除未改条件为代价。

### 7.5 条件结构只承担明确语义，不强迫所有事实关系化

“北区新增每周四次，南区不变”可能同时要求新增北区安排、修订“两区均无单独安排”的旧总述，并保留南区现状。程序展开已明确的关系，模型判断自然语言中真正受影响的内容。

不能为了提高condition数量把普通分类、同时发生的事实或模型猜测写成适用关系。终态condition数量与操作次数只能作为机制使用统计，不是准确率。

### 7.6 Host功能线继续推进，但只做已有三个连续流程

复用最新两条已曝光故事及预先声明的重复安排，覆盖：

1. 保存→更正→实际保存历史；
2. 业务部分完成→剩余业务→只补保存→新实时查询；
3. 明确遗忘→重开→查询。

新短target必须绑定实际已交付凭据；候选导航不能授权操作。遗忘按真实撤销范围表达，不声称物理删除审计日志；查询必须区分当前新观察与旧Source；业务身份不得来自记忆自由文本。

三类流程共享两条故事，不能算作三个独立来源，更不能把重复执行算新增任务。[G2]

配置本身先保证一个普通用例能使用；版本、服务、数据和参数在启动记录一次。原始来源、答案和私有日志不推送到公开仓库。

## 9. 开发安排：功能接通后集中评价，不先建庞大矩阵

### 9.1 四个工作包

| 工作包 | 主要交付 | 最小完成证据 |
|---|---|---|
| **A：协议与数据入口** | 同一ObservedSession喂入、QA20/更新10分开、信息字段明确 | 一段普通历史按顺序写入；当前问题前没有未来会话 |
| **B：强基线与外部适配** | RawRAG-local＋Hindsight-native-local；原生返回薄适配 | 原生输出可保存、重开可读取，适配不重写内容 |
| **C：MiLAi纯记忆与交付** | 复用现有纯记忆调用，补共同适配；直接与staged可独立选择 | 不复制一套维护链；当前历史能形成、查询、更正 |
| **D：完整Host与统一结果** | 复用短target／实时query／续办；原答案与程序反馈分存 | 原连续流程真实执行，失败能够定位而不被COMPLETED掩盖 |

A给出一页协议约定后，B/C/D可并行；不要求每项先在benchmark上显著胜出才能集成。

### 9.2 多Agent分工

**一名集成者＋三名开发者。**

| 角色 | 负责 | 不得同时改 |
|---|---|---|
| 集成者 | 协议、配置、公共合同、资源调度、最终合流 | 不把评测答案交给方法开发者 |
| Agent A | RawRAG原生入口、Hindsight薄适配 | 不改MiLAi Editor与公共评分规则 |
| Agent B | MiLAi纯记忆门面、直接/staged交付、复用容量续读 | 不重写外部后端原生流程 |
| Agent C | Host三个流程、效果反馈、离线结果整理 | 不改变用户业务权限或把测试control送给Host |

每人独立worktree和临时bank；共享文件由集成者管理。真实模型调用统一串行调度，避免抢占当前运行端点。交接只写：已完成能力、修改文件、一个运行示例、已知断点。

### 9.3 开发过程中只反思四件事

每个工作包合流时简短记录即可，不设置审批会议或另一个核对Agent：

- 这次真正减少了哪一层不必要转换？
- 是否把外部方法的正常能力包装没了？
- 是否因为提高分数而改变了信息或时间条件？
- 是否同时改了多个因素，使后面无法解释？

## 10. 实验顺序：一个小型三方比较，再做必要归因

### E0：原生与适配接通，不以追到论文分数为完成条件

先用既有普通样例检查实际入库、查询、重开及来源时间传递。一个真实闭环后即可进入集中样本，不反复围绕同一姓名或偏好调提示。

Hindsight原生服务若在当前模型配置上不能正常运行，记录具体阶段；先修配置或薄适配。不要将“有API响应”视为正确，也不要将“达不到91%”视为接线失败。

### E1：三个系统、同一开发范围

首批固定使用现有四开发用户的前八会话：32会话、73题、72个原生更新机会。三个后端各自空库：

| 臂 | 目的 | 回答方式 |
|---|---|---|
| R：RawRAG-local | 不做语义修订的强简单参照 | 原文检索＋共同Reader |
| H：Hindsight本地原生记忆 | 独立外部参照 | 原retain/recall＋共同Reader；原生回答另列，不混入主列 |
| M：MiLAi纯记忆候选 | 检查MiLAi维护是否有净收益 | 现有Editor＋同一Reader；首轮用显式直接读取配置 |

三臂最多形成219个主QA输出机会，不把内部调用数当样本数。这个数字不包含选择性原生回答诊断、评分和Host运行。

已有501、1cfb等结果保留为历史，不直接填入这张新表。新配置改变模型输入或检索时，必须从各自初始状态运行；不接上旧bank后缀。

**先完成三个后端的预测，再独立评分。** RawRAG没有语义抽取输出时，形成F1为N/A；外部后端不支持会话输出时同理。不能通过额外Extractor补齐指标后仍称原系统。

E1目的是找最早差距，四个开发用户不承担总体统计显著性或最终论文泛化结论。

### E2：只针对E1的主要断点增加一项诊断

不默认全部运行下表。先确定最主要失败层，只执行能区分该层原因的一项。

| 诊断 | 固定 | 只改变 | 能解释什么 |
|---|---|---|---|
| 原生→薄适配 | 同一实际原生返回 | 输入传递和呈现 | 是否因适配丢失材料 |
| 直接→Selector | 同一检索池、模型、输出额度 | 是否二次选择 | 选择的收益或遗漏 |
| 原文→实际语义状态 | 同一合法历史范围、同一Reader | 使用实际原文或实际形成状态 | 形成／修订总体信息损失；不直接定位单个算子 |
| 条件结构→等义字面呈现 | 同一真实状态、同一来源、同一问题 | 关系的显示形式 | Reader是否用好表示；不能证明写入优势 |
| 同表示全量→局部算子 | 同一个实际前态、当前事件及可用证据 | 编辑算子 | 非目标损伤与更新落实是否改善 |

不能把“把正确目标人工塞进输入”当作正常系统结果。确需oracle/充分证据定位时，独立列为诊断上界；Writer、检索器和控制流仍不得接触gold。

### E3：检验MiLAi的增量作用，而不是把整个系统一起开关

当公共输入与读取可用后，复用现有B0/B1/B2/M/Append-only的定义，而不是再创一套名字相同、意义不同的组。**不要求每次E2修复后把五组全部再跑一遍**；先执行支撑当前主张的必要对比，最后候选再完成所声明的完整比较。旧501结果仅在源码与配置相符的分析中复用。

| 对比 | 主要解释 |
|---|---|
| B0 vs B1 | 普通表示下全量与局部编辑 |
| B0 vs B2 | 条件表示＋其接口的整体作用，不能只归因某条边 |
| B2 vs M | 相同条件表示下局部／例外操作 |
| M vs Append-only | 写时维护相对读时重建是否值得 |
| 最终MiLAi vs RawRAG/Hindsight | 系统级净收益和功能权衡 |

“终态没有条件边”不排除条件schema负担；“有条件边的用户更好”也不是随机化因果证据。自然连续历史是主结果，固定前态只是解释机制。

新RawRAG＋来源语义视图的混合路线仅在确有需要时启用；与RawRAG单独比较时，两者获得同样合法原文预算，额外整理和调用单列，不能把更多上下文当成局部修订优势。

### E4：确认与外部迁移

候选明确后再进行长历史、保留用户与外部任务。HaluMem继续用原四个开发用户合计277会话（分别65／77／62／73）及既有时间顺序；每个方法独立运行这组历史，首用户65会话是该方法277会话的子集，不重复另跑。最终采用的新版本不能将旧前缀拼成完整结果。

LongMemEval先用已有28个注册case检查迁移；500题完整协议或其他扩大范围须单独声明，不拿28题描述整个榜单。HaluMem的16保留用户按既有访问记录与隔离安排处理，不宣称程序从未解析过任何其元数据。

对重复／重叠历史按实际来源分组。HaluMem按用户给配对结果；LongMemEval按问题及实际重叠情况说明独立性。最终必要重复预先固定次数，不挑最优一次。

## 11. 评价什么：更新完成与保持必须同时成立

### 11.1 主指标

| 指标 | 解释 |
|---|---|
| QA Correct / 全部已声明机会 | 主端到端指标，报告准确分子、分母、缺答和invalid |
| 官方更新标签 | 按作者口径从当时状态评价，不等于UPDATE动作计数 |
| 形成召回／准确性 | 仅基于后端真实会话输出；不支持则N/A |
| 新要求落实 | 该事件真正要求的变化是否在实际状态中可用 |
| 非目标保持 | 变化前已正确且变化后仍有效的内容是否受损 |
| 来源与模态忠实性 | 主体、说话者、报告／发生时间、计划／完成是否正确 |
| 功能完成 | 保存、核对、遗忘、恢复是否达到真实用户要求 |

“什么都不写”可以降低删除率，但新要求落实失败；“全部保留”可以提高覆盖，但保留过时状态也可能失败。不能只优化一个指标。

### 11.2 可解释的最早断点记录

复用现有逐题／维护产物，最多补一个简短原因字段：

```text
原事件未进入 → 形成／更新失败 → 当前状态正确但池外
→ 池内未选 → 选中未交付 → 证据不足
→ 证据充分但Reader错误 → 业务／恢复／反馈错误
```

具体案例可能跨层；主归因使用最早已确认断点，其他作为附加观察。没有独立来源核查时，“Judge判Hallucination”不自动等于已确认事实幻觉。

对一次早期身份漏写引发多题错误，同时报告原始QA影响和根因事件数；不能把所有后续失败都当独立错误机制。

### 11.3 invalid、unknown与未运行

- 已知未发送、没有答案的只读失败在对应已尝试机会中保留缺答；不是成功，也不是假装模型答错。
- 正式答案存在但Judge不可判时保留invalid，报告有效判断与全部机会两个分母，不静默重命名标签。
- 尚未运行的用户／问题不填零，不把部分轨迹称完整准确率。
- HTTP结果、写入或业务效果未知时沿现有恢复规则核对，不盲重试。
- 源文与参考冲突保留原官方分数，另列来源审查；不修改Source追参考答案，也不只挑冲突案例重评分。

### 11.4 实用收益与统计不夸大

小开发集只作描述性选择：给出每用户配对差、错误类别和成本，不以73题中多答对一两题宣布算法优势。

确认阶段先冻结主指标、实际重复、主要对比和可接受的退化范围。采用配对报告／按用户或来源组汇总；缺少足够独立历史时明确不确定性，不以数百次Judge调用冒充数百个独立样本。

有效性不只等于总QA上升：若QA相近，但在真实连续更正中显著减少范围错误和附带损伤，可以提出限定主张；如果只有接口成功率提高，应定位为工程收益；如果只有更大预算才提高，应明确资源权衡。

### 11.5 成本与输出身份

记录形成、检索、选择、阅读、外部内部生成、embedding／rerank、Judge各阶段成本；同时看峰值上下文和累计token，不只看某次输入变短。

原始模型答案与程序追加回执分别评分。完整用户输出可以评价系统可用性，但不能把程序补充的事实算成模型自主推理成功。实际回执只证明操作与字段，不保证整段解释受支持。

## 12. 最少必要检查：检查接口，不把测试平台变成主要产物

开发期仅保留直接受影响的四类检查，尽量复用已有用例：

| 检查 | 为什么不可省 | 范围 |
|---|---|---|
| 时间前缀和字段投影 | 避免未来信息／gold进入方法 | 一个短序列和现有ObservedSession检查 |
| 外部原生返回→适配返回 | 避免包装器改坏有效方法 | 一个已保存响应，不要求再调用模型 |
| 保存→重开→查询 | 检验持久路径确实接通 | 每新增后端一个正常流程 |
| 修改或遗忘相关边界 | 避免数据损坏和越权 | 仅修改到的现有SQLite／工具用例 |

不新增庞大测试矩阵，不对每个提示改动跑全仓，不按通过测试数量计研究进度。合并需要的既有CI照常；测试覆盖有价值，但不能替代真实任务效果。

发现语义漏写、模态强化时保留案例，继续完成其他功能，再集中分析。越权、跨bank泄露、未知副作用或数据损坏先修，不因“功能优先”继续制造效果。

## 14. 根据结果选择下一步：允许简化，不预设结论

| 实际发现 | 判断 | 行动 |
|---|---|---|
| RawRAG与Hindsight好，MiLAi差 | 自建形成、筛选或呈现可能损失信息 | 在固定状态上一次绕开一个环节，不同时加新模块 |
| 原生外部好，薄适配后差 | 传递、截断、时间、角色或Reader不同 | 先修适配，不重写外部算法 |
| RawRAG好，所有语义记忆都差 | 当前来源抽取／压缩可能不适合该任务 | 原文路径作为功能底座，语义视图增量启用 |
| 直接读取好，staged差 | Selector过滤未显示净收益 | 该任务默认直接；只在实际容量需要时用staged |
| MiLAi更新变好但QA不变 | 读取或题型未体现收益 | 检查真实证据链；不能只靠操作统计宣称有效 |
| MiLAi QA提高但来源更差 | 可能迎合参考或过度推断 | 不作为可信改进，定位来源与Judge差异 |
| MiLAi与普通局部相当 | 条件复杂度尚无净收益 | 保留普通局部；条件仅用于真实必要的范围／例外 |
| 强追加式同样或更好 | 写时修订未显示优势 | 接受追加式为默认，对修订缩小主张 |
| 三者在充分来源下都差 | Reader能力、任务歧义或参考冲突 | 单独诊断，不继续无目的扩大检索 |
| QA可用而Host遗忘失败 | 产品交互未可靠 | 继续独立修Host，不否定全部记忆问答 |

旧v13.4的Simplify只收口当时未建立重复必要性的复杂关系消歧分支；本文不恢复旧分支，也不将其扩张为禁止研究当前局部修订。[H2]

## 15. 论文定位：只保留能够被数据支持的一条主线

建议将核心主张聚焦为：

> **在真实事件保留和强普通检索可用的基础上，来源关联的局部语义修订，能否减少连续更新中的附带损伤，并使当前状态与历史适用性更可靠？**

需要三类证据共同支撑：

1. **系统级**：在对齐协议下，最终任务不逊于或优于强简单／独立原生参照。
2. **机制级**：实际状态的改善可归因于需要检验的修订机制，而不是更宽检索、不同Reader或额外身份信息。
3. **迁移级**：冻结候选后，在未用于当前调参的用户／来源中仍观察到相应作用。

条件表示、JSON补丁、多键检索和分阶段阅读本身已有先例。创新应落在明确机制及其可重复效果，不把模块组合、节点数、测试数量或复杂元数据当原创性证明。

五条工程方向全部保留，但论文不需要同时声称解决全部业务恢复、所有遗忘语义及所有认知机制。若最终贡献主要是可用接口和失败边界，应如实定位；如果方法产生稳定增益，再扩大相应主张。发表等级不是结果保证，不能为追求正结论牺牲来源与实验诚实性。
