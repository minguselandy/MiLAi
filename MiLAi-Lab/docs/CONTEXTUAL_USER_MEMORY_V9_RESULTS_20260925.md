## B–D：已接通的合同与必要检查

实际组合为 method v14／write v13／material view v9／ingestion v30／operation v2／maintenance v3／runtime store v1。v9 配置显式选择 `turn-maintenance-v3`；旧 v2 保留独立合同，配置及协议身份检查阻止混用旧库。本次只改变 Lab 研究协议，没有修改 Product Schema、权限或 Canonical 行为，也没有移动包边界或打包入口。

终结时 Host 仅给出 `processed`、`not_selected` 或 `pending` 及真正剩余项；程序计算实际提交、业务结果、已交付范围和未审阅范围。零写入不会生成假提交。可信审阅／持久化义务不能被 Host 降级；普通可选材料可以部分或尚未交付，未读范围如实保留。缺少应用硬性持久化义务不代表没有语义维护责任。

MaterialView 与写入解析共用 session 的实际绑定，区分完整可改目标、已交付来源正文、链接和既有关系。显式 delta 只接受准确目标版本、正文 patch、来源增减及可选依赖增减；归一化保留旧关系的稳定顺序，复用 CAS、生命周期、权限与依赖校验。继承不会伪装为本轮阅读，撤回只需已交付目标关系；主体、范围、时间等变化继续走完整替换。`basis_change` 在现有版本历史中保留继承、新增、撤回与实际阅读范围，没有第二套可见性账本。

窄检查为材料／增量／ingestion／准备及适配器 62 项、维护／Host／store／恢复 58 项，均通过；后续源码清单修正、可选未交付材料和 v3 提示修复仅重跑各自受影响的 1、2、3 项及相关 Ruff／mypy。部署环境 vLLM 0.27.1／xgrammar 0.2.3 的 16 个 grammar 探针全部通过，无生成请求。没有运行全量测试、benchmark 或构建。

恢复检查 `test_v3_raw_business_result_recovers_in_new_process_and_finishes` 使用两个真实子进程及确定性 Provider：第一个进程在原始成功业务结果落盘后故障；第二个恢复同 session／turn，Host 再次提出相同已完成动作被 `RECOVERED_ACTION_ALREADY_SETTLED` 拒绝，再真实提交记忆并终结。业务计数与 intent 数均保持 1；不是仅检查运行器没有自动重放。此限制只用于明确恢复时已经结算的动作，新轮次及恢复后产生的新合法动作不做全局参数去重；unknown 仍需核对业务结果。这是受控本地恢复证据，不是任意外部系统的 exactly-once 保证。
