# MiLAi 小模型记忆策略控制
## 开发、训练与实验规划 v1.0

**日期：2026-11-16｜资源：2 × NVIDIA A100 40GB｜研究目标：可归因、可复现的训练收益**

**基线版本：** `minguselandy/MiLAi@2b4b17383d8d892d21651b02130b9e33deab5bec`。本次核对了主分支、Reader 效用报告及策略执行／训练导出／Laya 投影接口；不是对全仓库或本地 GPU 产物的重新验收。[P1–P5]

**文档性质：** 本文是待执行的开发实验方案，不是已训练成功的结果报告。未启动训练、修改仓库或消耗用户 GPU。所有样本量、超参数、预算分配和验收阈值，除明确标注为历史实测或论文信息外，均为本方案的设计值。

**核心决策：** 不绑定 Jev、Laya、JEPA 或任何单一模型家族；保留已有记忆服务和执行链，训练可替换的小型策略网络。优先建立“冻结表征＋小网络”“可微调编码器”“0.6B 小语言模型一次前向读出”三条可比路线，再根据任务收益决定是否扩大模型或采用强化学习。

**最终完成定义：** 工程接线、数据导出、训练收敛和 checkpoint 保存均不是项目终点。必须证明训练后的策略在新的真实任务上，比训练前的可用策略更有效，并达到预先选择的质量优势或质量约束下的成本优势。若未达到，应继续有针对性的算法探索；不得用更换分母、删除失败、挑选 seed 或重新定义主指标制造成功。

## 执行摘要

本轮围绕一个主问题展开：**在固定任务模型与记忆执行器的条件下，小模型能否学习“何时读、读什么、交付什么、何时停”，并在后续阶段学习“何时维护、如何选择维护操作”，使真实任务结果改善？**

项目采用“一个执行环境、三个模型路线、两类任务、分阶段学习”的结构。第一阶段固定 Writer 和 Reader，只学习读取与停止，避免把记忆形成、答案能力和策略控制混在一起。第二阶段再学习工作集交付和预算分配。第三阶段扩展到跨会话维护与未来任务反馈。创新探索与可靠基线并行，任何高级机制都必须证明优于同骨干、同数据的简单方法。

| 工作线 | 必须得到的结果 | 不接受的替代结果 |
|---|---|---|
| 可学习性验证 | 数据里存在可判定、可利用的动作差异；小模型能学到且泛化 | 只发现训练 loss 下降 |
| 策略控制 | 实际调用训练模型并改变完整动作绑定；任务收益可归因于这些变化 | 只有动作类型准确率、执行次数或代码测试 |
| 质量与成本 | 在固定主指标和新来源上形成可靠质量／效率证据 | 只在局部 proxy、旧 DEV 或单个正例胜出 |
| 创新机制 | 至少一个机制有消融、反例、适用边界和跨条件验证 | 将“小模型＋RL”或已有方法改名作为创新 |
| 开发交付 | 可恢复训练器、统一适配器、模型产物、复现实验和失败记录 | 大量新框架、状态文档与审核器代替训练 |

首轮优先顺序：**测量可用 → 强基线与数据上限 → 三路线小规模真实训练 → 同状态结果学习 → 自身状态再采集 → 固定候选的新来源确认 → 跨会话维护。**

## 1. 目标、范围与研究约束

### 1.1 三个层次的目标

**G1，训练有效。** 在相同状态投影、动作空间、数据划分和任务环境中，训练后的候选优于同骨干的可用训练起点。随机初始化策略只能作为管线检查，不能作为唯一效果基线。

**G2，方法有效。** 候选还要优于事先固定的强简单策略，或者在明确的质量非劣约束下显著降低完整系统成本。超过旧 Laya 但未超过强固定策略，只能称为旧方法改进。

**G3，研究有效。** 至少一个机制贡献能够解释“为什么有效、在哪些条件有效、什么条件下失败”，且不依赖换 Reader、扩大可见证据、暗增预算或候选生成器偷做决策。

三个目标分别验收。达到 G1 不自动满足 G2；达到 G2 也不自动证明论文新颖性。最终交付必须明确各项状态，不以工程完成替代科研完成。

### 1.2 本轮必须做与暂不做

| 必须做 | 暂不作为主线 |
|---|---|
| 统一完整动作评分；读取、交付、停止学习 | 从零预训练语言模型 |
| 原有执行链内的模型替换和训练数据导出 | 建设第二套 MemoryService、Agent 框架或数据库 |
| 同状态实际分支反馈、自身状态采集 | 一开始进行 Writer＋Reader＋View 全系统联合 RL |
| 表征与决策头的分离对照 | 强制采用 Jev／Laya／JEPA／世界模型 |
| 新来源、连续任务、预算与 Reader 迁移 | 以论文故事为由提前固定复杂模型 |
| 实际 GPU 吞吐与完整系统成本 | 以 GPU 使用率或训练 tokens 取代任务收益 |

### 1.3 保持探索性，但不无限扩展

建议将一期可支配算力按 **60% 主线训练与确认、20% 数据和测量校准、20% 创新分支**分配，阶段结束后依据实际计量调整。比例不是硬件占用承诺，也不代表各类作业同时运行。

任何分支启动前填写一页实验卡：假设、最接近工作、唯一主变量、对照、预期诊断、停止／转向条件。失败可以触发新假设，不允许仅因为一次结果不理想就放弃全部研究；也不允许把同一无效配方扩大十倍当作探索。

### 1.4 工程风格

以真实训练和功能闭环优先。仅保留必要的动作合法性、来源可见性、版本一致性、预算和训练数值检查；不增加层层注册、重复审计、自动兜底或大规模状态证明框架。程序错误应明确失败并记录，不偷偷切换成固定策略、不自动重跑直到成功。继续保留权限和不可逆业务边界，这些不属于可取消的防御性冗余。

## 2. 当前基线与需要修正的研究假设

### 2.1 已确认的历史证据

最新合并包含 Reader 效用与决策学习工作。报告中 E4 新来源确认的强固定策略为 116/256 个完整受支持首次答案，10k＋Q 为 92/256；主比较为 −9.375 个百分点，来源配对 95% 区间为 [−15.625，−3.125] 个百分点。未知判断、同模型评审和单训练 seed 仍限制真实质量解释。[P1,P2]

已有 600 个质量反馈机会，最终形成 331 个可用材料质量状态，其中 249 个有方向、82 个为正质量平局。600 不能写成 600 个可靠监督样本。旧弱评分可用于辅助，但不应等同于材料充分性或任务成功。[P2]

自然应用中 129 次 View 构建、14 次复用均未成功交付；自动评审还存在已知正例被屏蔽为 unknown 的问题。它们首先是交付和测量故障，不能用更多训练直接掩盖，也不能据此判定 View 无价值或真实成功率为零。[P2]

### 2.2 实际可复用接口

| 已核对入口 | 已有能力 | 本轮改动原则 |
|---|---|---|
| `methods/memory_control.py` | `MemoryAction`、`MemoryControlState`、`MemoryPolicy.choose`、实际执行与单步干预 | 保留唯一执行入口；新模型实现同一策略接口 |
| `methods/memory_control_learning.py` | 训练例导出、审阅偏好、标签屏蔽与离线指标 | 抽离对 Laya 投影的依赖；保留旧导出兼容性 |
| `methods/laya_memory_policy.py` | 完整动作绑定、共享状态投影、已观察与已交付材料区分 | 形成模型无关投影；Laya 作为适配器与历史对照 |
| 已有来源／版本／支持路径 | 为来源忠实、变更和局部更新提供基础 | 先清点并复用，不再创建平行图系统 |

前三项源文件已读取；最后一项还须在开发时确认具体调用路径与测试覆盖，不能仅凭文件名认定已完成集成。[P3–P5]

### 2.3 本轮要避免的六个误判

模型选择变了，不等于任务变好了；动作与教师一致，不等于教师正确；更多 READ 不等于更多有效证据；token 减少不等于总成本减少；View 构建不等于交付；重复训练很多步不等于学习到了可迁移策略。

因此，本轮最重要的结构性变化不是“再加一个更复杂的头”，而是让**信息条件、动作绑定、训练反馈和最终任务结果可以逐层归因**。

### 3.1 直接采用的设计依据

| 研究 | 可借鉴内容 | 不能直接声称为 MiLAi 新贡献 |

| BudgetMem，ICML 2026 [R1] | 学习成本档位，显式比较质量—成本 | 小控制器分配记忆预算 |
| Memory-R1，ACL 2026；AgeMem，ACL 2026 [R2,R3] | 可学习维护操作、分阶段训练 | ADD／UPDATE／DELETE 加任务奖励 |
| Memory-R2，2026 论文 [R4] | 共同中间状态的局部分支比较 | 同状态反事实信用分配本身 |
| Memento，2025 论文 [R5] | 固定大模型，轻量案例选择策略 | 冻结大模型后训练小选择器 |
| MemSifter，2026 论文 [R6] | 结果驱动的记忆筛选 | 相关性改成任务效用 |
| Set Transformer；DAgger [R7,R8] | 集合交互、自身状态分布学习 | 集合注意力或迭代聚合数据本身 |
| Small Heads, Strong Decisions，2026-11 预印本 [R9] | 在共同协议下先比较简单头与骨干 | 直接把结构化判断结果外推到长期记忆控制 |
| MemCredit，2026-11 预印本 [R10] | 状态、上下文与策略条件化的记忆效用 | “反事实记忆贡献＋小效用网络”这一总思路 |

表中论文机制仅作为设计依据；论文中的成绩不作为本项目成绩。未逐项确认正式录用的工作只标“论文／预印本”。本计划不依赖某篇论文对自身性能的宣传结论。

### 3.2 建议保留的四个可证伪创新假设

**H1：交付感知的动作价值。** 控制器显式区分“候选可见、正文已观察、当前被选择、最终实际交付”，比只看检索相关性或动作历史更能避免读取后遗失证据、重复获取和错误停止。最小对照是同骨干、同数据，移除这些状态字段。

**H2：候选集合条件化。** 对候选动作与已知证据联合建模，可以识别冗余、互补和替代支持；收益必须出现在实际选择和终点结果，而不是只出现在人为构造的集合分类题。

**H3：预算可迁移的策略。** 将预算作为输入，并按多个实际预算训练，可使同一 checkpoint 在不同预算下调整行为，而不是针对每个预算重训或靠硬编码阈值。须控制实际候选生成和编码成本。

**H4：小策略与任务模型可解耦。** 在至少两个 Reader 条件下，控制器无需为每个 Reader 完整重训，仍能保留部分质量—成本优势。若奖励严重依赖特定 Reader，需研究低成本校准，而不是宣称天然可迁移。

版本／依赖感知的更新控制作为第二阶段 H5；仅在读取主线建立可靠反馈后启动。以上是假设，不是“首创”声明。最终论文只保留有消融和边界证据的机制。

## 4. 任务形式化与系统边界

### 4.1 控制状态与实际环境状态分开

将控制过程视为部分可观测序列决策，而不是未经验证地假设一个短摘要就是完整 Markov 状态。实际环境包含数据库、原始来源、业务状态和完整历史；策略只读取合法可见的观测：

`o_t = (q_t, K_t, O_t, C_t, H_t, B_t, V_t)`

`q_t` 是任务目标；`K_t` 是当前拟交付材料；`O_t` 是已观察但未必交付的材料；`C_t` 是候选及合法动作；`H_t` 是最近操作与真实结果；`B_t` 是预算；`V_t` 是角色、时间、版本与可见性。

只有实际调用允许读取的内容才能进入策略输入。索引中已有的原文编码若包含策略尚未获准读取的完整正文，使用该编码也属于信息暴露，必须显式设为一种更强观察条件、计入获取成本并对所有方法公平开放。

### 4.2 两个时间尺度

| 时间尺度 | 触发方式 | 主要决策 | 第一轮状态 |
|---|---|---|---|
| 快速读取控制 | 当前任务内部每次真实操作后 | SEARCH、READ、选择交付、HANDOFF | 主线必须完成 |
| 低频维护控制 | 新来源、修订或任务结束时 | 是否创建／更新／整理／保留；选择已提议的编辑 | 第二阶段学习 |

小模型负责决策；大模型在必要时负责复杂内容提案和最终回答；程序负责权限、对象绑定、实际操作和容量计量。控制器不能直接把记忆文字当成业务完成回执。

### 4.3 第一轮动作空间保持现有合同

现有 `Operation` 包含 `SEARCH / READ / USE_VIEW / REFRESH_VIEW / HANDOFF`。[P3] 第一轮不新增十几个动作类型。选择、保留、换出等行为优先通过已存在的参数化 HANDOFF 与交付机制表达；确需新语义时作为独立版本实验，不热改正在评测的动作空间。

每个动作是完整绑定 `a=(kind,target,parameters)`，策略返回其本地 ID。ID 只负责查找，不承载题号、标签、全局排名或隐藏真值。动作类型预测只能作为辅助指标。

### 4.4 强制结束与主动停止分开

只有一个合法动作、预算耗尽、环境故障和策略主动 HANDOFF 都可能结束轨迹。四者必须分别记录。不得把所有终点统称为“学会停止”。单一合法动作的状态不进入策略优劣主监督，但保留在轨迹成本与执行率统计中。

## 5. 模型路线与最小结构

### 5.1 三条必跑路线与一个历史对照

| 编号 | 结构 | 首轮建议 | 作用 |
|---|---|---|---|
| M0 | 冻结已有文本表征＋MLP 动作价值网络 | 256 维隐层、两层 MLP；可训练量以实测为准 | 检验任务是否真的需要更大骨干 |
| M1 | 编码器＋轻量候选交互＋动作头 | 约 0.1B–0.4B 级候选；先简单头，再加一至两层交互 | 主线的低延迟结构 |
| M2 | Qwen3-0.6B 隐状态＋直接动作打分 | 不生成推理或 JSON；先简单余弦／MLP 头 | 较强语义表征的并行主线 |
| M3 | 同 M2，但使用 1.7B 骨干 | 只有语义诊断或 scaling 证据支持时启动 | 检验模型能力瓶颈 |
| L0 | 当前可复现 Laya/S1 与旧 10k＋Q | 保持各自原输入条件；适配对照另列 | 历史价值与退化定位 |

Qwen3-0.6B／1.7B 是官方开放型号；ModernBERT 的官方 base／large 为 149M／395M，但以英语与代码为训练背景。中文主任务不能未经验证直接默认 ModernBERT 合适。[R11–R13]

M1 的具体中英骨干通过一个独立的语义诊断集选择：主体交换、否定、数字阈值、有效日期、局部例外与来源角色。选择仅用 TRAIN／DEV；不可先看最终任务分数再切换语言覆盖策略。

### 5.2 推荐的统一前向接口

输入包含状态文本／结构特征、N 个动作描述、合法性 mask，以及可选的候选关系。输出包含 N 个未归一化动作分数、可选的价值预测和成本预测。所有路线适配到同一接口，执行器不依赖模型名称。

参考计算：

`h_s = StateEncoder(o)`

`h_i = ActionEncoder(kind_i, visible_target_i, parameters_i)`

`z_i = Interaction(h_s, {h_j}, h_i, features_i)`

`score_i = MLP([h_s, z_i, h_s*z_i, features_i])`

第一版可令 Interaction 为恒等映射。候选交互的额外收益与额外成本必须单独测量，不因为名称更复杂就默认更先进。

### 5.3 排列等变与候选 ID

对集合路线，打乱候选输入顺序后，应将输出分数按对象映射还原，比较是否一致；不要把原始位置 embedding 当作语义特征。真实检索 rank 可以作为显式特征保留，并单独消融。

Decoder 路线因因果注意力可能受排列影响，不能声称天然等变。训练中进行位置随机化；评估使用事先固定的多种排列，只报告稳定性，不进行排列搜索或多数票提高主要成绩。候选别名重命名后也应保持同一完整绑定选择。

### 5.4 内容生成与动作评分分开

第一轮不让 M2 一边生成查询、一边生成编辑、一边生成回答。候选查询来自当前问题、已知要求或固定候选提出器；复杂维护提案来自固定生成模块。小模型只选择已存在的合法绑定。后续若研究生成式提案，必须计算提出器成本，并与“同小模型短动作生成”做独立比较。

### 5.5 参数量与成本披露

分别报告总常驻参数、可训练参数、编码器参数、决策头参数、embedding 服务和 Reader。不得只报 0.5M 决策头而省略其背后的 0.6B 骨干；不得把固定大模型从整体方法成本中消失。

## 6. 状态表示、上下文与缓存

### 6.1 三种信息条件必须显式区分

| 条件 | 内容 | 用途 |
|---|---|---|
| V0，机械状态 | 类型、长度、rank、预算、操作结果等；不含新增语义正文 | 检查数据捷径和元数据是否已足够 |
| V1，合法语义状态 | V0＋实际允许的片段、已读正文、任务文字和来源属性 | 主条件 |
| V2，完整已观察状态 | 在原权限范围内保留更多已获取正文及历史操作 | 表征上限与压缩损失对照 |

V2 不是把尚未读取的完整数据库交给策略。若设计 full-pool oracle，只能作为离线诊断上限，单独计费、单独标记，不进入部署策略或主要公平比较。

### 6.2 初始长度配置

设计起点：状态文本目标 1,024 tokens，最大 2,048；候选文本每个目标 96、最大 192 tokens；每次最多 32 个展示候选，必要时沿原分页机制查看更多。它们是调优起点，不是数据已经满足的事实。

选择器不能只看到句子中间而丢失否定、条件或有效时间。截取应以完整语义单元／来源范围为基础；不能容纳的状态明确记录为超长分层，并测试分页或更大窗口。不可删除超长难例后只报告容易子集。

Decoder 联合输入可以先设 4,096、再试 8,192 的总上限，但状态、候选和特殊 token 必须一起计量，不能把分项上限简单拼接成永远可容纳的承诺。所有模型记录实际长度与丢弃内容类别。

### 6.3 静态内容与动态条件分开编码

来源内容、稳定候选描述可以缓存；query、预算、最近结果、已观察／已交付状态以及有效版本动态编码。微调编码器时，训练必须使用可求梯度的当前编码，不可继续使用冻结前缓存冒充端到端微调。

线上缓存键最少包含来源 ID、来源版本、编码器版本和投影版本。无需为每个 token 或每次访问再建立重复指纹门禁。模型或内容变更后正确失效即可。

### 6.4 不要求模型“看到金标准支持路径”

支持关系可作为输入的前提，是它来自实际存储或合法已读材料。离线人工标注的 proof、未来修订和答案不能作为在线特征。用这些信息构造标签时，必须保留在线输入与离线监督的独立字段。

## 7. 数据集、划分与样本单位

### 7.1 两条任务轨道，不混成一个总分

**R 轨道：读取与停止。** 固定 Writer 产生的来源／记忆库，评价当前问题的证据获取和最终回答。用于第一轮建立训练效应。

**L 轨道：长期维护与连续任务。** 允许不同策略产生不同的记忆状态，评价后续多任务完成、修订处理和非目标保持。不能要求这一轨道各方法拥有相同终点记忆库。

LongMemEval 可作事实记忆的外部参照；MemoryAgentBench 覆盖增量交互记忆能力；MemoryArena 专门连接跨会话记忆与行动。采用时须分别固定原生协议和共同条件改编协议，不能将改编分数称为官方成绩。[R14–R16]

### 7.2 数据分工

| 数据来源 | 训练／评测作用 | 关键限制 |
|---|---|---|
| 旧 MiLAi TRAIN 轨迹与分支 | 接线、warm start、错误诊断、旧弱标签辅助 | 重新清点输入条件；旧 weak／unknown 不升级成强标签 |
| 可执行的程序化记忆环境 | 提供时间、例外、主体、修订和重复读取的准确状态反馈 | 只证明受控环境机制；与自然任务分开报告 |
| 新自然来源与真实问答 | 主训练与来源级泛化 | 按文档、用户及依赖组隔离；不得复制旧确认集 |
| 公开原生基准 | 外部验证与跨环境迁移 | 核查协议、许可证、规模、污染和是否允许训练使用 |
| 连续业务／工具轨迹 | L 轨道的真实结果反馈 | 使用隔离可复位环境，不对用户真实业务做随机探索 |

### 7.3 划分规则

在生成分支前按根来源、用户和已知依赖组分割，派生 query、重写、翻译、同历史多切点、cold／known 版本和中间状态都随根归组。相同来源不能先分支再随机分行。

保留四个不混用的集合：TRAIN；DEV-fit（调超参数）；DEV-select（挑模型与机制）；CONFIRM（最终确认）。旧 E4 已暴露，只能用于历史比较和诊断，不能再宣称是新留出。外部任务再单独保留。

### 7.4 计划规模与触发条件

以下是生产目标，不是已有库存。实际数目必须以来源清点和有效标签产出为准。

| 阶段 | 独立根来源目标 | 决策／标签目标 | 进入下一阶段依据 |
|---|---:|---:|---|
| D0，真实管线与可学习性 | 64–128 | 256–512 个状态，部分状态 3–4 个实际分支 | 标签可靠且动作存在可利用差异 |
| D1，首轮模型筛选 | 约 500 | 5k–10k 合法状态；至少 2k 可比较监督状态 | 三路线都有真实训练与 DEV 任务读出 |
| D2，主训练 | 1k–2k，依可用来源 | 20k–40k 状态；目标 5k–10k 可靠结果监督 | 学习曲线仍改善且非重复曝光假象 |
| D3，自身状态 | 来自 TRAIN 根来源 | 两轮各 1k–3k 新到达状态 | 覆盖部署分布、继续／停止边界和新失败 |
| CONFIRM | 由功效分析确定；目标约 1k 独立单位 | 每任务每方法首次完整执行；固定子集重复 | 达到预注册精度，不靠相关行数凑 N |

正式数据集不足时，必须调整可宣称的效应范围，或使用预先设计的新研究测试集并明确标成扩展集。不能把一个公开 benchmark 的有限历史拆成很多“独立来源”，也不能将多个异质基准的分数简单拼接来填样本量。

### 7.5 数据配额是覆盖措施，不是效果保证

TRAIN 初始按正常获取、冗余／已充分、缺口／不可回答、主体／时间／例外、多条互补、操作失败与恢复六类做覆盖。先均衡来源，再平衡决策类别；正式报告仍显示自然分布成绩。主动采样额外保留至少 30% 随机探索配额，避免只收集当前模型争议或失败附近的数据。

## 8. 同状态分支与监督生产

### 8.1 分支实验的原子单位

每条分支比较固定一个实际 before 状态、合法完整动作菜单、可见来源版本、Reader 配置及后续策略。执行不同首动作后，用相同的已声明续跑策略完成任务。比较单位是同一来源中的同一机会，不是不同轨迹随意找两个相似状态。

优先执行 3–4 个分支：立即 HANDOFF；强固定策略动作；当前学习策略动作；一个覆盖不足的合法替代。三者相同时，不重复造出不同动作；保留真实去重和分支数。互补组只在合法支持结构／候选组合提供时加入，不能用 gold 偷选组合。

### 8.2 局部和完整轨迹两个目标

`h=0` 观察动作后直接交付的收益；`h=2` 观察相同后续策略的有限续跑；完整任务滚动用于主评测和少量校准。三种结果分开存储，不能把短程收益伪装成长期价值。

结果效用定义为：`U = task_success - lambda * incremental_cost`。其中 success 的精确定义按任务固定；费用权重只在 DEV 调整，原始质量、token、调用数和时延仍分别报告。未知语义结果不填零，也不参与方向性排序。

### 8.3 稀疏标签不得当成穷尽真值

设 O 为实际执行且可比较的动作集合。监督只约束 O 内的相对优劣；未执行动作不得自动标成错误。观察子集的 softmax／KL 应仅在 O 内计算并记录 scope。在线仍在全部合法菜单中决策，因此必须通过探索和全轨迹评测检查未监督动作的行为。

“best observed branch”只是在已测分支中的最佳结果，不是全动作空间的 oracle。重复 Reader 后再选最高分会产生选择偏差，只能作为上界诊断，不作为策略任务成绩。

### 8.4 标签来源等级

| 标签等级 | 来源 | 训练使用 |
|---|---|---|
| A | 隔离环境的明确成功条件、确定性状态与实际操作结果 | 可用于已定义范围的任务监督 |
| B | 实际材料与回答的经校准审阅，含盲化复核和可追溯判断 | 用于任务／支持监督，保留不确定性 |
| C | 答案 token 似然、相关性、教师偏好、规则近似 | 低权重辅助或采样；不可直接代替 A/B |
| U | 无参考、评审不确定、输入不完整、未执行 | 对相应语义损失 mask；保留执行和成本记录 |

A 级程序标签只覆盖程序确实定义的属性，不意味着自然语言含义已全部验证。引用定位成功也不自动升级为语义蕴含成功。

### 8.5 反馈成本预估与停止扩量条件

调用量先按下式预估：`calls = states × unique_branches × reader_repeats + review_calls + continuation_calls`。例如 1,000 个状态、平均 4 个分支、单次 Reader，至少有 4,000 个 Reader 位置；它不包含分支中的继续读取、来源评审与重采样。

每关闭一个块报告：可比较状态比例、方向性标签产出、每千输入 token 的有效监督、不同来源覆盖和成本。如果有效产出过低，先定位标签／任务／候选问题；不要用低质弱标签自动填满目标 10k。


## 9. 测量与标签校准：不让评审故障决定训练方向

### 9.1 主指标先于模型筛选固定

R 轨道的首选主指标是“计划任务中，首次输出完整且由实际交付材料支持的比例”。执行失败留在计划分母；语义未决与确定不成功分开列出。若自然来源评审不能达到可用性要求，不能把该指标直接写成“真实成功率”。需保留验证标签率与未知识别区间，并用可执行任务主指标或经过盲化复核的新评测协议继续研究。

L 轨道优先采用原环境定义的完整任务成功，同时报告部分成功、重复副作用、更新准确性、旧信息保持和总成本。HTTP 成功、工具执行成功与任务成功分别记录。

### 9.2 校准包与校准目标

先创建 200 个固定校准实例，覆盖受支持且完整、支持但不完整、不支持、执行失败和真正未知；正反例都要有。建议其中至少 100 个由未参与模型选择的人按盲化方法核对，并对全部分歧进行裁决。若无独立审阅者，明确标为作者核对，不虚构独立性；确定性环境仍可继续提供训练证据。

建议进入正式自然任务比较前满足：已知正例召回至少 90%、已知不支持例误报不高于 5%、已知例被格式规则误屏蔽比例不高于 5%。这些是本项目校准设计值，必须附样本数和区间；达到点估计不等于总体误差已精确确定。

### 9.3 四个标签轴不合并

每个实例保存 `execution_status`、`material_sufficiency`、`answer_support`、`answer_completeness`。输出 JSON 不合格式、引用 span 不匹配、证据不充分和答案错误，不能一律变成 unknown，更不能为了训练方便一律变成负例。

主要自动评审不采用“与其他方法一起展示后比较”的格式，以减少候选分组对判断的影响。固定单方法输入、随机化方法别名、冻结评审协议；方法比较在评审后进行。同一回答重新评审得到不同结果时，记录测量变化，不写成模型进步。

### 9.4 正式确认不做纠错重试

首次输出全部保留。必要的重复采样在结果出现前选定相同来源子集，每种方法都运行同样次数，首次仍是主结果。第二次不替换第一次、不取 best-of-N、不把重复回答当作新来源。

## 10. 训练目标与可执行的超参数起点

### 10.1 统一目标，但按阶段启用

总损失设计为：

`L = alpha*L_choice + beta*L_pair + gamma*L_value + eta*L_cost + rho*L_aux`

`L_choice` 是有依据的多正例／软目标选择；`L_pair` 是同状态可靠分支的成对排序；`L_value` 预测固定续跑条件下的结果；`L_cost` 预测增量计算或操作成本；`L_aux` 只用于已定义范围的已读／交付／版本辅助任务。不是每个阶段同时启用全部项。

第一轮建议：warm start 使用 `alpha=1`，其余为 0；结果监督阶段从 `alpha=0.5, beta=1, gamma=0.25` 起步；成本头作为独立诊断，确认能预测真实成本后再进入决策。辅助任务权重从 0 开始，只在消融证明有益后加入。权重是调优起点，不是理论最优值。

### 10.2 多正例与稀疏监督

有多个经过验证的好动作时，不强行指定单个 ID。可采用“好动作集合概率质量”损失：`-log sum_{a in A_good} pi(a|o)`，但前提是该损失的比较范围内坏动作已有相应证据；未审阅动作不自动排除。

成对损失采用 `-w*log sigmoid(score_good-score_bad)`，`w` 反映标签可靠性和来源权重，不根据最终测试表现回填。质量平局不人为制造方向；可用分差约束或仅保持两者均可接受。

### 10.3 全局归一化与分布式训练

所有 loss 记录有效标签数量、来源数量和原始 loss 总和。梯度累积按整个更新窗口的有效分母归一，不取各 microbatch 平均后再平均。多卡时对分母及必要的总量做正确同步，处理 DDP 自身梯度平均；否则标签稀疏率和候选数不同会改变实际目标。

避免在一个 state 的大量 pair 上反复放大权重：先 state 内归一，再按来源／依赖组控制贡献。三条模型路线使用共同样本次序、候选映射和曝光统计；不同 tokenizer 的实际 token 工作量另外报告。

### 10.4 初始超参数表

| 项目 | M0：冻结表征 | M1：编码器 | M2：0.6B 直接读出 |
|---|---|---|---|
| 优化器 | AdamW | AdamW | AdamW |
| 学习率候选 | 3e-4、1e-3 | 编码器 1e-5／3e-5；头 1e-4／3e-4 | LoRA 5e-5／1e-4；头 1e-4／3e-4 |
| 训练方式 | 只训头 | 先冻结头训，再部分／全量微调对照 | 默认 LoRA；0.6B 全量为受控对照 |
| 有效更新 batch | 128–512 状态 | 64 状态起步 | 32 状态起步 |
| 初始遍数 | 3，观察 1／2／3 | 3，观察 1／2／3 | 3，观察 1／2／3 |
| 精度 | FP32 小头 | BF16 前向，敏感 loss FP32 | BF16 前向，softmax／loss FP32 |
| 正则与调度 | weight decay 0.01 | decay 0.01；warmup 5%；cosine | 同左；LoRA rank 16、alpha 32、dropout 0.05 起步 |
| 梯度裁剪 | norm 1.0 | norm 1.0 | norm 1.0 |

这些配置在 G0 容量与吞吐测试后固定。首轮每路线最多两个小型学习率候选，避免“公平对照”演化成无法完成的大网格。LoRA 具体模块名由实际骨干确认，不在未检查实现时假定通用字符串适配所有模型。

### 10.5 精度与恢复检查

训练可用 BF16，但标签生产中的近似相等分数不能未经数值检查直接排序。对固定输入、不同 batch 组合做一个有限一致性探针，明确可分辨的分差范围；不要求所有硬件、所有 kernel 逐位一致。

保存 optimizer、scheduler、RNG、采样器位置、数据版本和更新步；中断恢复后在小固定检查集上确认数值与决策合理一致。此项用于可恢复训练，不延伸成每一步重复完整审计。

## 11. 分阶段训练路线

### 11.1 T0：可学习性与系统上限，不超过一个有限试验块

在 D0 实际状态上比较强固定动作、简单随机动作和有限 best-observed 分支，检查是否存在真正的任务质量／成本差异。同步用 32–64 个清晰训练实例做过拟合测试，验证反向传播、ID 对齐和完整动作输出。

如果所有可执行动作得到同一个包，或者所有包都不足以回答，先修候选／环境；如果标签不能区分已知正反例，先修测量；如果可用信息不足以区分动作，修状态投影。T0 不是长期关卡，更不是“等系统完美才训练”。

### 11.2 T1：结构化监督暖启动

训练合法绑定、可见状态理解、明确证据进展与停止。建立可用的 `bridge checkpoint`：它懂接口和对象，但未学习本轮结果效用。该 checkpoint 是后续结果训练的同骨干起点，同时保留强简单策略作为外部参照。

三路线都至少完成一次实际优化、保存、加载和 128 来源以内的完整 DEV 读出。不能只比较离线 action accuracy 就淘汰所有路线。第一轮必须把“接口错误”“材料选择错误”“Reader 使用不足”分开。

### 11.3 T2：同状态结果监督

使用相同 bridge、相同可靠数据，比较：仅结构监督、弱似然辅助、真实结果成对监督。每个模型至少保留 bridge、T2 中间点和预定最终点。checkpoint 选择由 DEV-select 的固定准则决定，不按最终确认结果选择。

主线先选择 M0、M1、M2 中至多两个有竞争力的路线。若 M0 已达相同质量且明显更便宜，就保留它；不为论文叙事强行选择更大模型。

### 11.4 T3：自身状态再采集与两轮聚合

当前策略在 TRAIN 根来源上执行，采集其真实到达状态；按随机、模型／固定策略分歧、停止边界和欠覆盖动作分配复核预算。每轮保留旧数据 replay，建议新／旧结果监督 1:1，并单独限制单来源最大贡献。

执行两轮为一期默认上限；第三轮需说明新增机制或仍改善的来源级曲线。DAgger 为处理策略诱导分布变化提供了经典依据，但本项目使用分支反馈时不能直接借用其专家标签假设下的理论保证。[R8]

### 11.5 T4：条件触发的序列 RL

仅在以下条件同时存在时启动：候选有可靠结果差异；监督模型离线可学但全轨迹存在明确延迟信用问题；环境可复位；当前策略已不是随机动作；真实 rollout 成本可接受。

对有限动作分布优先使用 actor–critic／PPO，不强迫生成 token 后再做 token 级 GRPO。初始可用 PPO clip 0.2、GAE 0.95、折扣 0.99、每块 rollout 2–4 个优化 epoch，并在 DEV 校准；不同任务持续时间下的折扣应有明确含义。

离线选择性标签不能直接当 on-policy rollout。记录 behavior policy、动作概率、合法 mask、价值与终止原因；若缺失这些量，不假装能做无偏 off-policy 评估。非随机环境重复结果的同 seed 只是一种配对措施，不保证模型服务采样完全相同。

### 11.6 T5：冻结候选与正式确认

冻结模型、数据、状态投影、动作生成器、Reader、预算、选择准则和主要比较。运行新来源首答，按预定协议分析；失败和未决不删除。开发结果不进入确认集更新，也不进行逐题 prompt 修补。

如果确认失败，冻结该负结果，依据错误结构提出下一轮新假设，并使用新的确认资源。不得原地调到过关后覆盖旧实验。

## 12. 第二阶段：工作集与跨会话维护控制

### 12.1 View 先成为可执行选项，再学习是否使用

修复最终请求包装的容量计量：比较的是 system、task、工具说明、来源字段、选中正文和输出预留组成的完整请求，不只是 View 正文。先提供原文直达、紧凑抽取式材料包、分阶段读取三个明确选项，限制复杂自由改写。

逐层统计构建、可容纳、实际交付、Reader 使用和任务成功；记录失败 View 已花费的成本。只因能构建 View 不可给策略正奖励；只因一次 View 失败也不永久屏蔽该动作。

### 12.2 维护策略先选提案，不先生成全文

固定提案模块产生少量合法编辑：新增、局部更新、保留旧值并添加时间范围、明确无变化。小策略根据原事件、相关旧值、来源和未来效用选择提案。提案生成成本计入维护；不允许根据测试问题或答案产生“完美记忆”。

只有在提案上限明显阻塞、并经过诊断后，才单独研究小模型生成编辑文本。此时与“固定提出器＋小选择器”的对照保持独立。

### 12.3 维护收益看未来，而不是当前一次回答

同一写入前状态分支执行不同维护操作，随后处理相同的若干未来任务，评价累积成功、非目标损伤、过时断言和维护成本。未来任务只用于离线目标，不进入当前在线观察。

建议使用 4／8／16 会话作为长度条件，先短后长；这些是实验设置，不是保证一次 rollout 足以代表无限长期效用。不同长度分别报告，不将所有步骤当独立样本。

### 12.4 删除、换出与失效必须区分

工作集 EVICT 只是暂不交付；旧内容因新版本而不适用，不等于永久删除；用户授权的遗忘还涉及来源可见性。不能让一个学习到的“省 token”动作跨越这些语义和权限边界。读取主线可不学习永久删除，第二阶段在隔离环境下单独检验。

| 分支 | 主变量 | 必须的对照与反例 | 支持／否定机制的观察 |

| I1，交付感知状态 | 显式 K/O/实际送达标记 | 去标记、相同正文；已读但换出、读到但未交付 | 是否减少遗失证据与错误停止，并提高任务结果 |

## 14. 基线与实验矩阵

### 14.1 必须冻结的基线

B0：强原文固定策略，含合理检索和预算管理；B1：相同候选下的相关性／近期性／去冗余启发式；B2：固定少量读取后停止的成本基线；B3：当前 Laya／S1 与旧结果候选；B4：M0 冻结表征＋小网络；B5：所选同骨干 bridge。

另外至少加入一个最接近研究的共同条件对照：结果驱动的独立候选效用打分（MemCredit 思路）或预算档位路由（BudgetMem 思路），按提出的主机制选择。[R1,R10] 改编实现必须标为 inspired baseline；只有保持原生模型、动作和协议的实现才称原方法复现。

规则和阈值仅在 DEV 上调，不故意选择明显弱的基线。强简单基线 `B*` 在 CONFIRM 前固定；不能看测试后选一个更弱的对手。Full-context 在共同预算内可以作为基线，超预算的全文条件只能是另列的上限参考。

### 14.2 训练归因对照

在 DEV 上至少比较：bridge；真实标签训练；相同更新数的标签置乱训练；仅弱标签训练；真实结果训练。置乱只用于诊断，不需要在最终全部任务重跑。

如果只是比随机头强，不能宣称任务策略训练有效；如果优于 bridge 却不优于 B*，只能证明学习起效，不能证明方法值得替换强简单策略；如果 T2 未优于 T1，不能把 T1 的全部增益算作结果训练收益。

### 14.3 一期实验编号

| 编号 | 内容 | 最小范围 | 主要产物 |
|---|---|---|---|
| E00 | 测量、候选上限、过拟合、真实执行接线 | D0；三路线最小功能拟合 | 错误定位与可学性报告 |
| E01 | M0／M1／M2 共同数据筛选 | 每路线最多两配置、seed0 | 任务质量—总成本对照 |
| E02 | bridge／weak／真实结果监督 | 两条入围路线、同状态标签 | 训练目标归因 |
| E03 | 2k／5k／10k 有效监督与匹配曝光 | 主路线；来源与 token 工作量分列 | 数据 scaling 与重复曝光对照 |
| E04 | 自身状态聚合两轮 | 主路线、旧数据 replay | 部署分布改善证据 |
| E05 | I1–I4 中至少两个机制 | 同骨干、同数据；必要反例层 | 机制消融 |
| E06 | 三 seed 的正式拟合与冻结选择 | seed 0／1／2；禁止测试择优 | 训练随机性范围 |
| E07 | 新来源确认＋第二 Reader／预算迁移 | 按预注册 N 与完整首答 | 主要效果与迁移报告 |
| E08 | L 轨道维护与后续任务 | 独立历史；4／8／16 会话 | 长期记忆控制效果 |

E03 不能只“多训几遍”：扩量与重复曝光需从共同初始化开始，保持可匹配的数据内容与 replay，分别报告主状态曝光、来源、tokens 和训练工作量。三种匹配口径不能冒充相同。

### 14.4 共同预算与共同信息

初始材料预算以既有 2,048 tokens 为锚，DEV 再比较 1,024／4,096／8,192；控制步数以现有 8 步为锚，4／12 步只作明确变更条件。材料预算与完整上下文窗口分别检查：2,048 是记忆材料限额，不是完整请求窗口；完整请求还须满足 context−输出预留。Reader、输出预留、候选产生器和来源权限必须一致。不同方法可以不花满预算，但不能额外获得隐藏读取、调用或免费编码。

## 15. 最终有效性验收与统计协议

### 15.1 三层验收证据

| 层次 | 必要证据 | 不能证明什么 |
|---|---|---|
| E，执行与学习接线 | checkpoint 被真实加载；梯度更新；完整动作合法；模型实际被调用 | 不证明策略有用 |
| T，训练效果 | 新来源上优于同骨干可用起点；明确贡献来自哪阶段训练 | 不自动证明优于强简单方法 |
| M，方法采用 | 超过 B* 的质量／成本目标，且迁移与维护边界可接受 | 不等于无条件 Product 发布或顶会录用 |

一期最终成功至少满足 E＋T＋M。若只满足 E 或 E＋T，保留产物但项目目标仍未达到，进入有原因的下一轮，而不是“已完成全部训练目标”。

### 15.2 默认选择质量优先路线 A

**A 路线主标准：** 在预注册主任务、主要预算和新来源集上，候选减 B* 的主指标点估计至少 **+5 个百分点**，来源／依赖组配对 95% 区间下界大于 0；候选相对同骨干 bridge 的差值区间下界也大于 0。完整系统成本不得超过同一预先设定预算上限。

此外，三训练 seed 的平均收益为正，逐 seed 结果全部披露，至少两个 seed 的点估计优于 B*；不要求每个 seed 都单独显著。源样本 bootstrap 只反映任务抽样，不能冒充无限训练 seed 的稳定性证明。

第二个预先选定任务或 Reader 迁移集需满足质量差的 95% 区间下界高于 −2 个百分点的非劣目标，或达到另外预定的任务阈值。若样本量不足，结论只能限定在主条件，不能同时声称泛化验收通过。

### 15.3 效率路线 B 只能在确认前选择

若 DEV 显示质量接近强基线但成本明显降低，可以在解封 CONFIRM 前，将 B 路线预注册为主要目标：质量差 95% 区间下界高于 −2 个百分点；预先选定的完整推理成本比值的 95% 区间上界不高于 0.70；预先选定的延迟／显存／升级率约束不退化到不可接受范围。

成本主轴只选一个：例如同机器完整端到端设备时间，或固定服务与预算下已知生成 tokens。另一轴作为必要补充，不能在失败后改选对自己最有利的成本定义。只测到 tokens 时，不宣称 GPU、能耗或金额同时下降。

B 路线还要证明训练相对同骨干起点确实改善了该质量—成本目标。测试后从 A 改 B 属于新假设，必须新确认，不能作为原计划成功。

### 15.4 样本量不能由“已有 256 个”决定

对配对二元结果，令差值为 D∈{−1,0,1}，不一致率为 p_d，目标差为 delta。忽略聚类时，80% power 的粗略规划式为：

`n ≈ (1.96 + 0.84)^2 * (p_d - delta^2) / delta^2`

当 p_d=0.30、delta=0.05 时，约需 933 个独立配对单位；若真实差为 0、非劣界 0.02、p_d=0.20，采用相同双侧 95% 区间口径，粗略量级约为 3,920。以上为本方案计算示例，不是对实际数据功效的结论。

实际 N 依据 DEV 的不一致率、来源内相关性、指标类型和可获得历史数量做模拟确定。不能把 1,000 个问题当作 1,000 个独立用户，也不能宣称 256 个来源必然能够证实 2pp 非劣。最终正式 N 在查看确认结果前冻结；只有预先允许的盲化方差／失访估计可以调整 N。

### 15.5 配对、未知与多重比较

同一根来源的所有方法、任务切点和重复输出一并重采样；跨来源依赖组按更高层归组。训练 seed 分别报告并给平均效应，Reader 重复不增加来源 N。多个创新机制的探索性显著性不能代替唯一主比较；确认性次比较预先声明并采用适当的多重比较控制。

语义未决显示为 U，报告验证标签率和最保守／最乐观识别范围。若处理 U 的合理方式会改变主要结论，不能无条件宣称真实质量提高。基础设施故障是否剔除必须在协议中按明确外部标准定义，并对受影响配对统一处理；方法本身的超长、格式或容量失败保留。

### 15.6 实用附加标准

执行非法动作率应为 0；控制器不触发额外越权行为；主要结果不依赖自动兜底；至少包含一次冷缓存与一次稳定热缓存测量。停止策略报告过早交付和过度读取两个方向，不以平均读取次数单独评价。

## 16. 双 A100 40GB 的训练与数据流水线

### 16.1 先做真正的性能剖析

使用有限的 PyTorch Profiler 采样而非全程开启高开销 trace。[R17] 对每条路线，固定代表性短／中／长输入，运行预热后约 200 个 optimizer steps 的有限测试，测量有效 tokens/s、状态/s、padding 比例、显存峰值、数据等待、前向／反向／优化耗时和验证开销。M0 可能更适合 CPU 或单卡；不为让 GPU 看起来忙而人为增大无效计算。

建议性能目标：稳态数据等待占 step wall 低于 10%，padding 浪费低于 20%，周期性验证不超过训练阶段 wall 的 15%。这些是待调优目标，不是实现保证；短 Q 阶段可单独采用较低验证频率，不能让逐步全评测吞掉训练收益。

### 16.2 解耦昂贵反馈与梯度更新

前期将来源解析、tokenization、静态编码和分支数据编译成紧凑 shard；训练直接批量读取，不在每个 step 打开 SQLite、解析巨大 JSON 或串行请求 Teacher。

训练、采集、评测作为三个有限队列。每个队列有明确数据块与终点，不无限守护运行。Reader／Teacher 若占用同一物理 GPU，要安排阶段切换，不把两个 40GB 当作可随意共享的连续 80GB。

### 16.3 建议资源安排

| 阶段 | GPU 0 | GPU 1 | 调度注意 |
|---|---|---|---|
| 数据校准 | Teacher／分支反馈 | M0／M1 功能训练或编码 | 同服务并发前先核实容量，不猜吞吐 |
| 模型筛选 | M1 单卡训练 | M2 单卡训练 | 相同数据曝光，不强行 DDP 小模型 |
| 主训练 | 入围模型 seed0 | 入围模型 seed1／数据生产 | seed2 后续接续；避免峰值互抢 |
| 正式评测 | 固定 Reader 或释放给共享服务 | 策略推理／记录 | 比较延迟时隔离后台负载 |

一期可先预留 **240 个本地 GPU 设备小时的规划包络**，两卡时长相加；建议分配为训练 90、反馈与编码 70、正式评测 40、探索 40。该数值是计划控制上限而非预计工期，需在 G0 以实际吞吐修订。外部 Reader 服务的算力、tokens 与排队时间另列，不隐藏在“免费教师”中。

### 16.4 显存与精度选择

0.6B 全量 Adam 训练按每参数约 16 bytes 的常见混合精度参数／梯度／优化器粗估，仅模型状态约 9.6GB；1.7B 约 27.2GB，尚未含激活、KV、临时 buffer 和框架开销。具体实现可能不同，因此 1.7B 先采用 LoRA 或分布策略，经实测再决定全量训练。

不为了对齐 GPU 占用将上下文扩到 128K。优先缩短合法状态、共享静态内容编码、按长度分桶和扩大有效 batch。冻结编码器时可缓存 embedding；微调时不能使用陈旧缓存冒充当前前向。

### 16.5 成本台账保持简单且不重复

每个阶段记录一次：数据读取／准备、编码、Teacher、训练、控制推理、记忆操作、Reader、评审。父进程 wall 与子作业 wall 不重复相加；GPU 分配时长不等于 kernel 忙时；线程时间不等于 CPU process time。保留未知项，不填零。

| W3，批处理与训练 | 复用现有训练基础；必要时拟 `learning/memory_policy/` 小模块 | 动态候选 batch、稀疏标签、全局归一化、恢复与三路线 |
| W4，分支数据 | 复用 `FirstActionIntervention` 与原日志 | 相同 before、完整绑定、有限续跑、标签与成本分离 |
| W5，评价 | 复用现有任务 Reader 和来源评审，修复标签合同 | 主指标、来源配对、未知范围、三 seed 与重复子集 |
| W6，实验入口 | 拟 `tools/run_small_memory_policy.py` | 一个工具提供 prepare／train／rollout／evaluate；禁止多个同义 runner |
| W7，维护扩展 | 原维护执行器与版本／依赖机制 | 先提案选择，再评估跨会话未来收益 |

W1 尤其要消除 `memory_control_learning.py` 对 Laya 专属 payload 的不必要耦合，但不能破坏旧训练记录的读取。[P4,P5]

### 17.2 数据合同保持三层

**在线观测：** 只含策略可见状态和实际合法动作。**离线监督：** 参考答案、proof、评审、分支结果与成本。**运行元信息：** 数据划分、根来源、模型／投影／环境版本、seed 和完成状态。

三层可放同一个容器，但模型数据加载器只读取在线观测；训练标签另取。避免默认把 metadata 拼进文本。未知 reference 不应触发自动伪标签填充。

### 17.3 提交节奏以真实运行闭环为准

建议按 W1/W2 最小真实预测、W3 真实拟合、W4 真实分支、W5 全轨迹评测四个垂直切片提交，而不是先完成全部抽象层再训练。每个切片带一个可运行命令、一个小产物和一项明确验证；模型实验结果另行记录，不靠测试通过推断。

## 18. 测试、故障定位与探索转向

### 18.1 必要测试集合

| 范围 | 最低检查 |
|---|---|
| 状态与动作 | 完整参数对齐、候选置换、别名重命名、在线／离线字段隔离、单动作状态 |
| 训练 | 32–64 例过拟合、参数确实变化、未知 mask、空标签 batch、变长候选、累积归一化 |
| 推理 | 保存后加载、同一执行接口、实际模型调用、无隐藏 fallback、预算耗尽与主动停止区分 |
| 环境 | 相同 before 的独立分支、来源版本、交付材料与实际 Reader 输入一致 |
| 评价 | 固定正反例、未知／失败分母、配对聚类、重复结果不覆盖首次 |

先执行最小覆盖，随实际 bug 增加有针对性的回归。不要为一项实验新建数十个互相重复的审核工具，或把全仓库无关测试变成每次训练前的串行瓶颈。

### 18.2 诊断决策表

| 现象 | 优先验证 | 下一步实验，不是默认扩量 |
|---|---|---|
| 小样本都拟合不了 | ID／mask／loss／梯度／模板 | 修接线；不谈模型能力 |
| 能拟合，来源外不泛化 | 语义信息缺失、来源泄漏、标签不一致 | 换合法投影；增加独立来源；语义对照 |
| 离线排序好，完整任务差 | 自身状态分布、停止错误、后续策略差异 | T3 再采集；固定动作干预；拆终止原因 |
| 所有分支都差 | 候选缺关键来源、Reader 失败、任务不可答 | 测 best-observed 与可见池上限；修环境 |
| 候选都同包同答 | 动作表缺实际干预、参数未生效 | 验证执行变化；不继续拟合虚假差异 |
| 模型读得更多且更差 | 弱奖励鼓励阅读、冗余、预算强停 | 停止反例；显式增量成本；去弱标签对照 |
| 成本低但质量退化 | 过早停止、过滤难例、只省正文不省调用 | 按预先质量约束训练；恢复完整分母 |
| 一个 Reader 有效，换模型无效 | 奖励过拟合、答案能力差异 | 小头校准／Reader 条件化，与完全重训分开 |
| 更新后错误增多 | 版本未失效、局部例外误传播 | I5；不自动扩大受影响区域 |

### 18.3 有界停止，不等于停止科研

一个创新分支连续两个有限版本在相同诊断上无改善，应暂停该分支，记录反例并换假设。主项目至少保留简单模型、强基线和可靠数据生产路线。算力预算耗尽时明确“本轮未达到”，不得自动无限训练或宣称计划已成功；下一阶段由新的实验卡和预算推进。

## 19. 里程碑、依赖与验收产物

不用未经测量的“几小时完成”或“若干天必然成功”作为承诺。按可观察产物推进：

| 里程碑 | 前置 | 必交产物 | 放行条件 |
|---|---|---|---|
| G0，可运行且可测 | 基线清点 | 校准包、真实 before／action／result、三路线小拟合、吞吐剖析 | 无系统性标签故障；有实际动作差异 |
| G1，选型成立 | G0＋D1 | E01/E02、bridge、真实读出、主指标与预算冻结草案 | 至少一条路线表现出可学习信号；否则定位表征／数据 |
| G2，训练收益 | G1＋D2 | 结果监督、scaling、自身状态曲线、失败分类 | DEV 上不是只赢随机基线，且有机制解释 |
| G3，机制证据 | G2 | 至少两个机制对照、正式三 seed、成本曲线 | 冻结唯一候选与 A／B 路线，不触碰确认 |

| G5，长期控制 | 可靠读取／测量 | E08、未来收益、非目标保持、实际维护成本 | 读取与维护效果分别成立，不借短任务替代 |

G0 只修阻断学习的问题，不要求消除全部产品缺陷。G1–G3 允许探索，G4 禁止事后调参。G5 可与后期探索并行准备，但不抢占尚未建立读取收益的全部资源。

## 20. 最终交付与结论模板

### 20.1 必须交付的研究实物

一个可复现训练入口；模型无关策略适配器；M0/M1/M2 的比较记录；选中模型三个 seed 的权重与恢复状态；数据来源与暴露范围清单；真实分支监督和未决记录；主比较、消融、迁移、长程及成本表；固定正反案例；最终效果与限制报告。

权重和大产物存入项目实际可访问的产物目录，文档使用经过核实的相对路径或实际链接。不把仅存在于训练机的 `/data/...` 写成所有读者都能打开的公开附件，也不在仓库上传私有来源、凭证或完整原始对话。

### 20.2 最终结论必须采用分层表述

合格示例：“在协议 X、预算 B、N 个根来源、三 seed 的范围内，结果监督相对 bridge 提升 A；相对 B* 提升 C，区间为 D；总成本变化为 E。机制 I1 的去除使收益降低 F；第二 Reader 的结果为 G。尚未证明的范围为 H。”

不合格示例：“训练全部完成，测试全绿，因此训练有效”“参数更小，因此更高效”“某个 seed 好了，所以算法有优势”“四方法没有 supported 标签，所以真实成功率都是零”。

### 20.3 完成判定

**工程交付完成：** 代码与产物齐全。**训练目标完成：** T 层成立。**方法目标完成：** M 层成立。**创新主张成立：** 有针对性消融与外推边界。四个字段不得合并为一个绿色状态。

本规划要求持续以真实收益为目标，但不预先保证任何特定模型或机制一定成功。合理的失败应当改变实验，而不是改变事实。最终采用哪一种骨干、是否需要 RL、是否保留 View，都由上述证据决定。

```python

    action_ids: list[str]
    scores: list[float]
    predicted_value: float | None
    predicted_cost: list[float] | None

# 实施接口说明；不是已经加入仓库的可导入类。
# score(observation, actions) -> PolicyScores
# choose(state, actions) -> selected_action_id
```

执行时对返回 ID 进行一次绑定检查即可；不需要多层代理反复验证。只有一个合法动作时由执行器处理，并标记 forced，不能记成模型推理成功。

## 附录 E. 结果表与实验卡模板

### E.1 每个正式实验一页卡

实验 ID；假设；当前最接近工作；与父实验的唯一主要变化；固定骨干／Reader／候选／预算；训练来源与有效标签数；初始化与 seed；checkpoint 规则；主要比较与置信区间方法；成本上限；停止／转向条件；实际结果；失败解释；下一步。

### E.2 最终结果表字段

| 字段组 | 必须包含 |
|---|---|
| 身份 | 模型、训练阶段、数据版本、投影、seed、Reader、实际预算 |
| 样本 | 根来源／依赖组／问题／状态／实际首次调用，各自分母 |
| 质量 | 任务成功、材料充分、答案支持、完整性、未知和失败 |
| 控制 | 主动／强制停止、READ／SEARCH、重复获取、对象错误、升级次数 |
| 训练归因 | 对 bridge 的差；对 B* 的差；对应区间；哪一阶段产生收益 |
| 成本 | 数据与教师、训练、控制、执行、Reader、评审；已测／未测分别列 |
| 稳定性 | 三 seed 原值、来源区间、Reader 重复、候选扰动与迁移 |
| 限制 | 暴露来源、测量偏差、上限诊断、未完成任务和不支持的主张 |

### E.3 探索性状态压缩分支（可选）

若剖析显示大部分成本来自反复读取状态，而非动作头，可增加一个独立分支：学习保留决策所需信息的紧凑状态，而不是通用摘要。以完整合法观测策略作为蒸馏参照，同时用实际结果约束压缩损伤；最小对照是相同长度的规则抽取与同骨干不压缩输入。

建议目标为“决策排序保持＋实际任务损失＋状态长度成本”。完整观测教师不是真值：若其选择错误，不应因为忠实蒸馏而奖励学生。必须保留能够改变正确动作的否定、主体、时间和例外干预，验证压缩没有删除关键区别。

该分支可以成为创新候选，但只在状态成本确实主导、基本控制策略已可用时启动。不能把“摘要更短”直接写成训练有效。
