## 2026-11-17：独立四轴、实际分支与受控 bridge

新增 `control_outcomes` 将已观察的执行状态、评审输入可用性与材料充分性、回答支持性、回答完整性分开保存。原始回答全文进入评审；无效研究 JSON 不直接抹掉回答，真实空材料与缺失交付捕获分开。已知执行失败保留为计划分母中的不成功，评审失败只屏蔽相应语义轴，不重试首答。

两个有限的引文生成版本 v3/v4 各运行200例、180次实际调用（20例输入确实不可审阅，不调用）。两版仅17/40完整正例通过程序定位，故停止继续调整同类引文提示。v5改为评审返回实际来源单元 ID，由程序绑定完整原记录；这只证明引用位置，不证明蕴含。v5符号校准为完整正例40/40、矛盾40/40、无支持40/40、部分回答39不成功/1未知、执行失败20不成功、不可审阅20未知。6个评审失败保留，其中5个方法执行本已失败。这是作者构造的有限符号校准，未证明自然语义评审可用。

从旧TRAIN实际状态收集16个来源，各自 h=0/h=2，执行122个不同绑定分支；至少30%的随机来源配额保留。每个分支用独立SQLite备份复放真实前缀，同一已声明续跑策略，完整菜单评分，不将旧未观察动作标成错误。当前M0所选16动作中14个此前无反馈，2个为仅观察动作。原Reader实际调用108次，同状态/同horizon完整wire相同的14个位置复用首次；7个首次失败保留，绝非122个独立来源。

P02因此采用计划允许的可执行受控任务。96个程序定义登记库按根分为64 TRAIN、16 DEV-fit、16 DEV-select；每库3个相反查询、4个实际已读前缀，共768/192/192状态。所有合法只读绑定从同一请求checkpoint真实执行，标签只定义字段覆盖与公开的操作/材料成本，是结构bridge，不是Reader效用。主体、字段、有效区间决定记录是否适用；同一前缀更换查询会使最佳动作在READ/HANDOFF间反转，真实SQLite测试已验证。原Task Reader、来源权限与2,048材料/8步预算保持一致。联合输入实测1,152状态均可容纳，2,300–2,662 tokens，无截断。
