## 0. 优先级调整：从接口存在转向真实使用

### 0.1 最新运行证明了什么

本次读取 `v5-online-v977` 的真实请求、提案、checkpoint 和回答 trace。核查开始时，38 个实现文件与该运行源码一致，映射 SHA-256 为 `c63e43b1a0859d62f430a59f29a933484dfc36b315ccb5669536b13201bf5d35`；整理期间工作区已有独立的摄入协议 v6 修改，不能再把该散列标为后续代码的身份。

- 六批覆盖 12 条原消息，提案为 12 次 RETAIN_SOURCE、6 次 NO_CHANGE；历史 checkpoint 有 12 个来源、0 张理解卡、0 个历史版本、0 项待维护记录。
- 六次真实请求均提供 CREATE／RETAIN_SOURCE／NO_CHANGE；每份实际 schema 均允许最小 CREATE。REVISE 因没有已交付旧卡而不出现，这是合法目标绑定的结果，不能倒过来归因为更新 schema 丢失。
- 合法历史先表达重新写影评、开设博客，后表达停止影评、关闭博客。存在维护事项的机会；但更正到达前未创建旧理解，后面无法形成版本修订。此判断只读原历史，不读取 gold 来构造运行输入。
- 作答为 1 次 search、4 次 read、0 次 save，原生 pass=1。这是来源检索成功，不是理解维护成功。
- ordinary 与 ordinary_linked 均为 `contextual=False`，不向 Host 提供 memory_state。公共 attention 决策函数虽会被调用，但收到的主动 AttentionState 为 None；不能用函数调用次数冒称 State 驱动取材已启用。

随后到位的四题首轮记录也已核对：共 25 批、49 个来源、57 次 RETAIN_SOURCE、25 次显式 NO_CHANGE，四份历史 checkpoint 都没有理解卡和修订；25 份实际请求均保留 CREATE。后续协议 v6 的 v1003 复核已出现完成标记，历史仍为 0 卡／0 修订。这支持继续处理执行职责，而不能认定仅增加提示说明已解决问题。各次运行的费用和评分保持原身份，不合并成独立新样本。

这也不意味着所有功能都没用：来源检索和精简投影确实运行；较早 v4 有一条 H2 材料—回答一致链。应分别说明“未接入、未提出、未提交、未进入材料、已使用但收益未知”。

### 0.3 先完成一条真实闭环

```text
合法历史到达 → 来源按既定策略接收
            → Host 形成可维护理解 → 程序提交
后续真实变化 → 程序交付相关旧理解与新来源
            → Host 提出修订 → 程序提交新版本
当前任务     → 建立／更新任务 State
            → Attention 实际影响查询、选择或展开
            → 当前理解与必要限制进入 Host 材料
            → 回答原始任务
```

程序负责把已经设计好的能力接入阶段和数据流，Host 负责语义判断。不要让模型再判断“系统是否应该运行这一阶段”，也不要让程序伪造一份正确理解代替 Host 完成语义任务。

1. **来源接收和理解维护分开。** 在已经授权完整历史摄入的 runner 中，由程序完成确定性的来源接收／保留，将本来就有的一次 Host 提案用于 CREATE／REVISE／NO_CHANGE。来源保存成功不能替代理解维护；独立来源保留工具仍可用于其他操作场景，不额外增加一轮 Agent。
2. **NO_CHANGE 合法，但语义要可解释。** 没有值得维护的新内容、已有理解已经覆盖，都可以不写；已有来源本身并不是“不需要理解”的理由。用同一提案中的简短说明或现有诊断记录区分这些情况，不新增语义审查模型。不得强制每条消息创建卡、每次到达修订，也不得根据 gold 规定目标卡内容。
3. **明确交付更新机会。** 先检查旧卡是否在变化前真实创建，再检查其主体／事项、当前正文与新来源是否送到同次提案。没有旧卡先解决创建；已有旧卡没交付解决接线；已交付仍选错目标才是 Host 的语义问题。不要跳过上游断点直接做 H2 评分。
4. **State 有输入，Attention 有消费者。** 普通基线继续关闭主动控制；功能接线诊断采用现有 state 能力，在既有 Host 循环中表达任务理解、冲突或缺口，下一次 search 实际消费该状态。可信任务身份和显式约束由程序提供，语义推断由 Host 表达；不将问题前提自动写成事实。
5. **记录效果，不统计仪式性调用。** 核对旧／新版本、有效查询、入选引用和实际交付材料；State 调用成功但后续读取没有消费状态，仍未完成接线。材料与答案一致只说明使用证据，与独立因果收益分开。

`maintenance_settled` 当前只表示提案与局部调用已处理，不能升级为“语义维护完成”。以后分别汇总来源已接收、提案已结算、理解实际变化及后续材料使用；复用已有 trace，不建立新账本或大型监控系统。

已完成的合同修复及材料压缩不重复立项。先用已有失败记录定位创建断点，调整同一 Host 的维护职责与最小接线，再进行下一次有明确问题的模型运行；不要继续按旧协议顺序跑题等待偶然触发。

四题首轮已执行，不能再把 v569 等已完成的 ordinary 结果改标为功能诊断。现有协议修复及默认复核也按各自身份保留，本次文档调整不启动或切换其他进行中的运行。

## 3. P0：普通维护与破坏性操作分权

### 3.1 能力按可信请求装配

| 阶段 | 默认允许 | 默认不允许 |
| --- | --- | --- |
| 历史摄入 | 保留已发布来源、创建／修订理解、无变化 | 删除原始来源与派生内容 |
| 回答 | 搜索／读取；依据已取得历史作必要修订 | 从问题或历史自由推断删除授权 |
| 明确生命周期操作 | 可信接入授予的特定能力和目标范围 | 扩大到其他用户、任务或未授权根对象 |

普通工具 schema 不包含删除分支；dispatcher 仍核对执行上下文，直接构造参数不能绕过工具列表。删除继续使用现有底层能力，但只有受信执行器调用。内部恢复根据已持久化删除记录完成既有操作，不从模型重新取得授权。

首版不增加自然语言授权分类器。用户消息中的“停止影评”“退出竞赛”只能作为内容变化的候选依据；模型自填 `explicit=true`、任务阶段名称或操作 ID 都不能取得权限。

可信删除范围绑定根对象；服务端按现有规则计算同一用户内的派生清理闭包。范围应明确包含必要派生清理，不要求模型猜出每个历史版本，也不扩大到其他运行目录或远端服务。

### 3.2 无变化必须没有状态副作用

对新的空删除请求，固定采用 `NO_CHANGE`；内部变更函数也检查空目标，不能只依赖 schema。无变化不修改记忆、TaskState、删除代次、缓存、trace 正文、transcript 或任务目的。允许保留无敏感正文的普通调用统计。

保存／修订和删除同时出现，入口一次性拒绝，不先执行其中一个。无权限的非空删除同样在状态变化前拒绝。校验集中于外部边界与实际变更函数必要前置条件，不在各层堆叠重复 validator。

显式 `NO_CHANGE` 与工具失败分开，但不必为每个无变化批次额外调用模型。空提案可由程序规范化为该结果。

### 3.3 回执是实际结果，不能成为新的模型指令

执行回执至少有以下概念，具体字段与现有类型合并时固定：

```text
operation_id：程序绑定的执行身份
decision：REJECTED / NO_CHANGE / COMMITTED / PARTIAL
memory_changes：确实发生的对象与版本变化
cleanup_effects：本操作仍需完成的受管清理步骤
completion：COMPLETE / PENDING / FAILED
```

字段由程序生成。`COMMITTED + PENDING` 可以表示记忆删除已提交但清理未完成；`NO_CHANGE + COMPLETE` 表示新的空操作。部分成功继续保留各局部结果，不把统一回执变成整批原子性承诺。

改动必须覆盖 `receipt_outcome()`、ingestion 的提交／恢复判断、Host 的进展判断及 runner 清理入口。NO_CHANGE 不是失败，也不是可无限重复的有效进展；现有有界循环保留。

### 3.4 删除续处理：复用本地账本，补齐效果状态

不能仅以“本次删除数量大于零”决定是否清理。已有操作可能已经删除记忆，剩余清理仍须继续。

在现有独立删除账本中扩展小型操作记录，保留操作 ID、授权范围身份、目标／影响引用、逻辑提交状态和清理完成步骤。只记录恢复所需结构，不复制待删除正文。单实例同步执行，不建设分布式 outbox。

```text
授权与范围核对
  → 持久化操作计划
  → 持久化删除标记与提交状态
  → 应用实例内删除
  → 依次完成受管文件／缓存／上下文清理
  → 持久化完成回执
```

删除标记与提交记录应共享一个明确的持久化边界。若进程中断，恢复先应用标记、再补未完成清理，完成前不发出可能携带旧正文的新模型请求。

同一操作 ID 的续处理只能使用原始冻结计划；ID 与不同用户／目标／范围组合时拒绝复用。清理步骤允许幂等重做，不重复增加删除代次或建立新删除操作。新空请求没有待处理效果；旧操作即使本次新增删除量为零，也应继续自己的待处理效果。

现有旧 checkpoint 防复活检查继续保留。当前 `_apply_deletions()` 直接调用 `forget()` 的路径要收敛为“重放已有删除标记”，避免恢复被误认作新的用户删除请求。

### 3.5 一个协调入口消费副作用

由单一协调入口驱动记忆、受管制品和 Host 上下文的效果。可由几个同步函数组成；Host 接受明确的清理／继续任务输入，不再看到 `FORGOTTEN` 就自行改写用户请求。

原始任务目的来自 TaskEnvelope：

- 仅要求删除：完成后直接返回可信回执，无需额外模型调用来“确认”。
- 删除后继续回答：清理完成后，只用允许保留的任务信息继续原目的。
- 原始任务正文也属于清理范围：删除正文，保留非敏感任务身份；没有足够合法输入继续时返回明确输入不足状态，不恢复旧文本、不让模型编造新的用户意图。

不承诺程序能理解任意文本的全部敏感含义。续行依据可信接入提供的可保留输入与受管范围；无法保证时停止续行，而不是默认保留整段任务正文。

## 4. P1：语义写入从宽松字段变成明确操作

### 4.1 普通维护提案

| 操作 | 必要语义 | 程序负责 |
| --- | --- | --- |
| CREATE | 新理解、主体／事项、范围说明、可选来源 | 创建对象身份和首版，作者来自调用者 |
| REVISE | 已交付目标、新的当前正文、必要元数据变化与依据 | 从目标句柄取得预期版本，执行 CAS，不替换为最新版本强行覆盖 |
| NO_CHANGE | 本批没有可提交维护 | 返回无变化，不伪造写入 |
| 保留来源 | 已发布来源句柄 | 保存准确来源，不要求 Host 重写正文 |

保留来源可以沿用现有独立参数／入口，不为了操作表重新要求 Host 先判断 Evidence 或 Note。没有外部依据的独立想法仍可创建，不能伪装成用户原话。

短句柄旁边交付主体、稳定事项描述、当前正文、范围和关键来源入口。先复用现有 subject/context 及对象身份；只有真实需求证明现有字段不足时，才新增独立事项字段。不建设主题分类服务。

程序检查句柄已交付、版本一致、引用合法；事项连续性仍是 Host 的语义判断。语义相关不代表可覆盖同一记录。无关 fan-trailer 被改成停止影评，应作为真实 Host 失败保留，不通过自动把目标改为“最相似卡”修正。

### 4.2 当前正文与历史分工

新正文表达当前采用的理解、仍有效范围和未决冲突；旧版本由系统保存。不要要求 Host 在每次更新中重述全部历史再追加“现在不同”。

局部情境变化保留其他有依据的内容，不机械“最后一句胜出”；不强制每次新输入必须更新。临时句柄只出现在结构字段，正文应可独立理解。有协议标记的引用可机械绑定；不对自由文本中的任意 `r0` 做全局替换。

### 4.3 条件定义与说明分开

受约束条件只表示外部适用谓词。首版使用少量、版本固定的通用条件定义或其已交付句柄，每项声明键的含义、值类型和比较规则；仅支持当前实现所需的精确匹配与共同约束，不加表达式语言或任意执行器。

允许的定义由程序／可信配置提供，不由模型在普通写入中临时创建。不能从本题 gold 派生条件键，也不以 `status/note` 禁词表代替定义约束。无法表达的范围保留在正文／context，仍可保存，但明确未被结构化验证。

| 情况 | 入口／读取处理 |
| --- | --- |
| 合法条件、当前有匹配依据 | 确定性匹配，保留依据出处 |
| 合法条件、当前缺少依据 | UNKNOWN／PENDING，说明缺失项 |
| 合法条件、当前明确不匹配 | 本任务不适用 |
| 条件定义未知、类型错误或注释冒充条件 | 提案合同错误，不作为合法 PENDING 保存 |
| 没有声明结构化条件 | 合法记录；材料注明未做结构范围判断，不认证全局有效 |
| 只有自然语言范围 | 交付范围说明，Host 仍须遵守；不自动解释成任意场景都成立 |

“无结构条件”也不意味着把所有普通笔记都设为永久 PENDING。结构谓词是否可求值，与叙述范围是否经语义核对分开表达；不扩大 `USABLE` 的含义。引用／摘录准确仍不证明语义推断正确。

ordinary 与 H2 共用该合同，不依赖打开 `memory_state`。主动 State／Attention 的功能接线按第 0 节单独验证，本轮不比较其独立收益，也不将其混入 H2 对照。

### 4.4 时间入口

只有准确日期进入结构化日期字段；`current/present/now` 等留在来源或 context，不猜成当前系统日期。到达序号与系统 known_at 由程序维护，不能冒充世界有效日期。

省略边界只表示没有作出该边界声明；已知发生结束但时间不明，沿用明确的未知边界表示，不能伪装成无终止时间。尽量复用已有 uncertain_start／uncertain_end，不要求每条无时间声明的笔记填写一组额外枚举。

已解析日期仍按当前确定性规则匹配；合法但未知的信息保持未知。新写入的格式错误在入口报告，不继续让任意字符串进入日期求值。旧快照的原值保留于诊断，不静默删掉后称为新协议的无条件记录。

## 5. P1：独立模型材料视图

### 5.1 完整存储与精简投影分开

程序保留准确 ID、版本、散列、来源角色、关系和运行身份；Host 默认接收短引用、必要版本、正文、当前／历史标记、适用限制、必要更正和展开入口。投影不能修改持久状态，不能通过省略字段把未知或过时记录变成有效。

读写共用同一准确引用解析机制，但材料短引用有自己的明确有效域。当前 transcript 中仍可见的旧短引用，必须继续绑定到原准确版本，或明确过期；不能下一次搜索复用相同字符串却指向另一个对象。服务端根据回执关联解析，不让模型补填散列、命名空间或猜版本。

新操作回执的 `operation_id`、完成状态及必要恢复入口可在模型视图中简写；完整 cleanup plan 留在执行器，不把程序内部恢复表再次塞给 Host。

### 5.2 公共组织顺序

```text
检索候选和范围
  → 解析请求所需当前／历史版本与适用性
  → 收集已记录、会改变本次用途的更正和限制
  → 在整个响应内合并准确对象及重叠范围
  → 以“材料＋必要更正”整体分配预算
  → 生成短引用视图与显式未展开入口
```

同一对象、版本及范围的正文只交付一次，多个关系引用共同节点。不同真实事件即使文本相同也不合并；正文 hash 只用于内容身份，不作为独立来源合并依据。

当前任务优先当前理解。历史问题、冲突和比较旧新表达时保留相关历史，不把“当前优先”解释成最新表达总正确。当前状态标记和明确不适用限制属于所有臂的公共正确性信息，不能只给 H2。

旧材料与必要更正是一个交付单元。预算不足时缩短准确原文范围、提供不足状态或展开入口；不能完整交付已知可能误导的旧正文，却隐藏它所需的更正。

预算明确约束序列化材料区，包括短引用、关系和限制。工具外层控制回执另由完整请求容量检查计入；极小材料预算连最小包都放不下时返回明确不足，不宣称整个工具消息满足任意字节上限。

### 5.3 H2 的唯一额外能力

ordinary、RAW 和 H2 共享公共格式、角色、范围与版本解析。H2 仅额外交付与本次旧来源／旧解释有关、会影响当前解释的已记录关系和必要正文；普通出处详情、前一版全文按需展开。

各臂返回对象本身已知的当前状态和限制，属于共同正确性下限。H2 的差异是关联更正的发现与交付，不能通过给 ordinary 错误版本、隐藏其合法可读的新来源或删除已知限制来制造收益。若公共合同收敛后某题没有剩余差异，就记录该题没有独立机制机会。

不在模型前增设“判断哪些更正必要”的 LLM。首版基于现有显式关系和任务读取模式选择；不能确定是否影响解释时保留限制和展开入口，不自动删除争议内容。

本轮只做响应内去重，不重启 H5 跨回合差量，也不改 BM25／向量排序、top-k 或上下文上限。内部参考展开与最终模型投影分别计量，不能把旧指标和新短视图的指标混为一条曲线。

## 6. 任务合同与恢复后的继续方式

TaskEnvelope 持有当前阶段、目的、合法输入和允许操作；QueryContext 只组织本次检索／适用性。工具回执没有改写任务目的的权限。

当前问题可提供查询范围和明确任务要求；其中引用、假设或事实前提不能自动变为持久用户事实。新的明确反馈通过正式来源接入后再维护，不能由 scorer、参考答案或问题标签补齐。

答题仍可根据已取得历史修订理解，不整体禁用写入。建议任务允许基于约束生成新建议；用户经历、当前优先项、可选补充和本次建议分清。历史事实问答不靠一般知识补缺。

所有臂共享任务合同。原生 Judge 分数保持原样；完整对话与评分摘要有解释差异时另列诊断，不改 rubric、不删数据，也不把人工异议改计通过。

### 8.3 真实运行范围

1. 修复后实际 ordinary 默认，只跑已暴露 `v11_000977` 一次自然容量 smoke；新配置明确不授予删除能力。检查既有原题是否正常回答、有无错误任务重置，原生分数照常保留。
