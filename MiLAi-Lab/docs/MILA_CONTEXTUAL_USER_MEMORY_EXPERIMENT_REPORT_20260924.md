# MiLAi Lab v7 实验评估报告与修改建议

**本轮已经把“长历史无法完成”推进到“固定完整历史能够摄入、作答和评分”，并观察到一条 H2 更正链进入自然取材和回答。但默认配置仍存在确定性的操作副作用，Host 对条件、更新对象和当前偏好的表达也不稳定；没有证据支持将 H2 或其他候选设为默认。**

本次独立核对发现两项需要补充到原有判断中的问题：

1. **最新默认 smoke4 并未留下非空记忆对象删除的证据。** 其实际回执为 `FORGOTTEN, refs=[]`，删除账本为 `refs=[] / generation=0`。服务端仍清空当前上下文、擦除运行正文，并要求 Host 确认删除。这是可定位的空操作副作用，不能全部归因于“模型把停止活动理解成删除”。首次 smoke1 才有明确的非空对象删除回执。
2. **条件能力不只是“真实调用未覆盖”，已经出现字段语义误用。** `v11_001002` 的五张当前卡中四张把记录状态和解释性说明写入 `conditions`，导致 ordinary／H2 材料分别出现 4／8 次 PENDING，且没有条件依据调用。这说明写入合同与读取合同尚未形成正确闭环。

因此，下一步优先修复操作合同和字段表达，再压缩材料、改进当前状态的呈现；不增加候选、不扩大题量、不用反复调用同一题代替诊断。

## 3. 问题一：空删除触发了真实的上下文破坏

### 3.1 可确定的源码与回执链

当前逻辑为：

```text
memory_save 参数含 forget_refs（即使为空）
  → save() 优先进入 forget()，其他保存字段不再处理
  → forget([]) 的 affected 为空
  → 仍重置 TaskState／工作状态，增加内存 forget_generation
  → 返回 FORGOTTEN，refs=[]
  → runner 按 FORGOTTEN 擦除 trace 正文并清理本次相关缓存
  → Host 按 FORGOTTEN 重置 transcript，任务改为“确认删除”
```

`forget_refs` 复用的数组 schema 没有非空约束；`save()` 用 `is not None` 判断入口。`forget()` 对空集合没有独立无变化回执。runner 和 Host 又只依据状态字符串决定后续副作用，没有区分是否发生实际删除。

smoke4 的保留 trace 第 28 行是 `FORGOTTEN / refs=[]`，第 29 行是上下文重置；其删除账本 generation 为 0。清理函数保留 `status` 和 `refs` 的实际值，因此这里的空数组不是日志脱敏把非空引用擦空造成的。

**可以确认：没有受影响记忆引用，却执行了重置与“删除完成”流程。不能确认：已擦除的原始模型参数中是否还混有其他保存字段，或模型当时为什么选择该参数。** 不应恢复被清理的旧正文来补猜动机。

### 3.2 与首次真实误删分开

smoke1 的回执包含 1 个卡版本和 5 个来源引用，账本 generation 为 1；这是非空删除。原生任务没有要求擦除记忆，说明真实删除意图边界也未落实。不过，具体触发文本已被清理，不能把推测写成已证实根因。

因此有两个独立修复项：**空操作不能产生副作用；真实删除不能仅由任意保存参数触发。** 修好第一个，不能宣称已经解决第二个。

### 3.3 最小修改建议

1. 为无目标删除规定明确无变化语义：在唯一入口拒绝空目标，或返回 `NO_CHANGE`；不得修改任务状态、删除代次、trace、缓存或 transcript。当前确切 bug 的修复不需要新 Agent。
2. 保存／更新与删除参数互斥。普通保存携带空删除字段不得悄悄吞掉正文更新；使用一个明确操作分支，或在入口一次性拒绝混合意图，内部不重复验证。
3. 清理和上下文重置依赖真实删除回执及实际影响，不依赖一个模糊状态词。真正删除仍执行现有受管清理，不能为了方便调试留存已删除正文。
4. 后续将删除能力与普通理解维护分开授权：可信 Host／接入层提供当前明确删除请求的操作上下文，模型提供目标引用；历史中的停止活动、退出计划或状态改变没有自动擦除权限。没有这类接入时保留普通更新能力，不能让模型自填 `explicit=true` 充当授权。

第四项是操作能力边界的设计，不是给每次记忆保存增加用户确认、审核 Agent 或分类模型。首个提交应先完成前面三个小修复。

## 4. 问题二：conditions 被当作记录说明，三态计算失去意义

### 4.1 已发生的误用

v1002 的当前卡实际包含：

```json
{
  "conditions": {
    "status": "updated_preference",
    "note": "Added condition reflecting the new preference for theoretical study over practical exercises."
  }
}
```

其他卡还填入 `historical_record`、`new_observation` 以及对原记录的解释。这些是记录自身的状态或注释，不是“当前任务满足什么条件时，此理解适用”的谓词。

`scope_result()` 正确按精确条件比较，而当前任务没有上述 `status`、整段 `note` 的值，于是返回 UNKNOWN／PENDING。v1002 的 ordinary 材料累计出现 4 次 PENDING，H2 为 8 次；这是回执中包含重复／关联版本的出现次数，不是 12 个独立错误。两臂均未提出 `condition_evidence`。

因此不能只归因为“被动上下文没有开启”或“还要增加条件提取”。它已经接通，**写入的字段内容不符合读取合同**。不能通过给查询自动补上这些说明文本，或把 UNKNOWN 改成 USABLE 来消除症状。

### 4.2 修改方向

- 明确区分主体／场景叙述、记录状态、可匹配条件。状态由版本管理生成，解释留在现有正文或 context；`conditions` 默认省略。
- 只有材料明确支持的外部适用条件才结构化。用少量稳定条件定义或已交付定义句柄约束字段，而非任意字符串字典承担所有说明；不建设完整本体，也不按本题出现的 `status/note` 写禁词路由。
- 当前不能可靠结构化的范围保留为自由文本说明，不伪造可机器判断的条件，不一律拒绝记录。
- 材料展示最小可操作原因：哪个条件未知、已有证据是什么。不要复制整套条件证据到每个来源包；需要时再展开。
- 在同一普通臂和候选臂检查真实 Host 是否写出了一个合法条件、随后根据实际任务建立依据；不能用程序直接注入的 fixtures 替代自然覆盖。

现有确定性三态实现值得保留。问题在语义字段的接口约束和真实使用，增加一个语义分类 Agent 只会增加成本和另一层错误来源。

## 5. 问题三：语法合法的提案仍可能破坏理解结构

### 5.1 未更新、错更新、混合更新是不同错误

| 现象 | 实际证据 | 后果 |
| --- | --- | --- |
| 应更新却只新增 | v569 旧卡实际可见，Host 新建 card4／5；旧卡仍是当前版本 | 新旧偏好并存，没有可供 H2 使用的准确修订关系 |
| 临时句柄进入持久正文 | v569 新卡正文包含 `as recorded in r0 and r1` | 离开该次提案后引用不可解释，不能据此建立机器可检查关系 |
| 不相关记录被覆盖 | v977 首题将 fan-trailer 卡也改成停止影评 | CAS 和句柄正确，目标语义仍错误；不可作为第二个修订机会 |
| 新旧规范混写 | v1002 某卡仍先写“重视实践应用”，再附“现在更重视理论”；当前卡又补入志愿服务收益 | Host 接到的是多项混合建议依据，而不是清晰的当前优先级 |

短句柄解决了引用拼写和范围表达，不能判断“是不是同一事项”。继续加 JSON 校验不会解决上述语义选择。

### 5.2 建议把更新意图做得更容易表达

普通提案可以收敛为明确的创建／更新操作：更新必须提供已交付目标和新正文；创建不带目标。将旧记录的稳定主题、主体、适用范围与短句柄一起交付，避免只靠文本相似度让模型选择覆盖对象。

新正文表达当前理解，历史正文由版本机制保留；不是要求模型在新卡里复述全部旧观点再追加一句更正。部分变化保留未受影响内容，不能把同一领域的所有卡统一改成最新一句话，也不能无依据合并不同活动。

正文要求可独立理解，临时句柄只用在结构引用字段。不要对自由文本中任意 `r0` 做盲目替换；有确切协议标记的引用才由程序展开。需要来源联系的语义必须放入准确引用／更新关系，不能靠正文里写“已取代”认证。

这仍是一个 Host 的一次提案，不增加独立审核模型。少量已有暴露 trace 足以检查接口改动是否让“新增与修订”更清楚，不需要新生命周期模块。

### 5.3 时间修复正确，但输入边界还需简化

时间比较由字符串改为可解析 ISO 日期，无法解析的 `present` 保持 PENDING；确定越界仍为 UNUSABLE，这是正确修复。首题没有任务日期，原来就为 PENDING，不能把之后的分数变化归因于该修复。

但 v569 仍写入 `valid_from="current"`，说明时间字段的生成合同仍允许含糊自然语言。建议明确“已知准确日期填日期；未知不猜；无上界用省略”，需要保留的相对时间叙述留在原文／context。事件到达顺序由程序记录，不能伪装成世界有效日期。无需引入宽泛日期猜测器。

## 6. H2：可达性已观察到，增益与成本仍不理想

### 6.1 五环节的真实分母

| 环节 | 固定四题中的结果 |
| --- | --- |
| 相关变化机会 | 4 个，每题一个；无关覆盖和多卡重复修改不增加计数 |
| 新来源与相关旧对象可见 | 4／4 |
| 提出相关更新 | 3／4；v569 停在这里 |
| 已提出更新提交 | 3／3 |
| H2 更正状态进入自然材料 | 已作答三条链中 2／3 |
| 回答与新状态完整一致可确认 | 1 条 v1003；v1002 部分采用但原生判污染；v977 归因 unknown |

v1003 自然搜索同时返回新来源、当前 card2@3、旧解释以及旧来源关联的 `revised_interpretation`。回答采用了课后法律素养项目、定期工作坊和定制课程。这支持五环节的操作与材料一致性，不证明模型必须依赖关联分支才答对。

RAW 和 ordinary 也通过；没有只改变该关联包的固定材料对照。因此本轮没有 H2 独立收益证据。ordinary 继续默认合理，但也不能据此声称 ordinary 已优于 RAW。

### 6.2 当前 H2 返回的东西多于“必要更正”

`materials.py` 会从当前卡展开 `prior_interpretation`，并附加多个 `source_provenance`；从旧来源又关联当前理解。去重发生在单个材料包内，同次搜索的多个包仍可能交付相同当前卡、旧卡和来源。

这不是错误的来源关联，但有两个可检验的代价：同一信息多次占用上下文；旧偏好正文再次出现，可能增加选择负担。不能仅凭 v1002 失败认定后者是因果，因为 RAW 和 ordinary 也失败。

建议先离线压缩已有包：同一结果中准确版本／范围正文只交付一次，关系保留为引用；优先交付影响当前解释的更正和限制，普通出处／前一版默认按需展开。保留角色、当前／历史标记及可展开引用，完整散列和运行身份留在程序制品中，不在每项材料反复送给 Host。

这是在本次响应内组织材料，不必重启 H5 的跨回合差量优化。之后若比较效果，保持 ordinary 与 H2 的公共表示一致，只改变候选必要关系；不能候选换成精简格式、普通臂保留冗长格式后宣称关系机制获益。

## 7. 原生评分失败还需区分“没记住”“没遵循”和“评分解释”

### 7.1 STALE：可执行后仍受当前问题措辞影响

同一摄入快照下，dim1 回答“Yes”，dim2 沿用旧的每周八小时计划，dim3 则给出 10—20 分钟的小步安排。它表明不同提问产生了不同取材／回答结果，不能简单归因为全部新信息都没被保存。

后续诊断应在既有三问 trace 中分别定位：新状态是否检索到、是否展开、何处决定采用旧计划。当前问题里的事实前提不能自动覆盖历史状态，也不能一律被当成新用户声明写回。先利用现有请求和材料分析，不立即重跑 50 批历史或改写三问。

### 7.2 v1002：保留失败，同时记录评价边界

三臂答案都承认了转向理论学习，却同时推荐志愿服务等实践活动；按冻结的原生 Judge，均为 `latest=0 / contamination=1 / pass=0`，这些结果保持不变。

但完整合法对话在“退出模拟法庭、转向理论”之后仍有用户肯定帮助他人的经历；Judge 的输入采用旧／新偏好摘要、问题和参考行为，没有完整对话。Judge 将志愿服务解释成新偏好明确排除的实践活动，是比“退出竞赛、增加理论学习”更宽的排除解释。

因此，**0 分不等于模型完全没看到新状态，也不能证明每一项附加建议都来自旧记忆污染。** 当前结果同时含有建议不够聚焦、来源角色与经历被推广成当前偏好的风险，以及评分摘要和完整对话之间的解释差异。

修改建议是让答案明确当前优先项及其依据，将可选补充与当前重点区分；历史 assistant 的建议不能直接成为用户已认可的偏好。不要为迎合本题把所有实践活动设成禁词，不删除原对话后半段，也不改 rubric 或把人工异议改算通过。诊断注释与原生得分并列即可。

## 8. 成本重算：主要消耗在输入与材料，而不是最终答案长度

### 8.1 全轮实际消耗

| 摄入生成 | 79 | 368,877 | 24,815 | 393,692 |
| 作答生成 | 63 | 543,381 | 9,772 | 553,153 |

输入占生成总 tokens 约 96.3%。这里统计实验实际消费，包含失败、修复和重复暴露题，不能直接作为一次部署请求的成本。去掉 Judge 后，本轮摄入与作答生成合计 946,845 tokens；embedding 不混入同模型费用换算。

四份外置账本分别为默认 118,560、STALE 499,388、C 首题 76,874、C 后三题 268,205 生成 tokens，总和一致。C 包为 68 次／345,079 tokens；v569 的 12,726 摄入 tokens 没有形成答案评分，仍完整计费。另有一次零发送的预算拒绝，不计成模型请求。

| --- | ---: | ---: | ---: |

分项按独立 token 化边界计数，不保证严格相加。它们仍足以指出，引用／状态字段和重复关联值得先处理。应测精简工具回执、去除空字段及重复正文，保留必要语义；不是优先缩短已经很短的最终答案。

共享缓存使部分 H2 embedding 新调用为零，不等于独立部署不需要 embedding。当前局部计时也没有证明深拷贝是瓶颈；不应把优化事务复制或增加并发作为下一轮主线。

## 9. 结项状态应该如何表达

经修订的 C 只要求一个真实机制链及有限比较，不要求四题全部作答。v1003 满足可见材料与回答一致的窄标准；STALE 已有完整执行与评分。因此可保留本轮有限研究活动的结项记录，不必重开旧 Goal 或为了凑全再发模型请求。

但“负面效果”不能覆盖所有问题：empty forget 是基本操作合同错误；conditions 的语义误用是接口正确性缺口。它们不应只放在“模型效果一般”的结论里。

| 维度 | 建议对外表述 |
| --- | --- |
| 有限开发与实验活动 | 已结束，冻结失败、费用和制品 |
| 固定长历史执行 | 已有一次完整实例，属于较早冻结源码 |
| 最终默认配置 | 可运行、可评分，任务失败；空删除副作用待修 |
| 条件系统 | 确定性三态已实现，真实语义表达未通过 |
| H2 可达性 | 一条自然材料与回答一致链已观察到 |
| H2 因果收益／泛化 | 未确立 |
| 普通记忆默认 | 保留简单对照与开发入口，不等于质量验收通过 |

原结果中“所有有限条件满足”的含义应限于诊断范围完成。若“结果可解释”还包含操作合同和任务边界都正确，smoke4 就是明确反例。建议后续交接把 **活动结项、运行覆盖、合同缺陷、任务质量** 并列，避免一个 COMPLETE 标签遮蔽已知 bug。

## 10. 修改优先级与最小验证建议

以下是后续修改建议，本报告没有启动新的 Goal、代码修复或实验。

| 优先级 | 修改 | 最小验收 | 不做的扩展 |
| --- | --- | --- | --- |
| P0 | 空删除无副作用；保存与删除意图互斥；按真实变更触发清理 | 空列表不改变记忆／任务／trace；普通保存不被吞；真实删除仍完成受管清理 | 不增加重试 Agent，不为所有写入加审批 |
| P1 | 真实删除有当前操作依据，历史状态变化只更新 | 停止活动不产生擦除能力；明确删除仍可执行且不泄漏正文 | 不用关键词禁词表或模型自报布尔值代替授权 |
| P1 | conditions／时间／状态说明分开；普通提案明确创建与更新 | 已暴露提案不再把注释当条件；更新对象与主题一致；临时句柄不成为永久指代 | 不建条件本体、日期猜测器或事实分类平台 |
| P1 | 当前卡写清当前理解，旧正文交给版本保存 | v569 的变化能被明确表达；v977 无关卡不被覆盖；v1002 不机械并列新旧优先级 | 不要求每次到达必须修改、不种入旧卡 |
| P1 | 精简共享回执；H2 先交付必要更正，响应内去重 | 相同版本／范围正文不重复；当前限制不丢；旧版本可按需读 | 不同时启动 H5、重写检索或扩大上下文 |
| P2 | 校准实验解释与结果汇总 | 未作答、Judge 失败、任务失败分别计数；状态一致不称因果收益 | 不修改数据、gold、rubric 或恢复确认集 |
| P2 | 沿修改点收拢状态所有权 | 删除副作用一个入口；条件计算一处；材料投影不改持久模型 | 不先大规模拆 runner 或重写事务系统 |

建议采用三段有限验证，避免新的复杂测试体系：

1. **先零模型调用修合同。** 在已有删除／Host 用例中覆盖空目标、混合意图和真实删除三个不同语义；对已暴露 conditions、时间和短句柄提案作定向检查。用冻结对象离线比较精简前后材料，不需要新增长历史实验。
2. **再用实际默认配置做一次修复复核。** 保持原题、问题、评分和所有失败记录，用新源码身份运行；目的先证明不再错误重置且完成用户任务。失败就定位实际回执，不循环同题直到得分通过。
3. **最后再检验普通更新和单一 H2。** 优先使用已有 v569／v1002 断点，v1003 作为已覆盖的材料链参照。普通写入语义未稳定前，不为候选继续买分数。涉及 LLM 的 Host 和 Judge 继续用 vLLM，不新开模型矩阵。

若进一步研究 H2 的独立价值，可在已冻结检索轨迹和相同候选材料下，做仅改变关联更正交付的窄消融，并完整披露直接新来源是否已足够作答。这与自然完整系统比较分开报告；不人为剥夺 baseline 的合法信息来制造胜出，也不以消融取代原生任务结果。

代码结构上，核心类现为 1,763 行、runner 1,514 行、ingestion 563 行，另有 capacity 244 行。行数不是验收标准，但继续把操作副作用、字段解释和材料呈现叠入大函数会放大耦合。先沿上述真实问题抽取窄函数与明确回执，保持改动可解释；不做纯粹移动文件的大重构。
