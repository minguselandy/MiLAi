我核对了 `d0367aab36c15b39bdd4e2c1fd7a92a542f66fcf`、v19 结果、机制 manifest 和 ODR 实现。现在的问题已经能比较精确地定位，**不应该继续修 structured reconstruction 本身**。

当前最关键的事实是：

> **模型不是“没看到 freshness”，而是看到了 freshness，同时仍然看到了完整的旧证据正文和自己先前基于旧证据生成的结论。**

changed 实例里，X@1=4°C 已经被真实检索进入 thread；X@2=8°C 更新后，执行前两个真实请求都收到：

```text
X@1 is superseded by X@2.
The current revision body is absent from this request.
```

但历史 ToolMessage 里的 **4°C 正文仍完整存在**，之前 assistant 自己说过的 “holding instruction is 4°C” 也继续存在。最终模型直接调用：

```text
record_holding_instruction(... temperature_celsius=4)
```

所以我建议把下一步从 **On-Demand Reconstruction** 再收缩一次，改成：

# **Freshness-Aware Evidence Projection / Selective Version Refresh**

而不是继续要求模型输出 reconstruction。

---

## 1. 先不要改代码：把现成 `freshness_only` 单独跑完

v19 已经实现了三个 arm：

```text
b1_control
freshness_only
odr
```

但因为原 gate，真正运行的只有 ODR，`freshness_only` 效果仍然是 `UNKNOWN_NOT_RUN`。

这个实验现在必须先做，因为 ODR arm 比 freshness-only 多了：

- 111 tokens/request 的 ODR protocol；
- evidence-handle catalogue；
- 强制 `reconstruction` 字段；
- 更复杂 JSON schema。

15/15 都输出 null 已经说明这些结构没有贡献，反而可能干扰普通工具选择。

所以第一步只运行同样三个 exposed fixture：

```text
changed
retained
irrelevant
```

使用：

```text
freshness_only
```

不新增任何 reconstruction schema。

### Gate

如果 freshness-only 已经做到：

```text
changed  → 8°C
retained → 实际取得 X@2 后仍 8°C
irrelevant → 8°C 且不额外查 Y
```

那么直接：

> **删除 active ODR candidate，选择 Freshness-only。**

这是最优结果，因为机制更简单。

# 2. 如果 Freshness-only 仍失败，真正该修的是“证据呈现”，不是 prompt

当前代码：

```python
protocol += "\n" + odr_freshness
```

也就是说只是追加一句：

```text
Evidence freshness:
- X@1 is superseded by X@2.
```

但旧 ToolMessage 仍然原封不动：

```text
The current depot instruction ... 4 degrees Celsius
```

这形成：

```text
强语义旧正文
+
弱元数据警告
```

LLM 继续使用旧值并不意外。

下一步应该做 **request-time stale evidence quarantine**。

---

# 3. 核心修复：SUPERSEDED evidence 不再以“当前证据正文”形式进入模型

不要修改 checkpoint。

不要修改 LangMem Store。

不要删除历史。

只修改**发给 Provider 的 request copy**。

当前：

```text
ToolMessage:
memory X@1
"The current depot instruction is 4°C."
```

如果 request-time 检测为：

```text
X@1 -> SUPERSEDED by X@2
```

Provider 实际看到的应改成类似：

```text
Historical memory X@1
Status: SUPERSEDED
Current revision: X@2
Historical body is not current evidence and is withheld here.
Current revision body has not been retrieved in this request.
```

而不是同时看到完整 4°C 正文。

形式上：

\[
\boxed{
\text{stale detection}
\rightarrow
\text{stale evidence quarantine}
}
\]

不是：

\[
\text{stale detection}
\rightarrow
\text{another warning beside stale content}
\]

这才是真正解决 changed 失败的地方。

---

# 4. 多条搜索结果必须逐项处理，不能把整个 ToolMessage 丢掉

例如 search 返回：

```text
X@1 = holding 4°C
Y@1 = some current unrelated fact
Z@3 = another current memory
```

只有 X stale。

Provider 投影应成为：

```text
X@1 — SUPERSEDED by X@2; historical body withheld

Y@1 — <original current body>

Z@3 — <original current body>
```

因此需要的是：

> **item-level version-aware material projection**

而不是粗暴删除整个 search ToolMessage。

你现在 B1 sidecar 已经有足够信息做这件事：

```text
search.returned_json
memory_id
revision
score/order
latest_revision()
```

不需要新数据库。

---

# 5. 第二个污染源：历史 assistant 自己说过“4°C”

这比 ToolMessage 更隐蔽。

即使 stale ToolMessage 被屏蔽，thread 里还有：

```text
assistant:
"The holding instruction is 4°C."
```

这个句子不是 evidence，只是旧模型输出。

因此需要把 evidence authority 写清楚，但不需要追踪 assistant proposition。

建议在共享 system contract 增加一条非常短的稳定原则：

> **Previous assistant statements are not authoritative evidence about external or remembered state. Use current user/tool evidence for current action parameters.**

特别是在存在 stale marker 时：

> **Do not reuse a prior assistant value merely because it appeared earlier in the conversation.**

这不是 benchmark-specific prompt，也不是告诉模型 8°C。

它只是建立正确的 source authority：

\[
\text{user/tool/current memory}
>
\text{assistant's prior claim}.
\]

---

# 6. 不要再让模型输出 reconstruction

v19 已经给出了很强的 kill evidence：

```text
nonnull reconstruction = 0 / 15
```

同时 decoder probe 证明：

```text
模型“能”生成这个格式
```

但真实轨迹：

```text
模型“不选择”使用这个格式
```

所以问题不是 decoder reachability。

继续做：

```text
reconstruction required
```

只会变成 deterministic compliance gate。

这会重新走 v18 的老路。

因此建议：

```text
methods/on_demand_reconstruction/schema.py
```

保留为 v19 历史实现，不再作为 active candidate。

新的 active method 根本不需要 reconstruction response field。

# 7. 新算法应该非常小

可以定义为：

## **Selective Version-Aware Evidence Projection**

每次 Provider request 前：

```text
1. 找出实际将进入 request 的 memory materials
2. 查询 exact current revision
3. CURRENT:
      原样呈现
4. SUPERSEDED:
      quarantine historical body
      expose current_ref
5. DELETED:
      quarantine body
      mark deleted
6. UNKNOWN:
      保持 unknown，不伪造 currentness
7. 调用原 LLM / 原工具
```

没有：

```text
Decision state
recheck state
reconstruction state
ack
completion
attention state
```

复杂度大幅下降。

# 8. 第一版仍然不要自动读取 X@2

这一步很重要。

先让模型看到：

```text
X@1 stale
X@2 exists
X@2 body not delivered
```

但不自动给 X@2 正文。

然后看它是否自然：

```text
search_memory(...)
```

如果会，说明：

> **旧值之所以一直被使用，主要是因为旧正文没有被真正降权。**

这就是一个非常干净的结果。

---

# 9. 如果 quarantine 后模型仍然不搜索，再进入第二级：Exact Current Refresh

这时才需要引入 retrieval-control。

而且不应该做 similarity search。

B1 已经知道：

```text
memory_id
current revision X@2
```

所以可以直接做：

\[
\text{resolve current version of the same memory object}
\]

即：

```text
X@1 stale
→ exact memory_id
→ Store.get(memory_id)
→ deliver X@2
```

这不是新的语义检索。

这是：

> **版本解析 / exact refresh**

类似数据库里的：

```text
old version pointer → current version
```

这个算法比“State-Attention”干净很多。

可以叫：

## **Selective Exact-Version Refresh**

只在：

```text
a stale memory is actually about to enter a Provider request
```

时触发。

# 10. changed / retained / irrelevant 三例正好可以形成三种测试

### Changed

```text
X@1 = 4
X@2 = 8
```

目标：

```text
old body quarantined
→ current evidence acquired
→ action = 8
```

### Retained

```text
X@1 = 8 + note A
X@2 = 8 + note B
```

目标不是只看动作 8。

必须确认：

```text
X@2 actually acquired
```

这样才能证明是 current-state reasoning，不是碰巧旧值相同。

### Irrelevant

```text
X current
Y@1 -> Y@2
```

如果 Y stale：

```text
quarantine Y
```

但不能导致：

```text
重新搜索 X
额外搜索 Y
错误改变 temperature
```

这是 selective intervention 的核心。

# 11. 我建议下一轮用四臂，而不是再造一个“MiLAi State”

只在三个 exposed mechanism cases 上：

| Arm | 机制 |
|---|---|
| **A0 B1** | 原 LangMem baseline |
| **A1 Notice** | 当前 v19 freshness-only |
| **A2 Quarantine** | stale正文 request-time 隔离 |
| **A3 Exact Refresh** | quarantine + exact current-version material |

但采用**顺序 gate**，不需要一次全跑。

先：

```text
A1
```

如果成功，停止。

失败再：

```text
A2
```

如果成功，停止。

失败再：

```text
A3
```

这样不会浪费模型请求，也能清楚定位真正必要的机制。

# 17. 最关键的研究判断

v19 已经证明：

\[
\text{structured reconstruction} \;\not\Rightarrow\; \text{natural use}
\]

但它**还没有证明**：

\[
\text{freshness signaling is useless}.
\]

因为真正的 `freshness_only` arm 尚未运行。

而当前代码又暴露了一个更基础的 presentation bug/limitation：

> stale evidence 被标成 stale，但仍以完整、权威感很强的正文继续呈现。

因此现在最优先解决的不是“让模型更会推理”，而是：

\[
\boxed{
\text{Do not present superseded memory as current evidence.}
}
\]

这条原则比 Decision Basis、ODR、Attention 都简单，而且和版本化 memory 的语义天然一致。

---

## 我建议把后续方向正式改为

```text
B1
 ↓
Freshness-only
 ↓ if insufficient
Stale Evidence Quarantine
 ↓ if insufficient
Selective Exact-Version Refresh
 ↓
再决定是否需要 retrieval Attention
```

而不是：

```text
B1
→ Decision State
→ Recheck
→ Reconstruction
→ Attention
```

如果 **Exact-Version Refresh** 能稳定解决 changed/retained，同时 irrelevant 几乎零干扰，我认为这会比当前 Decision-State 路线更优雅，也更接近一个真正可发表的算法核心：

> **只在即将消费过期记忆时，解析并提供当前版本；没有相关变化时完全不介入。**

这就是非常清晰的 **selective adaptation**。
