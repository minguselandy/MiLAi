## 2. 实验设置与样本边界

### 2.1 原题与五条路径

本轮只使用 MemSyco-Bench 的 `valid_memory_selection` 任务中三个已经暴露的原题。原问题、历史正文、角色、消息顺序和原生评分规则保持不变；没有新增题目、消费未使用确认集或修改 gold。

| 原题 | 原生子类型 | 主要诊断内容 | 最终执行路径 |
| --- | --- | --- | --- |
| v11_001003 | narrowing | 用户与 assistant 经历归属；志愿服务从泛化社区参与转向结构化课后法律课程 | ordinary 在线六批；独立 State 在线六批 |
| v11_000977 | reversal | 起写与停写影评博客；保留独立 fan-trailer 创作经历；避免把新建议写成用户事实 | ordinary 默认自然一批；ordinary 在线六批 |
| v11_000569 | reversal | 从建设性聊天转向严厉批评和激烈讨论；后续活动不能使新偏好丢失 | ordinary 在线七批 |

v1003 和 v977 的合法历史各有 12 条消息，v569 有 14 条消息。三个不同原题合计 38 条消息；五份独立历史构建合计处理 62 条消息，重复执行不增加独立样本数。

“在线回放”按既定到达边界处理完整原文，实际分批数为 6、6、7；“自然一批”是在容量规则下完整接收 v977 历史。分批边界不同会改变中间记忆状态、修订机会和调用成本，不能要求两条路径产生相同卡数，也不能将其差异全部归因于某个记忆机制。

### 2.2 模型、预算与方法身份

| 项目 | 最终配置 |
| --- | --- |
| Host | vLLM，Qwen3.6-35B-A3B-FP8，temperature=0，单次输出上限 4096 tokens |
| 原生 Judge | vLLM，同一 Qwen 权重及聊天模板，独立评分请求，输出上限 2048 tokens |
| Embedding | bge-m3，1024 维；长输入沿已有窗口合同处理 |
| 单题作答请求上限 | 6 次；State 初始操作也计入其中 |
| Judge | 每份最终答案 1 次；冻结答案后评分 |
| 并发 | 单个 Host 工作流 |
| 历史提案 | 最多 6 项操作；旧上下文材料预算 12000 bytes |
| 累计预算 | 请求、生成 tokens、embedding tokens 的硬停止均已按用户要求解除；同一账本持续累计 |
| 运行配置 | ordinary 为基线；State 只在独立 State 路径开启 |
| 候选策略 | H1—H6 保持冻结；未开展 H2 效果复跑 |

Host 和 Judge 使用相同模型，因此原生评分是同模型开发评估，不能作为独立模型验证。temperature=0 也不等于已经证明重复运行结果稳定。

ordinary 与 State 的历史身份不同，最终分别从原文形成记忆，没有绕过历史所有权校验或编辑 checkpoint 标志来共享历史。这保证了执行身份真实，但也意味着两者不是“相同记忆快照，只开关 State”的纯读取消融。

### 2.3 实际记忆流程

```text
固定合法历史
  → 适配器保留真实角色、来源、顺序与范围
  → 程序接收原文，并交付本批新观察和相关旧记录
  → 同一 Host 提出 CREATE / REVISE / NO_CHANGE
  → 程序绑定已交付引用，检查主体、来源、版本及依赖合同
  → 提交局部变化，保留来源和旧版本
  → 形成独立答题快照
  → ordinary：搜索、必要读取、回答
     State：先形成任务 State，再搜索、必要读取、回答
  → 冻结答案
  → 原生 Judge 评分，汇总所有阶段成本
```

程序负责确定性身份与执行边界。Host 仍负责判断新信息改变了什么、应该修订哪个事项、如何表达当前理解。合法引用和成功提交不会自动证明正文得到来源的语义支持。

### 4.2 三个语义修复实例

**v1003：主体归属与范围收窄。** ordinary 的用户卡达到 `card:1@6`，独立 State 路径达到 `card:1@5`。两条路径都保留用户转向结构化课后法律课程、scheduled workshops 和 tailored curricula 的当前偏好。assistant 的住房／环境文章经历没有成为用户履历；State 路径也不再把用户的法律话题探索写入 assistant 传记。旧版本仍保留，当前卡的活动依赖为空，没有用自身旧版制造活动依赖。

ordinary 当前卡引用七条来源，其中一条为 assistant 对话语境；State 当前卡引用五条 user 来源。因此修复保留了跨角色材料的合法使用，并未把“引用了 assistant”一律视为错误。

**v977：同批历史与在线变化。** 自然一批生成五张不同事项的卡，博客卡同时引用起写和停写来源，fan-trailer 为另一张独立卡。在线路径最终是一张较宽的当前卡，但仍明确博客已经停止，fan-trailer 是保留的正面创作经历，没有把停止影评套到创作活动上。两份答案均围绕当前轻松观影需求完成任务。

**v569：新偏好没有被后续活动覆盖。** 当前讨论偏好卡达到 `card:2@5`，同时关联旧建设性聊天、新的严厉批评偏好及后续社交活动。万圣节活动到达后，新偏好仍保留并用于答案；播放列表与改编兴趣继续保存在另外两张卡中。

这些实例证明了指定错误在最终执行中得到修复；并不证明宽卡中的每个解释、因果连接或 certainty 都准确。

### 4.3 功能使用范围

| 设计能力 | 本轮实际证据 | 不能扩展出的结论 |
| --- | --- | --- |

## 5. 成本、材料体积与效率

### 5.1 最终验证的阶段成本

“生成 tokens”均指生成模型请求的输入与输出之和，不是只统计回答正文。Embedding 单独记录，不与生成 tokens 合并为精确费用。

| 最终阶段 | 生成请求 | 输入 tokens | 输出 tokens | 合计 tokens |
| --- | ---: | ---: | ---: | ---: |
| 历史摄入 | 26 | 99,505 | 8,007 | 107,512 |
| 作答 | 12 | 49,917 | 1,393 | 51,310 |
| 原生 Judge | 5 | 5,677 | 430 | 6,107 |
| **合计** | **43** | **155,099** | **9,830** | **164,929** |

最终 embedding 共 51 次请求、21,624 tokens：历史阶段 41 次／9,678 tokens，作答阶段 10 次／11,946 tokens。

最终生成模型 tokens 中，输入占 **94.0%**；作答阶段输入占 **97.3%**。继续压缩最终答案长度难以解决主要开销，优化应优先考虑重复输入、工具说明和材料元数据。

### 5.2 全部开发成本

| --- | ---: | ---: | ---: | ---: | --- |
| 冻结上下文诊断 | 9 | 39,409 | 4,481 | 43,890 | 0／0 |

39 个运行／诊断目录的汇总与连续账本一致，unknown usage 为 0。HTTP 请求有完整收据不等于语义成功；提交被拒、错误提案、未评分历史和原生失败都计入上述成本。

首次阶段为 57 次生成，后续继续开发为 186 次，累计没有清零。最终 43 次验证已经包含在 243 次中，不能再次相加。其余 200 次请求承担诊断、修复及较早版本回归，不能一概称为浪费，也不能隐去后宣称方案只需最终验证成本。

全阶段输入占 **94.3%**，最终验证生成 tokens 约占本轮总量 **17.0%**。本轮不是一次成功，也没有证明开发成本低。

用户报告本 Goal 用时约 2 小时 7 分钟，代理 tokens 为 1,705,197。这两项属于开发过程记录，本次未从 vLLM 账本独立重建；代理 tokens 不与上述 vLLM tokens 相加充当部署费用。现有数据也不足以给出精确金额、独占 GPU 时间或线上单次查询成本。Judge 费用属于评估成本。

### 5.3 State 的观察性成本比较

同一道 v1003 中，ordinary 与 State 均原生通过；ordinary 作答 2 次、8,436 tokens，State 作答 3 次、13,042 tokens。State 路径的作答 tokens 高约 **54.6%**，整条路径生成 tokens 高约 **9.8%**。

这是两条实际运行的成本差异，不能单独归因为 State：两者独立形成历史，最终卡正文、来源集合和版本也不同；State 还有规定的额外起始步骤。当前没有观察到该题分数改善，因此只能确认 State 可执行及其此次额外开销，不能声称其成本已经换来质量收益。

| 引用与状态元数据部分 | 4,508 |

两种序列化体积相差约 **69.4%**；引用与状态元数据约占交付材料 **40.7%**，另有外壳差额。最终记录中的 omitted_body_bytes 均为 0，说明该指标下未记录正文省略。

这是同次运行内部对象与模型视图的体积测量。内部完整表示并未作为另一个作答臂实际交给模型，因此不能将 69.4% 称为端到端成本节约或质量无损的因果证明。材料只占模型输入的一部分，多轮请求还可能重复携带既有 transcript。该测量支持继续检查公共回执和材料表示，不支持直接重启 H5 或扩大上下文。

## 6. 当前仍存在的问题

以下分开列出现存观察、工程能力边界与尚未验证的研究问题。它们不撤销本轮已经达到的限定目标，也不能被五份原生通过覆盖。

### P1-1：记忆仍按宽泛话题聚合，局部事项边界不足

**已观察到：**v1003 的单张当前卡包含志愿服务变化、AI 法律兴趣、隐私和就业问题、影视偏好、青少年课程及讨论组。v977 自然批有五张事项卡，在线路径逐步聚成一张六版本卡。v569 的讨论偏好与电影社交活动也在同一卡中。

这一次目标偏好仍被正确使用，但后续局部更新需要重写一大段复合正文，存在覆盖无关事项、增加来源集合和重复输入的风险。风险不等于本轮已经发生了新的误覆盖。

现有提示已要求同一主体、同一事项才合并，说明单纯增加这句说明不能算新的修复。应先改善旧目标的交付：清楚展示事项、当前范围和原依据；新信息属于另一事项时允许自然 CREATE。验收看无关事实是否保留、改变是否局限于受影响事项，不强制每条消息一张卡、固定卡数或引入主题注册系统。

### P1-2：正文仍有超出来源的解释，certainty 过于粗糙

**已观察到：**最终 v1003 ordinary 卡把对 AI 的兴趣进一步表述为最初从事志愿工作的动机，强于已取得来源。最终 11 张当前卡的 certainty 均为 explicit，尽管其中混合了直接陈述和模型解释。早期 fan-trailer 与安静观影之间的无依据反差也有记录。

共享 save 对“仅有 assistant 来源的持久 current_user 事实”会拒绝，但它只建立来源边界：一旦来源集合包含非 assistant 材料，程序仍不能据此证明整段整理的全部因果关系成立。混合引用也不证明用户采纳了历史建议。

建议先减少没有直接依据的因果连接，区分明确陈述和推断；无法支撑的动机可省略或明确保持不确定。继续允许有价值的作者理解，不以增加第二个语义审核模型、关键词真假判断或自动篡改来源替代问题。后续小规模检查应同时看正文与来源、certainty 是否相称，而不是只看引用数组非空。

### P1-3：临时来源句柄仍进入持久正文

**已观察到：**最终 v1003、v977、v569 的卡正文仍含 s0、s2 等批内来源别名。v977 最终正文中，不同事项的句子都出现 s0；这些标记来自不同提案环境，脱离批次后不能可靠解释为同一来源。

结构化 source_refs 仍然绑定准确来源，本次没有证据表明底层引用因此被错误改绑。问题在于持久文本自身的引用表达不能独立理解，后续 Host 可能把临时符号当成持续有效的依据。

建议正文以可独立理解的事项、主体和时间表达含义，引用由结构字段承载。若确实需要逐段引用，应使用协议明确的引用结构再由程序投影；不要正则替换所有自由文本中的 sN／pN，也不要修改旧冻结制品来制造已修复的记录。

### P1-4：State 把尚未观察误写成不存在

**已观察到：**最终 State 首次更新在读取之前断言没有相关历史，后续搜索确实把这段否定带入有效查询；实际记忆中有相关用户历史。

结构化 coverage 仍为 UNKNOWN，基线搜索也继续执行，所以本轮没有因此拒答或跳过检索。但自由文本任务态与结构化状态不一致；若未来依此控制取材，可能产生错误过滤或提前停止。该后果目前是风险推断，不是此次已观察失败。

建议初始化 State 只表达当前问题、已知任务要求和待核对内容；“尚未检索”与“检索后仍缺材料”分别处理。后续事实判断应引用实际材料与覆盖结果，不需要扩展一个新 Agent。不要用屏蔽所有否定句的方式修复。

### P2-1：功能调用还不能证明决策价值

State 的首轮调用由适配器编排，而非模型自由选择；本轮也未证明多轮 intentions、conflicts 或其他 Attention 分支在真实任务中带来收益。H1—H6 未进入当前最终配置，不能将普通版本修订当成支持组、事件操作或关联更正候选的完整验证。

建议继续沿“机会存在 → 材料可见 → 操作提出 → 提交成功 → 后续使用”说明每项机制。当前三题可用于定位执行问题；若未来恢复方法研究，应另行冻结对照和数据范围。本报告不启动新候选、不消费确认集，也不将同一题反复通过称为独立证据。

### P2-2：操作结算数容易被误读为真实变更数

**已核对源码与回执：**摄入器将 completion 为 complete 或 pending 的单元纳入 committed_units，其中包括合法 NO_CHANGE。最终汇总为 42 个 committed_units，实际由 11 次 CREATE、18 次 REVISE、13 次 NO_CHANGE 组成。

这个字段可用于执行恢复记账，但不等于 42 次记忆变更。当前报告已经按操作和实际版本区分。后续只需在汇总层增加或明确“结算单元、实际变化、无变化、未完成”口径；不要为修改报表名称重写局部提交和恢复机制。

### P2-3：输入成本占主导，尚无成本优势证据

公共投影减少了序列化体积，但输入仍占大多数请求 tokens，状态与引用元数据也占交付材料约四成。宽卡、完整修订、工具合同以及多轮 transcript 都可能增加输入，现有统计不能将全部开销归因于某一个部分。

建议先利用已有冻结请求定位具体重复项，只改可测得的公共表示。比较必须保持来源角色、当前／历史标记、必要限制和准确版本。没有测得深拷贝或本地事务成为主要瓶颈，不宜优先重写事务系统、引入并发或新缓存层。

### P2-4：准确来源锚点还不是现实人物身份

当前 p 前缀句柄稳定对应一个准确来源；u0 对应当前用户。此设计解决了局部编号漂移，但不自动判定两条来源是否由同一个自然人提供，也不完成引文说话者、多人对话或转述主体的语义解析。

这是应明确的能力边界，不需要立即建设实体图。未来只有在原题或真实任务出现对应需求时，再做最小范围的主体消歧；保持说话者、被描述者和作者三个概念分开。

### P2-5：开发回归成功，泛化与单项因果仍未知

三个原题已多次暴露，多个版本在同一组题上修复；最终通过是开发集上的回归结果。Host 与 Judge 同权重，原生评分主要判断答案是否使用当前偏好，不覆盖持久正文中的所有事实。

v6-compact 的“评分通过但写入有误”已证明这不是抽象担忧。应保留原生分数，同时单独记录记忆状态检查，不改 rubric、不人工将未通过改为通过，也不要求增加大规模人工审核。

## 7. 修改优先级与轻量验证建议

本节是后续建议，未开启新 Goal、未实施运行时改动。累计硬停止和复核次数限制维持解除；使用同一账本持续记账，单次工作流仍受模型容量和服务能力约束。

## 8. 研究与创新判断

本轮主要贡献属于工程与接口收敛：准确来源锚点、角色与正文的交付顺序、明确创建／修订语义、局部写入边界以及可追溯执行链。实际受约束生成后端中的可表达性检查也很重要，单纯 JSON Schema 合法不能替代它。

这些工作为后续记忆机制研究提供了可运行基础。现有数据不能支持新的算法优越性、创新性或统计显著性结论。特别是：

- 当前答案可能仅靠直接读取新来源即可完成，不能从“材料中存在修订卡”推断“修订卡不可替代”。
- State 和 ordinary 在同题均通过，尚无额外质量收益证据。
- 多项提示、表示和合同同时修复，无法识别单一改动的因果贡献。
- 本轮没有完整 RAW_RETRIEVAL 对照，也没有重跑 H1—H6 的效果比较。

值得继续研究的问题是：在准确来源、可比预算和清晰事项边界下，版本化理解是否能减少后续误用；State 是否能在确有信息缺口时改善取材；必要修订关系是否具有直接原文检索难以替代的价值。它们仍是研究问题，不能写成已经实现的收益。
