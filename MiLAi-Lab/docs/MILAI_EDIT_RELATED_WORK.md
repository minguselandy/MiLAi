# MiLAi-Edit 方法核对记录

核对日期：2026-10-05。原计划中的发表与开放性核查仍单独保留；本记录补充实际方法比较，不把代码开放、正式发表和方法原创性混成一个判断。九篇原始论文的 HTML 与可读文本保存在仓库外的 `/cra/memory/mx_memory/reference-sources/milai-edit/papers/`；`retrieval-manifest.json` 记录实际地址和下载时间。没有另行下载模型或训练这些方法。

| 原始工作与实际阅读位置 | 已有机制 | 对本候选的约束与待检验差异 |
| --- | --- | --- |
| [A-MEM，v11，§3 与附录 B](https://arxiv.org/html/2502.12110v11) | 笔记保存原始内容、时间、关键词、标签、上下文、向量与链接；相似检索后生成链接，演化旧笔记的上下文和属性；读取可扩展相邻笔记。 | 结构化笔记、动态连接与演化已有明确先例。当前对照使用作者复现仓库的原始类，Qwen/BGE 回调和共同 Reader 属于公开适配，不能称复现原论文分数。M 的条件单元和局部算子是否减少连带损坏，需要 B1/B2 与真实序列结果。 |
| [Hindsight 研究论文，§3–6](https://arxiv.org/html/2512.12818) | 世界、经历、意见与观察四种网络，事实含发生区间和提及时间；retain/recall/reflect、混合检索及意见强化。 | 来源类型、时间组织和不同性质的记忆不构成新贡献。当前 M 未实现该四网络或意见学习；比较的是同一编辑载体中条件与内容的关系。未在本地运行 Hindsight，不拿其报告分数代替共同配置下的实测基线。 |
| [RARR，§2–3](https://aclanthology.org/2023.acl-long.910.pdf) | 对生成文本提出问题、检索网页证据、判断一致性，再最小修订；同时评价归因与保留，原方法还限制大幅字符编辑。 | 有证据的最小修改和保留评价均已有先例。持久记忆的连续修订、范围内例外与取消需要另测；字符保留不能直接充当语义条件保持。当前未接入 RARR 的搜索或编辑器，不把普通局部替换命名为 RARR。 |
| [HiMem，§2](https://arxiv.org/html/2601.06377) | Episode/Note 两层，主题与意外事件分段、多阶段提取；Note 不足且 Episode 有支持时，按独立、可扩展、矛盾关系进行 ADD/UPDATE/DELETE。 | 证据驱动的分类更新、不可变原始历史和删除已有近邻。M 未采用其问答触发的再整合与层次检索；假设限于显式条件和局部操作在共同读取下的作用。 |
| [SimpleMem，§2](https://arxiv.org/html/2601.02553) | 结构化压缩、写入时的语义合成与去重、符号/语义/词汇多视图索引和按意图规划检索。 | 自包含单元、合并和去重不能单独作为新算法。当前实验固定共同检索与 Reader，不把这些变化混入编辑算子的效果。不同 Text/Omni/Evolve 后端不共享一个未经核对的方法身份。 |
| [TrustMem，§3](https://arxiv.org/html/2606.25161v1) | Write/Revise/Prune；转换级 frozen-LLM verifier 检查 coverage/preservation/faithfulness；多粒度奖励及同状态候选排序参与 TR-GRPO 训练。 | 转换级覆盖、保留和忠实性评价已有明确设计。M 第一版不训练、不多候选排序；事后机制 Judge 只用于评价。若使用同家族核对，应另列原提案错误和最终错误，不能把核对本身称独立证明。 |
| [DeltaMem，§3、§5.1](https://arxiv.org/html/2604.01560v1) | 单 Agent 搜索并 add/update 普通原子记忆，含 training-free 版本；合成 expand/adjust/shift/partial-deletion，RL 奖励结合状态匹配和局部词汇保真。 | 轻量更新、局部调整和部分删除已有实质先例，不能以未部署其代码为理由忽略。待检验的是条件化表示与具体执行算子的边际效果，以及词汇保留之外的语义、范围和撤销结果。 |
| [MemTX，v2，§3–4](https://arxiv.org/html/2607.23929v2) | 记忆生命周期、快照事务、证据/有效期/冲突/依赖检查、动作门控和按类型级联修复；区分 scripted 强门控与 LLM 实验边界。 | CAS、事务、权限和恢复属于已有系统机制。本候选沿用当前 Service，未实现其整套信念协议；不能从保存回执推导业务授权，也不能将历史或撤销接口当作独立算法新颖性。 |
| [StateMem，§5 与附录 E](https://arxiv.org/html/2608.19652) | 带优先级、来源和 derived_from/coupled_with 边的持久单元；supersession 后确定性标记依赖需要重检，Reader 根据当前状态和触发原因重新计算。 | 显式单元、依赖、替代、保留历史和状态重检已有直接近邻。M 只实现一层条件/覆盖关系，未实现通用依赖传播。须具体比较操作与适用范围，不能声称首次用关系维护演化记忆。 |

上述差异是基于原始方法的推断，不是原创性结论。B0/B1/B2/M 四格先分开普通或条件表示与整体或局部操作；E2 用各臂自行形成的真实旧状态，并列 NeverWrite 和 RetainAll；E3/E4 检查后续回答、连续损坏与措辞/语言变化。用户已明确要求一个模型家族，所以生成与 Judge 都使用现有 Qwen3.6，不能据此主张跨模型家族或独立家族核对。

候选贡献在结果完成前仅能写成：检验“条件化内容载体配合有限局部操作，是否在有效更正与未改语义保持之间取得可重复改进”。若 B1 与 M 相近，按原计划缩小到普通局部编辑；若 B2 解释了收益，就承认表示因素；若仅个别受控故事有效，则不推广为公开长期记忆算法优势。正式贡献草稿仍待完整实验与功能回归。
