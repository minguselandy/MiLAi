## 0. 开工摘要：本轮改变什么

### 0.1 明确的方向调整

v2 已推动动态循环进入 Lab Host。本版不重做循环，而是将其放回**工具内部**，改变研究对象：从“给整个 Host 配一个控制器”转为“根据 Host 的调用要求，自适应执行一次记忆检索”。

Host 决定用户要完成什么、为什么需要记忆、查询什么时间和对象。Jev 决定在这些要求下从哪里找、读多大范围、是否复用解释、是否刷新，以及何时返回。本次检索不重新规划用户的业务任务，不自行改变 Host 的对象、时间或资源上限。

**增加字段不是成果，字段导致正确且有价值的行为变化才是成果。** 同样，一次合法工具调用、一次正确操作、证据充分和 Host 最终成功分别观察，不互相替代。

### 0.2 首个可交付切片

在现有 Lab Host 注册一个拟议的 `milai_retrieve` 工具：支持仅 `query` 的简单调用，也支持带 `read_goal`、当前上下文和预算的调用。复用原规则策略与本地 Laya 后端，直接返回来源片段；第一次交付不要求新的训练权重，也不要求自动生成完整覆盖报告。

用六条开发历史、每条两个不同取证目标，分别运行规则与 Laya，共 **24 次外部工具调用**。内部决策次数随状态变化，不能把 24 次工具调用称为 24 次模型请求。这一切片必须经过真实 Host 原生工具调用，不只手工调用 Python 函数。

### 0.3 数据与评测的选择

| 职责 | 首选资源 | 本轮用途 |
|---|---|---|
| 理解检索要求 | **FollowIR-train** | 学习查询相关性与要求符合性之间的区别 |
| 理解记忆变化 | **MemOps 已划入训练的背景＋新编训练历史** | 时间、主体、确认/计划、变化后补证 |
| 已读条件下的互补证据 | **MuSiQue-Full TRAIN；2Wiki TRAIN 作补充** | 构造真实已读前缀和必要补证，不将静态 QA 当完整记忆训练 |
| 学习内部执行 | **MiLAi 的实际工具训练轨迹** | 操作、参数、执行反馈与返回材料，这是主要监督对象 |
| 指令敏感性外部诊断 | **InstructIR；FollowIR 评测部分作为可用时的补充** | 同查询不同要求是否改变正确排序 |
| 工具作为记忆后端 | **LongMemEval-V2** | 返回紧凑证据给固定 Reader，评价质量与查询成本 |
| Host 利用记忆完成工具任务 | **Mem2ActBench_small** | 记忆参数补全；自主选工具另列扩展协议 |

资源情况与限制见第 7 节。没有一个现成数据集直接提供本版完整的 `HostRequest → 内部操作及参数 → 工具结果` 标签，必须经过实际执行转换。

## 1. 当前事实与本版设计的边界

### 1.1 已核查事实

远端研究头仍为 `1d568169`。[R1] 当前导航说明动态读取、真实操作训练、视图、历史导航与正常 Host 接线已存在。已关闭的外部开发切片为 8 背景、每方法 48 任务：24/36 背景 Laya 完整成功分别 11/48、20/48，固定上下文 22/48、规则动态 30/48；这些不是独立外部盲测，也不表示规则在所有任务上最优。[R2]

当前文档中的运行中进程、81 背景待训练和剩余确认只是发布时快照。本版没有访问开发机确认其即时状态，也不替正在执行的旧实验更换方法或重置费用。

代码已经有 `StructuredReadGoal` 和部分读取选择器上的 `read_goal`，可以作为新增入口的基础，而不是另造多套同义字段。[R3] 已有五类操作循环和策略工厂可继续使用；类型化决策不需要再套一层复核模型。[R4–R6]

### 1.2 本版新增的是设计，不是已有能力

本版提出的工具名、扩展字段、请求条件监督、预算档位、数据规模和实验编号都是拟议设计。实现时优先挂接当前已有入口；不把文档中的配置写成已经可以运行的 CLI。

首轮仅扩展检索与派生视图能力。显式保存、更正、遗忘继续由原专门操作处理；**读取请求不暗中改变持久事实**。允许的派生视图缓存不等于新的用户事实或业务授权。

历史保存状态查询需要实际存储版本。普通对话记载的“当时说过什么”不能代替“当时系统实际保存了什么”。这类差异用现有版本能力测试，不从公开 QA 的答案字段虚构数据库历史。

## 2. 目标架构与最小调用合同

```text
用户任务及 Host 当前合法上下文
    ↓
Host：在原工具调用中表达检索需求，不额外加一个规划 Agent
    ↓
milai_retrieve(request)
    ├─ 将请求映射到当前 MemoryControlState
    ├─ 构造当时真实可执行的操作＋参数候选
    ├─ Jev/规则/生成式策略选择
    ├─ 调用原检索、证据读取、历史、视图模块
    ├─ 用实际执行结果更新工具内部状态
    └─ 返回实际证据、结束原因和用量
    ↓
Host：回答、产生目标工具参数，或请求另一个确有必要的记忆操作
```

### 2.1 四种职责

| 部分 | 负责 | 首轮不承担 |
|---|---|---|
| Host | 原任务理解、是否调用、取证目标、最终综合和业务工具选择 | 不编排每一次内部 READ/SEARCH |
| Jev | 请求条件下的操作与参数选择 | 不修改原任务，不生成任意业务动作 |
| MiLAi 执行器 | 真实检索、读取、导航、视图操作与结果返回 | 不把成功返回解释成语义正确 |
| 原运行时 | 身份、来源可见性、版本与已有资源约束 | 不用新规则替模型判断每个语义问题 |

### 2.2 最小请求：简单任务不填表

以下为**拟议工具参数**，不是当前公共 API：

```json
{
  "query": "此前保存的晨会语言偏好是什么？"
}
```

### 2.3 丰富请求：表达目的，不规定程序

```json
{
  "query": "A项目在2026年11月2日的差旅审批门槛是什么？",
  "read_goal": {
    "purpose": "为审批说明补齐可核对的政策依据",
    "evidence": ["original_source", "current_interpretation"],
    "required_points": ["适用项目和费用类型", "金额门槛", "生效日期与例外"]
  },
  "task_context": {
    "as_of": "2026-11-02",
    "target_scope": {"project": "A"},
    "known_evidence_refs": []
  },
  "limits": {
    "max_return_tokens": 2000,
    "max_control_steps": 8
  }
}
```

字段决策如下：

| 字段 | 含义 | 执行规则 |
|---|---|---|
| `query` | 完整取证问题 | 必填；保留指代和原任务语义，不强制关键词化 |
| `read_goal.purpose` | 证据服务的当前用途 | 可选自然语言，不枚举所有业务领域 |
| `read_goal.evidence` | 原文、当前解释、实际保存历史等证据需求 | 沿用现有名称；不把偏好原文解释成排斥必要关联来源 |
| `required_points` | 要补齐的关系或属性 | 从任务与当前已见上下文产生，不包含金标准答案或 gold 证据 ID |
| `as_of` | 所问事实的适用时间 | 不用数据下载或入库时间补成事实生效时间 |
| `target_scope` | 答案针对的实体、属性或范围 | 不自动等于禁止读取共享规则或关联对象的上下文 |
| `known_evidence_refs` | Host 实际已取得的材料引用 | 经原引用路径解析；旧版本是否仍适用另判断，不自动视为当前真相 |
| `limits` | 请求愿意花费的资源上限 | 与运行环境上限取可用范围；Jev选择实际投入量，不提高上限 |

调用方身份、命名空间和访问权限仍由已有运行上下文注入，不新增让模型自行填写的授权字段。没有明确时间的任务可保持时间未知，不能强行填入今天。

`required_points` 是语义线索，不是必填长清单；缺少可选字段时按 query 运行，而不是拒绝正常调用或再调一次模型“补齐表格”。

### 2.4 Host 要求与内部执行参数分开

Host 不应指定 `READ candidate7`、固定先取 8 条再读 4 条。内部可以选择的参数首轮限制为少量已实现方案：

- 检索视角：原文、当前解释、存储历史；后者只在对应来源能力存在时提供。
- 候选扩展：初批与下一批；候选批大小用预设小档位，例如 8/16，而非一次预测几十个连续超参数。
- 读取粒度：当前片段、原会话上下文、精确历史版本。
- 视图：使用现有视图，或针对具体来源范围调用一次既有刷新器。
- 返回：结束当前取证，交付实际材料及必要限制。

先做“一个操作绑定一组参数”的候选选择，避免独立预测十个字段后形成不可执行组合。候选不能用离线正确答案生成；同一实验的所有控制器使用同一个候选生成器。

## 3. 可直接用于首个切片的 Prompt

### 3.1 Host 工具描述与系统提示草案

```text
MiLAi提供对已有记忆及来源的检索，返回证据，不替你完成整个用户任务。

当任务需要过去的信息、变化过程、既有偏好或历史保存内容时，调用milai_retrieve。
query应说明此次需要解决的实际问题。只有在有助于取证时，再提供读取目的、
需要补齐的证据点、对象范围、查询时间，以及你实际已经得到的证据引用。

未验证的判断应保留为待核实问题；不要把用户问题的预设当成已知事实。
不要指定内部检索、读取、缓存或刷新顺序，由工具根据请求和结果调整。

拿到结果后，以实际返回的证据继续原任务。工具结束不代表所有问题已经有答案。
确实仍缺材料时可以继续取证；不要为了调用而重复检索已得到的内容。
```

该提示放入原 Host 的工具描述/系统提示，不新增调用前的独立“意图分析 Agent”。Host 生成结构化参数产生的 tokens 和时延计入 Host 成本。

### 3.2 Jev 内部决策说明草案

```text
你控制一次MiLAi检索，不负责回答用户的完整任务。

根据Host请求、实际已读证据、剩余候选、新来源、已有视图和上一步结果，
选择最有助于完成本次取证的可执行操作。保持请求的对象、时间含义和资源上限。

只供导航的摘要、控制器观察、已经返回Host的证据是不同范围。
打开视图只是取得解释，不保证它正确或适用于当前任务。
有相关变化时考虑补读或刷新；现有证据已经足够时避免重复工作。
返回只交付已取得材料，缺失来源不能通过自己的判断补造。
```

Prompt 不写具体题目的应答规则，不包含训练家族名称或答案。训练与线上都调用同一请求投影函数，避免模型在训练时看到更完整或更“干净”的状态。

### 3.3 提示设计的两个必要对照

一是**等信息自然语言展开**：将丰富请求的字段转换为普通文本，用于判断收益来自结构字段还是额外表达的信息。二是**等义措辞变化**：字段顺序、描述语言和同义目的变化时，期望有效性保持，不要求输出动作 ID 完全相同。

真正改变 `as_of`、对象或所缺属性时，应改变适用结果。只改变返回预算时，不强制要求每个案例都改变路径；已有最佳短路径时保持不变是正确行为。

## 4. 工具状态与返回结果

### 4.1 在已有状态上增量扩展

复用 `MemoryControlState`，将 Host 请求与执行观察分开：

```text
request              原始 Host 需求与可选参数
visible_evidence     工具实际已读材料
returned_evidence    Host 已经获得的引用/本次准备返回的材料
pending_candidates   仅用于导航的候选与必要摘录
views / new_events   实际视图与新来源
last_result          已完成操作的真实结果
budget               剩余资源，不是语义充分性标签
```

这是逻辑分工，可映射到当前 `task/visible_evidence/...` 字典；不要求为了名称整齐更换全部旧数据格式。

不要每轮调用大模型重写完整状态摘要。版本、读取范围、已消耗资源由现有程序提供；相关语义正文与已有解释按当前决策需要投影。必要原文太长时提供可展开导航，而不是静默截断后让模型宣布“没有证据”。

### 4.2 返回证据而不是另一篇最终答案

首版返回：`evidence`、`termination_reason`、`usage`。`coverage` 与 `missing` 可选，只有确实产生了有依据的判断才填写；不为了字段完整再新增一个生成式评审调用。

```json
{
  "evidence": [
    {
      "ref": "example-source-A:revision-1:span-0",
      "kind": "original_source",
      "text": "示例：新规则从11月1日起适用于A项目的差旅。",
      "source_role": "user",
      "revision": 1
    }
  ],
  "termination_reason": "policy_return",
  "missing": ["本示例返回片段尚未包含金额门槛"],
  "assessment_kind": "model_assessment_not_certified",
  "usage": {
    "control_steps": 3,
    "source_reads": 2
  }
}
```

上例为格式示意，不是实际引用或执行回执。线上所有引用必须来自已存在的绑定路径。

结束原因至少区分策略返回、资源上限、可用范围没有进一步操作和执行异常。资源到限不等于来源不存在；策略返回也不自动意味着证据充分。沿用原 `HANDOFF` 即可，不为重命名新增一套执行机制。

### 4.3 请求内和请求间的动态性

请求内：根据读到的材料改变下一步。请求间：Host 通过已有引用和续取范围只请求剩余缺口。首轮使用原 Store 的版本化引用，不新建“会话恢复数据库”。

复用派生视图时，既看原支持是否可用，也看新事件是否改变了本次所问的含义。模型可以判断无关更新无需刷新；不要把所有新事件一律变成强制失效，也不要把版本未变一律变成语义有效。

## 6. 开发工作包：按可运行产物推进

### D1：Host → 工具 → Host 闭环

实现一个工具入口、一个请求投影、一个结果返回。先接规则与现有 Laya，使用原 Reader 作为 Host 的回答模块。此前 Laya 操作权重只作迁移起点诊断，不称为本版请求参数训练完成。

六条开发历史分别覆盖：简单事实；生效前后；原始表述与实际保存版本；Host已有部分证据；同名主体/作用域；缺少必要证据或旧视图过期。每条两种请求，至少一对只改变本次取证目的而不改变来源池。

产物：24次真实外部调用的请求、返回材料、Host结果和实际内部操作。它们是开发样例，不进入最后外部成绩。

### D2：请求条件下的参数调整

接入少量真实可执行的检索路径和范围参数。SEARCH 能根据当前请求要点选择初始检索，随后在发现新实体/缺口时补一次不同目标的搜索；不能只是对同一个 query 反复扩大 k。

检索字符串首先来自 query、已表达的 required_points 和实际读到的词语。首版无需单独的query生成模型；只有已定位到查询改写瓶颈时，才引入共用生成模块并计费。

产物：同一来源在不同请求条件下的路径和证据变化；不是每条历史都必须使用全部操作。

### D3：领域监督与自身轨迹

先用小批数据完成请求/操作学习，再补自身轨迹。首轮用一个种子修通学习链；主方法比较采用相同数据和预算的多个种子。现有 train/dev 数据归属保留，开发轨迹不因“急需数据”改成训练。

产物：一个明确版本的数据集、一组训练权重、同输入基线、真实工具级评价。训练方案见第8–9节。

### D4：外部接入与跨 Host 使用

完成 LongMemEval-V2 的 memory backend 适配与 Mem2ActBench 的 Host 使用流程。检索工具不需要继承所有外部框架；适配层只转换允许的输入/输出。

先用合成同格式样例调通接口，再在方法固定后进入外部任务。语义失败保留，必要工程修复用新版本记录，不把修后的成功回填原失败。

### D5：根据已定位瓶颈做一个小改动

若反复编码主导开销，做进程内模型复用、任务固定部分缓存或受控的来源表示复用；若过早返回主导失败，补返回/继续决策监督；若相关新来源未进入池，改SEARCH目标生成。不要三项同时改完后将收益归给一个名字。

本版不要求等待所有旧研究任务完成才编码，也不自动暂停或重跑旧队列。已有作业照其声明版本运行，新任务使用不冲突的工作目录与资源配置。

## 7. Benchmark 与数据集调研结论

**资料核查日期为2026-10-19。下表描述已读取的一手资料，不表示本轮已全量下载、复现或确认所有样本质量。训练来源、外部评价、开发回归是三种用途。**

### 7.1 FollowIR-train：首选的检索要求辅助训练

作者发布过滤后的训练数据与未过滤版本；数据卡页面显示1,776行，概述称约1,800个query/instruction样例。字段包括 `query`、`instruction`、`document`、`label` 和教师 `score`，文档为合成后筛选数据，数据卡标注Apache-2.0。[D1–D2]

**适配任务：**`query + instruction + candidate → 是否满足这次检索要求`。将instruction放入Host的purpose/required_points条件，与动作READ候选关联。这只能提供候选适用性，不提供SEARCH路径、刷新价值或正确返回时机。

处理时按原TREC主题ID分组，同一主题的相关/不相关文档不得拆进不同集合。教师score不是真实正确率，不直接当Jev置信度校准目标。不假设每个主题都同时有正负例；先统计，再仅在train中补充有来源依据的困难负例。

官方FollowIR评价包含Robust04、Core17、News21指令检索任务，可沿作者/MTEB实现报告原生指标。完整底层语料的取得与使用条件尚未逐项核实，**不让这件事阻塞首轮开发**；先用已可取得的训练数据与InstructIR完成指令机制验证。[D2]

### 7.2 InstructIR：判断参数改变是否真正改变检索目标

作者基准将同一个查询配以不同用户要求，目标材料随之改变；公开HF包含corpus、queries和相关性数据，数据卡标注MIT。它主要是评测资源，不是已明确划好的MiLAi动作训练集。[D3]

**适配：**在相同候选库上改变Host要求，报告作者实现的检索指标与成对要求响应。不得只凭排名变化宣称正确遵循指令；必须检查变化后仍符合新的相关性标签。

固定候选池组件实验和实际全库检索分开。若为降低成本预取候选，所有方法共用同一检索机会，并单列召回上限；不能把裁剪池成绩称为官方全库结果。

它不测试记忆生效时间、存储历史或Host任务执行，不能替代后两层评价。

### 7.3 MemOps：动态记忆语义与来源监督的主领域材料

官方仓库提供背景、证据对话、操作轨迹及注入后的历史产物，区分Remember/Forget/Update/Reflect/TrajectoryOps，并有确认、暂定、撤回等语义。已有产物可直接用于适配，不需要先重新生成全部数据；仓库声明MIT，载体对话等第三方内容仍保留其来源条款。[D4]

**适配：**复用当前MiLAi已登记train背景和加载器，形成工具请求、时间/主体条件和实际检索观察。原操作标签用于离线定位来源及审阅，不直接进入Host请求或Jev输入。按原对话触发位置回放，不能仅按操作数组排序。

没有核实到适用于本研究的官方微调train/dev/test划分，使用项目现有背景分组并声明自定义派生划分。当前已暴露的外部8背景和532条dev偏好继续作为开发分析，不能转为新训练或盲测。[R2]

历史对话中的“忘记某事”可用于理解历史语义，但不是当前Host实际授权删除的命令。本版检索主实验不因基准含Forget类别就执行新的持久删除。

### 7.4 MuSiQue-Full与2Wiki：辅助互补读取，不承担完整动态任务

MuSiQue官方发布Ans/Full的train/dev/test、评分脚本和单跳种子泄漏排除ID，数据声明CC BY 4.0。[D5] 采用Full TRAIN构造已读/缺失前提状态，保留不可回答情形；训练家族及所有改写先分组再展开。

2Wiki提供上下文、句级支持和关系三元组，并发布带实体别名处理的v1.1评价入口；测试答案及支持未公开。作者README中未明确数据独立许可，本轮不替其补写许可证，发布派生数据前核对下载包与作者条款。[D6]

2Wiki作为补充而非让并行比较压倒串行依赖。分开统计问题类型、关系长度和最短证据段数。关系gold仅用于训练标注或离线评价；不能把正确实体ID和证明链交给正常检索器。

### 7.5 LongMemEval-V2：最匹配“记忆作为工具后端”的外部主评价

官方数据卡说明有451个人工问题、1,870条任务轨迹，含文本观察与截图；分small/medium haystack配置。数据卡标注Apache-2.0，HF自动viewer中的“train/29行图片”不是451问题的官方训练划分。[D7–D8]

**官方接口已经匹配本项目：**`insert(trajectory)`摄入轨迹，`query(query, query_image=None)`返回text/image上下文，固定Reader随后回答。query阶段没有题型、gold答案或完整原题记录等benchmark元数据。[D7]

MiLAi适配应只接收官方允许的query/图像，从这些可见信息生成工具请求。请求构造的Host/模型调用若发生在backend内部，其成本计入该方法的query latency。不能把离线题型变成read_goal提示。

分两种运行方式：

1. **原生边界评价：**保持官方Reader、输入机会与返回上限；比较MiLAi与作者简单RAG基线。主结果按官方准确率、延迟与分项报告。
2. **Host请求实验：**在相同可见输入上加入参数化请求构造，并完整计成本。这是backend方法变化，不声称官方原本就提供这些参数。

首轮可只验证无问题图片的文本子集，但要按元数据预先选择并明确为派生子集。正式全量运行保留图像访问：Laya选现有图像/片段，Host的视觉能力或共用视觉模块解释图像；不能静默删图后称完整原生结果。多模态模块没有可用实现时如实分项，不为文本主线先建视觉平台。

本版不使用这些评价问题微调或按失败答案改Prompt。small/medium的同一题或共享轨迹不是独立新测试。

### 7.6 Mem2ActBench_small：评价Host是否真的用上记忆

ACL 2026论文研究记忆驱动的工具参数填充。官方仓库实际存在`Mem2ACTBench_small`成品，而不只是生成脚本。其统计文件是**400 QA、429会话**；论文提到的2,029会话是更大构建范围，不应写成small运行输入。[D9–D11]

首轮直接使用发布产物，避免为复现400题重新运行整套收费生成流水线。仓库README声明MIT，但ToolACE、BFCL、OASST1等上游材料并不因代码许可自动统一授权。

**必须保留两个不同实验条件：**已读取的arXiv v1主结果提供目标工具，用于隔离记忆参数填充；另有包含干扰工具的选择鲁棒性实验。正式ACL页面已核实，正式PDF与arXiv逐节差异本轮未全文复核。[D11]

- **M2A-GivenTool：**所有Host获得同样的目标工具文档，只比较根据记忆补参数。
- **M2A-SelectTool：**所有Host获得同一工具候选池，评工具选择与参数；不把这个扩展冒充原主结果。

首版固定GivenTool为外部主任务，SelectTool是扩展。原文TA/TSA/EM在不同段落有不同使用范围，不能自行把“格式/工具命中”当完整参数正确；保留作者指标，额外定义且清楚命名本项目的`strict_call_match`和`argument_value_accuracy`。未核实到可直接运行的完整官方评分器时，移植已说明的规则并标注为MiLAi适配，不宣称官方排行榜成绩。

原题中的工具schema可作为Host的任务输入，但gold参数、来源指针和答案不能进入请求。预测出的函数调用不等于真实外部业务执行；本实验不调用真实订票、支付或邮件服务。

### 7.7 可选资源，不纳入首轮必跑矩阵

| 资源 | 可用作用 | 本版取舍 |
|---|---|---|
| SGD / SGD-X | 官方train/dev/test；意图、槽位、服务调用与5种schema改写；CC BY-SA 4.0 | Host确实误解参数或schema措辞时再加辅助任务；不把槽位状态当长期记忆真相。[D12] |
| BIRCO | 多方面检索目标，公开dev/test | 作为目标复杂性扩展；不把临床匹配、文学取证等不同任务混成记忆总分。[D13] |
| LongMemEval原版、已有MEME/HaluMem切片 | 已有工程和历史回归 | 已暴露范围沿旧记录使用；不因换schema重新宣称未见 |
| 通用函数调用/typed-decisions | 调用结构与训练管线诊断 | 不代替语义检索或Host任务完成；Mem2Act上游相关数据避免跨集合混训 |

## 8. 训练数据处理：从源数据到实际工具轨迹

### 8.1 一个主要训练样本

```text
Host当时可见的任务与上下文
    → Host实际工具请求（保留不完整和错误表达）
    → MiLAi真实可见状态
    → 实际可执行动作及参数
    → 来源条件下可接受的下一步/动作偏好
    → 实际结果与最终交付（用于后果评价，不偷放回当前输入）
```

数据仍使用现有`state/questions/gold/metadata`形式。`metadata`保存源数据、原主题/背景、事件、请求变体、分组和审阅依据；`state`只保存当时工具可以知道的内容。

```json
{
  "state": {
    "request": {"query": "查询示例", "read_goal": {"purpose": "补齐生效时间"}},
    "observations": {"delivered_refs": [], "pending_candidates": []},
    "budget": {"remaining_steps": 5}
  },
  "questions": {
    "next": {
      "type": "choice",
      "instructions": "依据本次请求选择下一项实际操作。",
      "criteria": {
        "search_history": "检索已知对象的历史来源",
        "return": "返回目前已经取得的材料"
      }
    }
  },
  "gold": {"next": {"probabilities": {"search_history": 1.0, "return": 0.0}}},
  "metadata": {"split": "train", "source_group": "illustration_only"}
}
```

该样例仅说明格式，不是可直接训练的数据：真实版本必须包含能支持标签的可见输入和实际动作候选。

### 8.2 处理顺序

**A. 先划分来源组。** FollowIR按主题，MemOps按背景/操作链，多跳按原组合问题及共享种子，真实轨迹按源历史。先继承项目的train/dev/保留归属，再做新增；同一原案例的中英文、参数变体、预算档位、前缀和改写必须同组。

**B. 生成Host请求。** Host只读取用户任务、许可的近期上下文和工具目录。gold证据用于之后的标注，不用于生成必答要点。可以用人工设计的请求作诊断，但主结果必须有实际Host生成的请求。

**C. 原文进入原Store。** 保留角色、会话和接收顺序；真实事件时间未知就保留未知。由实际系统产生视图，不用人工正确视图覆盖主训练的before。

**D. 运行候选策略。** 使用规则、既有Laya或生成式策略形成轨迹；演示动作只是候选示范，不自动成为gold。用少量多策略采样增加错误视图、补搜和提前返回状态，不穷举所有动作序列。

**E. 标注请求条件下的行为。** 检查取得的证据是否满足本次目的，尤其是打开视图之后的继续/返回。允许多种有效动作；歧义留mask，不把“不在偏好里”一律定义为非法。

**F. 训练与实际使用。** 从同一函数导出训练/推理payload，回到正常工具调用测试，而不只在导出的前缀上评价。

### 8.3 六种必须覆盖的条件配对

| 配对 | 语义预期 | 不能使用的捷径 |
|---|---|---|
| 同query，不同取证目的 | 当前解释/原文/实际存储历史分别取证 | 将目的名直接映射成永远固定的唯一流程 |
| 同来源，不同适用时间 | 生效前后返回不同有效事实 | 以最后入库的值替代时态推理 |
| 同任务，Host已取得一部分证据 | 补缺口而非重复全部工作 | 输入金标准的“缺第3段” |
| 同视图，相关/无关新事件 | 相关时补证或刷新，无关时允许复用 | 只看新事件数量 |
| 同请求，指令中的排除/范围改变 | 同主题材料的适用性发生变化 | 只匹配query词面 |
| 同目标，不同预算 | 合理取舍、明确未覆盖部分 | 强制高预算一定多读，或低预算一律拒答 |

指令互换训练本身已有近邻：Dual-View Training通过改变要求使同一对文档交换相关性标签。[T2] 本项目潜在增量应落在**Host请求＋执行反馈条件下的操作参数与计算分配**，而不是宣称首次提出指令对照。

### 8.4 初始规模与扩展方式

以下是资源规划目标，不是已完成数量：

| 阶段 | 数据目标 | 用途 |
|---|---|---|
| 功能切片 | 6历史×2请求 | 工具接口与正常Host闭环，不做泛化结论 |
| T0操作试片 | 先用64个合法train来源组、16个dev组；每组2–4种请求，实际状态自然产生 | 检查请求条件与执行学习是否有效 |
| T1主训练 | 以128–256个实际独立train组为扩展目标，另32个dev组；与FollowIR训练主题按任务混合 | 增加关系/措辞/变化覆盖，仍按组报告 |
| 自身轨迹补充 | 从train组中抽32组当前策略轨迹 | 暴露旧视图误用、补搜失败、返回过早等状态 |
| 自建确认 | 另行登记32–48个来源组，数量按实际可用报告 | 方法固定后的新请求/变化泛化，不替代外部benchmark |

可以复用既有合法train组，不称它们为“新增独立背景”。MemOps实际背景数有限，不能把它展开成数千前缀后宣称数千背景；数量不足时用已声明的新领域历史或多跳组补充，分开报告来源。未达到目标规模不阻止首轮编码与小样本实验，也不把小样本包装成大规模确认。

初始训练采样可采用操作轨迹约60%、指令适用性约20%、多跳补证约20%的混合试配。最终以真实可用样本和任务表现调整；普通CE基线必须得到同样的数据，避免把多看数据的收益归给额外损失。

### 8.5 标签质量不再以“全部可尝试操作”为同等正例

SEARCH可执行不代表此刻值得执行；USE_VIEW可以检查不代表应该优先使用；REFRESH输入含完整来源不代表刷新后一定获益。区分三类标签：

1. **结构可执行性：**由既有工具确定，不当主要学习成绩。
2. **请求条件下的有依据偏好：**用于首轮CE；明确其是短程偏好而非最优策略。
3. **实际后果偏好：**来自训练组内的少量受控分支结果；用于后续效用学习。

已经充分时不把“所有继续读取”都标作灾难性错误；可能有核对价值或后续复用价值。没有足够证据衡量时，先报告冗余和未知，不伪造长期奖励。

## 9. 训练方法与模型使用

### 9.1 模型与起点

继续采用现有Laya Multilingual与当前已可加载的训练器。首轮显式指定checkpoint，不使用按语言自动切换模型的router。旧固定选材/操作权重可作为warm-start对照，但不得将其成绩记成新任务训练结果。

官方Laya已支持JSONL的expected或gold概率标签、soft-CE、编码器/决策头训练及模型保存；可复用接口，不需新训练平台。[T1] 不因上游出现新版本就连同本项目依赖一起升级。

### 9.2 三阶段训练，不直接跳到RL

**T0：请求条件操作CE。** 先只学习动态操作与绑定参数，采用当前原生头、家族/事件归一化权重。多可接受动作可以用现有soft目标；它是标注分布，不是真实概率。

**T1：加入指令与关系数据。** 使用FollowIR的要求符合性、多跳缺失前提和MemOps动态语义辅助。对照保持相同总更新预算，报告各任务实际抽样次数；若额外训练带来更多计算，明确按“完整配方”而不是纯方法增益解释。

**T2：自身轨迹数据聚合。** 运行当前策略在train历史上的实际工具请求和状态，补充后续操作标签，再与同样追加更新数但只使用旧样本的continued-CE对照。借鉴DAgger处理策略状态分布的思想，不宣称仅收集轨迹就实现了其理论保证。[T3]

Host首轮不训练权重，避免与Jev同时变化。Host提示通过开发数据选定；在跨Host确认时保持工具和Jev固定。

### 9.3 初始可运行配方

| 项目 | 起始设置/约束 |
|---|---|
| 编码器与头 | 全量领域微调作为主试片；冻结encoder只作资源/机制对照 |
| 损失 | 普通soft-CE；不默认RLCD或环境RL |
| 学习率 | encoder `2.5e-5`，head `1e-4`，作为沿用起点而非最佳保证 |
| 有效batch | 16；microbatch由实际可用显存选择，梯度累积补足 |
| 更新预算 | 先按有效训练数计算两遍数据的预算 `U=ceil(2*N/16)`； matched组使用相同U；同时记录tokens |
| 诊断 | 初始、中点、最终；主结果使用预定最终权重，不按保留集挑checkpoint |
| 种子 | 首切片0；声明主比较0/1/2，逐个报告 |
| 选项增强 | 同步置换操作与标签；等义schema措辞使用train变体 |
| 上下文 | 用实际tokenizer统计正文、已读证据和动作头；不假设把max_len调高即可保真 |
| 概率 | 先用argmax，未经独立校准不按阈值自信地结束取证 |
| 部署 | 进程内长期保留模型实例，设备可配置；冷启动与暖调用分开计量 |

上表预算不是要求所有样本必须重复到相同次序；实际采样、mask和丢弃计数可从现有训练日志得到。某些样本超长时，改为实际分步观察或明确的长输入实验，不能把关键约束裁掉后仍沿用原标签。

### 9.4 科研增量候选：请求—状态条件化，而非只是结构化输入

设请求为r，工具观察为o，可执行动作集为A，目标可写成：

\[
\pi_\theta(a_t\mid r,o_{0:t},b_t,A_t).
\]

在相同候选上，只改变请求要求r，应得到适用的新选择；在r不变但相关来源改变时，也应调整。目标等义变化应保持有效结果，不要求完全相同路径。

额外关系目标只作为独立因素：普通CE同样取得全部配对样本，关系损失才有资格谈增量。请求互换后多合法动作集合可能重叠，不能强制所有样本都换选。

后果训练可考虑“Host任务质量−实际增量计算”，但Host请求本身错误、工具未找全、Reader误用和视图生成错误分别保留。基础相关性收益与长期复用收益不能用同一个未经验证的打分器含糊混合。

## 10. 实验设计：先能回答问题，再扩大规模

### 10.1 三层证据，而不是一张动作准确率表

| 层次 | 评价对象 | 主要问题 |
|---|---|---|
| Host委托 | 从用户任务到工具请求 | 对象、时间、用途和已知证据是否表达正确？是否添加了不存在的前提？ |
| 工具执行 | 从同一请求到返回证据 | 是否找到/交付所需来源？是否按约束调整？是否无谓刷新？ |
| 最终任务 | Host收到证据后 | 回答或工具参数是否正确？完整计算是否值得？ |

不训练/修改最后的Reader来同时追分。先固定Host模型参数和最终任务提示，Prompt/接口变化按实验因素明确命名。

### 10.2 E0：正常功能首切片

6条历史×2种Host取证目标×2个执行器（规则、Laya）=24次外部工具调用。它证明接线与任务分化，不用于决定论文模型最优。

检查的不是“六条都调用了所有操作”，而是query-only可用、复杂请求没有换题、实际证据回到Host、引用可继续使用、模型在操作后看到新状态。语义错误直接保留并修一个最相关问题，不开始全仓清理。

### 10.3 E1：Host设计 × 执行策略的2×2主对照

| 编号 | Host请求表达 | 工具执行器 |
|---|---|---|
| H0-C0 | query-only工具接口与原使用提示 | 强简单执行策略 |
| H1-C0 | 本版参数化接口与Host提示 | 同一个强简单执行策略 |
| H0-C1 | query-only工具接口与原使用提示 | 请求条件Jev |
| H1-C1 | 本版参数化接口与Host提示 | 同一个请求条件Jev |

**共同条件：**同用户任务、Host可见上下文、记忆来源、原存储与视图能力、Host模型/解码、总预算、工具结果格式。H1无权看到gold事实、gold工具参数、题型标签或额外历史。两种Host都可以选择不调用工具，未调用造成的任务失败仍属于端到端结果。

C0不是故意削弱的top-1：先在开发任务中比较已存在的强固定上下文与规则策略，选择一个固定配置作主参照，同时保留另一个结果。Jev训练覆盖query-only与丰富请求，避免只在H1训练、再把H0失败算成接口优势。

开发先跑16个来源组、每组2种请求、4条件，共128个任务位置；独立来源数仍是16。最终在新保留组上固定配置重复，不把开发切片当确认。

**判读：**H1-C0的改善支持Host表达有价值；H1-C1对H1-C0的改善才支持Jev在新接口下的新增价值。两者的交互为描述性因素结果：

\[
I=(Y_{H1,C1}-Y_{H1,C0})-(Y_{H0,C1}-Y_{H0,C0}).
\]

这里H1同时改变提示和请求表达，属于Host接口配方效应，不声称纯JSON结构效应。用户目标正确与错误的请求都保留，不能只在Host已经生成理想请求的子集报主成绩。

### 10.4 E2：固定请求的工具内部对照

保存同一个Host实际请求、相同可用来源与实际before，让以下方法分别执行：强固定/规则、Jev、同操作库的生成式控制。各方法可以形成不同后续轨迹，不继续声称同before覆盖整条轨迹。

主评价为证据交付与固定Host的下游效果。**同一请求由哪个Host生成**属于已知条件，不在此阶段再次生成更好的请求给某一方法。

必要时增加一个来源审阅后的充分证据交付作诊断上限，判断“找全以后Host仍不会用”。它不是可部署方法，也不参与主排行榜。

### 10.5 E3：两个最值得做的机制消融

**A. 字段结构还是信息增加？** 同一个丰富请求分别采用结构字段与等信息自然语言展开；训练时各自使用对应形式。只给冻结模型删字段属于扰动诊断，不替代重新训练的消融。

**B. 动态反馈是否必要？** 相同初始化与训练数据比较一次路由/一次排序和完整操作反馈策略，保证最终返回预算与操作库一致。若简单单次策略同样有效，就保留更简单方式；不以路径丰富程度奖励动态模型。

普通线性头可作为第三个、小范围的模型对照。原生头有预训练、线性头随机初始化时，结论限定为完整模型配方差异。此前别的任务上的普通头结果不自动证明本版专用头优势。

### 10.6 E4：外部评价的明确协议

| 轨道 | 输入边界 | 主结果 | 执行规模 |
|---|---|---|---|
| InstructIR | 官方query、instruction、实际语料 | 原检索指标、按原query分组的要求响应 | 接口先用合成同格式数据；最终按选定完整配置运行 |
| LongMemEval-V2-Small | 官方query与可用query_image，无题型/gold元数据 | 准确率、五能力分项、query latency、上下文大小 | 小型固定方法首批检查后保持配置；完整451题是最终目标，文本子集单列 |
| Mem2Act-GivenTool | 当前任务、目标工具schema、历史检索工具 | 原参数指标＋strict_call_match | 发布small的400题作为最终目标；不用于新训练 |
| Mem2Act-SelectTool（扩展） | 同一工具池，而非先给正确工具 | 工具选择、参数、完整调用 | 不与GivenTool混报，不必首轮全量 |

外部完整矩阵不重复全部开发消融。先固定强简单参照和最终Jev配方，报告Jev三种子；生成式控制先在代表性、预先选定的开发面板上定位，外部是否全量按已声明预算决定。未执行的格子留空，不由其他实验推算。

LongMemEval-V2的原生后端评价与Host端2×2不是同一个实验：前者本来给定query并固定Reader；本版Host端完整调用能力主要由自建请求任务与Mem2Act检验。不要在原生后端成绩上追加未经运行的“自主Host”主张。

### 10.7 E5：动态资源调整与效率

中等预算先用返回2048 tokens、最多8次内部决策作为工程起点，简单任务可提前结束。之后只对两项已固定候选做少量返回预算工作点，例如512/2048/4096；不同时展开所有k、模型、Prompt和设备全因子。

对比实际交付量而非强制每法同样读4段；共享的是允许机会与上限。高预算不要求更多操作，低预算不能把明确任务改写成简单问题。

缓存工作负载至少有重复相同需求、等义改写、切换主题、相关变更、无关变更、迟到来源及生效时间越界。回放连续历史时，每臂拥有自己的缓存，不把另一臂产生的优质视图免费交付给Jev。

## 11. 指标、错误归因与统计

### 11.1 主指标与配套指标

**主指标：Host完整任务成功与证据忠实性，伴随完整成本报告。** 不先要求某个固定百分比增益再挑选样本；方法存在真实取舍时给质量—成本曲线。

| 项目 | 记录方式 |
|---|---|
| Host请求准确性 | 目标/主体/时间/用途是否忠于当时任务；无依据新增约束单列 |
| 候选发现 | 所需证据是否进入实际可读池；不能用最终选择错误解释召回缺失 |
| 证据交付 | 完整支持集合、必要关系覆盖、来源精确度；等价证明允许多解 |
| 条件响应 | 改变要求后双侧有效；等义改写后有效性保持，不只看动作ID一致 |
| 正确返回/继续 | 原文充分却重复工作、缺关键材料却返回、预算结束如实部分交付 |
| 复用/刷新 | 当前请求下的语义适用性、实际新增来源、视图生成错误与后续复用效果 |
| 下游任务 | QA、参数值、整体工具调用；官方指标与自定义严格指标分列 |
| 可用性 | 空返回、解析失败、未完成、返回额度、跨请求引用和重开读取 |

逐阶段计数可以很小，不需要为每个指标新建一个服务。直接复用原轨迹与当前来源，选有分歧和代表性错误作深入审阅。

### 11.2 错误归因表

| 观察 | 优先解释/修订对象 |
|---|---|
| Host把查历史写成查当前 | Host提示/请求表达，不直接惩罚正确执行该请求的Jev |
| 正确请求，但候选没有关键材料 | 搜索目标与检索范围 |
| 关键材料可见，却返回不相关/过期材料 | Jev的请求条件适用性与后续决策 |
| 视图有结构合法但含义错误 | 视图生成器；控制器可学习何时回到来源，但不能凭标签修复事实 |
| 工具返回完整证据，Host参数仍填错 | Host使用/推理，不把全部错误归到检索 |
| 原始事实保留，但检索答“没有” | 检索与交付，不误报成删除或遗忘成功 |
| 控制更快但任务不完整 | 取舍或失败，不作为净效率优势 |

可以给一个任务多个原因，不强迫归入一个唯一根因。没有受控分支证据时，使用“可能影响”而不是“已经证明造成”。

### 11.3 完整成本

\[
C_{total}=C_{Host\ request}+C_{index/ingest}+C_{search}+C_{Jev}
+C_{view}+C_{return}+C_{Host\ completion}.
\]

记录实际生成/embedding用量、原生前向次数和tokens、加载、CPU/设备、端到端时钟；嵌套的局部计时不再次相加。Host为了生成更多字段所增加的计算必须计入，原循环下省的操作不能掩盖新增请求构造成本。

冷启动与长期Host进程分别测。控制器可缓存稳定来源表示，但上下文化编码不会自动可复用；新的编码分工是独立方法变化。研究训练/标注成本另列，不每次查询重复摊全部研究费用；未计的人工标注时间不写成零。

### 11.4 样本与保留

按来源背景/主题/任务链聚类，随机种子、改写、预算、重复查询留在组内。InstructIR按原query；MemOps按背景；Mem2Act按实际共享目标来源/链检查相关性；若整个子集高度共享同一历史，不虚构400个独立用户或400个独立背景。

开发可反复迭代，但一旦外部面板被用于Prompt选择或错误补训，后续就作为回归。某次冻结评价的证据身份不因之后阅读结果而被抹掉；只是不能继续作为下一新方法的未见确认。

确认采用逐组结果和配对区间。区间跨零不等于等效；相关样本或组数太少时报告固定面板与不确定性，不用漂亮总题数掩盖。作者语义审阅与独立人工判定分别说明，参考答案有分歧时保留原生分数并单列来源审阅，不修改gold追分。

## 12. 使用性与工程取舍

本版优先减少三种重复：Host重复规划工具内部步骤、每消息重复加载Laya、各实验复制一套执行器。不是把原有必要错误处理删除。

**保留：**一处工具输入适配，既有身份/可见性/版本规则，实际执行反馈，真实失败与用量，训练和评价数据分离。

**不扩建：**额外审核Agent、第二账本/数据库、通用异常平台、强制内容指纹门禁、每次调用前后的语义审批、把所有旧测试全绿作为本次方法开发前置条件。

正常结果尽量直接返回；可选字段缺省时继续query-only路径；资源不足返回实际已有材料与结束原因。语义不确定不自动等于程序错误，程序错误也不伪装成“没有记忆”。

开发失败后先修当前触达路径，继续新版本的正常功能验证。原失败保持可见，不通过重复生成挑一份正确答案。运行恢复沿原机制，不为本版再造调度框架。

## 13. 里程碑、产物与采用判断

| 里程碑 | 必须产出的可用内容 | 科学判断 |
|---|---|---|
| M1工具闭环 | 一个入口、两个请求形式、真实Host调用、规则/Laya各有实际结果 | 证明可用，不证明动态策略优越 |
| M2条件响应 | 六类请求配对、原流程参数实际变化、未换题 | 若字段不影响有用行为，先修投影/监督而非加字段 |
| M3监督学习 | 数据版本、T0/T1权重、原生与实际工具指标 | 普通CE足够则保留，不为创新强加RL |
| M4因素实验 | Host×控制2×2、等信息文本与反馈对照 | 区分Prompt、数据、结构与策略增量 |
| M5外部证据 | 指令检索、记忆后端、Host参数使用三类结果 | 分数据、分任务报告，不混成一个总memory分数 |

采用原则不是“Jev必须赢”：Host提示若独立解释全部收益，就发布更好的工具接口和简单执行策略；Jev只有在复杂要求/状态变化中有增量，就将它用在这些请求，而不是每次简单lookup都强制调用。

如果库内必要证据齐全但Host不会用，下一项是Host使用Prompt和工具返回格式；如果缺失来自首次池，下一项是补搜；如果主开销来自重复编码，下一项是计算组织。不要一律转成“继续增加训练步数”。

### 开发者开工页

1. 从当前实际研究头创建本次工作分支，保留旧已冻结运行。找到Host工具注册点与`read_goal`，不要重写循环。
2. 接通`milai_retrieve(query)`和可选丰富请求；结果返回原Host，不让工具内部生成用户最终答案。
3. 规则与现有Laya共用同一请求投影，复用模型实例；先运行第一条历史的两个目的。
4. 完成六历史24次调用，定位一个最有影响的问题，形成可用配置与简短结果。
5. 导入FollowIR训练和合法MemOps/多跳train，形成实际操作数据，做普通CE和正常工具评价。
6. 完成Host×执行器对照后，再进入固定外部协议；不要先跑所有benchmark再决定训练目标。

**本版首要方法假设：Host提供目标和约束后，Jev能够根据新的执行观察调整检索参数，以较少的重复处理返回Host真正需要的证据。** 这个假设可以被简单策略、普通头或等信息自然语言请求推翻；应由实验决定保留哪一部分。
