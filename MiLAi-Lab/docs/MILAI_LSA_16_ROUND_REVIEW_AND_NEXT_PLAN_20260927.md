## 执行结论

16 轮实验已经证明系统能够维护、呈现和恢复 State，但还没有证明 State–Attention 比简单强基线稳定地更好。最大同源批次 G/L 各为 60/78 严格消息、LRU 为 59/78；LRU 完整轨迹略多，但总成本最高。后续短历史中完整历史与 LR 都为 10/12，LR 约贵 3.04 倍；滑窗摘要 9/12，完整历史 10/12，摘要总生成成本反而增加 6.50%。这些结论限定于相应运行，不是全局否定局部 State。[S01–S06]

后续优先级不是补齐所有未完成模块，而是解决四个科学断点：

1. **转移语义**：已应用当前增量的 State 又与同一用户指令进入 Host，可能导致二次解释、二次应用。
2. **保持语义**：局部 State 的 content 仍整段替换，未提及的独立事实没有天然保持机制。
3. **选择价值**：U/A 的分离被实现为多次模型调用，而当前小 bank 几乎不需要昂贵选择。
4. **实验归因**：同一个 arm 标签下，在线 State 分组和正文在选择前已经分叉；多数后续轮次仍是旧场景单次接线。

建议按“诊断 → 两项结构修复 → 固定 bank 注意力检验 → 同源小重复 → 真实规模边界 → 新任务与第二模型”的顺序推进。保留 `U != A` 的设计空间，但不预设它必须在每一步以两个独立 LLM 调用实现。

## 2. 问题分层：已观察事实、尚未确认原因和对应修复

| 层级 | 已观察事实 | 可以作出的判断 | 尚未确认 | 下一步 |
|---|---|---|---|---|

## 3. 当前代码的五个直接问题

### 3.1 逻辑分离被实现成调用串行化

`controller.py::_prepare_independent_read()` 的 LRU 在非空 bank、存在 pending 时依次运行 `update_selector`、`maintenance`、`read_selector`。小 bank 也会付出这些固定开销。目录字段主要是 `id/title/needs/revision`，缺少部分当前事实与条件；标题不好的 State 可能在正文检查前就被漏选。[S07]

P3 的 LRU：U 44,763 tokens、A 50,918 tokens，合计 95,681；正文候选为完整 bank 的69.1%，后续 LR wiring 仍为93%。相较 L，LRU 总生成成本约高33.6%。这不能被说成“Attention 已节省成本”。[S02][S04]

**修改方向**：U/A 在语义目标上保持独立；调用上允许合批、跳过重复 A、简单全读、按已有目录缓存或按 query/state 版本更新。何时拆成三段由测量决定。

### 3.2 当前局部 State 仍是整段摘要替换

`bank.py::apply()` 对每条合法 edit 直接将 `content` 替换为模型新字符串。未编辑的 State 保持，但同一 State 内没有被重新写出的事实会丢失。省略 needs/title 有保持语义，content 没有。[S08]

**修改方向**：首版只对反复出现的独立事实采用少量可定位条目或段落；模型修改命中的条目，程序复制未涉及条目。不是建立完整 Claim Graph，也不是固定业务 schema。该机制保证的是“未触碰文本不因整段生成而消失”，不是自动保证模型找对受影响条目。

### 3.3 State 的时点没有成为稳定的消费边界

`integration.py` 先记录当前用户/工具事件，再 `prepare()` 维护，随后把维护后 State 与当前原始消息一起交付 Host。[S09] 在已观察反例中，State 已含新增量，但 Host 又对这个新值应用相同原指令。[S03]

**修改方向**：先试“公开回合开始时的稳定 State＋当前完整 ReAct 原始前缀”，回合结束才合并新事件进入下一版本。当前用户消息不删除，工具回执不删；只避免在同一回合中把已消费该指令的新摘要不断回灌。另一个候选是明确 post-event 快照，但不能再只靠一条‘这是新状态’提示；两者须小对照选择。

### 3.4 记忆工具反馈与业务事实混在同一事件通道

hook 将 HumanMessage 和 ToolMessage 作为事件。memory create/update/search 的返回也是 tool 事件。工具回执是实际发生的结果，但由模型写入的普通 memory 内容不是对外部事实的新独立确认。State 与普通 LangMem memory 可能同时承载同一事项，并相互维持错误值。[S03][S09]

**修改方向**：保留所有真实回执，但区分外部观察、业务执行结果、内部记忆操作结果。内部 memory receipt 记录“写了什么”，不默认作为新的事实增量应用。是否允许业务 Host 另写相同工作状态，应做共享合同实验；不能只让 treatment 获得更强写入管理后称为纯 Attention 收益。

### 3.5 两个额外静态风险：须验证，不当作已观察根因

`bank.apply()` 可以部分提交合法 edit，但只要有一条 invalid，整批 event 仍 pending。后续重新让模型处理整批时，已成功部分可能重复解释；原报告没有证明这正是已发生二次增量的来源。应补一个不调用模型的重试测试，再决定是否增加极小的 `(event, target, operation)` 提交身份。[S08]

`evidence_refs` 单调并集，`dependency_source_ids` 还可能累积多个旧 State 的机械暴露来源。这适合保守删除风险追踪，不适合直接充当精确语义影响边。不要把删除/暴露依赖用作 U 的真值标签或语义支持证明。[S08]

## 4. State–Attention 的目标重述：不换名字，换验证单位

保留多个可维护的局部 State、更新集合 U 与使用集合 A 的解耦。当前研究目标应是：

> 在相同合法历史和合理计算预算下，能否让新的任务相关观察只改变需要改变的局部理解，并让当前问题获得足够证据，同时保留未受影响的认识？

不再把“多个 State”“三次控制调用”“合法引用”作为成功本身。

可以区分三个假设：

- **H-S：状态保持**。局部条目更新相较整段重写减少范围外事实损失，并能正确表达当前/历史/未执行/部分执行。
- **H-A：注意力价值**。在相同正确 State bank 和候选信息下，状态条件化选择优于普通检索或等预算全读。
- **H-U：选择性维护价值**。真实变化局部、重复使用频繁时，选择 U 并维护的总成本低于全量维护或按需重建，且不漏掉新事项和共享约束。

三个假设分别检验；H-S 失败不能直接说明 H-A 不成立，H-A 的 oracle-bank 通过也不能证明端到端 formation 已成功。

拟议技术贡献仅是研究候选：**具有明确事件时点的局部状态转移，以及根据任务需求选择更新与读取的状态关系。**本文不作新的 novelty search，不宣称这些组件首次出现。只有组件消融、同信息强基线和模板留出仍有增益，才可提升为论文方法主张。

## 5. 优先开发一：回合快照与事件归并边界

### 5.1 推荐先验证的执行顺序

```text
公开用户回合开始
  1. 取得此前完成回合的 State snapshot S_before
  2. 用户新消息进入原始 ReAct prefix
  3. A 选择当前所需 State / 来源；不足时允许原检索工具
  4. Host 执行正常业务工具；所有实际回执进入 prefix
  5. 在本回合内不把同一用户增量已合并后的摘要反复回灌
回合结束或进入真实暂停边界
  6. 维护器读取本回合新增外部观察及真实业务结果
  7. 对选中 State 产生局部变更，提交 S_after
下一公开回合
  8. 从 S_after 恢复
```

这是拟议时间边界，不是已验证修复。它不删除用户指令，不自动改工具参数，不把未完成动作标成已完成。长回合需要中途 checkpoint 时，可以在明确边界提交并标明覆盖前缀；不要首版支持任意时刻同时双写。

### 5.2 暂停或部分失败

若标签失败但预留已产生，维护真实预留与未完成标签，不回滚副作用，不概括为“什么都没有发生”。若结果未知，沿现有 journal 查询/恢复，不盲重放。维护器失败时当前业务结果继续成立，原始事件仍在合法历史中，下一回合可以使用原始尾部恢复。

### 5.3 单写入者不是全面关闭记忆能力

对同一事项的工作 State 建议一个语义写入入口。Host 的普通 memory 仍可作为独立用户长期记录接口，但不得把“某次 memory update 返回成功”当作同一数量又变化一次。开发时先单独比较单工作状态写入路径和原双路径，所有比较臂保持相同接口条件。

不修改已经执行的 native benchmark 工具或历史结果。若为了产品可用性引入统一写入口，明确它是 shared substrate 变化，并新建对照配置。

## 6. 优先开发二：小粒度、非破坏性的 State 修改

### 6.1 最小数据形式

无需重建存储服务。可在现有 State value 中加入少量条目：

```text
State
  id / owner / revision         # 程序拥有
  title                         # 事项标签，不承担事实真值
  entries[]:
    entry_id                    # 程序分配
    content                     # 小段自然语言，保留实际值/条件
    source_refs[]               # 已有可访问证据；不自动证明语义支持
  needs[]
```

首版不要求每个词成为命题，也不建立通用本体。条目按可以独立修改的条件/安排/执行事实组织；具体粒度用反例检验。

### 6.2 修改协议

只需 `upsert` 和显式 `remove` 两种局部操作；新建 State 仍是正常创建。未出现的 entry 保持，未被选中的 State 保持。标题/needs 的改变不隐含删除事实。

```text
新观察只改变 B 的交付条件
→ 更新 B 中相关 entry
→ A 的正文不重写
→ B 中未涉及的批准条件保持
```

“不要执行简报相关动作”不是“删除简报安排”；模型需要作语义判断，程序通过默认保持避免把未重复输出等同撤回。若模型显式错误地删了条目，仍按语义错误统计，而不是程序声称验证正确。

### 6.3 来源与生命周期

真实来源保留在共享合法历史；引用缺失时不能伪造 support。新型归档/物理删除不是本轮研究前提，继续遵守已有访问屏蔽和授权边界，未完成的物理清除仍标未完成。

### 6.4 不把局部补丁扩大成防御协议

不要求 Host 每轮输出 semantic ack、supports_value、completion proof。控制器只生成小修改；执行器检验结构、目标身份和权限。可选坏 edit 局部跳过，其余独立 edit 可提交；涉及相互依赖的多条修改可以采用小原子组，但不是每次调用都建立跨 State 分布式事务。

## 7. 优先开发三：Attention 先证明信息价值，再优化调用

### 7.1 固定 bank 上测试 A

先固定一个只包含当前时点已发生事实的 bank，冻结目录、候选材料及内容预算。比较：

1. 小 bank 全读（放不下时报告不可用，不暗中给它更小预算）；
2. 普通 query retrieval / reranking；
3. State-conditioned A；
4. 同预算错误/交换 State 的负对照；
5. 离线 oracle selection 上界，不能计入方法成绩。

若 oracle A 也不能改善 Host，重点是消费层/任务不需要选择，不应继续训练 selector。若 oracle 有用而在线 A 差，才投入状态描述和选择学习。

### 7.2 增强目录的信息含量，而非追加长 prompt

当前只用 title/needs/revision。可比较加入已有正文的短 extractive preview、已声明主体和未决条件；不为每次读取重新调用 LLM 写新摘要。测目录开销、候选召回和任务结果。

### 7.3 低成本执行策略

- 小 bank 可直接全读，只保持更新局部性；
- query、State 版本和新观察均未改变时复用 A；
- U/A 可以共用一次候选检索和一次模型请求，但两个输出目标独立；
- 大 bank 使用真实索引先取候选，再读取正文；不要把全 Store 扫描后删正文叫 I/O 节省；
- 新事项没有既有 State ID，必须保留 new/unassigned 路径；不要恢复“U 为空禁止创建”。

参数选择依据开发成本曲线，不把 top-k、State 数或调用次数写成论文真理。索引工程只有当扫描实际成为瓶颈才实施，避免先造大平台。

### 7.4 成本条件

只有当下式在实际轨迹上成立，才可以称注意力省成本：

```text
新增路由与维护成本
<
减少的 Host 输入、全量重写、重复取证与错误恢复成本
```

P3 中 U/A 共95,681 tokens。把它从总账单算术扣掉也不能当无 selector 的反事实运行；不同策略会改变后续轨迹。[S02]

## 8. Host 正确性：单独诊断，不让它吞掉 State 研究

### 8.1 两条独立分数线

主 strict 保持原 rubric。辅助列至少拆成：

- 事实值与条件是否正确；
- 原始对象/ID 是否正确；
- 真实业务动作与副作用是否正确；
- 回答有没有超出回执的断言；
- State 的当前理解是否正确。

例如 full_history 的 physical-dispatch 否定断言是一项回答可信度失败，不是同ID恢复失败；错误 item_key 也不能因成功恢复而补分。[S06]

### 8.2 固定前缀能力诊断

选取少量来源已完整送达的真实失败前缀，观察：

- 原视图；
- 只改变 State 时点/归并边界的视图；
- 只给已发生的完整原始历史；
- 离线正确 State 的诊断上界。

先只生成 action proposal，不执行真实业务；指标与在线 task success 分开。随后只把有信号的候选放进 sandbox 完整任务验证。

### 8.3 对象标识不是新 Attention 机制

不再重复“请精确复制”的提示。若确有通用 ID 解析需求，可在独立共同接口实验中使用环境提供的 opaque ID、现有对象选择或只读 lookup；所有臂共享。不得偷偷将错误名称自动映射到正确对象、改 native schema 或改 strict scorer，再声称 LSA 改善。

### 8.4 第二模型提前作小诊断

当前只有一个实验 Host。若正确信息也反复被误用，应在获得授权端点后提前做少量冻结前缀跨模型诊断，区分维护器、selector 和 Host 的瓶颈。不必先跑完整第二模型大矩阵，也不能把开发代理回答当该模型的正式实验。

### 故障处理原则

可选 State 解析/路由超时 → 保留事件、标记辅助能力退化、用当前原始观察和普通工具继续。不能悄悄把错误记为维护成功。

越权、非法业务参数、未知真实副作用 → 保留现有硬边界；减少防御性编程不等于允许跨用户读取或盲目重放。

离线诊断、序列化回归、论文审计尽量放在 runner/evaluator；不要把每条科学主张都变成 Host 必须通过的 runtime guard。

## 10. 分阶段开发与实验：按最小可区分问题推进

以下编号是新规划阶段，不改写总体报告的16轮编号。所有真实执行均在明确恢复后进行。

### D0：建立可复用的失败前缀集

- 从已暴露数据选择三类首断点：无关事实遗失、post-event State 二次应用、正确证据下对象ID误写。
- 加无变化、不同事件同文本、当前用户真实改值、部分成功四类对照。
- 每类保留完整合法输入、旧State、真实新事件、预期不变量、原输出与错误位置。
- 先做静态/离线检查，不调用实验模型，不将私有trace作为候选专享输入。
- 交付一页故障矩阵和少量固定前缀，不再新建庞大协议家族。

### D1：状态转移和保持修复

- E1：整段重写 vs 局部条目更新，同一维护模型、相同证据、相近输出预算。
- E2：现有pre-model更新视图 vs 回合开始快照＋当前原始prefix，对比二次应用及真实动作。
- 每项从约6–12个独立转移/前缀起步，每条件2–3次输出；有噪声再补重复，数字不是硬cap。
- 先分离两项修复，再测试组合，避免一次改schema、历史、时间边界和Host权限。
- 判定：未触及条目文本保持可确定性检验；真正语义适应、保留与行动仍由冻结rubric评估。

### D2：固定 bank 注意力实验

- 冻结相同State分组/正文，独立比较全读、普通检索、State-conditioned A。
- 换task但不换bank，换无关细节但不换正确选择；加State-swap和missing-state。
- 对U，固定前态和事件，比较all、U、U=A、oracle U；所有组保留创建机会。
- 约12–24个任务/变化对足以起步诊断，按事项耦合和需要证据数分层。
- 判定：如果State-conditioned选择并不优于同预算普通检索，保持LSA但简化selector，而不是增加协议。

### D3：恢复一个小型在线matched比较

- 使用统一最新共享底座，不把旧P3与新源码混合。
- 先比较full_history、全局G、局部L、最小有效LSA；需要时再单独恢复LR/U=A/R。
- 起步4–6条独立开发情景，每臂2–3次完整轨迹，使用相同初始信息、合法来源与业务工具。
- 同时报告strict消息、整轨迹、动作身份/事实子指标、调用及fallback。
- 不要求所有原有失败消失；要求新增State成本有可识别用途，且主要错误不再集中在同一个已知接口问题。

### D4：少数真实规模点，估计何时值得维护

- 独立改变N（总事项）、d（每次影响事项）、a（当前读取事项）、r（复用次数）和H（真实历史token）。
- 起步选4–6个代表点而非全笛卡尔积，例如小N全读、较大N稀疏d/a、较大N高耦合、反复恢复。
- 可用N约4/16/48、a约1/3、稀疏/密集d作初始设计；实际数值受运行成本调整。
- 历史增长来自真实多事项互动、变更及回执，不只附加无关办公室日志；full_history用模型实际可容纳的完整历史。
- 超窗时公开full的处理策略，不故意缩小baseline窗口；同时保留标准检索/summary baseline。
- 若小N选择无价值而较大N有价值，可以采用混合策略并报告边界，不追求所有场景都赢。

### D5：模板留出、原生任务与第二模型

- 按任务模板、工具模式、约束组合或场景族留出；不只是换名称/数值。
- MERIT seeds0–4已暴露，使用新的前瞻冻结selection；不改官方任务和scorer。
- MemoryArena资源已准备但隔离适配/评分未完成，先完成真实adapter边界再称为benchmark结果。[S01]
- 在核心方案冻结后运行两模型小matched包；若目前没有独立端点，明确未完成，不冒充通过。
- 不在结果出现后替换题目，不将诊断oracle混入原生方法分数。

### D6：必要时学习选择器，而不是继续手写越来越多规则

只有“oracle/人工诊断State或选择有价值、在线selector仍不稳定”时，才构造训练数据。

- 标签来自训练情景的实际新事件、受影响事实、允许来源和后续任务损失。
- 训练目标包括该变时变、无关变化保持、后台更新与前台读取分离。
- 同一轻量模型可输出两种选择，不要求每个State一个模型或一套网络。
- 可先用排序/偏好样本或轻量适配，再决定是否需要RL。
- 所有离线训练费用与在线推理费用分开；测试未来状态和rubric绝不能进入运行输入。

## 11. 最关键实验的成功、失败含义

| 实验 | 主假设 | 正面证据 | 若失败应该怎么改 |
|---|---|---|---|
| 局部entry编辑 vs full rewrite | 局部保持可以减少无关事实损失 | 相关事实正确变化、无关事实保持且成本可接受 | 分离定位错误和内容生成错误；必要时先用oracle定位诊断 |
| 回合快照 vs即时post-event回灌 | 二次增量来自消费时点混淆 | 同ID不重放、不同ID相同增量各生效、Host动作正确 | 检查普通memory双写/旧助手污染；不回头无限改维护prompt |
| 固定bank A | State提供信息选择增量 | 相同budget下胜普通检索，State-swap导致可解释变化 | 改目录信息或删掉无益selector；不能称State理念被普遍否定 |
| 固定前态U与U=A | 维护对象和当前使用对象不同 | 后台事项正确更新、前台不被无关改动干扰 | 检查数据有无真实U≠A机会；路由oracle后再估计控制能力 |
| R vs maintained LSA | 重复使用能摊薄维护成本 | r增加时质量不劣、累计成本出现拐点 | 使用混合重建策略；不为维护而维护 |
| full_history vs LSA | 工作上下文选择有实际效用 | 真实H/N增长时总成本或质量改善 | 短场景回退full；大场景也无差异则收缩方法主张 |

不要求某个温度或退款例必须通过才允许其他研究。也不以一次全通过认定机制成立。诊断的作用是排除解释、确定下一实验，而不是追逐固定答案。

## 12. 公平比较与统计纪律

### 12.1 两条证据轨道

**条件能力轨道**：相同合法前缀、相同bank和分组，只改变一个选择或转移操作。能定位原因，不能替代端到端。

**在线轨道**：各arm从相同原始信息独立形成与使用State。分组分叉是方法行为的一部分，但不能再称为“只改变A”的单变量消融。

### 12.2 基线

- full_history：真实强参考，短历史不能删。
- window/summary：保留已实现版本，但不可用其一次失败代表所有summary。
- G/L：共享维护生成器、合法信息和基本调用机会。
- query retrieval＋reranking：证明State条件化选择不只是普通相似度筛选。
- R：只在需要确认维护收益时实现薄目录＋合法历史局部重建，不加另一套平台。
- 原B1/Mem0：外部系统参考，清楚披露工具、自动摄取及存储语义差异，不当组件消融。

### 12.3 预算

相同legal information不等于prompt必须字节相同。主比较用相同总输入可用范围/输出上限/费用口径；同时报告自然运行成本曲线，而不只人为等量调用。

来源展开也算方法输入成本；不能因为State需要原文验证就让它额外免费看到baseline不可读的历史。相同owner、相同时间边界、相同read_history能力。

### 12.4 重复与区间

- 单位优先是独立情景/轨迹，消息嵌套在轨迹中；P3不是78独立样本/臂。
- 每个情景做重复以测模型/工具路径噪声，运行顺序交错。
- 报告每模板分布、成对差值；少数模板时先给原始结果，不伪造精确置信度。
- 样本增加后用按情景族聚类的区间；不能把请求数当样本量显著性。
- 36条旧轨迹不是最终新代码验证；历史结果不追改，只用作故障选择和方差参考。

## 13. 指标、归因与质量—成本边界

### 13.1 主指标保持

- 原strict消息通过率；完整轨迹通过率。
- 当前事实/条件正确性；真实对象ID/参数正确性。
- 真实副作用、部分失败恢复、无依据断言。

### 13.2 机制指标

- update adequacy：该更新的语义是否正确变化。
- frame preservation：不应受影响的事实是否保持；不把未更改字节自动当作语义正确。
- selection coverage：当前需要的信息是否实际交付，而不只看State ID命中。
- false activation：无关来源/State造成的输入与额外调用。
- event replay safety：同一真实事件重放不重复，两个相同文本的独立事件都有效。
- recoverability：State错误/缺项时是否通过原始来源恢复。

若State划分由模型生成，不能仅用人工State ID匹配评价；应评估事实覆盖与实际行为。

### 13.3 成本

```text
C_total = C_host + C_maintain + C_update_select + C_read_select
        + C_embedding/rerank + C_retrieval/I-O + C_retry/fallback
```

分别列Provider tokens/calls、实际延迟、逻辑文本/物理数据库、Store API/真实I-O已测口径。不要将controller之外的成本设为0，也不把旧checkpoint仍保存说成物理压缩。

### 13.4 确定收益口径

一个可发表的结果可以是：在特定N/d/a/r/H区域，LSA在相同质量下更省，或在预算相同下减少范围外误改。无须主张在短历史上总胜full。

但若收益只有“新增控制调用强迫多想一次”，等计算基线应该解释它；若patch baseline已经解释全部收益，不应归因于State–Attention。

## 14. 减少僵化限制，但保留真正重要的边界

允许调整：控制输出长度、调用节奏、State数量、窗口大小、检索候选数、thinking或模型能力诊断。每次调整只改变可解释的一项并新冻结配置，不悄悄覆盖旧结果。不把“vLLM没改”当作方法优点，也不为试验随意改共享部署。

不把以下约束写死为理论：零额外调用、每消息13控制、每消息12Host、只能32个State、必须每例全过才准下阶段。它们可以是资源保护的当前默认值，不能替代质量—成本分析。

必须保留：owner权限、合法时间范围、不能偷读未来、不能由gold填参数、真实未知副作用不得盲重放、旧失败和费用不删除、可选状态退化不冒称成功。

**减少防御性编程的具体做法**：模型输出只检验执行所必需的类型/对象/权限；语义争议记录供离线评测。不要增加第三个语义审核器、supports-value证明、状态完成证书和每轮全图一致性扫描。

### 15.2 每个失败必须产生一个决策

记录：观察事实 → 首个断点 → 两个可区分解释 → 最小修复 → 新反例 → 成本 → 继续/收缩。

- oracle有用而online差：改善学习/表示，而非宣布State无用。
- 相同信息简单方法更优：删掉多余选择/控制调用，保留LSA能证明的部分。
- 多个合法且代表性的配置仍无增益：缩小或放弃该具体机制主张，不机械杀死所有State–Attention研究。

## 16. 最小论文与创新性证据包

候选主张：

> 局部State能够作为可维护的任务信息视图；将状态转移与当前消费的时点分清，并在任务变化下选择更新和读取对象，可以减少无关事实损失与重复消费，同时在稀疏使用区间降低总成本。

这不是已经证明的新机制。局部编辑、缓存、事件身份、摘要分块和工具ID解析本身属于常见工程手段，不能合起来就宣称新范式。

最低需要：

1. 完整历史、强全局/局部笔记、普通检索基线；
2. 同bank A、固定前態U、U=A、维护vsR的关键消融；
3. 状态/证据变化与无关变化的敏感性、保持性反例；
4. 在线形成而非人工给State的未见任务；
5. 至少一个独立模型族的可重复方向；
6. 总成本和失败分解，而不是只报合法引用、候选正文比例；
7. 局部性成立/不成立的边界。

若最终只有局部entry编辑有效：如实定位为状态维护/保持贡献。若State-conditioned A无独立价值，不把它保留为核心创新。若只有规模较大时成立，明确该适用范围即可。

---

## 17. 下一步三个最先运行的实验（恢复后）

### 实验一：维护时点与重复应用

固定已发生的正确前缀，对比“即时post-event State回灌”和“回合开始snapshot＋本回合原始事件”。包含同ID重放、不同ID相同增量、纯工具结果、部分成功。先检查proposal，再用少量真实sandbox动作验证。

**目的**：让状态和Host不再各自把同一指令解释成新的变化；如果仍失败，区分普通memory双写和Host自历史污染。

### 实验二：无关事实保持

固定旧State和只改变一个事项的新事件，对比整段替换与局部entry修改；额外包含“禁止当前行动但保留安排”、明确取消、历史查询。

**目的**：证明局部维护真正维护了未受影响内容，而不是只把一个长摘要换成几段短摘要。

### 实验三：固定bank的Attention收益

同一个bank和任务、相同总材料预算，比较全读、普通query retrieval、State-conditioned A，加入oracle和State-swap诊断。

**目的**：在不被上游formation和分组随机性混淆的情况下，判断Attention是否值得进一步投入。

这三个实验都比立即再跑六模板×三臂大批次便宜，也更能给出下一步具体决策。成功后再进入online、规模和公开任务，不用新的几十个字段或新的方法名称掩盖旧断点。
