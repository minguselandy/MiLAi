### R1：减少标签模仿，不等于解决额外行动

[L1 报告](MILAI_REPAIR_V10_R1_L1_RESULTS_20260929.md)包含六个已曝光前缀、两条件各两次。候选改善部分输出/提案，仍不能消除污染历史维持的循环；三个必要行动/历史使用控制保留。它没有工具执行、业务持久化或完整任务效果。

[L2 报告](MILAI_REPAIR_V10_R1_L2_RESULTS_20260929.md)从新初态完整执行四个已曝光 arc/条件。两条件都为 4/4 arc、20/20 episode、8/8 dependent，各 61 次 generation；legacy 41 个响应共出现 178 个标签，候选为 0。两组都没有截断或额外部署，故不能把原故障未复现解读为已经治愈。两组仍各有四次当前请求未明确要求的附带工单写入。

63 次业务调用及后续真实请求中的回执均已关联核对；全部完成 Store 快照为空，memory 写入提案为 0，任务可使用合法历史。因此答对不证明长期维护成功。候选总 tokens 183,281，对照 184,910，仅少约 0.88%；轨迹和工具行为不同，不能称记忆压缩收益。

本批支持显式去标签候选的窄输出效果，保留 legacy 默认，不升级为行动可靠性方案。L2 中间用户暂停约 3 小时 44 分，恢复时源码/服务/账本核对一致，但时间间隔和服务非确定性仍是混杂。已曝光、小规模、同一模型家族不能证明稳定 unseen 收益。

### R2：保护挡住业务变更，错误事实仍进入持久记忆

[R2 暂停详报](MILAI_REPAIR_V10_R2_PAUSE_RESULTS_20260929.md)保留完整因果链与两个竞争解释。首条消息把目标 key 从复数改成单数，精确授权拒绝，未产生 reservation。第二条消息读取记忆为空后，未取得真实业务对象，直接生成虚构 reservation ID；实际 MCP CREATE 成功，随后以该 ID 提出的 label 操作被拒绝，MCP 又成功更新同一记忆记录并保留虚构 ID。最终回答仍引用它。

真实 world 最终 reservation/业务 attempts 均为 0；真实 PostgreSQL 留有 1 条错误记忆，报告阶段独立进程只读核对仍存在。没有其他 owner 记录。7 个 Host 回执、两个被阻止的业务提案和三次 MCP 结果已逐一关联后续输入，未把自报保存视为成功。

这说明真实工具/MCP/Store 功能链存在，但它既不保证内容真实，也不等于业务完成。当前规则未验证自由文本记忆的事实支持。第二条脚本预设“已有 reservation”，与第一条实际失败矛盾，是必须披露的任务前提混杂；不能用本条估计一般幻觉发生率，也不能忽略虚构内容已保存这一事实。

仅 2/13 次进程、2/12 条消息运行完；0/4 个完整案例完成。其余为未运行，不计失败率分母。预定 partial 效果未触发，unknown、无副作用重试和后续同参请求都没有真实验证。R2 不接受语义验收；暂停后未修改输入、补跑或清理错误记录。

原生偏好工具的错误回执能给出已有 key；只读/零模型合成工具验证证明发现路径可达，不证明 Host 已会使用。Mem0 日期绝对化始于首次形成，来源缺乏绝对时间锚点，固定 OSS SDK 又拒绝非空 timestamp；没有悄改原 pin。四个金额确认失败 episode 与三个精确邮件文字失败仍保留原分，另列格式/原文复制问题；政策冲突不以取消政策换分。没有新增对象平台、时间适配效果表或语义裁判。
