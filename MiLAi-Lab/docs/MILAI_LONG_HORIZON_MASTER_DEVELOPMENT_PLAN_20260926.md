## 0. 总体目标

MiLAi 的目标不再绑定某一种固定的 Decision State / State-Attention 结构，而定义为：

> **在持续任务中，识别证据新旧，减少旧记忆与旧推理产物对当前行动的污染，在必要时选择性取得当前证据，并以尽可能低的额外状态、检索和推理成本完成可靠适应。**

最终问题：

> **当长期记忆、外部世界和任务历史持续变化时，Agent 如何保证“当前行动基于当前证据”，而不是盲目复用历史上下文？**

当前最有希望的路线：

```text
versioned factual evidence
→ request-time evidence projection
→ invalidate stale derived context
→ selectively resolve current evidence
→ ordinary ReAct action
```

暂称：

## Selective Evidence Rebase（SER）

名字和具体字段不是最终创新点；若后续证据支持更简单机制，应主动简化。

# 1. 当前证据链

## 1.1 B0/B1 已成立

v15 建立公开 LangGraph + LangMem baseline；v16 建立 model-hidden provenance/version instrumentation。

B1 已能准确记录：

```text
Observation
MemoryRevision
SearchDelivery
RequestMaterial
Business ActionReceipt
```

并通过 raw-wire parity 证明 instrumentation 本身不改变 B0 模型可见合同和普通工具行为。

后续继续以 B1 为 shared substrate，不回到旧 contextual runtime。

## 1.2 Maintained Decision State 已被充分挑战

v17：
- exact adoption 和 revision_changed 可达；
- controlled recheck 仍执行旧 4°C。

v18：
- proposition + support role + explicit completion 更严格；
- Host 反而不能稳定建立初始 Basis。

因此 maintained semantic state 不是当前主路线。

## 1.3 Structured ODR 没有自然激活

v19 ODR：
- decoder probe 能生成 non-null reconstruction；
- 真实 15 次响应全部 `reconstruction=null`；
- changed 仍执行旧值。

说明：

```text
decoder reachability != natural mechanism use
```

structured reconstruction 不再作为 active candidate。

## 1.4 Freshness Projection 顺序结果

| Arm | changed | retained | irrelevant | 通过 |
|---|---|---|---|---:|
| A1 Notice | FAIL | FAIL | PASS | 1/3 |
| A2 Quarantine | FAIL | FAIL | PASS | 1/3 |
| A3 Exact Refresh | FAIL | PASS | PASS | 2/3 |

A3 已确认：
- 旧 X@1 ToolMessage 正文正确隔离；
- X@2 current body 通过 exact Store.get 真实送达；
- changed 仍调用旧值。

结果报告显示，历史 assistant 自己生成的旧结论仍在 thread 中，并持续影响后续回答和 business call。

因此当前 first broken link 是：

> **stale derived conversational context，而不是 current memory delivery。**

# 2. 长期研发原则

后续不使用：

```text
失败 → 只留档 → 结束
```

也不使用：

```text
失败 → 当前样例加规则 → 重跑
```

统一循环：

```text
Failure
→ Evidence localization
→ First broken link
→ Competing hypotheses
→ Minimal general fix
→ Counterexample controls
→ Small rerun
→ Update hypothesis
```

只有以下情况真正 kill：
1. 核心因果假设被多个独立诊断反复证伪；
2. 修复需要比问题本身更重的持续状态/协议；
3. 更简单机制达到相同或更好结果；
4. 改进依赖 benchmark-specific hard rule；
5. unseen matched evaluation 无收益或被 baseline稳定支配；
6. 成本/复杂度导致真实 Agent 不可用。

负结果必须保留，但负结果首先是下一轮机制诊断输入。

# 3. 参数策略：默认固定，证据驱动可变

主开发默认保持：
- 同一 Qwen；
- 同一 vLLM；
- thinking=false；
- 同一 LangMem；
- 同一 business tools；
- 同一公开开发样本。

但不永久锁死。

以下情况允许改模型/decoder/context/output/retrieval 参数：
- 截断成为主要瓶颈；
- schema/decoder 明显限制表达；
- context pollution 无法在算法层合理处理；
- baseline 默认参数导致不公平；
- 方法冻结后做 sensitivity；
- 不同模型能力本身是研究边界。

每次参数变化必须：
- 记录原因；
- 冻结新 config；
- 保留旧失败和旧成本；
- 保留至少一个 matched reference；
- 不只报告最好参数。

# 4. 当前优先修复：Derived Assistant Invalidation

## 4.1 问题

```text
search X@1 → assistant 说 “4°C”
X 更新为 X@2=8°C
A3 后续 request:
  old X@1 memory body 已隔离
  X@2=8°C 已送达
  但历史 assistant “4°C” 仍完整存在
→ 模型继续输出/执行 4°C
```

因此 factual invalidation 不够，还需要 derived-context invalidation。

## 4.2 禁止内容 heuristic

不能：
- 搜字符串 `"4°C"`；
- 对比具体金额；
- 按 fixture case_id 删除回答；
- 根据 business expected value 过滤历史。

必须使用 provenance：

```text
assistant response A
← generated by provider request R
← R contained memory revision X@1
← X@1 is now superseded/deleted
```

得到：

```text
A generated under a stale evidence snapshot
```

这是请求级 risk，不声称每个词都由 X 因果产生。

## 4.3 Request-copy demotion

不改 checkpoint，不删历史。

发送 Provider 前将高风险 ordinary assistant content 替换为：

```text
[Historical assistant response withheld:
it was generated under an evidence snapshot containing superseded memory.
Re-evaluate from current user/tool evidence.]
```

保留：
- role；
- 时间位置；
- tool-call history（若有）。

首版只处理 ordinary assistant text，不删除已执行 tool-call JSON。

## 4.4 审计事件

记录：

```text
derived_output_rebase:
  response_id
  generating_request_id
  original_body_hash
  projected_body_hash
  stale_refs[]
  current_refs[]
  reason
```

不把该事件当语义因果证明。

# 5. A4：Selective Evidence Rebase

A4 = A3 Exact Refresh + derived assistant invalidation。

第一阶段先解决 correctness，不立即优化 exact read 次数。

成功要求：

### changed
- X@1 曾真实进入上下文；
- X@2 真实更新；
- X@2 current body 实际送达；
- 旧 X@1 factual body 被隔离；
- 基于 stale snapshot 的 assistant output 被 demote；
- approval 后 business action 使用 current value。

### retained
- X@2 真实取得；
- 旧派生 note/回答被 demote；
- action-critical value 保持正确；
- 不是只因旧值碰巧相同。

### irrelevant
- primary action 不受无关更新干扰；
- 不因 derived invalidation 错误删除关键 current reasoning。

---

# 6. A4 失败后的反思，而不是立即停

若 A4 changed 仍失败，依次检查：

1. 是否仍有 stale factual source 未 quarantine？
2. 是否有更晚的旧 user/tool source表达旧值？
3. 是否 assistant tool-call arguments 自身成为历史锚点？
4. current evidence 是否虽然存在但位置/格式弱于旧结论？
5. business call 是否主要复制最近 assistant conclusion？
6. 是否需要 current evidence 更靠近当前 action request？
7. 是否需要进入独立的 action grounding 机制？

每次只选择一个最小可区分实验。

# 7. Anti-overfit：Generalized Development Suite

不能只修 4→8。

建立参数化开发诊断族，至少覆盖：

- Numeric change：4→8、1774→6595；
- Categorical change：warehouse A→B；
- Boolean/permission：pending→approved、allowed→cancelled；
- Same action-critical value + metadata change；
- Irrelevant lower-ranked change；
- Deleted evidence；
- Multiple revisions X@1→@2→@3；
- Conflicting current evidence；
- Assistant-only stale conclusion；
- No-stale control；
- Multiple memories mixed current/stale/deleted/unknown。

建议目录：

```text
data/diagnostics/selective_adaptation_v1/
```

方法 runtime 不得读取 expected value / rubric / case type。

# 8. A5：Rank-Bounded Refresh

只有 A4 correctness 成立后才优化。

当前 A3 irrelevant 会重复 exact-read Y。

目标：
- changed/retained 刷新真正相关 stale object；
- irrelevant 尽量不刷新低价值 stale item。

候选策略不要写死为单个常数，做成可调策略：

```text
refresh_until_current_candidate
max_exact_refresh_per_search
rank/score margin
```

开发默认可以保守，但后续用 ablation 决定。

第一版原则：
- 从高排名 candidate 扫描；
- 如果更高排名 current exact result 已足够形成当前候选，低排名 stale item默认 quarantine 而不 refresh；
- DELETED 可跳过继续；
- UNKNOWN 不冒充 current。

# 9. 可能的下一修复：Current Evidence Capsule

如果 A4 后仍有“current evidence 虽已送达但被历史上下文压制”，下一候选不是加 semantic State。

可以在当前请求临近 user/action 位置加入机械 capsule：

```text
Current evidence snapshot:
- memory X@2: <exact current body>
```

特点：
- 只复制 current factual material；
- 不做语义总结；
- 不生成 decision；
- 不做第二 LLM；
- source/version 明确；
- request-local。

需要与 A3/A4 单独消融。

---

# 10. 可能的独立 Pivot：Evidence-Grounded Action

只有当：
- stale factual body 已隔离；
- current evidence 已送达；
- stale assistant output 已 demote；
- 模型仍反复调用旧 business parameter；

才进入。

研究问题变为：

> **action-critical tool parameters 是否需要显式 current evidence binding？**

候选形式：

```text
business call:
  arguments
  evidence_refs[]
```

程序只验证：
- ref 当前；
- ref delivered；
- ref exact。

不判断自然语言真值。

这是独立方法，不冒充 SER 修复。

# 14. Memory Formation：独立问题，不与 SER 混合

当前 baseline 仍有：

```text
first agreement not stored
```

SER 解决的是：

```text
existing memory / historical context becomes stale
```

不是：

```text
important future-relevant observation never entered durable memory
```

因此 Memory Formation 必须单独研究。

候选问题：

> 哪些尚未完成的未来事项应跨 session 保存？

建议从最小机制开始：

```text
counterfactual future-use test
```

例如：

> 如果这条 observation 在下一相关 session 不可用，Agent 是否可能丢失用户承诺、约束、未完成义务或可复用结果？

可比较：

```text
LangMem default
vs
minimal prospective-retention cue
vs
event-triggered retention
```

不默认纳入主论文；先独立验证。

---

# 15. Post-Action Reconciliation：第二条独立生命周期问题

当前 baseline 已多次出现：

```text
business action succeeded
but memory still says pending / do not process
```

这与 SER 有联系，但不是同一个问题。

候选机制：

```text
business receipt
→ identify potentially affected persistent memory
→ mark as reconciliation candidate
→ ordinary LLM decides update / no-op
```

程序不能直接改正文。

需要单独评估：
- stale-current rate；
- false update rate；
- unnecessary maintenance；
- action-to-memory consistency。

---

# 16. 可能的统一框架：Selective Evidence Lifecycle

若 Formation、SER、Reconciliation 均有独立证据，最终可统一为：

```text
Observation
  ↓
Formation
  ↓
Versioned Durable Memory
  ↓
Consumption
  ↓
Selective Evidence Rebase
  ↓
Action
  ↓
Receipt
  ↓
Reconciliation
```

这比维护一个持续 semantic Decision State 更符合真实 Agent Memory 生命周期。

---

# 17. State–Attention 的未来位置

State–Attention 不再作为默认下一阶段。

只有当：

```text
current evidence known insufficient
+
ordinary ReAct repeatedly fails to acquire needed current evidence
```

才重新考虑。

此时 Attention 输入应是：

```text
request-local missing action-critical evidence
```

而不是 persistent Decision Basis。

候选：

```text
current task
+ current evidence snapshot
→ unresolved information need
→ targeted retrieval
```

如果 exact version refresh 已解决主要问题，就不增加 Attention。

---

# 18. 模型与系统鲁棒性

方法在 primary model 上稳定后，必须做 sensitivity，而不是永久固定一个配置。

可变化：

```text
model family / size
thinking on/off
temperature
context length
max output
retrieval top-k
embedding model
memory density
history length
```

顺序：

```text
method freeze first
→ sensitivity second
```

不要在主开发期间不断换参数寻找最好结果。

短 fixture 不能代表 continual agent。


- 多次 search；

- stale derived context accumulation；

# 21. 多对象与多版本

必须覆盖：

```text
X current
Y superseded
Z deleted
W unknown
```

并支持：

```text
X@1, X@2 in history; X@3 current
```

目标：
- 只改受影响对象；
- 保持 search item order；
- 不因一个 stale item污染整个 ToolMessage；
- 不把 latest 简化成“总是正确”。

---

# 22. Conflict Case

如果两个 current evidence 相互冲突：

SER 不应自动选 latest 或最高 score，除非 source contract 明确。

应允许普通 LLM：
- clarify；
- search；
- defer；
- compare authority。

因此 currentness 与 semantic authority 必须分开。

---

# 23. Derived Context Lineage 的扩展策略

首版只处理 ordinary assistant content。

后续只有真实失败出现时再考虑：
- assistant tool-call arguments；
- planner notes；
- summaries；
- cached work notes；
- other generated artifacts。

不一开始构建完整 reasoning DAG。

原则：

> 只追踪真实证明会跨 turn 污染行动的 derived artifacts。

---

# 24. 与 checkpoint / Store 的边界

SER：
- 不改 checkpoint 原历史；
- 不改 upstream LangMem CRUD；
- 不删除历史记录；
- 只改 outgoing request copy；
- exact Store.get 只用于 current-version resolution；
- 所有 projection/rebase 都可审计。

后续若要 checkpoint compaction，独立研究。

---

# 25. Formal Evaluation Freeze Gate

消费未见任务前，至少满足：

1. 多类型 changed/retained/irrelevant controls 成立；
2. 无 stale factual body leakage；
3. derived-output invalidation 有真实 request 证据；
4. irrelevant intervention 可控；
5. multi-memory / multi-revision 基本通过；
6. protocol rejection/truncation 不主导；
7. 参数和方法冻结；
8. 无 benchmark-specific rule；
9. 完整成本可统计。

---

# 26. 正式 matched evaluation

```text

```

- SER-lite = quarantine + selective current refresh；

- tools；

- memory initialization；
- retry/failure policy；
- scorer；

# 50. 总结

当前问题已经从：

```text
“为什么 4°C 没变成 8°C？”
```

抽象为：

> **底层证据更新后，由旧证据生成的历史 assistant 结论是否仍继续污染后续行动？**

当前优先修复：

```text
stale factual evidence
+
stale derived context
→
current evidence rebase
```

长程路线：

```text
Selective Evidence Rebase
→ generalized adaptation diagnostics
→ refresh optimization
→ exposed regression
→ unseen matched evaluation
→ Formation / Reconciliation
→ optional Attention
→ robustness / external baselines
→ optional Jev efficiency
```

最重要的执行纪律：

```text
失败
→ 找 first broken link
→ 至少两个可区分假设
→ 最小通用修复
→ 加反例
→ 再验证
```

项目最终目标不是完成某个预设架构，而是得到一个：

```text
generalizable
auditable
selective
low-overhead
real-agent-usable
```

的持续记忆适应方法。
