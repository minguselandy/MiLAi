# v8 持续记忆：开发与真实使用记录

承接[当前 Goal](MILA_CONTEXTUAL_USER_MEMORY_DEVELOPMENT_GOAL_v8.0_20260925.md)。本轮修复首次漏存、执行后旧状态和恢复入口；历史 v7 的 5/5 不能代替这些要求。本轮 A–E 已完成，限定验证为保留失败的分阶段修复，详见[v8 结果](CONTEXTUAL_USER_MEMORY_V8_RESULTS_20260925.md)。

## 实现

- `finish_turn` 与业务／记忆工具共享同一模型循环，直接携带最终回答和每个新观察的维护决定，不另起反思模型。`saved` 必须指向真实提交、当前持久版本及实际来源；`no_change` 允许正常零写入；`pending` 保留会话以便继续。业务 unknown 与记忆维护状态分开。
- 每个新轮次先按当前请求以最多 6000 bytes / 4 项现有检索取回材料，再接收新观察，避免请求自身挤占已有记忆。材料经过正常投影和真实可见性绑定；没有自动写入、强制 State 或额外 Host 往返。
- 本地运行存储按所有者／配置／协议精确绑定，独占写锁、原子替换并 fsync。持久库可重开；活跃会话恢复实际 transcript、短引用和可见范围，清空失效读缓存。相同完成轮次复用结果，不再次调用模型；相同轮次 ID 换输入被拒绝。
- 业务调用先保存 intent，执行返回后先保存原始结果，再接收／投影来源。中断恢复交付已有结果；只有意图或结果 unknown 时不会自动再次执行相同动作。应用可用实际业务查询结果调用 `reconcile_action`，保留核对依据及原结果。
- 中文全文路径增加汉字和相邻双字词项，英文及标识符仍按原规则拆分；不依赖额外模型。旧删除 fixture 改用原有可信生命周期授权，权限未放宽。MERIT 异常保留世界、任务记忆、真实会话、调用、预算及原异常，标为未评分。
- 共用写入合同要求保留原语言中的实际操作标签、完整枚举和更正值；默认回答遵循用户语言。程序核对提交合同，不宣称能证明自由文本的语义正确。
- 精确片段修订 `content_patch` 与完整 `content` 互斥。局部更正必须唯一匹配已交付的准确版本，多个片段不得重叠；程序保留其余正文，仍检查 CAS、完整来源和独立依赖。恢复核对后的结果作为新的真实来源交付，原 unknown 记录继续保留。

## 使用入口

默认配置：[ordinary/off](../configs/contextual-memory-v8-off.json)；可选 State：[optional](../configs/contextual-memory-v8-optional.json)。两者累计费用上限为 null，单次工作流容量仍保留。`task_runtime` 支持显式 `state_path`；新进程使用相同所有者、配置和目录即可恢复。新会话只检索持久库，原会话的临时材料仅用于恢复该会话。

真实文件示例读取 `工作目录/document.md`，支持按 SHA 版本写入和必需章节检查。将自然语言请求保存为文本文件后运行：

```bash
uv run python examples/contextual_document.py --live \
  --workspace artifacts/my-document/workspace \
  --state artifacts/my-document/state \
  --output artifacts/my-document/runtime \
  --session plan --turn first --request-file /absolute/path/request.txt \
  --required-section '# 概览' --required-section '# 变更' --required-section '# 限制'
```

需要同会话后续轮次时加 `--keep-session` 并沿用 session、使用新 turn；新会话换 session。同轮中断后沿用相同 session/turn/请求；状态不同于 complete 时不会自动关闭。不要以换 ID 代替核对 unknown 动作。配置和语义协议变更需要明确迁移或新库，不能忽略身份错误读取旧库。

`--live` 才调用模型；不带它运行原有确定性接线样例。运行制品和状态放 ignored 的 artifacts 内；普通入口只有读／维护权限，既有可信删除合同继续单独执行。它是 Lab 原型，不是 Product 部署。

## 已保留的失败

| 阶段 | 真正发现的问题 | 后续修复 |
| --- | --- | --- |
| 初始终结回执 | 模型把 `records` 填为拟写正文，零保存，却重复声称已登记；程序拒绝 complete；12 次请求 | 改为统一 `finish_turn` 动作、`record_refs` 准确别名、动态已提交句柄范围；拒绝分支也执行已有无进展判断 |
| 统一动作后 | 首次 2 次请求完成 CREATE；更正轮将包含长期更新的消息整体判为临时指令 | 新会话紧凑预取旧事项；明确执行限制与事实/要求作用范围 |
| 前置旧事项后 | 来源完整、REVISE 合法，但模型把三项更正成两项，遗漏替换的新值 | 共用合同保留原标签、完整结果集合和新值，避免把合法提交等同于语义正确 |
| 保留原语言后 | 正文列出三项，却仍称“两个一级章节”，回答与保存正文不一致 | 提供准确旧版本上的精确片段修订，减少局部更正时的无关改写 |
| 精确片段接口后 | 模型仍选完整改写并漏掉新值；后续写回旧章节，未调用检查工具却声称检查完成，未保存执行状态 | 停止增加内容提示；核对实际生成协议及模型推理配置，继续开发 |

五个相位的原始结果、源代码和费用均保留。错误首先出现在模型生成中，不是材料投影或引用错位；翻译只是可能促因，不作为已证明原因。精确修订与完整改写的 schema 分支互斥，部署 grammar 接受两种合法调用，没有证据表明 grammar 强迫模型遗漏新值。

调用层与容量计数此前都硬编码 `enable_thinking=False`。v8 将其改为显式配置，并启用同一 Qwen Host 的推理；配置、计数模板和请求必须一致。每次输出 4096 tokens 同时容纳推理及动作 JSON，遇到截断仍禁止执行。没有切换模型或额外审查调用。该改动是否改善上述语义失败，需要原序列的实际结果证明；重复验证仍不是独立样本。

启用推理后，首次约定与完整更正均实际保存，真实文件也补全为正确三章并保存完成状态。
仍暴露两个后续缺口，继续保留而不计为通过：

- 终结回执把未引用的读取来源与已保存来源合组，重复报错后 pending。新增按真实提交计算的简短来源对应提示及具体错误信息；同轮恢复补齐确实支撑“保留原内容”的读取来源，未再次写文件。
- 新进程的一次记忆调用因把 interpretation 当作 source 被正确拒绝，但其零材料回执被存储层误当交付，触发 `RUNTIME_DELIVERY_NOT_IN_TRANSCRIPT`。修复非材料回执持久化；已有实际绑定继续严格验证。退出持久化再次失败时保留原异常，并附加后续错误说明。

原固定请求未要求一定调用名为 `document_check` 的工具；目前 Host 的草稿核对基于实际 `document_read`。
独立开发只读检查验证了真实文件章节齐全，其结果未交付 Host，不冒充 Host 工具调用。
初始推理相位和恢复修复分别冻结，结果需注明这条分阶段修复链，不能称作一次无中断全通过。
