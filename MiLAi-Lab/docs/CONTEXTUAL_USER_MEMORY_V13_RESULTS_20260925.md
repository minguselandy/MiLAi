## 4. 未达标项与失败定位

### 4.1 首次约定漏存：把暂缓执行误当成不值得跨轮保留

首集业务只要求确认未来退款约定，不能立即退款。Host 完成消息发送，却没有创建后续可用的事项记录。首集持久记忆快照中 cards、sources 均为空；实验 trace 保存了原输入与回执，不等于下一会话可以通过记忆服务取得它们。

R2 的工具说明明确要求：尚无当前卡时，未来需要的新约定也应保存；pending 不代表已经执行。实际 Provider 请求确认包含该说明，但 Host 仍将“临时、等待确认”作为不写入理由。由此可排除“说明没有送到模型”这一解释；不能再将其报告为恢复或入口故障。

首次持久化验收为 **NOT_MET**。后续 episode 重新提供了完整要求，因此两条历史依赖任务仍通过。这正说明只看 native success 会漏掉维护问题。未用强制每轮保存、订单专用规则或另一模型审核来抹平这个失败；R2 的无效说明也未继续保留。

### 4.2 独立退款：评分失败与无回执声明需要分开

两轮都读到全额退款高于无需审批阈值。原生 checker 要求发生退款，轨迹却只发送客户消息，故原生评分保留失败。该任务的工具集合没有审批动作；原生退款工具也没有执行政策表中的审批限制。这是政策材料、动作能力和 checker 的解释边界，不能仅凭该失败归因于记忆，也不能擅改 gold 或强迫忽略政策以获得通过。

R1 另外存在确定的行为错误：最终声称已经升级人工审批，但日志没有审批提交回执。内部计划和客户消息不能证明外部审批发生。R2 只表达可继续申请审批，没有复现这项误述；两轮均未完成原生退款。R2 更谨慎的措辞不能证明首次约定提示产生了因果改善，也不能覆盖最终 R1 的限制。

### 4.3 永久正文仍可能写入会话短句柄

R1 两张当前卡正文含 m4／m7／m10／m19 等会话临时引用，尽管现有写入合同要求正文可独立理解。结构化来源与当前金额正确，并不能消除自由文本可读性问题。R2 两张当前卡没有该现象，只说明一次运行的行为不同。

这不是版本引用解析失败；不能盲目替换正文中的所有 mN 来假装修复。新实现若处理这一问题，应复用明确标记的结构引用或改进材料中稳定主体／事项的表达，避免误伤真实文本。

### 4.4 控制和成本收益仍未验证

ordinary／notes／State off 是唯一方法配置。gap search、自动版本通知均为零，不能声称本轮改善了 Attention。失败处理提示也没有自然触发，因此最有价值的新证据是正式入口可运行，以及完整轨迹揭示的语义缺口。

本轮工程交付与限定诊断结束，以下是尚未实现、不能计入完成项的后续工作。优先顺序由已观察失败决定，不继续扩充记忆机制。

| P0 | 暂缓执行的未来约定首次漏存 | 在现有同一 Host 维护路径中区分“业务暂缓”和“没有跨轮价值”；先明确尚未履行事项的保留合同，不将其等同于长期用户画像。检查何时允许这些来源退出可检索记忆 | 正常原生首次输入后有可恢复当前事项，行动仍未误执行；随后只更新同事项 |
