# V13 分支采样与反馈计费核验

本次核验回放了 TRAIN 合法动作和冻结续跑，使用已记录的 Reader 返回验算质量与成本。全部额外验证使用 CPU，新增 Reader 请求为零。实验目录为 `/cra/milai-experiments/v13-qrag`。

| 核验范围 | 观察结果 |
| --- | --- |
| 共同 warm 的前 160 个完整根 | MuSiQue 92、QASPER 50、Persona 18。Persona 占 11.25%。同一 QASPER 包内出现重复终端请求的有 12 包，160 条分支得到 148 种包内不同请求 |
| 回放其中 32 个根 | 重建的实际请求、动作轨迹、原生质量和未来成本与原始记录对应。精确复用覆盖 126 次监督曝光 |
| 同请求重复实际测量 | 根 47107 的两条等价终端请求具有相同解码配置与 seed，原始 Reader 输出分别为 76 和 94 tokens。跨臂复用优先匹配该根、该动作的原始付费测量 |
| 共同 warm 调度变更 | 在 198 个完整根和 729 次收费闭合后切换。742 份逻辑回执均已对应到根，未发提案为零。全部旧数据及成本保留，两臂共享同一份 warm |
| 修正后的真实计费 | 到累计第 1,000 次收费时，切换后的 74 个包共新增 271 次请求，逐包预估曝光及新增请求均与实测相符。此时 272 个根的来源构成为 Mu/Q/P 163/82/27 |
| 2k 真实闭合 | 550 个完整根、2,035 份有归属回执与 2,000 个互不重叠的收费槽。未归属收费、未归属回执和未知请求数均为零。切换后的 352 包全部逐包匹配了预计曝光及预计新增请求 |
| 机制池累计限额 | warm 的 Mu/Q/P 为 330/166/54 根，同组最大 1/2/3。冻结池剩余任务分别为 39,518/2,427/1,406 项。纳入 warm 后各组能达到的最大值为 2/6/6 |
| 原生组与预算压力测试 | 在真实 TRAIN 组库存上模拟选择，费用从已测 TRAIN 包费用重采样。4,000 和 6,000 单位分别保留 1,000 和 1,500 单位随机曝光。同组最大 before 数均满足 Mu/Q/P 4/6/6 上限 |
| 跨轮抽窗重复性 | 对两轮分别抽取 512 个均匀根，缺少轮次种子时两轮根全部重复。加入轮次种子后重复 16 个。机制对照两臂仍使用相同的轮内坐标 |
| 合法八候选窗口试算 | 使用 S0 四头在 CPU 执行固定规则续跑与策略续跑。机制 U/A 初始候选一致，选中同一根。自然轮的两个选择不同，其结构化定价实际展开 3/8 个包与 12 条终端轨迹，累计 66.67 秒本地时间。均匀选择展开 1 包 4 条，累计 16.51 秒 |

正式采样器按实选根校正来源比例。Persona 的累计上限取总根数的十分之一下取整，剩余名额按 Mu/Q 2:1 分配。每个组在达到名额前可从所有剩余任务中选择。2k→6k 两臂继承共同 warm 已用的原生组名额，并引用同一份未标注 TRAIN 根候选清单。6k 之后按冻结策略形成新的采集轮。

结构化得分的分母采用本臂先前未获得的不同终端测量数，计入所需 companion。同包同任务、同 wire 和同 seed 的兼容结果可以合并。对臂选样留下的可用测量只改变实际请求的复用，优先分保持独立。每包记录预计和实际曝光、项目新增请求、失败情况下的扣账上界，以及未选候选的控制器计算。活跃采样的排序优先级、强制随机槽与全零回退均有独立标记。记录的选择概率以来源和候选窗口为条件，主动臂的质量比较使用预先注册的自然 DEV 队列。

上述压力测试与 S0 窗口试算用于检验调度机制。判断采样收益仍需共用 pi₀ 的 6k 读出、各臂自身策略的 12k/24k 读出，以及计划规定的独立采集复核。

可从以下实验记录复查。目录前缀均为 `/cra/milai-experiments/v13-qrag/`。

- `warm-11/sampling-handoff.json` 与 `warm-11/sampling-v2.json` 记录新旧调度边界。
- `runtime-validation/sampling-final-prefix160.json` 记录实际请求回放与最终额度压力测试。
- `runtime-validation/sampling-prefix160.json` 记录 S0 四头在 32 个真实根上的优先分观察。该次中间测试发现 6,000 单位尾部的保留随机额度可短少 2 次，随后加入尾部完整包保护。
- `runtime-validation/round-pool-overlap.json` 与 `runtime-validation/policy-window-registered-seeds-s0.json` 记录轮间重合度与最终种子的窗口试算。

## 多粒度实际交付与代价

对全部 550 个 TRAIN 根重建同一合法 before，并核对所有已选首动作均在菜单内。对同一候选索引同时执行过 R2 和 R3 的对象，分别从该 before 回放一次真实 READ，比较 Host 首步交付包及选中来源上的半开区间并集。终态另取已保存的完整 Reader 请求。质量和未来成本从单题回执重算；MuSiQue 如有可比较对象须重建同一 companion 下的原生 pair 分。正负差均取 R3 减 R2。

| 来源 | 全部根 | 同时可选两个粒度的对象槽 | 两臂实测的对象（原生组） | 首步交付不同 | 最终请求不同 |
| --- | ---: | ---: | ---: | ---: | ---: |
| MuSiQue-Full | 330 | 0 | 0 | 未识别 | 未识别 |
| QASPER | 166 | 328 | 82（79 篇论文） | 82/82 | 42/82 |
| PersonaMem-v2 | 54 | 294 | 51（33 个 persona） | 51/51 | 51/51 |

| 来源 | 平均原生质量差（百分点） | 质量升/平/降 | 平均首步材料差 | 平均未来成本差 | 平均总成本差 | 总成本更高且质量未升 / 全部实测 | 在更贵对象中质量未升 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| QASPER | −1.19 | 6/71/5 | +533.49 | −336.13 | +197.35 | 36/82（43.9%） | 36/42（85.7%） |
| PersonaMem-v2 | −1.96 | 2/46/3 | +137.57 | +444.04 | +581.61 | 49/51（96.1%） | 49/51（96.1%） |

成本单位为训练目标的原始 token 计数。总成本含该根之后的净材料增量及终端 Reader 输入/输出，未来成本从中扣除首步已知材料成本。两来源的 R3 首步均更贵；仅按首步计，质量未升的比例分别为 76/82 与 49/51。上述 133 对的质量、未来成本和终态请求均有观测。程序对其他轮次的缺测值保留 mask，分母随观测项单列。

QASPER 有 40 个对象首步内容不同，冻结 π₀ 续跑却得到相同终态请求。其中 35 对复用同一实际回复，5 对有不同的真实付费请求。后一组质量差均为零，但有一对输出长度相差 18 tokens。对不同 wire 的单次 Reader 观测，质量未升仅指所记录的原生分数。所选包倾向同对象可区分的粒度，以上比例适用于确实执行的两侧，不能用作所有 622 个可选对象或其他续跑策略的平均收益。

## MuSiQue 桥接证据与原生组质量

冻结自然 DEV150 中共有 25 个 MuSiQue-Full 原生组。每组的可答成员均可将官方分解的首个有支持段落编号的步骤映射到实际正支持对象；25/25 的该步子答案随后被其他步骤引用。初始 BM25 粗召回 32、取前 8，按对象 ID、修订与字符区间覆盖整个段落判定可达。两臂 25/25 个搜索后候选菜单与历史轨迹一致。导航预览不计为 Reader 交付。仅在实际 READ 前尚未覆盖、READ 后完整覆盖时记一次桥接补足，最终恢复的交付包与已执行 Reader wire 逐项相符。

| 冻结策略 | 前八可达桥接 | 可达时经 READ 补足 | 第一次 READ 即补足 | 全证据集交付 / 可达 | 全部 25 组原生均分 |
| --- | ---: | ---: | ---: | ---: | ---: |

只有 10/25 个原生组的全部支持证据包含在前八候选允许的来源区间内。可达性是在具体 READ 次数与材料预算约束之前计算的候选上界。两臂完整交付的 5 组中有 3 组重合。pair 质量按该策略对可答和不可答两个成员的实际返回重新门控，25/25 均有观测。以上为已暴露 DEV 队列上的条件均分；每类的任务难度与策略访问状态都可能不同。

## 正式检查点结算

主研究的 `settle_memory_control_v13_round.py` 在真实 6k、12k、24k 曲线点闭合时自动调用同一个 CPU 重放入口。每个检查点只读当前轮的 PQ-U、PQ-A 新增包，各重放一次。对应的轮内曝光为 4,000、6,000、12,000。6k 校验共同 π₀；12k 和 24k 分别对照各自前一检查点的冻结策略身份。DQ 的粒度表引用 PQ-U 的原始结果，QR 单条在线轨迹的同 before 双粒度效果标为未测。

桥接表同时检查 QR、DQ、PQ-U、PQ-A 及已冻结的规则和原生 GTE 六臂，使用相同自然 DEV 任务与预算。各阶段完整的原生组记录与来源区间保存在 `read-effects/a11-N.json`，其中 N 为累计曝光。`dev-review-a11-N.json` 的 `read_effects` 字段记录原目录、续跑身份、分母与按来源摘要。空分母、质量缺测和未来成本缺测分别保留，每轮新增 Reader 请求及控制器 GPU 使用均为零。
