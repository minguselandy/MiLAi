# MiLAi 计算自适应记忆控制
## 开发、训练与实验规划 v2.0

**日期：2026-11-17｜资源：2 × NVIDIA A100 40GB｜交付格式：Markdown**

**研究目标：** 训练一个小型记忆策略模型，学习下一份计算与访问成本应该花在什么记忆、什么精度、什么时间点，以及哪些旧计算值得复用，从而产生可归因的真实任务收益。

**工作简称：** CAMC（Compute-Adaptive Memory Control，计算自适应记忆控制）。简称只用于项目组织，不代表已发表方法或已确认的新颖性。

**文档性质：** 待执行的研究与开发方案。本文未启动 GPU 训练、未修改远端仓库、未证明新模型有效。除明确标注的项目历史与文献事实外，样本规模、超参数、资源分配、阈值和实验顺序均为设计值，不是已经测得的结果。

**仓库核对基点：** `minguselandy/MiLAi@2b4b17383d8d892d21651b02130b9e33deab5bec`。本次读取了主分支信息、控制循环、依赖范围和 Reader 实验报告；未检查本地 GPU、私有 checkpoint、完整原始实验目录或所有模块调用路径。[P1–P4]

**与 v1 的关系：** 本文接续 `MILAI_SMALL_MODEL_MEMORY_CONTROL_PLAN_20261116_v1.md`。保留其模型无关、完整动作绑定、同状态结果监督、自身状态采集、新来源确认和训练有效性标准；将架构主线升级为“记忆对象注意力＋渐进信息访问＋可学习计算分配”，并补充真实缓存、重算和异步预取的开发与评价。本版自包含；与 v1 不一致处以本版明确说明为准，不覆盖 v1 或旧实验结果。

> **最终完成条件：** 工程能运行、模型权重改变、loss 下降、attention 更稀疏、缓存命中率提高，都不是终点。必须证明训练后的策略优于同架构的可用训练起点，并在新任务上相对强简单策略取得预先声明的质量优势或质量约束下的完整成本优势。若未达到，记录证据、诊断瓶颈并进入下一项有根据的假设；不得改分母、挑 seed 或复用已曝光确认集制造“训练成功”。

## 执行摘要

本轮不从零训练基础模型，不绑定 Jev、Laya、JEPA 或任何模型家族，也不重建 MemoryService。固定任务 Reader 和第一阶段 Writer，让小模型控制可寻址的记忆对象。模型内部使用连续表示和注意力，外部仍执行明确、合法、可观察的动作。

核心思想从“哪个记忆相关”推进到三个问题：**当前需要更多信息、更多计算，还是更及时的状态？** 对应的资源操作是获取新证据、提高表示或证据精度、增加有限交互计算、刷新条件化状态，以及在收益不足时停止。预测式预取作为有真实等待瓶颈时的条件分支，不为架构完整而强行建设。

| 工作线 | 核心假设 | 一期地位 | 必须交付的证据 |
|---|---|---|---|
| P：渐进读取与表示 | 只为会改变任务决策的记忆增加细节，比固定精度更有效 | 主线 | 同状态展开收益、质量—成本曲线、真实任务读出 |
| D：变化驱动重算 | 独立基础编码可复用，条件化计算可按变化范围更新 | 主线第二步 | 与完整刷新及规则刷新比较，包含过时错误和刷新成本 |
| F：预测式准备 | 联合预测对象、精度和使用时机，能隐藏有价值的等待 | profiling 后触发 | 实际重叠、额外流量、尾延迟和任务质量 |
| A：计算深度自适应 | 某些问题缺的是关系计算，不是更多来源 | 受控探索 | 固定深度、随机深度、学习深度的同信息对照 |
| X：受限精确路由 | 对固定线性打分器，误差界可支持渐进式精确选择 | 小型理论/工程分支 | 保持 argmax/Top-k 的单元验证与真实成本，而非语义无损 |

优先完成的最小闭环是：**真实瓶颈测量 → 同一材料的两级可用表示 → MLP 与对象注意力基线 → 实际分支标签 → 小模型真实训练 → 新来源完整任务 → 三 seed 与消融。** 在此之前不开发复杂预取服务、通用插件框架或完整多模块联合 RL。

## 01. 目标、范围与完成标准

### 1.1 三项独立目标

**G1：训练有效。** 同一架构、输入权限、候选生成器与执行环境下，训练后优于可用的训练起点。以随机策略为唯一对照不成立；相同训练量的弱标签/行为模仿对照必须保留。

**G2：方法有效。** 候选还要达到相对强固定策略或强规则策略的预注册质量／效率要求。只超过旧 Laya 或旧 10k＋Q，不足以证明值得采用。

**G3：机制有效。** 至少一个创新假设有干净消融、机制干预、反例与迁移证据。单纯工程缓存加速不能计为学习贡献；把已有多级缓存改名不能计为算法新颖性。

工程完成、实验执行完成、统计结论、产品采用是四个不同状态。允许“实验已完整执行但 G1/G2 未达到”；不允许用这一状态宣布目标已经实现。

### 1.2 主线范围与明确不做

| 必须做 | 不作为一期目标 |
|---|---|
| 读取、精度、工作集交付、停止的可学习控制 | 基础 LLM 从零预训练 |
| 真实表示缓存与成本核算 | 直接重写 Reader 的 KV/attention 内核 |
| 可选择的条件化刷新 | 同时训练 Writer、Reader、Retriever、Judge |
| 同状态反馈、自身状态训练和多 seed | 先建设巨型世界模型再找任务 |
| 最小的状态与动作接口扩展 | 第二套数据库、权限体系或 Agent 框架 |
| 有界创新探索与失败转向 | 为了 GPU 满载而无目标地重复旧数据 |

### 1.3 默认主要效果口径

延续 v1，默认主比较采用**同预算的质量优先路线 A**；成本是共同主要描述与重要次指标。若 profiling 和 DEV 显示本轮主要价值确为效率，则可在最终确认数据与结果出现前，以一次明确的协议修订选择**质量非劣＋成本优势路线 B**。不能在看完确认结果后从 A/B 中挑选过关路线。

任何路线都要求 G1。若采用路线 B，只能证明“训练后在明确质量约束下更经济”，不能把质量数值下降省略为“全面提升”。最终标准见第 20 章。

### 1.4 开发风格

实现一个正常路径、明确的数据结构和可定位错误。只保留动作合法性、当前权限、版本可用性、容量、标签隔离与数值稳定等必要边界。不新增重复校验层、逐事件内容指纹、无效自动重试、静默规则回退或泛化注册框架。使用 commit、配置版本、数据划分 ID、模型版本与 run ID 即可串联实验；不为审计而复制原始数据数十次。

## 02. 项目起点与本版修正

### 2.1 已知事实与适用范围

仓库所记录的 Reader 确认实验，强固定上下文为 116/256 个完整受支持首次答案，10k＋Q 为 92/256；主比较为 −9.375 个百分点。该数字属于报告中的验证标签口径，不能绕开未知与评审偏差解释为无条件真实质量差。[P4，另见 v1 的历史整理]

自然应用中 129 次 View 构建与 14 次复用均因材料预算未交付；自动来源评审还存在已知正例被屏蔽为 unknown 的问题。由此不能认定 View 本身无用，更不能把已验证标签为零说成真实成功率为零。[P4]

**本轮优先修复实际交付和可用标签；不会把扩大模型、换精度或增加训练步数当作测量故障的解决方案。** 本次未重新计算这些旧实验，引用的是固定源码版本的已发表报告。

### 2.2 实际接口与改造位置

| 已核对对象 | 已有能力 | 本版利用方式 |
|---|---|---|
| `methods/memory_control.py` | `MemoryAction`、`MemoryControlState`、`MemoryPolicy.choose`、真实执行循环、`FirstActionIntervention` | 保留唯一动作执行边界和同状态首动作干预 |
| 当前 `Operation` | `SEARCH / READ / USE_VIEW / REFRESH_VIEW / HANDOFF` | 一期优先参数化已有操作；新类型必须显式改接口与测试 |
| `MemoryControlState` | 已选材料、候选、View、新事件、最后结果、预算、可选已观察内容 | 补充资源状态，不重新定义事实真值 |
| `methods/dependency_memory.py` | 受影响区域、只读前提、显式保留、支持路径 | 作为局部刷新候选，不把图可达当作必须编辑 |
| v1 的学习与投影入口 | 完整动作绑定、导出、屏蔽监督、历史 Laya 适配 | 开发时确认调用点并复用；禁止为每种模型复制执行器 |

前四行由本次直接读取确认。[P2,P3] 最后一行继承 v1 的核对结果，不代表本次已再次检查全部源文件。[P5]

### 2.3 相对 v1 的实质变化

从“模型选哪个动作”扩展为“模型选择追加哪种工作”；从单条相关性转向已读集合条件下的增量价值；从单一文本投影转向多分辨率、动态交互和工作状态；从每轮重算转向基础编码复用与变化相关刷新；从串行访问扩展为有测量支撑的预取调度。

不改变的底线是：不能让候选生成器偷做全部语义决策，不能将索引中的完整正文向量假装成零信息观察，不能将预取内容假装成已交付证据，不能用更多可见内容或更大 Reader 预算解释成架构优势。

## 03. 推理加速依据与创新边界

下表只列本次核实到的原论文、正式论文页面或研究机构原始说明。文献机制与 MiLAi 的迁移方案分开：前者是已有工作，后者是本计划假设。论文中的速度倍数不作为本项目目标保证。

| 依据 | 已有机制 | 映射设计 | 不能迁移的结论 |
|---|---|---|---|
| QUEST，ICML 2024 [R01] | query-aware 的 KV 页访问选择 | 低成本目录与路由键先筛访问范围 | 近似选择不等于语义正确；少读页不等于少存数据 |
| NSA，ACL 2025 [R02] | 压缩、细粒度选择与局部计算结合 | 全局粗表示＋局部精表示 | 算法稀疏率不直接等于 GPU 或总任务加速 |
| LazyLLM，2024 论文 [R03] | 延迟计算，后续可重新启用此前跳过 token | 可恢复的记忆降级与延后展开 | 本轮不看不意味着永久遗忘 |
| MatryoshkaKV，ICLR 2025 [R04] | 可训练嵌套投影，按压缩预算使用 | 嵌套记忆表示与决策保持训练 | 表示重构误差不等于任务损失；只切 tensor 不必然省算 |
| EAGLE-3，NeurIPS 2025 [R05] | 直接预测与训练期自身多步状态模拟 | 用真实决策训练，覆盖策略自身状态 | 语义计划检查不能继承 speculative sampling 的分布保证 |
| Vegas，ICML 2026 [R06] | 重用验证中已有信号，减少选择器额外工作 | 重用真实操作、读取与结果反馈 | 引用次数、历史 attention 不能当作因果价值 |
| CacheBlend，原论文 [R07] | 缓存复用与选择性重算跨内容交互 | 独立基础编码＋条件化局部刷新 | 相同正文不代表上下文相关 hidden state 完全可复用 |
| OasisKV，2026 预印本 [R08] | lookahead 预测和稀疏预取 | 对象×精度×到达时机的准备策略 | 无真实并行和慢访问时不能宣称隐藏延迟 |
| FlashAttention，NeurIPS 2022 [R09] | IO-aware 的精确 attention 组织 | 优先减少重复编码、碎片读取和中间张量 | 精确内核优化与近似记忆选择必须分别归因 |
| Speculative Decoding，ICML 2023 [R10] | 草案与目标分布校正 | 只读动作的有限提前准备 | 未实施对应校正，不能声称语义策略“无损” |
| Set Transformer／Perceiver IO [R11,R12] | 集合关系与潜在瓶颈 | 记忆对象交互、紧凑工作槽 | attention 图本身不是效果证明 |

### 3.1 最接近的记忆系统不能忽略

BudgetMem 已经研究轻量策略对运行时记忆模块选择成本档位；ClawVM 已有多分辨率驻留与最低保真约束；MemSidecar 已有预测查询、并行检索和缓存交付。[R13–R15] 所以“增加层级”“增加缓存”“增加预取 Agent”“小模型分配预算”不能单独作为新贡献。

本文的待验证区别是：**同一个小控制器根据任务、已观察／已交付状态、变化和缓存条件，选择下一种最有价值的增量工作；通过实际分支结果学习，而不是只按相关性、固定精度或历史命中次数选择。** 这仍需相关工作持续核对，不能预先称首创。

### 3.2 三类可发表贡献的边界

**算法贡献：** 条件化精度与工作类型选择、变化相关的价值重估，能超越固定规则与同架构基础学习。

**架构贡献：** 对象级静态表示、局部条件交互与紧凑工作状态，在质量相近时形成真实计算优势，并在对象规模增加时保持可用。

**系统贡献：** 若主要收益来自批量加载、缓存布局或预取调度，应诚实定位为系统工作；必须有真实负载、并发、尾延迟与成本证据，不包装成新的语义学习算法。

## 04. 任务形式化：追加工作的价值

### 4.1 部分可观测、操作时长不一致

环境包含持久来源、记忆版本、执行器、任务模型、当前缓存与真实时间。控制器只获得合法观测，不假设一个摘要就是完整 Markov 状态。实际 READ、局部刷新与预取耗时不同；概念上按部分可观测、可变时长的序列决策处理，而不是把所有动作都当成等价一个 token。

定义：

\[
o_t=(q_t,K_t,O_t,C_t,h_t,b_t,v_t,\chi_t),\qquad a_t\in\mathcal A(o_t)
\]

`K_t` 为当前选择的交付材料；`O_t` 为控制器实际观察过的内容；`C_t` 为候选与合法绑定；`h_t` 为有限操作状态；`b_t` 为预算；`v_t` 为版本与可见性；`χ_t` 为缓存驻留、在途请求和资源状态。未来问题、答案、未来修订和未执行分支结果不在观测中。

### 4.2 主优化目标

首先将质量和资源写成约束优化，而不是随意把量纲相异的数相加：

\[
\max_\pi\;\mathbb E[Y]\quad\text{s.t.}\quad
\mathbb E[C]\le B_C,\quad T_{p95}\le B_T,\quad\text{合法执行约束满足}.
\]

训练时可以使用归一化拉格朗日形式 `Y − Σ λ_j C_j`，但必须保存各原始成本轴，并在 DEV 选定权重。一次预取如果增加总 GPU 工作但降低墙钟延迟，两项都报告，不能只呈现其中有利的一项。

### 4.3 增量价值而非相关性

以现在交付或指定的低成本动作 `a_base` 为对照：

\[
\Delta U(o,a)=\mathbb E[Y\mid o,a,\pi_c]-\mathbb E[Y\mid o,a_{base},\pi_c]-\lambda^\top\Delta C.
\]

`π_c` 是预先固定的续跑策略。训练记录必须带 `continuation_policy_version`。短程 h=0/h=2 与完整 episode 是不同目标，不能混成同一 Q 标签；更新续跑策略后，旧标签仍属于其原定义。

### 4.4 两个时间尺度

当前任务内优化读取、交付和停止；跨会话优化刷新、缓存驻留和后续维护。第一阶段冻结 Writer，仅在给定版本变化流下研究读取与条件化刷新；后续再开放真正的写入操作。不能把“更新缓存表示”写成“学会事实维护”。

## 05. 信息、精度与资源状态合同

### 5.1 不再用一个“已读”布尔值

每个记忆对象至少分别描述以下轴，避免状态笛卡尔积膨胀成大量新枚举：

| 轴 | 典型取值 | 含义 |
|---|---|---|
| 权限/版本 | 当前可见、已撤销、历史可见、版本已变 | 由真实服务判定，不由策略猜测 |
| 物理驻留 | 持久层、主存缓存、设备缓存、加载中 | 搬运与占用状态 |
| 控制器观察 | 目录、潜在表示、证据单元、原文范围 | 策略确实获得了什么信息 |
| 工作集选择 | 未选、已选、已换出 | 当前准备交付什么 |
| Reader 实际交付 | 未交付、已交付范围/版本 | 只以最终请求为准 |
| 派生计算 | 独立编码、条件化表示、受变化影响 | 旧计算是否仍对应当前条件 |

这些轴不是一条严格线性状态机。材料可以被预取但未观察，也可以观察后被换出。被换出并不意味着永久删除；权限撤销则不能仅删除一个显示引用，还要处理相关缓存和潜在状态。

### 5.2 三个精度轴必须分开

**R，证据访问深度：** R0 目录；R1 已授权的紧凑语义表示；R2 原文中完整证据单元；R3 更大来源上下文。

**D，潜在表示宽度/数量：** 例如 64/128/256 维，或每对象 1/2/4 memory tokens。它改变控制计算的信息容量，不自动增加 Reader 的来源证据。

**L，内部计算深度：** 例如 2/4 个交互块。它只处理已观察信息，不产生新来源事实。

数值 BF16/FP32/INT8 是第四个工程轴，不与语义精度混称。一期固定数值协议，只重点学习 R；D 与 L 分别做有限探索，避免同时搜索全部组合。

### 5.3 R1 的信息暴露必须诚实

若 R1 从完整正文离线编码而来，它确实携带正文信息。主协议采用“允许使用预构建索引表示”的条件：所有方法可访问同样的授权索引，预处理和刷新成本显式记录，不能称为只看标题的公平比较。另做“仅从已展示片段产生 R1”的受限条件；两种结果分开。

控制器的 latent 不能直接作为固定 Reader 的证据或 KV。首版 Reader 只接收来源可定位的文本；潜在表示帮助选取文本，不证明文本已交付。

### 5.4 不能由策略延迟的事项

权限撤销、对象版本变化通知、真实预算余额与请求取消必须即时生效。可以学习推迟的是昂贵语义重算，不是隐藏最新版本通知。对已撤销来源，清除相关持久派生表示与当前工作状态中的贡献；无法精确剥离时重建小工作状态，不能保留可能泄漏的隐藏向量。

### 5.5 容量按最终请求测量

证据单元、来源元信息、工具回执、schema 和 Reader 模板一并计量。R2/R3 超限时返回真实不可交付状态；不得先生成大 View，再把交付失败记成学习成功。不同方法使用相同包装器及相同材料上限。

## 06. 总体架构与模型路线

### 6.1 推荐数据流

```text
持久来源/记忆/版本/已存支持关系
          |
          +--> 独立基础编码与多级表示（可缓存）
          |
当前任务 + 已观察证据 + 当前交付集合 + 变化 + 预算/缓存
          |
          v
   轻量对象级状态编码器
          |
   小型潜在工作空间 + 条件化候选交互
          |
   工作类型选择 --> 完整合法绑定的指针评分
          |
   真实执行器/有限调度器 --> 实际结果、耗时、版本和新增信息
          |                                  |
          +----------------------------------+
          |
   最终来源文本包 --> 固定 Reader --> 任务结果与离线反馈
```

只存在一个事实存储和一个真实动作边界。训练模型不能绕过执行器直接修改数据库。预取器不自行生成新业务目标。

### 6.2 三条模型路线

| 路线 | 结构 | 作用 |
|---|---|---|
| M0 | 冻结现有 embedding＋两层 MLP＋成本特征 | 最低成本学习基线；判断是否真的需要 attention |
| M1 | 独立记忆编码＋潜在交叉注意力＋完整动作指针 | 首选主线；便于缓存与局部更新 |
| M2 | 小语言模型隐藏状态＋直接动作头 | 更强语义表达对照，不生成思维链/JSON 作为必需步骤 |
| L0 | 现有 Laya/S1 及旧候选 | 历史参照，原条件与共同条件适配结果分别列出 |

不把新增控制器头参数当作系统总参数。分别报告基础编码器、控制器、可训练参数、候选提出器与 Reader 的成本。已有编码器的语言覆盖先用中英主体/数字/否定/时间诊断验证，不能只凭模型名选型。

### 6.3 M1 的首版结构设计值

建议起点：控制宽度 384，6 个 attention heads，16 个工作槽，4 个交互块，FFN 宽度 1,024；每对象先 1 个潜在向量，再比较 4 个。基础投影最大 256 维，控制器内部另投影到 384 维。候选池先 64/128，部署扩展再测 256 及更大池。

工作槽数、候选数和表示宽度是实验参数，不是已测容量。首版默认每次操作后重建或完整重算小工作空间；持久循环状态作为消融后再启用，避免缓存难题与策略训练同时爆炸。

### 6.4 扩展性只在候选池内成立

若召回器只返回 128 条，控制器只能在这 128 条及后续合法分页中决策。全库扫描、索引构建、ANN 检索和候选遗漏单独计量。不能把池内 attention 的线性复杂度写成全系统随完整数据库线性扩展的结论。

## 07. 多分辨率记忆表示

### 7.1 对象而非全局词表 ID

记忆对象表示为 `MemoryRef(source_id, revision, span_or_unit, representation_version)`。ID 用于寻址，不是通过训练记住每条记录的固定词表。新记忆通过内容和元信息编码，必须能处理训练后出现的对象。

基础表示：

\[
Z_i=P_\theta(E_\phi(x_i),\mu_i)\in\mathbb R^{r\times d}.
\]

`μ_i` 包含真实来源角色、报告/生效时间、可见性、记录版本和当前已读状态等。任意数据库顺序不充当事件时间；真实检索 rank 可作为显式特征并消融。

### 7.2 R2 优先抽取，不优先自由生成摘要

首版 R2 使用原有来源中可定位的完整证据单元，至少保留主体、谓词、必要数量、否定、条件、时间和来源范围。只切固定字符长度容易截掉限定，不应作为唯一方案。若需要模型形成单元，应对所有方法使用同一冻结形成器，并计入形成成本与错误。

R3 打开相邻或完整来源范围，记录新增范围，不重复收取已加载字节，但重新发送给 Reader 的 tokens 仍按实际成本计算。

### 7.3 D 的嵌套训练

对同一个高维基础向量，训练可用的 64/128/256 维前缀；对多向量池使用嵌套的 1/2/4 组表示。小表示是更大的子结构，不是部署时任意截去未经训练的维度。

每个训练窗口至少采样一种低维条件和最大条件；用实际监督及有限的高精度策略蒸馏联合训练。蒸馏教师不是语义真值，低精度下有多项正确动作时不强制复制教师唯一 argmax。[R04]

### 7.4 真实省算的必要条件

基础编码器若每次仍把完整正文编码一次，再切 64 维输出，减少的只是后续计算/搬运，不是基础编码成本。要报告真实节省，必须使用离线缓存、按需表示加载，或真正支持分级计算的编码路径。

离线构建全部 R1 表示的成本不为零。报告冷启动、预构建后的单次任务、连续任务和摊销成本；当编码器参数变化时重新计算缓存。训练需梯度的阶段不能从旧 detached 向量声称端到端学习。

### 7.5 组合证据与最低条件

允许对已知互补关系提出小型组合读取候选，但不是全子集枚举。关系必须来自实际已存或已观察信息；gold proof 只用于离线标签。每条记忆的最低表示要求用于约束表达完整性，不代表语义正确性已经被程序证明。

<a id="s08"></a>
## 08. 记忆注意力、内部状态与完整动作

### 8.1 任务条件化交互

使用少量工作槽 `H_t` 对当前可用表示 `Z` 做交叉注意力：

\[
H'_t=\operatorname{Block}\left(H_t,\operatorname{softmax}\left((H_tW_Q)(ZW_K)^\top/\sqrt d+B_t\right)ZW_V\right).
\]

`B_t` 的强 mask 只表达权限、不可用对象等确定约束；时间、版本、关系等弱偏置应可学习或做消融，不能把离线答案硬编码进去。注意力得分不直接定义“记忆事实可信”或“应永久删除”。

### 8.2 输出指针而非生成对象 ID

在合法候选动作 `a=(kind,target,parameters)` 上计算分数，返回本地 ID，由唯一执行器映射到完整绑定。这借鉴指针式输出的对象选择方式，不把普通注意力融合权重直接当作动作策略。[R21]动态动作数使用 mask；候选重排后必须按对象还原比较。

类型、对象、精度与参数可以按条件分层评分，但后一级必须依赖已选前一级。不得独立预测几个 argmax 再拼成从未存在的动作。

### 8.3 概念工作类型与实现操作分离

| 研究概念 | 一期映射 | 明确边界 |
|---|---|---|
| 获取新信息 | `SEARCH / READ` | 必须实际执行后才能更新观察 |
| 提高已有对象证据精度 | 参数化 `READ`，或独立版本的扩展操作 | 现有 `expand_context` 不是任意多级表示能力 |
| 选择交付 | 参数化 `HANDOFF`／现有工作集机制 | 只发送实际取得的文本范围 |
| 重算条件化状态 | 控制器内部计算策略 | 不冒充生成一个新的事实 View |
| 创建/打开事实 View | `REFRESH_VIEW / USE_VIEW` | 与刷新 latent cache 是不同成本和语义 |
| 提前准备 | 明确的新调度接口或扩展操作 | 现有串行执行器不天然支持异步预取 |
| 增加内部深度 | 早退出/再计算调度 | 消耗计算预算，不产生来源新信息 |

### 8.4 注意力不作为唯一解释

主要分析使用对象替换、关系遮蔽、精度降级、相同状态分支与真实任务差异。attention 热图是辅助描述。记录“模型实际调用次数”和“仅有单合法动作次数”；不把后者算成策略成功。

## 09. 算法 P：决策驱动的渐进读取

### 9.1 最小实现

每次先看共同可访问的目录与低精度表示，生成有限动作：保持当前精度、展开某对象、补充当前对象上下文、继续搜索、选择交付、停止。先支持两级 R2/R3，再加入 R1；没有真实可用的中间层时，不要为了层级数量制造无意义摘要。

同一状态的主要比较是：低精度直接完成，与升级后按固定续跑策略完成。记录升级是否真的改变正文、对象选择、交付和任务结果。重复编码同样信息不能标为一次有效精度升级。

### 9.2 展开价值

训练 `gain_head(o, object, r, r')` 和 `cost_head`，分别预测任务差异与资源增量。部署排序可以使用预定权重，但主要报告保留质量与成本分项：

\[
V_{expand}=\widehat{\Delta Y}-\lambda^\top\widehat{\Delta C}.
\]

`ΔY` 来自真实分支；未得到明确语义判断的样本可以训练可观察成本，不能训练成零质量增益。低精度已经充分但高精度被 Reader 随机答错时，应保留观测及重复方差，不通过主观重标来保证“更多信息单调更好”。

### 9.3 配额与组合

初期每步最多提名 2 个升级对象，最多 1 个双对象组合。组合只从实际可见关系或固定邻域产生，提出器不看 gold。对照包含同数量随机升级、最高相关性升级、固定所有对象 R2 和固定少量对象 R3。

多步策略必须计入决定“是否展开”的控制开销。若单独一轮控制比直接读取更贵，允许学习或规则直达路径，但该路径对所有可比模型公平开放，且记录为资源路由而非暗中兜底。

### 9.4 受限精确选择分支 X

只对固定 query 和固定线性路由分数 `s_i=qᵀk_i+b_i` 使用误差界。设低精度向量为 `k̂_i`，其实际误差上界为 `δ_i≥||k_i−k̂_i||₂`，且 `b_i` 已知，则：

\[
L_i=q^\top\hat k_i+b_i-\|q\|_2\delta_i,\quad
U_i=q^\top\hat k_i+b_i+\|q\|_2\delta_i.
\]

当 `L_best > max U_other` 时，可以在该固定候选集合上确认同一 argmax；Top-k 需要所选集合的最小下界超过未选集合的最大上界。平局按预定规则处理或继续展开，不能把等号当作严格确定。

`δ_i` 可以来自固定正交分解中尾部的实际范数；若只是预测误差、经验分位数或未校准估计，就不能称严格界。query 或投影模型更新后必须重新计算适用的界。该结论不覆盖 ANN 未召回对象、非线性交互分数、最终语义正确性或动态策略分布。

先与完整精度路由比较：若维护界与分级加载的成本大于节省，则关闭此分支。它不是必须加入主模型的“数学装饰”。

### 9.5 判别性任务

关键限定在 R2 中、只在 R3 中、根本不存在三种情况都要覆盖。添加大量词面相似的干扰对象，以及相关但已重复的来源。测试模型是否能把预算留给少量改变决策的对象，而不是把所有来源统一展开。

<a id="s10"></a>
## 10. 算法 D：变化驱动的增量重算

### 10.1 三种缓存分离

| 缓存 | 可复用条件 | 失效条件 |
|---|---|---|
| 基础内容编码 `z_i` | 同来源版本、同编码器/投影、同许可范围 | 内容、模型、权限或投影变化 |
| 关系局部表示 `g_i` | 所依赖对象与边均有效 | 相关对象/边变化；共享参数变化 |
| 当前任务表示 `c_{i,t}` 或工作槽 | 相同任务条件和已观察状态 | query、预算、证据集合或操作结果变化 |

不能用“正文没变化”保留全部任务条件化状态。基础内容可以长期复用；小型工作空间通常值得每步重算，这可能比复杂失效传播更便宜。CacheBlend 仅提供选择性重算的启发，不证明本方案语义状态的等价性。[R07]

### 10.2 真实变化与可延后计算分离

变化事件先写入可信元信息和可见性层，更新 `revision/dependency_epoch`。控制器立刻看到“某些派生状态待重算”，再选择：直接用独立基础表示、局部重算、完整重算，或读取新来源。

不能为了节省成本继续把旧修订声明为当前事实；旧版本可用于历史问题，但必须保留时间与版本解释。

### 10.3 局部性由计算图定义

若关系模块只有显式 k-hop 稀疏邻域，可对变化对象的实际依赖闭包重算；如果使用全局 self-attention，不能声称一条变化只影响几个节点。训练/评测均保留完整重算参考，比较逐层表示与最终动作差异。

`dependency_region` 给出需要重新考虑的候选范围，不自动决定事实失效、编辑内容或删除结果。[P3] 对共享条件、局部例外、独立支持替代三种关系都要测试，避免把兄弟节点全部误删。

### 10.4 刷新收益训练

在固定真实事件到达后，比较 `复用基础表示并重算工作槽`、`局部刷新`、`完整刷新`。任务标签来自后续查询或任务，成本来自实际计算；“表示差异大”只可用于采样，不等于刷新必要。

预设困难分层：仅正文变、仅有效时间变、仅支持来源撤销、关系变但正文不变、任务完全切换、多个变化并发。没有变化时也应有样本，防止学成每轮刷新。

### 10.5 嵌套隐状态的安全重建

潜在工作槽可能混合多个来源信息。若无法精确追踪某来源的贡献，权限撤销或来源删除后直接从仍合法的当前材料重建小工作槽。不要以 `mask` 了一个对象为由继续复用已混入其内容的向量。

此项是正确性要求，不交给模型选择。学习只优化允许复用的计算，不优化是否遵守撤销。

### 10.6 成本比较

对照至少包含无缓存、只缓存基础编码、固定 TTL 刷新、版本变就全刷新、显式依赖规则局部刷新、学习型刷新。若学习型只超过无缓存而未超过简单版本规则，只能称工程改进，不能称学到了更优变化控制。

## 11. 算法 F：预测式准备与只读操作合并

### 11.1 触发条件

只有实际 profiling 显示加载、远端等待或重复读取具有显著优化空间时启动。先计算 Amdahl 上限及并发竞争，不能凭“预取先进”开工。同步内存内小库几乎没有可隐藏等待时，主线继续 P/D，不构造主观慢服务来制造胜出。

可做带可控延迟的压力实验，但它只能解释在哪类负载有用，不能代替真实部署结果。

### 11.2 预测输出

预测对象 `i`、目标精度 `r` 和未来需求时间窗口 `τ`。一期使用有限窗口 `{下一操作、未来2步、未来4步}`，不预测开放式长计划。输出是未来需求的候选，不是当前授权的新任务。

仅预测会访问的 ID 很容易复制旧策略；需要使用真实需求、收益与等待作为多项监督，并测试新策略下的分布变化。

### 11.3 调度收益

对每个提名请求估计：

\[
G_i=p_i\,\widehat T_{hidden,i}-\widehat T_{visible\_overhead,i}
-\lambda_b\widehat{Bytes}_{extra,i}-\lambda_m\widehat{Occupancy}_i
-\lambda_s\widehat{StaleRisk}_i.
\]

这个式子是训练/调度代理。实际隐藏等待必须由真实重叠测量，不能直接以被搬运数据大小换算。额外资源项不能在最终结果中只留下有利的延迟一项。

### 11.4 最小执行器

复用原存储读接口，加一个有限并发队列、取消标志和版本/权限复核。初始并发上限 2、每次最多 2 个对象、最多 2 个 speculative steps；具体字节额度以 profiling 的缓存容量冻结。

后台准备只写暂存缓存，不自动把正文加入 `observed_evidence` 或 `visible_evidence`，也不触发最终回答。若控制器实际读取了缓存内容，立即登记观察范围与成本。等待未完成时执行正常合法操作，不伪造“已经读取”。

这描述的是拟开发运行时功能，不表示本次文档生成已经启动任何后台任务。

### 11.5 提交前复核和取消

物理加载开始及观察/交付前分别检查当前权限和来源版本。版本变化时丢弃或重取，记录浪费；取消后的残余工作仍计入总资源。不得先执行写入、遗忘、业务操作，再希望“验证失败就回滚”。一期推测范围限只读、无外部副作用操作。

### 11.6 独立读取与依赖读取

目标及参数已由当前真实状态确定的独立读取可以批量合并；下一步依赖前一次正文内容的读取只能预估需求，不能拿预测内容补进事实状态。

多子任务共享同一物理读取时可以合并 IO，但仍保持各自观察范围、版本、权限、交付包和计费归属。共享成本只计一次总量，方法级分析使用预定分摊并同时提供未分摊总量。

### 11.7 训练与评价的特殊问题

没有未来访问可能是请求真正没用，也可能是轨迹提前失败、取消或预算耗尽。需求标签带 `window_complete`；窗口被截断时不能简单记为负例，可屏蔽或单列删失模型。未来任务可以用于离线标签，但不能进入在线 predictor 特征。

实时 A/B 运行相同初始缓存、相同资源配额和固定来源版本，随机交错运行顺序。离线回放仅用于初筛；开放式策略改变后续访问分布时，固定旧访问日志不构成最终效果证明。

### 11.8 基线与最接近工作

必跑无预取、最近访问/邻近关系规则、转移频率预测、学习需求概率、学习时机与精度、完整候选方法。可复现 MemSidecar 的相同条件适配作为更强基线，但不能把经过改写的简化版称为原论文实现。[R15]

## 12. 自适应计算深度与已有反馈复用

### 12.1 学会区分工作类型

`SEARCH_NEW`、`REFINE_EXISTING`、`COMPUTE_MORE`、`REFRESH_CHANGED` 与 `HANDOFF` 是研究语义，不要求第一版同时新增操作枚举。内部计算深度由控制器自己的调度决定，外部动作仍由统一执行器执行。

R 读取深度与 L 计算深度独立：先冻结 L=4 做渐进读取；随后固定相同信息比较 L=2、L=4 和学习退出。若每次都算完4层再决定“本来2层足够”，这只产生标签，不产生部署加速。

### 12.2 深度训练

为2层和4层设置共享/兼容读出头，在 TRAIN 的同状态上监督两者的实际动作及任务收益。训练期间随机截断深度与少量全深度蒸馏结合，避免浅层只复制复杂网络的偏差。额外计算最多一次或预定上限，防止内部空转无限消费。

策略熵、不同 head 分歧与 attention 强度只可作为输入特征。校准目标是继续计算的真实收益或错误停止风险，而不是让概率变得更尖锐。

### 12.3 可复用的廉价信号

直接复用实际获得的信息：新增来源范围、重复读取、实际容量、版本变化、失败类型、明确工具回执和最终任务结果。这对应 Vegas 的“减少额外选择工作”思想，但只是可用反馈来源，不是可移植的 KV 验证保证。[R06]

Reader 引用某段、没有引用某段、给出高置信度，均不是独立的因果价值标签。将这类反馈标成弱信号；用于采样或辅助损失，关键动作偏好仍依赖受控分支。

### 12.4 不强制依赖 Reader 内部特征

默认仅使用部署可获取的请求、回复、回执与本控制器状态；可访问本地 Reader hidden states 的实验单列。API-only 主线不能用训练时可见、部署时不可见的 logits/attention。教师使用额外信息只作为离线标签，且不能据此宣称所有观察条件相同。

## 13. 数据、任务和划分

### 13.1 三条轨道

| 轨道 | 环境固定项 | 研究问题 | 主评价 |
|---|---|---|---|
| R：单任务记忆读取 | Writer、Reader、来源库、候选提出器 | 渐进读取、交付、停止、内部计算 | 首次来源支持任务结果＋完整成本 |
| C：持续变化与资源控制 | 相同事件到达流、权限、资源配额 | 刷新、缓存、预取、时机 | episode 完成、过时错误、等待与资源 |
| W：跨会话维护扩展 | 相同原始历史和固定内容提案器 | 维护决策对未来任务的价值 | 后续任务收益＋非目标保持 |

一期必须完成 R；C 中先 D 后条件 F；W 不应阻塞首轮训练，但只有完成 W 才能声称学习了广义长期维护。不同轨道不拼成一个不透明平均分。

### 13.2 公共基准的角色

LongMemEval 用作长期事实、时间与更新读出的外部参照；MemoryAgentBench 用作增量交互能力验证；MemoryArena 用于跨会话相互依赖任务的记忆—行动闭环。[R18–R20]

每个基准固定原生版本、许可、划分、环境和评测入口。改变读入协议、任务生成或 judge 时，结果标成 MiLAi 的共同条件改编，不称官方成绩。没有训练划分的测试基准不反向导出训练标签；规模不足不能靠把同一历史分成很多相关行增加独立 N。

### 13.3 数据来源分工

旧 TRAIN 轨迹用于暖启动、输入适配和历史错误诊断；旧 DEV/E4 已曝光，只用于回归与解释。新增自然来源承担主要泛化训练。程序化环境提供主体、时间、例外、撤销、冗余和部分执行的可执行真值，用于机制和接口验证，但单独报告，不代替自然任务。

需使用训练来源生成 query 时，保存生成协议；不让生成器按拟议模型的表示结构专门写容易题。加入无答案、来源不足和简单直达问题，避免模型只学会复杂化。

### 13.4 划分单位

先按原始用户、文档、任务世界和已知依赖关系分组，再生成 query、派生翻译、分支和时间切点。同一个根来源的全部派生材料随组归属。使用 TRAIN、DEV-fit、DEV-select、CONFIRM 和 EXTERNAL；划分表先于目标生成冻结。

持续任务中，完整共享状态的 episode 是基本聚类单位。用户跨多 episode 时进一步按用户聚类。只有明确独立的环境世界才能作为独立样本；训练 seed 和 Reader 重复不能把来源数量翻倍。

### 13.5 建议的有限数据块

以下为生产目标，实际数量须由来源可用性和可靠标签产出确定。

| 数据块 | 根来源/世界目标 | 状态/反馈目标 | 用途 |
|---|---:|---:|---|
| D0 | 64–128 | 256–512 状态；每状态最多3–4个主要分支 | 真实闭环、标签与可学习性 |
| D1 | 500–1,000 | 5k–10k 状态；目标≥2k可靠比较状态 | 架构与监督筛选 |
| D2 | 1k–2k，依库存 | 20k–40k 状态；目标5k–10k可靠比较状态 | 主训练与学习曲线 |
| D3 | 原 TRAIN 内新到达状态 | 两轮各1k–3k；保留随机来源 | 自身状态分布适配 |
| C-track | 新的独立多步 episode | 至少覆盖四种真实变化/负载形态 | 刷新与预取训练/验证 |
| CONFIRM | 按第20章功效设计 | 每方法首次完整执行，固定子集重复 | 最终确认 |

必须报告机会数、可执行分支数、明确质量比较数、成本标签数、未知数和独立根数，不能把每个候选对都当成独立训练来源。

### 13.6 多样性与主动采样

首轮覆盖：直接可答、低精度遗漏关键限定、组合支持、冗余干扰、时间变化、对象/角色混淆、无答案和执行异常。主动采样初始保留≥30%随机配额，其余用于模型分歧与欠覆盖；比例只在 TRAIN/DEV 调整。

持续数据加入 query 切换、突发版本变更、冷热切换、预算降低和跨 Reader 条件。不要为了某个机制胜出，将全部任务人为设置成特别长、特别慢或特别频繁更新。

<a id="s14"></a>
## 14. 同状态分支、结果标签与评审校准

### 14.1 分支实验单元

一个 before snapshot 固定实际来源/版本、合法候选、权限、缓存、当前交付包、Reader 和续跑策略。不同分支从独立副本开始；并行执行时不能共用会被各臂更新的工作集或计时缓存。

比较对象可为动作，也可为内部计算/表示选择。每次只改变明确变量；若精度、对象数和 Reader 提示同时改变，必须标为联合条件，不能称纯精度实验。

### 14.2 首批推荐分支

| 状态类别 | 基础分支 | 对照分支 | 主要信号 |
|---|---|---|---|
| 低精度候选明确 | 当前交付 | 展开一个对象 | 是否值得增加内容 |
| 候选冲突/例外 | 单对象展开 | 完整支持组合 | 组合贡献与范围 |
| 材料已齐全 | 当前计算停止 | 同信息增加计算 | 是否缺计算而非信息 |
| 真实修订到达 | 用当前有效基础表示 | 局部/完整条件刷新 | 过时风险与重算收益 |
| 未来需求有规律 | 按需加载 | 固定/学习预取 | 真实等待与浪费 |

初始不穷尽所有合法动作。必须承认偏好只在执行过的分支间有效，不能将未执行动作当作负例或宣布找到全局最优。

### 14.3 标签至少四轴

`execution_status`：完成、确定失败、结果未知、未运行；
`material_status`：充分、不充分、无法判断；
`task_status`：成功、失败、无法判断；
`resource_status`：实际已测、部分观测、未知。

格式拒绝和引用解析错误要与语义错误分开。真实任务定义包含格式时可计任务失败，但不能反推材料不足。Reader 超长失败属于真实执行结果；网络失败未知不得凭空评分。

### 14.4 校准集合

在正式训练前固定独立于最终确认的 120–200 个判例，包含明确支持、明确不支持、来源充分但回答错误、表达正确但结构不符合、权限不允许、以及真正未知。由不同于生成路径的评审与有能力的人工/独立审阅进行核对；若无法取得真正独立审阅，应明确限制，优先使用可执行环境真值。

校准重点是正例召回、否定准确率、unknown 结构和方法间差异，不是只看总体一致率。分歧发生在关键定义时修订训练评审协议并给版本；不得回头挑选最有利的旧标签合并。

### 14.5 部分标签与未知

未知质量样本可用于成本预测、状态表示或自监督；质量损失 mask 为0。不同分辨率下的未知率分别报告，防止某种方法只因输出更短/更符合 schema 而被更容易评分。

“低精度未知，高精度明确”不自动表示高精度质量更高。可作为标签可用性变化记录，只有实际任务结果可比较时才排序。对缺失样本做敏感性与最坏/最好界，而不是仅删除后计算漂亮准确率。

### 14.6 偶然性与复用

训练阶段可在预先声明的子集上重复 Reader，以估计增益方差；不得只重复负结果。请求严格相同且协议允许时可共享首次回答标签，包含失败也共享，但性能基准不能通过共享回复规避真实延迟。

本地 seed 相同也不保证外部服务逐位一致。记录模型/版本、temperature、解码参数与请求身份；训练 seed、环境 seed、Reader 重复分别分析。

### 14.7 反馈产出管理

D0 之后计算每100次实际读出产生多少明确成对状态、多少来源，以及完整反馈成本。若可靠比较率持续很低，优先处理评审、任务范围和比较设计；不得继续把几十万 unknown 包当作训练规模成绩。

保留有限探索，但给每轮反馈生产明确来源块和预算。块结束后形成数据产出与学习效应的对照，再决定扩量；不因一次负结果立即放弃研究，也不无限堆积相同无效标签。

<a id="s15"></a>
## 15. 训练目标：主任务、追加收益与资源预测

### 15.1 不把全部目标一次打开

建议统一模型具备动作分数、结果价值和成本输出，但按阶段启用损失。首版采用：

\[
\mathcal L=\lambda_{act}\mathcal L_{act}+\lambda_{rank}\mathcal L_{rank}
+\lambda_y\mathcal L_y+\lambda_c\mathcal L_c
+\lambda_d\mathcal L_{distill}+\lambda_b\mathcal L_{anchor}.
\]

只有已校准的实际任务结果进入 `L_y` 和主要 `L_rank`。表示重构、关系预测、引用频率、attention 蒸馏均不作为完成证明。

### 15.2 动作监督与多正例

在全菜单标签确实完整的程序化环境，可用多个可接受动作集合监督；若只是采样分支，不能把未执行动作通过全菜单 cross-entropy 隐含压成负例。采用比较子集内的条件 KL、已知结果回归或已执行对的排序。

对已执行集合 `S_o`，蒸馏/偏好概率在 `S_o` 内重新归一化；它只能教会已比较项之间的关系。必须另有跨状态、多样候选和真实执行反馈，避免未观察动作分数任意漂移。强制唯一合法动作不进入动作区分损失。

### 15.3 成对结果损失

对有明确方向且差异超过训练协议阈值的一对动作：

\[
\mathcal L_{rank}=-w_{ij}\log\sigma\left((s_i-s_j)/\tau\right).
\]

`w_ij` 来自预先定义的标签质量/重复不确定性，不随“是否符合当前模型”调整。真实平局可用软偏好或价值回归；unknown mask。一个状态有很多候选对时先状态内归一，防止它在训练中占据不成比例权重。

同一来源产生很多状态时再采用来源平衡采样。主表同时报告自然分布与分层结果，不把重采样后的比例冒充部署分布。

### 15.4 结果价值与成本分开训练

`value_head` 预测明确范围内的任务成功概率或收益；`cost_head` 预测各资源轴，不能把秒、tokens、字节直接相加。连续目标可使用 Huber/log-cost 损失，二分类使用适当的概率损失，并在 DEV 校准。

成本头只看执行前可见信息，训练标签才包含真实耗时。资源竞争和硬件配置影响成本时加入条件特征；预测误差随负载单独报告。没有测量的 GPU 服务端时间不填零。

### 15.5 嵌套表示和深度蒸馏

在相同合法观察范围内，高表示精度/深度策略的 logits 可以作为暖启动教师。教师冻结，样本同时包含低与高预算，使用温度化子集 KL；加入结果监督后逐步降低纯模仿权重。

教师访问更多原文时，这属于离线特权教师；学生输入保持低精度。需要单列这类数据，并保留“只有低精度无法区分”的例子：正确行为可能是请求展开，而不是强迫学生猜出高精度答案。

### 15.6 明确奖励跨度

读取轨道可使用 episode 终点结果减去各实际资源开销。局部分支 h=2 的收益是有限续跑条件下的标签，不标为全时域 Q。跨任务维护使用未来任务结果，在预先固定的 horizon 上计算。

若采用按时间折扣的 SMDP，可以用 `γ^(Δt/τ0)`；若不需要时间偏好，则保留 `γ=1`，以显式延迟成本表达速度。不能同时把同一延迟重罚而不说明。

### 15.7 PPO/actor–critic 的进入条件

先证明暖启动和结果监督在实际任务中有收益，再在确有多步信用问题时进入在线策略优化。动作是离散绑定，可以直接优化动作概率，无需把选择生成成长文本再做 token 级 RL。

初始只在隔离可复位环境使用有界探索；保存行为概率、mask 和策略版本。日志未记录 propensity 或缺少动作覆盖时，不使用逆倾向估计宣称无偏离线政策收益。正式效果依赖实际 rollout，而不是离线 Q 预测自评。

### 15.8 正确的归一化

所有损失按本次优化窗口内真实有效的状态/对/标签数归一，不按填充后的候选数或 microbatch 数平均。不同分量分别计分母；某分量整窗无有效目标时跳过该分量，不强行将 unknown 转成零。

DDP 默认平均梯度时，需使各 rank 的有效样本计数正确参与全局均值；不能平均各 rank 的局部均值后宣称全局加权一致。CPU 小测试比较单批、累积批和多 rank 模拟梯度，再进行真实 GPU 微型恢复验证。

## 16. 分阶段训练路线与初始参数

### 16.1 阶段安排

| 阶段 | 做什么 | 最小成功证据 | 未通过时的行动 |
|---|---|---|---|
| T0 可学习性 | D0真实状态、完整精度参考、随机/规则/MLP | 候选中存在可利用差异；模型能拟合并在新根上部分泛化 | 修复候选覆盖、表示或标签，不扩大无效数据 |
| T1 表示与动作暖启动 | M0/M1共同输入；R固定，完整绑定监督 | 从保存模型实际选择正确对象，而非只有类型 | 查ID捷径、关键限定遗漏与特征上限 |
| T2 追加收益学习 | 同状态精度/停止比较，主攻P | 对新来源真实任务有方向性收益 | 比较误评分、Reader随机性、选择与交付断点 |
| T3 自身状态 | 两轮聚合；保留旧数据/replay | 实际到达状态中的错误停止、重复工作减少 | 调整采集覆盖与课程，不自动切更大模型 |
| T4 变化控制 | 引入D，固定P候选；再单列联合训练 | 比规则刷新更好，且不增加过时错误 | 简化依赖范围或只保留基础编码缓存 |
| T5 条件探索 | F/A/X按profiling和诊断触发 | 各分支存在真实净收益 | 暂停该分支，保留结论，不阻塞主线 |
| T6 最终冻结 | 选定模型、协议、阈值、训练seed | 新确认与外部迁移满足第20章 | 进入明确的新研究周期，而非修补旧确认 |

### 16.2 初始优化设置

以下是第一轮有限搜索起点，须根据显存和 D0 数值检查调整；不写成已经运行的配置。

| 项目 | M0 | M1 |
|---|---|---|
| 优化器 | AdamW | AdamW |
| 决策/交互学习率 | `3e-4`，搜索 `{1e-4,3e-4}` | `3e-4`，搜索 `{1e-4,3e-4}` |
| 编码器 | 冻结 | 先冻结；需要时仅选一组 `1e-5` 的部分解冻 |
| Weight decay | `0.01` | `0.01` |
| Dropout | `0.1`起点 | `0.1`起点 |
| 有效 batch | 64个状态，按有效标签计 | 32个状态×2累积起点，按token预算调整 |
| 前向精度 | BF16可选；小头可FP32 | BF16 autocast，参数/优化器保持明确的FP32协议 |
| 梯度裁剪 | 全局范数1.0 | 全局范数1.0 |
| Warmup | 计划更新的5% | 计划更新的5% |
| 首轮遍数 | 3遍＋固定位置评估 | 3遍＋固定位置评估 |
| 种子 | 开发先seed0 | 最终候选seed0/1/2，不能挑赢家 |

不通过延长极短拟合来制造大训练量；每次报告真实主状态曝光、来源覆盖、有效监督、非填充tokens和更新数。D1 初期只允许两档 LR，不同时搜索十几个 scheduler 和几十个损失组合。

### 16.3 首轮损失权重设计值

T1 使用 `L_act=1.0`，可选 `L_distill=0.2`。T2 使用 `L_rank=1.0, L_y=0.5, L_c=0.1, L_anchor=0.05`，实际可用动作标签另以1.0启用；各分量独立归一。先比较“只有结果监督”与“结果＋有限暖启动锚定”，再决定是否需要辅助关系损失。

权重只在 DEV-fit 选定，不能为了确认集结果回调。加入新损失前必须说明它针对哪种已观测错误及最小消融。

### 16.4 课程与数据混合

建议 T1 从固定精度开始；T2 先学两级 R2/R3，随后再加入 R1，减少同时学表示、精度与动作语义的难度。T3 每轮的起始混合可为50%新状态、30%旧结果监督、20%结构暖启动/replay；弱分数数据单列上限，不挤掉明确结果标签。

在所有阶段混入应停止、无答案、已充分和低成本直达状态。否则模型容易把“做更多工作”误学成成功特征。

### 16.5 学习曲线与训练归因

比较至少三种训练量，例如可靠状态1k/3k/完整池，并设置同曝光重复旧池对照。新来源数量、有效标签、token工作量和模型更新数分开匹配或披露，不能同时变化后称纯规模效应。

保存固定训练位置的 checkpoint；DEV-select 冻结选择规则。最终三 seed 使用同规则选点，而不是每个 seed 从确认结果挑最好 checkpoint。模型恢复保存 optimizer、scheduler、采样器、RNG 和数据位置；微型恢复比较使用同硬件/数值条件及明确误差容忍，不跨不同 kernel 承诺逐位一致。

### 16.6 无监督/错标签控制

小型管线诊断可用随机标签、ID重命名和标签打乱，确认模型未从数据路径泄漏答案。但这些不是正式性能基线。正式训练贡献应相对同骨干的可用暖启动、相同曝光的行为模仿和旧弱目标，而不是相对显然无用的随机模型。

## 17. 双 A100 40GB 的训练与数据实施

### 17.1 先建立实际容量与吞吐表

每种候选至少测代表性长度与候选数：短/中/长正文、64/128/256候选、1/4 memory tokens。记录 forward/backward、优化器、输入等待、checkpoint保存、评估时间和显存峰值。数据中超长状态独立保留，不能删除后只报短样本吞吐。

两个40GB设备不能当成一个普通进程自然可用的80GB连续显存。DDP复制参数不合并单卡容量；必要的模型并行属于另一个复杂度，首版不默认采用。

资源规划可继承v1的**240个本地GPU分配小时包络**，两卡时间相加，建议训练90、反馈/编码70、确认40、探索40。它是待按实际吞吐与项目预算修订的控制包络，不是预计工期或本次已获准消耗的资源；外部Reader另计。先完成一个不超过24分配GPU小时的pilot块，再据有效标签与任务结果重新分配剩余部分。不要为凑满包络延长无收益训练。

### 17.2 推荐流水线

```text
真实来源/状态采集
    -> 分支执行与结果反馈（昂贵、可独立调度）
    -> 编译结构化训练分片/预tokenize
    -> GPU批量训练（不在线等待逐样本Reader）
    -> 保存模型
    -> 固定DEV完整rollout
    -> 选择下一批自身状态
```

训练循环不反复解析巨大 JSON、不每个 step 打开 SQLite、不每次更新调用教师。GPU 等待反馈时允许运行既定独立试验，但不要为了利用率重复计算无信息增量的数据。

### 17.3 双卡调度

| 环节 | GPU A | GPU B | 注意事项 |
|---|---|---|---|
| D0与缓存准备 | 批量编码/数值验证 | Reader或教师反馈，按实际显存 | 固定服务占用先测量，不默认两卡全空 |
| M0/M1筛选 | 一个配置训练 | 独立配置或数据生产 | 小模型先单卡大批量，不默认通信划算 |
| 正式主训练 | 同候选seed或大batch | 另一seed/反馈 | 可并行seed，但评测资源不相互污染 |
| 部分解冻 | 单卡测容量后再决定DDP | 同上 | DDP收益以有效样本/s证明 |
| 性能基准 | 固定任务资源占用 | 仅协议声明的服务 | 不以后台抢占造成的差异归因算法 |

### 17.4 数据布局与缓存

使用少量连续分片存储训练状态、动作绑定、mask和目标；向量与token张量可使用适合随机批读的布局。分片按根来源组织索引，但训练采样按来源平衡。不要每16条状态重复重写全部历史大文件。

冻结编码器时可以预计算向量。部分解冻后必须读取原token并对当前参数求梯度；不能用旧cache伪装微调。切换 checkpoint 时部署缓存按模型版本失效，显式记录重建开销。

### 17.5 数值与吞吐

BF16 前向不意味着所有参数/优化器也是 BF16。质量目标、softmax/logsumexp、损失累计和比较可保持FP32；高精度教师分数如果对微小差值敏感，应先做相同输入不同batch的稳定性检查。使用当前安装版本支持的 autocast/attention 实现并冻结环境，不在本计划中假定某个库版本已安装。[R22]

按真实长度分桶、适度预取host数据、使用pinned memory及异步搬运前先做profiling；这些是建议优化，不是已测收益。频繁 `cuda.synchronize()` 会破坏正常重叠，详细同步只在独立profiling窗口使用。

### 17.6 不用“设备小时”冒充活跃计算

并行作业的wall之和不是项目经过时间；作业分配到GPU的时长不是kernel忙时。分别记录GPU活动、阶段wall、总作业elapsed和CPU process time。外部模型服务没有GPU计量时保留请求与tokens，不捏造FLOPs或能耗。

## 18. 代码集成：保持一个执行系统

### 18.1 首批改动边界

`MemoryPolicy.choose` 继续返回一个实际候选ID。增加模型无关的 `score` 接口供训练/分析使用，旧 Laya adapter 与生成式adapter保持可用。先用现有动作集完成P的两级实验；只有实际表示/异步执行需要时才升级动作合同。

不能让策略在 `choose()` 内暗中读取数据库或调用Reader。内部latent计算可以发生，但任何新来源读取都通过记账的操作或明确声明的授权索引。预取请求由单独可见调度路径执行，不藏在模型预测函数里。

### 18.2 旧类型不能直接接新枚举

当前 `Operation` 仅有五类。[P2] 任何 `REFINE/PREFETCH/WAIT` 示例均为拟议语义；必须修改类型、菜单、执行器、序列化与测试后才能使用，不能将其写入配置就声称已支持。

首版 REFINE 尽量复用实际 `READ` 范围扩展；条件化重算放在控制器计算预算；F 成熟后明确增加运行时调度接口，而不是强塞为无语义的 `REFRESH_VIEW`。

### 18.3 建议模块组织

以下是职责边界，不要求每项都新增一个文件。开发前先查现有模块，能扩展则扩展。

| 职责 | 建议实现位置/动作 | 依赖 |
|---|---|---|
| 模型无关观察与绑定投影 | 从现有Laya投影提取通用部分，旧格式保留 | 原projection、MemoryControlState |
| 多分辨率材料 | 现有来源/工作集路径增加显式表示清单 | 原来源范围、容量计量 |
| 策略网络与模型加载 | 一个小包覆盖M0/M1和可选M2适配 | 公共 `score/choose` |
| 基础/条件缓存 | 复用现有缓存，补版本和依赖键 | 来源版本、模型版本 |
| 分支标签编译 | 扩展现有控制学习工具 | FirstActionIntervention、结果字段 |
| 训练与评估入口 | 一个可配置训练入口、一个rollout入口 | 不复制环境执行代码 |
| 预取调度 | 条件新增有限队列 | 原读API、取消与权限边界 |

### 18.4 最小缓存身份

键包含对象/来源ID、revision、范围/表示级别、编码器/投影版本与权限域。条件缓存另带query/workspace/dependency epoch。避免为每次访问建立昂贵内容指纹；模型与内容版本清晰变化即可。

权限域不能只靠用户字符串猜测。持久遗忘需要触及相应派生缓存和隐状态；工作集淘汰不影响持久库。现有语义与授权边界优先，不另建一套覆盖它们的规则系统。

### 18.5 记录最小但足够

每步保存 before引用、实际候选、模型版本、选择模式、完整动作、真实结果、新观察/交付范围和分项成本。大正文通过已有来源引用一次保存；训练记录不重复嵌入全部来源库。只有明确需要语义复核的样本保存受权限保护的原文快照。

关键选择模式包括 `policy`、`only_available_action`、`budget_forced`、`intervention` 和 `runtime_failure`。没有调用模型的步骤不得用于证明模型学会策略。

## 19. 基线、实验矩阵与变量控制

### 19.1 三组不同目的的基线

**系统基线：** 原实现、优化后的固定策略、基础编码缓存、固定层级/固定刷新/简单预取。这组识别工程收益。

**学习基线：** MLP、固定精度对象attention、仅SFT、旧弱目标、条件收益监督。这组识别训练贡献。

**研究近邻：** BudgetMem式预算档位、ClawVM式驻留规则、MemSidecar式准备，以及可复现的原生方法。[R13–R15] 对共同条件改编版明确标注“inspired/adapted”，与原生复现分开。

强简单策略只在DEV-select选择一次并冻结。所有学习方法与该策略共享可用候选、预处理、权限、Reader、最大预算和相同工程优化。保留 full-context/完整精度参考；若它超出主预算，就作为更高成本参考而不是不公平主对照。

### 19.2 分组实验，避免全排列

| ID | 目的 | 主要对照 | 是否必跑 |
|---|---|---|---|
| E00 | 测瓶颈与系统上限 | 原固定、工程优化固定、完整精度 | 必跑 |
| E01 | 数据可学与表示保真 | 机械特征、冻结向量MLP、对象attention | 必跑 |
| E02 | 记忆交互的价值 | 同骨干独立打分、集合交互、latent瓶颈 | 必跑小筛选 |
| E03 | 渐进读取 | 固定R2、固定R3、相关性升级、学习升级 | 主比较 |
| E04 | 训练目标贡献 | 同起点SFT、旧弱监督、实际结果监督 | 必跑 |
| E05 | 自身状态分布 | 固定数据同曝光、两轮自身状态聚合 | 必跑 |
| E06 | 变化刷新 | 全刷、TTL、依赖规则、学习局部刷新 | D主比较 |
| E07 | 预取净收益 | 无、规则、统计预测、学习对象/时机/精度 | 条件启动 |
| E08 | 计算深度 | 固定2/4层、随机预算、学习退出 | 探索 |
| E09 | 精确路由界 | 全精度、近似低精度、界限渐进 | 小型探索 |
| E10 | 组合与贡献 | P、D、P+D，F有收益才加入 | 候选冻结前 |
| E11 | 跨条件 | 预算、对象数、语言、Reader、变化率迁移 | 必跑有限集 |
| E12 | 新来源确认 | 冻结候选、训练起点、强简单策略、关键去机制 | 必跑 |

先比较单变量，再在有证据的机制上联合训练。最多两条重型探索分支同时活动；不能把十二个实验ID自动展开成几十倍模型组合。

### 19.3 训练效果的必要对照

同一M1骨干必须有可用暖启动 checkpoint、同曝光继续SFT、结果监督、结果＋自身状态四个阶段。若不同阶段样本/来源不同，另加重复旧池或相同来源额外曝光对照，说明非纯目标变化。

比较attention与MLP时同时提供参数/计算匹配的小变体。超过参数更小的MLP不足以单独证明关系模块的独特贡献。

### 19.4 机制消融与真正干预

移除已交付/已观察区分；移除版本变化；关闭关系交互；固定精度；固定刷新；打乱预取时机但保留次数；相同潜在维度却固定全部加载。每个消融保持其他预算和训练条件尽量一致，无法匹配时披露。

使用候选重排、ID重命名、同义改写、加入冗余对象、局部反例、隐藏关键限定、时间/角色替换和撤销事件。正确的机制应在其针对的分层有收益，也应在不需要它的简单任务中不过度付费。

### 19.5 不让压缩或预取创造隐藏信息优势

同一协议下所有模型可访问相同的R1索引；任何模型访问R2/R3均记账。策略可观察的范围与Reader的最终包分别保存。低维模型不能偷偷读取高维答案特征，预取模型不能拿下一条实际query作为预测输入。

性能测量不跨方法共享warm cache或回复。标签生产可在严格相同输入下复用响应，但另开公平性能运行；二者不能混计。

## 20. 统计协议与最终有效性验收

### 20.1 主指标先固定

R轨道默认主质量指标为计划任务分母上的“首次完整且受实际交付来源支持”的结果；环境轨道优先使用可执行成功条件。原生F1/准确率另列，不能在看结果后用词面指标替换来源支持指标。

执行失败计入计划分母。语义未知不伪装为失败真值：分别报告 verified-positive/全计划、unknown比例、可判定子集和识别界。若未知过高或方法间差异明显，不能仅凭verified-positive差异宣布真实质量优势；应做独立补充评审或收窄结论。

### 20.2 G1：训练有效的最低证明

与同骨干、同信息、同预算的可用训练起点比较：在预注册的新来源主任务上出现质量改善，或在预定质量约束下出现完整成本改善；配对区间排除无效方向。必须证明保存后的权重实际部署、执行完整动作，且增益不是新规则、更多候选或更大Reader带来的。

同曝光SFT/弱监督对照用于说明哪个训练阶段有效。只超过随机标签、未训练随机头或旧低质量方案，不满足完整的G1证据。

### 20.3 路线 A：质量优先，默认

设计目标：相对冻结强简单基线，主要任务质量点估计提升≥5个百分点，来源/依赖组配对95%区间下界>0；同时G1成立。实际资源不超过预注册预算上限，成本与尾延迟完整报告。

“点估计≥5pp且CI下界>0”说明可靠正增益及达到实用点目标，不说明可靠增益至少5pp；若要声称后者，区间下界也必须超过5pp。此区别写入最终结论。

### 20.4 路线 B：质量约束下的效率优势

只有在确认数据暴露前明确选定B才用于完成判定。建议起点：质量非劣界2个百分点（需任务风险论证），主要效率目标为端到端平均延迟比的95%区间上界≤0.70，质量差的95%区间下界>−0.02。成本路线也可改为某个真实可测资源，但必须先注册，不能事后在延迟/tokens/GPU秒之间挑选。

选择延迟为主时，建议增加总推理资源开销不高于基线1.10倍、P95延迟比不高于1.05的护栏；这些阈值须DEV阶段基于应用需求一次冻结。增加总资源换延迟的方案可以研究，但不自动满足“降低完整成本”。

任务成功率与失败模式不得恶化到未测范围。更快失败不等于效率提升；超时/取消和后台尾部成本保留。系统不具备足够功效时，不以“无显著差异”当作非劣成立。

### 20.5 样本量：用不一致率而不是现有库存决定

对独立配对二值任务，设 `d_i=Y_i^new−Y_i^base`、均值差Δ、配对不一致率p_d，则 `Var(d)=p_d−Δ²`。粗略功效规划可用：

\[
N\approx\frac{(z_{1-\alpha/2}+z_{1-\beta})^2(p_d-\Delta^2)}{\Delta^2}.
\]

例如两侧α=0.05、功效约80%、目标差0.05、p_d=0.20时，近似需要约620个独立配对单位。若检验真实差近0、非劣界0.02，按同样近似量级约3,920个单位。它们是规划示例，不是正式统计保证；聚类、离散性、多个seed与缺失通常需要进一步模拟。

多个问题来自同一来源时，先使用DEV估计组内相关并进行来源级模拟/聚类bootstrap。若只有几百独立单位，不能借由重复Reader或拆分状态宣布达到数千独立样本。可增加新的研究集并明确其性质，或报告实际可检出的效应，不能偷偷放宽非劣界。

### 20.6 多 seed 与重复

最终候选至少3个训练seed，分别报告，并使用预定方式汇总。三个seed不足以可靠刻画所有训练随机性，应给出范围和限制，不能只报平均。 路线A还要求三seed平均效应为正，至少两个seed的点估计优于冻结强基线；不要求每个seed都单独显著，也不由此声称普遍seed稳定性。路线B逐seed呈现质量与成本约束，不能用平均值隐藏某个灾难性退化。

每个任务、方法保留首次执行作为主结果。预先固定的重复子集可估计Reader波动；不best-of-n、不替换首次、不倍增来源N。来源聚类与训练seed变异分别表达，必要时采用分层bootstrap，但不能因bootstrap次数多就声称信息量增加。

### 20.7 比较层级与冻结

唯一主要方法比较及主要指标在确认前冻结。对多个独立创新主张使用预注册层级检验或Holm等多重比较控制；大规模探索结果仅称探索性。阶段性看CONFIRM并继续调参即失去确认性质，应转为开发数据并另建新确认来源。

### 20.8 缺失和判断偏差

报告至少一个“未知全部不利于新方法”的敏感性界，以及预定独立评审样本的结论。如果主要方向依赖unknown被忽略，则结论为测量不足，不宣称训练成功或证明无效。

方法间judge偏好可能来自格式、长度或引用风格。评审输入协议固定；来源支持和任务完整性分开判断。自动评审一致率不是独立准确率，开发作者的复核也不自动成为独立人工真值。

### 20.9 产品采用与研究结论

至少预先选择一个第二Reader或外部任务作为迁移验证。未达到其预定质量要求或样本量不足时，主条件下的正结果仍可报告，但不能同时宣布通用迁移验收完成。额外Reader的校准成本与完全零样本迁移分开。

论文或实验主张可限定在已验证任务/预算/语言；产品默认替换还需跨权限、恢复、并发、极端长度和实际负载验证。未达到产品条件时可以有真实科学贡献，但不能静默更改现有产品策略。

## 21. 成本、延迟与真实系统测量

### 21.1 分项计量

至少记录候选生成、存储读取、CPU/GPU搬运、编码、策略、局部重算、预取、证据包装、Reader及等待。阶段区间可能重叠，阶段wall求和不能当作端到端延迟；父子CPU计时也不能重复相加。

端到端主计时从任务接受至首次最终响应或明确终态；取消后继续运行的预取/服务尾部另计资源与尾部时间。失败不会从分母或成本表删除。

### 21.2 冷缓存、热缓存与完整生命周期

提供至少：首次建库+首任务、固定warm-up后任务、完整连续episode。离线索引/多级表示构建成本及更新成本按实际频率计入生命周期；如提供摊销结果，列出摊销任务数。

可用简单盈亏平衡式说明：`N_break_even = 额外预处理成本 / 每任务净节省`，分母非正时无盈亏平衡点。不能只展示预热后的有利数字。

### 21.3 预取专项指标

及时有用率、太晚完成率、未使用率、因版本/权限失效率、额外读取字节、缓存占用时间、实际隐藏的等待、前台争用延迟、取消后的残余工作。一次IO服务多个对象时按物理总量计费，不能把逻辑条目减少当作页级流量减少。

请求中途被截断的访问窗口与真正无用预取分开。需要用户/来源权限隔离的缓存不能为速度共享给不具权限的请求。

### 21.4 GPU与服务基准

固定硬件、设备拓扑、模型服务、并发、batch、输入/输出长度分布和缓存初始状态。性能比较随机交错方法顺序，避免温度/背景负载的系统偏差。GPU profiler只在有限代表性窗口启用，完整基准使用低开销计时。

不为获取所有attention图而退回慢kernel再宣称注意力策略有速度收益。关注物理字节、显存分配与真实吞吐；稀疏索引不自动释放物理页。[R16]

### 21.5 成本诚实性

CPU秒、GPU秒、tokens、字节与金额各列一栏。不知道外部服务的活跃GPU时间就标未知；没有固定价格依据不换算金额。训练费用、标签费用、推理费用分别列出，不能通过省略数据生产来宣称“训练非常便宜”。

### 21.6 延迟和资源不是同一个目标

更多异步工作可能使延迟下降但总工作上升；少Reader tokens可能被控制器长输入抵消；少候选可能没有减少物理页读取。所有“更快/更省”结论要明确是哪一项，最终完成判定按第20章的预定主轴。

## 22. 长期维护扩展：从读控制走向未来任务控制

### 22.1 不把本轮读取成功夸大为完整记忆学习

P/D/F 主要决定如何访问与计算已有记忆。真正的写入、修订和长期保留会改变未来环境；只有加入W轨道，才能评价记忆维护学习。读取主线先建立可信反馈，随后固定候选生成器，训练小模型选择维护提案。

### 22.2 维护候选与未来收益

首版候选为现有系统提出的 ADD/UPDATE/NOOP/关联与保留操作，不让小模型同时生成复杂全文。每个操作绑定实际来源和目标版本；内容提案器消耗计入总方法成本。

评价同一起始历史下不同维护分支对未来任务的影响，包含新事实落实、旧未撤销事实保持、例外与时间、重复维护、永久遗忘的实际范围。当前问题答对不能证明未来任务受益。

### 22.3 三种“刷新”保持分离

**计算刷新**更新派生向量；**事实维护**更新语义记录；**重新检索**改变当前可见材料。三者需要不同事件和成本。某个向量过期不能直接授权删除事实；事实版本变化也不意味着整个数据库全部重建。

### 22.4 联合训练的进入条件

只有读控制已形成稳定收益、维护提案有足够实际正反案例、未来评价能复位且来源不泄漏时，才开展读/写联合优化。采用交替阶段固定另一模块的方式逐步接近联合，而不是第一天全系统同时更新导致无法归因。

### 22.5 探索目标

探索“哪些记忆值得形成高精度表示、何时维护以摊销未来成本、如何在不损伤非目标信息时局部更新”。这是可能的长期算法贡献；若仅运行了缓存刷新，应将论文范围限定在计算控制。

## 23. 创新探索管理与转向规则

### 23.1 假设账本

| 假设 | 独特可测预测 | 最小反例/对照 | 失败后优先转向 |
|---|---|---|---|
| H-P 条件展开 | 升级次数下降但关键限定遗漏不增加 | 固定精度、相关性升级、随机等次数升级 | 检查表示失真和候选召回，再改奖励 |
| H-D 变化相关重算 | 低变化时省算，高变化时主动扩大重算 | 简单版本规则与全刷新 | 若规则已够，保留工程方案，不堆神经模块 |
| H-F 时机精度联合 | 比只有需求概率的预测器隐藏更多等待 | 同次数随机时机、同精度规则预取 | 检查瓶颈是否确实可隐藏，或关闭F |
| H-A 计算/信息分辨 | 信息已齐时选计算，缺证据时选读取 | 固定深度、只READ/STOP | 强化状态诊断或合并为更简单策略 |
| H-X 路由界限 | 相同路由选择但减少精度加载 | 完整扫描、普通低精度近似 | 界过松或维护昂贵则停用 |
| H-T 策略迁移 | 同模型在不同预算/Reader仍保留部分收益 | 每环境重调阈值与零迁移 | 改为低成本校准，收窄通用性主张 |

### 23.2 分支立项卡

一页卡必须写：最接近工作、尚未解决的差异、唯一主要变量、可反驳预测、最小数据量、最大模型调用/设备预算、必要对照、转向触发和具体产物。不要求先写长篇论文故事。

每个探索块结束要回答“获得了什么新的可判定信息”。若只是重复旧负结果且没有新诊断，就不继续机械扩量；若发现明确新瓶颈，可以开下一项有界实验。停止某配方不等于停止科研。

### 23.3 资源分配

建议起点为60%主线训练与确认、20%可靠反馈/测量、20%探索。按实际资源消耗而非提交数计量。主线至少形成一次真实训练→保存→加载→任务执行的闭环后，再启动第二个重型机制。

探索可以改变架构和任务假设，但正式确认范围内的模型、数据、阈值和指标不能随结果变动。旧确认曝光后只能进入诊断集合。

### 23.4 可以得到的负面科学结论

多分辨率有表示损失；注意力成本大于收益；真实数据不需要组合关系；预取缺少可隐藏等待；版本规则已经优于学习；小模型不能保留关键语义。只要证据充分，这些都能指导下一次实验。不能为保持“创新性”而拒绝更简单有效的实现。

### 23.5 避免以工程进度替代探索

每个新模块至少绑定一个可判别实验。没有任务收益假设的模块不进入主线。相对代码规模，优先投入高质量训练对、实际难例、对照公平性与学习曲线。

## 24. 必要测试与故障定位

### 24.1 测试覆盖以风险为边界

| 范围 | 必要检查 |
|---|---|
| 动作绑定 | 重排/重命名后完整对象与参数不变；不存在的ID明确失败 |
| 观察与交付 | 预取不自动暴露正文；已观察未选中不冒充已交付；最终包装容量正确 |
| 版本与权限 | 更新使相应派生缓存失效；撤销后缓存与混合隐状态不继续泄漏 |
| 分级表示 | R2/R3范围真实、限定未机械截掉；低维目标不是从标签生成 |
| 增量重算 | 稀疏闭包正确；全局依赖时不虚假声称局部等价 |
| 预取 | 并发上限、取消、版本竞争、无用工作结算、不同臂缓存隔离 |
| 训练 | mask、全窗归一化、梯度非零、无标签窗口、恢复和保存模型实际调用 |
| 分支 | 同before、不同副本、续跑策略固定、未知不转负例 |
| 数据 | 根来源隔离、未来字段不进入在线输入、候选生成无gold |
| 路由界 | 固定线性模型的argmax/Top-k、边界平局、query变更使旧界失效 |
| 性能 | 小型快库不会被预取强行拖慢而隐藏；物理量与逻辑数量分开 |

这些是必要合同测试，不需要每项单独建立注册器、审核器和文档流水线。合成测试通过不替代自然任务质量。

### 24.2 故障到行动

| 现象 | 首先定位 | 不应采取的“修复” |
|---|---|---|
| loss下降，任务不变 | 目标是否只是模仿、候选是否同包、策略是否真调用 | 仅加epoch或换更大checkpoint |
| 动作变多但更差 | 停止标签、成本权重、结果监督噪声 | 把更多READ写成更强推理 |
| 低精度快但丢限定 | R2构造、信息上限、困难分层 | 删除这些难例 |
| 缓存命中高但总延迟差 | 编码重复、调度/打包开销、前台争用 | 只报命中率 |
| 局部刷新出现旧事实 | 依赖遗漏、任务状态复用、隐状态污染 | 增加静默全刷新后不计成本 |
| 预取有效但总工作增大 | 提前量、无用率、缓存占用 | 将后台开销从账本移除 |
| 评价unknown偏高 | 评审合同、格式、证据范围、独立校准 | unknown统一当0或只算有效分母 |
| DEV好、确认差 | 来源复用、调参选择、状态分布、训练随机性 | 持续重跑确认挑一次好结果 |
| GPU低利用 | 数据/教师等待、长度填充、IO、batch | 无目的增加重复数据量 |

### 24.3 可学习性失败也要分层

如果完整精度参考同样失败，优先检查Reader或候选覆盖；如果完整精度能区分但低精度不能，改表示/展开机制；如果低精度下人工/规则可区分而模型不行，检查训练与容量；如果离线能选对而运行轨迹不行，检查自身状态与执行。

完整精度Reader不是理论最优上界；“从若干已执行分支挑最好”也只是采样候选集合中的事后参考，有选择偏差，不能作为部署分数或全局oracle。诊断表要明确其作用。

## 26. 首批实施顺序与最终交付

### 26.1 第一批必须按此依赖顺序推进

先核对环境与真实模型文件，测量一组正常任务的实际延迟分解；修复现有View/材料包装的容量问题；统一模型无关投影；实现仅两级的实际来源读取；冻结优化后的强固定策略；导出D0分支；训练M0与最小M1；加载保存模型在新根来源执行完整任务。

首批不做预取服务，不扩展数十个动作，不训练所有模块。只有真实P闭环结果出现后，再决定D/F与更大骨干。

### 26.2 必须交付的实物

最终包含：可调用的小策略模型与权重、训练与部署配置、数据来源/划分/标签清单、必要环境版本、实际rollout结果、完整成本、三seed汇总、机制消融、迁移与失败案例、源代码入口和复现说明。受限原文不必公开，但需要提供可发布的小型样例或合成复现集，不将私有实验目录假装为用户可下载资源。

### 26.3 最终结论模板

> 在〔固定信息条件、Reader、预算、来源范围〕下，模型〔版本〕相对同架构可用训练起点〔结果与区间〕，相对强简单基线〔结果与区间〕。完整成本为〔真实资源轴〕；〔机制〕的消融显示〔差异〕。尚未验证〔语言/规模/维护/负载〕，未知判断与失败为〔数量及口径〕。因此 G1〔状态〕、G2〔状态〕、G3〔状态〕，产品采用〔状态〕。

### 26.4 本计划的核心承诺边界

文档规定必须追求并验证训练有效性，不能保证某个尚未运行的算法必然胜出。没有收益时继续做有依据的探索；有局部收益时准确说明范围；达到最终标准时才能宣布本轮目标实现。

**成功不是更复杂的记忆框架，而是一个确实学会少做无用工作、把成本花在关键证据和计算上的小模型。**

## 附录 F. 数学、规模与保证边界

### F.1 注意力复杂度不等于整体复杂度

候选N、每对象r个向量、宽度d、工作槽S：完整对象self-attention的交互项约为 `O((Nr)^2 d)`；latent交叉attention约为 `O(SNr d + S²d)`。两者还包含投影、FFN、正文编码和索引成本。[R11,R12]

例如N=128、r=4、S=16时，单head的候选两两交互位置为262,144，交叉交互为8,192。这个32倍比例只是交互位置数比，不是预期端到端32倍加速；投影/FFN、kernel形状和基础编码可能主导。

若GPU为可变宽度仍统一补齐到256维并调用相同矩阵乘法，则64维实验可能只减少语义容量而不减少计算。真实省算需要分桶/分组kernel或低维实际算子，并计入重排与调度开销。

### F.2 Amdahl上限

若可优化阶段占原端到端比例f、该阶段加速s倍，理想整体加速为 `1 / ((1−f)+f/s)`。f=0.2、s=5时约1.19倍。若全部可隐藏IO仅占10%，即使完全隐藏，理论上限也只有约1.11倍，尚未扣预测开销。

这用于决定是否投入F，不是用人工延迟放大f后作为真实成绩。

### F.3 精确缓存更新的狭窄范围

固定query q、固定独立keys/values时，attention分子分母为：

\[
N(q)=\sum_i e^{s_i(q)}v_i,\quad D(q)=\sum_i e^{s_i(q)},\quad y=N/D.
\]

若只有有限对象的k/v变化，可以在数学上移除旧项、加入新项；数值实现需稳定缩放并处理最大值变化。query变了、上层hidden state变了、全局关系耦合变了，就不能沿用这一简单更新式。

该分支只适合固定查询中的表示替换或受限计算，不能宣称通用Transformer状态可常数成本增量更新。通常重算小工作空间更简单可靠，是否采用由实测决定。

### F.4 严格路由界不覆盖什么

Cauchy–Schwarz误差界只保持固定score的选择。它不保证score等于任务价值，不保证Top-k证据充分，不保证Reader采样相同，也不保证未召回记忆不会更好。近似query、估计δ、动态softmax上下文与新候选到达都需要重新验证条件。

### F.5 统计示例不覆盖什么

第20章的620/3,920是假设独立配对单位、给定不一致率与近似正态功效的量级示例；不覆盖大比例unknown、来源聚类、多重比较和训练seed变异。正式N由模拟和可用来源决定，不能对照公式凑行数。

### F.6 总成本盈亏

若多级表示一次构建额外成本B，每任务省c、每次版本更新额外成本u、平均每任务更新率ρ，则净节省为 `c−ρu`；只有该值为正，才存在约 `B/(c−ρu)` 的摊销盈亏点。成本必须同量纲；外部tokens不能直接与本地毫秒相减。
