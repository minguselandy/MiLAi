## 自然更新与 J1 反馈修复

自然就业更新已闭合：同一真实模型形成的4条seed记录复制给两分支，随后各执行原始退休决定子序列。
两分支都选择普通replace、各提交一次；三个非目标完整value与历史rev1保持，原月薪不再作为当前工资。
patch-enabled选择了旧h支持，普通replace未选择；前者另有“正在专注”稍强于原决定动机的问题。
未用旧after或手写理想before，不强制patch，不能宣称该算子获胜或完整后续Reader语义通过。
共享seed为2次生成13,761tokens；replace为3次生成21,073＋2次embedding209；
patch-enabled为3次生成16,368＋2次embedding215。两分支的主要成本差来自selector输出，不能归因于patch。

J1原两题闭合：S2为1/2 Correct＋1 invalid；J1-v1为0/2，含1缺答＋1 invalid。
首题原J1实际读完15条后仍保留51,935tokens最终集合，超过32,256；随后8次空正文调整，
共11次调用仍未发送最终回答。这是实际预算选择断点，旧结果保留。

新`joint_selection=budgeted_nominations_v2`只对J1启用：保留累计模型提名（减显式drop），
独立计算完整最终请求能准入的整个原件与语义视图，真实来源优先；记录被排除项，不删除记忆、
不缩短原件、不跳过候选页。后续drop释放额度时可重新准入先前排除项。全部页交付后直接使用
该预算内集合，不再反复空页修复；选择完成不等于证据充分。S0/S1/S2原行为不变。

## 入口

在本开发工作树的 MiLAi-Lab 执行（实际冻结副本和运行配置另存 ignored artifacts）：

```bash
PYTHONPATH=src /cra/memory/mx_memory/MiLAi/MiLAi-Lab/.venv/bin/python \
  tools/run_baseline_alignment.py configs/milai-evidence-s0-dev-v1.json \
  artifacts/evidence-development/s0-six-v1 --phase predict --backend MiLAi-memory-only
```

S1／S2／ranked 使用各自配置与独立结果根。预测终态与资源闭合后，同配置同根显式 `--phase score`。
运行结果的 evidence-results.json 保存逐题答案路径、交付材料、各模型输入输出与耗时；
ranking.json 记录排序模型、各批实际索引及最终顺序。Judge费用与预测费用分开。
