## Efficient failure handling

A local failure triggers one bounded diagnosis and a general repair when the input,
product identity, and primary hypothesis remain unchanged. A failed case does not freeze
unrelated development. A changed treatment, label use, product build, or primary metric
starts a new declared run.

Required evidence is proportional to the claim:

- unit tests for local contracts;
- a pin check for product identity;
- a bounded smoke run for execution validity;
- a preregistered evaluation only for a method-effect claim.

Repeated receipts, self-referential manifests, duplicated environments, and identical
post-repair reruns are not required.
