用户重新打开开发，要求修复全部当前问题、优先完成开发、授权自行审查，不以原生小样本得分作为可用性的替代。本轮承接 v7 的明确缺口；v7 的源码快照、两次失败和最终 5/5 成绩保持冻结。

## 已确认的问题与交付

| 工作包 | 实际问题 | 完成条件 |
| --- | --- | --- |
| A 维护闭环 | 首轮约定漏存；成功执行后旧卡仍是待处理；final answer 被当作全部完成 | 新输入、更新和真实执行结果均进入可追踪维护决定；该保存／修订的事项实际提交；无变化可直接结束；未完成维护明确返回 pending，可继续恢复 |
| B 持久入口 | task_runtime 每次建立空库；会话/业务动作中断没有完整恢复入口 | 原子落盘、同所有者身份校验、关闭重开持久库、同轮恢复真实已交付材料、已完成轮次去重；未确定业务动作先查证，禁止自动重放 |
| C 缺口收敛 | 中文全文召回受整句 token 限制；旧删除 fixture 不遵守可信合同；异常制品缺少当前世界和 checkpoint | 通用词法补齐并验证局部召回；修正 fixture 而不放宽权限；失败保留当前状态和完整成本，异常不能变成成功 |
| D 真正消费者 | v7 本地文件样例只证明脚本接线，尚未证明自主使用／重开 | 一个小型真实文档任务：首次要求保存、随后更正、真实检查失败/修复/成功、新进程会话消费当前要求和完成状态；用户无需手工构造内部 checkpoint |
| E 集成交付 | 过去把限定通过误当整体完成 | 更新可直接运行的入口、配置、身份快照与简短使用说明；受影响窄检查、实际部署 grammar、少量真实 Host 验证后核对所有工作包 |

先完成实现再运行少量实例。必要时使用已经暴露的原生 MERIT 单元做回归，不扩题、不改题、不改评分；通用文档消费者是功能验证，不另造正式准确率。State 仍可选，普通记忆是默认；不要求每轮 State、每轮写入、额外反思模型或重新摄入历史。

维护决定应与同一次最终回复组合，优先不增加无事可做时的模型往返。程序仅检查来源/版本/决定覆盖与真实操作回执，不根据业务关键词自动生成事实。业务完成、记忆维护完成、世界结果可确定性分别报告，不能用模型一句“记住了”代替提交。

恢复支持一个同步应用、一个本地写者；业务工具由应用提供，持久日志不能替代外部工具的幂等／状态查询。副作用不明时不得假设未执行。恢复中的临时材料仍属原会话，不作为新会话隐蔽历史检索。
